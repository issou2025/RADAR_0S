# PRD: Flutter Port Repair

## Problem Statement

The Flutter port of What Car AI was rushed from React Native. Navigation is broken (go_router routes ignore passed data, auth uses wrong Navigator API, duplicate routes), the scan-to-identification flow does not work, and Riverpod data/auth providers are fragmented. The app does not compile cleanly and core features fail silently.

## Solution

Repair navigation to match RN structure (Home + Garage tabs, FAB modal scan), unify auth and data providers, fix Firestore schema parsing, and leave AI identification as explicit TODOs until API keys are configured. Add test coverage for route params and data models.

## User Stories

1. As a user, I want to open the app and see the home dashboard, so that I can access quick actions and recent scans.
2. As a user, I want to tap a center scan button to open the camera, so that scanning matches the RN app UX.
3. As a user, I want to capture or pick a photo and proceed to processing, so that I can identify a car.
4. As a user, I want processing to show my image while working, so that I know which photo is being analyzed.
5. As a user, I want a clear message when AI is not configured, so that I am not confused by silent failures.
6. As a user, I want to view car details after identification, so that I can see specs and images.
7. As a user, I want to browse the app without signing in, so that I can try scanning before creating an account.
8. As a user, I want a prompt to sign in when saving a scan, so that I understand why auth is needed.
9. As a user, I want to sign in with email or Google, so that my scans sync to the cloud.
10. As a user, I want to register and stay signed in, so that I do not have to log in again immediately.
11. As a user, I want to reset my password via email, so that I can recover my account.
12. As a user, I want to switch between Home and Saved (Garage) tabs, so that I can manage collections.
13. As a user, I want collection detail pages to load the correct collection, so that I see my saved cars.

19. As a developer, I want DataProvider initialized on startup, so that save operations do not throw.
20. As a developer, I want tests for route params and Firestore parsing, so that regressions are caught early.

## Implementation Decisions

- **Navigation:** `StatefulShellRoute.indexedStack` with Home (`/`) and Garage (`/garage`) branches; `/scan` as `fullscreenDialog` push from FAB.
- **Route paths:** Keep Flutter paths (`/process`, `/collections/:id`) — no RN path renames.
- **Route params:** Centralized helpers in `route_params.dart` reading `state.extra` and `pathParameters`.
- **Auth:** Single `AuthProvider` (`StateNotifierProvider`) with email, Google, sign-up, reset, sign-out. No route-level auth guard.
- **Auth UX:** Soft prompt on save via `ensureSignedInOrPrompt`.
- **Data:** `AppBootstrap` calls `dataProvider.initialize()`; auth listener syncs `DataState.user`.
- **Firestore:** `Car.fromFirestore` merges nested `carData` and `imageUrl` into flat Car fields.
- **AI:** `_identifyCar` returns null with TODO until API key configured; no silent stub.
- **Deep linking:** Deferred.
- **Premium/RevenueCat:** Deferred with TODO in settings.
- **Platform:** Android Firebase only this pass; iOS deferred.

## Testing Decisions

- Test public interfaces: route param helpers, `DataState`, `AuthState`, `Car.fromFirestore`.
- Use `fake_cloud_firestore` for Firestore document parsing tests.
- Avoid widget tests that require full Firebase init; test router param wiring directly.
- Provider tests that need Firebase deferred or test state classes only.
