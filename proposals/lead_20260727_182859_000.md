# Project Proposal — Pdf To Revit

## Project Understanding
You need assistance with: 
**Validation terrain V2 — fixtures IFJA réalistes avant nouvelle architecture**

*Project description:*
## Objectif

Valider le Cockpit V2 fusionné sur des cas qui ressemblent réellement aux dossiers et aux échanges IFJA avant d’ajouter Learning, Evaluation, mémoire, framework ou nouvelle couche d’architecture.

Cette issue est volontairement une campagne de validation et de mesure, pas une proposition de nouveau concept.

Les fixtures doivent être **synthétiques et anonymisées**, mais reprendre la structure de sujets réellement rencontrés dans les discussions : maison neuve, rénovation lourde, patrimoine, ERP, chantier, marchés de travaux, DCE/CCTP, réglementation, coordination BET/entreprises, Gmail/Drive/Notion/Google Contacts, BIM/Revit et outils IA.

- Project

- Contacts

Et vérifier les invariants :


## Scénarios transversaux à mesurer

### Project / ProjectClaim

- Project reste lisible malgré identité stable + attributs descriptifs + claims projetés.
- Une valeur comme `312 m²`, `UDb` ou `600 000 €` peut être affichée simplement.
- La provenance reste accessible derrière la valeur sans exposer de Claim Card.
- Plusieurs parcelles peuvent être agrégées depuis plusieurs claims scalaires.
- Une valeur `asserted` peut exister sans prétendre être vérifiée.

### Information

- ACTÉ reste immuable.
- Une version en rédaction peut coexister avec la dernière version ACTÉE.
- Le changement de fichier/lien/source porte le nouvel indice.
- Une modification du résumé/détail ne consomme pas un nouvel indice.
- La carte vierge `Nouvelle information` permet : Fichier / Lien / Brouillon.

### Work / Decision / ChangeCandidate

- Work expose objectif, jalons, responsabilités, skills, fonctions et outils sans devenir workflow engine.
- Decision n’existe que lorsqu’une validation est nécessaire.
- ChangeCandidate conserve base_revision, diff, provenance et idempotence.
- Un changement stale n’écrase jamais une valeur plus récente.

### Contacts

- Une seule carte Contacts par Projet.
- Les contacts sont simples à lire et modifier malgré plusieurs dizaines d’intervenants.
- Google Contacts / Gmail peuvent proposer des données sans devenir autorité.

### Tool

- Le catalogue reste distinct de l’observation runtime.
- Absence d’observation != `not_installed`.
- `healthy != safe` reste visible dans l’UX.
- Aucun bouton UI ne devient implicitement autorisation.
