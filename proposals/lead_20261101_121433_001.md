# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Proposal: switchable UI profiles (ribbon layout or tool palette + info panel), core untouched**

*Project description:*
Hi! I'm an architect in Italy. I model every day in Archicad and use IFC for quantity takeoff. BIMCraft's engine impressed me: everything is a command, the core is UI-free, IFC4 is validated. I'd like to propose something that could bring users from that workflow without touching the core.

## The idea
Switchable **UI profiles** on top of the same engine and the same commands:

- **Ribbon profile** (today's layout, the default)
- **Palette profile**: a vertical tool palette instead of the ribbon, a context-sensitive info panel showing the active tool's or the selection's main settings (type, heights, location line, layers), and a navigator tree for the project

Both go through `Session::execute`, so the model, files, undo and MCP behave the same. Only `crates/ui-egui` changes.

## Built on ideas already in IDEAS.md
- **UX-10** Workspaces: a profile would be a named workspace
- **UX-09** Editable, importable shortcuts: one shortcut set per profile
- **VIEW-18** Navigator / minimap, **VIEW-15** Element info on hover

## Optional features, switchable in any profile
Workflow features from other tools, each one a setting that can be turned on or off in either profile:
- **MOD-13** Magic wand (click inside a closed shape to make a floor, roof, room…)
- **MOD-12** Gravity (place onto the slab or roof under the cursor)
- **MOD-01** Priority-based junctions of compound layers (this one touches the core, so it would be a separate proposal)

All of it described by what it does, with no trademarked names, as IDEAS.md asks.

## Suggested first step
A small, testable start: a profile setting in File > Settings that swaps the ribbon for a tool palette listing the same tools, plus a per-profile shortcut set. The info panel and the navigator would come later, each as its own PR.

## Coming from Archicad: export, not native files
Reading native project files has no public specification, so I'm not asking for that. A guided export would do:

1. **Model through IFC**: an Archicad IFC translator set up for BIMCraft. I can provide real test files exported from Archicad, so the IFC import can be checked against them.
2. **Documentation through a JSON sidecar**, extracted with Archicad's own scripting API, for what IFC doesn't carry:
   - **views**: plans, sections and elevations with their level, scale, cut height and which layers and renovation status they show, recreated as BIMCraft views;
   - **layouts**: sheet name, number, size and where each drawing sits on it, recreated as BIMCraft sheets;
   - **publishing sets**: named groups of sheets printed together. BIMCraft would need named sheet sets for this (today it prints every sheet into one PDF);
   - plus layers, renovation status and zone categories.
3. A BIMCraft command reads the sidecar after the IFC import and rebuilds the views and sheets on the imported model.

Step 1 alone would already be useful; step 2 could come one part at a time.

## Why it might be worth it
Many architects in Europe work in that other workflow. A familiar layout on an open engine with solid IFC is something no free tool offers today.

I can help with the profile's spec, test builds on real residential projects, and review the result from a daily user's point of view. Does this fit where you want the UI to go?
