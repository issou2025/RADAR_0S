## Summary

Keep a fail-closed three-outcome contract for the canonical TypeScript `deft update` path on **this checkout** against the **selected content package**. Recut after design-critique on this issue: the four named children stay independently buildable, but they do not compose that contract by sequencing alone.

This epic owns the shared pre-write fact surface and outcome vocabulary. Child issues own local primitives. Derived acceptance criteria live on this recut body.

## Problem

The consumer upgrade path is split across the TypeScript updater, generation stamping, managed-artifact overlay, scoped staging, and rehearsal. Each piece has useful safeguards. The operation is not yet honest about outcomes.

Measured failures that remain in scope:

- #4158: the updater can replace the deposit and auto-stage framework files in a dirty or stale checkout before proving that checkout is a valid upgrade target.
- #4120: generation stamping consults local state and can rewind relative to a readable default-branch token; session bind can mint a synthetic token before any update proof.
- #4121: the observed pin clobber still needs diagnosis; the shipped preserve-non-v4 rule already exists and must not be rebuilt as if it were missing.

#1999 as filed is a v0.56.0 Python-vendored local harness. It is prior art, not the Wave 0 extraction source for this updater.

## Required invariant

For a consumer repository, `deft update` must reach exactly one honest outcome on **this checkout** against the **selected content package**:

1. **No-op:** payload and derived artifacts already match, and dest plus index are unchanged (modulo a declared volatile-field set, default empty).
2. **Prepared upgrade:** one deterministic, reviewable, framework-only delta from a validated checkout, reported from the mutation ledger.
3. **Refusal:** unsafe, dirty-overlapping, stale-invalid, ambiguous, or unsupported state is detected before the first dest write, with a structured reason and recovery guidance.

Stale checkout when default already carries the upgrade is **not** a Git-unchanged no-op. If this checkout is a valid target, that cell is a prepared upgrade of this checkout. If it is dirty or otherwise invalid, that cell is a refusal.

Pre-write refusal is zero-write. A failed post-swap reconcile or stamp is a named recoverable failure, not an unchanged tree, and is not #2849.

This invariant does **not** claim pre-write proof of engine identity or of #1604 release-handoff state. Those remain related verification, not children of this epic.

## Shared fact surface (epic-owned)

Extend the existing single classifier (`classify()` / `plan()` / `classifyUpdateState`) with target-safety facts rather than private child preflights:

- worktree and index cleanliness, including overlap with planned paths
- occupancy / owner-liveness for the duration of the mutation, or an explicit single-writer assumption
- readable default-branch generation token (untrusted blob; fail closed on missing, incomparable, or rewind-risk)
- structured refusal codes that dry-run can print **with** the dest plan

#4158 and #4120 add facts to that surface. They do not grow a second classifier or a second dry-run vocabulary.

## Epic acceptance criteria

- [ ] Dirty staged, unstaged, mixed, overlapping, and occupancy-conflict starting states refuse before the first dest write by default; an explicit new override is required and is visible in structured output (`dirty_tree` / `dirty_files` measured, not literals).
- [ ] No-op means dest plus index unchanged on this checkout when payload and derived artifacts already match, modulo a declared volatile-field set (default empty). Stale checkout vs already-current default is prepared upgrade or refusal, never this no-op cell.
- [ ] A behind-default checkout cannot stamp a generation lower than a readable default-branch token; missing, incomparable, or rewind-risk tokens refuse before write.
- [ ] Managed workflow refresh preserves a non-v4 consumer pin until diagnosis says otherwise; any strictly-newer advancement uses a trusted ordering signal and refuses incomparable refs.
- [ ] Failed **preflight** leaves deposit, generation token, managed projections, index, and worktree unchanged. Failed post-swap reconcile or stamp reports a named recoverable state and does not claim an unchanged tree.
- [ ] Successful mutation reports ledger-derived paths written, deleted, and staged; product paths are never added to the upgrade stage set (regression on #3378 / #3394).
- [ ] Dry-run and real execution derive from the same operation plan and agree on no-op, prepared, or refused. Preflight refusals appear in the dest plan with structured reasons; they do not collapse to generic `refresh_deposit_failed`.
- [ ] CHANGELOG and consumer-facing recovery guidance identify any new refusal codes or override semantics.
