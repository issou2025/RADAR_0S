## Summary

`canonicalizeProviderOutput` (`cli-connection-reader/model-canonical-v2.mjs`) takes **~106 s** for a medium Tekla model's provider output (11,746 entities, ~74k properties, one 74 MB GLB tile). On a cold read it is the largest single stage. The provider itself now takes ~73 s, AWARE's output admission ~27 s, and FloLess verification ~30 s.

## Measured (AWARE `origin/main`, v0.157.1, Windows 11, Node 24)

Cold read timeline from a real `aware app run` (Tekla Parser provider, FloLess dev server):

| Stage | Time |
|---|---|

| provider (parse + write output) | ~73 s |
| `verifyProviderOutput` (copy, hash, record checks) | ~27 s |

## Likely causes

1. **One async write per record, plus one for its newline.** `model-metadata-sort.mjs` `writeRun` and the k-way merge call `writeAll(handle, record.bytes)` and then `writeAll(handle, NEWLINE)` for every record (lines ~250 and ~374). That is about four `FileHandle.write` round-trips per metadata record across the run and merge phases, which accounts for the 42 s of idle plus ~11 s in `writeBuffer`/`write`. Each run is already sorted in memory, so batching records into ~1 MB buffers before writing should remove most of that time.
2. **Strict canonical JSON per record** (`defineJsonProperty` / `normalizeJson` / `stringValue` / `canonicalJsonBytes`): about 35 s CPU for ~86k records. Worth a look after (1), e.g. avoiding a second canonicalization of bytes that `verifyProviderOutput` already proved canonical.

## Expected

Canonicalizing ~86k metadata records and one 74 MB tile should take a few seconds, not ~1¾ minutes. Every Tekla/Revit reference read pays this cost.

## Repro

Any provider output of this size works. Call `canonicalizeProviderOutput({ workRoot, output: { root, files: manifest.files }, effectiveSource, formatId, capabilityId, providerPackageManifestSha256, conversionRequestSha256 })` and time it with `--cpu-prof`. The FloLess Tekla Parser's output for its "Bridge template" model reproduces it (available on request).

Related: the 96 MB `payloadBytes` per-file limit in `model-provider-output.mjs` forced this model's GLB down from 126 MB; filed separately if needed.
