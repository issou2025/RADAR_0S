### 💬 What Happened?

I am trying to read the exact definition that Home Assistant has loaded for an automation or script declared in a YAML package. Both entities are present in Core, and the MCP session can list tools and read entity state. The client cannot get either loaded definition through the advertised tool contract.

### Environment

- Home Assistant Core 2026.11.2, stock HA-MCP 9.2.0 over local stdio, and File & YAML companion 9.2.0 active.
- Read Only Mode on. Tool Search off. The failure reproduces with a direct MCP client.

### Minimal reproduction

1. In a disposable Home Assistant instance, set `homeassistant.packages` to `!include_dir_named packages`. Save this file as `packages/definition_contract.yaml` and start Core.

```yaml
automation:
  - id: qualification_packaged_night
    alias: Qualification Packaged Night
    initial_state: false
    triggers:
      - trigger: event
        event_type: qualification_unfired_event
    conditions:
      - condition: time
        after: "19:00:00"
        before: "06:00:00"
    actions:
      - event: qualification_automation_only
    mode: single
script:
  qualification_packaged_speakers:
    alias: Qualification Packaged Speakers
    sequence:
      - event: qualification_script_only
    mode: single
```

2. Confirm `automation.qualification_packaged_night` and `script.qualification_packaged_speakers` are present in Core. Call `ha_config_get_automation` with the automation `entity_id` and `ha_config_get_script` with the script `script_id`.
3. Inspect the `ha_search` schema in `tools/list`. Try each full entity ID as `query`, with `exact_match: true` and `limit: 1`.

### Expected result

An advertised read returns exactly the requested loaded definition. The automation body contains the `qualification_automation_only` action and the script body contains the `qualification_script_only` sequence action.

### Actual result

- The automation getter returns `CONFIG_NOT_FOUND`. The script getter returns `RESOURCE_NOT_FOUND`.
- The advertised exact search returns no loaded body for either entity. `tools/list` omits `include_config` and `search_types` from `ha_search` with the companion active.
- As a diagnostic control, the same stock server returns the exact loaded definition when given the following arguments in a direct `tools/call` to `ha_search`. For the script, use `script.qualification_packaged_speakers` and `["script"]`. Both reads worked with Read Only Mode on.

```json
{
  "query": "automation.qualification_packaged_night",
  "exact_match": true,
  "include_config": true,
  "search_types": ["automation"],
  "limit": 1
}
```

The control suggests a discoverability problem in the companion-backed search schema. Could HA-MCP advertise a supported exact loaded-definition read for package-backed automations and scripts?
