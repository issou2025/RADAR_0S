# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**feat(trace): the remaining uncaught paths reach the trace, nothing is written past the redactor, and the owner decides whether errors leave the device**

*Project description:*
Part of **#4391** (X7). Follows the closed #742. Touches `lib/main.dart`, `lib/core/trace`.

## Outcome

An error thrown outside the framework's two handlers, inside a background isolate or while building a widget is recorded like any other. Whether recorded errors are ever sent to a server is decided and written down.

## Measured (master b4e4bde00)

- Present: `FlutterError.onError`, `PlatformDispatcher.instance.onError` (returns false), `TraceProviderObserver`.
- Absent: `runZonedGuarded` around `runApp`, `ErrorWidget.builder` (a failed build shows the framework's grey box in release), an error listener for the three `compute(` sites.
- `lib/core/trace/guarded.dart:66,76` writes the message and the exception with `debugPrint`, beside the facade and so past `redaction.dart`. 54 further `debugPrint(` inside catch bodies, 5 of them with no facade call.
- The sink is a 500-entry ring and `deskilo-trace.log` (512 KB, rotated), exported by hand from the developer screen. No remote sink, no server table.

## Decision for the owner (before the last checkbox)

Should errors leave the device at all? Options: (a) stay local as today; (b) an opt-in "send this trace" action that posts the redacted log to the installation's own server; (c) automatic reporting of redacted error entries to the installation's own server. (b) and (c) need a privacy statement, a retention rule and a place in the operator's view. Until decided, nothing is sent.

## Shape

- [ ] `ErrorWidget.builder` showing a worded, localised failure tile in release and tracing the error.
- [ ] `runZonedGuarded` around start-up, or a note in `trace_hooks.dart` stating why `PlatformDispatcher.onError` covers it on every target, proven by a test.
- [ ] Isolate work goes through one helper that returns failures to the main isolate's trace.
- [ ] `debugPrint` leaves `guarded.dart`; a lint at 0 for `debugPrint(` inside a catch body without a facade call.
- [ ] The decision, then its implementation if (b) or (c).

## Acceptance (testable)

- A widget test with a child that throws in `build` shows the worded tile and one trace entry.
- A test throws inside a `compute` callback and finds the entry in the trace.
- `rg -n "debugPrint" lib/core/trace/guarded.dart` returns nothing.
