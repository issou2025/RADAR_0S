Design context: [`docs/pipeline-design.md`](https://github.com/Nikola1Davydov/AnalyzeTool/blob/claude/pipelines-plan-f8jrgf/docs/pipeline-design.md) §"No modal dialogs".

## What the code shows

Eight transaction sites. Six carry `SwallowWarningsPreprocessor` (Families slice —
`FamilyActionsService` ×4, `LibraryService`, `PlaceFamilyInstance`). Two do not:
`SetDataToParameters` (the bulk parameter write) and `IsolationInRevit`. `ExecuteRevitCode`
(`Destructive = true`) is uncovered by construction — the script author writes the transaction.

A modal failure dialog raised inside one of these blocks the Revit thread **inside**
`RevitTaskHub.Execute`, whose `while (_queue.TryDequeue(...))` loop is the single path to the
model for every transport. One dialog freezes the whole platform, not one command.

`RevitBridgeClient.InvokeAsync` had **no timeout** (list has 8s, connect 3s), so an MCP agent
calling into a blocked Revit hung until its own client gave up.

Diagnostics do survive this, and that part was already right: `GetQueueStatus` never touches
the Revit thread, and `RevitAvailability.IsRevitBusy` detects the stall within ~1.5s.

## Done — first pass, commit `b8f2156` on `claude/pipelines-plan-f8jrgf`

- [x] `Tools/Shared/FailureHandling.cs` — `CollectingFailuresPreprocessor`: deletes warnings so
      no modal is raised, but **records them first**. Errors untouched, so an invalid edit still
      rolls back.
- [x] `SetDataToParameters` covered; returns `{ ok, written, skipped, warnings }` instead of
      `null`. A caller could not previously tell 500 successful writes from 460 successes and
      40 silently dropped items. (This is the one command whose result type arrives inside #88
      rather than #89 — warnings need somewhere to live.)
- [x] `IsolationInRevit` covered; reports a non-modifiable active view instead of a bare `null`
      indistinguishable from "nothing to do".
- [x] **`Destructive` flag repaired.** It carried three extension-management commands and
      parameter writes, but NOT `DeleteFamilyElements`, `PurgeFamilies`, `PurgeFamilyTypes`,
      `RenameFamily`, `RenameFamilyType`, `SetInstancesWorkset`, `LoadLibraryFamilies` — so any
      rule keyed on it (like the approval gate in #92) would have gated the harmless case and
      waved the irreversible one through. All seven now marked.
- [x] `PlaceFamilyInstance` marked `Destructive`, and its description now says placement blocks
      on a user click so an unattended caller must not dispatch it — it is advertised over MCP
      with nothing previously saying so.
- [x] `RevitBridgeClient.InvokeAsync` bounded at 10 minutes, with an error pointing at
      `GetQueueStatus`. Generous on purpose: real work takes minutes, and a timeout that fires
      on legitimate work is worse than none. A caller's own cancellation still propagates as
      cancellation rather than being mislabelled a timeout.

⚠️ **Not compiled and not run** — the authoring environment has neither `dotnet` nor Revit.
Needs a build on Windows before it is trusted.
