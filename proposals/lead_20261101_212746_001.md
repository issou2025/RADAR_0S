# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Classes of a few small elements depend on block counts of the byte scan and change when unrelated records are removed**

*Project description:*
The class of some small elements is decided by the block counts of the heuristic byte scan, and a change in unrelated bytes can move a false positive block from one element to another. In the sample project jp_sample_3 (Revit 2022), removing four superseded records that belong to two link symbols (ids 19291850 and 19291853) made element 19 (a line pattern) lose its class while element 28 (a material) gained its class. Neither element is stored twice.

The effect is one class slot in one sample file today, but it shows the class of tiny elements is not decided by their own record. Needed: take the class of these elements from their own root record by the file schema, or reject a block count that is not backed by the element table, and add a test with a file where the surrounding records change.
