# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Per-chunk block scan stops at a header-like byte run for an element that is not in the element table and hides the current block behind it**

*Project description:*
The per-chunk block walk stops at a byte run that looks like a block header when the element named by the run is not in the element table. When the run lies in front of a real block, the block is never reached. Example in the Revit 2021 advanced architecture sample: wall 143858 has its root block (19,946 bytes) in a chunk, but a header-like run 134 KB earlier, for element id 182663, makes the scan jump over it. The problem was hidden while old copies of other elements sat near the start of other chunks and were reached instead.

A mitigation (continue after the run instead of stopping, and read the drive curve of a wall from its exact root block) is applied only when superseded element copies are removed. The same fragility exists in all other files and is not measured. Needed: measure how often a header-like run for an undeclared element precedes a real block across the sample files, and make the scan resynchronise on the block framing of the schema instead of stopping.
