## The rule

**A test build leaves only through one workflow, from main, signed with keys that live only in GitHub's secrets.**

| Part | Android, on Linux | iPhone, on macOS |
| --- | --- | --- |
| Built by | `flutter build apk --release` | `flutter build ios --no-codesign`, then `xcodebuild archive` |
| Signed with | REDIX's upload key, written from secrets into `android/key.properties` | Apple's distribution certificate, which Xcode creates and keeps in Apple's cloud, through an App Store Connect API key |
| Checked before upload | The APK's certificate fingerprint is REDIX's (`apksigner verify --print-certs`: `keytool -printcert` reads only the old JAR signature, which this APK does not carry) | Apple checks the signature itself |
| Sent with | Firebase's own CLI, `appdistribution:distribute`, group `testers` | `xcodebuild -exportArchive`, destination upload |
| Version | `1.0.0` from `pubspec.yaml`; build number = the workflow's run number | same |
| Server | `config/prod.json`: `API_BASE_URL` `https://<domain>:8443`, `LINK_HOST` `<domain>` | same |

Secrets: `ANDROID_UPLOAD_KEY`, `ANDROID_UPLOAD_KEY_PASSWORD`, `ANDROID_UPLOAD_KEY_SHA256`, `FIREBASE_SERVICE_ACCOUNT`, `FIREBASE_ANDROID_APP_ID`, `APP_STORE_CONNECT_KEY`, `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APPLE_TEAM_ID`.

## Acceptance criteria

- CI's unsigned iPhone build passes on a push.
- A run of "Test builds": the fingerprint check passes; Firebase shows 1.0.0 (N); the testers are emailed.
- The HUAWEI installs the build from the email's link (R9).
- TestFlight shows 1.0.0 (N) ready to test with no export question; an iPhone installs it.
- A second run shows N+1 on both.
- A run with `API_BASE_URL` empty stops before building; a run without the upload key stops before uploading.
