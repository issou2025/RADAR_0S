## Project Understanding
You need assistance with: 
**get_reference_line ignores Axis representations in "Model" contexts (Revit/ArchiCAD exports), and regenerate_wall_representation silently rebuilds walls from the 1 m fallback axis**

*Project description:*
### Bug Description

### Description

`ifcopenshell.util.representation.get_reference_line` only looks for a wall's Axis representation in a **"Plan"** context:

```python
if axis := ifcopenshell.util.representation.get_representation(wall, "Plan", "Axis", "GRAPH_VIEW"):
```

Real-world exporters put the Axis subcontext under **"Model"** instead:

- **Revit 26.5.0.55** (ODA SDAI 25.12), IFC4 Design Transfer View: `ContextType='Model'`, `ContextIdentifier='Axis'`, `TargetView='GRAPH_VIEW'`. Measured on a fresh export of a residential building: **2 178 of 2 178 walls** carry a genuine `IfcPolyline` axis under that subcontext, and `get_reference_line` finds none of them.
- **ArchiCAD 20** (the AC20-FZK-Haus sample): `ContextType='Model'`, `TargetView='MODEL_VIEW'` — also missed by the "Plan" lookup (that file happens to survive via the extrusion fallback, see below).

(Bonsai authors wall axes under a `"Plan"`/Axis/GRAPH_VIEW subcontext, which is presumably why the lookup works fine for Bonsai-authored files.)

When the "Plan" lookup misses, the extrusion fallback only understands profiles whose `OuterCurve` is an `IfcPolyline` or `IfcIndexedPolyCurve`. `IfcRectangleProfileDef` (which has no `OuterCurve`) and `IfcCompositeCurve` outer curves fall through, so the function silently returns the **fallback axis of length 1** — and `regenerate_wall_representation` (and `connect_wall`, which also calls `get_reference_line`) then rebuilds the wall from that fictitious axis without any warning or error.

Measured consequence on the Revit file: calling `regenerate_wall_representation` on an *untouched* wall turned a 1.474 m wall into a 1 718.4 m wall. Reproduced identically on ifcopenshell **0.8.5** and **0.9.0.post1** (pip wheels, Python 3.13, Linux).

### Minimal reproduction (no external files needed)

```python
import numpy as np
import ifcopenshell
import ifcopenshell.api.aggregate, ifcopenshell.api.context, ifcopenshell.api.geometry
import ifcopenshell.api.material, ifcopenshell.api.project, ifcopenshell.api.root
import ifcopenshell.api.spatial, ifcopenshell.api.unit
import ifcopenshell.util.representation
import ifcopenshell.geom

f = ifcopenshell.api.project.create_file(version="IFC4")
project = ifcopenshell.api.root.create_entity(f, ifc_class="IfcProject")
ifcopenshell.api.unit.assign_unit(f, length={"is_metric": True, "raw": "METERS"})
model = ifcopenshell.api.context.add_context(f, context_type="Model")
body_ctx = ifcopenshell.api.context.add_context(f, context_type="Model", context_identifier="Body", target_view="MODEL_VIEW", parent=model)
# Axis subcontext exactly as Revit 26.5 (ODA SDAI 25.12) writes it: ContextType "Model", NOT "Plan"
axis_ctx = ifcopenshell.api.context.add_context(f, context_type="Model", context_identifier="Axis", target_view="GRAPH_VIEW", parent=model)

site = ifcopenshell.api.root.create_entity(f, ifc_class="IfcSite")
building = ifcopenshell.api.root.create_entity(f, ifc_class="IfcBuilding")
storey = ifcopenshell.api.root.create_entity(f, ifc_class="IfcBuildingStorey")
ifcopenshell.api.aggregate.assign_object(f, products=[site], relating_object=project)
ifcopenshell.api.aggregate.assign_object(f, products=[building], relating_object=site)
ifcopenshell.api.aggregate.assign_object(f, products=[storey], relating_object=building)

wall = ifcopenshell.api.root.create_entity(f, ifc_class="IfcWall")
ifcopenshell.api.spatial.assign_container(f, products=[wall], relating_structure=storey)
ifcopenshell.api.geometry.edit_object_placement(f, product=wall, matrix=np.eye(4))

# genuine 5 m axis
axis_pl = f.createIfcPolyline([f.createIfcCartesianPoint((0.0, 0.0)), f.createIfcCartesianPoint((5.0, 0.0))])
axis_rep = f.createIfcShapeRepresentation(axis_ctx, "Axis", "Curve2D", [axis_pl])
# body: 5.0 x 0.2 x 2.4 m extrusion with IfcRectangleProfileDef (a very common exporter form)
profile = f.createIfcRectangleProfileDef("AREA", None, f.createIfcAxis2Placement2D(f.createIfcCartesianPoint((2.5, 0.0)), None), 5.0, 0.2)
solid = f.createIfcExtrudedAreaSolid(profile, None, f.createIfcDirection((0.0, 0.0, 1.0)), 2.4)
body_rep = f.createIfcShapeRepresentation(body_ctx, "Body", "SweptSolid", [solid])
wall.Representation = f.createIfcProductDefinitionShape(None, None, [axis_rep, body_rep])

ref = ifcopenshell.util.representation.get_reference_line(wall)
print(f"get_reference_line: {[list(p) for p in ref]}   <- expected [[0,0],[5,0]], the real axis")

# consequence: regenerate destroys the wall (material layer usage added for thickness)
ms = ifcopenshell.api.material.add_material_set(f, name="w", set_type="IfcMaterialLayerSet")
mat = ifcopenshell.api.material.add_material(f, name="m")
layer = ifcopenshell.api.material.add_layer(f, layer_set=ms, material=mat)
ifcopenshell.api.material.edit_layer(f, layer=layer, attributes={"LayerThickness": 0.2})
ifcopenshell.api.material.assign_material(f, products=[wall], type="IfcMaterialLayerSetUsage", material=ms)

def length_x(w):
    sh = ifcopenshell.geom.create_shape(ifcopenshell.geom.settings(), w)
    v = np.array(sh.geometry.verts).reshape(-1, 3)
    return (v.max(0) - v.min(0))[0]

print(f"wall length before regenerate: {length_x(wall):.3f} m")
ifcopenshell.api.geometry.regenerate_wall_representation(f, wall=wall)
print(f"wall length after  regenerate: {length_x(wall):.3f} m   <- silently rebuilt from the 1 m fallback axis")
print(f"ifcopenshell {ifcopenshell.version}")
```

Output — identical on 0.8.5 and 0.9.0.post1:

```
get_reference_line: [[0.0, 0.0], [1.0, 0.0]]   <- expected [[0,0],[5,0]], the real axis
wall length before regenerate: 5.000 m
wall length after  regenerate: 1.000 m   <- silently rebuilt from the 1 m fallback axis
```

### Expected behaviour / suggestions

1. `get_reference_line` finds the genuine Axis representation also when the subcontext's `ContextType` is `"Model"` (the Revit/ODA and ArchiCAD form) — e.g. by also trying `("Model", "Axis", "GRAPH_VIEW")` and `("Model", "Axis")` after the current `("Plan", "Axis", "GRAPH_VIEW")` lookup.
2. Ideally the extrusion fallback could also handle `IfcRectangleProfileDef` (via `XDim`, where the profile position allows) — though with the Axis lookup fixed this matters much less.
3. `regenerate_wall_representation` (and `connect_wall`) should refuse or warn when only the length-1 fallback axis is available, rather than silently rewriting a wall's geometry from a fictitious axis.

Happy to test a fix against the Revit 26.5 export we measured on.
