## Research Findings

_Research conducted 2026-08-03 against branch `9-agent-tool-set` (worktree of `main`)._

### Summary

Three new agent-tool areas requested: folder creation, project user management, and Revit linked-files listing. The repo already has a well-established tool-registration pattern in `Tools/BimManagerAssistantTools.cs` + `Services/AgentChatService.cs` — every new tool slots into that class as a `[Description]`-annotated method and gets wired into the `AIFunctionFactory.Create(...)` array. All three features can reuse existing infrastructure:

- **Folder creation**: no existing create-folder code anywhere in the repo. `DataManagementClient` is registered and used for READS only (`GetProjectTopFoldersAsync`, `GetFolderContentsAsync`, `GetItemParentFolderAsync`). The `Autodesk.DataManagement` SDK v2.1.3 is present; whether it exposes a create-folder method or a raw HTTP `POST /data/v1/projects/{projectId}/folders` is needed remains to be confirmed against the SDK.
- **User management**: `AdminClient` (from `Autodesk.Construction.AccountAdmin`) is registered but only two calls exist repo-wide (`GetProjectUserAsync` in `ProjectRoleService`, `GetProjectAsync` in `Chat.razor`). No hub user search, no project user listing, no user add, no company/role assignment code exists yet — all must be added.
- **Revit linked files**: `Services/AccLinkedFilesService.cs` already implements the ACC RCM linked-files endpoint (`GET /construction/rcm/v1/projects/{projectId}/published-versions/{versionUrn}/linked-files`) and is consumed only by `Components/Pages/LinkMatrix.razor`. Wrapping it as an agent tool is straightforward — inject `IAccLinkedFilesService` into `BimManagerAssistantTools`, resolve tip version URN from an item (pattern already used at `LinkMatrix.razor:485`).

### Key Discoveries

- Tool registration pattern is centralized in two files: `Tools/BimManagerAssistantTools.cs:14-22` (primary constructor DI) and `Services/AgentChatService.cs:30-36` (`AIFunctionFactory.Create(...)` array). New tools just add a `[Description]`-decorated public method and one entry to that array.
- Context injection uses instance properties, not method parameters: `HubId`, `ProjectId`, `ConversationId` (`Tools/BimManagerAssistantTools.cs:27-29`). Set from `Components/Pages/Chat.razor:616,637,697`. `RequireHubId()` / `RequireProjectId()` / `RequireConversationId()` guards throw `InvalidOperationException` when unset (`Tools/BimManagerAssistantTools.cs:362-390`).
- Access token comes from `session.AccessToken` inside each tool (3-legged user token). A 2-legged app token is available via `IAPSAuthenticationService.GetTwoLeggedTokenAsync()` for webhook management only (`Tools/BimManagerAssistantTools.cs:300`).
- Long-running work uses `IAgentTaskService.CreateTaskAsync / UpdateTaskAsync / FailTaskAsync` for a task-panel entry with `Pending → Running → Completed/Failed` states (`Services/AgentTaskService.cs`, `Models/AgentTaskInfo.cs`, `Models/AgentTaskStatus.cs`). Reference impl: `PublishRevitModelAsync` at `Tools/BimManagerAssistantTools.cs:57-127`.
- `RevitAutomationTools` is registered (`Extensions/AutodeskServiceExtensions.cs:36`) but NOT wired into `AgentChatService.tools:[]` — only consumed directly from Blazor pages. Separate parallel path; new tools targeted at the chat agent must go through `BimManagerAssistantTools`.

### Detailed Findings

#### Folder creation

**Existing folder API usage** (all read-only):
- `dataManagementClient.GetProjectTopFoldersAsync(hubId, projectId, accessToken)` — `Tools/BimManagerAssistantTools.cs:40`
- `dataManagementClient.GetFolderContentsAsync(projectId, folderId, accessToken)` — `Tools/BimManagerAssistantTools.cs:396`
- `dataManagementClient.GetItemParentFolderAsync(projectId, itemId, accessToken)` — `Tools/BimManagerAssistantTools.cs:287`
- Raw HTTP GET on `/data/v1/projects/{projectId}/folders/{folderId}` in `Services/NamingStandardsService.cs:60` (reads folder extension data for naming standards).
- SDK types imported: `FolderData`, `ItemData` in `Autodesk.DataManagement.Model` — pattern-matched in `Tools/BimManagerAssistantTools.cs:405-409` and Razor pages.

**Precedent for POST via raw HTTP** if the SDK lacks a create-folder method: `Tools/BimManagerAssistantTools.cs:210-219` posts to `/data/v1/projects/{projectId}/commands` using `IHttpClientFactory` + bearer auth from `session.AccessToken`.

**Structure creation option**: agent could accept a nested folder spec (e.g. `["Design", "Design/Architecture", "Design/Structure", ...]`), create each recursively, and use `IAgentTaskService` to track a multi-step job so partial failures surface. Payload per POST follows JSON:API shape used by other Data Management commands (see the `PublishModelPayload` composition at `Tools/BimManagerAssistantTools.cs:71-96`).

#### User management

**Currently wired** (only these two `AdminClient` calls exist repo-wide):
- `adminClient.GetProjectUserAsync(projectId, userId, accessToken)` — `Services/ProjectRoleService.cs:28` (single-user lookup for role names).
- `AdminClient.GetProjectAsync(projectId, accessToken)` — `Components/Pages/Chat.razor:690` (project metadata + `AccountId`).

**`IProjectRoleService`** (`Services/IProjectRoleService.cs:3-7`):
- `GetProjectRolesAsync(projectId, userId, accessToken) → IReadOnlyList<string>` — implemented at `Services/ProjectRoleService.cs:14-47`. Strips `b.` prefix (lines 24-26) to convert DM project ID → Account Admin project ID, then wraps `AdminClient.GetProjectUserAsync`, caching results by project ID.
- `IsBimManagerAsync(projectId, userId, accessToken) → bool` — `Services/ProjectRoleService.cs:49-53`.

**What must be added** — none of these exist yet:
- Hub/account user search (by name or email): no `GetUsersAsync` / `SearchUsersAsync` call anywhere.
- Project user listing (plural): no `GetProjectUsersAsync` call anywhere.
- Project user add: no `AddProjectUserAsync` / `CreateProjectUserAsync` / `PatchProjectUserAsync` anywhere.
- Companies: no `GetCompaniesAsync`.
- Role enumeration: no `GetRolesAsync`.

**Wiring implication**: `AdminClient` is not currently injected into `BimManagerAssistantTools` (`Tools/BimManagerAssistantTools.cs:14-22`). New user tools require adding it as a constructor param. Alternatively, wrap all new calls behind an expanded `IProjectRoleService` (or new `IProjectUserService`) and inject that.

**Note on IDs**: Data Management project IDs are prefixed with `b.` (e.g. `b.<guid>`); Account Admin expects the raw GUID. The `.TrimStart('b','.')`-style conversion is already in `Services/ProjectRoleService.cs:24-26` and must be applied for every new AdminClient call.

**Auth scopes**: user info endpoint already requested via `AccountRead` scope at `Controllers/AuthController.cs:24`. Writing project users (add/assign role) may need an additional scope (e.g. `account:write` / `data:write`) — to be confirmed against the AdminClient SDK requirements.

#### Revit linked files

**`Services/AccLinkedFilesService.cs`** — endpoint already implemented:
- `GetLinkedFilesAsync(accessToken, projectId, versionUrn) → AccLinkedFilesResponse?` — `Services/AccLinkedFilesService.cs:14-51`.
- URL: `https://developer.api.autodesk.com/construction/rcm/v1/projects/{projectId}/published-versions/{encodedVersionUrn}/linked-files?includeHost=false` — `Services/AccLinkedFilesService.cs:25`.
- Requires a **published** version URN, not a tip item version URN. `LinkMatrix.razor:485` shows the pattern to extract the tip version from `itemData.Relationships?.Tip?.Data?.Id`.
- Response model at `Services/AccLinkedFilesService.cs:55-104`: `AccLinkedFilesResponse.LinkedFiles.Results` is a `List<LinkedFile>` where each `LinkedFile` has `ModelName`, `SignedUrl`, `ItemId`, `VersionId`, `PublishStatus`.
- Only consumer today: `Components/Pages/LinkMatrix.razor:9` (`@inject`), invoked at lines 519-522 inside `LoadLinksForAllModels()`.
- DI registration: `Extensions/AutodeskServiceExtensions.cs:33` (`AddScoped<IAccLinkedFilesService, AccLinkedFilesService>()`).

**New tool shape** (drop into `BimManagerAssistantTools`):
1. Add `IAccLinkedFilesService accLinkedFilesService` to the primary constructor (`Tools/BimManagerAssistantTools.cs:14-22`).
2. New method takes item ID (or model name resolved via `ListRevitModelsAsync`), calls `DataManagementClient.GetVersionAsync` (pattern at `LinkMatrix.razor:547`) or resolves tip version from item metadata, then calls `accLinkedFilesService.GetLinkedFilesAsync(session.AccessToken, RequireProjectId(), versionUrn)`.
3. Return a strongly-typed list (mirror the `RevitModelInfo` pattern at `Tools/BimManagerAssistantTools.cs:426-430`).

**Existing agent link-modification path** — `Tools/RevitAutomationTools.cs:10-36` `LinkModification` is a Design Automation workitem (not the ACC linked-files endpoint) and takes `modelName` + `modelGuid` per link (`Tools/RevitAutomationTools.cs:109-116`). Model GUIDs come from Data Management version extension data (`LinkMatrix.razor:547-565` reads `version.Data.Attributes.Extension.Data["projectGuid"]` and `["modelGuid"]`). Unrelated to the linked-files listing tool — different SDK, different data source.

### Decisions

- **Roles + company on user add**: The agent must ask the user for the role and company to assign before calling the add-user tool. Do not infer or default these values.
- **Project type scope**: Target Construction Cloud projects only. No hub-type branching (`hubs:autodesk.bim360:Account` vs personal vs other) — the `b.`-prefix strip in `Services/ProjectRoleService.cs:24-26` applies universally.
- **Folder creation idempotency**: The agent must ask the user to confirm before creating folders. Do not create silently.
- **Task-tracking for folder structure**: One `IAgentTaskService` task per folder-structure creation operation (not one task per individual folder). Use `AgentTaskInfo.ProgressDetail` for incremental progress within that single task.

### Open Questions

- Does `Autodesk.DataManagement` v2.1.3 expose a create-folder method on `DataManagementClient`? If not, use `IHttpClientFactory` + raw POST to `/data/v1/projects/{projectId}/folders` (JSON:API payload with `type=folders`, `attributes.name`, `attributes.extension.type=folders:autodesk.bim360:Folder`, `relationships.parent.data`).
