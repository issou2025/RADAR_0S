### v0.2 vision — what “top tier” means here

v0.1 is a **deterministic assembler**. v0.2 should behave like an **enterprise presentation platform layer** that agents and automation pipelines can trust in production:

| Dimension | v0.1 today | v0.2 target |
| :--- | :--- | :--- |
| Input contract | Loose JSON Schema; empty slides possible | Per-layout required fields + narrative lint + archetype hints |
| Visual quality | Fixed templates + 3 theme tokens | Vibe-driven themes, auto-fit typography, brand kits, contrast-safe palettes |
| Images | path/base64 only; silent text-only fallback | Placeholders, crop/fit policy, normalization, optional gen behind gates |
| Existing decks | Read-only `inspect` | Extract → patch → re-render round-trip (Skillware-native first, external best-effort) |
| Enterprise fit | Offline render | Brand governance, classification banners, accessibility lint, audit metadata |
| Agent UX | Instructions + schema | Worked examples, deck archetypes, `lint_deck`, diff/preview actions |
| Production hardening | Happy-path tests | Golden PPTX regression, cross-viewer smoke notes, edge-case matrix |

**Design invariant (unchanged):** Agent owns narrative and asset acquisition; skill owns assembly, validation, and file fidelity. No LLM calls inside default `execute()`.

### Goals (v0.2)

#### 1. Smart images — placeholders and optional generation

**Problem:** v0.1 accepts `image.path` or `image.base64` only. Agents often supply URLs as paths (`ASSET_NOT_FOUND`) or omit images entirely.

| Mode | Behavior |
| :--- | :--- |
| `placeholder_id` | Bundled neutral placeholders per layout (hero, logo, icon, chart backdrop, team headshot silhouette). Render immediately; user swaps in PowerPoint. |
| `placeholder_prompt` | Agent supplies alt-text / visual brief; skill renders styled placeholder slide with caption (no network). |
| `fit` policy | Per image: `cover`, `contain`, `crop_center`, `native` — prevents stretched logos and clipped screenshots. |
| `generate` *(opt-in)* | Host/agent calls image API **outside** skill by default; optional `action=resolve_assets` or manifest-gated `generate_images=true` with `GEMINI_API_KEY` / `OPENAI_API_KEY` for Imagen/DALL·E/Gemini Image — **document env vars, rate limits, dry-run, and confirmation gate**. |
| Public-domain search | **Do not** embed stock search in core skill. Prefer separate registry skill (e.g. `creative/stock_image_finder`) returning local paths, composed via chain before `render`. |

**Image pipeline hardening:**

- Normalize with Pillow: EXIF orientation, max dimension, max file size, reject empty/corrupt inputs
- Color space: convert CMYK → RGB; preserve PNG alpha; document SVG policy (rasterize via optional `cairosvg` extra or reject with clear error)
- DPI targets: projection (96–150 DPI effective) vs print handout (220+ DPI) — `deck_spec.output_profile`
- Aspect ratio mismatch: letterbox vs crop vs agent warning (`IMAGE_ASPECT_MISMATCH`)
- Duplicate asset dedup: same path/base64 on multiple slides → embed once (file size)
- Alt text / accessibility: `image.alt` required when `strict_a11y=true`; surfaced in `lint_deck`
- Optional watermark on placeholders: “Replace before external distribution”

**Acceptance:** Agent can build image-heavy decks without user assets; missing images never silently fail; copyright-safe defaults documented in `instructions.md`.

---

#### 2. Theme & aesthetics — describe the vibe

**Problem:** v0.1 theme tokens are manual hex/fonts. Users want “warm fintech”, “Apple keynote minimal”, “dark cyberpunk”, or “match our re:Invent deck”.

- Extend `deck_spec.theme` with optional `vibe` (free text) and/or structured tokens: `palette`, `mood`, `density`, `corner_style`, `shadow_depth`, `background_style`
- New action `derive_theme` *(optional, offline)*: map vibe string → token set using bundled palette library (deterministic lookup table, not LLM in `execute()`)
- Optional host-side LLM step documented in `instructions.md`: agent converts user aesthetic → `theme` block before render
- Template expansion: **≥2 new masters** (e.g. `dark_pitch_v1`, `editorial_v1`, `data_dense_v1`) + documented layout indices
- Per-slide overrides: `background_color`, `title_color`, `hide_footer`, `emphasis` (callout box)
- **Brand kit import:** optional `brand_kit_path` or inline `brand_kit` object — primary/secondary/neutral colors, logo paths, font stack, footer legal line, default classification label
- **Contrast safety:** validate WCAG AA contrast for title/body on background; auto-adjust or emit `CONTRAST_FAIL` in strict mode
- **Font fallback chain:** document Linux/macOS/Windows substitution (e.g. Calibri → Carlito → Arial); bundle no licensed fonts — use system-safe stacks

**Acceptance:** Same narrative spec + different `theme.vibe` produces visibly distinct decks without hand-picking hex codes; contrast failures are actionable before render.

---

#### 3. Rework existing PPTX — not just inspect

**Problem:** `inspect` is read-only. Users import decks from colleagues, Gamma exports, template vendors, or older Skillware output and want surgical edits without rebuilding from scratch.

| Action | Purpose |
| :--- | :--- |
| `extract_spec` | Read arbitrary `.pptx` (Skillware or external) → partial `deck_spec` + `source_manifest` (layouts, placeholders, unmapped content flagged) |
| `merge_spec` | Apply `deck_spec` delta to existing file: append/replace slides by index or title match, update text/charts where mappable |
| `render_patch` | `input_path` + `patch_spec` → new `output_path`; preserve foreign master slides when possible |
| `diff_specs` | Compare two `deck_spec` objects or extracted specs → human/agent-readable change list |

**Constraints:**

- Best-effort for external decks — document limitations (custom masters, grouped shapes, SmartArt, embedded OLE, morph transitions)
- Never mutate `input_path` in place; always write new file
- Fail closed on unsafe paths; same traversal rules as v0.1
- Reject or quarantine: password-protected pptx, macro-enabled `.pptm`, encrypted packages — clear `UNSUPPORTED_INPUT_FORMAT`

**Round-trip fidelity targets:**

- Skillware-generated deck: ≥95% text + notes recoverable via `extract_spec`
- External corporate template deck: titles + body text + notes where shape tree is flat; flag unmapped shapes in `source_manifest.unmapped[]`
- Charts: extract categories/series when native chart data accessible; else placeholder + warning

**Acceptance:** Round-trip test: render v0.1 deck → `extract_spec` → modify one bullet → `render_patch` → inspect shows updated text; external sample `.pptx` extracts titles + notes without crash.

#### 4. Schema & agent ergonomics

- JSON Schema **per slide type** `required` fields — clearer agent errors than empty slides
- `instructions.md`: worked examples for NL prompt → full 7-slide `deck_spec`; explicit **“URLs are not paths — download first or use base64”** (reinforce v0.1 rule)
- Optional `deck_spec.version` field for forward compatibility (`"1.0"`, `"1.1"`)
- `list_layouts` action (or extend `list_templates`): character limits, recommended bullet counts, example JSON snippets per type, “when to use” guidance
- **`deck_spec` JSON Schema published** as `$id` URL in bundle for agent/tooling validation outside Python
- Constraint hints for agents: max slides per deck, max bullets per slide, max title length — returned by `validate_spec` as structured `limits` object
- **Error/warning code catalog** in `instructions.md` and catalog page (all v0.1 + v0.2 codes with fix hints)

#### 6. Enterprise brand & governance

- **Classification banners:** `metadata.classification` → `CONFIDENTIAL`, `INTERNAL`, `PUBLIC` ribbon on master or per-slide
- **Document metadata:** author, subject, company, revision, `created_at`, `deck_id` (UUID), `source_spec_hash` for audit trails
- **Legal footer:** configurable boilerplate (© year, forward-looking statements, etc.)
- **Custom template upload:** `template_path` param pointing to validated `.potx`/`.pptx` master (path-safe, no network)
- **Template locking:** `theme_locked: true` prevents agent from overriding brand colors/fonts except via approved tokens
- **Locale / i18n hooks:** `deck_spec.locale` (`en-US`, `de-DE`) → number/date formatting; document RTL limitations in v0.2 (full RTL = v0.3 candidate)
- **Print vs screen profiles:** `aspect_ratio` `16:9` \| `4:3` \| `16:10`; warn when content density unsafe for projector readability

---

#### 7. Layout engine & typography intelligence

- **Auto-fit text:** shrink font within bounds before truncating; emit `TEXT_OVERFLOW` if still impossible
- **Dynamic bullet density:** reduce font or split across continuation slide when >N bullets or >M chars
- **Safe margins & grid:** enforce minimum padding from slide edges
- **Typography scale:** map `theme.density` → H1/H2/body pt sizes consistently across layouts
- **Orphan control:** avoid single bullet on otherwise empty slide — suggest merge in `lint_deck`
- **Consistent punctuation & casing lint:** optional `lint_deck` rules (trailing periods on titles, ALL CAPS titles)
- **Speaker notes separation:** never leak notes into visible slide body on extract/render

---

#### 8. Data fidelity — charts, tables, and numbers

- **Strict chart validation:** category count = every series length; reject NaN/Inf; empty categories forbidden in strict mode
- **Number formatting:** `chart.series[].format`, table cell types (`currency`, `percent`, `integer`, `date`)
- **Source attribution:** optional `source` field on chart/table slides → rendered as footnote
- **Citable metrics on `metrics` layout:** value + unit + period + delta direction (↑↓)
- **Table overflow:** max rows/cols with `TABLE_TRUNCATED` warning and “see appendix” speaker note suggestion
- **Linked data metadata:** optional `data_ref` (CSV path or URI string for agent traceability — skill does not fetch in default mode)

---

#### 9. Quality gates — `lint_deck` action (new)

Separate from schema validation — **presentation quality** checks agents and CI can gate on:

| Code | Check |
| :--- | :--- |
| `DECK_TOO_LONG` | Slide count exceeds archetype recommendation |
| `WALL_OF_TEXT` | Body chars / bullet count over threshold |
| `CONTRAST_FAIL` | WCAG AA text/background |
| `MISSING_ALT` | Image without alt text (a11y mode) |
| `DUPLICATE_TITLE` | Same slide title repeated |
| `EMPTY_SECTION` | Section divider with no following content slides |
| `NARRATIVE_GAP` | Archetype expects “problem” before “solution” slide |
| `CHART_UNLABELLED` | Chart missing axis context or title |
| `SPEAKER_NOTES_EMPTY` | Training archetype requires notes on all slides |
| `ASSET_LOW_RES` | Image effective DPI below output profile |

`lint_deck` returns `score`, `warnings`, `suggestions[]` (agent-readable fix hints). Integrate with `strict` mode optionally.

| Archetype ID | Typical flow | Slide count hint |
| :--- | :--- | :--- |
| `investor_pitch` | Title → problem → solution → market → traction → team → ask | 10–15 |
| `qbr` | Title → agenda → KPIs → wins → risks → next quarter | 8–12 |
| `technical_deep_dive` | Title → context → architecture → demo → ops → Q&A | 12–20 |
| `training` | Title → objectives → modules → exercise → recap | 10–25 |
| `board_update` | Title → executive summary → financials → strategic items | 6–10 |
| `product_launch` | Title → customer pain → product → features → pricing* → CTA | 8–12 |

*Agent/user constraint flags (e.g. “no pricing”) validated against archetype.*

New action `suggest_outline`: input `{ archetype, topic, constraints[] }` → recommended slide sequence (types + placeholder titles) for agent to fill — **deterministic template**, not generative copy.

#### 11. Agent orchestration & multi-pass workflows

Document and support production agent pipelines:

```text
plan (agent LLM)
  → suggest_outline (skill)
  → draft deck_spec (agent LLM)
  → validate_spec (skill)
  → lint_deck (skill)
  → resolve_assets / bg_remover / stock_image_finder (chain)
  → render (skill)
  → inspect + thumbnail preview (skill)
  → human review
  → render_patch (skill) OR re-render
```

- **`preview_slide`:** render single slide index to temp PNG/PPTX slice — fast iteration without full deck
- **`render` idempotency:** same spec + template + theme + seed → byte-identical output (document any intentional exceptions)
- **Partial failure recovery:** if render fails on slide N, return slides `[0..N-1]` manifest + error
- **Output bundle:** optional `package_output=true` → zip containing `.pptx`, `deck_spec.json`, `manifest.json`, thumbnails/, warnings.log

#### 12. Security, compliance & privacy

- **Default offline:** no network in `render`, `validate_spec`, `extract_spec`, `lint_deck`
- **Optional URL fetch (if ever added):** SSRF protection — block private IPs, file://, redirect chains; allowlist schemes; max bytes; timeout; explicit param `allow_remote_fetch=true`
- **Temp file hygiene:** assets decoded to temp dirs cleaned after render; no world-readable paths by default on Unix
- **PII / secrets lint (optional):** regex scan speaker notes for API keys, SSN patterns → `SENSITIVE_CONTENT` warning
- **Audit metadata in output JSON:** spec hash, skill version, template IDs, timestamp — no user content in logs unless caller opts in
- **Macro rejection:** never execute macros; don’t emit `.pptm` unless explicitly requested and documented

---

#### 13. PPTX interoperability — production checklist

| Edge case | v0.2 handling |
| :--- | :--- |
| PowerPoint vs LibreOffice vs Keynote font metrics differ | Document “verify on target viewer”; golden tests note primary target |
| python-pptx layout index drift when template edited | Template version pin + layout name resolution fallback |
| Grouped shapes on extract | Flatten or skip with `UNMAPPED_GROUP` flag |
| SmartArt / diagrams | Extract text if possible; else preserve as static image reference |
| Embedded Excel chart cache stale | Prefer inline series from spec on render; warn on extract-only decks |
| Unicode / emoji in titles | Test suite with CJK, Arabic, emoji; document font fallback |
| Very long decks (100+ slides) | Performance budget; streaming render option |
| Large embedded images (50MB+) | Pre-render size estimate; `FILE_SIZE_WARNING` |
| Password-protected input | Clear error, no partial read |
| Corrupt OOXML / truncated zip | `INSPECT_FAILED` with parse detail |
| Duplicate internal slide IDs after patch | Regenerate IDs on save per OOXML rules |
| Notes master vs slide notes confusion | Extract stores in `speaker_notes` only |
| Timezone in chart date axes | UTC vs local documented |
| Right-to-left text | v0.2: detect + warn; v0.3: layout mirroring |

---

#### 14. Export, preview & delivery packaging

- **PDF export** (optional extra): slides + optional notes pages; configurable quality
- **PNG/JPEG slide rasterization:** for Slack/email previews; not a substitute for editable pptx
- **Handout layout:** 2-up / 3-up slides per PDF page (via converter)
- **Presenter script export:** concatenate speaker notes → `.md` with slide titles as H2
- **Version diff artifact:** when patching, emit `patch_changelog.json` for agent to summarize for user

#### E. Named YAML chain — validate → lint → render (CI / scripts)

Add to `.skillware.yaml.example`:

```yaml
chains:
  deck_build_pipeline:
    description: Validate, lint, and render a deck_spec from host variables
    steps:
      - skill: creative/deck_builder
        action: validate_spec
        params:
          deck_spec: "{{ deck_spec }}"
          strict: true
      - skill: creative/deck_builder

        params:
          deck_spec: "{{ deck_spec }}"

      - skill: creative/deck_builder
        action: render
        params:
          deck_spec: "{{ deck_spec }}"
          output_path: "{{ output_path }}"
        when: "{{ steps.1.score >= 70 }}"
```

### Acceptance criteria (v0.2.0)

**Core (must ship):**

- [ ] Bundled image placeholders render on `image` / `title` / `team` slides when no asset supplied (configurable policy)
- [ ] Image `fit` policy prevents obviously stretched/cropped logos in tests
