**Serve the bundled web client from the API**

*Project description:*
## Problem

The Flutter web client must share an origin with the API. It builds request URLs from the browser origin and signs in with same-origin, httpOnly session cookies. Its `docs/dev/web-proxy.md:3-8` says "in production the client is served from the backend origin", but nothing serves it.

Bundling the built client into the BGE image and serving it from the API's HTTP server gives a self-hoster one origin and no proxy to configure. Each backend build also ships the client built for it. That reduces deployment mismatch, but it does not remove compatibility work: open tabs, cached files and installed mobile apps keep talking to newer servers (BoardGamesEmpire/board-games-empire-client#263).

## Scope

### Delivery into the image

- The client publishes its web build as a digest-pinned assets image (BoardGamesEmpire/board-games-empire-client#418). The BGE Dockerfile copies it with `COPY --from=<image>:<version>@sha256:…`.
- Renovate's dockerfile manager tracks `COPY --from` references, so once Renovate runs on this repo (#599) a client bump arrives as a PR.
- A SHA-256-verified tarball is the fallback if an image proves awkward.
- The image records the client's version and digest in its OCI labels (#593).

### Serving

An optional static-serving capability on the API's existing HTTP server, not a separate role, and off when the image carries no client.

- **Server routes keep precedence:**
  - `/api/*`, including better-auth's `/api/auth/*`, which mounts on raw Express before Nest;
  - `/.well-known/*`;
  - `/health*` and `/metrics`;
  - `/socket.io`, once realtime lands.
- **The SPA fallback answers page navigations only.** That means a `GET` that accepts `text/html`. A missing `.js`, `.wasm`, `.json` or other asset gets a real 404, never `index.html`.
- **Caching:** Flutter does not content-hash its output. Its web FAQ says it "doesn't currently support appending build IDs to resources automatically". So `index.html`, `flutter_bootstrap.js`, `main.dart.js` / `.wasm` / `.mjs`, workers and the asset manifest keep the same URLs across releases. They are served with revalidation (`no-cache` plus an ETag). Long `immutable` caching applies only to URLs whose content cannot change.
- **Cross-origin isolation (COOP/COEP):** headers only as BoardGamesEmpire/board-games-empire-client#320 decides. That issue owns the decision and its browser testing; this one owns the serving layer that applies it.

## Acceptance

- With the client bundled: `/` and any client route load the app; `/api/*`, `/.well-known/*`, health and metrics behave as before; a missing asset returns 404.
- A test checks the cache headers against the policy above.
- With no client bundled, the API behaves exactly as it does today.
