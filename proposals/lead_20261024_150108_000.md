*Project description:*
## Destination

A build-ready spec for rebuilding this repo as **Shape A** from the Shape A Hand-off. Every cross-layer decision is locked: shared core, C# shim, named pipe, add-in architecture and UI, code standards, usage logging, efficiency measurement and migration. It comes with a phased implementation backlog (hand-off phases 0–4) the team can pick up without deciding anything more.

## Notes

- **Constraints:** the Shape A Hand-off (`D:\AI with ACE\BuildRevitMcpServer\docs\Shape-A-Handoff.md`) and the Shape A architecture doc in the same folder. The hand-off's *Decisions locked* and *Engineering rules* are constraints; reopen one only with a new fact.
- **Where:** built in place in this fork. The new C# stack (shared core, shim, add-in) goes in new folders. The old TypeScript `server/`, `plugin/` and `commandset/` stay as they are until phase 1 reaches parity, then are deleted in one change. The two stacks are never bridged.
- **Revit versions:** 2024 through the latest release; 2020–2023 are dropped.
- **Tool prefix:** `ibim_`.
- **Code practices:** no IBIM house standard. Adopt general best practice: SOLID, suitable design patterns, dependency injection, and code that is easy to maintain, debug and extend.
- **Logging:** local only in v1. The event schema must allow opt-in telemetry later without changing the code that emits events. Model data never leaves the machine.
- **Measurement:** runtime performance (latency, main-thread time, result size), agent effectiveness, and prompt and resource quality. Evals run on developer machines against real Revit and fixture models; CI only builds and runs unit tests.
- **Add-in UI:** for architects, not developers. Its job is trust and visibility: connection status, the attached AI client, the user's Role, a live feed of AI actions with an undo hint, and support-bundle export. Permissions replace the old command toggles.
- **Carried forward:** query and create tools, the Interior Elevation tools and prompts (ADR 0001), and `send_code_to_revit` behind an Admin Permission. **Dropped:** the SQLite store. **Replaced:** `command.json` loading, by the compiled shared-core catalog.
- **Vocabulary:** use `GLOSSARY.md` (Revit Session, Seat, Role, Permission). For grilling tickets, call the `grilling` and `domain-modeling` skills.

- [Evaluate the official C# MCP SDK for the shim](https://github.com/AxelerateEngineering/mcp-servers-for-revit/issues/10): `ModelContextProtocol` 2.3.0 (spec 2026-07-28, net8.0/netstandard2.0, AOT-compatible) fits; serve a hand-built `McpServerTool` catalog (trim-safe); elicitation and `list_changed` support vary by client, so plan fallbacks
- [Revit 2024+ build and add-in UI platform facts](https://github.com/AxelerateEngineering/mcp-servers-for-revit/issues/12): Nice3point SDK 6.3.2 with R24 net48, R25/R26 net8.0, R27 net10; ILRepack dependencies below 2027 and isolation from 2027; theme via `UIThemeManager`/`ThemeChanged` with our own theme assembly (not stock Wpf.Ui); one dockable pane registered in `OnStartup`. New fact: .NET 8 support ends 2026-11-10, so the hand-off's .NET 8 shim is reopened in the code-standards ticket

## Not yet specified

- **Licence token contract** (format, signing, refresh API). The licence service already exists elsewhere; integration with it (validation, DPAPI cache, shim filtering, add-in enforcement) is in scope. Needed before phase 2, deferred for now.
- **Guarded-write mechanics** (phase 3): limits per Role, confirmation for destructive tools, how tool annotations map to them.
- **Result conventions:** compact and paged results, ID-only returns, size budgets on large models.
- **MCP resources:** which ones we expose, if any (none today).

- **Release and versioning pipeline:** replaces `release.yml` and the npm publish.
- **Admin script escape hatch:** safety design for `send_code_to_revit`.
- **The phased backlog itself:** assembled once the design tickets close.
