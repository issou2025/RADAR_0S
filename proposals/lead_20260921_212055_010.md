## Problem

The plugin has 14 skills, but production-critical workflows have uneven coverage across Flutter, Android, iOS, React Native and Kotlin Multiplatform. Existing references cover parts of these topics; this is a depth and discoverability gap, not a claim that all guidance is absent.

## Priority and scope

1. **Performance:** assess a dedicated `mobile-performance` workflow that establishes a baseline, measures startup, rendering, memory and battery, verifies improvements, and detects regressions. Reuse existing Android profiling and platform references.
2. **Offline synchronization:** assess `mobile-offline-sync` covering durable operation queues, idempotency, conflict resolution, synchronized deletions, process termination, recovery and reconnection tests. Extend the existing Flutter caching and platform data guides.
3. **Production observability:** assess `mobile-observability` covering release/device segmentation, error context, app/API correlation, alerts, sampling and privacy. Reuse Crashlytics, symbols and MetricKit guidance; add Firebase Performance Monitoring references where applicable.
4. Expand existing focused references for provider-independent authentication (OAuth/OIDC, PKCE, concurrent refresh, session recovery), billing lifecycle (pending/restored/refunded/revoked purchases and backend reconciliation), background execution, and localization (plurals, RTL, dates/currencies/time zones, fallbacks and layout tests). Create additional topic skills only when a distinct cross-stack workflow justifies them.
