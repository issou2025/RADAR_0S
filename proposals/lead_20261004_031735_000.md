# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**feat: process many models with steps, code, exports and save**

*Project description:*
The batch collector (`revit_batch_start`) reads many models but cannot change or export them, by design. Coordinators also need the other half: open each model in a list with the right settings, apply the same changes or script, export or save, close, and get one report.

## Decision

A new action, `revit_process_models`, runs in the user's interactive Revit session, one model at a time. It does not use the read-only collector worker, and the collector stays read-only. The tool is refused in read-only mode like every other action.

## Tool

`revit_process_models(paths=null, folder=null, recursive=false, pattern="*.rvt", open=null, steps=null, code=null, exports=null, save=null, stop_on_error=false, dry_run=false, confirm_token=null, response_timeout_s=14400)`

- Sources: `paths` (1-500 absolute paths) or `folder` with `recursive` and `pattern`. Path rules and `trustedNetworkRoots` apply. RSN paths are accepted; cloud paths are not.
- `open`: the `revit_open_document` options `mode` (default `detached`), `worksets` (including patterns) and `audit`. Documents always open in the background.
- `steps`: optional list of `revit_batch` steps, run per model in one transaction group with one undo entry (the undo entry is irrelevant after close but keeps the step code identical).
- `code`: optional C# script with the `revit_execute_code` contract (#153), run after `steps`. `{"code": "...", "transaction": "auto" | "none"}`. `ScriptContext.Document` is the processed model.
- `exports`: optional list of `revit_export` requests (#155) without `document`; `folder` may contain `{model}` which is replaced with the model file name without extension. Default folder: `<output>\<model>`.
- `save`: `{"mode": "none" | "output_dir" | "in_place", "output_dir": null, "compact": true, "overwrite": false}`. Default `none`.
  - `output_dir` saves a copy with the same file name into `output_dir`. Detached workshared models are saved with `WorksharingSaveAsOptions.SaveAsCentral=true`. A path equal to any source path is refused.
  - `in_place` saves over the source. Only for non-workshared files. It needs the existing two-step confirmation: the first call returns `needsConfirmation` with the list of files that will be overwritten; the second call with `confirm_token` runs.
- `dry_run=true` opens each model, runs `steps` and `code` with rollback, resolves exports without writing, never saves.
- Models already open in the session are skipped with a reason.
- Every model is closed after processing, without saving unless `save` says so.
- Dialogs and failures while opening and processing use the existing handlers; dismissed dialogs are reported per model.

## Result

Per model: `path` (redacted by the existing rules), `status` (`done`, `failed`, `skipped`), `elapsedMs`, `opened` (mode, worksets, audited), `steps` summary, `code` result (`returnValue`, `log`), `exports` (files), `saved` path, `dialogsDismissed`, `error`. Totals and a one-line `summary`.

Progress: report the current model index through the existing job status mechanism if one exists for long actions; otherwise the server waits up to `response_timeout_s`.

## Rules

- Reuse `DocumentActions` open/close, `BatchActionExecutor` steps, the execute-code runner and the export code. No second implementation of any of them.
- The active document is never closed or changed.
- One model failing does not stop the run unless `stop_on_error=true`.

## Acceptance criteria

- Three sample models: set a parameter on all walls with `steps`, export each to IFC, save copies to an output folder. Sources are byte-identical afterwards.
- A script that returns the wall count runs on every model and the counts appear in the result.
- `in_place` requires confirmation; a non-workshared copy is saved in place after confirmation.
- A model that fails to open is reported and the run continues.
- Core tests for argument validation and save-mode rules; Python tests for mappings and confirmation flow.
- Docs: `docs/actions.md` and a short section in `docs/batch.md` contrasting it with read-only collection.
