## Reproduction

Step 8 of `.claude/skills/implement-change/SKILL.md` gives the one command the skill grants (`Bash(gh pr create *)`, `PowerShell(gh pr create *)`):

```bash
gh pr create --title '<title>' --body-file '<file>'
```

The body goes through a file, but the title is pasted between single quotes. Take a title this repository has merged, #1078's `fix(skills): grant each skill's scripts by name and refuse own-folder wildcard grants`, put it in place of `<title>`, and parse the line:

- `bash -n` exits 2: `unexpected EOF while looking for matching '`.
- PowerShell's parser (`[System.Management.Automation.Language.Parser]::ParseFile`) reports `The string is missing the terminator: '.`

## Expected

The step's command takes any title the "Pull requests" rules allow, so a title is passed in a way the shell cannot misread. ## Actual

Of the last 300 merged pull requests, 77 have a title with an apostrophe, a backtick, or `$`. The apostrophe is the usual case: a possessive such as "skill's" or "git's". Each of those breaks the command as written. In Bash, the text after the apostrophe is read as shell syntax, not as the title. A session has to notice the problem and requote by hand, and the step gives it no guidance.

Known siblings: the `gh issue create --title "<title>"` lines that other skills and the step 2 briefs use are double-quoted. They break on `$` and backticks in Bash instead. This issue covers only `implement-change`. The same placeholder pattern elsewhere would need its own check.
