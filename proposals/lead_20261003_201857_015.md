## Minimal durable authorization service

- [x] https://github.com/anaregdesign/cosmos-sync/issues/33 — Implement and verify minimal durable BFF authorization for hosted developer onboarding

After considering Azure-managed capabilities, the selected model keeps provider-independent validated API-token authentication and BFF managed identity/native Cosmos RBAC, then adds an opt-in durable BFF account/personal scope and fixed-creator shared owner with reader/writer membership APIs. A shared mutation uses a same-partition policy ETag fence; admission, in-flight commit and offline revocation guarantees must be implemented and separately tested. This minimum is implemented and independently accepted in #33: durable verified issuer/subject accounts, personal self-access, fixed shared owner, reader/writer/none membership, same-partition policy commit fencing, causal authorization checks and documented revocation limits. Actual hosted/provider acceptance is separate.

Existing explicit grants remain a fail-closed legacy mode. Do not silently adopt legacy partitions, grant access from email or unverified claims, expose Cosmos credentials, infer Apple/Google linking support, or introduce a general permission DSL. The developer should use documented provider configuration and supplied BFF membership APIs rather than write custom IAM/sync infrastructure. Updated Terraform, onboarding, tests and actual hosting acceptance must agree on the final interfaces.

The selected code architecture does not authorize extra managed Azure services, identity/role/network changes or Terraform apply. Keep any necessary external approval concrete and keep the approved reusable validation resources retained.
