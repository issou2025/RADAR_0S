## 1. What OpenFlow is competing as

OpenFlow is a **visual, self-hosted iPaaS-shaped engine** (canvas, credentials, templates, workers) that also carries **agent/MCP** and **Ansible ops** surfaces.

It is **not** trying to be:

- Temporal / Trigger.dev / Inngest (code-first durable execution)
- Airflow / Prefect / Kestra (data orchestration)
- Zapier/Make cloud (catalog + hosted SaaS, no self-host)
- Node-RED IoT/edge
- Windmill internal-tools + multi-language scripts platform

If we market as “n8n but Apache,” buyers will score us on **working integrations, production runtime, and governance**. That is where the gaps are.

## 5. OpenFlow advantages (do not dilute)

These are real. Double down. Do not trade them for a fake 400+ claim.

1. **Apache-2.0 intent** vs n8n fair-code and Windmill AGPL. Patent grant. SaaS-friendly in a way n8n Community is not. **Must actually ship LICENSE on the product tree (#6) or the wedge is a lie.**
2. **n8n-shaped JSON interop** without loading `n8n-nodes-*`. Migration on-ramp no other OSS iPaaS has. Honesty: placeholders + compatibility score (#32).
3. **Ansible gallery + ansible-flow-mcp.** Unique vs n8n/Activepieces/Zapier. StackStorm is the ops rival, not n8n.
4. **Remote MCP with OAuth 2.1 and per-workflow grants.** Ahead of most self-host iPaaS. Activepieces is the MCP catalog rival (pieces-as-MCP).
5. **Lite / harness runtime.** Embed exported JSON in another Node process (CleanFlow, coding-agent loops). n8n has no equivalent small library.
6. **Clean-room factory.** Legal/process story for scaling nodes without copying n8n source. Only valuable if depth badges are honest (#24).
7. **Family:** mcp-flow, skill-flow, ansible-flow-mcp, CleanFlow. Agent-native distribution n8n does not have.

## 7. Gaps vs each rival (short)

### vs n8n (primary)

**We win on:** Apache intent, Ansible gallery, MCP grants, lite runtime, no per-execution cloud tax (we have no cloud).

**We lose on:** working integration depth, community nodes, queue/HA, durable wait/cron, git environments, SSO/audit, template corpus quality, security defaults, community size (2 vs 204k stars), Python code, Insights/evals, error workflows.

**Do not promise:** “runs n8n community nodes,” “400+ integrations,” “drop-in n8n.”

### vs Activepieces (license rival)

**We win on:** n8n JSON migration, Ansible, Apache patent grant, OpenFlow MCP grants, harness runtime.

**We lose on:** MIT core already on the product tree, 600+ **working** pieces, Helm, weekly releases, flow versioning, auto-retries, loops as a first-class step, pieces published as MCP automatically, cloud SKU, i18n, sandbox story.

If a buyer wants “open Zapier” and does **not** need n8n JSON or Ansible, they pick Activepieces today.

### vs Automatisch

They have fewer apps and a weaker canvas. Those apps are more likely to **work**. Our risk is looking bigger and failing on Slack/Gmail OAuth in week one.

### vs Node-RED

They own IoT/edge/MQTT. We should not chase industrial palettes. We can take SaaS/agent/Ansible users who find Node-RED dated.

### vs Windmill

They own code-first internal tools. Our canvas + n8n JSON + Ansible **gallery** is a different job. Do not race them on Python/K8s/git-sync until E8/E9 exist.

### vs Zapier / Make

They win catalog, HITL, SSO, templates, compliance. We win self-host, license, data residency, Ansible, MCP. Never claim catalog parity.

### vs Trigger.dev / Temporal

They win durability. We win visual SaaS glue. If Wait/HITL stay in-process, agent workflows will leave for Trigger.dev.

### vs StackStorm

They win ops packs. We win visual iPaaS + Ansible-from-canvas. Keep the deny-list (no free-form shell). That is a feature.
