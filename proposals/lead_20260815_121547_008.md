## Problem

Neither `ios/Podfile` nor `ios/Podfile.lock` exists anywhere in the repo (confirmed on disk and in `git ls-files`) despite the app depending on plugins with native iOS code (`supabase_flutter`, `shared_preferences`, `cached_network_image`, `app_links`, `url_launcher`). `ios/Runner.xcodeproj/project.pbxproj` has no `DEVELOPMENT_TEAM` set on the `Runner` target, uses the deprecated `"iPhone Developer"` code-sign identity (current is "Apple Development"), and `Info.plist` has no `ITSAppUsesNonExemptEncryption` key. `git log` shows `ios/` was last touched 2026-07-15 for a design change, not a build.

## Why it matters

The total absence of a `Podfile` is proof `flutter build ios`/`ipa` has never once succeeded against this repo — the entire iOS delivery path is unverified on a platform the app is nominally shipping to. No `Podfile.lock` also means native dependency versions are unpinned (the iOS analogue of not committing `pubspec.lock`). #32 explicitly scopes itself to the Android debug-keystore problem; nothing currently tracks the iOS signing gap. The first attempt at a TestFlight build will likely hit pod resolution, deployment-target, and provisioning failures simultaneously, discovered at submission time instead of now.

## What's needed

Run a real `flutter build ipa` on a Mac to generate and commit `ios/Podfile` + `ios/Podfile.lock`, set `DEVELOPMENT_TEAM`, modernize the code-sign identity, and add `ITSAppUsesNonExemptEncryption` to avoid an export-compliance prompt on every upload.
