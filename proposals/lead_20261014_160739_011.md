### Steps to reproduce

We could not reproduce this ourselves. App Review hit it on two submissions in a row:

1. Our app is a universal iOS app (iPhone and iPad) on the UIScene lifecycle (`FlutterSceneDelegate`), with StoreKit 2 enabled in `in_app_purchase_storekit`.
2. On an **iPad Air 11-inch (M3) running iPadOS 27.0**, App Review opened the purchase screen and bought an auto-renewable subscription (`buyNonConsumable` with an app account token).
3. The purchase failed, and Apple rejected the app under Guideline 2.1(b): "we tried to purchase the subscription and the app returned an error".

### Expected results

Apple's payment sheet opens and the purchase completes, as it does on iPhone.

### Actual results

The purchase fails before anything is charged.

- The sandbox App Store Server Notifications history holds no `SUBSCRIBED` notification from App Review in any review round, so StoreKit refused before the purchase completed.
- The same builds complete sandbox purchases on iPhone.
- On the iPad simulator with iPadOS 26.5 the payment sheet opens. We have no iPadOS 27 device, so we don't know the exact error StoreKit returned.

### Analysis

`InAppPurchasePlugin+StoreKit2.swift` buys with `product.purchase(options: purchaseOptions)`, which passes no UI context. Apple's documentation for [`Product.purchase(options:)`](https://developer.apple.com/documentation/storekit/product/purchase(options:)) says:

> Use `purchase(confirmIn:options:)` for apps that use UIKit. […] Use `purchase(options:)` for apps that runs on watchOS.

A Flutter iOS app is a UIKit app. Without a scene, StoreKit has to pick the window for the payment sheet itself. On iPad (resizable windows, Stage Manager) that seems to be the step that fails.

There are two more pointers in the same direction:

- In the iOS 18 SDK, the deprecation messages for the StoreKit 1 purchase APIs name `Product.purchase(confirmIn:options:)` as the replacement (see #170442).
- The plugin already resolves the window scene through `registrar?.viewController?.view.window?.windowScene` for `presentOfferCodeRedeemSheet`.

### Proposal

On iOS 17+, confirm the purchase in the window scene of the Flutter view. If that view has no window, use the foreground scene. Keep `purchase(options:)` only when there is no scene or the OS is older. On macOS 15.2+, `purchase(confirmIn:)` with the `NSWindow` could be used the same way.

We shipped exactly this as a patched copy of 0.4.13+2, and App Review approved the next build on the first try. That evidence is circumstantial, because Apple doesn't say which device the reviewer used, but the change matches Apple's guidance. If this approach works for you, we're happy to open a PR with tests.

### Code sample

The app-side code is the standard `InAppPurchase.instance.buyNonConsumable(purchaseParam: ...)` with StoreKit 2 enabled; nothing app-specific is involved. The change we shipped in `InAppPurchasePlugin+StoreKit2.swift`:

```swift
// In purchase(id:options:completion:):
let result = try await confirmPurchase(of: product, options: purchaseOptions)

@MainActor
private func confirmPurchase(
  of product: Product, options: Set<Product.PurchaseOption>
) async throws -> Product.PurchaseResult {
  #if os(iOS)
    if #available(iOS 17.0, *), let scene = purchaseScene() {
      return try await product.purchase(confirmIn: scene, options: options)
    }
  #endif

  return try await product.purchase(options: options)
}

#if os(iOS)
  /// The scene showing the Flutter view, else the app's foreground scene.
  @MainActor
  private func purchaseScene() -> UIScene? {
    if let scene = registrar?.viewController?.view.window?.windowScene {
      return scene
    }

    let scenes = UIApplication.shared.connectedScenes

    return scenes.first { $0.activationState == .foregroundActive }
      ?? scenes.first { $0.activationState == .foregroundInactive }
  }
#endif
```
