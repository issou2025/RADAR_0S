secureTokenStore: secure storage delete failed for "enjoy_player.cached_profile_json"

`-34018` is `errSecMissingEntitlement`. On macOS, a **sandboxed** app can only touch the keychain when it carries a `keychain-access-groups` entitlement; without one, `SecItem*` calls fail with exactly this error. The repo's own packaging doc says the same thing.

## The code, the docs, and the release script disagree

| Source | `keychain-access-groups`? |
|---|---|
| `macos/Runner/DebugProfile.entitlements` | yes - `$(AppIdentifierPrefix)$(CFBundleIdentifier)` |
| `macos/Runner/Release.entitlements` | yes - `$(AppIdentifierPrefix)$(CFBundleIdentifier)` |
| `macos/Runner/ReleaseDirect.entitlements` | **no key at all** |
| `docs/packaging.md` (direct download) | "Use the app's own `keychain-access-groups` entry (`$(AppIdentifierPrefix)$(CFBundleIdentifier)`) for secure storage - never an empty array (launch error 163)" |
| `docs/features/auth.md` (Developer ID zip row) | "sandbox + network + **app keychain group** (no Apple Sign-In entitlement)" |
| `macos/scripts/notarize_release.sh` (header comment) | "Uses ReleaseDirect.entitlements (no Sign in with Apple / **keychain groups** - those are unsupported for Developer ID and cause launch error 163 on macOS 26+)" |

`ReleaseDirect.entitlements` is what signs the **Developer ID direct-download channel** (`macos/scripts/notarize_release.sh` passes it to `codesign --entitlements`), so that build is sandboxed **without** any keychain access group - the one channel whose entitlements contradict `docs/packaging.md` and `docs/features/auth.md`.

## How it got there

`5a45c3de` ("fix(macos): unblock Developer ID direct download launch on macOS 26") created `ReleaseDirect.entitlements` to drop the **Apple Sign-In** entitlement - that entitlement is genuinely unsupported for Developer ID and caused launch error 163. The keychain group was dropped in the same file, so the direct channel lost keychain access as collateral damage rather than by decision.

## Note on `$(AppIdentifierPrefix)`

`$(AppIdentifierPrefix)` is an **Xcode build setting**: the Xcode build expands it during `ProcessProductPackaging`, but `codesign --entitlements` does **not** expand it. So simply copying the `DebugProfile`/`Release` form into `ReleaseDirect.entitlements` would ship the literal string `$(AppIdentifierPrefix)ai.enjoy.player` in the signed entitlement - which is what the "launch error 163" comment in `notarize_release.sh` is likely about. A fix has to bake a **literal** group into the signed entitlements at signing time (the Team ID `46X685R747` is already referenced in `notarize_release.sh`), or use the plain bundle id (`ai.enjoy.player`).

## Impact

Every secure-storage operation on the direct-download channel can fail with `-34018`: sign-in token writes, the cached profile read/write, and the sign-out delete (`clearAllAuthSecrets`) that produced the log line above.
