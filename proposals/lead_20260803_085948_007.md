## The problem

The four most complex and risk-bearing services in the codebase have **zero test coverage**:

| Service | Risk | Lines |
|---|---|---|
| `ApiClient` | Single Supabase boundary; every network call; session revocation detection | ~1,400 |
| `UploadService.uploadPlan` | Credit consumption → multi-phase upload → compensating refund on failure | ~800 (one method) |
| `AuthService` | Practice bootstrap; session persistence; magic-link fallback | ~600 |
| `SyncService` | Offline queue; pending-op flush; conflict resolution | ~1,500 |

The `uploadPlan` method in particular contains the credit-consumption-and-refund flow. A logic error here causes practitioners to be double-charged (consume credit, fail, refund fails silently — see companion issue #1133). This is exactly the kind of business-critical invariant that benefits most from unit tests.

The `local_storage_service.dart` already exposes a **test-only factory** (`LocalStorageService.forTesting(db: inMemoryDb)`) that enables SQLite testing without a device. `ApiClient` can be tested with a mock `SupabaseClient`. The infrastructure for service-level testing already exists.

## Suggested remedy

1. **UploadService** — test the credit/refund invariant: `consumeCredit` succeeds → upload fails → `refundCredit` called once; `consumeCredit` fails → no upload attempted.
2. **ApiClient** — test `_guardAuth` session-expiry detection with a mock client that throws a 403; test `refundCredit` returns `false` on network failure (not just "no refund needed").
3. **SyncService** — test that `queueXxx` methods enqueue exactly one `PendingOp` and call `flush`; test that flush dequeues in FIFO order.
4. **AuthService** — test `ensurePracticeMembership` bootstrap path and the fallback to magic-link on empty password.

## Why developer input is required

Writing these tests requires decisions about:
- Which parts of the Supabase client to mock vs. use with a local Supabase instance.
- Whether `ApiClient` should accept a `SupabaseClient` constructor injection (currently it reads from a singleton) to enable unit testing.
- The scope of the first test sprint vs. what gets deferred.
