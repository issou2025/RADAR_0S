## Project Understanding

**[Ticket]: Check completion, hover and squiggles for the fespalier: section of pubspec.yaml in VS Code and IntelliJ**

*Project description:*
### Type

Spike / Investigation

### Summary

Since 0.23.0 (#290) both editor plugins complete and check the `fespalier:` section of `pubspec.yaml`:
- **VS Code** gives Red Hat's YAML extension (`redhat.vscode-yaml`) one schema for `pubspec.yaml`. Keys and values complete, a key shows what it does on hover, and a mistake is underlined.
- **IntelliJ IDEA and Android Studio** do the same through the JSON support the IDE bundles. There is nothing to install.
- Both ship `fsp schema --pubspec`: the JSON Schema Store's pubspec schema (by `$ref`) with the `fespalier:` section added. An editor applies one schema to a file, so this is how the store's own checks of the rest of the file stay.

The tests cover a lot without a window:
- `fsp schema` is compared with what `fsp` accepts and refuses (`cli/src/schema_tests.rs`).
- The VS Code tests run the YAML language server (`yaml-language-server` 1.24.0) on the shipped schema, with a stand-in for the store's schema.
- The IntelliJ tests run a headless IDE with no network.

No test has opened a real editor window, used the real store schema, or gone offline. This ticket is that check.

Expected result: a report on each case below, per editor and operating system.

### Intent

Make sure a developer who opens a real `pubspec.yaml` sees completion, hover and underlines in the `fespalier:` section, still sees the store's checks on the rest of the file, and understands what happens without the YAML extension, offline, or with remote schemas off. These are the "UNCHECKED" items of `docs/configuration.md`, "Completion and checks in your editor".

### Expected Behavior

- **VS Code with the YAML extension.**
  - Keys of the `fespalier:` section complete as you type, and the values each takes (`remount:` offers `never`, `on_segments`, `on_location`).
  - Hover shows what a key does.
  - An unknown key, a value of the wrong type, or a value off a list is underlined.
  - The store's checks of the rest of the file stay.
  - The status bar names the schema.
- **VS Code without the YAML extension.** Nothing is completed. Saving `pubspec.yaml` still runs `fsp check`, which stops on an unknown key or a value of the wrong type in the section: the status bar shows `fespalier: failed` and the message is in the fespalier output.
- **VS Code offline.** The YAML extension cannot load the store's schema, which the fespalier schema refers to. It shows one warning at the top of `pubspec.yaml`, `Problems loading reference 'https://www.schemastore.org/pubspec.json'`, and validates nothing in the file. Turning the store off (`yaml.schemaStore.enable: false`) does not avoid it. The docs say these two are UNCHECKED.
- **IntelliJ / Android Studio.** The same completion, quick documentation (F1 or Ctrl-Q) and highlights. A schema mapped to `pubspec.yaml` by hand would still win. With remote schemas off, the section should still complete (UNCHECKED).

### Technical Context

**Setup.**

1. You need:
   - VS Code 1.85 or later, and/or IntelliJ IDEA or Android Studio on platform 252 or later (the build number in _Help | About_ starts with 252 or a higher number).
   - Flutter 3.35 or newer on `PATH`, and `git`.
   - For the VS Code plugin: Node.js and npm (CI uses Node 22).
   - For the IntelliJ plugin: JDK 21.
2. Get `main` and check that it has #290:
   ```sh
   git clone https://github.com/fespalier/fespalier && cd fespalier
   git log -1 --format=%h
   git merge-base --is-ancestor ce35d87 HEAD && echo "has #290"
   ```
   Write down the short hash `git log` printed. It goes in your report. Run steps 3, 5 and 6 from the root of this clone.
3. Install `fsp` 0.23.0 or later (`install.sh` from the README), or build it from `main`:
   ```sh
   (cd cli && cargo build --release)
   ```
   Then put `cli/target/release` on `PATH`. `fsp --version` should print `fsp 0.23.0`. A build of `main` before the release prints `fsp 0.22.1`, because the release tooling bumps the number when it cuts the release. That is fine here.
4. Make an app in a folder of your own (not inside the clone), and open its `pubspec.yaml` in the editor:
   ```sh
   fsp create editordemo && cd editordemo
   ```
   Add this under a `fespalier:` section. If the file already has a `fespalier:` section, put the keys under it. YAML refuses a repeated key.
   ```yaml
   fespalier:
     app_dir: lib/app
     main: auto
     remount: on_segments
     telemetry: false
     adapters: auto
     tasks:
       dev:
         hot_reload: true
   ```
   Save. Nothing in it should be underlined (cases 1 to 3 start from here).
5. **VS Code plugin and the YAML extension:**
   ```sh
   code --install-extension redhat.vscode-yaml
   (cd editors/vscode && npm install && npm test && npx @vscode/vsce package)
   code --install-extension editors/vscode/fespalier-*.vsix
   ```
   Restart VS Code. On macOS, `code` needs _Shell Command: Install 'code' command in PATH_ from the command palette. To try the plugin without installing it, run `code --extensionDevelopmentPath=editors/vscode <path to editordemo>` from the repository root.
6. **IntelliJ plugin**, with JDK 21:
   ```sh
   (cd editors/intellij && ./gradlew build buildPlugin)
   ```
   (`gradlew.bat` on Windows.) Then _Settings | Plugins | gear icon | Install Plugin from Disk..._ and pick `build/distributions/fespalier-intellij-<version>.zip`. Restart the IDE. The first build downloads the IntelliJ Platform (the README says a 1.7 GB archive; leave room for several GB). Or run `./gradlew runIde` for a sandbox IDE with the plugin.

### The cases

**VS Code, with the YAML extension** (open the `editordemo` folder; the extension must be enabled):

1. **The schema's name.** Open `pubspec.yaml` and look at the status bar, bottom right. The YAML extension shows the name of the schema it applied. We expect `pubspec.yaml with fespalier`, the `title` of the shipped schema. Report the exact text. Report it too if it names only the store's schema, says `No Schema`, or lists several.
2. **Keys complete.** On a new line under `fespalier:`, indented two spaces, press Ctrl+Space. Expect `app_dir`, `adapters`, `tasks` and `telemetry` in the list, and not `main` (it is already there). On a new line at column 0 press Ctrl+Space again: expect pubspec's usual keys that the file does not have yet, such as `homepage`.
3. **Values complete.** After `remount: ` press Ctrl+Space: expect `never`, `on_segments`, `on_location`. After `main: ` expect `auto`, `generated`, `manual`. After `adapters: ` expect `auto`.
4. **Hover.** Hover the mouse over `remount`. Expect text that includes `fresh state because its URL changed`. Hover `adapters`: expect text that starts `Packages that plug into the generated main() through package:<name>/fespalier_adapter.dart`.
5. **Squiggles.** Make these mistakes one at a time, and hover each underline. CI's run of the same language server gives the messages in brackets. Yours may read a little differently: report what you see.
   - `app_dirr: lib/app` under `fespalier:` (`Property app_dirr is not allowed.`)
   - `remount: sometimes` (`Value is not accepted. Valid values: "never", "on_segments", "on_location".`)
   - `hot_reload: maybe` under `tasks: dev:` (`Incorrect type. Expected "boolean".`), and `telemetry: maybe`
   - `app_dir:` with no value (the schema refuses it on purpose: `fsp` reads it as not set, but it is almost always unfinished typing)
   - `fespalier:` on its own with no keys under it must **not** be underlined.
   Undo each mistake before the next.
6. **The store's checks stay.** Under `environment:`, change `sdk:` to `sdk: 3`. Expect an underline from the store's schema (CI's stand-in says `Incorrect type. Expected "string".`). Undo it. On a new line under `environment:`, press Ctrl+Space: expect `sdk` and `flutter`. If `sdk: 3` is not underlined, try `description: 5` and say which one worked.
7. **Other YAML files are left alone.** Open `analysis_options.yaml`. Press Ctrl+Space on a new line: `fespalier` and `app_dir` must not be offered. The status bar must not name `pubspec.yaml with fespalier`.

**VS Code, without the YAML extension:**

8. **No YAML extension.** Disable _YAML_ (Red Hat) in the Extensions view and reload the window. Open `pubspec.yaml`. Expect no completion of `fespalier:` keys, no hover, no underline.
9. **`fsp check` still stops on a mistake.** Add `nope: true` under `fespalier:` and save. Expect the status bar to show `fespalier: failed` (hover it: `fespalier could not run; see the fespalier output. Click to check again.`). Open _View | Output_, pick _fespalier_. Expect a message that includes ``unknown field `nope`, expected one of `app_dir`, `output`,``. Remove the key and save: the status bar goes back to a check mark and `fespalier`.
10. **What `fsp check` does not read.** With the extension still off, put `hot_reload: maybe` under `tasks: dev:` and save. Expect nothing in the editor (only `fsp doctor` and the task commands read `tasks:`). Run `fsp doctor` in the app folder and expect an error row for it (the `tasks` row), with this message in it:
    ```text
    `fespalier.tasks.dev.hot_reload` must be `true` or `false`, got `maybe`
    ```
    Then enable the YAML extension again and check that `hot_reload: maybe` is now underlined (case 5).

**VS Code, offline** (the first run: nothing cached):

11. **A fresh profile.** Install both extensions into folders of their own, while you are online:
    ```sh
    code --user-data-dir ~/vscode-offline --extensions-dir ~/vscode-offline-ext --install-extension redhat.vscode-yaml
    code --user-data-dir ~/vscode-offline --extensions-dir ~/vscode-offline-ext --install-extension <path to the clone>/editors/vscode/fespalier-<version>.vsix
    ```
    Turn the network off (Wi-Fi off, cable out). Start VS Code with the same two folders and the app:
    ```sh
    code --user-data-dir ~/vscode-offline --extensions-dir ~/vscode-offline-ext editordemo
    ```
    Open `pubspec.yaml`. Expect one warning at the top of the file, `Problems loading reference 'https://www.schemastore.org/pubspec.json'`. Add `app_dirr: lib/app` and `sdk: 3`, and report whether either is underlined (the docs say nothing in the file is validated offline). Report whether the keys of `fespalier:` still complete.
12. **The store switched off does not help.** Offline still, in _Settings_ set `yaml.schemaStore.enable` to `false`, then close and reopen `pubspec.yaml`. The docs say the warning stays, because the reference is the fespalier schema's own. Report whether it did.
13. **Back online.** Turn the network on and run _Developer: Reload Window_. Expect the warning gone, and case 5 and 6 working again.

**IntelliJ IDEA or Android Studio** (open `editordemo`; _Settings | Languages & Frameworks | Schemas and DTDs | Remote JSON Schemas_ allows downloads, which is the default):

14. **The schema's name.** Open `pubspec.yaml`. The JSON schema widget in the status bar (bottom right) names the schema. We expect `pubspec.yaml with fespalier`, the name the plugin gives its schema. Report the exact text.
15. **Keys and values complete.** As cases 2 and 3: on a new line under `fespalier:` press Ctrl+Space. Expect `app_dir`, `adapters`, `tasks`, `telemetry` and not `main`. After `remount: ` expect `never`, `on_segments`, `on_location`.
16. **Quick documentation.** Put the caret on `remount` and press F1 (macOS) or Ctrl+Q. Expect text that includes `fresh state because its URL changed`. Hovering the mouse should show the same.
17. **Highlights.** Repeat the mistakes of case 5. Report the text IntelliJ shows for each. If nothing is underlined, look in _Settings | Editor | Inspections_ for a YAML inspection about JSON Schema compliance, turn it on, and say so in your report.
18. **The store's checks stay.** Make `sdk: 3` under `environment:`. Wait a few seconds for the download. Expect an underline. Report whether it took a while to appear.
19. **Remote schemas off.** In _Settings | Languages & Frameworks | Schemas and DTDs | Remote JSON Schemas_ untick _Allow downloading JSON schemas from remote sources_, apply, and reopen `pubspec.yaml`. Expect the `fespalier:` section to still complete and still underline `app_dirr` (the docs say this is UNCHECKED). Expect `sdk: 3` to stop being underlined, because the store's part cannot load. Report whether the IDE shows any message or error about the missing download. Tick the box again afterwards.
20. **Other YAML files are left alone.** Open `analysis_options.yaml`: `fespalier` and `app_dir` must not be offered.
21. **Android Studio, if you have one.** Repeat 14 to 19.
22. **Offline, if you can.** With the network off and the box in 19 ticked, restart the IDE and open `pubspec.yaml`. Report what the `fespalier:` section does and whether any message shows.
