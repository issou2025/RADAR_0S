## Summary / Description
Zedu Desktop has no installable Windows package. The only Windows builds are the per-PR `desktop-windows` zips from the fork build: a folder with an unsigned `zedu.exe` plus its DLLs and `data\` folder. Testers have to unzip it, click through SmartScreen and run it from wherever they extracted it. There is no Start menu entry, no uninstall, no file or protocol association, and there are no GitHub releases.

This ticket adds an MSIX installer, built from a release build, that installs Zedu Desktop like a normal Windows app.

## Why is this ticket needed?
- Non-developers (reviewers, testers, early users) need to install the app without unzipping build folders.
- **Deep links depend on it:** the app uses `zedu://` links (for example `zedu://credits/payment-success?...` from `credits_remote_datasource.dart`, read through `app_links`). On Windows a custom scheme only opens the app when it is registered, and an MSIX can declare it.
- **Notifications:** `local_notifier` notifications are more reliable when the app has a package identity, which MSIX provides.
- Install, update and uninstall become clean (no leftover folders), and every build gets a version number that matches `pubspec.yaml`.

## Details
Suggested approach, using the `msix` Dart package:
- Add `msix` as a dev dependency, and an `msix_config:` section in `pubspec.yaml`:
  - `display_name: Zedu`, `publisher_display_name`, `identity_name` (e.g. `chat.zedu.desktop`), and `msix_version` derived from `version:` (currently `0.1.0+1`)
  - `logo_path`: the existing app icon (`windows/runner/resources/app_icon.ico` source PNG)
  - `capabilities: internetClient, microphone, webcam`. The microphone is needed for voice notes (`record`) and Agora calls; the webcam for Agora video.
  - `protocol_activation: zedu`, so `zedu://` links open the installed app
  - `execution_alias: zedu` (optional)
- Build: `flutter build windows --release`, then `dart run msix:create`.
- **Signing:** an MSIX only installs if it is signed by a certificate the machine trusts. For internal testing, a self-signed test certificate plus a documented "install the certificate first" step is enough. For distribution, sign in CI with a real code-signing certificate stored as a secret, never committed.
- **CI (follow-up, needs reviewer agreement because `.github/` is protected):** a job that builds the `.msix` on a version tag and attaches it to a GitHub release.
- Out of scope: auto-update, Microsoft Store submission, and macOS/Linux packages.

## Steps to reproduce
1. Look for a Windows installer: there are no releases on `zedu-hng/zedu-desktop`, and there is no MSIX, Inno Setup or WiX configuration in the repo.
2. Download a PR's `desktop-windows` artifact: it is a zip of the raw build folder.
3. **Expected:** a single installer that adds Zedu to the Start menu and can be uninstalled from Settings › Apps. **Actual:** only a portable, unsigned folder.
