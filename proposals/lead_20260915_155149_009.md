# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**iOS distributed trace v3 — launch-to-request attribution, root lifetime & span timing**

*Project description:*
## Destination

An **implementation-ready iOS spec for distributed trace v3** — the Android v3 model (`NCG-Africa/edge_telemetry_android` map #120, tickets #121–#132) landed on iOS, plus the iOS delta filed against the backend wire contract.

Fidelity rule for this map: **wire-identical, mechanism free.** Attribute names, the `traceparent.outcome` enum, `trace.root_type` values and their semantics are frozen to Android's contract — divergence on the wire is a defect. *How* iOS produces them (swizzle vs wrapper, `@TaskLocal` vs thread-dict, which monotonic clock) is decided per-ticket on iOS merits.

Done when: a Swift-implementable spec exists in `docs/specs/`, and the iOS column of the backend wire contract is filed. No SDK code merges from this map.

## Notes

- **Domain:** iOS RUM SDK (`EdgeRum*` targets, SwiftPM + CocoaPods). Plan-only — this map produces specs and decisions, not merged Swift.
- **Skills:** `/grilling` + `/domain-modeling` by default; `/research` for AFK evidence tickets. Ground every claim in `file:line` from `Sources/`, `CLAUDE.md`, and `PLAN-iOS.md`.
- **Prior art to read before deciding, not to copy:** Android map #120 and its children #121–#132 (`NCG-Africa/edge_telemetry_android`). iOS map #140 established the standing stance **"iOS conforms to the Processor of record"**; ADR-014 in `docs/decisions.md`.
- **iOS ground truth that contradicts a naive port** (verified 2026-09-15 @ `b90a869`):
  - Zero trace/span code exists today — `grep -rE 'traceparent|trace\.id|span|TaskLocal|rum_action|root_type' Sources` returns nothing.
  - HTTP capture is `URLProtocol` + `URLSessionConfiguration` class-swizzle (`Sources/EdgeRumCapture/HTTPCapture.swift:1-40`) — **zero-touch install**. A `session.dataTask(with:)` *wrapper* is an opt-in shape and would forfeit that property.
  - Taps already mint at **touch-ended** (`Sources/EdgeRumCapture/InteractionCapture.swift:175`, `UIWindow.sendEvent(_:)` swizzle) — Android's 300 ms `onSingleTapConfirmed` misattribution defect (#131) **has no iOS twin**.
  - Launch anchor is `Date()` on first reference (`Sources/EdgeRumCapture/PageLoadCapture.swift:71`), **not** process start. Prewarm detection already exists (`:105`).
  - `Clock` is `Date`-only (`Sources/EdgeRumCore/Clock.swift:19-25`) — **no monotonic source**. The one `mach_absolute_time()` use (`Sources/EdgeRumCapture/RunLoopObserverCapture.swift:167,170`) stops during sleep.
- **Backend posture:** do not wait on persistence. Android #129 found the v2 trace contract has been **write-only since 2.2.0**; the Go processor schema is being authored now, so the iOS delta is a live input with a deadline.

- [T1 — Where does iOS capture the trace context, and what holds it?](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/154) — instance-swizzle `URLSession`'s task-creation family (all `dataTask`/`uploadTask`/`downloadTask` overloads) so capture runs on the caller's thread and install stays zero-touch; `URLProtocol` unchanged for load + metrics; carrier is one process-global ambient root (`nonisolated(unsafe)` static + `os_unfair_lock`), correct by expiry not by thread scoping; capture point always stamps a marker, so `injected_unattributed` (no live root) and `injected_unwired` (coverage hole) stay distinguishable. No public opt-in wrapper.

- [T2 — Monotonic clock + root expiry (2 s idle / 10 s cap) on iOS](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/155) — expiry runs on `clock_gettime_nsec_np(CLOCK_MONOTONIC_RAW)`, sleep-**inclusive** on Darwin (the inverse of Linux; `CLOCK_UPTIME_RAW`/`mach_absolute_time` are the ones that stop) and the `elapsedRealtime()` analogue; injected as a plain `() -> UInt64` closure on the root store, so `Clock` and its 6 consumers are untouched and tests move uptime and wall-clock independently (sleep vs NTP jump); Android's 2 s idle / 10 s cap, both extension triggers and lazy evaluation all hold unchanged, with no background hook needed because the sleep-inclusive clock ages the root through suspension; the suspected `mach_absolute_time()` hang defect is **refuted** — sleep-exclusion is correct per runloop turn — but `HangWatchdog` timing hang duration off `Date` is real, off-path, and filed standalone as #164.

- [T3 — Trace-path defect & overhead audit (evidence only)](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/156) — evidence asset `docs/audits/trace-v3-path-audit.md` (10 overhead rows, 10 defects, all `file:line`, static read at `b90a869` — no device run); the two costs that dominate are **O1**, every recorded event doing a synchronous atomic file write on the caller's thread with no dirty check (`Recorder.swift:539` → `SessionSidecar.swift:85-102`), which taps pay on the main thread, and **O3**, a fresh ephemeral `URLSession` per intercepted request (`HTTPCapture.swift:721-731`) that destroys connection reuse so every request pays a full TLS handshake — wire-visible, and trace v3 spans would inherit an SDK-induced latency profile; the `os_unfair_lock` statics come back **clean**; two ticket premises are corrected — the double-issue is a dispatch not a transmission, and `sanitizeUrl` runs on the internal delegate queue, **not** the caller (`:730`, `:768`); the decision-bearing defects are **D3** (the recursion guard at `:724-726` is dead code — only the getter is swizzled, so the marker hop rests on one mechanism), **D4** (`taskDescription` never crosses to the internal task), **D5** (`stopLoading()` never records, so cancelled requests give `injected_unattributed` a third cause T1 does not separate) and **D6** (`startedAt` is stamped in `startLoading()`, so `http.duration_ms` excludes the caller-side queueing gap — the very interval this map is named after); no unbounded per-request state exists today, and a `taskIdentifier` stash would collide across the session hop and leak on every cancellation; the ephemeral session discarding the host's config and bypassing host TLS pinning is off-route and filed standalone as **#165**.

- [T4 — Header injection and attribute hand-off across the URLProtocol boundary](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/157) — everything is decided at the capture point on the caller's thread (injection, allowlist, adoption, sampling flags, `span.start_time`), leaving the `URLProtocol` layer **read-only** with respect to trace state; the hand-off is **one `URLProtocol` property key holding a `[String: String]` bag** — the only thing that crosses `startLoading()`'s hop, never on the wire, dying with the request, so there is no stash, no eviction and no leak (T3's suggested associated-object-on-the-task is **unreachable** from the emission site, which is defect D4 restated) — and **the bag's presence *is* the marker**: present+root → `injected_attributed`, present+no root → `injected_unattributed`, **absent** → `injected_unwired`, one object doing both jobs; `span.start_time` is stamped at task creation as an absolute epoch (fixing **D6** and, as a wire-visible side effect, making `http.duration_ms` finally include the caller-side queueing gap); Android #124's allowlist is adopted verbatim (dot-anchored entries, warn-once-when-empty, ≥2-further-labels validation) and the ticket's "contains-style filter" premise is **corrected** — `:221-223` is an *exact* match; a redirect carries the injected header to a host that was never allowlisted, so `willPerformHTTPRedirection` must re-run the allowlist and strip it (closing half of **D2**); inbound headers are **adopted read-only** — mirror their ids, never rewrite, never mint, `parent.span.id` absent — with the bag guarding against adopting our own header on a retry; **sampling does not port from Android** — `Sampler` is per-session, private to `Recorder` and re-rolled on rotation, so the root carries no `sampled` field and instead injection always happens with the W3C flag bits reflecting the session decision, which **collapses the gate-ordering question** (allowlist decides *whether* a header is written, sampling decides only its *flags*) and adds **no new outcome enum member**; and **D5** is fixed without new vocabulary by recording from `stopLoading()` with `URLError(.cancelled)`, so a cancelled request emits a real child span instead of masquerading as a coverage hole — leaving D3 (load-bearing for trace state now) and D4 (self-exclusion rests on the `X-Edge-Rum-Internal` header alone, since `taskDescription` is set *after* task creation) as spec-level mitigation notes for #162.

- [T5 — Launch as a root: anchor instant, idle exemption, prewarm guard](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/158) — yes, a launch root minted at init, but with the two clock domains held **apart and never converted**: the wire gets `span.start_time` = `kinfo_proc.p_starttime` via `sysctl(KERN_PROC_PID)` (already epoch, exactly T4's format — no conversion, and no `sysctl` exists in `Sources/` today), while expiry takes a *fresh* `CLOCK_MONOTONIC_RAW` reading at mint through T2's injected closure, because converting between them is only sound if no NTP correction landed since fork — the hazard T2 picked that clock to dodge; the fork→init gap is therefore **span duration but never expiry budget**. On a **prewarmed** launch `p_starttime` is the *prewarm* fork (possibly hours stale), so the root is still minted as `trace.root_type = launch` but the anchor falls back to `launchStart`, with the existing `page_load.prewarmed` on the same payload already saying which anchor was used. The ticket's iOS-14 sub-question **dissolves** — prewarming shipped in **iOS 15**, so `PageLoadCapture.swift:109`'s `return false` is correct rather than a detection gap, and there is nothing to decide. The live half of Android's importance check is the background case: `applicationState == .background` at mint → **no root**, so a silent-push or `BGTaskScheduler` wake honestly yields `injected_unattributed` — deliberately diverging from `PageLoadCapture`, which arms and waits (`:265-273`), because a window can afford to wait for a foreground and a causal scope cannot. The **exemption ends at the first active `CADisplayLink` tick or `didEnterBackground`, whichever comes first** — the tick is the true analogue of Android's first resume (`didBecomeActive` fires *before* the first frame, so it would start the 2 s clock mid-render and cut the launch trace short) and it is Recorder-independent, since the link `invalidate()`s unconditionally at `:311-314` even when no `page_load` is recorded; it costs one seam, as `Driver.tick` is private. During the exemption the root is exempt from **both** the 2 s idle and the **10 s cap**, so a 12 s cold start stays one trace, and Android's 60 s backstop is **not ported** — it exists because `onActivityResumed` can never fire, whereas an `.active` app ticks at 60 Hz and the only miss is backgrounding, which `LifecycleCapture.swift:157` already observes. `page_load` becomes a **span-carrying event** (launch-root ids + `trace.root_type`, per Android Δ13) but `page_load.duration_ms` keeps its `launchStart` anchor — the fork→init gap is already derivable server-side, so re-anchoring would shift a shipped metric for no new information and would re-inherit the prewarm hazard. Mint point is an ordering constraint, not a decision: **between `EdgeRum.swift:189` and `:245`**, after `launchStart` is sampled and before `HTTPCapture.install`. Warm foreground resume is left undecided and filed as fog.

- [T6 — Interaction and navigation roots: minting, naming, and clearing the carrier](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/159) — the ticket's own premise is **corrected**: Android #131's misattribution defect **does** have an iOS twin, wearing ordering rather than latency — `UIWindow.sendEvent(_:)` dispatches the responder chain *synchronously*, so at `InteractionCapture.swift:319-323` a target-action firing a request runs one stack frame **before** the capture point and captures the previous root (`UIViewControllerCapture.swift:382-386` has the same shape); the fix is to **split the swizzle** — mint before calling through (an `os_unfair_lock` acquisition and two ids), emit `user.interaction` after — because both halves cannot move together: #156's **O1** synchronous file write would otherwise land on the critical path of every tap the user feels, adding SDK latency to the very interval this map measures. A **secure-field tap now mints its root but still drops its event**, which is safe precisely because the wire carries no root-name attribute — a root's descriptive identity rides entirely on the `user.interaction` event holding its ids — so auth-request latency stays attributed while nothing descriptive leaves the device, instead of handing `injected_unattributed` a fourth cause. `viewDidAppear` mints a `navigation` root **only when the carrier is empty or expired**, so tap → nav → content stays one trace (the screen's own `viewDidLoad` fetch keeps the tap's root, which is the truthful causal chain, not a defect) and `navigation` roots come to mean "no gesture and no launch behind this" — deep links, push opens, programmatic nav; T5's expiry-exempt launch root therefore absorbs the cold-start landing screen too. **One root per `sendEvent`**, not per ended touch — the gesture is the causal unit, and N roots would orphan N−1 instantly against a last-writer-wins carrier — with the event count at `:175` unchanged. **No background clear hook**: T2's sleep-inclusive `CLOCK_MONOTONIC_RAW` already ages the root out, so a clear would differ only in the sub-2-second app-switcher peek, where *keeping* the root is the better answer, and it would make fog patch 3 strictly worse. Two ticket decisions **dissolve** — "who reaps the childless roots" (expiry reaps them; #161 item 4 already made envelopes query-time views with childless roots NULL) and the in-flight-request-across-backgrounding sub-question (T4 stamps attribution at *task creation*, so completion never reads the carrier). Finally, the secure-field guard at `:230` is found **insufficient**: `resolveTargetIdentifier` (`:276-289`) collapses developer-authored `accessibilityIdentifier` and **rendered button text** — routinely PII ("Pay Sarah £40", a contact name on a cell button) — into one attribute, and only password fields were ever gated, so iOS adopts the **`ui.name_source` analogue** to label the two classes, dropping nothing and making the PII-bearing branch filterable, with the exact name frozen to Android's and filed through #161. `trace.root_type` needs no decision (Android's frozen values, denormalized per #129). Wire-visible for the handover: same names, **materially fewer `navigation` roots** than Android. No new tickets; **fog patch 2 resolved outright**, fog patch 3 graduated to #166.

- [T7 — Annotating crash and hang events with the last root (never parenting)](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/160) — yes, a **second** reference distinct from T1's carrier, non-expiring, written through at every mint — not for reachability (T1's carrier is already process-global, unlike Android's `ThreadLocal`) but for **lifetime**, since reading the expiring carrier would annotate NULL for any hang following 2 s of idle, which is most hangs; its **lock-free** property is load-bearing rather than an optimisation, because a main thread hung *inside* T6's split swizzle while holding the carrier's `os_unfair_lock` would block a watchdog read forever with no timeout, killing the hang event in exactly the case hang detection exists for (the `thread_suspend` window itself is contained — `MainThreadStackSnapshot.swift:117-118` — so it is not the hazard). Three ticket premises are **corrected**: there is no async-signal-safety constraint at all, since PLCrashReporter owns the handler (`PLCrashIntegration.swift:195-197`) and every line of our crash code runs on the *next* launch at `:151`; the three emitters are three different shapes, and `RunLoopObserverCapture` is **not a crash emitter** — it goes through `recordPerformance` as `long_task` (`:132`) on the very thread that mints; and iOS has **no `app.exit`**, so Android's exclusion has no twin to name. Cross-process survival costs **no new I/O and no new main-thread work**: the annotation rides the `sidecar.write(snapshot: context.snapshot())` that `Recorder.swift:539` already performs on every enqueue (T3's **O1**, already paid) — the half of the problem Android explicitly deferred as fog, which iOS gets for free from an always-on write Android lacked. The vehicle is a **widened `write(snapshot:extra:)`**, not the context, because `PayloadBuilder.swift:39` merges context into every event and would put the annotation on the wire for events that are not spans; `extra` merges after `filter(_:)` so `mirroredKeys` keeps its identity-only meaning, and the crash path needs **zero changes** — `CrashSidecarReader:83-85` already sweeps unconsumed keys into `extras` and `PLCrashIntegration:163-165` splats them. **Annotated: `app.crash`, both causes** (disk for the replay, `lastRoot.load()` for the hang at `HangDetector.swift:327-333`); **`long_task` excluded** — it fires on the minting thread, so "last known root" is the wrong concept for it. Names are **Android's unchanged** — `trace.id` + `rum.action.id`, with `span.id`/`parent.span.id` deliberately **absent** ("not a new child span, since a crash has no duration"), which is also the structural half of the guard: there is no parent attribute to parent *with*; a `trace.last_root.*` namespace considered mid-ticket was **dropped as a fidelity defect**, and no mint-timestamp attribute is needed since the join reaches the root's own `span.start_time`. One **deliberate divergence**: Android stamps nothing on an expired root, iOS **always stamps** plus an additive iOS-only **`trace.root_expired`** — absent means live and joins exactly as Android's does, present lets the backend judge, and Android's wire is unchanged because it never stamps a stale root; this is **new vocabulary that must clear #161 before #162 can freeze it**, and it is the only consumer of T2's thresholds outside the carrier, so #162 must state they read one policy. The **guard** is one behavioural test — mint root A, expire the carrier via T2's injected closure while `lastRoot` still holds A, then assert a request gets `injected_unattributed` with **no attribute equal to A's ids** and `parent.span.id` absent, *and* that a hang emits those same ids with `trace.root_expired == true`: it passes only if injection reads the **carrier** and annotation reads the **ref**, and its second half stops the test being "fixed" by disabling the feature. Two documented gaps for #162: T6's secure-field tap mints without enqueuing, so a crash there names the **previous** root (closing it means an O1 write per keystroke — refused), and a publication scheme must be tear-free without blocking, since a torn multi-word read fabricates a trace id that never existed, strictly worse than NULL.

- [T10 — Coverage of the swizzled task-creation family: async/await, background, WKWebView, third-party](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/163) — evidence asset [`docs/audits/trace-v3-swizzle-coverage.md`](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/blob/docs/trace-v3-swizzle-coverage/docs/audits/trace-v3-swizzle-coverage.md) (branch `docs/trace-v3-swizzle-coverage`, `c47c6a9`), and unlike T3 this one was **run, not read** — nine Swift programs against Darwin Foundation plus a body-counting local server, reproducing `startLoading()`'s exact shape. The ticket's **re-open trigger fires**: every async/await API misses every public creation selector and dispatches instead to a **disjoint private family** carrying the per-task delegate (`_dataTaskWithRequest:delegate:completionHandler:` and four siblings, `bytes(for:)` on `_dataTaskWithRequest:delegate:`), which funnels neither way — so T1 as written puts **100% of async/await traffic into `injected_unwired`** — but it resolves to an **amendment, not a re-open**, because the mechanism is unharmed and only the enumeration was wrong: the family is **ten** selectors, discovered at install by enumerating `class_copyMethodList(URLSession.self)` against `^_(data|upload|download)TaskWith.*[Dd]elegate:` so no private-API literal sits in the binary and a rename survives, with a missing selector obliged to **degrade rather than trap** and install reporting its bound-arm count (a future OS resolving zero arms would otherwise revert async to `injected_unwired` in silence). A **failure class worse than a coverage hole** is found behind two doors: background configs fire the creation swizzle but never `URLProtocol`, and `URLSession` **snapshots its configuration at creation** so the `protocolClasses` getter swizzle (`:842-880`) can never reach a session built before `EdgeRum.start()` — while a class-wide creation swizzle installed later *does* fire for it retroactively; both yield a **`traceparent` on the wire with no client span ever recorded**, a dangling parent that is strictly worse than a hole because a hole is visible as `injected_unwired` and this is invisible. The fix adds **no vocabulary** — inject only when the session's `protocolClasses` actually contain `EdgeRumURLProtocol`, a positive check closing both doors (`configuration.identifier != nil` catches only the background subset) — and the retroactive swizzle is a net **gain**, closing an ordering hole today's getter swizzle has. **D9 is refuted**: a 5000 B streamed upload and a 3000 B data upload both arrive intact through the protocol hop and a `downloadTask` still delivers a correct file to its caller, because `mutableCopy()` at `:715` carries `httpBodyStream` across — only D9's O5 half (download body materialised in RAM at `:752`→`:771`) stands, as overhead not correctness. **T4's D4 premise is corrected**: `URLProtocol.task` is the **outer** task (`desc:OUTER-MARK` measured), since Foundation builds the protocol via `initWithTask:` and consults `+canInitWithTask:` rather than `+canInitWithRequest:` whenever a session task exists — T4's bag decision stands, but self-exclusion is **no longer single-mechanism**: overriding `canInit(with task:)` reads back `"edge-rum-internal"` set at `BatchTransport.swift:136` before `:137`'s resume, restoring defence check #2, and `:699-702`'s comment that `taskDescription` is unavailable at this layer is **incorrect** (the inner-task read at `:776` is still always `nil`, so D4 as a defect is confirmed and D4 as a dead end is not). Two ceilings are documented rather than fixed — **WKWebView** takes **zero** creation-swizzle hits, so in-page traffic is invisible under an otherwise-minted tap root, and non-`URLSession` stacks (**Flutter's `dart:io` most consequentially — such a host emits no HTTP spans at all**, plus gRPC-Swift/NIO, Cronet, raw `CFNetwork`) are unreachable, both failing as **silence** rather than as `injected_unwired`, while everything on `URLSession` (Alamofire, Apollo, GTMSessionFetcher, RN `RCTNetworking`) is reached by construction. **#161 gets nothing**: no new attribute, no new enum member, no new `trace.root_type` — every finding is a coverage fact or an injection guard, and **the wire is unchanged**; #162 carries the degradation rule, the positive guard, the `canInit(with task:)` fix and the revised self-exclusion note. No new tickets, no fog graduated.

- [T11 — Warm foreground resume: does a rootless resume mint a root?](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/166) — **yes, it mints**, as `trace.root_type = resume` — a value Android has no twin for, so it clears #161 before #162 can freeze it; declaring `injected_unattributed` correct here was rejected because it collapses three distinct causes into one member (T1's genuine no-root, T4's coverage holes, the resume burst), the exact failure T1's always-stamped marker exists to prevent, and because the resume burst is the worst-latency traffic in the app (cold pool, cold caches, token refresh, every request paying T3's **O3** handshake) so "are resume requests slower than in-session requests" is the resume twin of the launch question this map was chartered to answer. Reusing **`navigation`** was the cheap answer and is wrong in a way that costs more than it saves: T6 produced **materially fewer `navigation` roots on iOS than Android**, a delta already going into the handover, and folding the app's highest-frequency root into it **reverses that difference's sign** while making every resume a phantom screen transition — the mechanical tell being that a root's identity rides on its carrying event, and a resume has no screen, only `app_lifecycle`. The mint is at **`willEnterForeground` (`LifecycleCapture.swift:164-171`), immediately before the existing `emit(state: "foregrounded")`** — `didBecomeActive` is too late by construction, since the burst is fired by host code hanging off the very notification we observe — and **conditional on an empty-or-expired carrier**, T6's `viewDidAppear` rule reused verbatim, which answers the sub-2-second peek for free and makes launch and resume mutually exclusive without depending on which notifications a cold launch posts. Mint-before-emit also makes **session rotation free**: that emit is the first touch after a >30-minute gap, so `Recorder.swift:335` refreshes the context before `app_lifecycle` is enqueued and the root is born into the new session — rotation is lazy and event-driven, never resume-driven, and `SessionManager.rotate()` has no production caller. Two ticket premises **corrected**: the resume *does* have an emitter (`app_lifecycle` foregrounded), and the resume emit *is* the rotation trigger. A trace can nonetheless straddle a rotation via T6's non-emitting secure-field mint (T5's launch root has the same shape), so rather than reintroduce the carrier-clear hook T6 refused, the handover states the constraint: **envelopes are keyed on `trace.id` alone, never `(session.id, trace.id)`**. **`app_lifecycle` becomes span-carrying** on the `foregrounded` transition when a root was minted (`trace.id`, `rum.action.id`, `trace.root_type`, `span.start_time`; `span.id`/`parent.span.id`/`span.duration_ms` absent) — not for filtering, which #129's denormalization already gives, but to keep the **resume instant join-reachable** rather than recoverable only by a time-proximity join, the fragile shape this map keeps refusing; absence on a `foregrounded` event is itself the peek signal, and carrying buys #162 a rule (*every root has a carrying event*) with T6's secure-field tap as the sole PII-justified exception. **T5's `applicationState == .background` guard must not be ported** — at `willEnterForeground` the state is *still* `.background`, so the guard applied verbatim suppresses **100%** of resume roots as a silent no-op indistinguishable from the bug; the notification itself is the guard, and #162 carries this as an explicit **do-not-add note** rather than as silence. **No expiry exemption** — T5's would end before the window it exempts (a warm resume renders within a frame or two) and the display link is already `invalidate()`d at `PageLoadCapture.swift:311-314`; T2's extension triggers keep a slow *sequential* burst as one trace anyway, since the 2 s is idle time, not wall time. **No new `traceparent.outcome` member** — a resume request finds a live root and is plain `injected_attributed`. No new tickets, no fog graduated.

- [T8 — File the iOS delta against the backend wire contract](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/issues/161) — the ticket's premise had moved: Android #132 **closed** and its backend half **shipped**, so this became a diff against live code rather than a filing into an open design — at `EDGETELEMETRYPROCESSORGO@2874607` the seven trace columns, the `rum_action_id` index and the `rum_action_envelopes` view all exist (`0002_android_wire_contract.up.sql:5-12, 77-78, 96-106`) and `extractTraceInfo` (`extract.go:280-290`) reads every one of the map's names, so **iOS needs no new column and no new table**. The name diff comes back **eight for eight with zero defects** — the fidelity rule held across eleven tickets — and `VARCHAR(16)` holds every `trace.root_type` value including the longest, `interaction`. The one real defect found is **in the map, not the backend**: T1 declined to split `injected_unattributed` into never-had-root vs root-expired because that "would need the contract changed first", but **the contract already contains `injected_expired`** (§6.1, new in v3, with iOS's own 2 s/10 s thresholds) — so iOS as specified would emit an Android *name* carrying a different *meaning*, invisible in exactly the way T1's always-stamped marker exists to prevent; **iOS populates all six**, with the carrier returning `.expired` rather than clearing (lazy expiry already, no new state, and deliberately **not** sourced from T7's `lastRoot`, which would hand the guard test a route it was written to forbid).
