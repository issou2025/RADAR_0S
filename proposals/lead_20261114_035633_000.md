# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Plugins: read MPB 3.0 in Unreal, Revit, and AutoCAD and Civil 3D**

*Project description:*
## Brief

**What:** The Unreal, Revit, and AutoCAD and Civil 3D plugins import MPB 3.0 bundles beside 2.x, with one level choice and one import flow in every host.
**Why:** Production switches to MPB 3.0 on 2026-12-15, and every released plugin refuses a 3.0 bundle.

---

## Problem Statement

MPB 3.0 is a breaking major. Its manifest moves to the bundle root, its folders and file names change, the level belongs to the download instead of to each category, and the terrain tiles leave the bundle. Every released plugin refuses a manifest newer than major 2, so on the day production switches to 3.0 a curator who orders a site cannot import it in Unreal, Revit, AutoCAD or Civil 3D.

The three plugins have also drifted apart. Revit has an import window, a checklist and a level chooser. AutoCAD has no import window and cannot import a zip from disk. Unreal has one panel, no level choice, and its Cancel stops only the download. A curator who uses two hosts learns two products, and each new host is built from a copy of another host's code.

## Solution

Three releases that read MPB 3.0 beside 2.x: `unreal-0.9.0`, `revit-1.2.0` and `autocad-1.2.0` (AutoCAD and Civil 3D). They are on GitHub by Monday 2026-12-14; the date is a target that may be beaten. Each is submitted to its store the same day, and no date waits on a store.

In every host the curator signs in, opens the vault, chooses Max, Med or Min with each level's size shown and the platform's recommendation preselected, downloads, and imports through one import window that lists the steps and can be cancelled between steps. A zip on disk imports with no account. The same actions carry the same words in the same order in every host.

Behind that, the plugins share what can be shared: one home for the host-neutral .NET source and windows, one set of reader cases in the conformance corpus that every plugin's reader passes in its own language, and one written common core in the host plugin standard that a new host is built against.

## Acceptance

1. Each plugin imports a conforming MPB 3.0 bundle and still imports an MPB 2.x bundle. A bundle is 3.0 when the manifest is at the bundle root, 2.x when it is at the 2.x location, and a major above 3 is refused with the existing update message.
2. For a 3.0 bundle a plugin finds each file by its promised name in the manifest's one file catalog. It reads nothing from a per-host block, and a name absent from the catalog is reported as not in this bundle.
3. A host never converts a georeferenced file itself. Anything a host showed from 2.x that 3.0 holds no file for is left out for 3.0 bundles and named in that host's release notes.
4. Every host offers one level control: Max, Med and Min, each with its size, the platform's recommendation preselected, the curator free to choose. Revit's per-category column appears for 2.x bundles only.
5. A download request names the promised files the host wants and one level. A send from the web vault carries no level, and the host opens its import window with the control on the recommendation.
6. The cache holds one slot per host per order, the last level downloaded. A hit needs the same host and the same level; an entry with no host recorded is fetched again; choosing another level is a fresh download that replaces the slot. Each host's existing re-import rule is unchanged.
7. Revit and AutoCAD show the same sign-in, vault, import, about and notices windows, from one shared source. AutoCAD gains the import window and import from disk. Unreal offers the same import flow: the level control, the list of steps with their state, and Cancel between steps.
8. During an import every host shows the current step and the elapsed time, and an estimate where that host has a measured cost. In Revit a layer whose estimate breaks the five-minute budget starts unticked with its estimate shown; the plugin never thins a layer.
9. In Unreal, streaming the terrain of a 3.0 bundle fetches the terrain tiles Extra when the curator asks for it, and the action is disabled with a reason when the platform lists no tiles.
10. Unreal draws every public-record layer a bundle carries, aligned to the terrain (#559).
11. The host plugin standard states the common core every plugin supports, in order and with its words: sign in, list the vault, choose a level, download, import, import a zip from disk with no account, refuse a version out of range, show credits and notices, import again. A support matrix lists each host against it, and host-only features sit beside it, named as such.
12. The conformance corpus holds reader cases: for each valid 3.0 fixture, which promised files a reader finds, in which frame, and what it skips and why. The .NET reader and the Unreal reader pass the same cases.
13. All three hosts are verified and pinned at MPB 2.2.0 before the 3.0 text is frozen, live conformance is green, and each host is re-pinned at 3.0.0 with its release (#577, #569).
14. Each host's store listing text, reviewer instructions and README changes are files in this repository, each delivered as an open pull request for the founder. The reviewer instructions use the public samples page: download a sample, import it from disk, no account. The root README's host table lists AutoCAD.
15. A page tells a plugin author how to build a reader for MPB 3.0.
16. The time of every import step at every level in every host is measured at the release gate and published in the docs.
17. **Verified live:** for each host the packaged release zip is installed clean, signs in on the dev platform, downloads at a chosen level, and imports one dev-built 3.0 bundle and one 2.x bundle, all through the host harness with no manual step: `unreal.import-check` and `unreal.automation-suite` on Unreal 5.8; `revit.plugin-loads` and `revit.import-check` on Revit 2025, 2026 and 2027; `autocad.plugin-loads` and `autocad.import-check` on AutoCAD 2025, 2026 and 2027; `civil3d.plugin-loads`, `civil3d.import-check` and `civil3d.landxml-import` on Civil 3D 2027; `vault.round-trip` for a send from the web vault. If the dev platform has no conforming 3.0 bundle by 2026-12-11 no release is cut on fixture evidence alone: the releases wait.

## Implementation Decisions

Decisions the founder made in the grilling of 2026-11-13:

- **Two reading paths, chosen by where the manifest is.** The 2.x path is frozen as it ships and takes fixes only. The 3.0 path is new and feeds the same import steps. 2.x reading stays until a founder decision removes it.
- **No per-host blocks in the 3.0 manifest.** Every value a plugin reads from its host block today needs a neutral home in the manifest. An inventory of those values is checked against the draft format text before the freeze (#586).
- **A plugin names its promised files and a level.** The platform keeps no per-host file list for 3.0. The glossary entry for a download view is reworded to match.
- **One level control in every host, the curator chooses.** Per-category levels are not built for any host; #316 closes as superseded.
- **The platform keeps recommending for launch.** "Recommended" means the highest level expected to import in about five minutes on the reference machine, Revit's promise extended to every host. The gate's timing table is what the platform's figures are set from.
- **Sizes now, minutes later.** At launch the control shows each level's size and the recommendation. The manifest's catalog states each file's count (rows, features, triangles or pixels) and the platform's answer carries the counts per level beside the sizes, so "about N minutes" beside each level can follow in the first release after launch.
- **The Unreal tiles mode stays and must ship**, moved onto the terrain tiles Extra. It is compatibility work.
- **Cache:** one slot per host per order, as in Acceptance 6. Unreal's per-project cache gains the level only (#564).
- **A shared .NET home.** The host-neutral .NET source moves out of the Revit tree into a home named for no host, with no behaviour change, after #588 and before the freeze. The 3.0 reader is written once there for every .NET host. Unreal and the Python reader share through the corpus reader cases.
- **One shared set of .NET windows** in that home, so Revit and AutoCAD are identical by construction. Alignment is worth extra time. If the date is threatened, Unreal's step list is ship-if-ready and its level control stays must-ship.
- **Unreal's import window has no per-layer checklist**, and the support matrix names that as the one gap in the common core.
- **Parity is the common core plus the corpus reader cases** (Acceptance 11 and 12). Aligned windows and words are part of parity.
- **The Platform API description** for the level request, the recommendation, the sizes, the counts and the Extras list is published with the freeze on 2026-11-27. The readers build against it with a test double and meet the real platform on dev.
- **All live checks run through the host harness**, with the same check names in every host; no ticket hands back a "load it and look" step. Civil 3D 2025 and 2026 ship if ready.
- **Releases, store submissions and outward-facing copy are the founder's steps.** Builds run without the founder.
- **A new decision record** in this repository states the common core, the shared .NET home, the corpus reader cases and the separate version tracks. The founder merges it.

Decisions made while writing this spec, each with its reason:

- **Versions are `unreal-0.9.0`, `revit-1.2.0` and `autocad-1.2.0`, with no rule that the hosts stay in step.** AutoCAD skips 1.1.0 so the two Autodesk plugins that share a source carry one number at launch. A binding rule would force empty releases or hold a fix in one host for another, so each host keeps its own track.
- **The decision record is its own pull request, not part of the pull request that makes the shared home.** A founder merge on the move would hold every ticket behind it; the move itself was decided in the grilling.
- **The per-layer checklist stays in the shared .NET import window for launch.** Acceptance 8 depends on it. Whether any host needs per-layer selection once the slow layers are fixed is reviewed after launch.
- **The reader cases wait for the conformance check's 3.0 fixtures (#587)** instead of carrying their own, so there is one set of valid 3.0 fixtures.
- **The repository holds no sample bundle.** Import checks use a 3.0 fixture held outside the repository that passes the open conformance check; the release gate uses bundles built by the dev platform.
- **Each host's release candidate is packaged in the first gate ticket for that host**, so the gate proves the zip that ships.
- **The 2.2.0 baseline is two tickets:** #569 clears the 2.1.0 changelog entry and the vendored API description, then #591 verifies and pins the three hosts and closes #577.
- **Revit's 3.0 import is two tickets,** a headless plan and a live import, because together they exceed one builder's budget.
- **Unreal's cache gains the level with its level control,** not with the shared cache fix, so that fix stays inside the .NET code.

Tracker: #569, #564 and #559 become tickets of this spec. #577 is closed by the pin ticket. #460 and #513 wait on their host's release ticket here. #557 is met by the Civil 3D 2027 gate.

## Testing Decisions

- **Corpus reader cases** are the highest seam for reading: a fixture in, a neutral result out, the same cases for every reader. Prior art: the conformance corpus and its per-host "verified against" pins.
- **Each host's existing headless suite** covers the import plan built from a reader's result: the .NET core tests for Revit and AutoCAD, the Unreal automation suite.
- **The shared windows** are tested through their view state (labels, order, enabled state) in the shared home, with the labels checked against the standard's words. Prior art: the shared window labels and their tests.
- **The cache** is tested at the cache-validity seam: host and level in, hit or miss out.
- **The download request, recommendation and sizes** are tested against a test double of the published Platform API description; the dev platform is met at the gate.
- **Live:** the host-harness checks named in Acceptance 17. A reader's pull request runs its host's import check on the generated 3.0 fixture and on a 2.x bundle.

Test external behaviour only: what a curator sees listed, imported, skipped or refused.
