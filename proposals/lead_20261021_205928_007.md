### Summary / Description
On macOS, the Zedu desktop app's keychain access group is still the Flutter template value `com.example.flutterStarter`, but the app's bundle identifier is `com.zedu.desktopApp`. The two do not match.

### Why is this ticket needed?
- The app keeps the login session with `flutter_secure_storage`, which uses the macOS keychain. A keychain access group that does not belong to the app's own identifier can make keychain reads and writes fail in a properly signed build, so the user would be signed out or unable to stay signed in.
- The mismatch is invisible in a debug run on a developer's Mac and shows up only in signed release builds.
- Not a duplicate: #274 is about the Windows file details that say "com.example". This ticket is about the macOS keychain group.

### Details
- `macos/Runner/Configs/AppInfo.xcconfig` line 11: `PRODUCT_BUNDLE_IDENTIFIER = com.zedu.desktopApp`.
- `macos/Runner/Release.entitlements` (lines 8-11) and `macos/Runner/DebugProfile.entitlements` (lines 13-15): `keychain-access-groups` is `$(AppIdentifierPrefix)com.example.flutterStarter`.
- `pubspec.yaml` line 22: `flutter_secure_storage: ^10.2.0`.
- The same template value is also in `AppInfo.xcconfig` line 14 (`PRODUCT_COPYRIGHT = Copyright © 2026 com.example.`).

Scope: set the keychain access group in both entitlement files to `$(AppIdentifierPrefix)com.zedu.desktopApp` and fix the copyright text. Whether a signed build actually fails needs a check on a Mac with a real signing identity, which I did not do.

### Steps to reproduce
1. Open `macos/Runner/Configs/AppInfo.xcconfig` and read the bundle identifier.
2. Open `macos/Runner/Release.entitlements` and read the keychain access group.
3. Compare them.

**Expected:** the keychain group is built from the app's identifier (`com.zedu.desktopApp`).
**Actual:** it says `com.example.flutterStarter`.

### Acceptance criteria
- [ ] Both entitlement files use `$(AppIdentifierPrefix)com.zedu.desktopApp`
- [ ] The macOS copyright line no longer says "com.example"
- [ ] A signed macOS build keeps the login session after a restart
