## Why

The repo's top level is in good shape, but three areas have grown into catch-alls since the original layout. Most of the drift comes from features that were placed wherever was nearest at the time.

- **`server/device/` (43 files, about 26,600 lines, roughly half the server).** CONTRIBUTING still describes it as "Simulator control (simctl, idb)". It now holds:
  - device backends: `simctl`, `idb`, `sim_bridge`, `wda`/`wda_client`, `devicectl`, `pmd3`, `tunneld`, `usbmux`, `adb`, `u2_client`
  - the Android build pipeline: `gradle`, `jdk`, `build_records`, plus `macho` and `elf` for symbolication
  - host tool management: `tool_updates`, `tool_versions`, `tool_probe`
  - preview and media: `preview`, `scrcpy_preview`, `media_engine`, `screenshots`
  - web inspection: `webinspector`, `web_content`, `web_probing`
  - knowledge: `landmarks`
  - app state: `app_state`, `plist`, `live_plist`
- **The recording feature is loose at the top of `server/`:** `recording.py`, `recording_video.py`, `record_cli.py`. `server/main.py` (2,250 lines) is both the FastAPI app and 8 `_cmd_*` CLI handlers, beside a second entry point, `server/__main__.py`.
- **`docs/` has 16 loose files.** Reference docs sit beside specs and planning docs that belong in `docs/proposals/`, a shipped fix's write-up, and an unreferenced infographic.
- **CONTRIBUTING's architecture diagram is stale.** It has no Android, no recording or trace, and no MCP tool set.

This issue tracks the cleanup, **one PR per phase**. Phases 1–2 are cheap and safe. Phase 3 is the big one, done as several mechanical PRs.

## Rules for every phase

- **Mechanical moves only.** Use `git mv` plus import updates, and change no behaviour. The PR description lists every changed line that is not an import or a path.
- **Check a new package name against `.gitignore`** (`git check-ignore -v server/<name>/x.py`). `build/` is ignored, so a `server/build/` package would leave new files out of commits.
- **Update every string reference to a moved path:**
  - test patch targets (`"server.device.adb.…"`)
  - `.coderabbit.yaml` path rules (it has rules on `server/device/sim_bridge.py` and `server/device/webinspector.py`)
  - per-file ignores in `pyproject.toml`
  - comments and docs that name the file
  - paths built from parts, which a search for the path string does not find: `/ "server" / "device" / ...` (`tests/test_readme_sync.py` reads the backend modules this way, which matters for 3f). Prefer locating a source through its module's `__file__`.
- **No compatibility shims for internal imports.** Nothing outside this repo imports `server.*`. The exception is entry points named as strings: `server/lifecycle/ports.py` recognises quern by `"server.main"` in a process's arguments, and `setup.py` runs `python -m server.main`. Those must keep working.
- **Updater safety (#212).** Since 0.18.4, the updater hands everything after the swap to a fresh process. Updaters from 0.18.1–0.18.3 import only `server.config`, `server.lifecycle.invocation` and `server.lifecycle.update_check` from the new tree (`server/lifecycle/stale_modules.py`). A phase that moves any of those, or anything setup or the updater imports, must run `scripts/release-rehearsal.sh` before merge.
- **Coordinate with in-flight work.** Before starting a move, check the open PRs and live sessions (`ListAgents`) for branches that touch the files being moved. Merge `main` into those branches afterwards.
- **One PR at a time.** CodeRabbit allows about one review an hour, shared across sessions.
- **Verify every phase:** the full suite with `PYTHONPATH=$PWD`, the MCP tests, `quern start` from the worktree with a smoke check, and a grep showing no stale references to the old path.
