## 🇨🇳 中文讨论区 (Chinese Version)

想和大家认真征求一波新版 `jeikcode` 的真实体验感。

我自己目前已经在生产环境高频重度使用它了，家里和机房里的软路由、多台 Linux 服务器、Windows 工作站等七八台设备全都装上了 jeikcode。

坦白讲，它给我个人最大的感受就是：**编码准、用起来顺手、极其强悍的运维神器，而且代码写得也很漂亮**。这主要是因为 jeikcode 吸收了市面上众多开源 Agent 的优秀特性，同时加上了我亲自反复推敲、精简的提示词与工具集——每一句话都没有废话，全都是精益求精打磨出来的。

大家之前提的前端 BUG，目前我已经基本解决掉了。现在重心转向下一阶段，我给自己定下了两个核心硬目标，以及一个重头戏规划：

---

### 1. 模型提供商的前端重构
说实话，目前前端和 TUI 的模型管理我自己是相当不满意的。当时为了能让核心编码和运维功能先跑起来，这块确实处理得比较糙。
- **改进方案**：这次准备彻底推倒重构，做成**以提供商为核心驱动**的架构。
- **具体结构**：一个提供商下可以配多个 Base URL 和 Key，方便管理同一个厂商的多个账号；每个 Key 下面再自由添加绑定的模型，统一纳入管理，逻辑上会清晰、科学得多。

### 2. 主流模型生态一键预设接入
直接把大家最高频使用的供应商订阅全部做成开箱即用的一键配置，省去到处翻文档配端点的麻烦。
- 涵盖：**OpenRouter、opencode go、command go、MiniMax、DeepSeek、小米、Anthropic、ChatGPT Codex、Gemini、Grok、Step 阶跃星辰、阿里、豆包、Kimi、基元律动** 等核心服务商。

### 3. 多 Agent 架构演进（重头戏）
这个点我想着重展开聊聊。下一个阶段，jeikcode 会往类似 Grokbot 的多 Bot 架构演进。每个 Agent/Bot 都会标配自己专属的 Skill、MCP 和工具链，真正像人类团队一样分工协作：
- **前端开发 Bot**：标配标准的专业工具（比如 Claude Design Skill、UIUXProMax），专精交互与页面。
- **后端开发 Bot**：直接发挥 jeikcode 本身就极强的底层后端编码能力，保持纯粹精干，不需要硬塞无关的冗余工具。
- **测试与 QA Bot**：直接挂载 Chrome MCP、Playwright MCP，真刀真枪地在真实浏览器里跑测试、抓前端交互 BUG、测后端接口。
- **代码审查 Agent**：调度两个不同的模型进行双向并行 Review，模拟真实团队的 Code Review 流程。
- **爬虫与浏览器自动化 Bot**：配齐 Python 全套自动化 MCP/Skill 工具，让它们自主去抓取数据、清洗排查并汇报结果。
- **灵活部署**：每个 Bot 都可以自由自定义挂载的模型、运行的机器（跑在本机还是云端服务器）。

这套多 Agent 体系工程量绝对不小，但慢工出细活，我希望能把它打磨成一个真正扎实、高质量的产物。

## 🌐 English Discussion (For International Users)

I’d love to gather authentic community feedback on the latest version of `jeikcode`.

I have been dogfooding and heavily using jeikcode in production across 7 to 8 heterogeneous machines, including x86 soft routers, multiple Linux servers, and Windows workstations. 

To be completely frank, the biggest impressions it leaves on me are: **accurate code generation, effortless daily usage, an absolute powerhouse for server ops, and high-quality refactoring**. This comes down to jeikcode absorbing the strongest design elements from various open-source agents, combined with lean, hand-crafted system prompts and lightweight tool definitions—no filler tokens, just distilled execution logic.

The frontend bugs reported earlier are now largely squashed. Looking ahead, I have set two mandatory milestones, followed by a major architectural leap:

---

### 1. Frontend & TUI Model Management Overhaul
Honestly, I’m quite dissatisfied with the current model settings in both the Web UI and TUI. Back then, the priority was simply getting the core execution engine off the ground, so config ergonomics took a back seat.
- **The Rework**: Moving to a **Provider-driven architecture**.
- **Hierarchy**: One provider can hold multiple Base URLs and API Keys (making multi-account management seamless). Each Key can then associate with its designated models under a clean, unified dashboard.

### 2. Native One-Click Presets for Mainstream Providers
Out-of-the-box configuration presets for all high-frequency model providers, eliminating manual endpoint guesswork.
- Supporting: **OpenRouter, opencode go, command go, MiniMax, DeepSeek, Xiaomi, Anthropic, ChatGPT Codex, Gemini, Grok, StepFun, Alibaba, Doubao, Kimi, Jiyuan Lvdong**, and more.

### 3. Dedicated Multi-Agent Architecture (The Main Focus)
This is where the real architectural leap happens. In the next phase, jeikcode will evolve toward a specialized multi-bot architecture similar to Grokbot. Each agent will be equipped with its own dedicated Skills, MCPs, and toolchains—collaborating just like an actual software engineering team:
- **Frontend Bot**: Armed with dedicated UI/UX skill stacks (e.g., Claude Design Skill, UIUXProMax) to handle styling and user experience.
- **Backend Bot**: Lean and focused. It relies directly on jeikcode's native backend strengths without unnecessary wrapper layers.
- **QA & Testing Bot**: Integrated with Chrome MCP and Playwright MCP to run live end-to-end tests inside real browsers, hunting down frontend UI glitches and backend API failures.
- **Reviewer Agent**: Runs two distinct models in parallel to conduct thorough, unbiased cross-model Code Reviews before landing changes.
- **Scraping & Automation Bot**: Equipped with a full Python-based browser automation stack to independently scrape data, verify results, and report back.
- **Decoupled Execution**: Every single Bot will allow custom model selection and runtime targets (local workstation vs. remote cloud node).

Building this will take serious engineering work, but I want to take the time to craft it into a durable, enterprise-ready workflow.
