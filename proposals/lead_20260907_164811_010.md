## Problem

The original iOS bundle ID (`com.madhusangita.sharedTasks`) is stuck in a
state where it can't be registered by any account we have access to.
Thoroughly investigated (across two sessions):

- Checked both current accounts (personal Gmail, work email) on
  developer.apple.com — team `4TH9L6GGA3` not found on either, initially
- Found a cached certificate in the local Keychain identifying it as
  `Apple Development: madhusangita.behuria@gmail.com`, team `4TH9L6GGA3`
- Confirmed it was never a paid Apple Developer Program membership
- **Resolution found**: a fresh, explicit interactive sign-in in Xcode's
  Accounts pane (Settings → Accounts → "+", `madhusangita.behuria@gmail.com`)
  reactivated a stale cached session. Team `4TH9L6GGA3` turned out to be
  perfectly fine — it's this personal Gmail account's own team. Confirmed
  by successfully registering a *different* bundle ID
  (`com.madhusangita.dev.sharedTasks`) under it, both in Xcode's UI and
  via CLI, on a real device.
- The specific string `com.madhusangita.sharedTasks` remains stuck no
  matter which account/team is used — that's scoped to the string itself
  (likely a stale/orphaned registration from however this project was
  first scaffolded), not an account-access problem.

**Separately, and importantly:** discovered that real iPhone testing over
the past ~2 weeks had actually been signing under the **work Enterprise
team** (`EREU5CMX5R`, A.P. Møller - Mærsk A/S) via Xcode's automatic
signing silently resolving to it — not the committed `4TH9L6GGA3`. That
must stop: Apple's Enterprise Program terms restrict that account to the
company's own internal use, not personal projects, regardless of
technical convenience.

## Known limitation to flag now, not fix here

The free Personal Team came up during investigation as a fallback option
but wasn't needed in the end — team `4TH9L6GGA3` (a free Personal Team
itself) is what's actually in use. Free Personal Teams **cannot enable
Push Notifications (APNs)** — that capability requires a paid Apple
Developer Program membership. This doesn't block anything today, but it
directly affects **#12** (push notification on task assignment): iOS push
notifications will need a paid account regardless of this migration. Out
of scope for this issue — raising it now so it's not a surprise later.
