# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[Work]: Replace Makefile with go-task for cross-platform developer commands**

*Project description:*
### Objective

Replace the root `Makefile` with a `Taskfile.yml` run by [go-task](https://taskfile.dev) so contributors on Windows, macOS, and Linux run the same developer commands without `make` or a POSIX shell.

### Context

The root `Makefile` (~100 targets across `api-*` and `sim-*`) is the canonical entry point for backend validation, simulator runs, and host operations. It is referenced by CI (`api.yml`, `simulator.yml`, `post-deploy-smoke.yml`) and by `README.md`.

`make` is not installed by default on Windows, and the recipes assume a POSIX shell. Because TailTag is an open-source project with Windows contributors, that is a setup barrier. Most target logic already lives in Python scripts under `scripts/` and `tools/simulator`, so the migration should be mostly mechanical.

go-task is proposed over `just` because its built-in shell runs recipes on Windows without Git Bash or `sh` on the PATH. `just` and `poethepoet` were considered; reviewers may challenge this choice before implementation.

Related: #132 (Flutter contributor tooling and diagnostics).

### Scope

Included:
- Add `Taskfile.yml` at the repository root with a task for every current Makefile target, each with a `desc:`. `task --list` replaces `make help`.
- Keep target names where practical so existing commands map directly (`make api-check` → `task api-check`).
- Preserve guarded behavior: `--confirm` arguments, required-variable checks, and the devcontainer branch used by Django commands.
- Preserve sequential execution for `api-check` and `sim-check`, matching `.NOTPARALLEL`.
- Update the CI workflows to invoke go-task, with a pinned install method.
- Update `README.md`, `CONTRIBUTING.md`, and current developer docs that reference `make` commands.
- Remove the `Makefile` once parity is verified.

Excluded:
- Behavior changes in `scripts/` or `tools/simulator`.
- Replacing `uv`, Semgrep, or Docker tooling.
- New confirmation prompts on destructive targets, unless approved separately.
- Rewriting historical documents that mention `make`.

### Acceptance criteria

- [ ] `task --list` shows every former `make help` target with its existing description.
- [ ] Each Makefile target has a task with the same arguments and environment variables.
- [ ] `task api-check` and `task sim-check` run their prerequisites sequentially.
- [ ] Missing required variables (for example `POOL`, `TARGET`, `RUN_ID`) fail with a clear error.
- [ ] A Windows contributor can run `task api-check` with only go-task and the documented prerequisites installed. Verified on Windows, macOS, and Linux.
- [ ] CI runs go-task for the affected workflows and passes on a pull request.
- [ ] Current docs use go-task commands. No `make` references remain outside historical material.
- [ ] `Makefile` is removed after parity is verified.

### Dependencies or blockers

Open decisions to resolve before implementation:
- Whether to keep go-task (see Context) or choose a different runner.
- How to handle the `bash -n` bootstrap syntax check (`sim-host-bootstrap-check`), which requires bash and so is not native on Windows.
- Whether destructive targets (`sim-cleanup`, staging reset) should gain `prompt:` confirmations. The default is parity with the Makefile.
- Whether `requires:` checks should be added where the Makefile has none (`sim-convention`). The default is parity.

### Implementation notes

- Makefile variables with `override` and `$(call run_django_command,…)` map to `vars:` and an internal task.
- `$(wildcard)`/`$(sort)` in `SIM_SEMGREP_TARGETS` need a replacement (a `sh:` variable or a small Python helper).
- Make's `$(subst ','"'"',…)` quoting workaround should not be needed in go-task, but quoting must be tested with values containing spaces or quotes.
- `api-check` and `sim-check` must use sequential `cmds: - task:` entries, not `deps:`, which run in parallel.
