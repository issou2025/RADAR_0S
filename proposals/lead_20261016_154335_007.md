# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Table semantics: a cell without TableCell is shifted right by its column's left offset**

*Project description:*
Reproduced on Flutter 3.47.4 stable (9584c6713b), Chrome on macOS. The code involved is unchanged on master 697012a97f (links below).

When a `TableRow` child is not wrapped in `TableCell`, `RenderTable` synthesizes a wrapper cell semantics node for it. The child's semantics node is then shifted right a second time by its column's left offset whenever the column is wider than that offset (the widths of the columns before it combined). The y axis has the same flaw for a row that is taller than its top offset. The offset is in the framework's semantics tree; on web it misplaces the DOM elements built from it, for example a `TextField`'s `<input>`.

### Steps to reproduce

1. Create a package named `repro` and put the code sample in `lib/main.dart`.
2. Run the widget tests below with `flutter test`. They turn semantics on, compose each labelled node's rect with its ancestors' transforms, and print the result next to where the widget is laid out.

import 'package:flutter/rendering.dart';
import 'package:flutter_test/flutter_test.dart';

/// Every labelled node reachable from the root, with its global left edge.
List<String> walk(WidgetTester tester) {
  final out = <String>[];
  void visit(SemanticsNode n, Matrix4 t) {
    final m = t.clone();
    if (n.transform != null) m.multiply(n.transform!);
    final r = MatrixUtils.transformRect(m, n.rect);
    if (n.label.isNotEmpty) out.add('${n.label}@${(r.left / tester.view.devicePixelRatio).round()},${(r.top / tester.view.devicePixelRatio).round()}');
    n.visitChildren((c) {
      visit(c, m);
      return true;
    });
  }

  visit(tester.binding.pipelineOwner.semanticsOwner!.rootSemanticsNode!, Matrix4.identity());
  return out;
}

### Expected results

The `reps` node starts at x=36, where it is laid out. The `load` node starts at x=108.

In the y-axis test, the `top of tall row` node starts at y=20, where it is laid out.

### Actual results

The `reps` node is at x=72, one column-0 width (36px) too far right. The `load` node is correct.

The y axis has the same issue. The `Text` at the top of the 200px row is laid out at y=20, but its semantics node is at y=40.

On web, in a real app, in a grid with a 36px "#" column followed by a 72px "Reps" column, every row's Reps `<input>` was positioned 36px right of its cell `flt-semantics` element and overlapped the next column's input. The cell element had `transform: matrix(1,0,0,1,36,0)`, and the input was drawn a further 36px right. Wrapping the cell in `TableCell` fixes it, because the child's role is then `cell`, so no wrapper is added.

### Cause

All references are to `packages/flutter/lib/src/rendering/table.dart` in `RenderTable.assembleSemanticsNode` at 3.47.4.

- [L729-L732](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L729-L732): when a cell has more than one child, or its single child's role is not `cell` or `columnHeader`, a wrapper cell node is synthesized.
- [L755-L758](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L755-L758) translates the wrapper to `_columnLefts[x]`.
- [L774-L776](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L774-L776) then guesses whether the child's rect is still table-relative: `localRect.left >= cellWidth ? -_columnLefts[x] : 0`. A fresh rect in column `x` has `left ≈ _columnLefts[x]`, so the guess is wrong whenever `_columnLefts[x] < cellWidth`: any column (other than the first) that is wider than the columns before it combined. The child is then not shifted back, and the wrapper's translate adds `_columnLefts[x]` a second time.
- [L766-L768](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L766-L768): the y guess `localRect.bottom > rowBox.height + tolerance ? -_rowTops[y] : 0` has the same flaw for a row taller than its top offset.

The same code is unchanged on master 697012a97f: the x guess is at [L768-L770](https://github.com/flutter/flutter/blob/697012a97f5d094a68015b177cf86216dd007073/packages/flutter/lib/src/rendering/table.dart#L768-L770) and the y guess at [L760-L762](https://github.com/flutter/flutter/blob/697012a97f5d094a68015b177cf86216dd007073/packages/flutter/lib/src/rendering/table.dart#L760-L762).

### Suggested fix

Before the write to `_idToIndexMap` at [L761](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L761), record `final wasCached = _idToIndexMap.containsKey(child.id)`. A child that was not cached was just bucketed with `findColumnIndex(rect.left)` and `findRowIndex(rect.top)` ([L683-L699](https://github.com/flutter/flutter/blob/9584c6713b324636289d067944a46fd6b49df14b/packages/flutter/lib/src/rendering/table.dart#L683-L699)), so its rect is table-relative by construction. For those children (`!wasCached`), shift unconditionally by `-_columnLefts[x]` (wrapper case) or by `-_rowTops[y]`. The guesses are only needed for a child reused from the cache, and the "store the transform you assigned" approach in #194545 removes them altogether. This has not been tried.
