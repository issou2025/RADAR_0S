## What do you need?

To create a top-level `/guides` section for SEO/AEO content

## Summary

All SEO/AEO content on posthog.com is in `/blog` today. It is separated only by a `Comparisons` tag, which the blog index then hides (`src/pages/blog.tsx:121`). 

This issue is for us to create `/guides` as a top-level section for that content. It reuses the new `/blog` landing page layout, moves 88 posts out of `/blog`, and replaces the single `Comparisons` tag with four tags that match how that content is written.

**Why now.** SEO/AEO content has different goals from the blog. The blog is for thought leadership, product updates, and engineering stories. `/guides` is for people (and bots and LLMs and answer engines) who compare tools and want a direct answer. A dedicated section gives that content a clear URL namespace (which we can also use for reporting more easily), a landing page that can rank, and an easier tag taxonomy. It also removes the `Comparisons` exclusion hack from the blog index.

## Scope

### 1. New `/guides` landing page

Add `src/pages/guides.tsx`. We should have the same style as /blog and the same components available.

The new page also needs:

- Its own GraphQL query, filtered on `fields.slug` regex `^/guides/`.
- A small wordmark/header component, in the pattern of `BlogHeader` in `src/pages/blog.tsx`.
- A new `Accent` value in `src/components/PostsIndex/accents.ts` (blog is `blue`, newsletter is `red`).
- A `tagOrderOverride` of `['Comparisons', 'Alternatives', 'Roundups', 'Explainers']`.
- An update to `src/components/PostsIndex/README.md` to record the third consumer.

### 2. Move the content

Move 87 files from `contents/blog/` to `contents/guides/`. The slug comes only from the file path (`gatsby/onCreateNode.ts:254` uses `createFilePath`), so the move alone changes each URL from `/blog/<slug>` to `/guides/<slug>`. No frontmatter drives the path.

In each moved file, also change:

- `rootPage: /blog` → `rootPage: /guides`. This field is the filter for the main RSS feed (`gatsby-config.js:364`). If it stays `/blog`, all 88 guides continue to publish into `/rss.xml`.
- `sidebar: Blog` → `sidebar: Guides` for consistency. The field is queried but unused in `src/templates/BlogPost.tsx` today.

### 3. Replace the tags

Retire the `Comparisons` tag and use four tags that match the content shape:

| Tag | What it holds | Count |
|---|---|---|
| **Comparisons** | Head-to-head, one product against one product (`posthog-vs-*`) | 17 |
| **Alternatives** | Alternatives to a single named product (`best-<product>-alternatives`) | 40 |
| **Roundups** | Best-of lists for a category ("best error tracking tools") | 25 |
| **Explainers** | "What is X" pages, how-tos, etc | 5 |

Each moved file carries **exactly one** of these four tags. Remove the secondary tags for now (`Privacy`, `Open source`, `AI observability`, `Growth`, `Product engineers`, `Studies`) from the moved files. `usePostFilters.ts:37-42` builds the filter pills from every tag present, so a leftover secondary tag adds a stray pill to the `/guides` filter row.

The full per-file plan is in the "Tag change plan" section below.
