# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Shortcuts with Ctrl held: Ctrl+C/X/V can't be typed, and a setting for plain letters**

*Project description:*
Since f9abb32f (#400), two-letter shortcuts are typed with Ctrl held. We've been using this on our fork and found two things.

## 1. Shortcuts with C, X or V can't be typed in a real window (bug)
- **Cause.** egui-winit turns Ctrl+C, Ctrl+X and Ctrl+V into `Event::Copy`, `Event::Cut` and `Event::Paste(..)`, not `Event::Key`. `ctrl_letters` reads only key events, so it never sees those three letters.
- **Effect.** Any shortcut with C, X or V in it can't be typed with Ctrl held: CO Copy, MV Move, TX Text, CS Create Similar, CG Cancel Edit Mode, ZC and so on, in the project and in the Family Editor.
  - With an empty system clipboard, Ctrl+V arrives only as a key release.
- **Why the tests pass.** `shortcut()` sends raw key presses, so it never takes this path.

## 2. A setting for plain letters (proposal)
- **The proposal.** A **Shortcuts need Ctrl** check box in Settings > User Interface, kept in `settings.json`. It would be **on by default**, so main's behaviour doesn't change. Turned off, two plain letters are a shortcut, as they were before f9abb32f.
- **Why.**
  - In Revit, keyboard shortcuts are plain letters: WA, not Ctrl+W, A.
  - Users coming from Revit type them without thinking. Holding Ctrl for every shortcut is a habit they'd have to unlearn.
  - The Ctrl design suits users who'd rather keep letters free, so both are worth offering.
- **With it off:**
  - Ctrl+S/O/N/K/P/D/Z/Y/1 act at once, with no half-second wait.
  - Digits still start a typed length.
  - Nothing fires while a text field has focus.

## What we have
Both are done on our fork in one change, with tests:
- the bug fix: Copy, Cut and Paste events count as C, X and V while a shortcut can start, and on their own they still copy, cut or paste once;
- the setting, for the project and the Family Editor;
- `shortcut()` following the setting.

On our fork the default is off. For main it would be on.

If you'd like this, we can open a small PR from main, as two commits (the fix, then the setting), so you can take the fix alone. It would land after #404, keeping to one open PR from us at a time. It shouldn't get in the way of #403: the setting only decides whether Ctrl must be held, not which keys map to what.
