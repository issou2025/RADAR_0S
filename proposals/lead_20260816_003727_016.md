## What

A **process tier**: the sibling of ADR 0008's connector tier, one altitude *above* inference. A process is a declarative stage list in `processes/*.yml`, advanced by a generic **reconciler** that runs on a schedule and is a pure function of the events recorded so far.

Two normative rules:

- **The reconciler acts; Aware observes.** Milestones POST to `/sensors/<app>` like any other producer — no runtime change, no new engine, no new topic.
- **Processes are definitions-as-data.** The `events/*.yml` move, one tier up. Process N+1 is a YAML file, not a component.

Every stage is `act` (the reconciler does it and emits the event) or `await` (it watches for a fact and emits when it appears). `after` is a list, so a process is a DAG.

## Why

The monthly DreamHost invoice was built and abandoned: 12 n8n workflows, 79 nodes, 7 webhooks and a Redis keyspace, stalled on one parenthesis in the original design — *"send an email to me so that I could validate the data (**trigger the workflow continuation in some way**)."*

That is the saga problem: resume tokens, correlation IDs, a callback endpoint outliving the runtime. Reconciliation **avoids** it rather than solving it — nothing is suspended, so nothing needs resuming. A fact is recorded; the next run notices.

Durable state was the right instinct in the original; what went wrong is that the finished half pays for it while needing none, and the half that needed it was never built.

## Decisions needed before building

- [ ] **Is Prefect earning its place?** A daily idempotent loop is also a CronJob on the existing cluster. Prefect buys run history, alerting, and the (read-only, beta) MCP inspection surface. Worth it if more flows follow.
- [ ] **Execution environment** — whether Prefect Cloud's free tier includes managed execution, or the reconciler needs a K8s worker (`workers/reconciler/Dockerfile` would be auto-discovered by `publish-images.yml`).
- [ ] **Where the code lives** — `processes/` + `workers/` here, or its own repo.
- [ ] **Cycle keying vs. Aware's `user_id` entity keying** — different partitioning concepts; unresolved what happens with two concurrent cycles.
- [ ] **Do milestone events belong on the Aware timeline?** If they need suppressing everywhere they're displayed, they may not belong on `raw_sensors`. Cheaper to settle before the dashboard module exists.

## Trip-wires (from the ADR)

The one to watch: **the reconciler starts holding state between runs.** Any persisted cursor, lock or high-water-mark voids the crash-safety argument entirely.

Also: a stage kind that is neither `act` nor `await`; `ACTIONS` growing per-process branching; process N+1 costing more than one YAML file.
