# Building the AuraSight Dataset
### Generating audio that exercises everything the detector can see

A dataset is only useful if it mirrors the detector's **decision space** — not just the five classes, but the *features* AuraSight actually measures, across the *range* it can see, at *multiple difficulties*. Here's how to build one that does.

---

## 1 · Core Principle — Exercise Every Signature

AuraSight classifies by measuring specific signatures. Your dataset must deliberately vary **each one**, or you'll be testing a detector that's never seen half its own inputs.

| AuraSight measures | Generate to exercise it |
| :--- | :--- |
| Harmonicity | Natural (high) ↔ vocoded (low) |
| Pitch–formant consistency | Natural (matched) ↔ pitch-shifted (mismatched) |
| F0 plausibility (60–400 Hz) | Low-bass & high-female speakers, ±12-semitone shifts that push out of range |
| Spectral nulls | Carved at many cut-low / cut-high settings |
| Band-envelope texture | Vocoded at 4 / 8 / 16 / 32 bands, all three carriers |
| Temporal regularity | Scrambled across grain / reach / reverse settings |
| Envelope smoothness | Robotic TTS (over-smooth) ↔ natural (rough) |
| Speech-band energy | Non-speech confusers that sit *near* the speech band |

And for every class, build a **difficulty ladder** — the detector's real quality lives on the hard rung:

| Class | Easy (obvious) | Medium | Hard (boundary) |
| :--- | :--- | :--- | :--- |
| Natural | Clean read speech | Conversational, mild noise | Whispered, fast, low-SNR, accented |
| Modulated | ±12 semitones | ±6 semitones | ±2 semitones (subtle) |
| Masked | Full blackout, 4-band vocoder | Single engine, mid depth | 20–30% depth, formant-only shift |
| Synthetic | Robotic (espeak) | Standard neural TTS | Best neural TTS, lightly post-processed |
| Non-speech | Silence, pure tone | Music, traffic | Coughs, laughter, humming, **TV speech**, speech-shaped noise |

## 2 · Per-Class Recipes

| Class | How to generate | Tools | Key parameters |
| :--- | :--- | :--- | :--- |
| **Natural** | Record scripted speech; vary speaker, level, distance, room | Your mic + browser | Multiple speakers, phonetically rich scripts |
| **Modulated** | Pitch-shift **without** formant preservation (creates the mismatch) | Audacity *Change Pitch* / rubberband / AuraVeil P1 | ±2, ±4, ±6, ±8, ±12 st; formant-only too |
| **Masked** | Run natural clips through AuraVeil, one engine at a time + combos | **AuraVeil** (record out) | Vocoder bands/carriers, scramble grain/reach, carve cuts, depth 20–100% |
| **Synthetic** | TTS the *same* scripts | espeak, browser `speechSynthesis`, macOS `say`, Azure/Google/Piper | Robotic → neural range |
| **Non-speech** | Collect + public corpora | Freesound, ESC-50, UrbanSound8K, FMA | Include speech-like confusers |

**The superpower — matched pairs.** Generate every class *from the same source content*: record 10 sentences naturally, then derive the modulated, masked, and synthetic versions of those exact sentences. When the detector gets one right and another wrong, you know precisely which feature it keyed on. This is your debugging instrument, not just a dataset.

**AuraVeil as the MASKED generator.** Sweep it systematically:
- Vocoder: bands {4, 8, 16, 32} × carrier {noise, saw, breath}
- Scramble: grain {30, 60, 120} × reach {200, 500, 800} × reverse {0%, 50%, 100%}
- Carve: cut-low {150, 250, 350} × cut-high {1800, 2600, 4000}
- Depth: {25%, 50%, 75%, 100%} — the low depths are your hardest MASKED cases
- Combos: pitch+formant (the "witness" signature)

You don't need the full Cartesian product — sample it — but cover each engine across its range.

## 3 · Partial Words — Ground Truth by Construction

The cleanest way to get *labeled* complete/partial words is to **build them so you already know the answer**:

1. **Record clean, slow, isolated words** with clear pauses: "the … quick … brown … dog."
2. **Truncate mid-word** with `ffmpeg -i word.wav -t 0.18 cut.wav` → you know exactly where the cutoff is and that it's partial.
3. **Generate the three partial types:**
   - *Cut-off:* hard truncate mid-word (`-t`).
   - *Fragment:* extract a short onset slice (`-ss 0.05 -t 0.12`).
   - *Trailing:* apply a fast fade-out mid-word (`afade=t=out:st=0.15:d=0.08`).
4. **Splice into sentences** at known timestamps (concat with silence gaps) → word boundaries are known by construction.
5. For naturalistic partials ("I was going to the mar—"), record deliberately and hand-label a small subset.

This gives you a word-boundary eval set without needing forced alignment for most of it.

## 4 · Augmentation & Automation

Real-world robustness comes from controlled degradation. Apply across classes:

```bash
# Telephone line (8 kHz µ-law) — the classic hard case
ffmpeg -i in.wav -c:a pcm_mulaw -ar 8000 phone.wav

# "Bad laptop mic" band-limit
ffmpeg -i in.wav -af "highpass=f=300,lowpass=f=3400" badmic.wav

# Level-normalize everything (removes loudness as a cheat cue)
ffmpeg -i in.wav -af loudnorm=I=-16:TP=-1.5 norm.wav
```

```python
# Precise SNR mixing (numpy + soundfile)
import numpy as np, soundfile as sf
def mix_at_snr(speech, noise, snr_db):
    s, sr = sf.read(speech); n, _ = sf.read(noise)
    n = np.resize(n, len(s))
    n *= np.sqrt(np.mean(s**2) / (np.mean(n**2) * 10**(snr_db/10)))
    return np.clip(s + n, -1, 1), sr
# Use SNRs: 20, 10, 5, 0 dB
```

Batch-process with a shell loop or a small Python driver. **Normalize loudness across all classes** — otherwise the detector learns "quiet = masked," a useless cue.

## 5 · Manifest, Naming, Splits

One machine-readable manifest; filenames stay human-readable but the manifest is the source of truth:

```json
{
  "file": "masked_vocoder_b16_noise_d100_0001.wav",
  "class": "masked",
  "sub_type": "vocoder",
  "params": { "bands": 16, "carrier": "noise", "depth": 1.0 },
  "source": "natural_0001.wav",
  "speaker": "spk01",
  "snr_db": 30,
  "sample_rate": 48000,
  "duration_s": 4.2,
  "words": [
    { "text": "the", "start": 0.12, "end": 0.28, "complete": true },
    { "text": "bro", "start": 0.30, "end": 0.41, "complete": false, "partial_type": "cutoff" }
  ]
}
```

**Split 70 / 15 / 15** (train-tune / dev / held-out test), stratified by class *and* difficulty. The test set is sacred: you never tune thresholds while looking at it. Even a DSP (non-ML) detector needs this discipline, because threshold-tuning *is* the training.

## 6 · Scale & Validation Harness

**How much:** for the DSP MVP, **150–300 clips per class** (~1,000 total) is plenty, plus ~50–100 clips with word-level labels. Grow to thousands per class only when you move to ML.

**The harness that makes it useful:** factor AuraSight's feature-extraction + classifier into pure functions, then run a small offline evaluator:

```
evaluate.js  manifest.json  →  per-file predictions  →  confusion matrix
```

Output you want on every run:
- **5×5 confusion matrix** (where MASKED gets called NATURAL, etc.)
- **Per-class precision / recall / F1**
- **Word-boundary F1** and **complete/partial accuracy**
- **Breakdown by difficulty rung** — this is where you'll find the real weaknesses

Run it after *every* threshold change. The dataset + harness together are your instrument; without the harness the dataset is just files.
