# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Windows: publish builds through the Microsoft Store (MSIX) so installs skip SmartScreen without a code-signing certificate**

*Project description:*
## Problem

Windows releases are unsigned, so SmartScreen shows "Windows protected your PC" and users have to click through **More info -> Run anyway** to install. #848 tracked signing the installer and was closed on Oct 23 because there is no cheap, easy way to get a code-signing certificate right now (SignPath, Azure Trusted Signing, Certum and EV certificates were all considered there).

## Proposal

Publish the Windows app through the Microsoft Store as an MSIX package, alongside (or instead of) the Inno Setup installer. Suggested by @readme42 on #848: the Store is the Windows equivalent of the App Store, and apps distributed through it are signed by Microsoft, so no separate code-signing certificate is needed and SmartScreen doesn't warn.

Things to look into:

- Microsoft Partner Center developer account (one-time registration; currently free for individual developers) and Store certification requirements.
- Packaging: Flutter's `msix` package can produce an MSIX from the existing Windows build; the Store re-signs it on submission.
- CI: add an MSIX build to the Windows job in `.github/workflows/build-all.yml`, and optionally automate submission (e.g. the Microsoft Store submission API / `msstore` CLI).
- Updates: Store installs update through the Store, so the in-app updater (`SparkleUpdateService`) should be disabled for Store builds.
- Optional follow-up: a winget manifest pointing at the Store listing.
