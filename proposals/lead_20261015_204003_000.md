## Problem Statement

The user produces NPM and VPM deliveries for the Moscow regulation (56-page PDF) with a board of AI workers. Today
only OKS BODY is proven on real objects (L3). For every other production area - windows/doors, decor, UV/atlas,
textures, UCX, master -> NPM/VPM derivation, export/package, Ground surface, Ground textures, GroundEl/MAF, Flora - an
agent that takes a card does not find in one place the rules, the checks it can run on its own output and the
etalon to compare with. The result: agents re-read the regulation each time, misread numbers from the PDF's broken
text layer, cannot tell whether their model passes, and every acceptance lands on the user.

## Solution

Every area climbs three readiness levels with a fixed artefact per level, and the board tracks the level per area:

- **L1 - the agent knows the rules**: one requirement sheet per area (`Requirement | reg page | NPM | VPM | How it
  is checked | L2 coverage | Detail in`), numbers checked on rendered PDF pages, conflicts only pointed to. Format
  approved on BODY/UCX/MAF; 8 areas remain.
- **L2 - the agent checks itself**: every sheet row whose `L2 coverage` is `none` becomes an automatic check on the
  exported FBX (or a benchmark against an etalon), so the row's cell turns into a validator id.
- **L3 - verified on a real object**: an independent `verify` card produces a check table and renders, the
  orchestrator tells the user it is ready and offers to open the scene in Blender; only the user accepts.

The working model is one mid-poly master <= 150 000 triangles per OKS FBX ([D010], user 2026-10-15), derived into
NPM and VPM.

## Implementation Decisions

- Readiness levels L1/L2/L3 as in the roadmap §3; "official AGR check passed" is a flag on the object, not a level.
- L1 sheets live in the pilot until migration; one file per area; the seven-column table is fixed; numbers are
  checked on rendered pages (PyMuPDF), renders stay outside the repo (PNG is Git LFS, budget exhausted).
- **Seams (accepted by the user 2026-10-15, highest first):**
  1. *Delivery check seam* - the existing twinqa finding registry run on an FBX readback (`scene_findings`, V001-V017).
     Every L2 gap closes as a finding there (new id or an extension of an existing V-id), never as a job-local script.
  2. *Etalon seam* - the existing benchmark runner (`tools/qa/run_benchmark.py`, B01/B02/B02t): area benchmarks
     (`bench-ucx-01`, `bench-maf-01`, ...) plug into it with an etalon and a comparison table.
  3. *Board seam* - the `verify` card consumes the outputs of seams 1 and 2 plus renders from fixed cameras; it is a
     card kind in `hermes_kanban`, not code in the pilot.
  4. *Document contract* - a small test per sheet (prior art: the UCX sheet test) asserting the column set, a source
     per row and that every `none` row is listed under "L2 gaps".
- First L2 wave (no new etalon needed): BODY-D (units/scale readback into V002), BODY-J (regulatory defect counts),
  BODY-K (co-directional clearance band), UCX R05 (missing-UCX per FBX), R07 (no material slots on UCX), R08 (UCX
  names), R09 (mutual intersections generalised from the job scripts), MAF-04 (units), MAF-11 (mesh name syntax).
- Shared UCX tool generalised from `jobs/KPP1` and `jobs/PSU275` `vpm_ucx.py`, parameterised by target (Main/Ground).
- CAD adapter: AutoCAD 2025 core console (DXFOUT) + ezdxf; tests needing AutoCAD carry the `acad` marker; ODA not
  installed for now; IfcOpenShell stays transient until the Revit adapter.
- Routing: L1 sheets and simple checks on cheap lanes (agy/Pi/Cursor), new checks with geometry logic on
  Codex/Claude (medium/hard), experimental work capped at 2 slots.

## Testing Decisions

- A good test drives the public seam: build or load an FBX readback / fixture, run the finding registry or the
  benchmark, assert the finding ids and counts - never the helper internals.
- Every new check ships a RED fixture (defect present -> finding) and a GREEN fixture (clean -> no finding); for
  coverage-only rows a mutation-RED is accepted (user decision on #108).
- Prior art: `tests/qa/test_scene.py` (scene findings), `tests/qa/test_orientation.py` (geometry checks on box
  fixtures), `tests/test_plan_dxf_*` (0.01 mm CAD round trips), `tests/test_ucx_requirement_sheet.py` (document contract).
- Full non-DCC suite green on main after every merge batch; DCC/`acad` tests marked and run only where the program exists.
