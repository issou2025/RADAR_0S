# Project Proposal — Flutter App

*Project description:*
## User story

As Yuriy, I want an animated browser presentation about YAB so that I can show techies (mostly developers, but also POs and PMs) what the framework is for, how it is used, and where it has (and hasn't) been proven.

## Behaviour

- Runs in a browser, built with [reveal.js](https://revealjs.com), hosted as a static page (GitHub Pages).
- Can be played full screen (F key or a button), like a YouTube video; full screen is optional.
- Slide transitions and in-slide reveals are animated (reveal.js Auto-Animate and fragments).
- Light green theme, palette taken from Habit Loop.
- Available in English (primary) and German, with a language switch that keeps the current slide.
- 15 to 20 minutes, with enough slides to walk through a typical multi-WU flow.
- Approachable for POs and PMs: no slide requires reading code to follow.
- The first slide is a table of contents; each entry links to its section:
  1. Purpose of YAB
  2. An example of using it (a multi-WU ticket)
  3. Cases: Habit Loop, CheckLister
  4. What it can't do yet, or what has not been tested properly
  5. Link to YAB itself (https://github.com/lutsenko-yuriy/yuriys-agentic-boyz)

## Out of scope

- Russian translation.
- Video export or recording of the deck.
- Speaker notes and a presenter view.
- Other promo formats (landing page, social posts).

## Decisions (2026-10-21, resolved open questions)

- **Example section:** Habit Loop's HAB-202 "Adjust and start again" (WU0 scenarios → WU0 scenario correction → WU1 data → WU2 logic → WU3 links behind an off kill-switch → WU4 button + switch on).
- **Mordovorot:** left out of the deck entirely.
- **Section 4 content:**
  - *Not proven yet:*
    - Scaling is an open question: proven only by one developer working with agents, never by a team.
    - Project scale: proven on a Flutter app (Habit Loop), a React Native app (CheckLister), a Kotlin Multiplatform (KMP) project and a small Spring Boot backend; large projects spanning several repos are still to be researched.
    - Agent runtimes: Claude Code is the primary, proven runtime; Codex was used on CheckLister and works, but token-heavy, with a less mature OpenAI model mapping; OpenCode is untested.
    - Tool coverage untested beyond: Linear and GitHub Issues as PM tools; Python 3.11+ for the full tooling.
  - *Coming in the nearest updates:* token/cost tracking per skill run; automated YAB template sync into adopted projects.
  - *A separate slide:* the human stays responsible, and this is one of YAB's core values: the human is the main one, and the AI is an extremely smart yet very humble assistant. Plans still miss things, manual testing still finds bugs automation misses, and the human owns decisions and verification. These are not YAB's fault, so they are not listed as YAB limits.
