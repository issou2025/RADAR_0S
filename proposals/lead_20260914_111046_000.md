# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Design: assembly unloading and dependency isolation on Modern hosts**

*Project description:*
## Context

Loaded plugin assemblies and their static state stay in the Revit process until Revit exits. Updating a plugin therefore works only because each version loads from a new run folder with a new assembly identity; static caches, event subscriptions and singletons from the old version keep living. On .NET 8 (Revit 2025+) collectible `AssemblyLoadContext` could unload; on .NET Framework (2022–2024) there is no unload at all.

## Discussion needed

- Is per-plugin `AssemblyLoadContext` isolation on Modern hosts worth the complexity, given that Revit API types must stay shared with the default context?
- What is the contract for plugin authors: "static state is per version, never assume unload" (document) versus "DevLoader unloads on uninstall on 2025+" (implement)?
- Dependency isolation: two plugins shipping different versions of the same library currently collide; a load context per plugin fixes this on Modern only.

Outcome of this issue is a design note in `docs/how-it-works.md` and follow-up issues.
