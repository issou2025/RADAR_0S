# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**REL-02 [R0]: Make the local Docker verification gate repeatably reliable**

*Project description:*
## Problem

The canonical non-mutating gate in `scripts/ci/verify-local-docker` is functionally correct but operationally fragile on a normal developer/Codex host. During the 2026-10-02 validation of exact GitHub `main` at `e2b166d2a7b055f5825fae0cb8578b199254c094`, the run required recovery from:

- Docker supplementary-group access requiring an elevated retry;
- two `/tmp` quota failures while Terraform installed the AWS provider (about 624 MB had been written);
- a transient Gradle distribution download timeout.

These failures add delay and make a valid clean checkout look unreliable even though the code lanes pass.

## Goal

Make repeated local Docker verification predictable on the supported host without weakening the credential-free, validation-only safety boundary.

## Acceptance criteria

- [ ] Add a deterministic preflight at the public `scripts/ci/verify-local-docker` seam that checks Docker access, writable capacity/cache location, required network/cache prerequisites, and the clean-checkout identity before starting the expensive lane.
- [ ] Remove the implicit dependency on a near-quota `/tmp` filesystem for Terraform providers and other dependency-heavy work. Use an explicit configurable cache/work directory on the repository filesystem or fail before the container starts with an actionable remediation.
- [ ] Make Gradle/Terraform/Flutter dependency acquisition retryable or cache-aware with bounded, observable retries. A transient download failure must not require manually restarting the entire verification without an explicit, useful diagnostic.
- [ ] Make Docker access deterministic for the documented supported invocation. If the current process cannot acquire the Docker group, fail fast with the exact command/action needed; do not begin a partial validation or require an opaque elevated retry.
- [ ] Preserve the existing safety contract: production AWS credentials are never passed to the container, EC2 metadata is disabled, Terraform runs only `fmt`, backend-free `init`, and `validate`, and no production mutation is introduced.
- [ ] Add public-seam regression/contract tests for the preflight, storage selection, retry behavior, and credential/mutation boundaries. Tests must fail before the implementation and pass after it.
- [ ] From five fresh clean checkouts of one exact `main` SHA, run the complete Docker gate five consecutive times with no access, quota, dependency-download, test, browser, or other environment errors. Retain sanitized logs and record the SHA, commands, durations, and result for every run.
- [ ] Keep this issue open until the fix is merged and all five clean runs are recorded. Do not close it based on a single green run or a passing unit/contract suite.
