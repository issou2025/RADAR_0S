# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**watched folders for plugins (let external tools drive the open project)**

*Project description:*
### Problem

I'd like an external program (an AI agent, a script) to push edits into the model I have open, while I keep working in it. I built something like this for Revit using pyRevit: a toggle that, when on, runs scripts dropped into a folder in the live model.

Today the closest option is a plugin button: with the files permission, a plugin can read a macro from a known path, run it as one undo step and write a result file. But plugin code only runs when a command is invoked, so the user has to click for every change. And plugins can't list a folder or move or delete files, so a tool has to reuse one fixed file name and wait for each result before sending the next. ccad mcp doesn't help here: it works on its own copy of a project, not the window that's open.

### Proposed solution

Watched folders for plugins (plugin API 4). This adds two things:

No click needed: the app checks a folder the user chose and runs new files while it's idle.
A real queue: any number of files run oldest first, and each one moves into done/ or failed/.

How it works:

A plugin declares [[watchers]]: a command that takes one file (ui = "open_path"), plus a label and an interval.
The user picks the folder and turns it on (a ribbon toggle or the Plugins window). The plugin can never turn itself on, and it gets no new file access: each file is passed to it the same way an importer gets the file the user opened.
Each file runs as one undo step, then moves to done/ or failed/ next to a .result.json (result or error), so the sender can read back what happened.
Files wait while the user is busy (sketching, in a dialog with Cancel, recording a macro).
ccad watch does the same without the app.
An example plugin, Script Runner, runs dropped .ccmacro files.

I have a working prototype with tests and docs and can open a PR if this direction looks right.

### Alternatives considered

1. A plugin button that runs a file at a fixed path: works today, but needs a click per change and handles one file at a time.
2. ccad mcp: edits a separate copy of the project, not the open window.
3. A local socket connection between ccad mcp and the running app: live, but a bigger change to the app and harder to keep secure than a folder the user chooses.
