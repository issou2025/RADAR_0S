*Project description:*
Progress (2026-08-11): the QS3D semantic interchange pipeline is now substantially broader than the original export-only gap, but this issue remains open because it is still not full production round-trip interoperability.

Implemented source/static layers now include deterministic `QS3D.SemanticSnapshot` export, strict bounded validation, immutable typed reading, deterministic semantic diff, target collision/provenance preview, explicit fail-closed resolution planning, runtime/name-collision compatibility planning, confirmation freshness guards, multiple rollback-safe mutation policies, and a dedicated reviewed native FieldMerge orchestration path.

Current semantic mutation policies include:

- **Append-only** (`QS3DINTERCHANGEAPPEND`): all incoming identities must be new; no implicit rename/replace/merge; source CAD handles/native ownership are discarded.
- **KeepTarget**: colliding target identities remain authoritative while planner-approved new identities append.
- **UseSource Element / Catalog / ALL**: guarded source-semantic replacement paths with reviewed-target freshness checks and ownership-safe invalidation boundaries.
- **UseSourceSemanticData executor** (merge `ada6d3bf6957392520e61421622963aba451295a`, PR #202): bounded Core semantic replacement with target-only invalidation, explicit native-cleanup authorization and rollback-safe mutation. Native BricsCAD cleanup/rebuild remains a separate adapter/runtime boundary.
- **Import As New / deterministic remap** (`QS3DINTERCHANGEREMAPPLAN` + `QS3DINTERCHANGEREMAPAPPEND`, PR #210 / merge `00d671ee7a40f3ec95f578c4da26e68eb419edc4`): retains both namespaces, remaps runtime-bounded Zone/Floor/Family/Element identities and duplicate names, keeps blocked plans inspectable, checks target capacities/property limits, strips source/native ownership, binds confirmation to the reviewed project/version, and re-plans immediately before mutation.
- **Reviewed same-ID field-level precedence** (`ProjectInterchangeFieldMergePlanner` + `ProjectInterchangeFieldMergeImporter`, Core execution merge `0ff97a919e7a2bdf6e7bd7f17d8232cab7cc0cce`): explicit group-level `Unspecified` / `KeepTarget` / `UseSource` decisions for Zone/Floor/Family/Element semantic fields, source/target/decision freshness binding, exact generated-handle cleanup requirements, canonical Family services and `ProjectStateSnapshot` rollback. This is intentionally not a fifth generic coordinator mode.
- **Dedicated native FieldMerge command** (`QS3DINTERCHANGEFIELDMERGE`; adapter source in `InterchangeFieldMergeImportService`): read-only target preview precedes all precedence prompts, policy/plan/final confirmation complete before canonical mutation binding, then ProjectId + drawing fingerprint + ChangeVersion are rechecked. Native generated-dependent erasure is prepared while reviewed ownership metadata is intact, the exact Core authorization is re-planned/validated before semantic apply, metadata cleanup follows, and CAD commit occurs last under one native transaction with semantic snapshot rollback on pre-commit failure. This is source implementation, not exact-V25 runtime qualification.

PR #210 also centralizes portable property-carried semantic references through `ProjectInterchangeSemanticReferencePolicy`. `HostWallId` maps through the Element namespace; `BottomLevelId` and `TopLevelId` map through the Floor/Level namespace. Registered refs must resolve inside the source snapshot, unknown `*Id/*Ids/*Ref/*Refs/*RefId/*RefIds` properties remain fail-closed, and imported level relations validate bottom/top/offset consistency before success. Source handles/fingerprints never become target CAD ownership through this path.

Current `main` additionally centralizes semantic-reference validation before export/after typed read, keeps generated/native and arbitrary Element handle-bearing metadata drawing-local at interchange boundaries, preserves target-local nonportable metadata through field merge, and reports reviewed native cleanup as required/authorized rather than falsely claiming Core alone completed native CAD cleanup.

The generic import UX is review-before-mutation rather than a blind apply. The dedicated FieldMerge UX is also cancel-safe before canonical binding: cancelling any field-group precedence prompt or final confirmation must remain a read-only/no-mutation path.

Still open / not to be overstated:

- exact-SHA licensed BricsCAD V25 qualification of `QS3DINTERCHANGEFIELDMERGE`: per-prompt/final-confirm cancel behavior, cold-cache canonical binding, stale/replaced target rejection, native Prepare/Core-apply/CAD-commit fault injection, transaction abort + semantic rollback, Undo, save/reopen and multi-DWG isolation;
- explicit rebuild of invalidated generated outputs after FieldMerge; the command intentionally does not auto-build3D/cut/rebar/curtain/grid/save;
- generic coordinator exposure of FieldMerge (it remains a dedicated reviewed command);
- any new/broader precedence model beyond the current reviewed same-ID group-level field contract, including per-key mixed policy if the product ever requires it;
- target-DWG source-handle rebinding/adoption policy;
- IFC/Revit/BCF/vendor/cloud interchange formats and schema/version evolution;
- customer/private-DWG qualification and representative performance.

Keep this issue **OPEN**. Current source provides real guarded semantic import/export workflows plus dedicated native FieldMerge source orchestration, but it must not be presented as complete cross-platform/BIM round-trip interoperability or as locally V25-qualified until the remaining runtime/format/policy boundaries are closed.
