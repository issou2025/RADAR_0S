# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Spec: Unreal on Fab — MPB 2 ready, unreal-0.8.1 cut from main and resubmitted**

*Project description:*
## Problem Statement

An Unreal Engine user cannot install Mantle Place from Fab. Fab's review of `unreal-0.7.1` (case 27145849, 2026-10-24) passed every check except one: the package held a `LICENSE` file, and Fab refuses licence and policy files beside its own licence. The fix merged as #425, but `unreal-0.8.0` was tagged a few minutes before it, so no release yet carries it.

Resubmitting is not enough on its own. Bundles are now MPB 2, and a user who downloads a **selection** (an archive that holds only some of an order's parts) cannot import it in Unreal. The import refuses the whole archive as soon as a payload the manifest declares is not in it (#451). A storefront listing that fails on the bundles the website now hands out would ship a plugin broken on arrival.

## Solution

Unreal is shown to import MPB 2 bundles of every archive view before anything goes to Fab. Then one release cut from `main`, `unreal-0.8.1`, carries #425 and #451, and its Source zip is resubmitted against the existing Fab case.

## Acceptance

1. **#451 is fixed** to its own acceptance, as a sub-issue of this spec. A selection archive that leaves out a declared part imports what it holds and names what it skipped. A missing entry in a part the archive claims to hold is still refused.
2. **The release cut is `unreal-0.8.1` from `main`**, after #451 merges, following the Unreal README's packaging steps and `docs/releases.md`.
3. **The Source zip passes the Fab pre-submit list** in the Unreal README, checked with `unzip -l` against the zip itself:
   - no licence, EULA, trademark or other policy file;
   - no `Binaries`, `Intermediate`, `Saved` or `Build` folder;
   - no `Source/ThirdParty`;
   - a `Config/FilterPlugin.ini` that names no licence or policy file.
4. **Verified live — MPB 2 readiness**, recorded in the release body's Verification section. The cut's binaries import each of the following into Unreal Engine 5.8, and each looks right:
   - an MPB 2 bundle of each archive view (`everything`, `selection`, `host`);
   - one US imperial order and one metric order;
   - a World Partition level and a non-partitioned level.

   A failure is filed as an issue and blocks the submission, unless the release body names it as a known issue that does not break an import.
5. **Verified live — Fab:**
   - The Source zip is resubmitted against the existing Fab product. Any question about the review goes in a new Fab support ticket quoting case 27145849, because Fab does not read replies to its review email.
   - The release body's **Storefront** line records the date and the Source zip's sha256.
   - Once the listing is approved, its public URL is posted on #277. That closes #277 and #407.

## Implementation Decisions

- **A new cut, not 0.8.0.** `unreal-0.8.0` was tagged before #425, so its `FilterPlugin.ini` still names `LICENSE` and `TRADEMARK.md`, the thing Fab's last review failed on. The storefront receives only a release cut's tagged commit, and releases are cut from `main`, so the fix ships as `unreal-0.8.1`. A cherry-picked branch release was rejected because it breaks the cut-from-main rule.
- **The cut carries what is already merged.** Everything on `main` since 0.8.0 ships with it. That includes complete orders importing without Prepare, US road centrelines, and the plugin wording changes. Nothing new is written for this release beyond #451.
- **#451 follows its triage decision.** The archive's own `view` decides what it holds, in the pure integrity logic: a part outside `view.parts` is skipped and logged, and a part the archive claims but lacks is refused. The brief on #451 is the detail.
- **#450 stays in triage.** The spec defines `point_cap` as a property of the MAX file, not a limit a host applies, and the report needs the bundle it came from. The live readiness check will show whether any MPB 2 tree-points file places more points than it declares. If it does, that is a new issue.
- **Readiness is a live gate, not a new test.** Unreal's headless conformance pin is already MPB 2.0.0. What the headless suite cannot show is a real archive of each view importing in the editor. Public CI never compiles the Unreal plugin, so this runs on the release cut's binaries, as every Unreal gate does.
- **Fab's earlier third-party findings are closed.** The 2026-10-18 review failed the ThirdParty-folder and Third Party Software form lines. The plugin has shipped no third-party content since 0.7.1, and the 2026-10-24 review passed both lines.
- **Listing text** follows the Unreal README's Fab pre-submit list. The tested MPB version is updated to the one this cut is verified against.

## Testing Decisions

- **#451** is tested at the Unreal logic core's headless seam, next to the existing `VerifyAll` tests in the bundle layout test, covering a selection that leaves out a part, a claimed part that is missing, and `everything` or no `view`. The Unreal automation suite runs locally on that PR and its result goes in the PR body.
- **The Source zip's contents** are already checked by `tools/unreal-naming/check_third_party_layout.py` in public CI (no licence file in the tree, none named in `FilterPlugin.ini`). `unzip -l` on the built zip is the release-time check.
- **MPB 2 readiness** is the live check in Acceptance 4, run on the cut's binaries in Unreal Engine 5.8.
