# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Working Wall / Developer Mode: zoom, exact placement, snap grid, typography, multi-screen canvas, vocabulary corrections**

*Project description:*
## Goal
Improve Visual Language Castle Working Wall and Developer Mode so large language boards are fast to construct, easy to see at once, and precise to arrange.

## Immediate interaction changes
- Add zoom controls (zoom out/in, reset/fit-to-board) so more of the board can be visible at once.
- Preserve direct drag/drop placement: when a card is dragged from the selection/table browser onto the board, it must remain exactly where the user drops it.
- Remove the current cascade/automatic relocation that sends newly dropped cards toward the center/bottom edge.
- Keep card coordinates stable after drop, save, restore, and resize.
- Prefer a large pan/zoom work surface over clamping cards to the visible viewport so large boards can extend beyond one screen.

## Alignment / grid mode
Add an explicit Arrange / Snap Grid action that:
- squares all cards;
- aligns them into a compact perfect grid;
- places cards edge-to-edge with only a very small gap so each card's corners/borders remain visually distinguishable;
- does not overlap cards;
- preserves current ordering unless the user explicitly reorders;
- supports Undo to restore the pre-arrange positions.

## Readability
- Increase card-text contrast.
- Use bold/semibold text by default where it improves legibility.
- Preserve automatic font shrinking for long cards so text remains inside the card.
- Single-word cards should display with an initial capital letter consistently.

## Large / multi-display workspace
- Make the board usable when the desktop window is stretched across multiple monitors.
- Do not impose viewport-sized placement limits that pull cards back into one screen.
- The pan/zoom canvas should remain usable for a very large board.
- Actual multiple independent native app windows can be a later enhancement if needed; the immediate requirement can be satisfied by one large scalable board/window spanning multiple displays.

## Vocabulary corrections
Nominals:
- `Moment` -> `Momentum`
- Add `Commitment`

Verbs:
- `Adopted` -> `Adopt`
- `Established` -> `Establish`

## Capitalization rule
- Single-word vocabulary cards should use title/initial capitalization (`Notice`, `Adopt`, `Establish`, etc.).
- Do not blindly title-case multi-word patterns, formulas, or phrases; preserve their authored wording.

## Regression requirements
- Preserve existing category colors and metadata.
- Preserve Working Wall connections/arrows.
- Preserve archive save/restore and Developer Board persistence.
- Preserve direct note editing and Developer Mode research notes.
- Do not regress mobile behavior.
