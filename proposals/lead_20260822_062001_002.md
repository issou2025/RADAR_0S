*Project description:*
Design Automation runs AutoCAD, Revit, Inventor, and 3ds Max headless in the cloud. It is the most used APS API that no official Autodesk SDK covers, and the only large one that needs no user token. 43 reference pages.

## Notes before starting

### The region is in the path, not a header

`client.issues` and `client.account_admin` both send the region as a header. Design Automation puts it in the path instead. Read [Regions and quotas](https://aps.autodesk.com/en/docs/design-automation/v3/da-rate-limits/) and default to `us-east`.

### IDs carry a nickname and an alias

An activity is addressed as `owner.Name+alias`, for example `MyApp.PlotToPdf+prod`. Read [Aliases and IDs](https://aps.autodesk.com/en/docs/design-automation/v3/aliases-and-ids/) before naming any parameter. A caller who passes a bare name gets a 404.

### Workitems need polling, and the pattern already exists

`POST workitems` returns a workitem ID with a pending status. Poll `GET workitems/:id` until it finishes. Copy `client.model_derivative.wait_for_translation` rather than writing a new loop.

### Workitem arguments are signed URLs

Inputs and outputs are HTTP URLs, so `client.oss.get_signed_upload` and `get_signed_download` feed straight into a workitem. That link is the reason to add this service, so cover it in the docstrings and the README example.

### Callbacks and WebSockets stay out of scope

[Callbacks](https://aps.autodesk.com/en/docs/design-automation/v3/callbacks/) and the [WebSocket API](https://aps.autodesk.com/en/docs/design-automation/v3/websocket-api/) are alternatives to polling. Neither belongs in a first pass. Note them as follow up work.

### Appbundle upload is a two step form POST

`POST appbundles` returns an upload parameter set for a multipart form POST to a separate URL. It is not an OSS signed URL. Read the endpoint page carefully.

## How it fits the client

Follow the shape that `client.issues` already uses:

- `src/autodesk_platform_sdk/services/designautomation/operations.py` holds one `Operation` per endpoint and a `BASE` constant.
- `schemas.py` holds the Pydantic request and response models.
- `__init__.py` holds the service class with a sync method and an async method for each operation.
- Mount `client.design_automation` in both `client.py` and `async_client.py`.
- Add `cli/commands/designautomation.py` and register it on the `aps` group.
- Add `tests/test_designautomation.py` with mocked transports.
- Add the row to the services table in `README.md`.
