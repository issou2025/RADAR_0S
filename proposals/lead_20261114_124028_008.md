# Project Proposal — Permit Drawings

## Project Understanding
You need assistance with: 
**Opening Reference, sloped floor PitchAngle and door FireRating write values Revit leaves out on the BIM4LCA housing (RE-381, RE-384, RE-354)**

*Project description:*
Three rules that hold on the BIM4LCA concrete office, where they were developed, write a value that Revit's export leaves out on the BIM4LCA housing, the second project. RE-402 section 3, census cells `equal/different +written-that-Revit-omits`, by file (concrete as built, concrete permit, timber as built, timber permit, terrain concrete, terrain timber):

| Rule | Housing | Verdict |
|---|---|---|
| RE-381/382 opening `Reference` | 35/0 +1, 20/0 +1, 19/0 +1, 19/0 +1, -, - | does not hold on 4 |
| RE-384 sloped floor `PitchAngle` | 26/0, 32/0, 34/0 +1, 34/0, 1/0 +2, 1/0 +2 | does not hold on 3 |
| RE-354 door `FireRating` | 17/0, 17/0 +1, 18/0, 18/0, -, - | does not hold on 1 |

None reads "different": each is a value rvt-rs writes on an element where Revit writes none. The concrete office already counts the opening `Reference` this way (+3, +4, +2, +2, RE-402 section 3), so that rule fails on its first project too.

**Done when** each of the 10 elements is named (`PSETS_MISSING`, or the census's list of values Revit does not write), the reason Revit leaves its value out is found, and the rule is narrowed so it writes none of them, with no equal value lost on the office or the housing. Or, where Revit's exporters disagree on the value, it is left out by the standing rule.

Listed in "Measured on another project, and wrong there" on [Rules that rest on one project](https://github.com/DrunkOnJava/rvt-rs/blob/main/docs/one-project-rules.md) (#1636, #1979).
