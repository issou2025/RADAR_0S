# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**MouseTracker permanently disables mouse updates after a hit-test or hover exception (missing finally in _deviceUpdatePhase)**

*Project description:*
### Summary

`MouseTracker._deviceUpdatePhase` leaves `_debugDuringDeviceUpdate = true` when its task throws. A single hit-test or mouse enter/exit exception consequently disables future mouse updates, even after the original error has been corrected with hot reload. Every subsequent frame/pointer update asserts `!_debugDuringDeviceUpdate`.

This was investigated after repeated intermittent mouse-input freezes during hot reload in a macOS desktop app. The deterministic test below isolates the exception-safety failure: an intentionally thrown hover error during reassembly should be reported once, with later reloads and clicks continuing normally.

Related symptom reports: #84241 and #85383. #193566 also describes this secondary debug assertion after a tooltip layout failure. This report provides an isolated reproduction and a tested fix for the permanently latched mouse-tracker guard.

### Steps to reproduce

1. Use Flutter stable 3.47.9. `flutter upgrade` reported it was already up to date on November 2, 2026.
2. Put the following in `test/mouse_tracker_test.dart` in a Flutter project with the standard `flutter_test` dependency.
3. Run `flutter test test/mouse_tracker_test.dart` (offscreen; no manual mouse timing needed).

### Code sample

```dart
import 'package:flutter/gestures.dart';
import 'package:flutter/widgets.dart';
import 'package:flutter_test/flutter_test.dart';

void main() {
  testWidgets('reload hover failure does not freeze subsequent reloads or clicks', (tester) async {
    var generation = 0, failing = false, clicks = 0;
    final error = StateError('hover callback during reload');
    await tester.pumpWidget(Directionality(textDirection: TextDirection.ltr,
      child: StatefulBuilder(builder: (context, setState) => MouseRegion(
        key: ValueKey(generation),
        onEnter: (_) { if (failing) throw error; },
        child: GestureDetector(onTap: () => clicks++, behavior: HitTestBehavior.opaque,
          child: const SizedBox.expand()),
      )),
    ));
    final mouse = await tester.createGesture(kind: PointerDeviceKind.mouse);
    await mouse.addPointer(location: const Offset(20, 20));
    await tester.pump();

    // A replacement MouseRegion under the stationary pointer is entered during
    // the reload's post-frame mouse update.
    generation++;
    failing = true;
    final reload = tester.binding.reassembleApplication();
    await tester.pump();
    await reload;
    expect(tester.takeException(), same(error));
    failing = false;

    for (var i = 0; i < 20; i++) {
      generation++;
      final reload = tester.binding.reassembleApplication();
      await tester.pump();
      await reload;
      expect(tester.takeException(), isNull);
      await mouse.moveTo(Offset(21 + i.toDouble(), 20));
      await mouse.down(Offset(21 + i.toDouble(), 20));
      await mouse.up();
      await tester.pump();
      expect(tester.takeException(), isNull);
    }
    expect(clicks, 20);
    await mouse.removePointer();
  });
}
```

### Expected results

The original `StateError` is reported. Once the callback is corrected, subsequent mouse tracking, reassembly, and clicks work. The genuine recursive-update assertion remains enforced.

### Actual results

The original error is immediately followed by a secondary assertion, so even the first `takeException()` receives multiple exceptions. Further mouse/frame updates keep asserting on the same tracker instance.

### Root cause and verified fix

In `packages/flutter/lib/src/rendering/mouse_tracker.dart`, `_deviceUpdatePhase` resets the guard only after `task()` returns normally. Use `finally` for cleanup:

```diff
@@
-    task();
-    assert(() {
-      _debugDuringDeviceUpdate = false;
-      return true;
-    }());
+    try {
+      task();
+    } finally {
+      assert(() {
+        _debugDuringDeviceUpdate = false;
+        return true;
+      }());
+    }
```

The entry assertion and original exception propagation are preserved. The original layout/callback error remains available to diagnose and correct; it no longer permanently poisons the tracker.

Verification on the same stable SDK:

- The widget regression above fails before this patch and passes afterward, including 20 subsequent reassemblies and mouse clicks.
- Four direct `MouseTracker` regression cases fail before/pass after: a hit-test exception, enter exception, exit exception, and a genuinely reentrant update. Each verifies subsequent frame updates, pointer removal/re-addition, enter/exit delivery, and cursor selection. The reentrant call still asserts as expected.
- The 13 cases in Flutter's existing `test/rendering/mouse_tracker_test.dart` pass with the patch (executed from an isolated copy of that test and its helper using the application's resolved dependency configuration).
- The SDK source change was hot-reloaded into the existing desktop process; VM inspection confirmed the new method was loaded, and runtime-error inspection after reload reported no errors.
