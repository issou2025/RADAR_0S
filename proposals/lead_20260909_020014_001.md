# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Unauthenticated Revit command listener binds to all IPv4 interfaces**

*Project description:*
I am evaluating this project for company use with Revit 2025 and Claude/ChatGPT desktop clients.

In commit 86cf7057785f2423fc0d0892c9a5d9c93deb1aa3, plugin/Core/SocketService.cs creates:

`new TcpListener(IPAddress.Any, _port)`

The port is set to 8080. ProcessJsonRPCRequest validates the request format, looks up the registered command and invokes it. I could not identify caller authentication in this path.

Source:
https://github.com/mcp-servers-for-revit/mcp-servers-for-revit/blob/86cf7057785f2423fc0d0892c9a5d9c93deb1aa3/plugin/Core/SocketService.cs#L105

My understanding is that:
- The listener accepts connections on all IPv4 interfaces, although the supplied client connects to localhost.
- Remote reachability depends on Windows Firewall and network policy.
- Reachable callers can invoke enabled commands without going through the MCP client's approval interface.
- Where send_code_to_revit is enabled, the potential impact extends to code execution with the Revit process's permissions.

This is a source-review finding, not a demonstrated attack on a deployed workstation.

Is remote access intentional? Could local-only binding be the default, with authenticated requests and an explicitly secured opt-in for remote operation? A user-restricted named pipe with authentication would also suit the local workflow.

Please consider regression tests for rejected unauthorized requests and non-local connections. We need scripting functionality, so securing access while retaining authorized code execution would be valuable.
