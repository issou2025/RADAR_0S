# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**A container cannot fade: there is no opacity for a subtree**

*Project description:*
## Observed

A container has no opacity. Colours carry alpha, but there is no way to fade a
whole subtree — background, text, icons and children together — and so nothing
to animate for a fade. `RenderNode` (`src/renderer/tree.rs`) carries transform,
clip and overlay clip, and no alpha.

## Who is worse off

Any enter or exit that should fade — the natural pair for an exit transition
(#482). In allock's session picker the card's clip already hides both ends of
the slide, so a fade there would read better but is not needed.

## Expected

`container().opacity(f32)`, taking values, signals, `transition` and
`timeline` like the other animatable properties, applied to the whole subtree
as one layer (not multiplied into each child's colour, which double-darkens
overlaps).

## The decision

True group opacity is a new pass kind: a render-node attribute, a flattener
group that isolates the subtree (draw groups batch across the whole tree
today), drawing into a transparent scratch target, and compositing it back with
alpha. It meets the paint cache and backdrop blur inside the group. The pieces
it would build on exist — the backdrop pass's offscreen target resumed with
`LoadOp::Load`, `text_quad`'s offscreen text, the flattener's per-layer overlap
test (`docs/RENDERER.md`) — but the pass does not.

The choice to make: multiply the alpha into each draw when the subtree's rects
do not overlap (the existing overlap test), and go offscreen only when they do.
That is Compose's `CompositingStrategy.Auto` against `ModulateAlpha`, and the
fold Skia and Chromium make for a single-draw `saveLayerAlpha`. Most fades —
allock's included, whose names never overlap — would never leave the cheap path.

## Prior art

- CSS `opacity` composites as a group and creates a stacking context.
  https://www.w3.org/TR/css-color-4/#transparency
- Flutter `Opacity` uses `saveLayer`, with explicit cost warnings; it recommends
  `FadeTransition` or alpha in the colour.
  https://api.flutter.dev/flutter/widgets/Opacity-class.html
- Compose `graphicsLayer(alpha)` +
  https://developer.android.com/reference/kotlin/androidx/compose/ui/graphics/CompositingStrategy
- SwiftUI `.opacity` applies per child unless `.compositingGroup()`.
- GTK4 `gtk_widget_set_opacity` produces a `GskOpacityNode`.
- vello `Scene::push_layer(.., alpha, ..)`.

## Acceptance

- `opacity(0.5)` on a container with overlapping children draws them as one
  half-transparent layer (golden).
- `opacity(0.5)` on a container whose children do not overlap draws the same
  pixels as multiplying each colour's alpha (golden).
- `opacity(0.0.transition(..).entering_from(1.0))` fades.
