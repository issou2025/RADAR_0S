# cw-dealscan — Pre-deal On-Site Estate Inventory (Build Spec)

**Issue:** part of the cw-dealscan wayfinder map (#1). Frontier cleared (#8, #2, #6 resolved); this spec collapses the linked decisions into a buildable plan.
**Home repo:** `cw-ma-toolkit` (jcarthy16/cw-ma-toolkit). New sibling tool `cw-dealscan`.
**Seam target:** emits `cw-acq/evidence-package` v1 that `cw-acq-toolkit` imports unchanged.

---

## Problem Statement

An acquiring UK architectural practice needs a pre-deal "what we are buying" picture of a target Windows estate, run on-site from a Windows host/VM on the target's network. They need to know: which hosts exist, how powerful each is for the practice's design workloads (Revit/AutoCAD), which design apps are deployed and how current they are (Adobe CC, Autodesk), patch/EDR/CE+ readiness, the network topology, and a per-machine signal telling them whether to **keep, upgrade, plan-replace, or replace** each machine and **remediate or replace** it. Today this work has no tool: the on-site sweeper has no discovery, no hardware-suitability lens, and no structured output that feeds the downstream `cw-acq-toolkit` analysis. Existing siblings solve post-close/owned-estate enumeration (cw-estatescan) and offline assessment (cw-acq-toolkit) but neither does pre-deal *range-scoped discovery* with a *design-workload hardware* lens.

The user is also unsure the sibling tools aren't "too complicated" for on-site reality. cw-dealscan must be a **lean sibling** that reuses the siblings' evidence and safety seams without coupling to their internals.

## Solution

A new pre-deal sibling CLI, `cw-dealscan`, that an operator runs once against an authorised target: a single `sweep` command takes a **CIDR range + AD domain**, prompts for credentials (getpass, never `--password`), requires a scope acknowledgement (`--confirm`), then discovers hosts (AD-first, CIDR fallback) and reads each one **read-only**, assembling per-host inventory (host specs, hardware, software watch-list versions, subnet membership) into evidence-package v1 documents the toolkit imports unchanged. The tool also derives, per machine, a **Revit Hardware Suitability** decision plus CE+ readiness and software-debt findings, so the report answers "keep, upgrade, plan-replace, or replace" with clear reasons. Everything is deterministic, transparent, and safety-gated; output flows into `cw-acq-toolkit` for analysis → report → dashboard.

## User Stories

1. As an operator, I want to run one `sweep` command against a supplied CIDR + AD domain, so that a pre-deal on-site inventory is produced in a single authorised pass.
2. As an operator, I want the sweep to be **authorisation-gated** (mandatory authorisation reference, scope banner, `--confirm`), so that unauthorised or accidental collection is structurally hard.
3. As an operator, I want the sweep to **fail closed** when mandatory scope facts (authorisation reference, CIDR/mask, AD fqdn) are missing, so the tool never runs without a defined boundary.
4. As an operator, I want credentials prompted via getpass with **no `--password` flag** and wiped after the run, so passwords never reach CLI history or process lists.
5. As an operator, I want the reachable scope confined to the operator-supplied **CIDR + AD domain**, never widened by the tool, so the tool never touches hosts outside the authorised boundary.
6. As an operator, I want every read to be **read-only** (constant scripts, no state-changing verbs, no injection point), so the sweep cannot modify a target host.
7. As an operator, I want output **path-confined and overwrite-safe**, so a repeat run cannot clobber prior evidence and writes never escape the output folder.
8. As an operator, I want an **auditable run log** recording what was in scope and what was/wasn't swept (including `out_of_scope_discovered` for discovered-but-unswept hosts), so the engagement can prove its own boundaries.
9. As an operator, I want **AD-first discovery** (DNS SRV `_ldap` → read-only LDAP `(objectCategory=computer)` via `DirectorySearcher`) to enumerate domain-joined computers, so discovery works where Active Directory is present.
10. As an operator, I want a **CIDR fallback** (bounded TCP connect to 445/135, within the supplied range) when AD is absent, so hosts on non-AD estates are still discovered.
11. As an operator, I want `--operator-role cw-postclose|target-predeal` recorded in the run log, so the operating context is auditable.
12. As the practice, I want each host's **hardware spec** collected read-only (RAM, CPU model/cores, OS architecture/64-bit, GPU model + platform, dedicated VRAM, storage type/capacity/free, device age), so the hardware-suitability lens has the facts it needs.
13. As the practice, I want the collector to avoid the `Win32_Product` reconfiguration trap and read software from **registry uninstall keys** only, so enumeration is side-effect-free.
14. As the practice, I want the **software watch-list** (Adobe CC: Photoshop/Acrobat/InDesign/Illustrator; Autodesk: Revit/AutoCAD) enumerated per host with **name → version**, so deployed design-app versions are known.
15. As an analyst, I want each watch-list product classified `current | legacy | eol_eos | unknown` per host using **per-family currency rules** (Autodesk = latest major N..N-3; Adobe = latest major only), so design-app debt is visible.
16. As an analyst, I want the classification stamped with **`as_of` + `source`** (live vs table) so the currency confidence is transparent in the report.
17. As the practice, I want **Acrobat commercial editions** (Pro/Standard/Classic) flagged but the free **Reader tracked-but-never-flagged**, so the report isn't polluted by the free reader.
18. As the practice, I want the Revit firm's **hardware floor** enforced per machine (≥32 GB RAM, 64-bit OS, ≥8 GB GPU VRAM) so under-spec machines are caught for design workloads.
19. As the practice, I want a **Revit Hardware Suitability Assessment** per machine rating CPU/RAM/GPU/storage and returning `retain | upgrade | plan_replacement | replace | manual_review` with plain-language reasons, so every machine gets a clear buy-vs-remediate verdict.
20. As the practice, I want **workload profiles** (`revit_light`, `revit_standard` default, `bim_coordination`, `visualisation`) assigned per device (flag/sidecar), so the assessment reflects how each user actually works.
21. As the practice, I want CPU assessment driven by **single-thread benchmark score + laptop-suffix modifier + hard-fails** (never cores alone, never age/name alone), so it matches Revit's single-thread sensitivity.
22. As the practice, I want GPU assessment to use **actual dedicated VRAM via a curated name→VRAM catalogue** (platform-aware, unsure → `manual_review`), so the 8GB+ floor isn't corrupted by `AdapterRAM` truncation.
23. As the practice, I want **device age** treated only as a modifier (never a sole determinant — a 5-year-old machine can still pass), so proven-old machines aren't auto-failed.
24. As the practice, I want **hard-fail conditions** (Win11 unsupported, <4 cores, <2GB VRAM, mechanical system drive, etc.) to force `replace` unless the part is economically upgradeable, so genuinely dead machines are caught.
25. As an analyst, I want **unknown hardware never auto-classified Green** (it → `manual_review`), so the report never overstates suitability.
26. As the practice, I want the hardware decision to be the **primary per-machine signal**, with CE+ readiness (OS support, EDR, patch age) and software watch-list debt **escalating it one notch + adding reasons**, so one headline decision per machine is fully explained.
27. As an analyst, I want the per-machine decision expressed in the toolkit's deterministic finding model (impact/likelihood/score/recommendation, no hidden inference), so it's auditable and reusable downstream.
28. As an analyst, I want the **estate subnet LIST** from AD `CN=Subnets,CN=Sites,CN=Configuration` (or local route-table fallback) emitted as a `network-snapshot` package, so the topology view is authoritative.
29. As an analyst, I want **per-host subnet membership** (ip/subnet/gateway/dhcp/dns/mac) on each host record, so each machine's network position is known.
30. As the practice, I want the policy to be **version-controlled config files** (`revit-hardware-assessment.schema.json`, `revit-minimum-policy.json`, `cpu-rules.json`, `gpu-rules.json`) with annual maintenance, so thresholds are reviewable and calibrated without code changes.
31. As an operator, I want a `validate` command to locally validate a produced package, so output can be checked before import.
32. As an analyst, I want a cw-dealscan package to import into `cw-acq import` **unchanged**, so the downstream analysis/report pipeline consumes it with zero conversion.

## Implementation Decisions

### Tool shape & safety scope model (from #2; load-bearing)
- **Single combined `sweep` command** (`cw-dealscan sweep --cidr <range> --domain <fqdn> [--workload-profile ...] [--operator-role ...] [--username] [--workers N]`), one `--confirm` ack, one pass, plus a `validate` command.
- **One broad boundary**: the supplied CIDR + AD domain is simultaneously the discovery AND enumeration scope. After one `--confirm`, every discovered host is swept. No host-type filter, no out-of-scope skip by default (explicit, informed operator call).
- **Scope gate ports ADR-0003/0004**: mandatory authorisation reference; scope banner always rendered (showing the boundary) before any probe/sweep; fail-closed on missing authorisation reference/`--cidr`/`--domain`; path-confined overwrite-safe output; assessment-id charset restriction.
- **Credentials**: getpass-only, no `--password` flag; in-memory `Credentials` object (masked `__repr__`, `.wipe()` after the sweep); `--username` or `CW_ESCAN_USERNAME` env; `--operator-role cw-postclose|target-predeal` recorded in the run log.
- **Read-only only**: constant PowerShell fragments with no operator-controlled injection point; only `Get-*`/`Select-*`/`DirectorySearcher` primitives; never `Set-`/`Remove-`/`Invoke-`/`Start-`. `$ErrorActionPreference='Stop'` makes a missing class a non-zero exit, not an empty success.
- **Run log**: auditable, records what was in scope and what was (and wasn't) swept; `out_of_scope_discovered` records hosts discovered-but-unswept **at sweep time** (e.g. offline/unreachable) — even sweep-all has gaps.
- **New dealscan ADR — "scope is the boundary; discovery never widens it"**: reach confined to the supplied CIDR + AD domain; enumeration only within it; the tool never derives new scope past what it was given. Reachability probing stays bounded (TCP 445/135, bounded concurrency, within range; never ICMP, never nmap).

### Discovery (from #5)
- **AD-first**: DNS SRV `_ldap._tcp.dc._msdcs.<domain>` to locate a DC, then one read-only LDAP **subtree search** `(objectCategory=computer)` → `dNSHostName`/`sAMAccountName` via `System.DirectoryServices.DirectorySearcher` (in .NET/PowerShell on any Windows host — no RSAT, no ActiveDirectory module, no WinRM-to-DC).
- **CIDR fallback**: bounded TCP connect probes to **445 (SMB)** and **135 (RPC)** within the operator-supplied CIDR (not ICMP, not nmap). Confirmed hosts become the sweep scope.

### Evidence seam to cw-acq-toolkit (from #3; the one external integration seam)
- **One new collector id `deal-scan-inventory`** registered in the toolkit's `_COLLECTOR_AREAS` (→ Endpoints) and `_COLLECTOR_AREA_SECTION` (→ an endpoint inventory section), so packages route via **`_map_inventory_records`** (which copies all record fields verbatim + `evidence_ref` + `verification: imported`). This is mandatory: routing via the asset path (`_map_records_to_assets`) whitelists to hostname/type/support_status/edr_managed/patch_age_days and would **drop** the software/hardware/subnet fields. Optional (recommended) additive `_IMPORT_FIELD_CONTRACTS['deal-scan-inventory']` type-hardening.
- **Estate subnet LIST** rides the **existing** `network-snapshot` collector — additive subnet fields only (`name`, `role`, `site`, `description`, `host_count`, `vlan`, `gateway`), one additive `FIELD_CONTRACTS['network-snapshot']` extension.
- Per-host software/hardware/subnet fields ride the `deal-scan-inventory` records (additive, schema-open at the record level — no schema bump; stays v1).
- Emitter mirrors estatescan exactly: `schema`/`schema_version`=1/full engagement fields/`collector.id`/`version`/`started`/`finished`/`errors`, separate structured run log, SHA-256 provenance.

### Per-host collection (from #3/#4/#7 + #6 hardware expansion)
- **Software watch-list**: `Get-ItemProperty` on `HKLM\...\Uninstall\*` and `HKLM\...\WOW6432Node\...\Uninstall\*` (read-only; **never `Win32_Product`**); watch-list filter applied **client-side before JSON** (WinRM ~150KB envelope); name→version one-to-one per subkey; absent key ≠ not-installed.
- **Hardware (new additive read-only fields)**: `total_ram_bytes` (`Win32_ComputerSystem.TotalPhysicalMemory`), `cpu_model` + core count + base-clock reference (`Win32_Processor`), `os_architecture`/64-bit + Win11 support (`Win32_OperatingSystem.OSArchitecture`), `gpu_model` + platform + dedicated VRAM (curated **name→VRAM catalogue**, platform-aware `desktop|laptop|integrated|virtual`; **avoids `AdapterRAM` >4GB truncation**; unresolved → `unknown`, never guess), `storage_type`/`capacity`/`free`, device age (`Win32_BIOS.ReleaseDate`/OS-install proxy with `unknown` fallback, operator-overridable via sidecar).
- **Per-host subnet membership**: `Win32_NetworkAdapterConfiguration`/`Get-NetIPConfiguration` (additive `ip_address`/`subnet_cidr`/`default_gateway`/`dhcp_enabled`/`dns_servers`/`mac_address`); filter `IPEnabled=true`.
- These extend (never weaken) the read-only allowlist and `test_winrm_safety.py`-style guardrails.

### Derivation lens (from #6; Revit Hardware Suitability policy verbatim in issue #6)
- **Primary signal per machine = Revit Hardware Suitability**, decision `retain | upgrade | plan_replacement | replace | manual_review`, produced in the ordered assessment: collect → hard-fails → workload profile → CPU → RAM → GPU/VRAM → storage → age → decision → reasons.
- **Workload profiles** (operator-assigned via `--workload-profile` or sidecar map; default `revit_standard`): `revit_light` / `revit_standard` / `bim_coordination` / `visualisation`, each with RAM/CPU/VRAM/storage/OS baselines as specified.
- **CPU**: single-thread score (<2200 Red, 2200-2799 Amber, 2800-3399 Green, ≥3400 Strong Green); laptop-suffix modifiers (U/P/H/HS/HX/desktop); hard-fails (<4 physical cores, severe thermal); family rules + benchmark fallback for unfamiliar CPUs; insufficient info → `manual_review`. An unfamiliar recent CPU must not fail merely for being absent from the catalogue.
- **RAM / GPU / storage / hard-fails / age / overall logic / `manual_review`**: exactly as specified in issue #6 (per-profile RAM thresholds, upgradeable-RAM → `upgrade`, GPU model+VRAM catalogue, storage Red/Amber rules, hard-fail → `replace` unless upgradeable, age = modifier only, unknown hardware → `manual_review`).
- **Composition** (primary + layered): the hardware decision is primary; the toolkit's CE+ readiness (`support_status`/`edr_managed`/`patch_age_days` — including the "Windows 11 unsupported" hard-fail) and the #8 watch-list edition tiers escalate the decision one notch where material and add reason strings + finding rows, via the toolkit's deterministic `_score(impact, likelihood)`/finding model.
- **Watch-list currency** (from #8): Autodesk current = latest major N..N-3 (≥4 behind = EOL/EOS); Adobe current = latest major only. Latest known via **hybrid live lookup → versioned-table fallback**, every comparison stamped `as_of` + `source`. Acrobat commercial flagged, Reader tracked-unflagged. Normalisation: Autodesk leading-4-digit-year major, Adobe leading-int major; unparseable → `unknown`.
- **Policy config files**: 4 version-controlled JSON files (`revit-hardware-assessment.schema.json`, `revit-minimum-policy.json` [main], `cpu-rules.json`, `gpu-rules.json`) reviewed at least annually (recalibrate CPU benchmarks, add GPUs, review VRAM variants, review on new Revit major, bump `version`/`last_reviewed`, test against known Green/Amber/Red machines). Do NOT depend on an exhaustive CPU catalogue.

### CLI (mirrors estatescan, adapted to the sweep boundary)
- Commands: `sweep` (primary), `validate`. Output = evidence package(s) + run log; prints the `cw-acq import` invocation on completion.
- Producer side mirrors `package.py`/`runlog.py`/`scope.py`/`safety.py` from estatescan (build_package, write_package, build_runlog, banner, resolve_output_folder, assert_not_overwriting, assert_output_confined, check_value/check_record).

## Testing Decisions

**What makes a good test**: assert external/observable behavior, not implementation internals. Prefer deterministic, `today`-injected, `unknown`-fallback derivation tests; structural safety tests that pin invariants (CIM allowlist, no injection point, credential isolation, scope fail-closed); and a cross-tool import proof that the additive fields survive. No live Windows estate required — use an injectable runner, canned facts, and fixture packages (estatescan's established pattern of 108 tests via injection).

**S1 — Toolkit import seam (primary, external seam)**: a cw-dealscan-produced fixture package imports unchanged into `cw-acq import`, and the additive hardware/software/subnet fields survive via the inventory mapping path (not the asset path). Prior art: estatescan's cross-tool import test (live-collected package → `cw-acq import` → findings). Also assert `validation`: unknown/unregistered collector id is rejected; field-contract violations on the new `_IMPORT_FIELD_CONTRACTS['deal-scan-inventory']` fail import.

**S2 — Derivation/assessment seam (internal unit)**: pure-function tests for the Revit Hardware Suitability policy (per-profile RAM/VRAM/storage thresholds; single-thread CPU bands + suffix modifiers; GPU name→VRAM catalogue; hard-fail → replace; upgradeable part → upgrade; age-modifier; unknown hardware → `manual_review`), the watch-list currency tiers (Autodesk N..N-3; Adobe newest-only; `as_of`+`source` stamp; Acrobat Reader unflagged), and the CE+/watch-list composition (escalation one notch). Plus the structural safety contract: extended CIM read-only allowlist, no injection point in constant scripts, credential-never-in-output. Prior art: `test_derivation.py`, `test_winrm_safety.py`, `test_safety.py`.

**S3 — Scope-gate/CLI seam (internal unit)**: `sweep` fails closed without authorisation reference/CIDR/domain; `--confirm` required; banner rendered; output path-confined & overwrite-safe (repeat run refuses to overwrite); `--operator-role` recorded; getpass-only (no `--password` accepted); runlog auditable with `out_of_scope_discovered` for discovered-but-unswept hosts. Prior art: `test_scope.py`, `test_cli.py`.

## Out of Scope

- **Network performance** (throughput/latency/bufferbloat) — explicitly deferred; no active measurement, no bandwidth test (separate Mac-side network-audit tooling is the later path).
- **Full (non-watch-list) software inventory** — enumeration is watch-list-scoped only.
- **Auto-update enablement enumeration** — a standing report caveat ("watch-list apps are only as patched as auto-update allows — verify update settings"), not a collected field.
- **Modifying cw-estatescan or the cw-acq-toolkit core** beyond the one additive collector registration + subnet field extension.
- **Dashboard** and final report rendering — downstream consumers, out of this route (toolkit/UI partially serve them).
- **Buy-vs-remediate financial modeling / TCO** — the signal is the technical `retain|upgrade|plan_replacement|replace` decision, not cost modeling.
- **Modifying the evidence-package schema version** — stays v1 (additive fields only).
