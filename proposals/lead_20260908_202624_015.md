# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**kmc_programme_metrics has no server-side build_snapshot hook, so a run can only be frozen from a browser**

*Project description:*
## What is missing

`kmc_programme_metrics` declares `supports_saved_runs: True` with
`snapshot_inputs.state_keys: ["frozen"]` and **no** server-side `build_snapshot`
hook. Its snapshot is therefore whatever the RENDER staged into run state, which
means a run can only be frozen by a human (or a browser automation) opening the
page and clicking Freeze twice.

That defeats the design intent: the workflow + snapshot infrastructure is meant to
let an agent create a run and complete it over the API. Two templates already do
this — `weekly_dual_track_audit` and `program_audit_creator` both define
`build_snapshot`. This one should too.

Concretely, today an agent that wants a frozen KMC run has to drive Playwright
against the live page. That happened on 2026-09-08 and is what prompted this.

## Why it is not a one-liner

The snapshot's shape is defined by `buildFrozen()` in
`kmc_programme_metrics_render.js`, and every part of it is computed in JS:

| snapshot key | render source |
|---|---|
| `programInd` | `var programInd = React.useMemo(...)` :1548 |
| `byLLO` (with nested `opps`) | :1163 |
| `byOpp` | :1143 |
| `byFLW` | :1509 |
| `monthly` | :1705 |
| `monthlyByScope` | `monthlyFor(llo, opp, ...)` per scope, in `buildFrozen` |
| `mortalityCredible` | :1561 |
| `cMeasures` | the `/semantic/` catalog as published |

and each indicator is BANDED by `cBandOf` (:1004) → `nBandOf` (:1454). There is no
Python banding anywhere in `connect_labs/semantic/` — `grep -rn "def .*band"
connect_labs/semantic/*.py` returns nothing.

So a hook has to port banding as well as the aggregation, and keep both in parity
with the JS. A partial port is worse than none: it would put subtly different
numbers — including band COLOURS — on a frozen funder-facing dashboard than the
live view shows. `cBandOf`'s own comment records exactly that failure once
already ("returned 'unbanded' for EVERY indicator ... a truthful-looking '0 of 6
LLOs with a red indicator' while C09 sat at 37.8% against a red threshold of 40").

## Suggested shape

The semantic layer already computes every number server-side, which is what makes
this tractable now:

1. Call `semantic.runtime.evaluate` for
   `scopes=programme,llo,opportunity,flw,month,llo_month,opportunity_month,flw_month`
   in ONE pass (the endpoint already does this; ~1,200 rows, ~45s warm).
2. Port `nBandOf` to Python next to the registry, and have the RENDER import the
   thresholds from one place rather than each side owning a copy.
3. Reshape rows into the `buildFrozen` keys above.
4. Parity test: build the snapshot both ways for the same run and assert equality,
   so drift fails CI rather than appearing on a dashboard.

Step 2 is the one that keeps this fixed rather than fixing it once.
