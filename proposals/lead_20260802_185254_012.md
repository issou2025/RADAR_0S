### Fact vs inference
**Fact:** SkillJury’s current recovery records are snapshot-based and stale relative to a rapidly changing ecosystem.

**Inference:** The strongest defensible trust signal is increasingly not a generic quality score. It is an inspectable record of *which version was evaluated, what changed upstream, whether the installed/copied version diverged, and which trust conclusions remain valid after those changes*.

### Updated product hypothesis
SkillJury should narrow from a broad review directory toward a **version-aware provenance and lifecycle-risk layer for agent skills**. Discovery remains distribution; the core product should help a developer answer: “What exact skill version am I trusting, what changed since it was checked, and does the evidence still apply?”

### Highest-leverage bottleneck
The public methodology explains trust boundaries, but no skill record currently demonstrates version drift, evidence expiry, or reproducibility in a concrete inspectable format.

### Exactly one focused experiment
Create one static, recovery-safe **Version-Drift Trust Dossier** for a representative visible skill.

Minimum fields:
1. canonical repository and skill path;
2. evaluated upstream commit and evaluation timestamp;
3. current upstream commit observed at render/build time;
4. drift state: unchanged, changed, unavailable, or forked/copied;
5. changed files or instruction sections when deterministically available;
6. install path and supported agents;
7. declared capabilities and state-changing/system-level actions;
8. evidence sources, scanner/tool versions, and limitations;
9. conclusion expiry rule when upstream content changes;
10. reproducible checksum for the evaluated artifact.

### Success criterion
- One representative dossier is publicly inspectable and reproducible from source evidence.
- It clearly distinguishes evaluated version from current upstream version and invalidates or marks stale conclusions after drift.
- No live Supabase dependency, secret, paid resource, or write flow is introduced.
- Regression coverage prevents claims from surviving when the evaluated checksum/commit no longer matches.
- Preview, production deployment, live route verification, and an observation window are required before claiming success.

### Rollback
Single commit revert of the dossier page/data/test. No schema or user-data changes.

### Decision
**Continue, but narrow further toward version-aware lifecycle trust.** Keep issue #56 as the measurement experiment; do not add analytics code blindly. The dossier is the next product-format experiment once implementation can be isolated and verified without disturbing recovery reliability.
