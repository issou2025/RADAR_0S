# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**CI: where the minutes go, and what to change**

*Project description:*
An audit of `.github`, measured on recent runs rather than read off the YAML. CI is in better shape than its length suggests: failures are rare and almost all real, a ready pull request takes about 7 minutes, and queue waits are short. What follows is the avoidable part.

## Where the time goes

| Workflow | Job-minutes | Largest parts |
|---|---|---|
| CI, ready pull request | 66 a run (median of 10) | Python wheel 7.0 (5.3 in maturin), three viewer legs 5.5 to 6.6 each (about 2 each building the WASM), Corpus health 6.3 |
| CI, `main` | 82 a run | Windows wheel 9.4, macOS wheel 6.5 |
| Deploy viewer | 27 a run | the WASM built three times: 4.1, 4.3 and 3.6 |
| CodeQL | 9 a run | Analyze (rust) 6.9 |
| Measure | 720 over 36 dispatched runs | the Measure step 66%, Build 21%, every fetch together about 3% |

The longest wait for a Measure shard to start had a median of 3 minutes and a maximum of 9.7 over those runs. None of the 33 dispatched runs whose inputs could be read repeats another's commit and inputs.

Since 04:00 UTC on 2026-11-05, over 28 landings: 14,349 job-minutes. Full CI on pull requests is 51% (119 runs), CI on `main` 14%, Measure 13% (90 runs), CodeQL 11% (185 runs), a draft's fast CI 7%, Deploy viewer 3%. From 2026-11-04 to 11-05, of 328 full CI runs, 219 were a lane's own commit on a ready pull request, 57 the queue's update merges (none failed) and 52 a lane's merge of `main` (one failed, on `semver checks`). The Actions cache was at its 10 GB limit with 1,819 entries, 1,185 of them unusable (5.2 GB; deleted by hand on 2026-11-05).

## What to change

- [x] **Measure builds once per side.** Every shard of a commit misses the binary cache at once and builds the same binaries, so a 12-shard run builds 12 times. Build each side in a job of its own and hand the binaries to the shards as an artifact. The shards then need no Rust toolchain and run no build script (`tools/ci/measure-reference-models.sh` never calls cargo). Done in #1459.
- [x] **The viewer builds its WASM once per run, and Deploy viewer tests what it publishes.** CI's three legs each build it. Deploy viewer builds it three times and publishes the `build` job's copy, while `tests` and `measure` each test a build of their own, so the file published is not a file that was tested. Done in #1458.
- [x] **CI's wheels build without LTO.** They are smoke builds; `publish.yml` builds the release ones. CI already builds the viewer's WASM this way. The `rust-cache` step there restores a `ci` profile cache that `--release` in a container cannot use. Done in #1461.
- [x] **One pin list, one action and one cache for the RE1 models.** The same hashes are in four places, with two cache keys and two fetches that do not cache at all, one of which has a fallback host the others lack. Done in #1461.
- [x] **`publish.yml`: a dated nightly for the docs.rs preview, and no `--with-deps`.** It floats on `nightly` where `ci.yml` pins a date, so a nightly regression can stop a release that no pull request saw. `playwright install --with-deps` is the apt step `viewer-test.yml` removed after it stalled on a mirror. Done in #1460.
- [x] **A failed SARIF upload is retried.** It turned zizmor and Scorecard red on 2026-11-05 with no finding; each passed when rerun. Done in #1461.
- [x] **CodeQL skips drafts and documentation-only pull requests.** 185 runs and 1,630 job-minutes in a day, on every draft push too. It is not required, but landing waits for it. Done in #1461.
- [x] **Issue forms.** The Revit release lists stop at 2026 and start at 2016, and `re_finding.yml` links `docs/corpus-intake.md` with a relative path that leaves the repository. Done in #1462.
- [x] **Deploy viewer's trigger** names neither `viewer-test.yml` nor `.github/actions`. Done in #1458.
- [x] **Composite actions for setup**, last, since it touches every workflow: the Rust install is repeated 27 times and the `wasm-bindgen` steps 3 times. Done in #1491.

- [x] **`publish.yml` preflight**, a cheap first job: `CI passed` on the tagged commit, the tag verified and on `main` or a hotfix branch, every version in agreement. Today none of that is checked, and the version check runs after seven wheel builds. Done in #1460.
- [x] **A release can be re-run:** crates already published are skipped. **One global publish group**, so two tags cannot race for ghcr `latest`. **`SHA256SUMS` attested.** **The Intel macOS CLI smoked** under Rosetta. Done in #1460.
- [x] **PII guard:** the patterns start with `[a-z]`, so `/Users/Griffin/` and `C:\Users\Griffin\` pass, and every workflow file is exempt where only the one defining the patterns need be. The wider patterns match nothing on `main` today. Done in #1462.
- [x] **Timeouts:** 44 of 52 jobs have none, so they fall back to 360 minutes. Set them, with a check that fails on a job without one. Done in #1462.
- [x] **actionlint with shellcheck** in CI. It finds nothing today but the `$/` form it does not know. Done in #1462.
- [x] **Scheduled work:** `cargo audit` runs only on pushes, and `fuzz/Cargo.lock` and `tools/ci/witness-ifc-lite/Cargo.lock` are never audited; a NOT MEASURED that persists on `main` reaches nobody; Corpus nightly's failures reach nobody; `clean_caches.py` is a manual chore while the cache sits at its limit. Done in #1463.
- [x] **Pinned Windows and macOS runner labels**, by the reasoning that pins Ubuntu: `windows-latest` is `windows-2025-vs2026` and `macos-latest` `macos-26-arm64` today. Done in #1462.
- [x] **Stale comments and drift checks:** the `fast` input's description leaves out `corpus-mcp`, the test job's header predates the pure-helper exception, and the MSRV and documentation-only lists are kept in step by hand. Done in #1462.

## Left alone, and why

- **A merge queue** would be the canonical fix for repeated CI on update merges, but GitHub offers it only to repositories owned by an organization.
- **Skipping CI's jobs on documentation-only pull requests.** Only 4 of the last 60 merged pull requests were, and `tests/support_matrix.rs` and `tests/binary_inventory.rs` read those documents, so the checks that would be skipped are the ones they can break.
- **The `unnameable_types` rebuild in the clippy job.** That job takes 1.7 minutes.
- **Moving Deploy viewer to `workflow_run`** to free a runner during its wait for CI: that job's median is 0.5 minutes, since CI has usually finished by then.
- **`dependabot.yml`** already updates action pins, and `$/` is the form in the files and runs in CI.
- **The `[[bin]]` awk in `release-binaries.yml`:** a missing binary fails its `cp` under `set -e`, and `tests/binary_inventory.rs` pins the list.
- **The Measure step itself** is exports and scorers doing the work asked of them. Its own cache of scorer output already exists.
