## Proposed v1 design

### 1. Input authority

The public temporal surface is derived only from the checked-out trusted repository commit used by the Pages build.

It must build and validate one canonical Phase 13 `crypto-observation-hour-series/v1` record from the same immutable repository context. No raw-snapshot rendering bypass is allowed.

The Phase 15 selector must inherit the exact frozen Phase 13 snapshot-path participation and malformed/unorderable-population semantics. Phase 15 may reuse or extract a shared implementation primitive only if its behaviour remains exactly equivalent to the frozen Phase 13 contract; it must not define a second, weaker notion of a participating snapshot.

### 2. Bounded first surface and deterministic window selection

V1 publishes one historical evidence series only:

- kind: `metric`
- key: `BTC.price_usd`
- window: exactly 24 canonical observation-hour slots

For one immutable checked-out repository commit:

1. enumerate the snapshot population using the exact frozen Phase 13 participation semantics;
2. if any participating candidate makes the population malformed/unorderable under Phase 13, fail closed before selecting a window;
3. collect the canonical `run.observation_hour_utc` identities of all deterministically participating candidates;
4. if that set is empty, fail closed with no asserted temporal series and no `temporal.html` output;
5. otherwise set `window.end_utc` to the maximum canonical participating observation hour and set `window.start_utc` to exactly 23 hours earlier.

The selector never uses wall clock, workflow time, filesystem metadata, report titles, mutable branch state or network state.

Duplicate candidates for the selected end hour do not elect a winner and do not move the anchor backwards. The canonical hour remains the deterministic window end and the frozen Phase 13 series semantics expose the duplicate as an explicit ambiguity/gap. Missing, duplicate, invalid or otherwise unavailable evidence anywhere inside the selected 24-slot window remains explicit through the frozen Phase 13 gap states; it must not be filled, interpolated, skipped or replaced by an older slot.

### 2a. Trusted-main evidence prerequisite

The current trusted `main` has zero Phase-13-participating observations, so public-site integration cannot yet truthfully produce the proposed page.

Before the site-integration/public-proof slice may begin, a separately governed source-evidence promotion must place at least one Phase-12-valid participating snapshot on trusted `main`. That prerequisite:

- is satisfied only by reviewed repository-owned evidence that becomes part of trusted `main`;
- does not require 24 successful observations because missing hours remain explicit gaps;
- must not read or render directly from `automation/source-snapshot-rolling` or any other mutable branch;
- must not mutate or backfill historical snapshots;
- must not use Phase 14 `pilot`/`recurring`, deterministic-publication candidate automation or #477 as an implicit evidence-promotion path;
- requires its own governing authority if repository mutation is needed.

Phase 15 contract/renderer proof may be implemented and tested offline with deterministic fixtures before that prerequisite is satisfied, but site integration must remain gated until trusted `main` contains real participating evidence.

Once public integration exists, a later checked-out commit with zero participating observations must fail the temporal-page generation path closed rather than publish an asserted chart from stale, legacy, branch-only or fabricated evidence.

### 3. New Phase 15 public renderer boundary

Implement a small Phase 15 renderer that validates the Phase 13 record directly with `validate_observation_hour_series` before rendering.

It may reuse Phase 11 visual/accessibility conventions or pure presentation helpers that do not carry Phase 11 schema semantics, but must not:

- convert a Phase 13 record into a fake Phase 11 record;
- call an internal Phase 11 rendering path without its required validator;
- reinterpret Phase 11 or Phase 13 frozen schema semantics.

The renderer should emit deterministic semantic HTML + inline SVG + a complete evidence table. Meaning must not depend on colour alone. Gaps and continuity breaks remain visible.

### 4. Public-site integration

Prefer one dedicated generated page, for example:

`temporal.html`

with one low-prominence homepage entry point such as “View deterministic temporal evidence”. Do not expand primary navigation in v1 unless fresh review shows that it is necessary.

Integrate through the canonical `site_generator` pipeline rather than creating a parallel Pages build path.

Generated `_site/` remains disposable and uncommitted.

No homepage link may be emitted unless the temporal page was successfully generated from the same checked-out repository commit.

### 5. Public framing

The temporal page must preserve the repository’s demo/non-advice posture before the chart is read:

- deterministic historical evidence, not a forecast;
- AI/demo project context remains explicit;
- no recommendation, trading signal, market call or investment research claim;
- gaps/degraded evidence are visible rather than hidden.

No generated narrative or interpretation is added.

### 6. Existing Pages behaviour

No Pages workflow permission, trigger, environment or deployment redesign is proposed. `site_generator/**` is already a Pages trigger and `python -m site_generator` is the canonical build path.

Any later implementation merge would therefore have a real public Pages effect and requires separately authorised implementation/review/merge governance. This shaping issue does not grant it.
