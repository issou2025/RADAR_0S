## Summary

Two pieces of planned work need outputs that only a Revit installation can produce, which the project's CI does not have. If you use Revit and would like to help, this is a place where that is especially valuable.

## Checklist

- [ ] **A DWG export for the second witness edge.** The [verification protocol](https://github.com/DrunkOnJava/rvt-rs/blob/main/docs/verification-protocol.md) records "witness edges": a Revit file and an export of it, read by independent implementations whose agreement CI checks. Two RVT → IFC edges are recorded. The planned RVT → DWG edge, read with [dwg-rs](https://github.com/DrunkOnJava/dwg-rs), needs a DWG that Revit exported from one of the openly licensed reference models (Core Interior or Einhoven, see [`docs/reference-models.md`](https://github.com/DrunkOnJava/rvt-rs/blob/main/docs/reference-models.md)). Done when that export, with its settings recorded, is registered in `research/witness-registry.json` and gated in CI.
- [ ] **API fixtures for extensible-storage references.** Extensible storage (ES) entities can hold ElementIds of other elements. Remapping them is researched but not shipped, and the default IFC export leaves ES edges out. The research is in the [unified research report](https://github.com/DrunkOnJava/rvt-rs/blob/main/docs/research/unified-research-report.md), coordinated in [Discussion #112](https://github.com/DrunkOnJava/rvt-rs/discussions/112). Its fixtures need the Revit API run on openly licensed models. Done when such fixtures exist and the remapping is measured against them, or the research ends with a documented negative result.

## How to help

Please comment here before exporting anything, so we can agree on the model, the settings and the licence first. Everything has to follow [`CLEANROOM.md`](https://github.com/DrunkOnJava/rvt-rs/blob/main/CLEANROOM.md): outputs of Revit run on openly licensed files are fine; anything from Autodesk SDK internals is not.
