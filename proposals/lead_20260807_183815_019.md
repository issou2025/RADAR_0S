## 4. 社区热点

1. **[#7707](https://github.com/openclaw/openclaw/issues/7707)（28 条评论）— Memory Trust Tagging by Source**
   - 长期高热度增强请求（自 2026-02-03 累计），要求按来源（用户指令 / 网页抓取 / 三方技能）为 agent memory 打信任标签，防御 memory poisoning 攻击。

2. **[#44925](https://github.com/openclaw/openclaw/issues/44925)（25 条评论）— Subagent completion silently lost**
   - P1：子代理在 E31/E42/E45 等错误下完成回报丢失，无重试、无通知、无自动重启。
   - **诉求本质：** "长任务跑完用户却什么都没看到" 严重伤害信任，社区要求至少要有显式失败信号。

3. **[#92201](https://github.com/openclaw/openclaw/issues/92201)（21 条评论）— Anthropic thinking signatures invalid on replay**
   - P1：嵌入式 runner 流式产出的 thinking 签名间歇失效，且恢复包装器因错误文本被泛化而不会触发。
   - **诉求本质：** Anthropic 思考块重放是 Claude 4+ 的标配路径，OpenClaw 在此处的可靠性问题成为模型可用性瓶颈。

4. **[#84583](https://github.com/openclaw/openclaw/issues/84583)（12 条评论）— cron announce triggers EmbeddedAttemptSessionTakeoverError**
   - P1：cron 任务完成回执送达时与用户活跃会话冲突，触发会话接管错误。
   - **诉求本质：** "自动化"和"用户对话"两条路径对同一 session 的并发写权缺乏仲裁。

5. **[#53408](https://github.com/openclaw/openclaw/issues/53408)（10 条评论）— Write/exec tool parameters silently dropped after long conversations**
   - P1：长对话（≥15 轮）后，写入/执行类工具的参数被静默丢弃为空对象。
   - **诉求本质：** 工具调用的"看不见的丢参数"是最危险的一类故障——模型以为执行了，实际未执行。已有 PR [#120248](https://github.com/openclaw/openclaw/pull/120248) 在跟进 Bedrock 路径。

社区情绪关键词：**"silent failure"（静默失败）** 出现频率显著上升，集中在嵌入式 runner、cron、thinking 签名三条路径。
