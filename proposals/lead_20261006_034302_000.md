# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**docs: state which commands validate jobId over direct HTTP**

*Project description:*
## Symptom

Over direct HTTP, only action commands validate `jobId`. A non-action command such as `ping` accepts any string (`not-a-guid` returned 200). Reusing the same id then returns `duplicate_job_id`.

## Repro

1. `POST /jobs` with `{"command":"ping","jobId":"not-a-guid"}`: 200.
2. Repeat the same request: `duplicate_job_id`.
3. `POST /jobs` with a non-GUID-N `jobId` and an action command: 400 `invalid_job_id` (since #181).

## Expected

Pick one:

- Document that only action jobs need a GUID `jobId` (persisted results are named after it) and that any client-chosen id must be unique while the result is retained.
- Validate the format for every command so the rule is the same for all jobs.

I lean towards the documentation sentence in `docs/transport.md`, because read jobs are never written to disk under their id.

## Evidence

Checked on Revit 2026 and 2024 against 0.9.1 candidate. The bundled server always sends `uuid4().hex`, so MCP users are not affected. Only hand-written HTTP clients see this.
