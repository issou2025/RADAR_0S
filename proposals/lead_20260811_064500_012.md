*Project description:*
## Problem Statement

用户需要一个结构完整、可重复构建的 Zotero 9 第二阶段测试 XPI，在不破坏第一阶段论文关系浏览的前提下，完成插件 UI 学术文本翻译、已确认论文选择，以及通过合法来源把论文保存到用户文件夹的完整代码路径。

此前的规格仍以 vendored Python module、插件私有 venv 和 Reader 内运行时安装为中心，已经与最终决策及当前实现不一致。最终架构使用插件自有的版本化 JSONL stdio sidecar 作为唯一 Zotero-facing 接口，sidecar 再委托现有 compatibility bridge；机构路线在真实审计前只能是 candidate。规格必须反映这套边界，避免出现第二套 downloader、第二套协议、外部 ScanSci fork、静默 fallback 或把候选路线冒充为可用能力。

用户将亲自安装 XPI 并执行真实 Zotero、Paper Translate、文件下载及机构路线的手动测试，再把结果反馈给开发方。因此代理的交付责任是保证代码功能、模块结构、协议、失败语义、自动测试、构建和 XPI 内容审计完备，不得自行宣称用户侧实机验收已经通过。

## Solution

交付并维护一个 Zotero 9 Reader vertical slice：继续以 MinerU Markdown 驱动 Reference entries，以保守身份解析产生 Resolved references、Citing papers 和 Primary result；通过现有 PaperTranslateBridge 翻译插件 UI 中的用户选区；通过一个注入的 ScanSciPort 将已确认论文交给插件自有的进程外 Python sidecar。

sidecar 只暴露 `probe`、`visibleLogin`、`downloadOne` 和 `downloadBatch` 四项版本化 JSONL 操作，并继续委托唯一的 compatibility bridge 执行合法下载。所有下载先进入当前 Download destination 下本次请求或批次专属的 ScanSciCache 目录，再由插件验证来源证据与相对路径，按 canonical title 进行 containment 和 exclusive no-overwrite 最终提交。单篇或批量失败不得破坏 References/Citations、Paper landing page、详情卡或 Paper Translate。

自动验证聚焦代码可观察行为和边界契约。真实 XPI 安装、真实论文阅读流程、Paper Translate 服务效果和机构授权路线由用户手动验收；用户反馈应作为后续缺陷输入，而不是由自动测试模拟成功。

## Implementation Decisions

- MinerU Markdown remains the only source of Reference entries. Downloaded files, sidecar results and source availability must not create or change a Reference entry, Resolved reference, Citing paper or Primary result.
- Paper identity remains conservative: prefer stable identifier agreement; otherwise require a unique, non-competing exact normalized title and exact year match. Author evidence is auxiliary. Ambiguous or unresolved papers are never eligible for Download selection.
- The Reader/controller layer depends on one injected ScanSciPort and the existing PaperTranslateBridge. It must not import Python, sidecar process mechanics, publisher implementations or a second translation provider.
- The production ScanSciPort consumes only the plugin-owned versioned JSONL stdio sidecar. The legacy one-request bridge protocol is not a TypeScript-facing interface; the existing bridge remains an internal sidecar seam and the single download implementation.
- The sidecar belongs to this plugin repository and uses the plugin's compatibility namespace. External ScanSci source, installation and repository are not modified, forked or used as a second product control plane.
- The sidecar protocol exposes exactly four operations: `probe`, `visibleLogin`, `downloadOne` and `downloadBatch`. Requests and responses carry exact protocol, contract and result-schema versions plus one request identity.
- `probe` must report real application/runtime identity, Python version and architecture, fixed upstream provenance, clean manifest state, legal-only policy and route capabilities. Hard-coded or guessed capability success is forbidden.
- Probe occurs at Zotero startup, before route projection, after a successful visible login and immediately before each download. Incompatibility fails at that boundary with a concrete reason and no alternate runtime, protocol, MCP or HTTP fallback.
- The Zotero subprocess adapter owns JSONL line handling, stdin close, process wait and kill, AbortSignal cancellation, timeout, and bounded stdout/stderr. Invalid JSON, incompatible identity, duplicate or missing terminal messages, unexpected progress and output-budget overflow are explicit errors.
- Sidecar stdout contains protocol messages only. Stderr has a process-wide bounded budget and redacts Authorization, Cookie, secret-bearing JSON values and URL query data.
- The sidecar rejects arbitrary URLs, configuration writes, profile paths, credentials, cookies, tokens and unknown request fields. It fixes legal-only policy before any network egress.
- The open-access route is available only for audited arXiv and PMC sources. A downloaded result carries identifier, legal source evidence, allowed egress hosts and a relative path; a failed result carries a bounded code and message without a usable path.
- The institution route identity is `institution-webvpn/ieee/one-click-single`. Until the user reports a complete strict-TLS, egress, source-evidence, dedicated-profile, single-writer and real one-paper audit, it remains `candidate` and unavailable. `visibleLogin` must not start a browser for this candidate.
- A single selection invokes `downloadOne`. Multiple selections invoke one `downloadBatch`; sidecar concurrency is fixed and bounded, progress is emitted once per completed item, and one item failure does not abort unrelated items.
- The application snapshots the ordered Download selection and current Download destination before dispatch. Per-paper UI state is limited to queued, downloading, downloaded and failed; final domain results remain downloaded or failed.
- Each single or batch request receives exactly one caller-created `ScanSciCache` request directory beneath the selected destination. The sidecar may write only inside it and returns only relative paths.
- Before final commit, the plugin validates source evidence, resolves the sidecar path beneath the request directory, derives a Windows-safe canonical title target beneath the destination, and uses an exclusive no-overwrite operation. Traversal, absolute paths, missing files, directory targets, same-name targets and disk failures are explicit per-paper failures.
- Canonical title processing is the only normal rename. The plugin does not overwrite, append numeric suffixes, switch directories, retry at the application layer or choose a weaker source.
- After a normally handled success or failure, the plugin removes only the current request directory and retains the ScanSciCache root. Crash residue is not interpreted, recovered or silently cleaned at startup.
- Downloads remain pure filesystem operations. They do not call the Zotero Web API or create, update or index Zotero library objects.
- Paper Translate integration uses only its public version/capability and translation API for academic text selected inside plugin UI. It does not take over PDF body translation, OCR or Paper Translate configuration.
- Reader composition keeps References/Citations, Paper landing pages, detail cards and Paper Translate available when the sidecar is absent, incompatible, cancelled or failed.
- The artifact remains `Reference for Zotero (Second-stage Test)` on the supported Zotero 9 range. Zotero-required manifest metadata may remain, but no tag, GitHub Release or published update metadata is created without a separate user request.
- The XPI contains only the plugin-owned compatibility module and sidecar assets required by this contract. It must exclude a complete external ScanSci repository/package, Python runtime or venv, native extensions, browser binaries/cache, profiles, cookies, tokens, API keys, PDFs, ScanSciCache contents, tests, logs and diagnostics.
- No second source of truth, silent default, broad error swallowing, mock success, route-capability guess or compatibility fallback may be introduced to make an acceptance path appear complete.

## Testing Decisions

- The user's manual installation and real Zotero testing are the authority for installed-XPI behavior. The agent must not claim that Zotero UI, Paper Translate service, institution login or a real publisher download passed until the user reports that result.
- Automated tests verify external behavior at existing module seams rather than private helper implementation. Assertions should observe Reader state, port requests/results, JSONL messages, process lifecycle, filesystem effects and XPI contents.
- The highest application seam is the existing RelatedPapersController/ScanSciPort boundary. Contract tests cover ordered selection snapshots, single versus batch dispatch, per-item progress, failure isolation, cancellation and preservation of first-stage features.
- Reader tests exercise the existing Reader section/controller seam for eligibility, tab-local select-all, cross-tab ordered selection, DOM-selection independence, Paper Translate anchoring, download status and reveal-file behavior. Tests should avoid coupling to incidental DOM nesting or CSS class names.
- ScanSciPort contract tests run the same behavioral expectations against the production adapter boundary and a deterministic test adapter where platform injection is required. They cover exact capability states and downloaded/failed results without manufacturing runtime success.
- Sidecar protocol tests cover exact identity/version matching, operation whitelists, progress ordering, terminal-message cardinality, malformed JSON, unknown fields, source evidence, relative-path rules and failure payloads.
- Python interface tests exercise the real plugin-owned sidecar and compatibility bridge for probe, open-access single download, bounded batch behavior, policy rejection, containment, stdout purity and stderr redaction. Network-dependent smoke tests remain explicit and are not converted to fake success.
- Zotero subprocess adapter tests cover stdin/EOF, line framing, wait/kill, timeout, AbortSignal cancellation, one-time termination and stdout/stderr budgets. Failures must surface rather than being swallowed or truncated into valid-looking results.
- Filesystem behavior tests use isolated temporary destinations and assert request-directory isolation, canonical filename sanitization, containment, exclusive no-overwrite, per-item commit failure and scoped cleanup.
- Translation tests follow the existing PaperTranslateBridge prior art: public API capability detection, selected academic text only, stale-result suppression and independent failure.
- Regression tests follow the existing Reader, related-paper controller, literature matching and Paper session suites to prove that ScanSci failures cannot change first-stage paper identity or Reader availability.
- Artifact verification includes clean dependency installation, full Node tests, full Python tests, typecheck, lint, formatting check, production build and XPI denylist/content audit. The generated XPI hash and size are recorded for the user-provided manual test result.
- A failing automated check blocks code completion. A missing user manual result does not become a mocked or inferred pass; it remains an explicitly pending user-verification fact outside the agent's code-completeness claim.

## Out of Scope

- The agent performing or claiming the user's real Zotero installation, Paper Translate service validation, institution authentication or publisher entitlement test.
- Promoting WebVPN → IEEE Xplore from candidate to available before the user's complete real-world audit feedback is incorporated.
- Authenticated metadata enrichment or representing public Semantic Scholar metadata as institution-authenticated data.
- Modifying, forking, submoduling or fully copying the external ScanSci repository, or creating another downloader beside the existing compatibility bridge.
- General MCP/HTTP ScanSci control planes, arbitrary sidecar operations, arbitrary URL download, configuration mutation, secret import or Zotero Web API upload.
- Zotero item, attachment or collection creation; full-text indexing; automatic local import; duplicate detection against the Zotero library.
- PDF magic/content verification, identity re-verification from file bytes, SHA-256 content deduplication, journal, crash recovery, persistent queue, automatic retry, background prefetch or automatic download.
- Overwrite, automatic suffix rename, alternate destination, application-level second-source fallback or weakened legal-source policy.
- Sci-Hub, LibGen, SciBban, Tor, proxy pools, IP rotation, VPN-Sci, hidden login, CAPTCHA bypass or any access-control circumvention.
- Paper Translate provider configuration, PDF body translation, image OCR, Zotero 7/8 support, dark-theme redesign or a formal public Release.
- Third-stage `auth.json` literature filtering, relevance analysis and importance ranking.
