# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[web] Tooltip text is read twice: while a tooltip shows, its target button's accessible name is doubled via aria-owns**

*Project description:*
### Steps to reproduce

1. `flutter create bug`, replace `lib/main.dart` with the sample below (it calls `SemanticsBinding.instance.ensureSemantics()` so no screen reader is needed to build the DOM).
2. `flutter run -d chrome` (or `flutter build web` and serve it).
3. Open Chrome DevTools → Accessibility pane (or use a screen reader such as NVDA/VoiceOver).
4. Note the computed name of the `IconButton`: `New group`.
5. Hover the `IconButton` with the mouse until the tooltip appears (a long press with touch emulation gives the same result).
6. Check the computed name of the same button again.

### Expected results

The button's accessible name stays `New group` while the tooltip is visible. The tooltip text is already exposed on the button through `Semantics(tooltip:)`, so showing the tooltip box should not change what the button is called.

### Actual results

While the tooltip is visible, the button's accessible name is `New group New group`. Screen readers announce this computed name, so the label is read twice. The name goes back to `New group` when the tooltip hides (the overlay node is removed; the button keeps a stale `aria-owns` pointing at the removed id, which looks related to #195016).

Chrome's accessibility tree (`Accessibility.getFullAXTree` over CDP), the `IconButton` node:

| State | role | computed name | name source |
| --- | --- | --- | --- |
| before hover | button | `New group` | contents |
| tooltip visible | button | `New group New group` | contents |

The DOM shows why: while the tooltip is visible, the button's semantics element gets `aria-owns` pointing at the tooltip overlay's semantics node, whose child holds the tooltip text. Because a button's name is computed from its contents, and aria-owned elements count as contents, the text is added a second time.

```text
<!-- before hover (attributes trimmed to the relevant ones) -->
<flt-semantics id="flt-semantic-node-4" role="button" tabindex="0">New group</flt-semantics>

<!-- tooltip visible -->
<flt-semantics id="flt-semantic-node-4" role="button" tabindex="0" aria-owns="flt-semantic-node-7">New group</flt-semantics>
...
<!-- the tooltip's overlay entry, outside the route's subtree -->
<flt-semantics id="flt-semantic-node-7">
  <flt-semantics id="flt-semantic-node-8"><span>New group</span></flt-semantics>
</flt-semantics>
```

The second widget in the sample (`Tooltip` around a `FilledButton` that has its own label) shows a milder form: the button's name stays `Delete`, but the wrapper node that carries the tooltip gets `aria-owns` to the overlay too, so the tooltip text `Delete the item` appears as an extra static text in the reading order while the tooltip is visible.

Showing the tooltip through keyboard focus does not apply here: in this version a focused button does not show its tooltip.

**Cause.** `RawTooltip` (which Material's `Tooltip` in both `package:flutter/material.dart` and `package:material_ui` builds on) exposes the message twice:

- on the child, as `Semantics(tooltip: semanticsTooltip)`: [raw_tooltip.dart#L949-L952](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/packages/flutter/lib/src/widgets/raw_tooltip.dart#L949-L952)
- in the overlay, where the `tooltipBuilder` output (a `Text` with the same message) is placed without excluding semantics: [raw_tooltip.dart#L886-L894](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/packages/flutter/lib/src/widgets/raw_tooltip.dart#L886-L894), shown through `OverlayPortal.overlayChildLayoutBuilder` at [#L965-L969](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/packages/flutter/lib/src/widgets/raw_tooltip.dart#L965-L969)

Since the `OverlayPortal` semantics refactor (#173005, relanded in #178095, first in 3.41.0), `OverlayPortal` marks its child as the traversal parent of the overlay child ([overlay.dart#L2146](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/packages/flutter/lib/src/widgets/overlay.dart#L2146), [overlay.dart#L2724-L2730](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/packages/flutter/lib/src/widgets/overlay.dart#L2724-L2730)), and the web engine turns that into `aria-owns` ([semantics.dart#L977-L987](https://github.com/flutter/flutter/blob/22b8692dea61d1a2d467d22b4627d90e435206b0/engine/src/flutter/lib/web_ui/lib/src/engine/semantics/semantics.dart#L977-L987)). The tooltip's overlay text therefore ends up inside the button it describes.

The framework's semantics tree (from `debugDumpSemanticsTree` in a widget test, same for `TargetPlatform.android` and `TargetPlatform.linux`) has the same shape while the tooltip shows, so this is not web-only in the framework; I have only confirmed the user-facing effect on the web and have not checked what TalkBack or Orca read.

```
├─SemanticsNode#4
│ │ actions: focus, tap
│ │ flags: isButton, hasEnabledState, isEnabled, isFocusable
│ │ traversalParentIdentifier: _OverlayPortalState#f10eb
│ │ tooltip: "New group"
│ │
│ └─SemanticsNode#7
│   │ traversalChildIdentifier: _OverlayPortalState#f10eb
│   │
│   └─SemanticsNode#8
│       label: "New group"
```

**Suggested fix.** When `semanticsTooltip` is non-empty, the message is already on the child, so `RawTooltip` could keep the overlay content out of the semantics tree, e.g. wrap `widget.tooltipBuilder(context, _overlayAnimation)` in `ExcludeSemantics`. I checked this on the web with two buttons built from the public `RawTooltip` in the shape `ButtonStyleButton` uses (`Semantics(container: true, button: true)` around a `RawTooltip` around an `InkWell`): `Control` with the overlay unchanged, and `Fixed` with the overlay wrapped in `ExcludeSemantics`. On hover the first is named `Control Control`, the second stays `Fixed`. (The empty overlay node is still aria-owned, which does not affect the name.) If the overlay should instead carry `SemanticsRole.tooltip` (#161630), it would need to describe the button (for example `aria-describedby`) rather than be owned by it, or the name doubles again.

The relevant code is unchanged on `master` (22b8692dea61d1a2d467d22b4627d90e435206b0); I reproduced on 3.50.0 stable.

### Code sample

<details open><summary>Code sample</summary>

```dart
import 'package:flutter/material.dart';
import 'package:flutter/rendering.dart';

void main() {
  runApp(const MyApp());
  // Turn semantics on without waiting for an assistive technology.
  SemanticsBinding.instance.ensureSemantics();
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            spacing: 40,
            children: <Widget>[
              IconButton(
                icon: const Icon(Icons.add),
                tooltip: 'New group',
                onPressed: () {},
              ),
              Tooltip(
                message: 'Delete the item',
                child: FilledButton(
                  onPressed: () {},
                  child: const Text('Delete'),
                ),
              ),
            ],
          ),
        ),
      ),
    );
  }
}
```
