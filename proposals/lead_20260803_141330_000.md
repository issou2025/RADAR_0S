## Root cause

Bonsai v0.8.x, `bonsai.bim.module.qto.calculator`:

```python
def get_gross_side_area(obj):
    if not has_openings(obj):          # ← only IfcRelVoidsElement
        return get_net_side_area(obj)  # ← Gross becomes Net
    return get_lateral_area(..., subtract_openings=False, ...) / 2

def has_openings(obj):
    return [o for o in ifcopenshell.util.element.get_openings(element)]
```

Rule mapping (`ifc5d/IFC4QtoBaseQuantitiesBlender.json`):

```text
GrossSideArea → get_gross_side_area
NetSideArea   → get_net_side_area
```

`get_net_side_area` = lateral mesh area / 2 → correct Net (≈ Solibri).

`get_gross_side_area` short-circuits when there are no opening *relationships* →
Gross = Net, even when the mesh still has holes.

The same gate exists on `get_gross_volume` / `get_gross_surface_area`:
the gross path uses `disable-opening-subtractions`, but that only helps
when there are opening relationships to skip. With pure tessellation,
gross mesh == net mesh.

IFC4 definition (for reference):

- **GrossSideArea** — elevation view of the wall middle plane, **including** openings
  (≈ Length × Height of the full wall).
- **NetSideArea** — the same plane, **excluding** openings.

Solibri follows that definition (Gross = L×H). Bonsai only follows it when
`HasOpenings` is populated.

---

## What this is not

- Not a UI bug / rounding issue.
- Not a wrong QTO rule mapping in the installed Blender JSON
  (it correctly maps to `get_*_side_area`; the skill-doc example mapping to
  `get_gross_surface_area` is outdated/incorrect vs the real JSON).
- Not a Solibri error on this wall: L×H = 20.07985 matches Solibri 20.08.

---

## Solution directions

### A — Fix in Bonsai `get_gross_side_area` (recommended for the QTO symptom)

When `not has_openings(obj)`: Gross ≠ blindly Net, but bbox elevation:

```python
# already in calculator.py:
# get_side_area(o) := max(get_x(o)*get_z(o), get_y(o)*get_z(o))
return get_side_area(obj)
```

Then for this wall: Gross ≈ 20.08, Net ≈ 9.81 → Solibri parity.
Without openings (full rectangular wall) Gross ≈ Net remains.

**Ceiling:** bbox L×H overestimates for L-shaped / non-rectangular
plan outlines. Upgrade: outer-contour projection instead of bbox, or
parametric Length×Height from type/occurrence.

Same consideration for GrossVolume if volume must also be correct without
opening relationships — separate, harder fix (reconstructing a mesh without
holes is not possible from pure tessellation alone).
