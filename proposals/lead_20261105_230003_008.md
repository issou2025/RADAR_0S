## What to build

Make the foundation usable and enforced for the whole team. A teammate on Mac or Windows can onboard from the README alone, and GitHub actually enforces "passing CI is the only merge gate." This is a HITL issue, because the repo settings need admin access and the required checks must be picked by their real job names.

## Acceptance criteria

**README**
- [ ] Prerequisites: FVM, and Windows Developer Mode (needed by FVM symlinks and Flutter plugins).
- [ ] One-command setup.
- [ ] Daily testing loop per OS. Windows: Android emulator + physical Android tablet. Mac: also iOS Simulator and iPad. iPad checks for Windows developers go through Mac teammates or CI.
- [ ] Real-finger testing on a physical tablet is required for anything metric-related.
- [ ] CI overview: what runs on every PR, what runs only for build-sensitive changes, and what runs on `main`.
- [ ] Broken-`main` norm: whoever broke it reverts first, fixes second.
- [ ] Public-repo rule: synthetic data only; never real Patient data, session exports or screenshots with real IDs.
- [ ] CI status badge.
- [ ] Links to `CONTEXT.md`, ADR 0001 and the PRD.

**Repo settings (admin)**
- [ ] Default branch switched from `feature/balloon-demo` to `main`.
- [ ] Branch protection on `main` requires the CI checks from #3 (reviews not required).
- [ ] Merge method: merge commits only (squash and rebase disabled).
- [ ] Auto-merge enabled.
- [ ] Verified: a PR with a failing check can't be merged, and a green PR with auto-merge on merges by itself.
