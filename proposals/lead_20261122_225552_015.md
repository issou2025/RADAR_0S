## Phase 1 — End-to-end playback (highest priority)
- [ ] Wire the single global Flutter player to POST /playback/sessions after successful authorized source resolution.
- [ ] Send heartbeat events only while audio is actually in the playing state; stable event UUID and monotonically increasing sequence.
- [ ] Retry the exact same eventId/sequence on network retry; never create a new sequence for a retry.
- [ ] Correct pause/resume, seek, buffering, background/foreground, audio focus, interruption, route changes, track switch, stop, logout and app termination behavior.
- [ ] Stop/close the previous session on track switch and stop; do not heartbeat while paused or stopped.
- [ ] Recover from offline/poor connectivity without double-counting; persist a bounded retry queue and safely replay idempotent events.
- [ ] Renew expiring provider URLs without losing the active session; distinguish URL expiry from session expiry.
- [ ] Handle session expiry, rejected heartbeat, provider 403/404/429/5xx, stream interruption and unavailable source with deterministic user-visible states.
- [ ] Sync /home/recent separately from qualified play events; use /home/plays only for legacy compatibility, not as verified listening evidence.
- [ ] Add Flutter tests for all lifecycle transitions, duplicate retries, sequence handling, session expiry, URL renewal, track switching and history sync.
- [ ] Add backend/mobile E2E tests proving start → playback → heartbeat → stop → RecentlyPlayed/ListeningEvent, including short and qualified sessions.
- [ ] Validate actual audio output and playback behavior on supported platforms/devices; document what CI cannot prove.
- [ ] Document that heartbeat time is server-observed activity, not proof of audible playback or royalty eligibility; never use it as royalty accounting without stronger verification.

## Phase 2 — Provider reliability and lawful catalog coverage
- [ ] Maintain a provider capability/rights matrix for search, metadata, full stream, preview, lyrics, translation, download/offline, territory and attribution.
- [ ] Keep YouTube Music discovery/metadata-only unless an authorized playback agreement and supported playback path are established; no URL extraction as a rights workaround.
- [ ] Keep Jamendo disabled until written approval/terms and Breezze-specific use are confirmed; API registration or a CC field alone is not approval.
- [ ] Keep Audius limited to supported public/ungated paths and validate applicable rights/terms; do not assume every public track is licensed for Breezze.
- [ ] Do not enable Internet Archive as a streaming source solely from uploader-supplied license metadata; verify each rights basis and use restrictions.
- [ ] Research and implement additional providers only when their documented terms permit the intended free streaming product, territory, caching, attribution and scale.
- [ ] Add provider health checks, latency/error metrics, timeouts, bounded retries, circuit breakers and controlled failover.
- [ ] Implement source selection using capability, rights decision, territory, availability, quality and provider health; never fail over to a source without authorization.
- [ ] Normalize provider metadata into canonical Breezze track/artist/album identities; handle duplicates, conflicting metadata, artwork, explicit flags, duration and attribution.
- [ ] Add provider sync/reconciliation jobs, cursor checkpoints, rate-limit handling and safe backfills.
- [ ] Add takedown/rights revocation propagation to catalog, search, recommendations, playback resolution, caches and active sessions.
- [ ] Add contract tests against provider fixtures and live sandbox/supported API checks where credentials/terms permit.
- [ ] Keep provider secrets server-side; document setup, approval gates, quotas, data retention and provider failure modes.
