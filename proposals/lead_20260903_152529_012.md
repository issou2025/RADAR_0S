**Epic 36: Local Visual Regression Testing — Screenshot Golden-State Harness**

*Project description:*
## Overview

A local, screenshot-based regression harness that captures the "healthy" running state of the app for a set of critical user journeys, so a PR touching one area can be checked against real, current screenshots — not just unit/widget test assertions passing. Motivated by a recent incident where a Cloud Function change silently broke ELO calculation for all regular group games for ~2 weeks with no test catching it (see PR #920) — the goal is to catch "the code compiles and unit tests pass but the feature is silently broken" class of bug before merge.

## Design decisions

- Screenshots are **real iOS Simulator captures** (`xcrun simctl io booted screenshot`), not Flutter widget-level goldens — closer to what a user actually sees, including native chrome.
- Flows are driven via `flutter drive`/`integration_test` against the **Firebase Emulator** with seeded, deterministic fixtures (reusing the existing `functions/scripts/setup*TestEnvironment.ts` family).
- iOS Simulator status bar is frozen (`xcrun simctl status_bar ... override` — fixed time/battery/signal) to remove one entire class of nondeterminism before it can even show up as a false failure.
- Screenshots are diffed with a tolerance threshold, not exact byte match.
- Flows are **tagged by feature area** so a PR only needs to run relevant coverage (e.g. `--tags championship` skips auth-only flows).
- Entirely **local — no CI integration**. The runner produces a local markdown report + PNGs; a contributor pastes the relevant summary into the PR description by hand.
- Baseline goldens are committed to git and updated only **deliberately**, reviewed like any other diff — never silently regenerated.

## Directory layout

```
test/visual/
  flows/            # integration_test flow files, one per journey, tagged
  goldens/          # committed baseline screenshots (the "healthy state")
  tooling/          # orchestrator, screenshot-diff, report generator scripts
  reports/          # gitignored local run output
  manifest.json     # flow -> tags -> file path
  README.md         # how to run, how to update goldens deliberately
```

## Non-goals for v1

- Android, tablet, or multi-locale coverage
- CI integration
- Exhaustive action coverage — critical-path journeys only, grown incrementally per feature vertical. Planned follow-ups once the harness is proven: Games & ELO flows (the exact feature that broke silently), Championships/Leagues, Groups, Friends, Training Sessions.

## Architecture notes

Visual flow code lives under `test/visual/` — pure test infrastructure, not production code, so it may use any repository/BLoC needed to seed and drive the app regardless of the layered-dependency rules that apply to `lib/`.
