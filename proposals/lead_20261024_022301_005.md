# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Domain gap: families and parameters — list/load/reload families, purge unused types, create and bind shared/project parameters**

*Project description:*
## Goal

Close the two gaps that stop an agent from preparing a model for placement work on its own: it cannot bring a family into the project, and it cannot create the parameters the company standard requires.

| Tool | Permission | Purpose |
|---|---|---|
| `revit_list_families` | ReadOnly | Loaded families per category: name, kind (loadable / system / in-place), type count, instance count, whether editable, source path when known |
| `revit_preview_load_family` / `revit_load_family` | ReadOnly / RequiresApproval | Load one or more `.rfa` files; overwrite policy for an already loaded family; activate types |
| `revit_reload_family` | RequiresApproval | Reload a loaded family from its file (or a given path), keeping or overwriting parameter values |
| `revit_preview_purge_unused` / `revit_purge_unused` | ReadOnly / DestructiveRequiresManualApproval | Unused family types, families, and (opt-in) other unused elements |
| `revit_list_project_parameters` | ReadOnly | Project and shared parameter bindings: name, GUID, data type, group, instance/type, categories, varies by group |
| `revit_list_shared_parameters` | ReadOnly | Definitions in the company shared parameter file (groups, names, GUIDs, types) |
| `revit_preview_create_parameters` / `revit_create_parameters` | ReadOnly / RequiresApproval | Create project parameters (from the shared parameter file, or project-only) and bind them to categories |
| `revit_bind_parameter_categories` | RequiresApproval | Add or remove categories on an existing binding (`ReInsert`) |

## Why

Placement tools (`revit_place_*`, `revit_ensure_device_types`) assume the family is loaded; `DeviceCodeContext.FamilyExists` just reports "missing". Parameter QA (`company.parameter.qa`) reports missing parameters but nothing can add them. Both are routine, well-bounded Revit API operations, and both are prerequisites for the autonomy work (#99, #100): a job that starts with "load family X, create parameter Y" needs no human in the first five minutes.

## Design

### `revit_list_families`

`FilteredElementCollector(doc).OfClass(typeof(Family))`; per family: `Name`, `FamilyCategory.Name`, `IsInPlace`, `IsEditable`, `IsUserCreated`, `GetFamilySymbolIds().Count`, instance count via one `FilteredElementCollector.OfClass(typeof(FamilyInstance))` grouped by `Symbol.Family.Id` (one pass, cached for the call). System families (wall types, cable tray types…) are listed from `ElementType`s without a `Family` using `FamilyTypeSupport.KindOf`. Filters: `category`, `nameContains`, `kind`, `unusedOnly`; paged (`QueryGuard.NormalizePageSize`). Reuse `FamilyTypeSupport.CollectTypes` and `CountInstancesByType`.

### Load and reload

Arguments: `paths[]` (`.rfa`, validated by `FilePathPolicy.ValidateRead`; network paths need `AllowNetworkPaths`), or `folder` + `pattern`, max 50 files per call; `ifExists` = `skip` (default) | `overwriteParameters` | `overwriteAll`; `activateTypes` (default true, `FamilySymbol.Activate` on each symbol so placement works at once); `document`.

Implementation: `doc.LoadFamily(path, new FamilyLoadOptions(policy), out Family family)` with `FamilyLoadOptions : IFamilyLoadOptions` mapping the policy to `OnFamilyFound(familyInUse, out overwriteParameterValues)` and `OnSharedFamilyFound(..., out source, out overwriteParameterValues)` (shared nested families: `FamilySource.Family` unless `overwriteAll`). One `Transaction` "Revit MCP - Load Families", a `SubTransaction` per file so one bad file does not undo the others; failure text captured through `RollBackOnErrorPreprocessor`. Preview reads the `.rfa` title block cheaply: open as a family document is too slow for 50 files, so the preview only checks existence, extension, read policy, size and whether a family of the same name (file stem) is already loaded, and states which policy will apply. Result per file: `{path, family, status: loaded | skipped | overwritten | failed, types[], reason}`.

`revit_reload_family`: `family` (name or id), optional `path` (default: the family's last known path — Revit does not store it; keep a per-model map in `%LOCALAPPDATA%\RevitMCP\Families\<modelId>.json` written by `revit_load_family`; without a known path the tool asks for one). Same load options; result includes types added/removed and instance count.

### Purge unused

Preview collects: family symbols with zero instances (and not the only type of a family that is placed as a type, e.g. tag types used by tags), families whose every symbol is unused, and when `includeOther=true` other unused element types (line patterns, fill patterns, materials, text/dimension types) via `Document.GetUnusedElements(ISet<ElementId>)` where the target supports it — **check both Revit 2024 and 2026 builds**; where it does not compile, keep the instance-count method for types only and say so in the result. Never list: view templates, title blocks in use by sheets, types referenced by `revit_get_device_codes` map (company device map), element types whose family `IsInPlace`. Options: `categories[]`, `familyNameContains`, `passes` (1–3; Revit's own purge needs several passes because purging a type can orphan a nested family). Apply: one transaction, `doc.Delete(ids)` in batches of 500 with a `SubTransaction` per batch; approval summary "DESTRUCTIVE: purge N unused family types in M families (+ K other unused elements). Manual approval required." Result mirrors `DeleteElementsTool` (`deleted`, `removedAsDependent`, `failed[]`).

### Parameters

`revit_list_project_parameters`: iterate `doc.ParameterBindings` with `DefinitionBindingMapIterator`; per entry `{name, isShared, guid, dataType (SpecTypeId forge id + a readable label via LabelUtils.GetLabelForSpec), group (GroupTypeId + label), binding: instance|type, categories[], variesAcrossGroups}`. Filters `nameContains`, `category`, `sharedOnly`.

`revit_list_shared_parameters`: file from `sharedParameterFile` argument, else config key `parameters.sharedParameterFile` (project → user → company, same precedence as `GraphRoutingParameterConfig`), else `app.SharedParametersFilename`. Open with `app.OpenSharedParameterFile()` after setting `app.SharedParametersFilename` (restore the previous value in `finally`). Lists `DefinitionGroups` → `ExternalDefinition {name, guid, dataType, description, visible, userModifiable}`.

`revit_create_parameters` (preview + apply). Arguments: `parameters[]` of `{name, source: shared|project, guid? (shared: pick by GUID, else by name within group), group? (shared file group), dataType (`text`, `integer`, `number`, `length`, `area`, `yesNo`, `material`, or a SpecTypeId string), parameterGroup (GroupTypeId label such as `Data`, `Electrical`, `Identity Data`, `Text`), binding: instance|type, categories[] (names via `CategoryResolver`), variesAcrossGroups?, ifExists: skip|rebind}`, up to 50. Implementation: for `shared`, resolve the `ExternalDefinition` from the file (create it in the file only when `createInFileIfMissing=true` — the file is company property; default false → `validation_failed` naming the missing definition); for `project`, there is no API to create a non-shared project parameter in Revit 2024 and 2026 other than through a shared definition, so **`source=project` is implemented as a shared definition in a connector-owned group `RevitMCP` of a local scratch file** and the result says so plainly. `CategorySet` from `doc.Settings.Categories`, `InstanceBinding`/`TypeBinding`, `doc.ParameterBindings.Insert(definition, binding, groupTypeId)`; `ifExists=rebind` → `ReInsert` with the union of categories. One transaction, `SubTransaction` per parameter. Approval summary: "Create N project parameter(s) from the shared file '<file>': <name> (<type>, instance, 3 categories), …". Preview resolves everything and reports `willCreate | exists | missingDefinition | unknownCategory | invalidType`.

`revit_bind_parameter_categories`: `name` or `guid`, `addCategories[]`, `removeCategories[]`; `ReInsert` with the new set; refuses to remove the last category.

Pure logic (`RevitMCP.Addin/Parameters/`): `ParameterSpecMap` (friendly names → SpecTypeId/GroupTypeId strings and back, both targets use ForgeTypeId), `ParameterCreatePlanner` (validate requests, decide actions given current bindings and file definitions provided as DTOs), `FamilyLoadPolicy` (arguments → policy enum, file validation), `PurgePlanner` (given types with instance counts and protections, decide what to purge). All tested without Revit.

## Acceptance criteria

- Loading a family that is already loaded follows the chosen policy and the result says what happened per file; a bad file never undoes the good ones.
- Created parameters appear in Revit's Project Parameters with the right type, group, binding and categories; existing bindings are extended, never replaced, unless asked.
- The shared parameter file is never modified unless `createInFileIfMissing=true`, and `app.SharedParametersFilename` is restored after every call.
- Purge never lists protected types and needs manual approval; results match `DeleteElementsTool`'s shape.
- Unit tests green, both targets build, benchmark report committed.
