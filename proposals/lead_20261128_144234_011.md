## 3. Source-code audit — real code, not symbol counts

The main runtime directory is `miniandroid/`. Inspect the real implementation and call paths, including (discover exact paths from the tree):

- APK/ZIP parsing, manifest, resources.arsc, AXML, DEX/multidex;
- class loading, method/field resolution, interpreter and opcode semantics;
- DalvikValue types, unions, register widths, invoke argument marshalling, return propagation;
- object identity, heap, arrays, collections, class initialization, exceptions;
- Android Context, PackageManager, Resources, AssetManager;
- Activity/Service/Provider lifecycle, Intent, Handler/Looper, threads and scheduling;
- Window, DecorView, ViewTree, measure/layout, layout params and gravity;
- TextView, Typeface, StaticLayout, Unicode, bidi, font shaping/rasterization;
- Canvas, Paint, Bitmap, Drawable, clipping, transforms, alpha, invalidation;
- Surface, SurfaceView, EGL/GLES, JNI and native loading;
- Compose and WebView paths;
- input dispatch, hit testing, click/touch/gesture, state mutation and redraw;
- persistence, SQLite, files, SharedPreferences;
- diagnostics, first-divergence, screenshot provenance and authoritative-frame gates.

For each important path, trace:
`APK/source behavior → DEX/native call → bridge/dispatch → implementation → state mutation → render consumer → pixels/output`.

Look specifically for:
- fields written but never read by the consumer;
- getters that return stored values while behavior is not implemented;
- API methods that are registered but no-op;
- wrong DEX type checks or union member reads;
- silent default returns, swallowed exceptions, host fallbacks;
- duplicated or competing layout/measurement truths;
- dead/unreachable branches and stale comments;
- incomplete invalidation/frame pump;
- inconsistent object IDs between input and rendering;
- ABI/native paths incorrectly counted as ordinary failures;
- tests that exercise only helper/shadow code, not the actual consumer;
- tests whose type assumptions mask bridge defects;
- unchecked integer overflow, register-width, bounds, lifetime, or concurrency hazards.

Every reported code defect must include exact path + function/line (or stable symbol), a concise explanation, why it matters, evidence/test gap, affected app family, and a minimal next verification. Do not invent line numbers.
