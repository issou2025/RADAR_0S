*Project description:*
### Subsystem affected

ui/ — React + Vite board UI

### Problem or motivation

## Problem / Motivation

There is no native mobile app. The only way to manage agents on the go is
through the responsive web UI, which lacks push notifications, background
operation, and offline queuing. A third-party iOS app (pclip) exists but is
not official and has no Android counterpart.

### Proposed solution

## Proposed Solution

A native (or PWA) mobile app that allows:
- Viewing agent status and task queue
- Approving / rejecting agent decisions
- Receiving push notifications for escalations
- Monitoring costs and usage at a glance

### Alternatives considered

## Alternatives Considered

- **Web UI in mobile browser** — works, but no push notifications or background sync
- **PWA install** — better than raw browser, still limited by browser constraints
- **Termux self-host** — runs the server *on* the phone, not a client app

### Roadmap alignment

## Roadmap Alignment

ROADMAP.md lists a Desktop App as an unshipped milestone. A mobile app is a
natural next step for the same "control plane always close at hand" goal.   

### Additional context

## Examples from similar tools

- **n8n** (self-hosted workflow automation, closest analog): has 5+ third-party
  mobile apps (Nodera, n8n Hub, n8n Monitor, n8n Buddy, N8N Automations — Nathan)
  that connect to a self-hosted instance via API and provide:
  dashboard with active/failed workflow counts, execution history,
  trigger/activate/deactivate workflows, push alerts on failure.
  None are official — same gap Paperclip has today.

- **Linear** (issue tracking): ships a first-party mobile app (iOS + Android)
  for triage, status updates, and quick issue creation. Proves that
  "control plane on your phone" is a real need even for developer tools.

- **pclip** (iOS only): third-party app for Paperclip specifically.
  Confirms demand exists; no Android equivalent.

## Minimal viable scope (suggested)

A companion app (not a full editor) with:
1. **Dashboard** — agent list with status (idle / running / needs approval)
2. **Approvals** — tap to approve/reject pending decisions
3. **Notifications** — push alerts when an agent needs human input
4. **Cost glance** — current period spend per agent

This mirrors the n8n mobile app pattern: read-heavy, a few write actions,
no full workflow/agent editing on mobile.

## Suggested tech approach (for whoever picks it up)

- **React Native / Expo** or **Flutter** — matches the existing React/TypeScript stack
- Connects to the existing REST API; no new DB schema needed
- Push via FCM (Android) + APNs (iOS), with a small server-side
  notification-dispatch endpoint
- Could start as a PWA (service worker + manifest) to validate UX before
  committing to native
