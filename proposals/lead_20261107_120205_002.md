## High: these blocked the job

### 1. `FRAME_ELEMENTS_IN_CAMERA` is DRAFT, so no eye-level camera can be made
- **What happened:** `revit_change` refused it with *"It is proved first on a test model, with a negative case"*. The final image is therefore an isometric bird's-eye view, which is the main reason it looks flat.
- **Conflict:** the `visualise-a-view` method says each DRAFT rendering tool *"may be run once through try-once, behind Revit's Keep or Discard box (D-119)"*. No try-once route was offered or available from `revit_change`. Either the method text or the executor is wrong. Both are recorded here for the owner to decide.
- **Asked for:** prove the card (Groups IB/IC in NEEDS-CHECKING), or expose the try-once route the method describes.

### 2. No capability attaches walls to a roof
- **What happened:** raising the top roof by 450 mm (`wf-20261106-201523-0041-4312`) opened a visible gap above 8 walls that were not attached. Both *"attach wall tops to roof"* and *"attach walls top to roof or floor above"* resolved to `ATTACH_COLUMNS`, which handles columns only.
- **Workaround:** set Top Offset to 450 mm on the 8 walls that ran to Level 5-TOP (`wf-20261106-201732-0045-a5db`). Those walls now end at a fixed height and will not follow the roof if it moves again.
- **Asked for:** a wall attach/detach capability, or `ATTACH_COLUMNS` widened to walls with the same `where`, `offset` and `detach` inputs.

### 3. Words asking to read were ranked to capabilities that write
- **What happened:** through `revit_read`:
  - *"read parameter values of the elements"* ranked `SET_PARAMETER_VALUES_BY_ID` (MODIFY) first.
  - *"describe the selected roofs with their level, base offset, slope and thickness"* ranked `SET_FRAMING_JUSTIFICATION` (MODIFY) first.

  Nothing was sent, because `revit_read` refuses anything above ANALYZE. The right answer, `READ_ELEMENT_TABLE`, came second or not at all.
- **Asked for:** when the caller is `revit_read`, or `question=true`, filter MODIFY cards out before ranking.

## Medium

### 4. Two reads were too large to return
- `READ_ELEMENT_TABLE` on 53 walls × 6 parameters returned 59,018 characters, over the tool-result cap.
- `LIST_MATERIALS` with `namePattern=1.GRASS` and `withLibraryAppearances=true` returned 87,931 characters, because all 1,942 library appearance assets are listed whatever the pattern.
- **Asked for:** a compact table mode with values only, and a separate name filter for library appearances (for example `libraryPattern=Grass*`).

### 5. Name lists stop after three items
- `FIND_VIEWS`, `SELECT_TYPES` and `SELECT_VIEW_TEMPLATES` print `[a, b, c, ...]`. Only 3 of the 13 view-template names and 3 of the 18 deciduous tree types were visible.
- `REPORT_PARAMETER_INVENTORY` with `maxChars=12000` still cut `findings` to a few lines.
- `revit_views` gives counts but no view names.
- **Asked for:** print the full list up to about 100 items, or add a `names=full` switch, and make `maxChars` govern `findings` too.

### 6. Views that share a name are refused
- Plan names are unique only within a view type: `Level 3-FF` exists as a floor plan, a ceiling plan and a structural plan. `APPLY_VIEW_TEMPLATE` could template only 1 of 23 views (`wf-20261106-200816-0011-6af2`).
- **Asked for:** accept `ViewType: Name` (for example `CeilingPlan: Level 3-FF`), the form `revit_view_image` already accepts.

### 7. `APPLY_VISUAL_PRESET` and `REPORT_VISUAL_PRESET` print false lines
- Every run on the 3D view `Exterior - Day` printed *"noRender: 'Exterior - Day' is not a 3D view"* and *"noDisplay: … has no Graphic Display Options"*. The same answer showed `view3D View3D` and read back Render Quality High and 300 DPI (`wf-20261106-202742-0081-0f98`).
- **Asked for:** print `noRender` and `noDisplay` only when they are true.

### 8. `APPLY_VISUAL_PRESET renderFor=issue` silently reset a value set on purpose
- Sun Intensity had been set to 60 with `SET_GRAPHIC_DISPLAY_OPTIONS` (`wf-20261106-200942-0019-834c`). Re-running the preset to raise render quality put it back to 80. The answer did not say it had overwritten a value the modeller had chosen.
- **Asked for:** a way to change render quality and output only, or a line naming each setting moved away from a non-default value.

### 9. `SET_COMPOUND_LAYER_WIDTH` demands optional inputs and refuses `keep`
- Leaving out `material` and `layerFunction` was refused.
- Passing `keep` was refused: *"'keep' is not a layer function … blank leaves the function as it is"*. Only blank worked (`wf-20261106-201427-0037-c8a2`).
- The `checkOnly=true` run (`wf-20261106-201422-0036-573f`) said the fragment *"was KEPT"*, which reads as if something was written.
- **Asked for:** default both inputs to blank, accept `keep` as a synonym, and word check-only results as "checked, nothing written".

## Low
- **`SET_PROJECT_INFORMATION` is DRAFT,** so *"set Project Name to Villa 1"* was refused. It is a common, low-risk request, worth proving early.
- **Inconsistent input name:** `OPEN_VIEW` takes `viewName`, while `APPLY_VIEW_TEMPLATE`, `APPLY_VISUAL_PRESET` and `SET_CATEGORY_VISIBILITY` take `view`.
- **Narrow selection:** `revit_select_by_category` understands only ducts and pipes.
- **`revit_health`:** it listed the session as `(free)` without naming the open model. It also warned that `write.enabled` is TRUE on this PC, which is the owner's decision under D-19 and is noted only.
- **Sky background:** it was set and read back, but `revit_view_image` and `EXPORT_VIEW_IMAGE` both came out with a flat grey background. Worth checking.
- **`REPLACE_MATERIAL`:** it ranked first for *"change roof material"* but needs resolved Material objects, not names, so `SET_MATERIAL_APPEARANCE` was used instead.
