# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**docs(sdk): explain how to get a CLI session outside the app**

*Project description:*
### Context
A program outside the app can call session-bound SDK methods (for example `sdk.getHire(id, wallet)`) only with a CLI session (#259), opened with `CliSession.open` and a refresh token. Nothing in the docs explains how to get that token without the app. While running the SDK from a project outside the repository (#301), the only way was to reproduce the app's side by hand: request a wallet-auth challenge, sign it with an ephemeral key, verify it, and call `cliSession.create`.

Two details made it harder:
- The server's challenge already carries the server's signature, so the client must append its own signature to the existing list instead of replacing it.
- `stellar_flutter_sdk` cannot be used from a pure Dart program because it pulls in Flutter; `stellar_dart` works.

### Deliverables
1. A page or section under `docs/sdk/` that explains how a developer gets a CLI session outside the app: the supported path (the app's "CLI sessions" action, the CLI, or both) and, for automated tests, the wallet-auth flow with the signing package that works in pure Dart.
2. A link to it from `docs/sdk/quickstart.md` at the point where a session is first needed.

### Acceptance criteria
- [ ] Following only the docs, a project outside the repository obtains a session and calls a session-bound method against the local server.
- [ ] The docs state which signing package works in pure Dart and which does not.
- [ ] No secret, token or private key appears in the examples.

### How to verify
1. Start the local sandbox and server following `docs/testing/local-environment.md`.
2. In a new project outside the repository, follow the new page to get a session and call `sdk.getHire`.

### Out of scope
- New server endpoints or changes to the session model (#259).
- Rewriting the quickstart (covered by a separate issue).

### Depends on
None.
