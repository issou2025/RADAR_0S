# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Selector syntax: remaining IfcOpenShell constructs and the CLI/MCP/SDK adapters (follow-up to #4091)**

*Project description:*
Follow-up to #4091, which adds `parseSelector` in `@ifc-lite/query` plus one adapter onto the viewer's Filter tab. The parser accepts the whole IfcOpenShell filter grammar; the viewer adapter does not yet evaluate all of it, and reports each construct it cannot handle by name rather than dropping it silently.

Left for this issue:

**Viewer rule kinds that do not exist yet**
- GlobalId terms, both adding and subtracting (`325Q7Fhnf67OZC$$r43uzK`, `! 325Q7...`). Needs a `globalId` FilterRule kind, evaluator and editor row.
- `type=WT01`, matching the relating type's Name through IfcRelDefinesByType.
- Attributes other than `Name` and `PredefinedType` (`Description`, `ObjectType`, `Tag`, ...). Needs a generic `attribute` rule kind.
- `parent=Foo` (direct or indirect child of a named element), and `query:` value-query keys.
- Material `Category` — #4091 matches material and layer names only, IfcOpenShell matches Name **or** Category.

**Group unions**
- `+` unions two filter groups (`IfcSlab, material=concrete + IfcDoor`). The viewer's filter state carries a single top-level AND/OR combinator, so this needs either OR-of-ANDs in `FilterState` or running each group separately and unioning the resulting id sets.

**Other surfaces**
The point of putting the parser in `@ifc-lite/query` is that these adapt the same AST rather than growing a second grammar:
- `ifc-lite query --select "<selector>"` in the CLI, alongside the existing single-clause `--where`.
- `selector` parameter on the MCP `query_entities` tool.
- `bim.query().select()` in the SDK and sandbox.

All three need `matches` (regex) in `FilterComparisonOp` and the query backend before selector text can be honoured end to end, plus GlobalId and union support to avoid accepting text the backend then silently narrows.

**Also worth settling here:** whether `location=` should reach through spaces to the containing storey. IfcOpenShell's example 17 expects a pump inside a space on Level 3 to match `location="Level 3"`. #4091 pins whatever the current storey walk actually does in a test and documents it; if that turns out to be storey-name-only, widening it belongs here.
