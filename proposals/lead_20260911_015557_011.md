## Implementation steps
**Decision: region `europe-west1` (Belgium) for every regional resource.** Firestore's location can never be changed, so it has to be a region where every later service is fully available. Vertex AI Gemini (later sprint), Cloud Run, Cloud Scheduler and Artifact Registry are all GA in `europe-west1` with the full model catalog. `me-west1` has a narrower Vertex model list and Tier-2 (higher) pricing, which matters under a ₪100 budget. About 60 ms RTT from Israel is fine for this API, and Israeli privacy regulations allow transfer to EU member states. Firestore is regional `europe-west1`, which is cheaper than multi-region `eur3`; point-in-time recovery (PITR) covers recovery.

1. **Owner-action (an agent must not do this):** `brew install --cask google-cloud-sdk`; `gcloud auth login`; `gcloud auth application-default login`; `gcloud config set project maybesitter-app`; `firebase login`. Never paste tokens into chat, files or issues.
2. Create `infra/bootstrap.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`). Make it idempotent: guard every create with `… describe … >/dev/null 2>&1 ||`. Inputs come from env: `PROJECT_ID` (default `maybesitter-app`), `REGION` (default `europe-west1`), `GITHUB_REPOSITORY` (required, `owner/repo`). Steps:
   a. `gcloud services enable firebase.googleapis.com firestore.googleapis.com run.googleapis.com artifactregistry.googleapis.com cloudbuild.googleapis.com secretmanager.googleapis.com cloudscheduler.googleapis.com fcm.googleapis.com identitytoolkit.googleapis.com aiplatform.googleapis.com iam.googleapis.com iamcredentials.googleapis.com sts.googleapis.com firebaserules.googleapis.com`.
   b. `firebase projects:addfirebase "$PROJECT_ID"`. Skip if it is already a Firebase project.
   c. `gcloud firestore databases create --database='(default)' --location="$REGION" --type=firestore-native --delete-protection`, then `gcloud firestore databases update --database='(default)' --enable-pitr`.
   d. `gcloud artifacts repositories create maybesitter --repository-format=docker --location="$REGION"`, plus cleanup policy `infra/artifact-cleanup.json` that keeps the 10 most recent versions.
   e. Service accounts. Grant roles exactly as listed, nothing else:
      | SA | Purpose | Roles |
      |---|---|---|
      | `maybesitter-run` | Cloud Run runtime | `roles/datastore.user`, `roles/firebaseauth.admin` (verify/revoke/delete users, needed by UC-1.5 (#149)), `roles/secretmanager.secretAccessor` **on secret `maybesitter-deletion-receipt-pepper` only** |
      | `maybesitter-deployer` | GitHub Actions via WIF | `roles/run.developer`, `roles/artifactregistry.writer` (on repo `maybesitter` only), `roles/iam.serviceAccountUser` (on `maybesitter-run` only), `roles/firebaserules.admin`, `roles/datastore.indexAdmin` |
      | `maybesitter-scheduler` | Identity Cloud Scheduler signs OIDC tokens as | none at project level (the app checks its email; see UC-1.0d (#143)) |
      FCM-send and Vertex roles are added by the sprints that need them, not here.
   f. Secret container with no value: `gcloud secrets create maybesitter-deletion-receipt-pepper --replication-policy=user-managed --locations="$REGION"`. The owner adds the value without echoing it: `openssl rand -hex 32 | gcloud secrets versions add maybesitter-deletion-receipt-pepper --data-file=-`.
   g. Workload Identity Federation: pool `github`, OIDC provider `github-actions` (issuer `https://token.actions.githubusercontent.com`; mapping `google.subject=assertion.sub,attribute.repository=assertion.repository,attribute.ref=assertion.ref`; condition `assertion.repository=='${GITHUB_REPOSITORY}' && assertion.ref=='refs/heads/main'`). Bind `roles/iam.workloadIdentityUser` on `maybesitter-deployer` to `principalSet://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/github/attribute.repository/${GITHUB_REPOSITORY}`. Resolve `PROJECT_NUMBER` at runtime and never commit it. Print the provider resource name; the owner stores it as GitHub repo **variable** `GCP_WIF_PROVIDER`, and stores the SA email as `GCP_DEPLOYER_SA`. **Never create a JSON key.**
   h. Register Firebase apps: `firebase apps:create IOS "MaybeSitter iOS" --bundle-id com.maybesitter.app` and `firebase apps:create ANDROID "MaybeSitter Android" --package-name com.maybesitter.app`. UC-1.7 (#151) downloads `GoogleService-Info.plist` and `google-services.json` into `mobile-rn/firebase/`; this issue does not commit them.
3. **Owner-action, Firebase console → Authentication → Sign-in method:** enable Email/Password, Google and Apple. Apple needs a Services ID and key from the Apple Developer account; the `.p8` never enters the repo. Then restrict the auto-created API keys to the iOS bundle and Android package (GCP console → Credentials).
4. Commit:
   - `firebase.json`, with `firestore` in the multi-database **array form** from the start: `{"firestore":[{"database":"(default)","rules":"firestore.rules","indexes":"firestore.indexes.json"}],"emulators":{"auth":{"port":9099},"firestore":{"port":8080},"ui":{"enabled":false}}}`. UC-1.0d (#143) creates the named `staging` database and appends `{"database":"staging","rules":"firestore.rules","indexes":"firestore.indexes.json"}`, so both databases share one rules file and one index file.
   - `.firebaserc`: `{"projects":{"default":"maybesitter-app"}}`.
   - `firestore.rules`: deny-all baseline (`match /{document=**} { allow read, write: if false; }`). UC-1.0b (#141) replaces it.
   - `firestore.indexes.json`: `{"indexes":[],"fieldOverrides":[]}`.

   Deploy once with `firebase deploy --only firestore:rules,firestore:indexes`.
5. Create `infra/verify.sh`. It exits non-zero unless all of these hold: every API from 2a is enabled; `(default)` is in `europe-west1`, Native mode, with PITR and delete protection on; the three SAs exist; each SA has **zero** user-managed keys; the WIF provider exists with the exact condition; the secret exists.
6. Write `docs/operations/GCP_BOOTSTRAP.md`: prerequisites, the owner-actions, running both scripts, the region decision, the SA/role table, and pepper rotation. It must contain no personal emails, billing account IDs, project numbers or secret values.
7. Budget: keep the existing alert-only budget. The owner confirms thresholds at 50/90/100% in the console. Nothing billing-related goes in the repo.
