# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Find apps running in an Android emulator automatically**

*Project description:*
Apps running in an Android emulator on your computer do not show up automatically in the xRay desktop app. iOS simulators and desktop builds on the same computer are found without any setup, so Android developers who test on an emulator have to work around this by hand.

## Background

xRay has two sides: the **SDK**, which you add to your Flutter or Dart app, and the **desktop app**, which shows what is happening inside that app.

**Discovery** is how the desktop app finds apps running the SDK without you typing an address. Besides scanning the local network, the desktop app also checks the computer it runs on, which is how iOS simulators and desktop builds are found. An Android emulator, however, runs behind its own virtual network: the app inside it is not reachable on the computer's own address unless you forward the port yourself.

## User story

As a Flutter developer testing on an Android emulator, I want the xRay desktop app to find my app automatically, so that I don't have to look up addresses or run extra commands before I can start inspecting.

## Current behaviour

An app running the SDK in an Android emulator on the same computer as the desktop app does not appear in the discovery list.

## Expected behaviour

1. Start an Android emulator on the computer that runs the xRay desktop app.
2. Run an app with the SDK on that emulator.
3. Open *Add connection* in the desktop app: the app appears in the discovery list with the emulator's device name and the app name, like an iOS simulator does.
4. Click it to connect.

No extra setup (port forwarding, commands, settings) is needed for this to work.

## Acceptance criteria

- [ ] An app running the SDK in an Android emulator on the same computer appears in the discovery list after a single scan, with no extra setup.
- [ ] The entry shows the emulator's device name and the app name, and clicking it connects.
- [ ] With several emulators running, each app appears as its own entry.
- [ ] Discovery of real devices, iOS simulators and desktop apps keeps working as before.

## Out of scope

- Android emulators running on a different computer than the desktop app.
- Real Android devices not showing up in discovery (#7).
- Slow manual connections to Android devices (#17).

## Edge cases

- Emulator started after the scan finished → the app appears after pressing refresh.
- No emulator running, or no Android tooling installed on the computer → discovery works as before, without errors or delays.
- Emulator and real Android/iOS devices at the same time → all appear in the same list.

## Workaround

Forward the port from the emulator to your computer with `adb forward tcp:7780 tcp:7780`, after which the desktop app finds the app like a local desktop build. Alternatively, connect manually using the emulator's address.
