## Context

(`GET /repos/emil3663/test-assist/releases/latest`) and `gh release list`,

`python/main.py`'s `__version__` has read `"1.5.0"` on `main` since the
`ui-polish` merge landed (per `docs/HANDOVER_TO_CLAUDE_CODE_2026-09-16.md`'s

the stability-matrix refresh) - all of it sitting on a version string that
has never actually shipped.

This surfaced while trialling `sre-release`/`sre-toil` against TA-250: it's
exactly the scenario a rollback marker is meant to help with, except there
isn't even a `v1.5.0` release yet to roll back *from*.

## Change
One of two, not both - this needs a decision, not an assumption:

1. **Cut the release deliberately:** `git tag v1.5.0 <commit> && git push
   origin v1.5.0`, let `release.yml` build/verify/publish per its existing
   pipeline (already confirmed working correctly by `verified-release-pipeline`
   and untouched by this investigation).
2. **Document an intentional hold:** if there's a reason 1.5.0 specifically
   isn't ready to ship yet (unfinished manual verification, a known issue
   being held for a fix first, etc.), record that reason explicitly
   somewhere durable (this issue, or `TESTASSIST_BACKLOG.md`) rather than
   leaving the gap unexplained.

## Acceptance
- Either a `v1.5.0` tag exists and `release.yml` has run successfully
  against it (`gh release list` shows it), or this issue records the
  specific, named reason it's deliberately being held, not left silent.
- `python/main.py`'s `__version__` and the latest published release agree,
  or the disagreement is explicitly explained.

## Not in this issue
- **The actual decision of which path to take is deliberately left open
  here rather than acted on unilaterally.** Publishing a real release is a
  hard-to-reverse, externally-visible action - it produces a downloadable
  artifact for this tool's real corporate-machine users - and nothing in
  this investigation established which path Emil actually wants. Flagged
  back explicitly in this session's report rather than assumed.
- No change to any of the work that would ship in 1.5.0 - this issue is
  about the missing release step itself, not the release's contents.
