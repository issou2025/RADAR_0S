### What happened?

Internet radio playback to Chromecast players intermittently stalls a short way into a stream — audio stops and the player is left showing "playing" but never progresses, with the UI implying it's stuck buffering/reconnecting. It usually takes a manual stop/restart to recover. This happens across most of my Chromecast speakers and multiple different radio stations (not one specific station).

I was able to reproduce a stall with a plain ICY/MP3 station (Classic FM, `http://media-ice.musicradio.com/ClassicFMMP3`) on a Chromecast player: the debug log shows the ICY reader start, then goes completely silent — no further stream activity, no reconnect attempt, no error — for about 100 seconds, while Home Assistant's `media_player` entity stays in `playing` state with `media_position` frozen at 0 the entire time. Playback eventually resumed on its own right as I stopped it manually.

For comparison, a Chromecast stream via the BBC Sounds provider (HLS-based, different code path) played continuously for 2+ minutes with no issue in the same session — so this looks specific to the plain ICY/MP3 radio path rather than Chromecast output in general.

Looking at `music_assistant/controllers/streams/audio.py`, `get_icy_radio_stream()` uses `ClientTimeout(total=0, connect=30, sock_read=5*60)`. A stalled-but-still-open connection (socket stays open, server stops sending bytes) would only surface after the 5-minute `sock_read` timeout, and even then the reconnect handler's except clause only catches `IncompleteReadError` / `ClientConnectionError` / `ClientPayloadError` / `ServerDisconnectedError` — a plain timeout from that `sock_read` cap doesn't appear to be one of them. That would explain a stall with no visible error and no reconnect log line. The known ICY reliability fixes (#4422, #4421) are already present in my version (2.9.10) — this looks like a different, silent-stall case rather than a clean disconnect.

### How to reproduce

1. On a Chromecast-connected player, play a plain ICY/MP3 internet radio station from the Music Assistant library (reproduced with Classic FM: `http://media-ice.musicradio.com/ClassicFMMP3`).
2. Watch the player state / server debug log.
3. Intermittently, the stream stalls shortly after starting: the log goes silent for the ICY reader (no reconnect line, no error), and the player entity stays "playing" with position frozen, for anywhere from ~10s up to (in one captured case) ~100s, before either recovering on its own or requiring a manual stop/restart.
