# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**feat: iOS AutoFill Credential Provider extension for the vault**

*Project description:*
Part of #3592. Needs #3594, #3595, #3596 and #3597.

Add an AutoFill Credential Provider extension to the iOS app so Quark can fill passwords into Safari and other apps.

## Scope

- A new app extension target (`com.apple.product-type.app-extension`) beside `Runner` in `ios/Runner.xcodeproj/project.pbxproj` (today only `Runner` and `RunnerTests`, `:178-219`), with:
  - a bundle id under `org.autobutler.quark` (for example `org.autobutler.quark.CredentialProvider`) and iOS 15.0 or the floor the design chose;
  - entitlements: `com.apple.developer.authentication-services.autofill-credential-provider`, the app group, and the Keychain access group, on both the extension and `Runner`.
- `ASCredentialProviderViewController` subclass:
  - `prepareCredentialList(for:)`: list items whose host matches the service identifiers (domain or URL), using the matching from #3597, after biometric unlock;
  - `provideCredentialWithoutUserInteraction(for:)`: fill directly when the cached key is usable without UI, otherwise cancel with `userInteractionRequired`;
  - `prepareInterfaceToProvideCredential(for:)`: the biometric unlock UI;
  - locked with no usable cache, or no match: show a short message and a button that opens the Quark app. The app registers no URL scheme today (`ios/Runner/Info.plist` has no `CFBundleURLTypes`), so add one or a universal link. Fill nothing.
- Read the ciphertext cache and connection info from the app group; never call the server with a password.
- Respect the extension memory limit: decrypt only what is needed, no Flutter engine unless the design chose one.
- In-app settings: a vault setting that explains how to turn Quark on. The path is Settings › General › AutoFill & Passwords on iOS 18 and later, and Settings › Passwords › Password Options on iOS 17 and earlier.
- Signing: CI signs with one manually managed App Store profile (`scripts/ios-ci-signing.bash:54`, `:86`). The extension needs its own App ID and profile with the new entitlements, so the script, the `IOS_*` secrets, `docs/ios-release.md`, and `ios/ExportOptions.plist` need a second profile.

## Acceptance criteria

- [ ] With Quark enabled and the cache unlocked by Face ID or Touch ID, a login field in Safari and in another app offers matching entries, and choosing one fills username and password.
- [ ] Locked with no cache, or no match: nothing is filled and the extension offers to open Quark.
- [ ] Peak memory of the extension during a fill, measured in Instruments with a vault of at least 1,000 items, is recorded in the PR and stays under the limit.
- [ ] `make build/frontend/ios/ipa` and the CI `build-ios` job sign and build both targets.
