*Project description:*
## Goal

Pusingcuk is the foundation of one integrated digital ecosystem—not an isolated language demo and not four unrelated repositories. The first real-world software pilot is the Kawasan Masjid 1.000 Ha ecosystem, while its physical realization remains a long-term vision and must not be presented as guaranteed.

We are looking for collaborators who want to help evolve Pusingcuk itself and prove it in a working system.

## Current baseline (be precise)

- The repository has a C11 native interpreter/runtime and tests for a supported subset.
- A Python reference implementation/test suite still exists.
- Full language parity, production deployment inside CORE, browser/WASM support, and an Android release are not yet established.
- Contributions should improve working code, tests, reproducibility, and integration—not just add roadmap documents.

## First milestone: one end-to-end proof

1. Document the language subset and native runtime contract.
2. Add or improve conformance tests that can run against the native runtime.
3. Choose one deterministic, pure business rule for the CORE pilot.
4. Run that rule with a pinned Pusingcuk revision in CI; verify expected output and failure behavior.
5. Keep side effects (database, network, filesystem, secrets) behind explicit, testable host boundaries.
6. Record the exact commands, versions, test results, limitations, and next gaps.

This first milestone is an integration proof, not a claim that the whole ecosystem already runs on Pusingcuk.

## Who can help

- **Language/runtime:** C11, interpreters, lexers/parsers, memory safety, runtime diagnostics.
- **Compiler/tooling:** conformance tests, build systems, CI, packaging, reproducible releases.
- **Full-stack integration:** TypeScript/React, API design, Supabase/Postgres, authorization, test automation.
- **Developer experience:** examples, docs tied to executable tests, beginner-friendly setup and issue triage.

A contributor does not need to be an expert in every area. Small, reviewable, evidence-backed contributions are welcome.

## Working principles

- Native-first direction; Python may remain a temporary reference/testing tool until parity is demonstrated.
- No untrusted script gets ambient access to secrets, network, filesystem, or database.
- No claims of partnerships, funding, permits, land ownership, or physical implementation without evidence.
- Keep changes focused, tested, and compatible with the existing repository state.
- Before proposing a broad rewrite, identify the smallest failing test or missing capability that proves the need.
