## Summary

A stock `flutter create` app built with `flutter-webos build webos` installs successfully on a retail
webOS 26 TV and appears as a launch point, but never renders. On launch, SAM logs `NL_APP_LAUNCH_BEGIN`,
the app process exists for well under 0.3 s, and the surface manager **never emits an `NL_VSC` event for
the app**. The Home screen takes over ~2 s later. This reproduces in `--debug`, `--profile` and
`--release`.

In `--debug` the Dart VM service does start (so the engine initialises and Dart runs) and then the process
exits — which places the failure at window/surface creation rather than in Dart code. The same app runs
correctly with `-d linux`.

## Reproduction

```bash

flutter-webos build webos --release

# -> Success ; app appears on the home screen
```

`flutter-webos run -d myTv --debug` behaves the same (see "Secondary issue" for why the debug IPK often
cannot be installed on this model).

## Observed behaviour

`/var/log/messages` on each launch:

```
SAM NL_APP_LAUNCH_BEGIN {"app_id":"com.flutter.app.helloworld","caller_id":"com.webos.lunasendpub-…","mode":"normal"}
LSM NL_VSC {"app_id":"com.webos.app.screensaver","visible":false,"window_type":"_WEBOS_WINDOW_TYPE_SCREENSAVER"}
tvpowerd NL_POWER_STATE {"old":"Screen Saver","new":"Active"}
```

- No `NL_VSC` event is ever emitted for `com.flutter.app.helloworld`.
- No jail mount units for the app appear in the log on launch.
- Polling `ps` at 0.3 s intervals catches the process in a single sample, then it is gone.

**Debug (JIT)** — `<bundle>/appdata/log/com.flutter.app.helloworld` receives exactly one line per launch,
with a fresh port each time, then the process exits:

```
flutter: The Dart VM service is listening on http://127.0.0.1:40377/7CBqB1MVFnY=/
```

**Release / profile (AOT)** — the log file is never created at all.

So the engine initialises and Dart starts under JIT, and the process then dies without any error being
written to the app log.

## Ruled out

- **Shared libraries** — every `NEEDED` entry of `helloworld`, `libflutter_webos_media.so` and
  `libflutter_engine.so` is present on the TV (`libwayland-webos-client.so.1`, `libEGL.so.1`,
  `libluna-service2.so.3`, `libwebosi18n.so.1`, `libfontconfig.so.1`, `libPmLogLib.so.3`, …).
- **Architecture / ABI** — binary and `libapp.so` are ELF32 ARM, `Version5 EABI, soft-float`, matching the
  TV's `/lib/ld-linux.so.3`. `RUNPATH` is `$ORIGIN:$ORIGIN/lib:.`.
- **AOT snapshot** — `libapp.so` exports `_kDartVmSnapshotData`, `_kDartIsolateSnapshotData`,
  `_kDartVmSnapshotInstructions`, `_kDartIsolateSnapshotInstructions`, `_kDartSnapshotBuildId`.
- **Packaging** — `data/flutter_assets/**` + `data/icudtl.dat` + `lib/*.so` present and correct for each mode.
- **Executing outside the jail** — running `./helloworld` over SSH loads all libraries and reaches engine
  init (fails later only for lack of a Wayland display, as expected).
- **Dev mode / ACGs / disk space / memory** — session valid, `requiredACG` as injected by the build,
  release build installs with headroom, no OOM or memory-manager kill logged.
- **`"nativeLifeCycleInterfaceVersion": 2`** in `appinfo.json` (the runner defaults it to `1`, while LG's
  own system Flutter apps use `2`) — no change.
- **Impeller** via `"engine-switches": {"enable-impeller": true}` in `flutter-conf.json` — no change.
- **Firmware update** — TV reports it is already up to date.

## Questions

1. Is **webOS TV Lite** a supported target for Flutter for webOS? The guide states "webOS TV starting from
   webOS 26 Re:New"; this TV is webOS 26 (`W26N`) but the `webOS TV Lite` variant.
2. Is NDK starfish **11.2.0** expected to produce apps that run on **11.0.1** retail firmware? If a
   matching NDK is required, is one available? Only 11.2.0 is published in
   `lg-flutter-webos/ndk/releases`.
3. **How can the runner's own log be read on a retail dev-mode TV?** `runner_base/logger.h` logs to PmLog
   context `flutter` / msgid `runner`, but no `runner` lines reach `/var/log/messages` or
   `/var/log/legacy-log`, `pmlogctl` is not present for the `prisoner` user, and `ares-log` / `ares-shell`
   are unsupported on the `tv` profile. Without this, `FlutterWindow OnCreate failed` and the surrounding
   `LOG_INFO`/`LOG_ERROR` output is invisible, which makes this class of failure very hard to diagnose.

## Secondary issue: debug IPK cannot be installed on 8 GB models

On this TV `/media/developer` (`/dev/mmcblk0p60`) is 984 MB total with ~150 MB free, so installing the
debug IPK fails:

```
ares-install ERR! [com.webos.appInstallService failure]: luna-send command failed <There is no available space to install App>
```

The debug payload is ~176 MB unpacked (`libflutter_engine.so` alone is 86 MB, `libflutter_webos_media.so`
28 MB — both unstripped). Note `flutter-webos run` uninstalls the existing app *before* the install
attempt, so a failed run leaves no app on the device.

Stripping with the NDK's `llvm-strip --strip-debug` reduces the payload to ~102 MB (37 MB IPK), which
installs and still provides Dart-level logging:

| file | before | after |
|---|---|---|
| `libflutter_engine.so` | 82 MB | 37 MB |
| `libflutter_webos_media.so` | 26 MB | 2 MB |

Would it be possible to ship stripped engine libraries (or offer a `--strip` / split-debug option) so debug
builds fit on entry-level models?
