*Project description:*
## Scope of THIS issue

Harvest the IFC 4.3 schema (the open standard Revit reads and writes; schema `ifc`, fidelity `proxy`) into `catalogue/ifc/*.yaml`: entities, their inheritance, attributes, enumerations, and the alignment, road, terrain and spatial-structure parts.

Source: the buildingSMART IFC4.3 EXPRESS schema. **Read its licence first.** If it forbids derived works, do not commit generated catalogue files: commit only the harvest script, SOURCES.md and a note, and report. Prefer a reproducible EXPRESS parser in `tools/harvest/ifc/`.

Part of the catalogue pipeline: describe every entity once in a neutral YAML format, then GENERATE tables, Rust
types, diagrams and seed rows from it (founder direction, 2026-10-23: entity tables first, faithful per source,
no apps installed so only public, machine-readable sources). The format contract is `catalogue/FORMAT.md`
(landing with the foundation issue); schemas are named after the real SOURCE format.

## Reuse check

**Which existing concepts does this use?** The phase 1 history-table pattern and `core` spine (issue #29, merged), the `acad` pilot tables, and the manifesto's rule that data is authoritative and never derived.

**What new concept does it need, and why is it genuinely necessary?** A neutral catalogue description per entity, because hand-writing thousands of tables and types across five applications cannot be finished or kept consistent. The catalogue is the single source; everything else is generated.
