**Proposal: versioned GitHub releases + `foam3` CLI, submodule becomes optional**

*Project description:*
## Problem

foam3 has no releases, so everyone using it has to submodule it and build the scaffolding around it by hand.

To start a foam project today you:

- add foam3 as a submodule
- write a `build.sh` that shells into `foam3/tools/build.js`
- write `pom.js` by hand, copied from an existing project
- `sudo chown /opt` and create `/opt/<app>`, because the server writes journals and logs there
- run `./build.sh`

Simple for someone who knows foam, hard for a beginner.

To get a new version of foam you peg the submodule to a new commit, and you have no changelog.

To fix a foam bug or improve foam you check out a branch inside the submodule and do the change there.

## Proposal

Same model as the Flutter SDK:

- GitHub Releases own the version
- each release is the repo checked out at the tag, `.git` included, so people can still contribute from it
- a `foam3` CLI ships inside it
- install once per machine, add `bin/` to `PATH`

Start a project:

```
brew install foam3            # or: installer script (curl | sh), or unzip the release and add bin/ to PATH
foam3 create my_app && cd my_app
foam3
```

`foam3 create` writes:

- `pom.js` with the framework version pinned
- a hello-world model and menu
- `.gitignore`
- runtime dir (journals, logs, config) set to `./build/runtime/` instead of `/opt/<app>`, changeable in `pom.js`

Build: `foam3` takes every flag `build.js` takes today. `./build.sh -cj` becomes `foam3 -cj`.

Upgrade:

```
foam3 upgrade            # latest release
foam3 upgrade v3.40.0    # fetch that tag, check it out, update the pin in pom.js
foam3 checkout <sha>     # a live-tree commit instead of a release, for trying an unreleased fix
```

`pom.js` pins the framework version. `foam3` builds with that version and `foam3 upgrade` bumps it, so every machine on the project runs the same framework.

## Downside

One install per machine, so two projects on different versions or with local patches conflict.

Those projects keep the submodule, same as today.
