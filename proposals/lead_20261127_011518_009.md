# Upgrade Rust toolchain to latest stable: 1.99 → 1.100 (MSRV, builder image, CI pin, docs)

## Summary

Move the whole backend build onto the latest stable Rust release, **1.100.0**
(released 2026-11-12). Today the workspace declares MSRV `1.99`, the Docker builder
image is `rust:1.99-bookworm`, and the CI `msrv` job pins `1.99.0`. Most other CI jobs
already follow the floating `stable` alias and therefore run 1.100 today — this change
is about making the **declared floor, the production builder image, and the pinned
MSRV verification** deterministic and consistent with what CI actually compiles with.

This issue is written to be self-contained and explicit: it is intended for an
implementing agent and leaves no open design decisions.

## Decision (already made — do not re-litigate)

**Bump the MSRV floor to 1.100 together with the builder image**, i.e. the repo keeps
its documented invariant that the workspace `rust-version` matches the Dockerfile
builder image (`backend/Cargo.toml` comment states this explicitly).

- Per **ADR-020 D2** an MSRV bump is a **MAJOR change per crate**. No crate is
  published to crates.io and no deployment target exists yet, so this is bookkeeping
  only: record it under `[Unreleased]` in `backend/CHANGELOG.md` and follow the
  **ADR-020 D3 lockstep rule** (single coordinated workspace change, `core → infra → api`).
  Do **not** cut a release / image tag for this.
- Alternative "keep floor at 1.99, only move the builder image" was rejected: it breaks
  the documented floor-matches-builder invariant and the CI `msrv` job would then test
  a floor nothing actually builds with.

## Validation (all must pass before review)

1. `rustup update stable` (≥ 1.100.0), `cargo clean` optional.
2. `cargo fmt --check` — run `cargo fmt` if needed.
3. `cargo clippy --workspace --all-targets` — a new compiler minor can add/promote
   lints. **Rust 1.100 specifically stabilized the never type (`!`)**, which changes
   never-type fallback for editions 2015/2018/2021 (this workspace is edition 2024, so
   low risk, but) and cargo can now warn about **unused dependencies**: treat every new
   warning as a real finding — fix it, or remove the unused dependency; do **not** add
   blanket `#![allow(...)]` or `[lints] ignore` entries.

## Guardrails (hard rules from AGENTS.md — violations mean rewrite)

- No panics introduced (`unwrap`/`expect`/`panic!`/`todo!`) — clippy `deny` lints.
- No `#[allow]` additions to silence the new compiler/cargo warnings — fix the cause.
- No dependency upgrades in the same PR (lockstep rule: one concern per PR). Only
  `Cargo.lock` churn that results *mechanically* from nothing else should be absent —
  a pure toolchain bump should not change `Cargo.lock` at all; if it does, explain why.
- No edits under `openspec/changes/archive/` or generated/frozen trees.
- Do not touch `frontend-flutter/`, the fuzz/nightly jobs, or the vendored `kameo_es`
  patch sources.
