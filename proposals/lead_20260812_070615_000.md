# Project Proposal — Pdf To Revit

## Project Understanding
You need assistance with: 
**[Bug]: beta.1 YAML frontmatter parser regression — workspace skills with colons in field values silently dropped**

*Project description:*
### Bug type

Regression (worked before, now fails)

### Summary

After updating to v2026.8.1-beta.1, workspace skills whose frontmatter contains a colon (`:`) inside an unquoted string value are **silently dropped** — they disappear from `openclaw skills list` with no user-visible error. This worked correctly in beta.3 and earlier.

### Environment

- OpenClaw: v2026.8.1-beta.1 (regression vs. v2026.7.2-beta.3)
- Deployment: Docker Compose on Linux

### Steps to Reproduce

1. Create a workspace skill with a colon inside an unquoted frontmatter value:

```yaml
---
name: my-skill
description: Use this skill for conversion tasks. Trigger: "convert", "export to PDF".
---
```

2. Run `openclaw skills list`
3. Observe: skill is **not shown at all** — no error, no warning in the CLI

### Error

The error only appears in the **gateway log** (easy to miss):

```
[skills] Skipping skill with invalid frontmatter:
  file=~/.openclaw/workspace/skills/my-skill/SKILL.md
  error=invalid frontmatter: BLOCK_AS_IMPLICIT_KEY:
  *** mappings are not allowed in compact mappings
```

### Root Cause

The YAML frontmatter parser became stricter in beta.1. String values containing `: ` (colon + space) are interpreted as implicit block mapping keys, causing a parse error. These frontmatter files were technically malformed YAML, but previous versions accepted them without issue.

### Skills affected in our installation (6 total)

| Skill | Field | Problematic substring |
|---|---|---|
| `handoff` | `read_when` | `signals: user announcing…` |
| `konwerter-formatow` | `description` | `Trigger: "przekonwertuj"…` |
| `porzadkowanie-plikow` | `description` | `Trigger: "uporządkuj"…` |
| `przypomnienia-followup` | `description` | `Trigger: "przypomnij mi"…` |
| `streszczenia-dokumentow` | `description` | `Trigger: "streść to"…` |
| `revit-api-migration-checker` | `description` | `Trigger: migracja Revit…` |

### Fix

Quote the value or use a YAML block scalar:

```yaml
# Option A — quoted string
description: "Use this skill for conversion. Trigger: \"convert\", \"export to PDF\"."

# Option B — block scalar (no escaping needed, recommended)
description: >-
  Use this skill for conversion tasks. Trigger: "convert", "export to PDF".
```

### Requested Improvements

1. **Surface the error in `openclaw skills list`** — show a warning row for skills that fail to parse instead of silently omitting them (gateway log is not monitored in typical usage)
2. **Add `openclaw skills validate`** (or check) command that authors can run locally to catch YAML issues before deployment
3. **Consider a compatibility shim** for the beta.1 parser to accept previously-valid frontmatter with a deprecation warning rather than a hard drop
