# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**[Column] Tracer bullet: PickObjects with a face filter, and does a picked face map back to column_layout's four?**

*Project description:*
Required by `specs/column-roof-termination.md` §5 **before** any of that
addendum is implemented. Also blocked behind #102 in the sense that the
addendum is — but this one can be run *now*, because it proves API mechanics,
not a detailing rule, and mechanics do not need a citation.

## Why #69 does not cover this

#69 proved **passive reads** inside a rolled-back `SubTransaction`: section
orientation, cover parameters, the vertical neighbour search. **Interactive
selection is a different API surface.** Nothing in this repo has ever run
`PickObject`/`PickObjects` against a live host, and the addendum's whole input
mechanism (§3, pick the exception) rests on it.

`docs/token-efficient-expansion.md` §8 is the rule being applied: *a tracer
bullet only verifies what it actually executed.*

## What it must prove

1. **`PickObjects` (plural) with a face reference filter** works from the
   modeless window's Revit-context dispatch — the same
   `execute_in_revit_context` path the existing Pick button uses. §3's
   multi-pick decision means plural, not a loop of singles.
2. The returned `Reference` **reliably correlates back to one of the four
   vertical faces** in `column_layout`'s perimeter model. This is the load
   bearing one. A face reference that cannot be tied to a known face makes
   §3's input unusable no matter how well the picking itself works.
3. Whether the correlation survives a **rotated** column. #69 found
   `HandOrientation`/`FacingOrientation` invariant under a 35° rotation while
   the bounding box was not; the same question has to be asked of a picked face.
4. What happens when the user **picks a slab face, or the column's top or
   bottom face, or presses Escape** — §3 says pick the *column's own* vertical
   face, so everything else is a refusal path that needs a message.

## Not in scope

The detailing rules themselves. This proves the tool *can* ask the question in
§3; whether the answer produces `a + b = L_D` stays blocked on #102.
