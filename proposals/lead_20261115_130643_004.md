# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Automate Flutter analysis and tests with GitHub Actions**

*Project description:*
## Problem

Pull requests have no automated feedback for analysis or tests. Maintainers currently run these checks manually, which adds repetitive work and makes verification dependent on the available developer machines.

## Proposed outcome

Add GitHub Actions for pull requests and pushes to main:

- Use the Flutter version required by the project, with dependency caching.
- Run `flutter pub get`, `flutter analyze`, and the existing test suite.
- Cover Windows and macOS, including the existing plugin integration tests that start real child processes.
- Report the checks on each pull request; choose the stable checks to require before merging once the workflows are reliable.
- Keep tests self-contained: fake Moodle only, no real instance, credentials, learner data or interactive approval dialogs.
- Document the small set of manual GUI and real-instance checks that automation cannot replace.

Do not silently skip platform failures or widen this task into release publishing or installer distribution. Account for native dependencies, platform-specific setup tests and the time needed to compile the example plugin. Define permissions explicitly and avoid exposing secrets to untrusted pull requests.

## Acceptance criteria

- A pull request automatically receives analysis and test results for Windows and macOS.
- A deliberately failing analysis or test causes a failed check.
- CI runs require no Moodle credentials or manual user interaction.
- The developer handbook explains how to reproduce the checks locally and which checks remain manual.

Platform scope: Windows and macOS. Related: #92.
