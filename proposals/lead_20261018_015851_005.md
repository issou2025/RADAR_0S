## Summary

Let users share a mood result from MoodTune to **X** and **Instagram** (Stories first, Feed through the system share sheet). The share is a branded image card of the result (mood, track title/artist, descriptor tags, MoodTune branding) plus a short caption and link.

## Why

Results are the moment users care about most, and right now they stay inside the app. Shareable cards are the cheapest growth loop we have: every share is an ad that shows what the app does.

## Goals

1. A user on the results screen can share their result to Instagram Stories, X, or any app through the system share sheet, in 3 taps or fewer.
2. The shared image looks good at the target aspect ratio and clearly credits MoodTune.
3. Nothing private leaks: no audio, file names, user IDs, emails, or internal engine details.

## Non-goals (v1)

- Public web pages for shared results (deep-linkable `https://app.moodtune.com/r/<id>`). Blocked on domain and universal links. Track separately.
- Posting through the X API or Instagram Graph API (no OAuth to X/Meta). We only hand content to the native apps or the share sheet.
- Video or audio-clip shares, TikTok, Snapchat, Threads, Facebook.
- Sharing whole playlist analyses (`analysis_result_page.dart`, legacy flow).
- Share analytics dashboards (just emit events, see R9).

## Requirements

Each requirement has an ID so PRs and tests can reference it.

- **R1 Share entry point.** `ResultsPage` shows a "Share" action once a result is loaded (upload and catalog sources). Tapping it opens a bottom sheet (reuse `lib/shared/widgets/bottom_sheet_base.dart`) with these targets: **Instagram Stories**, **X**, **More…** (system share sheet). Hide a target if its app isn't installed, except "More…", which is always shown.
- **R2 Share card widget.** Add a new **static** (non-animated) widget `MoodShareCard` that renders the mood label, mood icon, up to 3 descriptor tags, track title and artist (if present), MoodTune wordmark/icon, and a short CTA ("Find your song's mood — MoodTune"). Background uses the `MoodTheme` gradient for the displayed mood. It must not depend on `AnimationController`.
- **R3 Image rendering.** Rasterize `MoodShareCard` offscreen to PNG at:
  - Story: **1080×1920** (9:16)
  - Post / X: **1080×1350** (4:5)
  Use `RepaintBoundary.toImage` with an explicit pixel ratio, or an equivalent approach. Write the file to the temp directory and delete it once the share call returns.
- **R4 Instagram Stories.** Open Instagram's Story composer with the card as the **background image** (or as a sticker over a mood-gradient background; see Decision D3). This needs a **Meta/Facebook App ID** passed as `source_application` (required by Instagram since 2023). iOS: `instagram-stories://share?source_application=<id>` with pasteboard items. Android: intent `com.instagram.share.ADD_TO_STORY`.
- **R5 X.** Share the 4:5 image plus caption text. Recommended path: system share sheet, filtered to X where the platform allows it. Fallback when X isn't installed or can't take an image: open `https://x.com/intent/post?text=<encoded caption>&url=<link>` with `url_launcher` (text only).
- **R6 System share sheet ("More…").** Share the 4:5 image plus caption through the platform share sheet. On iPad, pass `sharePositionOrigin` so the popover anchors correctly.
- **R7 Caption.** A default caption built from the result, localized in `lib/l10n/arb/` (en + es). Example: `My song "<title>" feels <Mood> 🎧 Find your song's mood on MoodTune <link>`. Leave out `<title>` when it's missing or looks like a raw filename (e.g. `track_01.mp3`).
- **R8 Privacy.** Card and caption include only `displayedMood` (what the user saw), descriptors, title, and artist. **Never** include: filename, file size, user email/ID, observation ID, `backendMood` vs `onDeviceMood` comparison, raw confidence numbers (Decision D4), or any audio.
- **R9 Telemetry.** Log `share_opened`, `share_target_selected {target}` and `share_completed {target, success}` through the existing Talker logger (`lib/core/logging/talker.dart`). Report errors to Sentry. No new analytics SDK.
- **R10 Failure handling.** If rendering fails, the target app rejects the share, or the user cancels, show an inline non-blocking message and stay on the results screen. Cancelling is **not** an error.
- **R11 Native config.**
  - iOS `Info.plist`: add `LSApplicationQueriesSchemes` → `instagram-stories`, `instagram`, `twitter`. Add `NSPhotoLibraryAddUsageDescription` only if "Save image" is in scope (D5).
  - Android manifest `<queries>`: add `<package android:name="com.instagram.android"/>` and `<package android:name="com.twitter.android"/>`. Add a `FileProvider` if the chosen plugin needs one.
  - The Meta App ID goes in through `--dart-define` (`META_APP_ID`) and is added to `env.example`, so each flavor can use its own value. The App ID is public (it ships in the binary). The Meta **App Secret** must never enter this repo, because the client doesn't need it.
- **R12 History.** Add the same Share action to each saved row in `history_page.dart`, building `ShareContent` from `ResultHistoryRecord` (`displayedMood`, `title`, `artist`). Saved records have **no descriptors**, so `MoodShareCard` must lay out well with zero tags. Golden-test it with and without tags.

## Share card spec (D9)

Option C from Jordan's design canvas. Sizes are given at 432×540 and scale ×2.5 to the 1080×1350 export. Everything else, including the Story background, is described in R2–R4.

- **Card:** `#2D2A26` (ink) background, 28 px corner radius, 32 px padding. Three blocks spaced top, middle and bottom (`spaceBetween`). Font is Inter Tight throughout. The app already uses it on the splash screen; bundle it if it isn't bundled, because rasterizing needs the real font.
- **Orb:** a 260 px circle filled with the displayed mood's `MoodTheme` gradient (150°, `background` → `backgroundEnd`), centred 60 px inside the top-right corner (offset −70 px on both axes) and clipped by the card.
- **Top:** the MoodTune note mark (26 px, peach `#D99D77`, face details in ink) and the wordmark `moodtune` (17 px, w700, cream `#EFECE6`).
- **Middle, top to bottom:**
  - `"<title> — <artist>"`, 15 px, w500, `#B8B0A3`. Without an artist, the title alone. Without a title, leave the line out.
  - The mood word in sentence case with a full stop (`Charged.`), 70 px, w700, letter-spacing −4%, line-height 0.92. Its colour is the per-mood accent: upbeat `#F5A623`, serene `#4ECDC4`, charged `#E8554A`, reflective `#7FA3D6`. These are chosen for contrast on ink, so don't use `MoodTheme.text`.
  - The quadrant label from `MoodTheme.quadrantLabel` (e.g. "Intense & Powerful"), 19 px, w600, cream.
  - The descriptors joined with ` · `, 15 px, w500, `#B8B0A3`, at most 3. **Leave the line out entirely when there are none** (History shares, R12).
- **Bottom row:** "What does your song feel like?" on the left, `#B8B0A3`, and `getmoodtune.com` on the right, cream. Both 13 px, w600.
- **Text that runs long:** a long title is ellipsized to 1 line. The mood word never wraps; reflective is the longest and fits at 70 px.
- **Goldens (AC2):** charged, serene and reflective, each with and without descriptors.

## Suggested architecture (follow `CLAUDE.md` clean-architecture rules)

```
lib/features/sharing/
├── domain/
│   ├── entities/share_content.dart      # mood, title?, artist?, descriptors, caption
│   ├── entities/share_target.dart       # enum: instagramStory, x, system
│   └── repositories/share_repository.dart   # ResultFuture<ShareOutcome> share(ShareContent, ShareTarget)
├── data/
│   ├── services/share_image_renderer.dart   # widget → PNG bytes/file
│   └── repositories/share_repository_impl.dart  # wraps plugin(s); maps exceptions → Failures
└── presentation/
    ├── widgets/mood_share_card.dart
    ├── widgets/share_sheet.dart
    └── cubit/ or bloc/share_bloc.dart   # status enum + copyWith, like other BLoCs
```

- Register `ShareRepository` and the renderer in `lib/di/injector.dart` so widget tests can mock them.
- The plugin layer must sit behind `ShareRepository`. No plugin imports in presentation code.
- `ShareContent` is built from `AudioUploadAnalysis` (and, for R12, `ResultHistoryRecord`) through a mapper in the sharing feature. Don't add sharing code to the analysis entities.
- Candidate packages (pick in D2): `share_plus` (system sheet; well maintained) plus either a vetted Instagram Stories plugin or a small platform channel (~60 lines per platform). Check that any plugin supports Android 15 / 16 KB page sizes and the current iOS SDK.

- **AC10 (R12)** Given a saved History row, tapping Share opens the same share sheet. The card shows the mood, title and artist, with no empty tag row.
