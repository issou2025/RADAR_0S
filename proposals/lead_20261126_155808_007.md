## Description

When `/build` reviews a branch, its own review agents quote the line each finding points at, and the build checks that quote against the code before keeping the finding. Findings that cite code that doesn't exist are dropped, so the ones that stay can be fixed with confidence. Unverified findings are never fixed without asking a human, which is a good safeguard.

Companion reviewers, such as the Flutter reviewer, return their own format: a location, a problem and a fix, but no quote. The build only checks that the file and line exist, then marks every companion finding as unverified, whether or not the code shows the problem. "Unverified" ends up describing the format a finding arrived in, not whether the code confirms it.

This has two effects:

- **Applying review findings.** A developer who picks "Auto-commit and apply review findings" ([#279](https://github.com/VeryGoodOpenSource/vgv-wingspan/pull/279)) still gets stopped for every companion finding. The Flutter companion runs in any Flutter project, so for those projects the setting only covers part of the review.
- **Agent mode.** Agent mode ([#307](https://github.com/VeryGoodOpenSource/vgv-wingspan/pull/307)) answers each question with the recommended option, or records a blocker when there isn't one. The unverified-findings question has no defined recommended option, so agent mode either blocks the run or applies fixes the rule says need a human, depending on how the question is worded.

Options for checking companion findings:

- The build reads the cited code and confirms or drops each companion finding itself.
- Companion reviewers are asked to quote the line they flag, so the existing quote check covers them.
- Both: ask for a quote, and fall back to reading the code when a companion doesn't give one.

## Requirements

- With "apply review findings" chosen, a confirmed companion finding is applied without asking.
- A companion finding the code doesn't confirm is dropped and listed with the other dropped findings.
- "Unverified" is kept only for findings the code can't confirm either way, like a commit message.
- Agent mode handles every remaining unverified finding the same way each run, and records it in the decision log.

## Additional Context

Seen on a Flutter project where all 13 findings from the Flutter companion were marked unverified, including one the code clearly confirmed: a link that screen readers can't activate.
