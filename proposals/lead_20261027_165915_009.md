# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Map: edge-rum 5.0 — traces & spans, contract 4 parity, Ionic specialisation (build spec)**

*Project description:*
## Destination

A **build spec** (`docs/spec.md`, rule-numbered) plus per-area **implementation issues** for **edge-rum 5.0.0** (Ionic + Angular + Capacitor) that a developer can build from with nothing left to decide. It covers:

- **Traces and spans** — distributed trace v3 (spans as attributes on existing events, W3C `traceparent`), adapted to a WebView/Angular/Capacitor runtime.
- **Contract 4 parity** — move off the legacy `telemetry_batch` 3.1 wire onto the contract-4 envelope and processor-typed names shared by Android / iOS / Flutter / Cordova.
- **Gap fills** — what's standard across sibling SDKs that Ionic lacks.
- **Ionic specialisation** — capabilities only this stack can offer (Capacitor bridge, Angular internals, Ionic UI lifecycle, WebView health + live updates).
- **Lightweight** — explicit size / hot-path budgets the whole design is held to.
- **Backend** — the processor / analytics / collector changes needed to surface Ionic-only events and traces.

## Notes

- **Planning only — write no SDK code.** Tickets produce decisions; the spec + impl issues are the output.
- **Align, don't restrict.** Siblings set the floor (wire names, trace contract); Ionic may exceed them. Divergence on shared wire is a defect; divergence in mechanism is Ionic's call.
- **Cardinal rule** (inherited from the operational-safety map): the monitor must not degrade the app. Every decision is judged against size, startup, and hot-path cost.
- **Existing rules to redraw, not silently break:** `CLAUDE.md` terminology firewall + tests that ban `span`/`trace`/`traceId`; ADRs in `docs/decisions.md` (ADR-001…032). Superseded ADRs get a new ADR.
- **Sibling sources** (local, under `edge_rum/`): `edge_telemetry_android` (trace wire owner: `docs/specs/backend-wire-contract.md`), `edge_telemetry_ios_sdk` (`docs/specs/distributed-trace-v3-ios.md`), `edge_telemetry_flutter`, `edge_telemetry_react_native` (`docs/coverage-gap.md`), `edge_telemetry_cordova_sdk` (closest sibling; `docs/research/*`, `docs/spec.md`), backend `edge_telemetry_processor_go`, `edge_telemetry_collector_go`, `EdgeTelemetryRUMAnalyticsGo`. Contract 4: `edge_rum/wayfinder/spec.md` (rules R1–R16) — cite, don't restate.

- [Research: competitor Ionic/Capacitor monitoring SDKs — borrow list (#73)](https://github.com/NCG-Africa/edge_telemetry_ionic_angular_capacitor/issues/73) — `docs/research/ionic-competitor-sdks.md`: borrow = escape NgZone, opt-in empty `traceparent` allowlist, `app://` stack paths, release id + OTA bundle id for source maps (market gap), deterministic trace sampling; skip replay / vendor headers / full OTel / NR-style unallowlisted propagation. Zone finding: frame loop + flush timer likely run in NgZone → #71 cost understated. Nobody instruments bridge / Ionic lifecycle / WebView death.
- [Research: backend readiness for Ionic on contract 4 and traces (#74)](https://github.com/NCG-Africa/edge_telemetry_ionic_angular_capacitor/issues/74) — `docs/research/backend-readiness.md`: 4.x Ionic batch accepted in merged collector (prod deploy unverified; stale collector would dead-letter); no `sdk.name` enum, `ionic` alias exists but SDK id unstored; Ionic shows only in mobile views (`/web/*` is a separate schema), android|ios App only; trace backend ready. Visibility gaps: crashes → `rum_errors` vs dashboards' `rum_crash_events`, frames/memory views mis-count, no `traceparent.outcome` col, session counters first-write-wins. Key mismatches: `user.interaction`, dotless frame/memory keys, ANR/crash-thread keys. ~23/112 keys reach a read column.
