# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Google & Facebook SSO login with join-family flow**

*Project description:*
## Overview

Add Google and Facebook SSO login to Village. New SSO users get an interstitial where they choose "create new family" or "join existing family with invite code."

**Repos affected:** `village-api` (backend) + `village-app` (Flutter frontend)

## Current State

- Auth is email/password only via JWT + BCrypt
- `User` entity has `PasswordHash` as `string.Empty` default (not nullable)
- Register flow: invite code blank = new family as Parent, else join as Child
- Login page has no SSO buttons
- No OAuth infrastructure exists

## Architecture

```
OAuth flow:
  Flutter → Google/Facebook OAuth popup → get ID token
  POST /api/auth/sso { provider, idToken, inviteCode? }
  API validates token → finds/links/creates user → returns Village JWT
```

**Link strategy:** If a user with matching email already exists (password or different OAuth), link the new OAuth provider to that account instead of creating a duplicate.

**Family choice:** New users who sign in via SSO see a choice page: "Create new family" (becomes Parent) or "Join existing family" (enters invite code, becomes Child).

## Implementation Plan

### API Changes (village-api)

**1. User entity** — `src/Village.Domain/Entities/User.cs`
- Add `string? OAuthProvider` (stores "google" or "facebook")
- Add `string? OAuthSubject` (provider's unique user ID)
- Change `PasswordHash` from `string.Empty` to `string?` (nullable for SSO-only users)

**2. Migration** — `src/Village.Infrastructure/Migrations/*_AddOAuthFieldsToUser.cs`
- ALTER Users: PasswordHash → nullable, add OAuthProvider, OAuthSubject columns
- CREATE UNIQUE INDEX on (OAuthProvider, OAuthSubject)
- Update DbContext OnModelCreating with index config

**3. GoogleTokenValidator** — `src/Village.Api/Services/GoogleTokenValidator.cs` (NEW)
- Uses `Google.Apis.Auth` NuGet package
- `ValidateAsync(idToken)` → returns `GoogleUserInfo` or null
- Validates JWT signature, extracts subject/email/name/email_verified

**4. FacebookTokenValidator** — `src/Village.Api/Services/FacebookTokenValidator.cs` (NEW)
- Uses `IHttpClientFactory` to call `graph.facebook.com/v19.0/me`
- `ValidateAsync(accessToken)` → returns `FacebookUserInfo` or null
- Validates token by fetching user profile, requires email field present

**5. SsoRequest DTO** — `src/Village.Api/Dtos/Auth/SsoRequest.cs` (NEW)
```csharp
public record SsoRequest(string Provider, string IdToken, string? InviteCode);
```
Validator: Provider must be "google" or "facebook", IdToken required, InviteCode max 50 chars.

**6. POST /api/auth/sso endpoint** — modify `AuthModule.cs`
- Validates token via GoogleTokenValidator or FacebookTokenValidator
- Looks up user by (OAuthProvider, OAuthSubject) → returning user, issue JWT
- Falls back to email lookup → link OAuth to existing account, issue JWT
- New user: creates account with OAuth fields, PasswordHash=null
  - inviteCode blank → creates new Family, user=Parent
  - inviteCode provided → joins existing Family, user=Child
- Returns same AuthResponse shape as /login and /register
- Rate limited at "Auth" tier, AllowAnonymous

**7. Register in Program.cs**
- `builder.Services.AddSingleton<IGoogleTokenValidator, GoogleTokenValidator>()`
- `builder.Services.AddHttpClient<IFacebookTokenValidator, FacebookTokenValidator>()`

### Flutter Changes (village-app)

**8. Packages** — `pubspec.yaml`
- `google_sign_in: ^6.3.0`
- `flutter_facebook_auth: ^7.1.1`

**9. SsoService** — `lib/core/auth/sso_service.dart` (NEW)
- `signInWithGoogle()` → triggers Google Sign-In, returns `SsoResult(provider, idToken, email, displayName)`
- `signInWithFacebook()` → triggers Facebook Login, returns same
- Uses `kIsWeb` check for web-specific config (Google client ID, Facebook webInitialize)
- Provider: `ssoServiceProvider`

**10. AuthService.sso()** — `lib/core/auth/auth_service.dart`
```dart
Future<AuthResponse> sso({provider, idToken, inviteCode})
```
Posts to `/api/auth/sso`, stores returned JWT via SecureStorage.

**11. AuthNotifier.loginWithSso()** — `lib/core/auth/auth_provider.dart`
```dart
Future<void> loginWithSso({provider, idToken, email, displayName, inviteCode})
```
Same pattern as existing `login()` — sets auth state, handles DioException errors.

**12. SsoFamilyChoicePage** — `lib/features/auth/pages/sso_family_choice_page.dart` (NEW)
- Receives `SsoResult` via GoRouter `extra`
- Two large tappable cards:
  - "Create a new family" → calls loginWithSso(inviteCode: null) → redirects to /hub
  - "Join an existing family" → navigates to /sso-join-family
- Shows SSO user's name and email at top

**13. SsoJoinFamilyPage** — `lib/features/auth/pages/sso_join_family_page.dart` (NEW)
- Invite code text field + "Join family" button
- Calls loginWithSso(inviteCode: code) → redirects to /hub
- Back button returns to family choice page

**14. Login page SSO buttons** — `lib/features/auth/pages/login_page.dart`
- Add "or" divider below the existing Sign In button
- "Continue with Google" OutlinedButton (with Google "G" icon)
- "Continue with Facebook" OutlinedButton (with Facebook icon)
- On tap → triggers OAuth flow → tries silent SSO login first (for existing users)
  → if that fails (new user), navigates to `/sso-family-choice`

**15. Router entries** — `lib/core/router/app_router.dart`
- `/sso-family-choice` → SsoFamilyChoicePage, passes SsoResult as extra
- `/sso-join-family` → SsoJoinFamilyPage, passes SsoResult as extra

**16. main.dart initialization** — `lib/main.dart`
- Facebook SDK web initialization (app ID, cookie, version)
- Add Facebook JS SDK script tag to `web/index.html`

## Risks

| Risk | Mitigation |
|------|------------|
| PasswordHash nullability | BCrypt.Verify handles null — returns false; no code change needed in login path |
| Facebook SDK JS must be loaded for web | Added to web/index.html in task 16 |
| Google Sign-In requires client ID on web | Passed in GoogleSignIn() constructor with kIsWeb guard |
| Both providers return different token types | Google=id_token JWT, Facebook=access_token — handled in respective validators |
| SsoResult passed via GoRouter extra (not type-safe) | Acceptable for v1, standard GoRouter pattern |
