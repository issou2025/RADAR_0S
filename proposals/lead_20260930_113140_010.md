## Outcome and finite implementation
1. Add a bounded native intake policy for concurrent decodes, queued shares, item count, text and aggregate accepted bytes before the Dart pipeline. Use one explicit small admission controller, not an unbounded executor or an unbounded fallback queue. Define overflow/busy/rejected behavior with a usable retry in the existing receipt-import consumer. Keep normal multi-file and text-only shares working.
2. Bound the user-visible operation across metadata lookup, open and copy, with cancellation and stale-delivery fencing. A blocked ContentProvider call may not be interruptible: do not claim Thread.interrupt/close forcibly releases every kernel wait. Bound retained workers/resources, isolate suspect slots, return an honest timeout/busy outcome, and prevent uncontrolled replacement-thread creation. The watchdog must not be globally stalled by one blocking close. Do not restore a single decoder where one wedged provider blocks all future normal shares.
3. Replace overwrite-prone pending delivery with bounded, uniquely identified ownership and an explicit disposition for every admitted share. Coordinate cold initial fetch, stream subscription, warm intents and Flutter-engine detach/recreation; preserve order or state the deliberate policy. An obsolete decode cannot deliver into a different active receipt flow. Do not claim decode succeeded merely because handleIntent accepted the intent.
4. Keep content:// only, streaming byte enforcement, partial-file cleanup, platform-thread channel delivery and GMS-free implementation. Clean orphan temporary files through existing safe retention ownership, never delete an in-use imported document. Redact provider URIs/filenames from diagnostics. Expose typed results to the actual Dart import UI, not raw exceptions.
