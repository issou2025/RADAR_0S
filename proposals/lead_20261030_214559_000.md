# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Document how to test agent skills and library changes through MCP in a live Revit**

*Project description:*
## Is your feature request related to a problem? Please describe

Changing agent skills or the pyrevitlib helpers they describe is best verified by running the snippets in a live Revit through the MCP server. Nothing in the repo describes that workflow, so every contributor (human or agent) rediscovers it. `docs/agent-runtime.md` documents the in-Revit "Agent Tests" buttons and `AGENTS.md` documents the build and `pyrevit clones add` / `attach`. The steps in between are missing, and each one failed while I worked on #3839 (PR #3863):

- **A rebuild fails while any `pyrevit mcp` server is running.** Each MCP client session starts `bin\pyrevit.exe mcp`, which holds files in `bin\` (for example `Colorful.Console.dll`). `BuildLabsModule` then fails with "The process cannot access the file ... because it is being used by another process". The server of every open client session holds the lock, not only the current one.
- **Python and markdown changes under `pyrevitlib` need no rebuild.** IronPython can `reload()` them. CPython cannot: reloading `pyrevit.revit.db.create` fails with `TypeError: Duplicate type name within an assembly` because `FamilyLoaderOptionsHandler` is baked once. A restart of Revit is the reliable way to load edited modules on both engines.
- **The "Security - Unsigned Add-In" dialog appears after every rebuild and restart** and has to be accepted ("Load Once") before the MCP host answers. `docs/ci-cd.md` mentions this dialog only as a CI failure.
- **How to test a snippet or helper is undocumented:** run it through `run_query` in a scratch family or project document (`app.NewFamilyDocument`, `app.NewProjectDocument`), close the document in `finally`, and restore any user setting touched (for example `app.SharedParametersFilename`). If a script fails with a transaction open, `Close(False)` raises and hides the real error, so roll back first.

## Describe the solution you'd like

- A short section "Testing agent skills and library changes through MCP" in `docs/agent-runtime.md` that covers the steps above in order:
  - when a rebuild is needed (C# changes) and when a restart or reload is enough (Python and markdown)
  - stopping running `pyrevit mcp` processes before a rebuild, and that clients must reconnect afterwards
  - accepting the unsigned add-in dialog after each start
  - engine differences when reloading modules
  - running a snippet in a scratch document and cleaning up
- A one-line pointer to that section from `AGENTS.md`, which should stay a list of conventions and commands.
- Optionally, a small dev-tools command or script that stops the `pyrevit mcp` processes started from the clone's `bin\` before a build.

## Describe alternatives you've considered

- Put the whole procedure in `AGENTS.md`. It is loaded for every task and is meant to stay lean, so a pointer is enough.
- Leave it to the contributor. This is what happens now: one failed build and several extra runs before the cause of the lock was clear.
- Keep it in a personal notes file. That helps one person and not other contributors or their agents.

## Additional context

Found on Revit 2024.1, Windows 11, a Debug build of `develop`, IronPython 2.7.12 and CPython 3.12.3. Related: #3839, PR #3863.
