# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**geometry: IfcTriangulatedFaceSet has no tessellation path, so IFC4 tessellated elements vanish instead of degrading to a box**

*Project description:*
`tessellateItemDepth` has no case for `IfcTriangulatedFaceSet`, which is IFC4's native tessellated body and the one SketchUp, BlenderBIM and Revit's IFC4 Reference View export. `IfcPolygonalFaceSet` has no case either.

**These elements don't fall back to a box: they disappear.** The OBB fallback has no bounding box to work from, so goifc returns the element with no triangles and a zero AABB (`[0 0 0]..[0 0 0]`). The only trace is a `no geometry for <GlobalId>` warning. By the cardinal rule, that is the worse failure: an element that vanishes is a total under-report, where a box is only an over-report.

## Measured

Found by an exporter-mix scan over every distinct real IFC model on a dev machine (goifc v0.12.1):

| Exporter | Schema | Elements | Result |
|---|---|---|---|
| SketchUp 2024 (IFC-manager 5.3.3) | IFC4X3_ADD2 | 14 | **14 empty**. `UnhandledItemTypes`: `IFCTRIANGULATEDFACESET 10` |
| ArchiCAD 20 / 25 | IFC2X3, IFC4 | 85, 1,922 | 0.0% / 0.2% OBB |
| Revit 2011 | IFC2X3 | 218, 805 | 0.0% OBB |
| Rhino (ASIFC) | IFC2X3 | 228 | 0.0% OBB |
| IfcOpenShell | IFC2X3 | 40 | 0.0% OBB |

None of the three parity corpus models uses `IfcTriangulatedFaceSet`. Parity cannot see this gap, and an IFC4 file hits it immediately.

## Shape of a fix

- `IfcTriangulatedFaceSet`: `Coordinates` is an `IfcCartesianPointList3D` and `CoordIndex` holds 1-based index triples. This maps straight onto `Verts`/`Tris`. `PnIndex`, when present, remaps the indices into the point list.
- `IfcPolygonalFaceSet`: its `IfcIndexedPolygonalFace`s need fan-triangulating, plus `IfcIndexedPolygonalFaceWithVoids` for faces with holes. This could follow separately.
- Even before tessellation lands, the bbox path could read `Coordinates`. An element would then degrade to its OBB instead of vanishing.
- A synthetic fixture and a public IFC4 model with this idiom in the parity corpus would keep it covered.
