# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**SkipGenerated/SkipType protect <PrivateImplementationDetails> and its members, but still rename its nested __StaticArrayInitTypeSize=N struct types (3.0.0-beta.18/.19)**

*Project description:*
## Expected behavior

Tell us what you expected to happen.

I expected this: with `SkipGenerated="true"` set (and, redundantly, an explicit `<SkipType rx="^&lt;PrivateImplementationDetails&gt;(/.*)?$" skipStringHiding="true" />` targeting the exact same hierarchy), **no** type or member under `<PrivateImplementationDetails>` should be renamed by Obfuscar — including the nested `__StaticArrayInitTypeSize=N` array-literal-blob helper struct's own type name, not just its container and its members.

## Actual behavior

Tell us what you see!

But a bug happened like this: `SkipGenerated`/the explicit `SkipType` **do** correctly protect the `<PrivateImplementationDetails>` container type itself, and correctly protect the nested struct's own *field* (the byte-blob data field) — both show up in `Mapping.txt` as `skipped: compiler generated attribute rule in configuration`. However, the nested struct's own **type name** is renamed anyway, on the very next line, with no "skipped" annotation at all:

```
[ObfuscarRepro]<PrivateImplementationDetails> skipped:  compiler generated attribute rule in configuration
	<PrivateImplementationDetails>/__StaticArrayInitTypeSize=700 [ObfuscarRepro]<PrivateImplementationDetails>/__StaticArrayInitTypeSize=700 <PrivateImplementationDetails>::22FB108E29D76950119863C325E356566EF8B2C8FCC47A3FD2321058CC0099E2 skipped:  compiler generated attribute rule in configuration
[ObfuscarRepro]<PrivateImplementationDetails>/__StaticArrayInitTypeSize=700 -> [ObfuscarRepro]<PrivateImplementationDetails>/A
```

The container and the field are both correctly excluded by the exact same rule that fails to exclude the type they both belong to/are declared as. This is reproducible on every run (only the generated short name, `A` above, changes between runs).

This is not just a theoretical/cosmetic issue: renaming this type breaks any downstream consumer that needs to resolve it by name/identity. We found this while building for Unity's IL2CPP target — its `UnityLinker` step needs to walk every type's base-type chain (to decide `MonoBehaviour`/`ScriptableObject`-ness for stripping) and fails hard the moment it reaches one of these renamed structs:

```
ILLink: error IL1999: ERROR: Failed to resolve base type System.ValueType
for type 1{<random-guid>}.2 in assembly MyAssembly.dll when linking
against the UnityAot-Linux profile
```

(That specific error is Unity/IL2CPP-specific and not something this report asks Obfuscar to fix directly — it's included only as evidence of real-world impact. The underlying defect — the skip rule not applying to the nested type's own name — is fully reproducible and observable purely via `Mapping.txt`, with no Unity involvement at all; see the minimal repro below.)

## Detailed steps

Detailed steps to reproduce the problem.

The steps are: a minimal, from-scratch repro project (not derived from any real codebase) is available at <link to `.examples/obfuscar-repro/` in this repo, or attach `Data.cs` + `ObfuscarRepro.csproj` + `run-3x/Obfuscar.xml` from that folder>. Summarized:

1. Create a plain .NET 8 console project with one file containing a `public static readonly byte[]` field initialized with a literal of ~700 elements (large enough that Roslyn backs it with a `<PrivateImplementationDetails>/__StaticArrayInitTypeSize=N` helper rather than per-element IL assignments — the exact values don't matter, only the count).
2. `dotnet build -c Release`.
3. Run Obfuscar 3.0.0-beta.18 against the built DLL with this config:
   ```xml
   <?xml version="1.0"?>
   <Obfuscator>
     <Var name="InPath" value="<bin/Release/net8.0 dir>" />
     <Var name="OutPath" value="<some out dir>" />
     <Var name="KeepPublicApi" value="true" />
     <Var name="RenameFields" value="true" />
     <Var name="RenameProperties" value="true" />
     <Var name="RenameEvents" value="true" />
     <Var name="HidePrivateApi" value="true" />
     <Var name="SkipGenerated" value="true" />
     <SkipType rx="^&lt;PrivateImplementationDetails&gt;(/.*)?$" skipStringHiding="true" />
     <Module file="<path to the built .dll>" />
   </Obfuscator>
   ```
4. Inspect the resulting `Mapping.txt` — the nested `__StaticArrayInitTypeSize=N` type will show as renamed (no "skipped" annotation) even though its declaring type and its own field are both correctly marked "skipped: compiler generated attribute rule in configuration" by the identical rule.

Also confirmed the same result using an explicit non-regex form instead of `rx` (`<SkipType name="&lt;PrivateImplementationDetails&gt;/*" skipStringHiding="true" />`), and using per-size hand-listed entries (`<SkipType name="&lt;PrivateImplementationDetails&gt;/__StaticArrayInitTypeSize=700" />`) instead of a wildcard/regex — all three forms produce the identical outcome.

## Related issues (searched before filing)

None of these are duplicates of this report (different trigger/symptom in each case), but they're the closest prior art found searching this repo's issue tracker, and may be useful context for whoever triages this:

- **#201** — Unity IL2CPP build failure involving `<PrivateImplementationDetails>`, closed 2019 after the reporter worked around it with `HideStrings="false"`. **We tried that exact workaround against this repro and it does not fix this issue** — `Mapping.txt` is unchanged with `HideStrings="false"` set, since this repro's `<PrivateImplementationDetails>` usage comes from an array literal, not from Obfuscar's own string-hiding feature.
- **#583** — "ExceptionHandlers table stripped... `SkipType` with `skipMethods="true"` → does NOT fix it" (ILRepack + Obfuscar). Same general shape as this report (a documented `SkipType` rule not actually preventing the described breakage) but for a different trigger (ILRepack-merged assemblies) and a different symptom (stripped exception handler tables, not a rename). Closed without a technical resolution recorded in the thread.
- **#340** — a different `<PrivateImplementationDetails>`-related failure (method-count overflow from `HideStrings` generating too many string-decoder methods on a large assembly). Root cause and trigger are unrelated to this report's array-literal-blob scenario.
- **#400** — another `<PrivateImplementationDetails>`-related crash ("declared in another module and needs to be imported"), triggered by a different codepath than this report.
- **#467**, **#191**, **#154** — the same general pattern ("still obfuscated/broken despite a skip configuration option") reported for *anonymous types* (`SkipAnonymous`) rather than compiler-generated array-literal helpers. #467 was closed as "not_planned" for lack of a clear repro; the other two describe anonymous-type properties being stripped under `HidePrivateApi`.
- **#613** — a separate, confirmed v2-vs-v3 regression report (unrelated symptom — a Revit API reference failing only on `3.0.0-beta.18`), included here only as evidence that cross-version behavior differences between the 2.2.x and 3.x lines are a known, recurring category of report for this project.
