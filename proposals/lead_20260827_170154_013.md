## Project Understanding
You need assistance with: 
**`just new-history` fails when `--details` text contains parentheses**

*Project description:*
`just new-history` dies on any `--details` string containing `(` or `)`:

```
new-history: 1: Syntax error: "(" unexpected
error: recipe `new-history` failed on line 198 with exit code 2
```

The recipe interpolates arguments into the shell without quoting, so the parentheses are read as shell syntax rather than as text.

This matters more than a normal quoting bug because of where it lands. `CLAUDE.md` asks every KB-entry PR to add a history record, and the `details` field is the one place the curation reasoning goes — which means it routinely contains PMIDs in parentheses, MONDO IDs in parentheses, or a parenthetical caveat. Hitting it mid-curation is the common case, not the edge case.

The workaround is to call the script directly, which quotes correctly:

```bash
uv run python scripts/new_history.py --kind disorder --slug Foo \
  --event CREATE --outcome changed --details "Text with (parentheses) works fine."
```

So the bug is in the `just` recipe's shell interpolation, not in `scripts/new_history.py`.

Found while curating Charcot-Marie-Tooth disease type X (https://github.com/monarch-initiative/dismech/pull/9700).
