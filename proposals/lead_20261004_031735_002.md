# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**feat: rotate, copy, mirror, change type and bulk parameter update**

*Project description:*
Move, delete and single-parameter edits exist. Everyday model edits also need rotate, copy, mirror, type change and a bulk parameter update by filter.

## Tools

All are actions with `dry_run`, `verification`, `summary` and one named undo entry, refused in read-only mode, and allowed as `revit_batch` steps (`rotate`, `copy`, `mirror`, `change_type`, `update_parameters`).

### `revit_rotate`

`revit_rotate(element_ids, angle_deg, center_mm=null)`

- Rotates about a vertical axis. `center_mm=[x, y]`; `null` uses the center of the combined bounding box of the elements.
- Elements that cannot rotate (pinned, or rejected by `ElementTransformUtils.CanRotate`-style checks) are reported by id; nothing changes if any element cannot rotate.

### `revit_copy`

`revit_copy(element_ids, dx_mm, dy_mm, dz_mm=0, count=1)`

- `count` 1-100 creates that many copies, each offset by one more step (a linear array without an array group).
- Returns the new element ids per copy.

### `revit_mirror`

`revit_mirror(element_ids, axis, point_mm, copy=true)`

- `axis`: `x` (mirror across a line parallel to the model X axis) or `y`; the line passes through `point_mm=[x, y]`.
- `copy=true` keeps the originals (`MirrorElements` with `mirrorCopies=true`) and returns the new ids.

### `revit_change_type`

`revit_change_type(element_ids, type_name, family=null)`

- Resolves the target type among types compatible with each element (`Element.GetValidTypes`). `family` disambiguates when several families have a type with that name. Ambiguous or incompatible targets are refused with candidates.

### `revit_update_parameters`

`revit_update_parameters(filters, parameter, value, parameter_id=null, max_elements=5000)`

- `filters`: the same filter object `revit_query_elements` accepts (categories, classes, levels, parameter conditions). Resolve it with the existing query code, not a second filter engine.
- `parameter`, `value`, `parameter_id`: the same rules as `revit_set_parameter`, applied to every matched element.
- More matches than `max_elements` (at most 20000): refused, nothing changes, the count is returned.
- Elements where the parameter is missing or read-only are reported per reason; the rest commit. `dry_run` reports the counts and the first 50 old and new values.

## Acceptance criteria

- Each tool works on the sample model and undoes with one Revit undo.
- `revit_batch` accepts the new steps and still rolls back the whole batch on the first failure.
- `revit_update_parameters` with a category and level filter changes exactly the elements `revit_query_elements` returns for the same filter.
- Core tests for argument validation and batch step parsing; Python tests for mappings.
- Docs: `docs/actions.md`.
