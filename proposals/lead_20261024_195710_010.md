# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[Research] Round 3: what users love & hate across ~90 SSH, terminal & remote-desktop tools (2026-10)**

*Project description:*
> Round-3 competitive research, 2026-10-24. Earlier rounds: #43–#69 (round 1, 2026-08-28) and #86–#104 (round 2, 2026-09-09). **This round asks what users actually love and hate**, not which features each product lists.

## Executive summary
Seven segment reviews covering about 90 products agree on one thing. People recommend tools they can install today that keep their data local and never take features back. They abandon tools after a pricing or licence rug-pull, after an update that loses data or breaks auth, or when AI is forced on them or sends data out.

TermDesk's position is strong on paper:
- cross-platform SSH, SFTP, VNC, RDP and tunnels in one MIT app, which is the "cross-platform MobaXterm" that every segment says is missing;
- no account and no telemetry;
- approval-gated MCP ("hands, never keys").

Delivery is the weak point, and I re-verified it on origin/main:
- No Release has been published. #118 is open, package.json is at 0.4.0, and the README says "no tags and no GitHub Releases".
- None of the 10 cores in src/shared is imported by src/main, src/renderer or src/preload: host-inheritance, ai-backend, completion, bench-metrics, vault-export, wake-on-lan, ssh-auth, reconnect, agent-tools and sync-contract. scripts/bench.mjs only mentions bench-metrics in a comment and is a scaffold whose app metrics are all marked "pending".

So the closed issues #38-#69 delivered logic and architecture docs, but nothing a user can see.

The plan has 7 milestones and 31 issues, down from 37 in the draft.

Wave 1 has two P0 milestones:
- **R3-1 "Ship what users can touch"** wires the six cores whose issues are closed. It adds a CI guard so no core can merge unwired again, and the first Release (#118, gated on U1 #113/#114/#115) is its exit gate.
- **R3-5 "Release trust"** adds a test that no credential is sent before the host key is accepted, paste hardening, a matrix against real sshd variants and a CI-proven no-telemetry check. These gate the first Release so it doesn't become a Tabby-style regression. The SBOM work moved into the existing #120.

Wave 2:
- **R3-2 Data ownership and switching:** importers (finishing #42), ssh_config export, restore from backup, the OPEN-CORE.md pledge and switching guides.
- **R3-3 Agent cockpit:** attention detection, OS notifications, rendering compatibility for TUI agents, a global AI-off policy and risk-tiered approvals. The agent sidebar went into #96 rather than becoming a duplicate issue.

Wave 3:
- **R3-4 Remote desktop over SSH trust:** RDP clipboard, RDP resize (finishing #66), a session toolbar with keyboard grab, and a VNC-server helper with its docs (finishing #68).
- **R3-6 Linux, accessibility and i18n.**

Wave 4:
- **R3-7 Gateways and local recording:** ProxyCommand support, and local encrypted recording that has only an interface for the paid central version.

The plan does not duplicate U1-U5 or M10-M13. It raises the priority of #118 and #124, adds evidence to #91, #96, #95, #90, #94, #99, #86, #100 and #120, and lowers #92 and #98. It reopens #38, #42, #46, #49, #56, #61, #66, #67 and #68 for wiring.

## Method & limitations
Seven parallel research agents covered about 90 products in these segments: commercial SSH, OSS SSH, modern terminals, AI/agentic terminals, remote desktop, secure access & file transfer, and cross-cutting sentiment. Sources were HN threads (via the Algolia API), the most-reacted GitHub issues, Trustpilot/AlternativeTo/Product Hunt, vendor changelogs and "why I switched" posts, prioritising 2025–2026. **Reddit was blocked in the research environment, and G2/Capterra returned 403.** Evidence for Royal TSX, Jump Desktop, Splashtop and Bitvise is thin. An adversarial reviewer then removed any claim or URL it could not trace to the raw research. Re-verify competitor claims before they go into public docs (#100).

The full per-segment findings, every love and hate with its sources, are in the comments below.

### Risks
- An unsigned first Release brings Gatekeeper and SmartScreen friction and 'is this malware?' doubts. Mitigate with SHA256SUMS, #120 attestations and SBOM, the netquiet proof and clear INSTALL.md guidance. Move #127/#128 forward as soon as certificates exist.
- #118 depends on U1 (#113/#114/#115). If U1 slips, the Release slips, so U1 is scheduled in wave 1 and nothing else in wave 1 blocks the Release except the R3-5 safety checks and vault export.
- Folder inheritance touches every connect path (SSH, SFTP, VNC, tunnels, fleet, MCP). Mitigate by landing the sshd matrix and host-key test first, and by keeping resolution behind a flag for one beta cycle.
- Export, import and restore are the data-safety features, so a bug in them is exactly the Termius-style failure we position against. Mitigate with dry-run-first import, a pre-restore backup, refusing newer schemas (#123) and fixture round-trip tests.
- Agent-attention pattern matching breaks as harness UIs change. Prefer the standard OSC 9/777/133 signals, keep fixtures per harness version, and fall back to idle rather than a wrong state.
- Scope creep toward a kitchen-sink app with AI surfaces everywhere. Keep AI opt-in and hideable through sidebar sections, and ship the global AI-off policy before #96 adds the agent sidebar.
- Importers that decrypt legacy mRemoteNG credentials could leak plaintext through logs. Require explicit opt-in, re-encrypt immediately via secrets.ts, and redact all importer logging.
- ProxyCommand and the VNC-server helper run commands, so a malicious imported ssh_config could execute code. Never run anything silently: require confirmation on import, use no shell interpretation, and document both in the threat model.
- The open-core boundary could drift. Recording, sync and inheritance are attractive paid candidates, and moving them would break OPEN-CORE.md and repeat the Teleport/XPipe backlash. Publish the pledge in wave 2 and keep paid features additive via interfaces (RecordingSink, #63).
- Single-maintainer bandwidth is limited: R3 plus U1-U5 plus M10-M13 is a lot of work. Sequence strictly by wave, label the S-sized wiring issues good-first-issue, and defer R3-6 i18n and R3-7 first.
- Evidence gaps: Reddit, G2 and Capterra were unreachable, and the evidence for Royal TSX, Jump Desktop, Splashtop and Bitvise is thin. Re-verify competitor claims before they go into #100 or the switching guides, and keep every claim sourced.
- Electron perf numbers in the README may look poor next to Ghostty or Alacritty. Present them against Electron and JVM peers, and treat budgets as regression gates, not marketing.
