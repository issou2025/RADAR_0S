# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Adaptive meditation audio: personal library, offline mixing, calibration, and EEG adaptation**

*Project description:*
## Problem Statement

neuroTune users want to meditate with their own music and nature recordings, compare fixed binaural tone settings without seeing their assignments, and eventually personalize tone changes using EEG patterns associated with their own reported experience of mental busyness and relaxation.

The current Android prototype generates stereo tones and records signals, but has no web audio editor, personal background library, offline background mixer, ten-session calibration, or post-session ratings. Its existing Personal and Comparison experiments use baseline-normalized outer-NIR intensity as reward; that learning path does not implement the requested personal EEG meditation controller.

## Solution

Provide a TypeScript web editor for uploading, trimming, mixing, auditioning, and saving personal audio profiles. Store immutable profile versions and their background files in the authenticated backend library. Let users browse, preview, and download profiles in neuroTune, then play the background and locally generated stereo tones throughout a ten-minute meditation without network access.

Make meditation the primary mobile flow while keeping the existing NIR experiments in a separate Experiments area. Begin with blinded, balanced ten-session calibration series and two post-session ratings. Recommend a preferred fixed action from those ratings. Pool eligible series in a context-aware personal EEG model; enable local, minute-by-minute adaptation directly once at least twenty usable sessions and the agreed predictive validation gates support it. Until then, continue fixed meditation and collect more data.

## Implementation Decisions

### Architecture and compatibility

- Deliver shared contracts and persistence, the web/backend library, offline mobile mixing, calibration/feedback, and personal adaptation as successive increments behind a meditation feature flag.
- Make meditation the main mobile flow. Retain the existing NIR Personal and Comparison modes in an Experiments area, with distinct policies, training routing, and reward descriptions.
- Introduce a meditation engine alongside the existing NIR engine. Reuse recording, diagnostics, foreground-service handling, Android PCM output, persistence, and synchronization. EEG frames reach the meditation engine without waiting for optics.
- Keep Muse, simulator, and playback datasets separate. Version quality checks, protocols, profile recipes, and models; existing session records remain readable.

### Audio library, editor, and rendering

- Build a standalone TypeScript editor using Vite and browser audio APIs, served by the existing backend origin. Reuse account authentication and hold browser tokens in memory.
- Support WAV, MP3, M4A/AAC, and FLAC uploads containing mono or stereo audio. Limit each source to 100 MiB and ten minutes, and each mix to four tracks. Reject unsupported, corrupt, oversized, and longer sources with actionable errors.
- Allow per-track trimming, fixed gain, and looping, with all tracks starting together. Save a named profile with a separate carrier and tone/background gains.
- Process imports and renders through FFmpeg in persistent worker jobs, using controlled paths and subprocess arguments, bounded processing time, and recovery for interrupted jobs. Expose pending, ready, and failed states.
- Render canonical 48 kHz stereo PCM16 WAV backgrounds, preserving stereo and duplicating mono. Store originals and renders in a dedicated volume shared by API and worker.
- Generate a thirty-second preview through the same pipeline used for the saved background. Browser playback starts from a user gesture. Saved background duration ranges from 30 to 600 seconds.
- Use fixed mix gains and one static peak-normalization factor recorded in render metadata. Playback gains do not change automatically.
- Default carrier is 220 Hz, tone gain is 0.2, and background gain is 0.6. Support carriers from 100 to 400 Hz and require the sum of tone and background gains to be at most 0.95.
- Profile edits create immutable versions containing the rendered background reference, source recipe, carrier, gains, loop settings, duration, and checksum. A version never embeds a fixed binaural action into its background.

### Contracts, APIs, and ownership

- Add versioned contracts for audio assets, mix recipes, immutable profile versions, calibration plans, feedback, meditation decisions, and personal EEG models.
- Extend session manifests with optional meditation metadata: protocol version, meditation mode, profile version, calibration plan and slot, fixed action, and model version. Preserve the existing raw upload/checksum contract.
- Extend the authenticated v1 API with asset upload/read/download, render creation/status, profile listing/version creation, idempotent calibration-plan create/read, idempotent feedback updates, meditation training requests, and latest-model retrieval including validation status.
- Store feedback separately from immutable session uploads, allowing later ratings without raw checksum conflicts.
- Add backend and mobile migrations for library data, downloads, calibration progress, feedback queues, personal models, and adaptive action statistics. Account ownership applies to all records, cached metadata, and files.
- Sync calibration plans before their sessions and feedback after session upload. Route meditation training independently of NIR training. Retries are idempotent and retain the existing deletion-first ordering.
- Session deletion removes feedback, invalidates affected models and action statistics, and rebuilds from remaining eligible data. Existing deletion tombstones continue preventing delayed restoration.

### Local playback and session lifecycle

- Mobile supports personal profile browsing, preview, download progress, cancellation, and local-copy removal. Download to a temporary file, verify format and SHA-256, then atomically mark it ready. Cache by account and immutable profile version.
- Require a verified local background to start. Playback, tone generation, adaptation, and session persistence make no network requests during the session.
- Use a bounded streaming WAV reader and stereo mixer. File reads and rendering occur outside the UI isolate while retaining PCM backpressure and the write watchdog.
- Mix left and right independently. Use a 500 ms linear overlap at background loop boundaries, then continue from the end of the overlapped opening segment.
- Generate tones at carrier minus half the frequency difference for the left ear and carrier plus half the difference for the right ear. The 0 Hz control uses the same tone in both ears.
- Change frequencies with a phase-continuous five-second glide and constant tone amplitude. Retain short amplitude ramps for session start and stop. Background position and profile gains remain unchanged during action changes.
- Run 600 seconds of active playback continuously, without a silent baseline or scheduled sound/pause blocks. Audio interruptions pause the session clock; resumption preserves the action and background cursor. Unrecoverable audio failure saves a stopped session.
- Poor or missing EEG retains playback and the current action while excluding affected periods from learning. Keep elapsed time and quality available without requesting ratings during meditation.

### Calibration and feedback

- Each ten-session series contains exactly two assignments for each difference: 0, 6, 8, 10, and 12 Hz. Shuffle and persist the complete schedule before its first session, and persist an attempt before playback.
- Use one fixed action for the full calibration session. Lock profile version, carrier, gains, duration, and eye state within a series. Setup changes begin another series; eligible series can later be pooled.
- Hide frequency labels in calibration session UI, history, notifications, and previews until the series finishes.
- A calibration slot completes only after a full session and both ratings. Interrupted attempts do not advance it. Completed sessions with missing feedback remain available for later rating.
- Collect integer 0–10 ratings after meditation only: mental busyness from none to extreme, and relaxation from none to complete. Combine them as (relaxation + 10 - mental busyness) / 2.
- Poor EEG does not invalidate the completed subjective comparison, but can exclude the session from EEG training.
- Recommend the action with the highest mean combined score for the current setup, falling back to pooled completed calibration results when no matching setup exists. Resolve ties in order 0, 6, 8, 10, 12 Hz. Allow a preference override after calibration.
- Offer additional ten-session series whenever more usable data is needed. Calibration and feedback remain durable offline and synchronize later.

### Personal EEG model and activation

- Train the personal model only from completed, rated calibration or fixed meditation sessions. Adaptive-session ratings are saved for descriptive outcome tracking and excluded from model training in this version.
- Reuse existing EEG quality checks. A minute contributes when at least two channels are valid for 80% of eligible seconds. Exclude the first ten seconds of every minute to cover filter startup or tone-transition effects.
- Use log theta/alpha and log beta/alpha power ratios, averaged across valid channels and eligible periods. Each session contributes one training row with its post-session score; minute windows are not independent labelled training samples.
- Fit per-person ridge regression with penalty 1, an unpenalized intercept, and training-data standardization. Include background asset identity, carrier, both gains, and eye state as context inputs.
- Require at least twenty usable sessions. Validate using leave-one-session-out predictions, fitting preprocessing inside each fold. Require mean absolute error at most 2 rating points, correlation at least 0.5, and at least 20% lower mean absolute error than a context-only model.
- Treat these thresholds as versioned engineering gates. Failed validation retains the preferred fixed action and offers further data collection.
- Enable adaptation only in contexts represented by at least five usable sessions, with the selected eye state represented and numerical settings inside training ranges. Unsupported contexts retain fixed playback.
- After successful validation, enable adaptation directly. A randomized adaptive-versus-fixed trial is not part of this release.

### On-device adaptive controller

- Download model coefficients, preprocessing, supported contexts, and validation status. Freeze the model version for each session and perform inference locally.
- Start with the preferred fixed action. Evaluate every sixty seconds and score the eligible EEG period using the frozen model.
- Use separate epsilon-greedy action statistics with epsilon 0.1, initialized from qualifying fixed-session minute scores. Persist statistics by account, exact setup, and model version.
- Update action statistics only from valid periods. Exploitation changes require an estimated advantage of at least 0.5 rating points; exploration may choose a different action. Apply changes using the five-second glide.
- Insufficient quality holds the current action and skips learning. Record action decisions, selection probabilities, scores, quality, model version, and transitions.
- Minute-level scores remain an experimental proxy for the user's post-session experience. The validation gate measures predictive association; it does not establish the benefit of adaptive changes.

## Testing Decisions

- Test observable behavior and public outputs rather than private helpers, internal call counts, implementation structure, or tests that duplicate production calculations. Prefer the highest practical existing boundary for each application.
- The user confirmed the primary boundaries: mobile session/controller behavior using a fake PCM output and real local persistence; authenticated backend API plus worker behavior; and browser user flows. Add focused signal and cross-language numerical checks where these application boundaries cannot identify an error reliably.
- Existing prior art includes controller tests with held starts and backpressured PCM writes, repository tests with in-memory databases and temporary files, upload retry and account-isolation tests, API tests using authenticated test clients, migration tests, and spectral/audio tests inspecting rendered samples.
- Exercise a complete mobile meditation through start, active playback, interruption/resumption, completion, persistence, and delayed feedback. Verify no in-session network dependency, optics-independent EEG progress, fixed gains, and correct terminal recording after audio failure.
- Test balanced schedules, persisted assignments and attempts, hidden labels on every user-facing calibration surface, setup locking, feedback-required completion, interrupted attempts, fixed preference scoring/tie handling, and restart recovery.
- Test download corruption, cancellation, atomic readiness, account/version cache separation, and local removal. Test sync ordering, idempotent retries, account changes, deletion tombstones, feedback removal, and model/statistics invalidation.
- Through authenticated API and worker boundaries, test valid and invalid imports, mono/stereo conversion, limits, owner access, immutable profile versions, preview/render consistency, bounded jobs, interrupted-worker recovery, and legacy/new migrations. Use real short audio fixtures and actual rendering for codec/mixing checks.
- Browser tests cover login, upload, editing, preview initiation, render status, profile save, and actionable failure states through user-visible controls. Avoid deep mocks of editor implementation internals.
- Focused PCM-output tests verify correct left/right tone pairs including control, preserved background stereo, mono duplication, clipping bounds, loop continuity, phase-continuous glides, constant amplitude during action changes, and bounded buffering. Reuse existing spectral checks where appropriate.
- Model tests use shared input/output fixtures to verify Python/Dart preprocessing and inference parity. Validate session-level splits, fold-local preprocessing, context-only comparisons, insufficient or degenerate data, all activation gates, unsupported contexts, source separation, and exclusion of adaptive sessions from training.
- Controller tests with deterministic action selection cover sixty-second evaluations, the 0.5-point exploitation threshold, exploration, poor-quality holds, skipped learning, frozen model versions, persisted statistics, and recorded decisions.
- Run existing core, Flutter, and backend suites to preserve NIR experiments, history, authentication, diagnostics, deletion, and upload behavior. Add web build and user-flow checks for the new editor.
- Complete physical Android acceptance checks for a full downloaded session in airplane mode, screen-off playback, audio interruption/recovery, and Muse quality loss. Simulator success alone does not complete hardware acceptance.

## Out of Scope

- Retiring the existing NIR experiments or rewriting their reward policy.
- iOS support, streamed session backgrounds, public/shared audio libraries, bundled licensed content, generative background creation, and a general-purpose digital audio workstation.
- More than four editor tracks, sources outside the agreed formats or limits, multichannel input beyond stereo, and changing profile gains or backgrounds during meditation.
- Pre-session or in-session ratings, silent baselines, within-session action changes during calibration, or visible calibration frequency labels before series completion.
- A universal EEG measure of meditation depth, claims of therapeutic benefit, an action assumed best for everyone, or enabling adaptation before the agreed data and validation gates.
- A randomized adaptive/fixed follow-up trial, causal efficacy conclusions from the predictive model, and training the EEG model from adaptive-session ratings in this release.
- Completing implementation tickets as part of publishing this parent spec. Ticket decomposition and implementation follow the engineering workflow separately.
