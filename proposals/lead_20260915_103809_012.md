### Steps to reproduce

1. Write a plugin following `docs/plugin_development.md`:
   - `android/build.gradle` with `compileOnly project(':dartnative_android')` (guide, "android/build.gradle — depend on dartnative_android for DNAppContext and friends")
   - Kotlin that calls `DNAppContext.get()` for a `Context`
   - a plain `dartnative: ^1.0.0` dependency in `pubspec.yaml`, as community plugins on dartpub.dev use (e.g. calendar_kit)
2. Run `dn plugin build` (or `dn publish`).

Expected: the AAR builds.

Actual: the build stops before Gradle with

```
battery_kit's android/build.gradle references project(':dartnative_android') but the framework checkout could not be located (via the pubspec `dartnative` path dependency). Build from the plugin monorepo, or vendor the binding.
```

`dn plugin build` only finds the binding when `pubspec.yaml` has a `path:` dependency on a framework package, which a community plugin cannot ship. The guide never mentions this, so a plugin that works fine inside an app (where the dn Gradle plugin wires `:dartnative_android`) cannot be published.

What worked instead, and what the guide could recommend for community plugins:

- Drop the `project(':dartnative_android')` dependency entirely.
- Take the `Context` from `FlutterPlugin.onAttachedToEngine(binding)` via `binding.applicationContext` and store it in the bridge object; clear it in `onDetachedFromEngine`. The generated registrant already instantiates the `pluginClass`, so this needs no extra wiring.
- The `io.flutter` plugin API is provided by the dn Gradle plugin in app builds and by the `dn plugin build` wrapper, so no dependency is needed for it.

With that change the same plugin built and published (battery_kit 0.1.0) and runs on a Pixel 8a.

Two smaller doc issues found while following the same guide:

- The `pubspec.yaml` examples for the plugin declaration use a `flutter:` top-level key (three occurrences, e.g. "Step 3. Declare the plugin class in your pubspec.yaml"). The key that the SDK actually reads, and that the shipped `dartnative_share` uses, is `dartnative:`.
- "`s.platform = :ios, '14.0'`" is below the minimum Xcode 27 accepts (15.0); `dn plugin build` already compiles for `arm64-apple-ios15.0`. (Filed separately for the `dn create` template.)
