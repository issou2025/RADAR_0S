# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**21 tools reject `null` for optional arguments whose schema default is `null`**

*Project description:*
### Tool name

`save_document` (and 20 others, listed below)

### What happened?

Optional arguments written `file_path: str = None` (also `dict = None`, `list[str] = None`, `float = None`, ...) are published as `{"type": "string", "default": null}`; `tests/tool_contract.json` pins exactly that for `save_document.file_path`. The advertised default isn't an allowed value, so a client that sends it back explicitly (several agent frameworks fill every optional field from the schema) gets a validation error before the tool runs. Expected: `null` behaves like the argument was omitted.

### Steps to reproduce

This doesn't need Revit: it's argument validation in the MCP SDK. I copied the `save_document` signature onto a stub tool registered with `mcp.server.fastmcp.FastMCP` (mcp 1.9.0, as locked in `uv.lock`; same result on 1.30.0) and called it over an in-memory client:

```
call save_document {"file_path": null}
```

With `file_path: str | None = None` the schema becomes `anyOf: [string, null]` and the same call runs.

### Error output

```text

file_path
  Input should be a valid string [type=string_type, input_value=None, input_type=NoneType]
```

### Fix

Annotation only: `T = None` becomes `T | None = None`. Callers that omit the argument see no change, and none of these `str` arguments carries JSON text. Since this changes 21 input schemas on purpose, `test_tool_contract_is_unchanged` fails on the patch until the snapshot is regenerated, so the PR would regenerate `tests/tool_contract.json` with the command in CONTRIBUTING and say so. I tried that locally: the regenerated contract differs only in those 47 properties, and `uv run pytest` passes (22 passed).

Happy to send that PR if you want it in one piece (or split by file). (Found with mcp-doctor, a static checker for MCP servers.)
