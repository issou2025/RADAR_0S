# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Inspect drift databases, with watch() streams that see the edits**

*Project description:*
`drift` is the most used typed database library for Flutter, built on SQLite. This issue adds `xray_drift_inspector`, a small package that shows an app's drift database in xRay's **Database** tab (see #56), and makes the app's `watch()` streams update when a row is edited from xRay. Setting it up is one line in the app.

## Background

xRay has two sides: the **SDK**, which you add to your Flutter or Dart app, and the **desktop app**, which shows what is happening inside that app. Each kind of data has an **inspector** you list in `XRayInspectorServerConfig(inspectors: [...])`. #56 adds the Database tab and the shared database support; each database engine then needs its own inspector package. A drift app works with its own database class (a `GeneratedDatabase`), and its UI usually listens to `watch()` streams, so an edit only helps if those streams hear about it.

## User story

As a Flutter developer whose app uses drift, I want to pass my database to an xRay inspector, so that I can browse, query and fix its data from the desktop app and see my app's UI update right away.

## Current behaviour

There is no way to see a drift database in xRay. Developers copy the database file off the device, and an edit made outside the app never reaches its `watch()` streams.

## Expected behaviour

1. The app adds `xray_drift_inspector` and registers `XRayDriftInspector(database: database)` with the database it already created.
2. The database shows in the Database tab, titled with its class name, with every table and view (also those created with `customStatement`) and their row counts.
3. Rows page, search and sort; the Query view runs SQL.
4. Read-only by default; `allowWrites: true` turns on adding, editing and deleting rows and queries that change data.
5. After an edit from xRay, the app's `watch()` streams re-run, so the UI shows the change without a restart.

## Acceptance criteria

- [ ] `XRayDriftInspector(database: database)` works with any `GeneratedDatabase`.
- [ ] Tables drift has no class for are listed too.
- [ ] A row edited in xRay makes a `watch()` on that table emit the new data.
- [ ] A query that changes data makes the app's streams re-run.
- [ ] Read-only queries run with writes off; other statements are refused by the app.
- [ ] A drift database encrypted with SQLCipher works without passing the key to xRay.
- [ ] The package is published on pub.dev with a docs page and an example.

## Out of scope

- Showing drift's Dart types (data classes, converters) instead of the stored SQLite values.
- Schema migrations from xRay.

## Edge cases

- The app holds a transaction → xRay's statements wait for it.
- A raw query that changes data → every table's streams re-run, because xRay does not work out which tables a statement touches.
- Several drift databases in one app → each shows with its own title.

## Workaround

Copy the database file off the device and open it in a SQLite tool; restart the app to see changes.
