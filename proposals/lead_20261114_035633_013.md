## 7. 趋势信号

以下信号从五个项目的社区反馈、缺陷报告和 RFC 活动中提取，代表**AI Agent 开发者应关注的新兴需求**：

### 🔴 高优先级趋势（已在生产环境造成痛点）

1. **凭证与模型上下文的隔离** — 每个项目都独立发现凭证可能通过工具输出、日志和持久化层泄露到模型上下文窗口。业界正趋向以只写凭证存储、作用域引用和出口代理作为缓解方案。**构建 Agent 框架的开发者应将凭证隔离作为一等架构需求，而非事后补救。**

2. **SQLite 负载下定时任务的并发安全** — 多个项目使用 SQLite 做任务持久化，在规模上遇到并发限制。这是整个生态系统的架构选择，需要通过更好的 busy_timeout 调优、WAL 模式优化或向更高并发存储迁移来解决。

3. **Windows 企业可靠性** — OpenClaw（P0）和 QwenPaw 均有重大 Windows 特有缺陷影响托管服务部署。随着 Agent 从开发者笔记本走向企业工作站，Windows 平价必须成为一等 CI 目标，而非尽力而为的附加项。

## 7. 用户反馈摘要

### 痛点

1. **v2.3.0 中微信不稳定**：升级到 v2.3.0 的用户遇到微信频道完全故障（启动时报 `ACCOUNT_IN_USE` 错误）和静默发送失败。这是目前对用户影响最直接的回归问题。

2. **升级路径导致插件陈旧**：升级机制不迁移内置频道插件，意味着从 v2.2.x 升级到 v2.3.0 的用户无法获得所有频道修复（#8559、#8558、#8584、#8599、#8411）。这造成了一种静默的版本碎片化，并非所有用户都能从最新版本中受益。

3. **Cron token 用量未被追踪**：定时任务的 token 消耗不会写入 `turns.jsonl`，导致 Console 用量面板呈现不完整的计费数据。运行自动化流水线的用户无法准确归因成本。

4. **Creator 性能随对话长度下降**：在创作助手输入框中打字时，每次按键都有延迟，且随对话长度增长而加剧。根因已确定：AgentDock 完全重渲染会重新解析所有对话 Markdown，没有 memoization。

5. **包含 `#` 的 Windows 路径处理**：保存在包含 `#` 的工作区目录下的附件在路径转换后无法解析，破坏了 Windows 用户在个人文件夹路径中出现 `#` 的工作流。

6. **CJK Markdown 渲染**：聊天消息中的 CJK 强调标记边界渲染不正确，原因是 CommonMark flanking 规则不兼容——这对中国用户群体来说是一个持续存在的 UI 质量问题。
