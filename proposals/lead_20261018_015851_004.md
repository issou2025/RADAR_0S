# Project Proposal — Autocad Drafting

## Project Understanding
You need assistance with: 
**[Ticket]: Check reduced motion (Reduce Motion / Remove animations) on a real Android phone and iPhone**

*Project description:*
### Type

Spike / Investigation

### Summary

We need someone to run fespalier's reduced-motion support (the `Transitions` presets and `RouteHero` honouring the system's "Reduce Motion" on iOS and "Remove animations" on Android, since 0.19.0; feature PR: #227) on a real Android phone and a real iPhone and tell us what the device does where no test can see: the system setting reaching the app, the Android predictive back gesture on a page that fades instead of moving, the iOS edge swipe, a sheet and a dialog opening at once, a hero that no longer flies, and a tab switch.

Expected result: an answer to each question below, per platform, with a short screen recording where the behaviour is visual.

### Intent

When the system asks for reduced motion, `Transitions.slide` cross-fades, `Transitions.material`, `cupertino` and `fullscreenDialog` fade in place while the page below stays still (they keep their `MaterialPage` / `CupertinoPage` types, so the back swipe and predictive back keep working), `dialog` and `sheet` open with no animation, `RouteHero` stops flying, and `fade` and `none` are unchanged. The widget tests set `disableAnimations` on a fake platform dispatcher; a device is the only thing that runs the real setting, the real back gesture and the real display.

### Source of truth (links)

- `docs/layouts.md`, "Transitions", the "Reduced motion" paragraph
- `skills/fespalier-layouts/references/transitions-and-restoration.md`
- `packages/fespalier/lib/src/reduced_motion.dart`
- Feature PR: #227

### Current Behavior

`packages/fespalier/test/reduced_motion_test.dart` passes with `FakeAccessibilityFeatures(disableAnimations: true)` and without it. Nothing has run on a device, and the Android predictive back gesture under reduced motion is UNCHECKED: no widget test drives it.

### Expected Behavior

Build `examples/tabs` and `examples/shop` in profile mode (`flutter run --profile`) and turn the setting on: iOS Settings › Accessibility › Motion › Reduce Motion; Android Settings › Accessibility › Remove animations (the name varies by vendor; "Animation scale: off" in developer options is a different switch, say which you used).

1. **Push and pop with `material`** (Android): open a detail page and go back with the button and with the back gesture. The new page appears by cross-fade, nothing slides or scales, the page below does not move, and the back gesture still pops. On Android 14 or newer with predictive back enabled in the app, say whether the peek still shows and whether the commit pops.
2. **Push and pop with `cupertino`** (iOS): the same, with the edge swipe from the left. The swipe still pops; the page below does not slide.
3. **`slide`**: the page cross-fades, no horizontal movement.
4. **A sheet and a dialog**: both appear at once, with no slide or fade-in; the sheet still drags to dismiss; the dialog's barrier appears at once.
5. **A hero** (the shop's list to detail): the image does not fly; it appears in place on the detail page.
6. **A tab switch** (`examples/tabs`): say what you see; the tab body is not animated by fespalier today, so this is a baseline.
7. **Toggle while running**: turn the setting off and on with the app in the background, come back and push a page. Pages follow the new setting at once; a dialog or sheet that was already open keeps the style it opened with.
8. **With the setting off**: run cases 1 to 5 again and confirm the usual motion is back (a regression check).

### Acceptance Criteria

- Each question is answered for Android and iOS, or marked "could not test" with the reason.
- The report lists the device, OS version, `flutter --version`, the fespalier commit, and a recording for cases 1, 2 and 5.

### Out of Scope

Changing the package. Report problems here.

### Technical Context

**Step by step:**

1. Clone the repository at the commit you test and run `cd examples/shop && flutter pub get && flutter run --profile` on the device; the same for `examples/tabs`.
2. Turn the system setting on and work through the cases, then off for case 8.

This needs some Flutter experience and a phone. Ask in a comment if anything is unclear.

### Risks

Flutter plays every animation controller at a twentieth of its duration while animations are disabled, so a fade is about 15 ms: it may look like "appears at once". Say what you saw rather than what the docs promise.
