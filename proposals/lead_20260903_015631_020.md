*Project description:*
## Summary

Google is moving Flow off Labs onto its own domain. On a **migrated** page load,
`https://labs.google/fx/tools/flow/project/<id>` redirects to
`https://flow.google.com/project/<id>` and serves a rewritten frontend that contains **zero
`<i>` elements**. Since cohort detection and every mode control are expressed as Material
Symbols ligature selectors (`i.google-symbols:text-is(...)`), nothing matches:
`detect_ui_mode` falls through to its classic default, the classic driver then misses
`mode_switch_trigger`, and the run dies with `UiSelectorDriftError`, exit 23,
`retryable: false`. Image and video alike.

**The migration flaps per page load.** The same account, same profile and same project land on
the old host on one load and the new host on the next, minutes apart, with no client change.
On an old-host load everything works end to end. That is almost certainly why this has not
been reported yet: whether you can reproduce it depends on which side your load happens to get.

`flow.google.com` appears nowhere in the source. Reproduced on 0.59.0, 0.62.1, 0.63.0 and
0.65.0 — nothing in between touches it. The incident bundle's own `ui.json` already flags the
host as unrecognised: `url.host_category: "other"`, `url.route: "other"`.

This is not #493 recurring and not the agentic cohort — the agentic indicators are absent too.
It is a different origin serving different markup.

## The two sides, measured

Same profile, same project, ~35 minutes apart, gflow **0.63.0** on both, nothing changed
locally in between:

| | old host | migrated host |
|---|---|---|
| final URL | `labs.google/fx/<locale>/tools/flow/...` | `flow.google.com/project/...` |
| `document.querySelectorAll('i').length` | **55** | **0** |
| `i.google-symbols` | **49** | **0** |
| `crop_*` trigger | **present** | **absent** |
| agentic indicators | absent | absent |
| `gflow image t2i` | `mode_switch_trigger` matched, `image_mode_tab` matched, NARWHAL, 9:16, submitted, HTTP 200, image downloaded, **exit 0** | `UiSelectorDriftError`, **exit 23** |

So the selectors are not stale in themselves — they are correct for the host they were written
against, and that host is being replaced under them.

Other notes on the migrated page: `console` is clean (0 errors — it is a healthy page, not a
broken render), `document.fonts` still lists `Google Symbols` (the font loads, it is simply no
longer applied to `<i>` elements), and `[aria-haspopup='menu']` does match several elements —
but they are project/grid/overflow menus, with no aspect or mode dropdown among them. The
composer is one bar: a text box, an **Agent** pill, and a single chip collapsing output type,
resolution, duration and count.

## Reproduction

Read-only, spends nothing, no generation needed. Run it a few times — that is the point:

```python
# launch a persistent context on an authenticated Flow profile, then:
await page.goto("https://labs.google/fx/tools/flow/project/<project-id>",
                wait_until="domcontentloaded")
await page.wait_for_timeout(9000)          # let the composer render
print(await page.evaluate("() => ({"
    "url: location.href,"
    "i_total: document.querySelectorAll('i').length,"
    "symbols: [...document.querySelectorAll('i.google-symbols')].map(e => e.textContent.trim()),"
    "})"))
```

- old host → `{'url': 'https://labs.google/fx/...', 'i_total': 55, 'symbols': ['crop_16_9', ...]}`
- migrated → `{'url': 'https://flow.google.com/project/...', 'i_total': 0, 'symbols': []}`

If every load gives you the old host, your account has not been rolled into the migration yet.

## Ruled out

Each tested, not assumed:

- **Stale version** — reproduced on four releases including the current one.
- **Project size** — a brand-new empty project fails identically. Diagnostics from a heavily
  populated project (`img 50, div 522, button 124`) and an empty one
  (`img 3, div 69, button 12`) both report `crop_present: false`, `ligature_count: 0`.
- **Browser version** — a newer Chrome was staged on the machine but never became active; the
  failing session reports the same Chrome major as the working one.
- **Classic-mode workaround** — logs already show `ui_mode: classic` bound (post-#596), and
  `mode_control.ensure_media_incomplete` still reports "classic media panel not restored".
  `GFLOW_CLI_PREFER_CLASSIC` is deprecated and adds nothing.

## Suggestion

Two things would help users well before full selector support for the new frontend:

1. **Detect the host and say so.** When the final URL is on `flow.google.com`, fail with a
   distinct, retryable error naming the migration instead of `UiSelectorDriftError` — which
   reads like the selectors rotted and sends people hunting in the wrong place.
2. **Treat it as retryable.** Because the migration flaps per load, a re-navigation often
   lands back on the old host and succeeds. Today the error is `retryable: false`, so callers
   with automatic retry give up on something that would very likely work on the next attempt.

Happy to run further read-only probes on an affected account and post the results; the failure
happens before submission, so broken attempts cost no credits and it is cheap to iterate.
