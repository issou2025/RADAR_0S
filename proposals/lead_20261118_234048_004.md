# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**am-feedback-scout: the session filter matches every session, and the nudge re-reads a window that am-feedback just covered**

*Project description:*
**Sessions read:** 2 local Claude Code sessions on 2026-11-18, and the subagent transcripts of one of them.

## Context

Related: #201. The nudge in `hooks/feedback-scout-nudge.ps1` fired about 4.7 hours after its last nudge. The agent then started `archi-magic:am-feedback-scout` in the background, with `since` set to the last nudge time. In that window there was one manual multi-session am-feedback run (it posted 9 issues and 2 comments), one PR session on this repo, and 11 repo subagents. No session called a pyRevit tool.

## What happened

- **The filter matches every session.** Step 1 of `agents/am-feedback-scout.md` keeps the files that contain `"skill": "archi-magic:`, `Launching skill: archi-magic:`, or `mcp__pyrevit__`.
  - `mcp__pyrevit__` is in the tool list that Claude Code writes into the transcript when the pyRevit MCP server is connected. Both sessions matched (23 and 2 hits). Neither made a pyRevit call (0 `tool_use` blocks with that name).
  - `"skill": "archi-magic:` (with a space) never matches. The transcripts are compact JSON: `"skill":"archi-magic:`. Only `Launching skill:` matched.
  - The am-feedback run itself counts as an archi-magic session, so the scout reads the feedback work as if it were Revit work.
  - Result: on a computer with the pyRevit server set up, "keep only the files that used archi-magic" keeps every session.
- **Subagent transcripts are not read.** The glob `projects\*\*.jsonl` does not include `<session>\subagents\*.jsonl`. On this computer, 1 of 28 subagent transcripts made pyRevit calls. The scout would miss friction in such a subagent.
- **The nudge does not know about a manual run.** The manual am-feedback run had already read every session and posted its feedback a few minutes after the window start. The scout read the same window again. It started right after the account's 5-hour usage limit reset, while 9 resumed subagents were also running.
  - cost: one extra background agent run, with little new to find.

## Proposed change

- `agents/am-feedback-scout.md` step 1:
  - Match real calls, for example the regex `"type":"tool_use","id":"[^"]+","name":"mcp__pyrevit__`, not the bare string.
  - Match skill launches with an optional space: `"skill":\s*"archi-magic:am-`. Do not count `am-feedback` itself as archi-magic use.
  - Also read `*\subagents\*.jsonl`, grouped with the parent session.
- `skills/am-feedback/SKILL.md` step 8: after a post, write the post time to `%LOCALAPPDATA%\archi-magic\feedback-scout.json` (for example `last_feedback_post`). In `hooks/feedback-scout-nudge.ps1`, use the later of `last_nudge` and `last_feedback_post` as `since`, or skip the nudge when a post happened inside the interval.
- Optional: the scout returns "no new feedback" at once when the window has no pyRevit calls and no am-* skill launches other than am-feedback.

## Acceptance ideas

- A fixture transcript with the pyRevit tool list but no pyRevit call is not selected.
- A fixture transcript with `"skill":"archi-magic:am-safe-change"` (no space) is selected.
- A pyRevit call in a subagent transcript is found.
- After am-feedback posts, the next nudge uses the post time as `since`.

## Not verified

- If every Claude Code version writes the tool list into the transcript. Seen with Claude Code 2.1 on Windows.
- Which hook event fired this nudge.
