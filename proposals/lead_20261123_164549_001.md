# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**PR: IFC4X3 export: Qto_WallBaseQuantities uses "GrossFootprintArea" instead of "GrossFootPrintArea" (Validation Service rule QTY001)**

*Project description:*
### Problem Description

### Summary
When exporting to IFC4X3 (IFC 4.3 ADD2) with *Export base quantities* enabled, walls are written with
`Qto_WallBaseQuantities.GrossFootprintArea` (IFC4 spelling). In IFC 4.3 this quantity is named
`GrossFootPrintArea` (capital P). The buildingSMART Validation Service reports it as an error under
normative rule **QTY001**.

### Steps to reproduce
1. Model a basic wall.
2. Export to IFC4X3 Reference View with *Export base quantities* = ON.
3. Validate the file at https://validate.buildingsmart.org

**Expected:** `Qto_WallBaseQuantities.GrossFootPrintArea`
**Actual:** `Qto_WallBaseQuantities.GrossFootprintArea`, which gives QTY001 once per wall (screenshot attached).

### Cause in the source code
- `Source/Revit.IFC.Export/Exporter/ExporterInitializer_QsetDef.cs` (IFC4x3 block, ~line 8780) correctly defines `GrossFootPrintArea`.
- Walls, however, are processed by `PropertyUtil.CreateWallBaseQuantities`
  (`Source/Revit.IFC.Export/Exporter/PropertySet/PropertyUtil.cs`, ~line 2308), which hard-codes `"GrossFootprintArea"`.
- `GetPreIfc4QuantityNameIfNeeded` only remaps names for IFC2x2/IFC2x3 and returns the IFC4 name unchanged for IFC4 and later, so the IFC4X3 name is never applied.
- The same code is still present in tag `IFC_v27.4.0.30`.

### Suggested fix (not compiled/tested)
```csharp
// GrossFootprintArea (IFC4) / GrossFootPrintArea (IFC4X3)
string footprintName = ExporterCacheManager.ExportOptionsCache.ExportAs4x3
   ? "GrossFootPrintArea" : "GrossFootprintArea";
quantityName = GetPreIfc4QuantityNameIfNeeded(quantitySetName, footprintName);
```
(Parameter-mapping lookups that use this quantity name may need the same distinction.)
