*Project description:*
## What is missing

A scene object cannot carry **typed** named properties in **named property sets** to the IFC file. FloLess is adding user attributes (the equivalent of Tekla UDAs, Revit parameters and IFC property sets) to every object in its steel model. They must reach the IFC export without losing their type, unit or length.

Today, on `origin/main` (4c519c7d9):

| What | Today | Source |
|---|---|---|
| Property value type | Member and extrusion labels are read from one **string** map and written only as `IFCLABEL` | `cli/src/render/ifc.rs:2780–2842` |
| Length | `IfcLabel` is STRING(255), so FloLess shortens longer values before it sends them, with a marker | floless.app `server/element-export.ts:12–27` |
| Set and relation GUIDs | Stable, but derived from the element key alone, so one object cannot hold several sets with stable ids | `ifc.rs:2608` and around it |
| Set names | Validation guards standard `Pset_` prefixes; there is no way to name a custom set per value | `ifc.rs:1883` |
| Object kinds | Plates, fasteners and welds use separate emission paths from members (`ifc.rs:1619,1683,2109,2279`), so a property shape must be attached to each | — |

## What is needed (generic, no FloLess vocabulary)

An **additive, versioned** scene property-set shape. Existing string labels and built-in/common psets keep working.

- Per object: `propertySets: [{ name, properties: [{ name, type, value, unit? }] }]`, where:
  - `type` is one of `label | text | integer | real | length | area | volume | mass | date | boolean | enumerated`;
  - `text` is written as `IfcText`, with no 255-byte limit;
  - measures use the project units (`IfcLengthMeasure` and others);
  - dates are written as `IfcDate`;
  - `enumerated` is `IfcPropertyEnumeratedValue`.
- The shape attaches to every emitted object kind: members, extrusions, plates, fasteners, welds and assemblies.
- **Stable GUIDs per object and per set.** A second export of an unchanged scene keeps every set and relation id.
- **Per-value receipts in the result:** written, converted (with the conversion named), or not written with a reason. Nothing is silently shortened.
- **Support negotiation**, so a caller can tell an AWARE that writes typed psets from one that does not.
- Correct STEP escaping for long and multi-line text.

## Acceptance

Unit tests that read a written file back:
- an `IfcText` of at least 10 kB round-trips byte for byte;
- a length in mm comes back with its unit;
- `IfcDate` and enumerated values come back as written;
- two custom sets on one plate both come back;
- set and relation GUIDs are identical across two exports.

The existing label path is unchanged, and the release notes name the new shape.
