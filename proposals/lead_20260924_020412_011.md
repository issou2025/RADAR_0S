# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[v10] Revamp webdriver.io: modern design, agent-first docs, new information architecture and Vercel hosting**

*Project description:*
## Why

webdriver.io still looks and reads like the Docusaurus 2-era site it grew from. With v10 we want to relaunch the website so that:

1. It looks like a modern developer tool (think [vite.dev](https://vite.dev) / [expo.dev](https://expo.dev)): slick, minimal, with small animations that explain what WebdriverIO does.
2. **Coding agents are a first-class audience.** Most users now work with WebdriverIO through an agent (Cursor, Claude Code, Copilot, …). When we have to choose, we optimize for agents first and humans second.
3. The homepage clearly says why to pick WebdriverIO over other testing tools: **community-driven and openly governed** (OpenJS Foundation), and **one framework for every platform**: browser, mobile (web/hybrid/native), desktop (macOS, Windows, Linux), apps like VS Code and Electron, and visual testing. It should also highlight the newer ecosystem tooling, [DevTools](https://github.com/webdriverio/devtools) and [MCP](https://github.com/webdriverio/mcp).
4. Users can find answers quickly, because the docs are organized around what they are trying to do rather than how the repo is laid out.
5. The site is hosted on **Vercel**, with preview deployments for every docs PR.

Constraints: we keep the current color scheme (WebdriverIO orange `#EA5906`) and keep Docusaurus.

## Current state (from an audit of `website/` on `v10`)

- **Homepage** (`website/src/pages/index.tsx`): ribbons canvas background (`/js/ribbons.js`), robot SVG, four "highlight" blocks (component testing, create-wdio, a YouTube talk, and the Lighthouse integration). It doesn't mention mobile-native, desktop, VS Code, visual testing, DevTools, MCP or open governance. The tagline is still "Next-gen browser and mobile automation test framework for Node.js".
- **Navbar**: 6 left items plus version, locale and 4 social icons. The version dropdown label is hardcoded to `v9`, and `GettingStarted.md` still says "docs for >=9.x".
- **Sidebar** (`website/_sidebars.json`, extended at generate time by `scripts/docs-generation/*`): 17 top-level categories that mix concepts, platforms, testing types and product areas. Services and reporters are appended as two huge flat lists. The mobile docs are thin and buried (Appium sits under "Configuration"). There's no page for Linux desktop, and `automationProtocols`, `enterprise` and `sponsor` aren't in the sidebar at all. Outdated migration guides (v6, v7, Protractor, sync→async) sit next to the v10 guide.
- **Agent surface**: already partly done in #15492 (`robots.txt`, `llms.txt`, `llms-full.txt`, Markdown twins for every page, `sitemap.lastmod`, mermaid in Markdown). Still missing: curated per-topic indexes, content negotiation, "copy for agent" page actions, a docs MCP endpoint, and agent-oriented writing conventions.
- **Deployment**: `deploy.yml` (manual dispatch) runs `pnpm run docs`, which runs `scripts/updateDocs.ts`. That script uploads to S3 bucket `webdriver.io` / `vX.webdriver.io`, invalidates CloudFront and deletes stale objects. The major version is derived from `lerna.json`, and there are no preview deployments.
- **Tech debt**: Google Analytics is still configured with a Universal Analytics ID (`UA-47063382-1`), and UA was sunset in 2023, so it collects nothing. Other items: the PWA plugin with a custom service worker (a risk of stale caches after the host moves), render-blocking Google Fonts (`display=block`), third-party `buttons.github.io` and `ribbons.js` scripts, redirects done on the client instead of as real 301s, and `website/README.md` still describing Docusaurus 2 with yarn.

## Plan

Work is ordered so that each step unblocks the next. Hosting comes first, so every later PR gets a preview URL. Each numbered item is meant to be one PR (or a small set of PRs).

### Phase 0: Decisions & alignment

1. **Sign off on this plan and the target information architecture (step 7)** with the maintainers/TSC before any content moves.
2. **Decide the open policy questions**:
   - Which locales to keep building. We have 13 locales, translations lag behind English, and the restructure will invalidate many translated pages.
   - AI crawler policy in `robots.txt` (training vs. retrieval agents; see the discussion in #15492).
   - The analytics replacement: Vercel Web Analytics, Plausible or GA4.
   - Whether to keep the Mendable AI chat widget once we have better agent tooling.

### Phase 1: Move hosting to Vercel

3. **Set up Vercel projects and the build pipeline**
   - Apply to the Vercel open source sponsorship program and create a `webdriverio` team/project. Coordinate DNS ownership with the OpenJS Foundation.
   - Build in GitHub Actions and deploy with `vercel build` + `vercel deploy --prebuilt`, rather than relying on Vercel's own build. `docs:generate` needs the whole monorepo (JSDoc, protocols, READMEs, i18n download), and a multi-locale build risks hitting Vercel's build limits.
   - Add a `website-preview` workflow that posts a preview URL on PRs touching `website/`, `scripts/docs-generation/` or package READMEs. Fork PRs don't get secrets, so they fall back to Vercel's Git integration or a maintainer-triggered preview.
   - Production deploys: for now, a manual dispatch plus a deploy on release. Secrets needed: `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`.
   - Enable Docusaurus Faster (Rspack/SWC via `future.experimental_faster`) and bump all `@docusaurus/*` to the latest 3.x, to cut build time.
4. **Add `website/vercel.json`**
   - `cleanUrls`, plus a `trailingSlash` setting that matches Docusaurus.
   - Move the `client-redirects` entries to real server-side 301 redirects. This matters for agents and SEO, because client-side redirects are only meta-refresh pages.
   - Long-lived immutable caching for `/assets/**`, and correct `Content-Type` for `*.md`, `llms*.txt` and `sitemap.xml`.
   - Content negotiation: rewrite `/docs/*` to the Markdown twin when the request carries `Accept: text/markdown` (a `has` header condition).
5. **Handle versioned sites and the cutover**
   - Add `v10` to `docusaurusVersions.ts` and make the navbar version label dynamic.
   - v10 is served at `webdriver.io`, and the `v9` branch moves to `v9.webdriver.io` (a separate Vercel project tracking the `v9` branch).
   - Keep v8 and older on S3/CloudFront, or freeze them as static Vercel deployments.
   - Ship a self-unregistering service worker (or keep a no-op `sw.js`) so returning PWA users don't get stuck on a stale cached site. Then remove `@docusaurus/plugin-pwa`.
   - DNS cutover checklist: TLS, apex + `www`, and a smoke test of the top 100 URLs from analytics and search console.
6. **Decommission the AWS path**: remove `scripts/updateDocs.ts`, the `docs:deploy` script and the AWS secrets from `deploy.yml`. Update `website/AGENTS.md`, `website/README.md` and `CONTRIBUTING.md`.

### Phase 2: Information architecture

7. **Restructure the docs around user tasks and platforms.** Proposed top-level structure (to be confirmed in step 1):
   - **Get Started**: Why WebdriverIO, Quick start (`npm init wdio@latest` and a first test in under 5 minutes), choosing a setup (test runner vs. standalone), project anatomy, **Using WebdriverIO with AI agents** (MCP, `llms.txt`, agent rules).
   - **Writing Tests**: selectors, interacting with elements, auto-waiting & timeouts, assertions/matchers, page objects, network mocking & spies, emulation, snapshots, custom commands, parameterized tests, organizing suites.
   - **Platforms**, each with its own landing page, a minimal working config and deep dives:
     - Web: E2E, cross-browser/BiDi, component testing for React/Vue/Svelte/Solid/Preact/Lit/Stencil/Nuxt.
     - Mobile: Appium setup, native iOS/Android, hybrid/WebView, mobile web, Flutter, real devices and clouds.
     - Desktop: macOS, Windows, Linux, plus Electron, Tauri and Dioxus.
     - Apps & extensions: VS Code extensions, browser extensions.
   - **Testing Types**: visual, accessibility, OCR, performance.
   - **Running Tests**: configuration file, capabilities, CLI, frameworks (Mocha/Jasmine/Cucumber), parallelism & sharding, retries, watch mode, headless/Xvfb, multiremote, Selenium Grid & cloud providers, Docker, CI (GitHub Actions, Jenkins, Bamboo).
   - **Debugging**: the DevTools app (live mode, trace mode, trace player, Allure, cross-framework support), IDE debugging, REPL, recorder, browser logs.
   - **Extending**: custom services, custom reporters, writing plugins.
   - **Upgrade**: the v10 migration guide first. Move v6/v7/Protractor/sync→async guides into an "Archive" section that is excluded from `llms.txt` and search boosting.
   - **Reference** (the "API" navbar item): the browser/element/mock/expect APIs, protocols, a **full configuration reference** (split out of `Configuration.md` / `ConfigurationFile.md`), a CLI reference, and environment variables.
   - **Ecosystem** (new navbar item): a filterable directory of official and community services, reporters and cloud providers, replacing the two giant sidebar lists. Also covers the DevTools and MCP product pages.
   - **Community**: support, events, governance, contributor stipends, team, contribute, sponsor.
8. **Preserve every URL**: use the `slug` frontmatter to keep existing URLs where the conceptual page still exists. Generate a redirect map (old path → new path) that feeds `vercel.json` and is checked in CI, so no existing link returns a 404. Keep the frontmatter `id`s stable, per `website/AGENTS.md`.
9. **Update the generation scripts** (`scripts/docs-generation/*`) so that generated pages (services, reporters, Electron/Tauri/Dioxus, protocols, 3rd-party plugins) land in the new sections, and the ecosystem directory is fed from the same metadata (`3rd-party/*.json` + package READMEs).
10. **Rework the navigation**: the navbar becomes Docs, Reference, Ecosystem, Blog, Community, plus a highlighted Sponsor button on the right. Collapse the 4 social icons into GitHub + a "Community" dropdown. Each section gets a card-based landing page ("Pick your platform"). Add breadcrumbs and a "Next steps" block on every guide.
11. **Update the Algolia DocSearch crawler** config for the new structure and add facets (section, platform).

### Phase 3: Optimize for coding agents

12. **Write agent-first content guidelines** as a docs style guide, linked from `website/AGENTS.md` and `CONTRIBUTING.md`:
    - Every page gets frontmatter `title` + `description` (the description is what `llms.txt` and search snippets show).
    - Pages open with a one-paragraph summary of what the page solves.
    - Examples are **complete and copy-pastable**: imports, ESM, TypeScript first, v10 APIs only, file names in code-fence titles. No `// ...` fragments where a full example is feasible.
    - The canonical answer comes first, and alternatives or edge cases come after. Include explicit version notes ("since v10"). Keep one concept per page, with stable heading anchors for deep links.
    - Don't hide essential content in tabs, videos or images alone. Everything in them must also exist as text.
    - Every platform page ends with a "Troubleshooting / common errors" section containing the literal error messages, so agents can match on them.
13. **Improve the machine-readable surface** (building on #15492):
    - A curated `llms.txt` with a hand-ordered index, instead of the plugin's default ordering.
    - Per-section bundles (`/llms/mobile.txt`, `/llms/desktop.txt`, `/llms/api.txt`, …) so agents can load only the context they need.
    - Archive and translated pages excluded from these bundles.
    - A CI check that validates `llms.txt` links, the size budgets of the bundles, and that every doc has a `description`.
14. **Add page actions on every doc page**: "Copy page as Markdown", "View as Markdown", and "Open in ChatGPT / Claude / Cursor" (prefilled with the page's `.md` URL).
15. **Publish a docs MCP endpoint**: either a small serverless function on Vercel (`webdriver.io/mcp`) exposing `search_docs` / `get_page` over the Markdown corpus, or docs tools added to [`@wdio/mcp`](https://github.com/webdriverio/mcp). Document the one-line setup for Cursor, Claude Code, VS Code and Codex.
16. **Add a "WebdriverIO for coding agents" guide**: MCP setup, a recommended `AGENTS.md` / Cursor rules / Claude skill snippet for WebdriverIO projects (conventions, commands, how to run a single spec, where the config lives), and how to feed DevTools `trace.zip` files to an agent. Follow-up in `create-wdio`: optionally generate that `AGENTS.md` in new projects.
17. **Improve the API reference output for agents**: every command page should have the signature, a parameter table with types, the return type, at least one complete example, and related commands. Fix gaps in the JSDoc at the source rather than in the website.
18. **Build a docs eval harness**: a set of ~20 real tasks (e.g. "set up an Android native test on BrowserStack", "mock a network response", "visually compare a component", "test a VS Code extension"). An agent attempts each one using only the docs, and we track the success rate before and after the revamp. Run it on demand, and in CI for PRs that touch docs, if the cost allows.

### Phase 4: Design refresh

19. **Build a design system on top of the Docusaurus theme** (`src/css/custom.css` plus swizzled components where needed):
    - Keep the orange brand color, add a refined neutral palette, and make dark mode the showcase (light mode stays fully supported).
    - Self-host fonts (Inter/Geist for text, JetBrains Mono/Geist Mono for code) with `font-display: swap`, replacing the render-blocking IBM Plex from Google Fonts.
    - A "grid lines + bordered panels" layout language like vite.dev, subtle orange glows and gradients, consistent radii and spacing tokens.
    - Restyle the navbar, sidebar, TOC, admonitions, tabs, cards, code blocks (file-name titles, line highlighting, copy button) and the footer.
20. **Clean up performance and dependencies**:
    - Remove `ribbons.js`, the `Robot` component, `buttons.github.io`, the dead UA analytics, `react-lite-youtube-embed` where it isn't needed, and unused CSS.
    - Optimize images (SVG/AVIF) and set a Lighthouse budget in CI (performance and accessibility ≥ 95).
    - Refresh the announcement bar content and make it dismissible.
21. **Make animations minimal and purposeful**: CSS/SVG only (no heavy animation libraries), lazy-started when they scroll into view, and fully disabled under `prefers-reduced-motion`. Candidates:
    - **Hero, "one test, every platform"**: an isometric diagram in the vite.dev style. A central WebdriverIO block sends command "packets" along lines to tiles for Browser, iOS/Android, macOS/Windows/Linux, VS Code and Electron, and each tile lights up as its step runs.
    - **Standards**: a command travelling over WebDriver/WebDriver BiDi to Chrome, Firefox, Safari and Edge.
    - **Get started in seconds**: a refreshed terminal animation of `npm init wdio@latest` (modernizing `CreateProjectAnimation.tsx`).
    - **Visual testing**: a before/after slider with the diff region highlighted.
    - **MCP**: a chat prompt → the agent calls `@wdio/mcp` tools → a browser or phone performs the steps.
    - **DevTools**: scrubbing through a trace timeline with screenshot, network and console panes.

### Phase 5: New homepage & messaging

22. **Rewrite the homepage** (`src/pages/index.tsx`, new components) with this narrative:
    1. **Hero**: a value-focused headline (e.g. "Test every platform your users are on"), a subline ("Open source, openly governed test automation for web, mobile, desktop and beyond, built on web standards and ready for your coding agent"), the CTAs Get Started / Set up with your agent (MCP), a copyable `npm init wdio@latest` with package-manager tabs, and the hero animation.
    2. **One framework, every platform**: tabs or cards for Browser (E2E + component), Mobile (web/hybrid/native, Flutter), Desktop (macOS, Windows, Linux), Apps (VS Code, Electron, Tauri, extensions) and Visual testing. Each has a short, real code snippet and a deep link.
    3. **Built for AI-assisted development**: the MCP server, agent-ready docs (`llms.txt`, Markdown pages, docs MCP) and DevTools traces that agents can read.
    4. **Debug with WebdriverIO DevTools**: live mode and trace mode, and the fact that it also works with Selenium and Nightwatch.
    5. **Community-driven & open governance**: OpenJS Foundation, open governance, no paywalled features, no vendor lock-in, the contributor stipend program, live stats (contributors, weekly downloads, Discord members) and the contributor wall.
    6. **Built on web standards**: WebDriver + BiDi for true cross-browser testing.
    7. **Ecosystem**: counts of official and community services/reporters, cloud providers, and a link to the Ecosystem directory.
    8. **Trusted by** (logo carousel), **Sponsors**, and a final CTA.
    - Remove or relocate: the Lighthouse highlight and the embedded YouTube talk (move to Community → Materials).
23. **Update the site-wide messaging**: the new `tagline` and `siteDescription` (config, `llms.txt`, OG tags), new OG/social images, and a rewritten "Why WebdriverIO" page that matches the homepage narrative, including an honest "WebdriverIO vs. other tools" section.

### Phase 6: Content pass

24. **Rewrite section by section** using the step-12 guidelines, in priority order:
    1. Get Started
    2. Platforms → Mobile, which is the largest gap
    3. Platforms → Desktop, adding a Linux page
    4. Agents guide
    5. Running Tests / Configuration reference
    6. Debugging / DevTools
    7. Everything else

    Each section is one PR with a preview URL, and each is re-checked with the eval harness from step 18.
25. **Prune and merge content**: deduplicate overlapping pages (e.g. `Configuration.md` vs `ConfigurationFile.md`, `BestPractices.md` vs `best-practices/*`, `Devtools.md` vs `devtools/*`), fix or remove pages that aren't in the sidebar, and move outdated content to Archive.
26. **Coordinate i18n**: sync the new structure with `webdriverio/i18n` and apply the locale decision from step 2. Make sure `test-docs.yml` keeps building an en + non-en locale.

### Phase 7: Launch with v10

27. **Final QA**:
    - No broken links, and the redirect map is verified against the top URLs.
    - Accessibility audit, and Lighthouse budgets pass.
    - Search re-indexed; `llms.txt` and the docs MCP verified with Cursor and Claude Code.
28. **Cut over DNS** to Vercel alongside the v10 release, and publish a blog post ("Introducing the new webdriver.io") explaining the new structure and agent features.
29. **Follow up after launch**: monitor 404s and search queries with no results via analytics and Algolia, and feed them back into content and redirects.
