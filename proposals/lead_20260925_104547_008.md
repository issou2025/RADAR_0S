# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**feature(workout): add exercise media (image/video URLs) to bundled catalog**

*Project description:*
## Summary

W3A2a (PR #339) shipped the bundled Exercise catalog as text-only, so it dropped the image and video media the owner source already has. This issue brings exercise media back into the catalog so the Exercises list (W3A2b) and Exercise Detail (W3B) can show images and videos.

Linear: [TNYX-274](https://linear.app/tnyx/issue/TNYX-274/w3a2a-f2-add-exercise-media-imagevideo-urls-to-bundled-catalog). Parent: TNYX-270 (W3A2).

## User Problem

Users browsing exercises need to see what each exercise looks like: a thumbnail in the list and a demo video in detail. A text-only catalog cannot show that.

## Proposed Behavior

**Owner decision:** media loads straight from the provider-hosted URLs in the owner source (`apilyfta.com`, some `cloudfront.net`). The owner's Tnyx-hub app already does this (`cached_network_image` for images, `VideoPlayerController.networkUrl` for video). The owner holds the full media data and maintains the URLs directly in the catalog JSON. No self-hosting is required, and the slice is not gated on licence evidence.

Source facts (`apps/core/assets/exercises/exercises_data.json`, owner file):
- All 101 rows have `media`: `type`, `defaultGender`, and `male` / `female` → `imageUrl`, `videoUrl`, `thumbnailUrl`.
- `imageUrl`: 101 male / 98 female. `videoUrl`: 98 male / 92 female. `thumbnailUrl`: only 4, so the list thumbnail falls back to `imageUrl`.

Planned slice:

```text
catalog: the owner-curated exercises_data.json (101 rows, no YouTube IDs or dead links, male/female set) becomes the Workout catalog content as-is, with all fields and the male/female structure unchanged, in the version envelope (replaces the text-only projection)
document: bump schemaVersion 1 → 2 in ExerciseCatalogDocumentDecoder
data: extend the W3A1 row DTO/parser to read and validate media now (https URLs, male/female variants, defaultGender); other curated fields ship and are read when their slice needs them
domain: add a canonical media value to Exercise in apps/shared (no second Exercise model)
tests: update the production-asset test to reflect the curated content (no longer a text-only allowlist) + parser/decoder/gender-selection tests
docs: update docs/screens/exercise-search.md and docs/MODULE_OWNERSHIP.md
```

States: an exercise without an image or video falls back to text-only (no broken placeholder). Offline, remote media is simply unavailable while the text catalog keeps working.

### Platform media contract (owner, 2026-09-25)

| Surface | Image / thumbnail | Video |
|---|---|---|
| Phone (`apps/app` + `apps/features/workout`) | YES | YES |
| Wear OS (`apps/wear`, Flutter) | YES (only) | NO |
| Apple Watch (`apps/watchos`, Swift) | YES (only) | NO |

- Tio-world is the clean rebuild of what already works in Tnyx-hub (`apps/flutter`) and Tio-hub. Tio-hub wear resolves an exercise image from a local asset first, then `media.<gender>.imageUrl`, then `thumbnailUrl`.
- The canonical media value lives in pure-Dart `apps/shared` so phone and Wear OS share it. watchOS consumes the same catalog contract (bundled or phone-synced; decided in the watch slice).
- Watch surfaces stay lightweight: image only, and never download or play video on the watch.
- Domain change: the owner will move media to a new domain later and update the full URLs in the JSON directly (see decision 3).

Decisions needed before implementation:
1. Phone list thumbnail in W3A2b (TNYX-272) rows? **Resolved (owner, 2026-09-25): YES.** The W3A2b contract is updated; this issue blocks and lands before TNYX-272.
2. Gender variant. **Resolved (owner, 2026-09-25): media follows the user's gender.** `male` → `media.male`, `female` → `media.female` (profile `ProfileGender` / `users.gender`); `other` / not set → `media.defaultGender`. If that variant lacks the asset, fall back to the `defaultGender` variant, then the other variant, then text-only. The selection happens in a domain/controller rule (not widget logic), shared by phone and watch.
3. URLs. **Resolved (owner, 2026-09-25): keep the full URLs exactly as in the curated source.** The owner updates the domain in the JSON.

Non-goals: rendering UI on any platform (phone list thumbnail = W3A2b / TNYX-272, phone video player = W3B / TNYX-262, watch image rendering = Wear OS / watchOS workout slices), reading instructions/standards/localized titles in code (they ship in the asset for later slices), curating the 5k+ raw pool, self-hosting media.
