# Project Proposal — Python Automation

## Project Understanding
You need assistance with: 
**Feature: attachment extraction fallback via JXA when the .emlx is not readable (no Full Disk Access)**

*Project description:*
### Environment
- apple-mail-mcp 0.4.3 via pipx, Python 3.14.6 (Homebrew)
- macOS: <sw_vers output>
- Client: Claude Desktop, no `--watch`, `APPLE_MAIL_READ_ONLY=true`
- Index built from Terminal (which has Full Disk Access); the client does not

### What happens
`get_email_attachment` fails for every attachment tried — 4/4 across two accounts, a full `.emlx` and two `.partial.emlx`, PDFs and an inline JPEG — with:

    Attachment '<filename>' not found in email <id>

while the index's `attachments` table lists each one with MIME type, size and content-id, and `get_email` on the same message returns the same attachments in its metadata. The index knows the attachment; the extractor cannot read the `.emlx` under `~/Library/Mail` because the server process has no FDA.

### Request
1. When the `.emlx` is unreadable, fall back to JXA (Mail's scripting interface, which the server already uses for accounts/mailboxes) to save the attachment — e.g. Mail's `save` on the attachment object. That works under the Automation permission ("<client> wants to control Mail"), a per-app grant, rather than Full Disk Access for the whole client.
2. Distinguish the errors: "attachment not present in MIME" vs "message file not readable (permission)". The current message sends users looking for a missing part when the cause is permissions.

### Why not just grant FDA to the client
Tested: granting FDA to Claude Desktop did not reach the server process (`get_emails` still reports `Cannot access ~/Library/Mail/V10`), so the only remaining route is FDA for the Python interpreter itself, which is far too broad. A JXA path keeps the grant scoped to Mail.

### Note
~76% of attachment-bearing messages in this store are `.partial.emlx`, where Mail keeps the attachment out of line in a sibling `Attachments/` directory. Worth confirming the extractor handles that layout too.
