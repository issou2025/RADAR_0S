## Today's Best Discoveries

### 1. CATS — 8.8/10
**Decision:** USE NOW

**What it is** — A REST API fuzzer and negative-testing tool for OpenAPI endpoints: point it at a spec and a running server, and it generates, runs, and reports thousands of boundary, type-coercion, injection, and stateful negative-path tests (IDOR, idempotency, update-read consistency, deleted-resource availability) with zero hand-written test code.
**Why I should care** — Negative-path testing is exactly the category that gets skipped under deadline pressure, and CATS is self-healing: when the OpenAPI spec changes, the generated tests change with it, so there's no hand-maintained negative-test suite going stale.
**What it could replace** — Hand-written negative/boundary test cases per endpoint, and the usual gap where positive-path tests pass but nobody checks what the API does with malformed input or already-consumed resources.
**Ways I could use it** — Run a security/compliance profile against a Node/Express or NestJS service in CI; use `cats lint` to catch contract issues before fuzzing; `cats replay --curl` to turn a finding into a reproducible bug report; the `--tui` mode to inspect a long run interactively instead of scrolling CI logs; `--qualityGate` as a release-blocking check.
**Agent opportunity** — Deterministic CLI with exit-code gating and structured JSON/HTML reports — straightforward to hand to a coding agent as a "run negative tests and summarize failures" tool, though it has no MCP server yet.
**Integration effort** — Low: Homebrew or a native binary, point at an OpenAPI spec and a server URL, no code changes to the target API.
**Maturity** — Mature: created 2020, 1,378 stars, 93 forks, Apache-2.0, backed by Endava, still actively released (v15.3.0 shipped the same day as this review), with a documented history of finding real bugs in HashiCorp Vault and Gitea.
**License** — Apache-2.0, no commercial-use restrictions.
**Alternatives** — Schemathesis and EvoMaster (both previously time-boxed out of this catalog as mature-but-generic fuzzers with no stack-specific angle); Dredd; manual Postman/Newman negative-test collections.
**Why this one** — Self-healing zero-code design plus built-in security/compliance profiles and dependency-aware request ordering across endpoints is a more differentiated pitch than the generic fuzzers already passed on.
**Recommendation** — Install and point it at an existing OpenAPI spec as a CI quality gate.

### 2. Debug Anything — 8.2/10
**Decision:** PROTOTYPE

**What it is** — An MCP server and CLI giving a coding agent (or a human) black-box observation of any running process, container, or pod — syscalls, CPU flamegraphs, thread stacks, sockets/fds, packets, heap retainers, container state — by wrapping strace/py-spy/perf/lsof/tcpdump/gdb/lldb/Node's inspector and turning their output into evidence-cited findings, with zero instrumentation or restart.
**Why I should care** — An agent can read every line of code and still have no way to answer "why is this process eating 4GB" — it fumbles the flags for strace, and raw trace output blows the context window. This is the sensory layer most agent-debugging tooling skips, and its evidence-contract design (a finding without a cited evidence id is rejected by the schema) makes the output auditable instead of a plausible guess.
**What it could replace** — Manually running and interpreting strace/lsof/py-spy/gdb output when debugging a hung, leaking, or slow Node/Python process, and the context-window cost of pasting raw profiler output into an agent chat.
**Ways I could use it** — `npx debuganything why <pid> --symptom leak` on a suspected memory leak; "who's holding port 8080" without running lsof by hand; Docker container OOMKill diagnosis; CI hang forensics via the companion GitHub Action; deadlock detection naming the exact blocking lines.
**Agent opportunity** — It is itself agent tooling: one MCP server, 14 tools, auto-setup for Claude Code/Codex/Cursor/Gemini CLI, a proactive hook that nudges the agent toward it on EADDRINUSE/OOM/segfault signals, and Python bindings for LangChain/LlamaIndex/CrewAI.
**Integration effort** — Low: `npx debuganything setup` auto-configures the agent; a `readiness` command reports what's usable on the current machine before any tool runs; no server, no account, no telemetry.
**Maturity** — Emerging: created 2026-10-17, 13 stars, 3 forks — but the engineering (evidence contract, honest per-OS capability matrix, hard resource caps, secret redaction, a Discord community, a documented roadmap) is unusually mature for a two-week-old repo.
**License** — MIT, no commercial-use restrictions.
**Alternatives** — mcp-debugger (already catalogued, USE NOW) and Microsoft's DebugMCP cover step-through debugging — a complementary, different problem (you need to already know where to put the breakpoint).
**Why this one** — No other tool found doing black-box, zero-instrumentation process/container observation specifically packaged for agent consumption with an evidence-citation requirement; it explicitly and correctly positions itself as the layer *before* a step debugger rather than competing with one.
**Recommendation** — Install the next time a Node or Python process hangs, leaks, or won't release a port.

### 3. dánwò — 7.8/10
**Decision:** PROTOTYPE

**What it is** — An E2E testing framework for web/Android/iOS that drives the UI via locators or cached plain-English agent steps, with an opt-in backend layer: emulated third-party providers (Stripe, Clerk, Resend, Google, Slack, 20+ more) behind a proxy, post-test invariants against the database/provider state, and built-in fault injection — `danwo matrix` reruns a test once per fault (500s, declined payments, duplicate webhooks, lost DB commits) and the invariant judges each run.
**Why I should care** — Most E2E setups stop at "did the UI show the right text." The fault matrix answers whether idempotency logic actually holds under a duplicate webhook or a mid-checkout provider 500 — removing an idempotency key from their own demo app and watching two fault-matrix trials turn red (a duplicate welcome email) is exactly the bug class that's expensive to find in production.
**What it could replace** — Manually simulating provider failures (or not testing them at all), and the need for real sandbox API keys for Stripe/Clerk/Resend/Slack/Google just to run a CI suite.
**Ways I could use it** — Fault-matrix-test a checkout or webhook-handling flow for idempotency gaps; migrate an existing Playwright suite incrementally; write a plain-English step once and let CI replay it from a cached recording with no further model cost; test a Next.js + Postgres + Stripe flow entirely offline.
**Agent opportunity** — Ships a skill and MCP server for Claude Code, Cursor, and Codex; every run produces a flight record (video, steps, calls) surfaced over MCP, not just to a human dashboard.
**Integration effort** — Medium: Node 22.22.3+/24.11.1+, mobile testing needs macOS/Linux plus an emulator or simulator, and the project's own docs warn "APIs will change."
**Maturity** — Experimental: created 2026-10-21 (9 days old), 17 stars, backed by a named company (Carbonme Inc.) with a real docs site and an 8-example gallery spanning Next.js/Postgres/Stripe, Clerk, Better Auth, SwiftUI, Jetpack Compose, and Flutter.
**License** — Apache-2.0 for the code; the name/logo is trademarked by Carbonme Inc. — standard, not a usage blocker.
**Alternatives** — Playwright/Cypress/Detox directly, which this wraps and extends without the provider emulation or fault matrix.
**Why this one** — No other self-hostable tool found combining UI-driving, real provider emulation, and systematic fault injection with invariant-judging in one framework.
**Recommendation** — Spike it on one checkout or webhook-handling flow; hold off wiring it into a release-blocking gate until the APIs stabilize.

### 4. Assay (assay-evals) — 7.3/10
**Decision:** PROTOTYPE

**What it is** — Behavioral regression testing for AI apps/agents in Python and TypeScript: a pytest plugin and a Jest/Vitest/node:test helper that auto-wraps an existing LLM SDK client, records each test case's tool calls/cost/context against its own last passing run, and separates real regressions from noise via repeated-sample comparison and judge calibration against human labels.
**Why I should care** — A green test suite doesn't show that an agent's *behavior* changed — Assay's own pitch example is one line added to a support agent's prompt making it skip a refund approval step while the final reply still reads fine; `pytest --assay` catches that because it diffs tool-call sequences, not output text.
**What it could replace** — Manually re-checking an agent's tool-calling behavior after every prompt/model change, and the false confidence an output-quality eval gives when the underlying tool-call sequence actually regressed.
**Ways I could use it** — Gate a prompt-engineering PR on behavioral regressions; wrap an existing Anthropic/OpenAI/Vercel AI SDK client with `instrument()` for call-level recording with no manual trace instrumentation; `assay diff` after a model swap; document-extraction regression metrics for structured-extraction agents.
**Agent opportunity** — `assert_called`/`assert_not_called`/`assert_max_steps` primitives are a reusable deterministic pattern for grading an agent's tool usage without another LLM judge.
**Integration effort** — Low: `pip install assay-server` / `npm install assay-evals`, native pytest/Jest/Vitest/node:test integration, no custom trace-emission code needed.
**Maturity** — Emerging: created 2026-09-24 (five weeks old), 23 stars, actively pushed the same day as this review, real published packages on both PyPI and npm.
**License** — MIT, no commercial-use restrictions.
**Alternatives** — whatbroke (already catalogued, PROTOTYPE) covers the same core idea via manual JSONL trace instrumentation instead of SDK-client wrapping; promptfoo/LangSmith remain the output-quality-scoring alternative both explicitly position against.
**Why this one** — Automatic SDK-client wrapping (no custom instrumentation), statistical noise-vs-regression separation, and human-label-calibrated judging (reported via Cohen's kappa) is a more rigorous trust story than whatbroke's manual-trace approach, though the overlap means picking one over adopting both.
**Recommendation** — Try it on one existing agent/support-bot test suite via the `instrument()` wrapper before deciding whether it replaces whatbroke.

## Small but High-Leverage Utility
**llmock** (piyook/llm-mock, MIT) is a local mock LLM API server speaking the OpenAI, Claude, and Gemini wire formats — fixture replies, Claude-style tool calls, streaming, error simulation, and a dashboard for inspecting exactly what a client sent. Testing AI-agent integration code against the real API means burning tokens and tolerating non-determinism in CI; this gives deterministic, offline, zero-cost responses across all three wire formats in one server instead of three separate hand-rolled mocks. Created May 2024 and still actively maintained (a release shipped the day before this review), it's a two-year-old project with modest traction (22 stars) rather than a weekend experiment — worth a base-URL swap in one existing AI-integration test suite.
