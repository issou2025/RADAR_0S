# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Unreal: read and build the realtime channel's messages**

*Project description:*
## Brief

**What:** The Unreal plugin can build and read every realtime message of the export contract, and its connected-host presence payload, as pure logic.
**Why:** The channel client and the export receiver are built on these messages, and pinning them headlessly keeps the socket code thin.

---

## What to build

The Unreal plugin can build and read every message of the realtime channel `docs/platform-export-contract.md` describes (protocol 1), as pure logic with no socket: the join of the private `vault:<user id>` topic with the session's access token, presence track and untrack keyed by the connection id, the `postgres_changes` subscriptions for exports and for order rows, heartbeats, and the replies and errors a join can get (an `Unauthorized` channel error apart from the ones that retry). It also builds the `ConnectedHost` presence payload: protocol, host, host version, plugin version, the open project or none, the machine, and the manifest versions the importer reads, taken from the constants the importer gates on.

The shared .NET core already does this for Revit and AutoCAD (its realtime frames, connected host and published realtime units, with their tests); port the behaviour and the test cases, in a `*Logic` unit in the Runtime module with a headless test beside it. Nothing here opens a socket or changes what a user sees.

**Agent tier:** standard

## Acceptance criteria

- [ ] Every frame the contract's sections 1 to 3 need is built and parsed by pure logic, and a headless test pins each against the same cases the shared .NET tests pin.
- [ ] The presence payload carries the fields the contract lists, and its readable manifest versions come from the importer's own constants.
- [ ] The plugin compiles on Unreal 5.8 and the `MantlePlace.` automation suite is green, with no `No editor` skip.
