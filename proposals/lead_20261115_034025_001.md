## The Problem
The app needs deployable Android/iOS builds from GitHub Actions, configured with the real intake and deletion-request URLs. The repository currently runs Flutter quality checks, but has no mobile artifact-build workflow or distribution signing configuration. The app identifiers are still template values.

## Plan
Codex will add GitHub Actions builds, download artifacts, and a manually dispatched signed-release path. Development builds must work before store credentials are configured. Release builds must validate required configuration and fail clearly if it is missing. #107 owns the app's configuration/settings integration.

Set these under **Settings → Secrets and variables → Actions → Repository secrets** (or in the documented release environment once the workflow lands). Put values in Secrets, never in issue comments.

### App configuration
- [ ] `WEEDZ_INTAKE_BASE_URL` — production/pilot HTTPS intake base URL, without a device credential.
- [ ] `WEEDZ_DELETION_REQUEST_URL` — real, publicly reachable HTTPS deletion-request page/form for people who have lost their device.

These values are embedded in the app and are public configuration, even though supplied through Actions secrets.

### Android signed builds
- [ ] `ANDROID_APPLICATION_ID` — final Google Play package/application id you control (not `org.example.weedz`).
- [ ] `ANDROID_KEYSTORE_BASE64` — base64 of the upload-signing JKS/keystore file.
- [ ] `ANDROID_KEYSTORE_PASSWORD` — keystore password.
- [ ] `ANDROID_KEY_ALIAS` — upload key alias in that keystore.
- [ ] `ANDROID_KEY_PASSWORD` — password for the selected private key.

Keep a secure backup of the upload key. A Google login/password or Play service account is not required just to build signed APK/AAB artifacts.

### Apple signed builds
- [x] `IOS_BUNDLE_IDENTIFIER` — final app bundle id registered with Apple.
- [x] `APPLE_TEAM_ID` — Apple Developer team id.
- [x] `IOS_DISTRIBUTION_P12_BASE64` — base64 of an Apple Distribution certificate **with its private key**, exported as `.p12`.
- [x] `IOS_DISTRIBUTION_P12_PASSWORD` — password protecting that export.
- [x] `IOS_PROVISIONING_PROFILE_BASE64` — base64 of an App Store distribution `.mobileprovision` matching the bundle id, team, certificate and required app capabilities.

The workflow will create a temporary keychain and remove signing files after building. It does not need your Apple account password.

### Apple provisioning automation
The user authorized Apple API setup. These secrets are configured for provisioning; routine artifact builds use the certificate/profile above and do not need API access:
- [x] `APP_STORE_CONNECT_API_KEY_P8_BASE64`
- [x] `APP_STORE_CONNECT_KEY_ID`
- [x] `APP_STORE_CONNECT_ISSUER_ID`

Apple API authentication succeeded. Bundle `nz.llm.weeds`, a matching Apple Distribution certificate/private key and an App Store distribution profile were created and validated. Private files remain outside Git in owner-only local storage. No App Store submission was performed.

A Google Play service-account key is not required for artifact builds and will be requested only if automated store upload is added. Production URLs, Android upload signing and actual signed-build verification remain outstanding.
