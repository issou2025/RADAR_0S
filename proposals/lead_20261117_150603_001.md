# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Preflight: let checks report structured findings (element ids) and export them as JSON/CSV**

*Project description:*
## Is your feature request related to a problem? Please describe

Preflight checks only print to the output window. That makes their results hard to act on and impossible to compare over time:

- **No element ids.** As #1267 describes, a check can say "44 reference planes have no name" but nothing tells you *which* 44. Finding the last few by hand is slow, and with schedules it isn't clear what the check counted.
- **No machine-readable output.** A BIM manager who runs the same checks on many models can't collect the results in a spreadsheet or a dashboard without copying text from the output window.
- **Results depend on the UI language.** Check names are localized, so the same check has a different name in each language, and results from different locales can't be matched up.

## Describe the solution you'd like

An opt-in way for a check to record **structured findings**, plus an optional results file. Existing checks keep working unchanged.

**1. `self.report(...)` on `PreflightTestCase`**

```python
self.report(
    "refplanes.unnamed",                       # stable rule id, never translated
    "%d reference planes have no name" % len(unnamed),
    element_ids=unnamed,                       # ints, ElementIds or elements
)
```

Each finding has a rule id, message, status (`pass` / `fail`), severity (`info` / `warning` / `error`), element ids and optional JSON data. Element ids work on all supported Revit versions (`ElementId.Value` on 2024+, `IntegerValue` before that).

**2. `run_preflight_check` returns the run's result**

The result holds a stable check id (`<extension>/<script>.<class>`, independent of the localized name), document title and path, UTC start time, duration, run status, summary and findings, with a `schema_version`.

A check that reports nothing gets the status `not_reported`, never `pass`, so checks that haven't adopted `report()` never look clean.

**3. Optional results file**

If the environment variable `PYREVIT_PREFLIGHT_RESULTS_PATH` is set, the result is also written to that file. The file extension picks the format:

| Extension | Written as |
|---|---|
| `.json` | this run, replacing the file |
| `.jsonl` | one line per run, appended (many runs or models in one file) |
| `.csv` | one row per finding and element, appended; UTF-8 with BOM so Excel shows non-ASCII text correctly |

If writing the file fails, the error is logged and the check is not failed. If the check itself errors, nothing is written.

**Implementation notes**

- New module `pyrevitlib/pyrevit/preflight/results.py` with no Revit dependency, in the same spirit as `pyrevit.unittests` / `junit.py`, so it can be tested without Revit.
- Small changes to `preflight/case.py` and `preflight/__init__.py`; a "Reporting findings" section in `docs/extensions.md`.
- Standalone tests in `dev/scripts/` (no Revit needed), passing with the existing suite; ruff and the IronPython 2.7 syntax checker are clean.

I have this implemented on a branch and can open a PR once the approach looks right to you. After that, the built-in checks (reference planes, schedules not on sheets, ...) could adopt `report()` in follow-up PRs, which would directly address #1267.

## Describe alternatives you've considered

- **Only improving the HTML output** (e.g. linkifying element ids). Helps one person at one model, but gives nothing to collect or compare across models and runs.
- **A setting in the pyRevit UI instead of an environment variable.** Friendlier for single users, but an environment variable also works for scripted and batch runs. A UI setting could be added on top later.
- **A JUnit-style XML report.** Fits CI tools, but BIM teams mostly use Excel and Power BI, where CSV and JSON are easier.
