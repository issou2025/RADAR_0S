## Project Understanding
You need assistance with: 
**Build fails against libtoxcore 0.2.18 (Ubuntu/Debian package): missing Tox_Friend_Number, Tox_Options typedefs**

*Project description:*
## Summary

Building py-toxcore-c from the current main branch fails to compile against the packaged `libtoxcore-dev` (0.2.18) available in Ubuntu 24.04 (Noble) repositories. The generated Cython C code references typedefs that don't exist in this version of tox.h.

## Environment

- OS: Ubuntu 24.04.4 LTS (Noble Numbat)
- gcc: 13.3.0
- Python: 3.12.3
- libtoxcore-dev / libtoxcore2: 0.2.18-1build3 (Ubuntu universe repo)
- py-toxcore-c: main branch, commit 26bcbaf ("refactor: Generate Cython bindings from c-toxcore headers via apigen")

## Steps to reproduce

apt-get install libtoxcore-dev libtoxcore2 python3-pip
pip install cython setuptools
git clone https://github.com/TokTok/py-toxcore-c
cd py-toxcore-c
cythonize pytox/toxav/toxav.pyx pytox/toxcore/tox.pyx pytox/toxencryptsave/toxencryptsave.pyx
python3 setup.py build_ext --inplace

## Actual result

pytox/toxav/toxav.c:22458:3: error: unknown type name 'Tox_Friend_Number'
...
error: command '/usr/bin/x86_64-linux-gnu-gcc' failed with exit code 1

After defining `Tox_Friend_Number` as `uint32_t` via a compat shim to get past that error, compilation fails again on:

pytox/toxav/toxav.c:1690:3: error: unknown type name 'Tox_Options'

Checked directly against the installed header:

$ grep -n "Tox_Options" /usr/include/tox/tox.h
529:struct Tox_Options {

The installed tox.h declares `struct Tox_Options` without a bare `Tox_Options` typedef alias, and has no standalone `Tox_Friend_Number` typedef at all — friend numbers are still plain `uint32_t` in function signatures. The .pxd files in this repo (`pytox/toxcore/tox.pxd`) assume these typedefs already exist upstream in tox.h:

ctypedef uint32_t Tox_Friend_Number

## Expected result

Either the build succeeds against the currently packaged/released libtoxcore, or the README/build docs specify a minimum required c-toxcore version/commit so users know they need to build c-toxcore from source rather than use their distro's package.

## Question

Is main currently expected to only work against a specific unreleased c-toxcore revision (i.e. ahead of the 0.2.18/0.2.20 release line)? If so, could the README note the required c-toxcore commit/tag, or could a version guard be added so the failure is clearer than a raw compiler error? Happy to test against a specific c-toxcore ref if pointed at one.
