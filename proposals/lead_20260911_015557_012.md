## Current SHAFT baseline (gap analysis)

Source of truth on `main` (do not invent paths):

| Surface | Path | Behavior today |
|--------|------|----------------|
| Selenium / Appium core | `shaft-engine/.../gui/element/internal/Actions.java` | `CLICK`: native `WebElement.click()`; on `InvalidElementStateException` optional JS click via `clickUsingJavascriptWhenWebDriverClickFails`. Mobile double-tap uses `PointerInput`. `TYPE`/`TYPE_SECURELY`: optional pre-click (`attemptToClickBeforeTyping`), `clearBeforeTypingMode` (`native`/`backspace`/`off`), then `sendKeys`, optional typed-text validation. `TYPE_APPEND` = sendKeys only. `JAVASCRIPT_SET_VALUE` sets `.value` + `input`/`change` events. File upload = `sendKeys(path)`. |
| Playwright | `shaft-engine/.../gui/playwright/element/ElementActions.java` | `click()` → Playwright locator click; `type()` → **`fill()`** (not `pressSequentially`). OCR click exists on Playwright path. |
| Flags | `Flags.java` / `PropertiesHelper` | `clearBeforeTypingMode`, `attemptToClickBeforeTyping`, `clickUsingJavascriptWhenWebDriverClickFails`, uniqueness checks. |
| Contract | `ElementActionsContract` | OCR click not supported on some impls; smart locators for clickable-by-name / input-by-name. |

**Gaps vs research (high level):**
1. One-size `sendKeys` / `fill` does not branch by control kind (checkbox, contenteditable, Select, date, file, ARIA combobox, Compose TextField, UIA Edit, …).
2. Playwright `fill` is fast but skips key events some apps need; Selenium path never offers Playwright-style actionability waits / `force` / sequential press as first-class strategy.
3. Click interception / overlay / animation / sticky headers: only partial JS fallback; no systematic scroll-into-view + retry ladder shared across backends.
4. Mobile: Appium `setValue` / `mobile: type` / hideKeyboard / Flutter semantics / Compose `testTag` paths are not a first-class type strategy matrix.
5. Desktop (WinAppDriver / UIA): control-type aware Click vs Toggle vs SendKeys vs Clear not modeled in the shared Actions switch.
6. Shadow DOM / iframe / closed shadow: iframe switch exists; open-shadow pierce and closed-shadow public-API fallbacks are not documented as strategies in ElementActions.
7. No shared “element kind → interaction recipe” table that both Selenium and Playwright (and mobile/desktop) consult — duplication and drift.

## Research catalog (≥10 element / interaction cases)

Keep extending this table in child issues if a new case appears in the wild; stop when no new kinds for ~1h of research. Live-user north star: **fewer flaky clicks/types + lower wall-clock per action**.

### Web — input and form controls
1. **Native text-like `<input>`** (`text`, `password`, `email`, `search`, `tel`, `url`, `number`) — focus → clear strategy → `sendKeys` / Playwright `fill`; validate `value`.
2. **`<textarea>`** — same as text; watch maxlength / autofill.
3. **Checkbox / radio** — **click or space**, never type; assert `checked`; avoid double-toggle.
4. **`<select>` / listbox** — `Select` API or option click; not sendKeys of visible label alone when value differs.
5. **File `<input type=file>`** — set files via path (`sendKeys` / `setInputFiles`); never “type” into visible fake button alone.
6. **Date / time / month / week / datetime-local** — prefer `fill`/set value + events; calendar popup click is secondary.
7. **Range / color** — JS value + input/change events often more reliable than drag.
8. **Button / submit / reset / image** — click center; watch overlay interception.
9. **`<a href>` / role=link** — click; JS navigation vs full navigation.
10. **`contenteditable` / designMode** — click to focus; `pressSequentially` / insertText; **`fill` often wrong**.
11. **ARIA `textbox` / `searchbox` / `combobox` / `spinbutton`** — role-based locate; combobox may need type-then-option-click.
12. **Masked / React controlled inputs** — character-by-character or JS value+React setter; validation must read the controlled state.
13. **Shadow DOM (open)** — Playwright pierces; Selenium needs deep CSS / JS pierce helpers.
14. **Shadow DOM (closed)** — no pierce; host public API, a11y tree, or coordinate last resort.
15. **Iframe / frame** — scope then interact (`SWITCH_TO_IFRAME` already exists).
16. **Canvas / SVG hit targets** — coordinate / OCR / accessibility sibling; not DOM value.
17. **Custom elements / web components** — treat as host + internals; prefer roles.
18. **Click intercepted / not interactable / covered** — scroll into view → wait stable → retry → optional force/JS (flagged).
19. **Sticky header / toast overlay** — dismiss or offset click; don’t JS-click blindly if users need real pointer.
20. **Disabled / readonly / aria-disabled** — fail fast with clear report; no silent JS override unless explicit API.

### Mobile
21. **Android `EditText`** — click focus → `sendKeys` / `setValue` / `mobile: type`; hideKeyboard after.
22. **iOS `XCUIElementTypeTextField` / `SecureTextField`** — `setValue` preferred; SecureField quirks.
23. **Flutter `TextField` / Semantics** — value keys / semantics identifier; tap then enter text.
24. **Jetpack Compose `TextField` + `testTag`** — `testTagsAsResourceId` + click-then-type; setValue may fail until focused.
25. **React Native `TextInput`** — accessibility / testID; focus then type.
26. **Mobile tap vs Selenium click** — touch `PointerInput` / W3C actions for reliability on native.
27. **Checkbox / Switch / Chip on mobile** — toggle semantics, not sendKeys.

### Desktop
28. **UIA Edit / Document** — Click → Clear → SendKeys; value pattern when available.
29. **UIA Button / Hyperlink** — Invoke / Click.
30. **UIA CheckBox / RadioButton** — Toggle pattern; assert toggle state.
31. **UIA ComboBox** — Expand → select; or type-to-filter then enter.
32. **WinAppDriver window / pane focus** — ensure foreground before type.

### Cross-cutting reliability tactics
- Actionability: visible, enabled, stable, receiving events (Playwright model as target; Selenium approximate with waits).
- Clear modes: native clear vs select-all+backspace vs off vs JS clear — pick by kind.
- Typed-text validation: skip for password/secure/masked/file; tighten for text.
- Telemetry: per-strategy latency + success so we can prove “faster”.

## Target architecture (spec for implementers)

Introduce a small **interaction strategy layer** used by Selenium `Actions` and Playwright `ElementActions` (and later mobile/desktop adapters):

```
resolve(locator) → classify(element) → pickStrategy(kind, flags) → execute → optional verify
```

**Classifier signals (cheap first):** tagName, type attribute, role/ARIA, contenteditable, Appium class/name, UIA ControlType, Playwright role snapshot when available.

**Strategies (illustrative):** `NativeClick`, `JsClickFallback`, `TouchTap`, `Fill`, `SendKeys`, `PressSequentially`, `SetValueMobile`, `SelectOption`, `Toggle`, `SetFiles`, `JsSetValueWithEvents`, `OcrClick` (existing Playwright), `CoordinateClick` (last resort).

**Non-goals:** rewriting locator engine; changing default public method names; Headroom.

- Scope creep into locator AI / OCR everywhere → OCR stays Playwright existing path; coordinate click last resort.
