## Task 1 — what is already in the vault

Before generating anything new: the account may already have a distribution certificate and an API key, and a second distribution cert eats one of only three slots.

```sh
trove unlock --env ~/icloud-christhomas/christhomas.kdbx

```

**Report in a comment: titles, groups, usernames, URLs, notes, custom-field *names*, attachment *names*. Never a protected value.** What matters is whether these exist, and whether anything has expired:

- [ ] An App Store Connect API key (`.p8`), with its Key ID and Issuer ID
- [ ] An Apple Distribution certificate, exportable as `.p12`
- [ ] An App Store provisioning profile for the bundle id above
- [ ] An App Store Connect app record for the bundle id (check the portal, not the vault)

Say which of the four are missing. Anything missing gets made in Apple's portals:

- API key — App Store Connect → Users and Access → Integrations → App Store Connect API → **Team Keys** → +, role **App Manager**. The `.p8` downloads exactly once.
- Certificate — if Xcode has archived on this Mac, one exists: Keychain Access → My Certificates → *Apple Distribution: …* → export as `.p12` with a password.
- Profile — Developer portal → Profiles → + → **App Store Connect** → the bundle id → that certificate. Make it explicitly; an Xcode-managed profile regenerates itself and would strand the secret.
- App record — Developer portal → Identifiers (register the bundle id), then App Store Connect → Apps → +. The first upload is rejected without it.

## Known defect — the automatic trigger does not work

The workflow says it runs on every merge to `main`. It will not, and the comment at the top of the file is wrong until this is fixed.

`auto-merge.yml` arms auto-merge with `GITHUB_TOKEN`, and GitHub does not start workflow runs for events caused by that token. The evidence: the only push-triggered run in this repo's whole history is from 2026-09-11. Every merge since — #13, #14, #15, #16 — produced no run on `main`.

`workflow_dispatch` is unaffected, so Task 3 is still valid. Options for a real fix, to decide after the pipeline is proven green:

1. Arm auto-merge with a fine-grained PAT (contents: write, pull requests: write) instead of `GITHUB_TOKEN`. Smallest change; adds one long-lived credential.
2. Arm it with a GitHub App installation token. App tokens do start workflow runs; more setup, no long-lived secret.
3. Leave it manual: whoever merges also runs `gh workflow run TestFlight`.

Option 1 or 2 is what "merge and it lands on the phone" actually requires. **Chris to decide.**
