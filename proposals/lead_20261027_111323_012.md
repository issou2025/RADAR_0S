## Context

PR #26 and #27 are merged. The program signs approval-registry checkpoints and can optionally publish them after durable approval registration via conditional S3 PUT (If-None-Match: *) and exact-byte GET readback. Go, Temporal recovery and SeaweedFS S3 protocol checks passed on PR #27.

This is NOT proof of object immutability, global freshness or atomic distributed commits. A signature authenticates the signer and Count/Head, not which version is globally latest.

## Real storage acceptance gate

- [ ] Use an isolated, operator-provisioned AWS S3 bucket with versioning and Object Lock enabled at creation; least-privilege identities; no long-lived CI secrets.

- [ ] Independently pin Journal ID, governance Ed25519 key fingerprint, expected Count/Head, host, version-specific object key, and test scope.

- [ ] Run optional auto-publish; verify exact locally signed vs S3 downloaded bytes, signer, Count/Head and object version metadata.

- [ ] Confirm identical replay is safe and a different payload at the same key is never overwritten.

- [ ] Exercise simulated PUT lost ACK and readback failure; remain Unknown until an exact-byte recovery confirms the object.

- [ ] Prove **permanent deletion of the exact retained object version** (`DeleteObject` with independently pinned `versionId`) is denied; a normal DELETE **without** a version ID may create a delete marker and must NOT be counted as Object Lock failure or success.
- [ ] Prove retention shortening on that exact object version is denied. Distinguish Governance vs Compliance and `s3:BypassGovernanceRetention` exposure. A generic 403 could merely be missing IAM permission; corroborate with provider-side retention configuration and a permitted control operation on a separate unprotected test object.
- [ ] Verify that a competing write or delete marker cannot cause consumers to accept a different **current key** as the trusted checkpoint. The protected version can remain immutable even when a newer version or delete marker shadows it; compare against independently pinned versionId and Count/Head, and validate IAM policy blocking unauthorized unversioned delete/overwrite.

- [ ] Demonstrate local registry rollback below independently pinned Count/Head fails before HTTP.

- [ ] Capture sanitized hashes, tool versions, retention mode/date, object version evidence and IAM-denial results; never publish presigned URLs, cloud credentials or personal account details.

- [ ] Recheck full Go/Temporal/S3 regression tests on the exact acceptance commit.

## Protocol compatibility prerequisite
- [ ] Presign the real Object Lock retained PUT with `content-md5;content-type;host;if-none-match` using the Base64 MD5 of the exact signed checkpoint bytes. EngageGuard PR #29 is **merged** (main `23462107018dd550858d3b499d23d3e61b558a02`), with Go/Temporal and SeaweedFS protocol CI passing. This is adapter capability only, not evidence of live AWS retention.
- [ ] For auto-registration, account for the fact that the signed checkpoint bytes are produced only after durable registration. Provision the checksum-bound URL from those finalized bytes and safely reconcile; do not invent the checksum from Count/Head alone. PR #30 is **merged** (main `4870bea760b70bb3ce3c5d46f51755aa46e285cd`) and adds an offline `registry-anchor-prepare` stage that emits deterministic signed bytes and Base64 transport checksum. Exact-head Go/Temporal CI passed (https://github.com/musuntana/EngageGuard/actions/runs/40445049872). Live AWS retention evidence is still pending.
- [ ] Independently corroborate version ID and retention evidence using the AWS API. Record safe hashes and decisions, never credentials or presigned URL query strings.
