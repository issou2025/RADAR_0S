## The four things that will hurt

**1. `SetWindowsHookEx` can be removed permanently and silently.** Microsoft's
own `LowLevelKeyboardProc` page: if the hook procedure times out, "the hook is
silently removed without being called. **There is no way for the application to
know whether the hook is removed.**" Default 300ms. `always.py` already says a
dictation key that silently stopped working is indistinguishable from a broken
keyboard; Windows ships that as documented behaviour. Under the GIL with an audio
thread and a transcribe subprocess, this is a when and not an if. **The hook goes
in a small native helper with a reinstall watchdog, not in ctypes from Python.**

**2. SendInput is blocked by UIPI and lies about it.** Verbatim from Microsoft:
"This function fails when it is blocked by UIPI. Note that neither GetLastError
nor the return value will indicate the failure was caused by UIPI blocking." So
nothing lands in an elevated window and the call returns full success. Same shape
as d2518e4. Mitigate by querying the foreground window's integrity level first
and saying so. (The hook direction of UIPI is strongly implied but has no single
Microsoft sentence; it is a twenty minute experiment on a test box.)

**3. There is no Fn key.** On most Windows laptops Fn is eaten by the keyboard's
embedded controller and never reaches the OS. Best available: Right Ctrl with
tap-passthrough (suppress past ~200ms, re-inject on a short tap), or Caps Lock
with suppression. Not Right Alt, which is AltGr and types `@ \ { } [ ]` on
international layouts. Wispr Flow ships **Ctrl+Win** on Windows and lists
standalone Ctrl as unsupported. Nobody has a one-key gesture on this platform.

**4. Delivery into a terminal is clipboard-only.** SendInput with
`KEYEVENTF_UNICODE` is reported not to reach TUI apps including Claude Code (a
synthesised `VK_PACKET` only becomes `WM_CHAR` after `TranslateMessage`; source
is a third-party issue mirror, closed "not planned" June 2026, so forum grade,
but PowerToys Quick Accent reportedly fails the same way). So `paste.py`'s
chunking survives, the typing fallback does not, and paste keys fragment across
terminals where Cmd-V is universal.

**And one hard-constraint violation to defend against before anything else:**
Windows clipboard history with cloud sync uploads every clipboard item to
Microsoft. If we paste through the clipboard, every transcript leaves the
machine. The fix is to register `ExcludeClipboardContentFromMonitorProcessing`
and `CanUploadToCloudClipboard` = 0, which is what password managers do. This is
non-optional and is not something anyone would think of without looking.

## Speed

Best modern laptop datapoint: CPU real-time factor about 0.3 on a Ryzen 7 6800H
and a Core Ultra 7 155H (reported January 2026). Against a Mac baseline of
roughly 6 to 9 times real time for the same model, **2 to 3 times slower**, and
worse on older machines. Parakeet rescues English (about 30 times real time on an
i7-12700KF, 17 on a 2014 i7-4790) and should be the Windows default, exactly as
`install.sh` already makes it. **Hinglish is the casualty**: no Hindi in Parakeet,
so it falls to large-v3-turbo, which is the slow path on a slower machine.

ggml has no DirectML backend. CUDA prebuilts are 285MB to 685MB and only help
the minority with an NVIDIA GPU. Vulkan is the only cross-vendor option and is
not in the stock zip. There is no CoreML equivalent; CPU is the honest answer.

Worth knowing for positioning: **Win+H voice typing is cloud-based on any
non-Copilot+ PC**, so "nothing leaves the machine" means more on Windows than it
does on macOS.

## Signing, and the finding that decides the cost

The Mac install sidesteps notarization because `swiftc` compiles on the user's
machine. **Windows has no system compiler**, so prebuilt binaries must ship and
SmartScreen stops being optional. From Microsoft's SmartScreen reputation page,
updated August 2026:

- Unsigned: "Windows protected your PC ... **Enterprise policy can prevent
  continuation entirely.**"
- "When a file is not signed, SmartScreen reputation must build for each new
  version of your files, starting with zero reputation." Every release restarts.
- Even signed, "it can take several weeks and hundreds of clean installs."
- Smart App Control "will block execution of unsigned files" and "signature
  checks apply to all executable files, not just those downloaded from the
  Internet."
- "**EV certificates no longer bypass SmartScreen.**"
- "**Do not sign potentially unwanted applications** ... or the certificate may
  develop **negative** reputation." A global keyboard hook plus input injection
  is that neighbourhood. You can poison your own certificate.

**And Microsoft's own cheap route is geographically closed.** Azure Artifact
Signing (formerly Trusted Signing), quickstart page, ms.date 21 May 2026, updated
29 September 2026, verbatim:

> Public Trust certificates are available to organizations in the United States,
> Canada, the European Union, the United Kingdom, Australia, New Zealand, Japan,
> South Korea, Singapore, Switzerland, Norway, and Israel. **Individual
> developers must be located in the United States or Canada.**

India is on neither list. What is left: a commercial CA that issues to
individuals (Certum, roughly $50 to $90 a year with cloud signing; vendor pricing
and it moves), or SignPath Foundation, free but open-source only and subject to
review. The Microsoft Store would remove SmartScreen entirely but its route for a
plain exe requires that "the binary and all of its Portable Executable (PE) files
must be digitally signed", and the whisper and parakeet binaries are, as measured
above, unsigned.

Last trap: **PyInstaller one-file + global keyboard hook + input injection + a
Run-key write + unsigned is four antivirus heuristics firing at once.** The
documented remedies are to recompile the PyInstaller bootloader so the binary
does not share the known-bad byte pattern, prefer one-dir, and ship a visible
tray icon and hotkey settings screen, which EDR vendors' own false-positive
checklists explicitly look for.
