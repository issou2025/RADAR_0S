# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Idea: fill door sill / threshold values from the floor finishes on both sides and the transition details**

*Project description:*
## Context

One session on 2026-11-19 (Revit 2026, pyRevit 7.0, IronPython engine, Claude Code desktop app). The user read a door schedule with `am-schedule-view`. Most doors had an empty SILL value. The user then asked for a workflow:

1. build a map of room -> floor finish,
2. build a map of finish pair (in alphabetical order) -> transition detail reference (`<detail number>/<sheet number>`) from the detail views on the transition detail sheets,
3. for each door with an empty SILL, find the floor finish in its From Room and To Room,
4. look up the pair and write the detail reference to SILL, and stop when the match is not clear.

No archi-magic skill covers this. Related: #132 (room finishing idea), #257 (detail sections from markup).

## What happened

- The agent wrote its own `run_query` to read the details on the sheets (viewport detail numbers and view names), the door SILL parameter and the room floor finish values.
- The data it found shows why a skill would help:
  - Room floor finish values are free text. One room can hold several codes joined with `/` or `,`. Some values are `-` or empty.
  - The finishes in the rooms are codes (for example `CPT`, `TZ`, `RF`). The detail view names use words (Carpet, Terrazzo, Rubber). The agent wrote a code-to-word map and tried to ask the user to confirm it. The user stopped the question, so the map is still not confirmed.
  - A room can be in more than one place for finishes (a finish floor and a key schedule).
- The session stopped at the questions step (a usage limit, then the user stopped the question). Nothing in the model changed.
- cost: one extra hand-written query. A long prompt and a list of questions to make before any change. The same work is needed in every project with door thresholds.

## Proposed change

A new skill, or a mode of an existing finish skill, for door threshold / transition matching:

1. Read the doors with their From Room and To Room (phase-aware), and the room floor finish from a parameter that the user picks.
2. Read the transition details from sheets that the user picks: detail number, sheet number and view name. Turn each name into a finish pair, using a code-to-word map that the user confirms.
3. Make a preview table: door, finish A, finish B, matched detail, and a status (match, no match, more than one match, mixed finish in a room, empty finish).
4. Write only the clear matches with `am-safe-change` (dry run, preview, apply). List the rest for the user.

## Acceptance ideas

- On a test model, doors with one finish on each side get the right `<detail>/<sheet>` value, and doors that have no match or more than one match are listed and not changed.
- The order of the finish pair (A|B or B|A) does not change the match.
- Doors on the outside of the building (one side has no room) and doors with the same finish on both sides are reported, not guessed.

## Not verified

- The full workflow was not run. The session stopped before any write.
- How other offices name their transition details. The name parsing must be easy to set up.
