# Project Proposal — Quantity Takeoff

## Project Understanding
You need assistance with: 
**Call for Maintainers — LibreFang is expanding its maintainer group (apply in the comments)**

*Project description:*
LibreFang is opening up its maintainer group, and this issue is the place to put your name forward.

## Why now

The project has grown past what one person can review well.
29 crates, a React dashboard, a Tauri desktop app, two SDKs, and roughly 80 open issues at the time of writing — and over the last 90 days the large majority of commits came from a single contributor.

That is exactly the situation [`GOVERNANCE.md`](https://github.com/librefang/librefang/blob/main/GOVERNANCE.md) says we should not be in: *"Maintainers should avoid becoming a single-person bottleneck. When possible, at least two people should be able to review and release the project."*

So we are fixing it in the open rather than quietly.

## What a maintainer actually does here

From [`MAINTAINERS.md`](https://github.com/librefang/librefang/blob/main/MAINTAINERS.md):

- Review pull requests in a timely way.
- Preserve attribution when accepting or adapting community work.
- Keep release notes and governance documents accurate.
- Triage security and regression reports quickly.

In practice, most of the value is in the first two.
Our PR policy is merge-first: if a contribution helps the project we merge it, and if it needs work we review it constructively instead of letting it rot.
A maintainer's job is to make that promise true for a corner of the codebase, not to gatekeep it.

## Where we need people

You are applying for an **area**, not for the whole repo.
These map to the teams in [`.github/CODEOWNERS`](https://github.com/librefang/librefang/blob/main/.github/CODEOWNERS) and to the `area/*` labels on issues.

| Area | What it covers | Helpful background |
|------|----------------|--------------------|
| `core` | Kernel orchestration, agent runtime, types, memory substrate, HTTP API | Rust, async/tokio, some architecture appetite |
| `integrations` | Channel adapters, skills, FangHub, importers, JS/Python SDKs | Rust plus one platform API; or just TypeScript/Python for the SDKs |
| `community` | Docs, agent templates, examples, i18n | Markdown and a language — **no Rust needed** |
| `devops` | CI/CD, release automation, packaging (AUR, Nix, Homebrew, Docker) | GitHub Actions, shell, packaging formats |
| `dashboard` | React + TanStack Query SPA in `crates/librefang-api/dashboard/` | TypeScript and React |
| `desktop` | Tauri app, including the Linux/Windows platform quirks | Rust + Tauri + TypeScript |
| `security` | Sandbox and secret handling review, GHSA triage | Security review experience |
| `triage` | Labelling, reproducing bug reports, closing duplicates, keeping the queue honest | Patience and a reproducible setup |

Platform testing counts as an area too.
We have very little regular coverage on Windows and on uncommon Linux setups, and a maintainer who simply runs the release candidate there every cycle is genuinely load-bearing.

## What we are not asking for

- Not a full-time commitment. A few focused hours a week, reliably, beats a burst and then silence.
- Not "know the whole codebase". Nobody does. Owning one area well is the point.
- Not Rust, for several of the areas above.
- Not exclusivity. Maintain other projects, take a break, hand an area back — all fine, just say so.

## What you get

- An invite to the [`librefang`](https://github.com/librefang) GitHub org and commit access for your area.
- Review rights on the paths your area owns via CODEOWNERS.
- A voice in project direction, per `GOVERNANCE.md` — technical decisions here happen in issues and PRs, in public.
- Your name in `MAINTAINERS.md`.

## How we decide

The bar in `MAINTAINERS.md` is "a record of constructive reviews, merged contributions, and reliable follow-through on user-facing issues."
We read that as evidence over promises, and we do not require that evidence to come from this repo.

The process:

1. We reply in this thread — expect a response within a week.
2. For most areas we start with triage plus review rights on that area for a few weeks, so both sides can find out whether it fits.
3. Commit access and a `MAINTAINERS.md` entry follow, as a PR against that file, the same way any other change lands.

Applications are rolling. There is no deadline and no fixed number of slots.
