# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Navisworks Manage 2027: plugin bundle crashes host at startup (silent exit after 10-20 s, no WER record)**

*Project description:*
## Summary

On Navisworks Manage 2027, loading the nwd-mcp v2.5.1 plugin bundle kills the
host process during startup. Roamer.exe exits silently 10-20 s after launch,
with no Windows Error Reporting event, no crash dump and no .NET Runtime error.
With the bundle renamed away, the same Navisworks starts and runs normally.

This matches the README's note that 2022-2024 and 2026-2027 shells are
build-verified against their APIs but have not been run live. It looks like
2027 has a real startup defect.

## Reproduction

1. Run `install.ps1` from the setup ZIP (all default locations).
2. Launch `Roamer.exe` (Manage 2027).
3. Observe: splash stage only, process gone within 10-20 s.

Three reproductions with `PowerShell Start-Process -PassThru`, checked via
`Get-Process` every 10 s inside the same parent process:

| Run | pid | t+10 s | t+20 s |
|---|---|---|---|
| 1 | 54604 | ALIVE (92 MB) | - |
| 2 | 36980 | (died before next check) | - |
| 3 | 49720 | ALIVE (87 MB) | DEAD |

Diagnostics after each death, all empty for Roamer.exe:

- Windows Event Log `Application` id 1000 / 1001 / 1026 (searched last 30 events)
- `%LOCALAPPDATA%\CrashDumps` (no Roamer dump)
- `%LOCALAPPDATA%\Autodesk\Navisworks 2027\` (no new cache/log writes that day)

So the host terminates without WER involvement, i.e. a clean/silent exit rather
than a caught native crash.

## Control experiment (plugin removed)

Renamed the bundle folder to `Bimwright.Nwd.bundle.disabled`, relaunched the
same `Roamer.exe` the same way:

| t | State |
|---|---|
| +10 s | ALIVE, 468 MB |
| +20 s | ALIVE, 694 MB |
| +30 s to +60 s | ALIVE, ~695 MB (fully loaded) |

Same machine, same launch method, same moment; the only variable is the plugin
bundle. Navisworks Manage 2027 itself is healthy on this machine.

## Expected behaviour

Navisworks Manage 2027 starts with the plugin loaded and writes the target
descriptor (`%LOCALAPPDATA%\Bimwright\nwd-mcp\navis-2027-<pid>.json`).

## Notes

- Both arms of the experiment launched `Roamer.exe` via `Start-Process` from an
  automation agent rather than a manual double-click, so the differential is
  valid but a manual-double-click data point was not taken.
- The dying stage is the splash/bootstrapping stage (87-92 MB); it never gets
  far enough to write Navisworks caches, which suggests the failure happens
  during plugin assembly loading/initialization.
- Happy to test a fixed build or collect more evidence (procmon trace, fusion
  log, verbose plugin loader log) if you tell me what you need.
