### Type

Spike / Investigation

### Summary

We need someone to sign in with DPoP-bound tokens on a real Android phone and a real iPhone, so the proofs are signed by the phone's secure hardware. `examples/auth` has a mode that runs its sign-in server inside the app, so no Keycloak and no network setup are needed.

Expected result: a short report per phone.

### Intent

DPoP binds a login token to a key that never leaves the phone, so a stolen token is useless elsewhere. The DPoP code moved to the new `fespalier_keypair_dpop` package, and its key now comes from `fespalier_keypair` (fespalier/fespalier#269). The tests use a fake key. This checks the real hardware key end to end.

### Expected Behavior

Folder: `examples/auth`. Run with:

```sh
flutter run -d <your phone's id> --dart-define=OIDC_ISSUER=demo --dart-define=DPOP=true
```

1. **Sign in** with the demo provider as `ada` / `ada`. Expected: no prompt (the DPoP key never asks for a fingerprint), and the orders page loads.
2. **Orders.** Open an order. Expected: it loads.
3. **Restart.** Swipe the app away, open it again. Expected: still signed in, and the orders load.
4. **Wait 6 minutes** with the app open (the demo token lives 5 minutes), then open an order. Expected: it loads, with no visible sign-in: the app renewed the token, with a new proof from the phone's key.
5. **Sign out**, then sign in again. Expected: both work.

### Technical Context

**Getting the app on your device (about 15 minutes the first time):**

1. Install Flutter 3.44 or newer: https://docs.flutter.dev/get-started. Run `flutter doctor` and fix what it reports for your platform. An iPhone needs a Mac with Xcode; an Android phone needs Android Studio's SDK.
2. Get the code:
   ```sh
   git clone https://github.com/fespalier/fespalier
   cd fespalier
   git checkout feat/auth-device-sessions   # only until fespalier/fespalier#269 is merged
   ```
3. Enable developer mode on the phone and plug it in. Android: Settings → About phone → tap "Build number" seven times, then turn on USB debugging. iPhone: Settings → Privacy & Security → Developer Mode.
4. In the example's folder (each case says which one):
   ```sh
   flutter create --empty . --platforms=android,ios,web   # adds the platform folders
   flutter pub get
   flutter devices                                         # find your phone's id
   flutter run -d <your phone's id>
   ```
   On an iPhone the first run may ask you to pick a signing team: open `ios/Runner.xcworkspace` in Xcode, select Runner → Signing & Capabilities, choose your Apple ID's team, then run again.

If a step does not match what you see, say so in a comment: that is a useful finding too.
