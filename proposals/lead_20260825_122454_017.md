## Why this one matters more than the other follow-ups

ADR 0003 (`docs/adr/0003-an-agent-gated-data-refresh-may-auto-merge.md`, on `main`) sets three preconditions before an unattended refresh may auto-merge. Two of them were repository settings, and **the owner has now applied both** — verified live, independently, twice:

```
allow_auto_merge: true
main protection: required_checks ["web-ci"], strict false, enforce_admins false
```

**This is the only precondition still open.** It is now the single thing standing between the `modeltree-refresh` skill set and a live unattended publisher, which is a materially different situation from when the ADR was written.

## The gap

`tools/updater/src/modeltree_updater/gates.py` defines a `source-approval` gate. The skill set in `.github/skills/` has **no equivalent**. It relocates that function to the scout — pre-review and agent-mediated — rather than enforcing it as a gate.

`npm run validate` cannot stand in for it. `sources.json` is itself patchable by a run, so a run that adds a source record *and* cites it satisfies referential integrity while citing a source nobody approved. Validation proves the citation resolves; it does not prove the thing cited was ever trusted.

That is precisely the failure this repository's central rule exists to prevent: *every important fact carries a primary source and a verification date*. A self-approved source keeps the letter of that rule and loses all of its value.

## Acceptance criteria

- [ ] A `source-approval` equivalent exists in the skill-set gates and runs **as a gate**, not as scout guidance — i.e. it can refuse, and refusal is not overridable.
- [ ] A run that adds a new source record to `sources.json` and cites it in the same change is **refused**, not accepted. This is the load-bearing case; a test that only covers citing a pre-existing approved source does not discharge it.
- [ ] The gate's decision is recorded in the run's published output (PR body or summary issue), so a human can see that it ran and what it allowed.
- [ ] The self-tests in `gates.test.mjs` prove the new rule fires by breaking real data the way the rule exists to catch — matching the existing suite's stated standard — and the added tests are shown to fail when the rule is reverted.
- [ ] ADR 0003's precondition 2 is either marked satisfied or the ADR is amended to say what remains, in the same change.

## Explicitly out of scope

- Turning the automation on. This closes a precondition; enabling is a separate, deliberate decision.
- Any bypass, `--force`, or skip flag. ADR 0003's own guardrail is that a genuine exception belongs in branch protection, where it is auditable.
- Reconciling the Python and JS gate implementations generally — that is a separate follow-up.
