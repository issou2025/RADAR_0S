## Brief

**What:** Cut `revit-1.1.0` from `main` once the connected host is verified live, and submit that release, not `revit-1.0.0`, to the Autodesk storefront.
**Why:** The storefront listing was staged with `revit-1.0.0` but never submitted, so the build it carries can still change. `revit-1.0.0`'s own known issues are fixed only on `main`: an idle signed-in Revit drops out of the vault's export list about an hour after signing in (#501), and `Uninstall.cmd` reports a failure when it cannot ask its last question (#499). Shipping the connected host to the storefront without the first fix would ship #430 broken after an hour.
**Waiting on:** #558's three live checks passing, so any fix they need lands before the cut. Then: `ready-for-agent` for steps 1 to 3; steps 4 to 6 are the founder's.

## What to build

The cut follows [`docs/releases.md`](https://github.com/mantleplace/mantleplace-dcc/blob/main/docs/releases.md):

1. **Version bump** on `main`: `<Version>` in `revit/Directory.Build.props` to `1.1.0`, the one place the Revit build declares it. A pull request, landed.
2. **Gate at that merged commit**, against the packaged zip (`revit/tools/Package-MantlePlaceRevit.ps1`): the three-year release gate from the Revit README (the ribbon loads and one real import completes in Revit 2025, 2026 and 2027, installed copy-first from the zip), plus the connected-host check #558 ran, on the packaged build.
3. **Draft the release** `revit-1.1.0 — Mantle Place for Revit` with the zip as its only asset, its body per the template. *Upgrading from 1.0.0*: nothing to do. *What's new*, one line each: the session renews before its sign-in lapses, so an idle Revit stays in the export list (#501); Open in Curator (#528); "Did this import come in right?" after an import (#500); an adjacent bundle builds at its offset from the project's first one (#573); an unattended uninstall keeps local data instead of failing (#499). Left as a draft for the founder.
4. **Publish** the release (founder), then download the asset and check its sha256 and its copy-first install, recorded under *Verification*.
5. **Storefront** (founder): in the staged listing, replace the app file with `MantlePlace-Revit-1.1.0.zip`, set the version number to `1.1.0` with a one-line version description, file the trade-compliance form, submit, and reply to the reviewer as #460 describes. Record the date and sha256 on the release's *Storefront* line.
6. **Correct `revit-1.0.0`'s release body** (founder): its *Storefront* line says it was submitted on 2026-10-29 and is in review. It was staged that day and never submitted; the line should say so and point to `revit-1.1.0`.
