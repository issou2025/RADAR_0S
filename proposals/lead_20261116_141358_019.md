# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Find out whether a Flutter app can drive the engine on Linux and Android**

*Project description:*
For anyone building the cross-platform demo app, this spike shows whether Flutter with `dart:ffi` can load the ggtts C library, render one line and play it on Linux desktop and on Android. Today the only app is native Android, and no Flutter code exists.

**Timebox:** one working day. **Question:** can a thin Flutter shell call `ggtts_load_opts` and `ggtts_render_opts` with an options document on Linux and Android, and what does it cost (build steps, library size, blockers)? The answer decides the stack for the epic.

## Acceptance criteria
- [ ] AC1: On Linux desktop, the app under `apps/flutter/` loads the ggtts C library, checks `ggtts_abi_version() >= 5`, renders one line through `ggtts_render_opts` with a JSON options document, and plays it; Evidence: run log and a screenshot or recording.
- [ ] AC2: On Android (arm64 device or emulator), the same app does the same with the library built for Android; Evidence: `adb logcat` excerpt and a screenshot.
- [ ] AC3: If loading fails (for example a missing model with download off), the app shows `ggtts_last_error()` and does not crash; Evidence: screenshot or log of the error path.
- [ ] AC4: A finding records the answer: what worked, build steps, library and APK sizes, blockers, and a go or no-go for Flutter; Evidence: the finding linked from this issue.

## Steps
- [ ] Scaffold `apps/flutter/` with Linux and Android targets.
- [ ] Dart FFI bindings for the ABI 5 calls the spike needs.
- [ ] Build the library for Linux and for Android arm64; load it from the app.
- [ ] Play the returned PCM.
- [ ] Write the finding.

Parent: the cross-platform demo app epic. Local builds count as evidence while CI minutes are unavailable.
