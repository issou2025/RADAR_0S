# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**permission_handler_android 14.0.0` hard-references API 37 symbols (`ACCESS_LOCAL_NETWORK`, `CINNAMON_BUN`) — breaks compilation on `compileSdk 36**

*Project description:*
### Summary

`permission_handler_android 14.0.0` references Android API 37 (Android 17) symbols as hard compile-time constants in `PermissionUtils.java`, with no `@RequiresApi` annotation, no reflection fallback, and no string-literal fallback. The plugin's own `build.gradle.kts` declares `compileSdk = 37`, so any project that compiles against `compileSdk 36` (the current stable API level) fails to build the `:permission_handler_android` module.

### Environment

- `permission_handler`: 14.0.0 (direct dependency, `^14.0.0`)
- `permission_handler_android`: 14.0.0
- Android Gradle Plugin: 9.0.1
- Kotlin: 2.3.20
- App `compileSdk`: 36
- App `targetSdk`: 36
- App `minSdk`: 28
- Plugin `compileSdk` (declared in `permission_handler_android-14.0.0/android/build.gradle.kts:31`): 37

### Reproduction

1. Add `permission_handler: ^14.0.0` to `pubspec.yaml`.
2. Set app `compileSdk = 36`.
3. Run `flutter pub get`.
4. Run `flutter build apk` → compilation of `:permission_handler_android:compileDebugJavaWithJavac` fails.

### Root cause

`permission_handler_android-14.0.0/android/build.gradle.kts:31` declares `compileSdk = 37`, and `PermissionUtils.java` references API 37 symbols directly as compile-time constants:

- Line 98 — inside a `switch` statement, no guard possible:
  ```java
  case Manifest.permission.ACCESS_LOCAL_NETWORK:
      return PermissionConstants.PERMISSION_GROUP_ACCESS_LOCAL_NETWORK;
  ```
- Lines 608-619 — a `PERMISSION_GROUP_ACCESS_LOCAL_NETWORK` case was added. This block includes a runtime guard:
  ```java
  case PermissionConstants.PERMISSION_GROUP_ACCESS_LOCAL_NETWORK:
      // The ACCESS_LOCAL_NETWORK permission is introduced in API level 37 (Cinnamon Bun)
      if (
          Build.VERSION.SDK_INT >= Build.VERSION_CODES.CINNAMON_BUN &&
          hasPermissionInManifest(
              context,
              permissionNames,
              Manifest.permission.ACCESS_LOCAL_NETWORK
          )
      ) permissionNames.add(Manifest.permission.ACCESS_LOCAL_NETWORK);
      break;
  ```
  The runtime guard (`SDK_INT >= CINNAMON_BUN`) is correct in intent, but it is moot: the symbols `Build.VERSION_CODES.CINNAMON_BUN` and `Manifest.permission.ACCESS_LOCAL_NETWORK` cannot be resolved by the Java compiler when compiling against `android.jar` API 36, because those symbols do not exist in API 36. The compilation fails before the runtime guard can ever take effect.

### Expected behavior

`permission_handler_android 14.0.0` should compile against `compileSdk 36` by using reflection or string-literal equivalents (e.g. `"android.permission.ACCESS_LOCAL_NETWORK"`) for API 37 symbols, with a runtime `SDK_INT` guard — rather than hard compile-time references that require `compileSdk 37`.

### Suggested fix

Replace hard references to API 37 symbols with string constants guarded by `SDK_INT`:

```java
// Instead of:
case Manifest.permission.ACCESS_LOCAL_NETWORK:
    ...

// Use a string constant + runtime check:
private static final String ACCESS_LOCAL_NETWORK = "android.permission.ACCESS_LOCAL_NETWORK";
...
if (Build.VERSION.SDK_INT >= 37 && ACCESS_LOCAL_NETWORK.equals(permission)) { ... }
```

This pattern is already used elsewhere in the Android ecosystem for forward-compatible access to permissions introduced in newer API levels.

### Workaround (for affected projects)

Downgrade the Android sub-package via `dependency_overrides` in `pubspec.yaml`:
```yaml
dependency_overrides:
  permission_handler_android: 13.0.1
```
Then run `flutter pub get` and `flutter clean`. This pins the Android sub-package to the compileSdk-35-compatible version. Note that `ACCESS_LOCAL_NETWORK` is not needed when `targetSdk < 37` (local network access is implicitly granted via `INTERNET` per the official Android documentation).
