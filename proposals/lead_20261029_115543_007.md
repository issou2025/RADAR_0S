## Binding product decision — Offline-only local import (2026-10-29)

**Approved Butlerly product principle:** For Alpha, Butlerly must provide **no application-level online accounts, cloud document connectors, automatic background sync, remote document fetching, online assistant/help search, or remote finance-data processing**. The user acquires/downloads documents **outside Butlerly**, then explicitly uses the device's local file picker to import a downloaded file. Butlerly parses, validates, reviews and stores accepted data **on-device**. No automatic changes to online source documents, and no continuous synchronization.

- Example: Google Drive / iCloud Drive / OneDrive / Dropbox / online bank → user downloads a supported file to the device → opens Butlerly → chooses Import → selects locally available file → reviews rows, fixes errors, handles duplicates → confirms local storage.
- If a cloud document is only a URL or provider-native file that Butlerly cannot parse, tell the user to **download/export into a supported local format** (e.g. CSV where supported) using the source service first. Do not ask for account credentials, OAuth access or an API key.
- No connected provider dashboards, automatic URL fetch, webhooks, file surveillance, real-time exchange rates, third-party OCR/AI calls or remote telemetry may silently be added to the Alpha build. Audit for existing network use and disable/remediate any in-app network-dependent features unless the owner expressly authorizes a narrowly scoped exception in a later release.
- App-store distribution and OS-level download activity outside Butlerly are different from Butlerly application data integration; users remain free to download their files using a browser or provider application. File import begins only after deliberate selection by the user.
- **Offline acceptance:** Airplane mode after installation: creating/editing/searching/reviewing data, importing supported downloaded files, local analysis, backup/restore, and bundled Help Search/FAQ all work without Butlerly contacting an Internet endpoint.
- Update actual shipping behavior, Legal & Privacy claims and user-help copy; avoid claiming a provider-native document (e.g. Google Docs online) can be imported before export or that import constitutes synchronization. The app should say **“Download the document to your device, then import it into Butlerly.”**
- This rule takes priority over older online-integration proposals. Any future connected service requires an **explicit new owner decision**, separate privacy/security/store review, and does not become authorized merely because it is present in a backlog issue. No code change or deployment is authorized by this issue edit.

**Required FAQ example:** **Q: Can Butlerly synchronize my documents from Google Drive, iCloud Drive, OneDrive, Dropbox or my bank?** **A:** “Not directly. Download or export the document to a supported file format on your device first. In Butlerly, choose Import, select the local file, review the results, and confirm. Butlerly does not connect to your cloud account or keep the file synchronized.” Link to a practical guide section on downloading/exporting from outside the app, file formats, local import, correction and duplicate review. Include EN / zh-Hans / es; make it findable by **sync, cloud, Google Drive, iCloud, OneDrive, download, import, bank statement** without calling the internet.

## Alpha Help Center decision — Search + FAQ (October 29, 2026)

**Owner-confirmed release requirement:** In addition to the comprehensive versioned User Guide, Butlerly shall provide an **in-app Help Center with searchable topics and a concise, browsable FAQ** so people can find practical answers without reading the whole manual. This is included in the Alpha release scope, not a future paywalled feature.

### Help Center UX
- [ ] Make **Help & FAQ** easy to find under Settings (and accessible from relevant error/empty states where appropriate), with a consistent responsive design on phone, tablet and desktop. No additional account, cloud service, AI key, or connection needed.
- [ ] Put a prominent **Search help** input at the top; on initial load show topic categories, **Popular questions**, and a clear link to **View full User Guide**.
- [ ] Search the bundled local documentation with short query matches across **titles, question wording, keywords/synonyms, tags, and article body**; case-insensitive and diacritic-tolerant where feasible. Rank exact title/FAQ matches before broader text matches. Return concise title/snippet/type (FAQ vs guide), section, and open-in-place article detail. Avoid showing empty or unrelated results as if they matched.
- [ ] Debounce entry appropriately, clear/reset search easily, support keyboard Return/search/focus and screen-reader labels, and handle **no results** with relevant topic links and the agreed support/bug-report route (do not invent support contact).
- [ ] Search is **offline on device**. Do not send queries, user records, typed financial information, or search analytics to any external service. Use bundled versioned articles and a deterministic local search/index; avoid new backend or speculative chatbot dependency.
- [ ] Provide **short answers first** with optional **Read more** anchor to the full guide/article; link from relevant FAQ entries to the actual feature/page when route and user state safely permit. Links to Settings/Backup must not automatically perform destructive actions.
- [ ] Use the same canonical content source or generated artifacts for FAQ/search/guide; no contradicted duplicate guidance. Match the finalized Alpha app's actual UI labels, backup/restore semantics and supported locales. Include accessible contrast/large text/dark mode.

### FAQ taxonomy and starter questions
- **Getting started & accounts:** Do I need a Butlerly account? Does Butlerly work offline? How do I change language, currency or time zone? What is the optional Financial Profile Survey?
- **Transactions & imports:** How do I add or edit a transaction? How do I import a CSV or statement? Why does a receipt not immediately create a confirmed transaction? What if an import fails?
- **Review & duplicates:** What does Keep Both mean? What does Consolidate mean? Why is an item marked Needs Review? Why do my totals differ from an imported statement?
- **Analysis & budgets:** Why are some totals unavailable? What happens with multiple currencies and missing FX rates? How do I view the transactions behind a chart? How do I create or edit budgets?
- **Privacy, backups & recovery:** Where is my data? How do I make an encrypted backup? What is the difference between Merge and Replace? What happens if I change/lose a device? How do I export or permanently erase data?
- **Platform & support:** Can I use multiple Apple/Android devices? Is automatic sync included? Are purchases or Family Pro available in Alpha? How can I report an Alpha problem?

### Content and implementation requirements
- [ ] Every FAQ answer is short (usually 1–4 sentences), accurate about Alpha, with actionable steps and a **Read detailed guide** link when appropriate; no generic speculative assurances about security, sync, purchases, or recoverability.
- [ ] Bundle an initial reviewed FAQ set in **English, Simplified Chinese, and Spanish**, aligned with the UI localization and user guide. Use stable article/FAQ identifiers and translated titles/keywords rather than translating user queries online; define a fall-back for missing translations without pretending they're localized.
- [ ] Content is easy to maintain (e.g. local structured JSON/Markdown assets with stable keys, locale and guide section anchors); choose the least complex integration that fits the existing Flutter app architecture. The final guide/editorial master may live in Google Drive, but the shipped help content must work offline and be traceable to the tagged release commit.
- [ ] Avoid duplicate search results for the same FAQ and linked guide section where possible; ranking and grouping should prioritize a direct answer, then longer reference articles.
- [ ] Test relevant search terms and spelling/case/diacritics, empty query, no results, FAQ-to-guide navigation, offline mode, stable IDs, broken links, and accessibility/responsive behavior on mobile/tablet/desktop.
- [ ] No usage tracking, external help-provider SDK or AI-generated answer at Alpha unless explicitly approved. A future AI help assistant may use the same content, but is **out of scope** for the Alpha Help Center.

### Additional release acceptance
