# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[Column] Probe: read the slab above, and can a longitudinal bar be BENT?**

*Project description:*
Two live questions stand between the roof addendum's math and its placement. Both are API shape, not detailing, and this project does not guess either.

## 1. The slab above — R37's read

R37: the roof slab's **thickness and cover are READ** from the element above, never typed. Today `find_support_face_z_mm` returns only a **z**; it must hand back the element too.

Unknown, and needed before §1 can be built:
- what the upward search actually finds at a roof column — a `Floor`, a `RoofBase`, a structural framing element?
- which parameter gives its **thickness** for each of those
- which gives its **cover**, and whether a slab carries top/bottom cover separately the way a column does
- what comes back when the element above is a roof rather than a floor, since the spec says "slab" throughout

**Stated default already recorded under R37:** if nothing is found, the tool refuses. The probe should confirm what "nothing found" looks like.

## 2. A bent longitudinal bar

`rft/revit/column_place_bars.py` builds exactly **one** `Line.CreateBound` per bar — a straight `RebarStyle.Standard` bar pinned with `SetDistanceToTargetHostFace`. §1 needs a bar with a **horizontal leg bent into the slab**, which is two curves in the array through the same `CreateFromCurves` call, and has never been run.

- does `CreateFromCurves` accept a two-curve `Standard` bar at all, and what does `normal` mean for one (#109 proved it only for a `StirrupTie` loop)?
- do the host-face constraints still resolve — `_pin_to_host_faces` is what makes the straight bar exact, and #92 measured the offset sign the hard way
- or is this a `RebarShape`/hook job rather than a second curve?
