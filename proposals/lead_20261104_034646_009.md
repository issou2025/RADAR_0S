## 概要

iOS / macOS / visionOS 27.3 beta の **Siri AI Developer Preview** で、スキーマに当てはまらない独自の App Intent も Siri が「ツール」として呼べるようになった。codegen をこれに対応させる。IntentTodo で 27.3 beta（27C5020n）を調べた結果をもとに、このリポジトリへの反映案をまとめる。

- [Siri AI Developer Preview](https://developer.apple.com/documentation/appintents/siri-ai-developer-preview) / [Bringing custom actions and content to Siri](https://developer.apple.com/documentation/appintents/bringing-custom-actions-and-content-to-siri) / [App skills](https://developer.apple.com/documentation/appintents/orchestrating-complex-actions-with-app-skills) / [Siri Evaluations](https://developer.apple.com/documentation/sirievaluations)
- プレビューが動くのは開発署名のビルドと TestFlight の内部テスターだけ（外部 TestFlight と App Store では無効）。Apple Intelligence に対応した端末が必要で、watchOS / tvOS は対象外

## SDK で確かめた事実（27.2 → 27.3 の AppIntents swiftinterface は追加だけ）

- `ToolIntent: AppIntent`（要件なし）、`AppIntentTraits.tool`、`@AppIntent(_ traits:)` / `@AppIntent(_:schema:)`。iOS / macOS / visionOS 27.3
- `GenerableEntity: TransientAppEntity`、`@AppEntity(.generable)`
- `IntentVisibility`（`.default` / `.internal`）。`@Property` / `@ComputedProperty` / `@DeferredProperty` に `description:` / `authenticationPolicy:` / `visibility:` が増えた（anyAppleOS 27.3）
- **どれも 26.x / 27.2 の SDK には存在しない**ので、`@available` ではなく `#if` で囲む必要がある（CLAUDE.md の「Which SDK actually has the symbol」の基準どおり）
- `xcrun sirimetadataanalyzer <App>.app`（27.3 beta のツールチェーンにだけある）。実機がいらず、ビルド成果物に対して回せる。**ツールが 0 本だと SMA109 しか出ず、ほかのルールは対象が無いので何も見ない**（IntentTodo で実測）

## 反映案

1. **`@IntentSpec(tool: true)`** → `@available(iOS 27.3, macOS 27.3, visionOS 27.3, *) extension <Intent>: ToolIntent {}` を出す（既存の struct は変えないので、iOS 17 の挙動はそのまま）。`#if APP_INTENTS_WWDC26`（または新しいフラグ）で囲む
   - **primary domain（reminders / messages / notes / system など）のスキーマを採用した Intent に付けるとビルドエラー**。`schema:` と同時に指定されたら、生成の段階で `InvalidGenerationSourceError` にする。Shortcuts 専用ドメイン（books / journal など）だけは併用できる
   - **ツールは、Siri がアプリに届く限りいつでも呼ばれる**。Flutter エンジンが立ち上がっていないと動かない経路（URL スキームモード、foreground の cache モード）はツールに向かない。FlutterBridge モード + コールドスタート時の挙動を確かめてから、どのモードで許可するかを決める
   - Apple のスキル（`siri-app-integration`）は「検索・発見のツールを作らない（Siri は `IndexedEntity` / `EnumerableEntityQuery` で entity を自分で探す。ツールでは `suggestedEntities` は使われず、`entities(for:)` は必須）」と言っている。README / usage にも書く
2. **`@EntityProperty(description:, visibility:)`** → `@Property(title:description:visibility:)`。ただし **27.3 より前の OS にも出す entity に `description:` を付けるとビルドエラー**になる。iOS 17 を最小 OS にしているこのパッケージでは、生成した entity を丸ごと 27.3 限定にしない限り使えない。出し方（27.3 限定の別の型を作る / 出さない）を ADR で決める
3. **`@EntitySpec(generable: true)`**（`TransientAppEntity` のみ）→ `@AppEntity(.generable)`。**プロパティにアプリ所有の entity を入れるとビルドエラーになり、そのターゲットの App Intents メタデータが丸ごと出力されなくなる**ので、生成の段階で検出する（値型 / AppEnum / generable entity とそれらの配列だけを許可する）
4. **App skills**: `Skills.skillsbundle/Skills/<name>/SKILL.md`（frontmatter は `name` と `description` だけ、本文は 1 万字まで）。Runner ターゲットの Copy Bundle Resources に入れる。エラーが 1 つでもあると **1 本も出荷されない**し、Copy Bundle Resources に入っていない場合は警告も出ない。docs で手順を案内し、frontmatter を検証する CLI（`name` がディレクトリ名と一致するか、文字数、余計なファイルが無いか）を足すかどうかを検討する
5. **検証**: `scripts/verify_experimental_swift.sh` に 27.3 SDK での型検査を足す。example app を `sirimetadataanalyzer` にかけて、指摘 0 件（info を除く）を CI 外の手順として docs に書く
6. **SiriEvaluations**: 実機専用で、テストターゲットのデプロイメントターゲットを 27.3 以上にする必要がある。example app 用のシナリオの雛形（`AppIntentsTests/` と同じ扱い。型検査だけ）を置くかどうか

## 🌐 English

## Overview

The **Siri AI Developer Preview** in iOS / macOS / visionOS 27.3 beta lets Siri call custom App Intents as "tools", even ones that fit no system schema. This issue covers bringing that support to the codegen. The proposals below come from investigating 27.3 beta (27C5020n) in IntentTodo. The preview only works in development-signed builds and for internal TestFlight testers (not external TestFlight or the App Store), needs an Apple Intelligence device, and does not cover watchOS or tvOS.

## SDK facts (27.2 → 27.3 AppIntents swiftinterface: additions only)

- `ToolIntent` (no requirements) plus `@AppIntent(.tool)`, `GenerableEntity` plus `@AppEntity(.generable)`, and `IntentVisibility`. `@Property` / `@ComputedProperty` / `@DeferredProperty` gain `description:` / `authenticationPolicy:` / `visibility:`.
- **None of these exist in the 26.x / 27.2 SDKs**, so they need `#if` gating, not `@available`.
- `xcrun sirimetadataanalyzer` ships in the 27.3 beta toolchain and needs no device. With zero tools it reports only SMA109, because the other rules have nothing to check (measured on IntentTodo).

## Proposed changes

1. `@IntentSpec(tool: true)` → a gated `@available(iOS 27.3, …) extension X: ToolIntent {}`. Combining it with a primary-domain schema is a build error, so reject that combination at generation time. Tools can be called whenever Siri can reach the app, so the URL-scheme and foreground cache modes (which need the Flutter engine) are poor fits; verify FlutterBridge mode on a cold start first. Do not generate search tools.
2. `@EntityProperty(description:, visibility:)` → `@Property(...)`. `description:` is a build error on any entity that also ships below 27.3, which matters because this package's floor is iOS 17. Decide the emission strategy in an ADR.
3. `@EntitySpec(generable: true)` → `@AppEntity(.generable)`. An app-owned entity property is a build error that drops the target's App Intents metadata entirely, so validate this at generation time.
4. App skills (`Skills.skillsbundle`): document the setup and consider a frontmatter validator. A single error ships no skills at all, and a bundle missing from Copy Bundle Resources ships nothing without a warning.
5. Verification: add a 27.3-SDK typecheck to `verify_experimental_swift.sh`, and document a `sirimetadataanalyzer` run of the example app.
6. SiriEvaluations runs on a device only, and its test target needs a 27.3 deployment target. Consider adding a typecheck-only scenario scaffold.
