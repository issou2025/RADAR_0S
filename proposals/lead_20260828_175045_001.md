## Goal

Make the extension documentation package the source of truth for shared and platform-specific extension guidance. Each Markdown file should describe how agents can discover and route to it without a hard-coded catalog in the Assistant server.

## Work

- Move the current extension workflow, runtime, project metadata, and tooling guidance into canonical Markdown in this repository.
- Separate instructions that apply to every Assistant extension from Revit-specific guidance.
- Add platform documents for Revit first. Keep the structure ready for AutoCAD and Navisworks without copying shared instructions.
- Add YAML frontmatter to every packaged document.
- Require these fields:
  - `id`
  - `title`
  - `summary`
  - `applies-to`
  - `tasks`
- Support `recommended: true` for documents that agents should read early when their platform and task match.
- Validate the complete document set during package creation.
- Reject missing fields, duplicate IDs, invalid values, and unreadable Markdown.
- Continue publishing the documents through `CW.Assistant.ExtensionDocs.Bundle`.

Semantic search is outside this issue. The metadata and document structure should support it later without changing document IDs.

## Initial document structure

```text
assistant/how-assistant-works
extensions/development-workflow
extensions/project-metadata
extensions/runtime-rules
platforms/revit/development
platforms/autocad/development
platforms/navisworks/development
```

Only documents with real content need to ship in the first change. Revit is the first platform implementation.

## Acceptance criteria

- Shared documents contain no Revit-specific instructions.
- Revit documents contain only host-specific guidance and refer to shared documents by ID when needed.
- Every packaged Markdown file has valid YAML frontmatter.
- Package validation fails for duplicate IDs, missing required metadata, invalid platform or task values, and unreadable files.
- Recommended documents can be identified from metadata without reading their full content.
- The NuGet package contains the validated Markdown and preserves its document paths.
- Tests inspect the packed artifact rather than only the source directory.
