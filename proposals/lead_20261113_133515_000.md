# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Agent: get_context doesn't flag binaries built from another commit than the clone**

*Project description:*
Found while beta-testing the agent runtime: modeling a 30x30 cottage from an image, then sheets, schedules and captures through `pyrevit.exe mcp`. Revit 2026 (26.5.0.55), develop @ 149eb02, IronPython 3.4.2, policy `auto`, template `English-Imperial/Default-Multi-discipline.rte`.

## What happens

On a dev clone whose `bin/` was built 22 commits earlier (d85e4ae) than the checkout (149eb02), the first agent script using the documented import failed:

```
from pyrevit.revit.db import query
ImportError: Cannot import name ApiContextQueue   (pyrevit/revit/events.py:13)
```

`pyrevitlib/` loads live from the working tree and already needed the newer C# type, but the runtime DLLs didn't have it. Meanwhile `get_context` reported `"commit": "149eb02"` (the clone HEAD) next to `"version": "7.0.0.26278+2233"`, with nothing showing that the binaries came from another commit. An agent following the skills hits this on its first script, with no hint that a rebuild is needed.

## Suggestion

- In `AgentContext.Describe`, read the commit from the runtime assembly's `ProductVersion` (`...+2233.<sha>`). Report it as `pyrevit.bin_commit`, and add `bin_stale: true` plus a short hint (rebuild with `dotnet run -c Release -- local`) when it differs from the clone HEAD.
- Show the same in `pyrevit agent status`.

See also #4021 (local builds keep the old assembly version, so the version string can't tell builds apart).
