## Problem to fix

The live Brother intake path conflates physical pages, logical documents, and a completed scan session:

- a front-side pass is finalized by a 5-minute stale timer before the reverse-side pass is reconciled;
- reverse pairing rejects valid passes unless their page counts match and their gap fits a 4-minute window;
- a fully written second PDF can remain unprocessed after a synchronization/event failure;
- generic keyword evidence (for example, `Aufenthalt`) can override document context and route a bank contract as a migration document;
- an inference failure can be rendered as a successful-looking template Telegram report with no useful semantic result.

Implement the repair in the single canonical Skeleton document pipeline. Do not create a second watcher, worker, database, archive, MemoryGateway, Scheduler, or Telegram sender.

## Required behavior

1. **Separate pass, session, package, document, and page state.**
   - Persist a durable session identity, scanner/profile identity, pass identity, ordered component claims, and state transitions in the existing noncanonical operational state store.
   - Associate passes using explicit session/profile evidence; time alone or text/OCR similarity is not proof.
   - Do not require equal front/back counts. Preserve exact physical order and page provenance; support blank backs/placeholders without shifting later pages. Ambiguous orientation/pairing routes to REVIEW.
   - A stale timer may flag an incomplete session for REVIEW/recovery; it must never declare a duplex session successfully complete.
   - Finalization requires an explicit supported completion event/action. A finalized session is immutable; duplicate events/restarts are idempotent.
   - Split logical documents only on the existing deterministic physical separator contract. Blank pages and topic/issuer/name/date/OCR changes cannot split a package or document by themselves.
   - Verify assembled PDF readback, page count, and SHA-256 before existing OCR/intake runs.

2. **Make file intake recoverable.**
   - Reconcile fully written source files after watcher/event/synchronization failure.
   - Use stable size/mtime observations plus readback/hash, durable retry/backoff, and idempotent claims so a completed file cannot remain silently stranded or be processed twice.
   - Preserve original bytes and the current archive-before-memory ordering.

3. **Correct bank-contract classification.**
   - Add contextual rules for Mittelbrandenburgische Sparkasse/MBS account contracts and related banking forms.
   - Generic incidental terms such as `Aufenthalt` must not by themselves imply migration-document classification.
   - Represent bank/issuer, contract/form type, account owner when explicitly evidenced, fees/conditions, and uncertainty as structured fields.
   - Conflicting or weak evidence routes to REVIEW; no unsupported owner, fee, or contract terms may be fabricated.

4. **Make reports truthful and useful.**
   - Send one coherent package-level success report only after verified assembly, useful semantic output, and canonical archive commit/readback.
   - Never render an empty/default template as a successful semantic report.
   - If inference/reporting fails, enqueue one idempotent technical-failure notice with a safe reason code and aggregate counts, clearly distinguished from a completed-document report.
   - Preserve retry/restart idempotency and avoid duplicate success or failure notices.

5. **Handle the existing quarantine backlog safely.**
   - Add a bounded, idempotent inventory/re-evaluation path after the classifier/report fix, reusing the existing pipeline.
   - Keep records quarantined unless a complete evidence-backed result passes the current acceptance gate; uncertain cases remain REVIEW/quarantined.
   - Do not bulk-release, rewrite, delete, or re-archive historical documents during code generation. Keep private backlog contents/counts local; public receipts are aggregate-only.
