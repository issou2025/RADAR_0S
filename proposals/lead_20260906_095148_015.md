## Project Understanding

*Project description:*
**There is no `.github/` directory. Nothing runs the test suite except a person remembering to.**

Found by the PR #47 reviewer, while assessing whether the precache digest mechanism that PR introduces can actually be relied on.

## Why it surfaced now

PR #47 makes `app/sw.js` carry a digest of the nine precached files inside the cache name, so that changing a shell file without changing the cache name fails the suite. It is a good mechanism and it closes a hole that has cost this project twice. But its enforcement is exactly one thing: `uv run python -m pytest`, run by hand, by whoever happens to be looking.

That is a mechanism guarding a convention, guarded by a convention.

## The concrete failure it permits

The digest test fails on the **merge commit**, not on either branch. Two branches that do not touch the same file can each be green, merge cleanly with no textual conflict, and produce a red `master` that nobody has run.

This is not hypothetical. It is the exact situation on this repo right now: PR #47 changes `app/sw.js`, PR #48 changes `app/app.js`, `app/app.js` is precached, the two have no overlapping lines, and git will merge them without complaint into a `master` whose recorded digest is stale.

The same shape applies to the whole suite, not just the digest. Any two branches whose combination is red but whose halves are green will land silently.

## What already depends on nobody forgetting

- The digest matching the precached files (#46, PR #47).
- `git diff master -- app/` staying empty for the harness's guarantees (task 9b).
- `app/api.js` remaining the only file that calls `fetch` or names `/api` (#32).
- The domain layer importing with Flask absent.

Every one of those is a test. Every one of those tests only runs if someone runs it.

## Scope

A workflow that runs `uv sync` and `uv run python -m pytest` on push and on pull request, and a branch protection rule requiring it before merge.

Two things make it slightly more than boilerplate:

- **`node` 20 or later is a test-time requirement of this repo**, not an optional extra. `tests/shell_harness.mjs` is driven by pytest and a missing `node` fails the suite loudly and is never skipped. The runner must provide it.
- **Line endings.** The digest normalises `\r\n` to `\n` for text entries precisely so a `core.autocrlf=true` checkout and a `false` one agree. A Linux runner should therefore compute the same digest as a Windows checkout, and CI going green on Linux while a developer is red on Windows would be a defect in that normalisation worth knowing about immediately.

## Out of scope

Anything beyond running the existing suite. No linting, no coverage gate, no release automation, no matrix beyond what is needed to run the tests once.

## Note on how this was found

The reviewer was asked whether the #47 mechanism was sound or theatre. It judged the mechanism sound and then observed that its enforcement is not, which is the more useful finding of the two.
