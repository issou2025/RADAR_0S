## Summary

`versioning-full-history.yml` is the counterpart to BHoMBot's overnight `RunVersioning("full")` sweep. It exists and works, but it lives **only in `BuroHappoldEngineeringSandbox/BHoM_Installer`**, and every green it has ever produced is vacuous.

## Two problems

**1. Not in production.** `BHoM/BHoM_Installer` has no `.github/workflows` directory at all (contents API returns 404). So the `--test-all` dimension has no production coverage.

**2. Its baseline is vacuous.** Seven runs, all `success`, latest 2026-07-02 (`Versioning vs v9.2.0-alpha.beta.8`). **All seven predate #138** (merged 2026-08-05), which fixed the `CollectLeafFailures` traversal bug. Before that fix the runner could not report a failure at all. Those greens prove the plumbing works end to end (release lookup, `.msi` download, `msiexec` install, assembly-count floor, framework build, runner invocation). They prove nothing about the verdict. It has never run with a runner capable of failing.

## Why it matters

It is the only position that runs `--test-all`. Per the design spec (`2026-07-01-release-readiness-cross-build-design.md:120`), `--test-all` "stays with `versioning-full-history.yml`" while the per-PR and cohort positions run previous-version mode only.

The failure class it uniquely catches is a break in an **old link of the upgrade chain**. `FromJson.cs:43-48` tests only `9.2` by default and 24 versions with `--test-all`. A corrupted 5.0-to-5.1 upgrade step is invisible to a 9.2-only test but breaks any user opening a 4.0-era model file.

## Proposed work

1. Promote the workflow to `BHoM/BHoM_Installer`.
2. **Re-baseline before trusting it.** Dispatch once against a known release with the current runner, and treat the result as the first real measurement rather than a regression.
3. Decide whether the cadence gap matters. BHoMBot ran the sweep every 24h. This fires only on alpha-beta and beta release publish, and alpha builds no longer publish a Release (`build-installer.yml` PR #34), so there is no full-history signal between beta releases. Measured cost of the sweep itself is ~6 min of runner time (14.4s for the 7.8 MB 9.2 dataset on a 547-assembly closure, scaled to the 197.7 MB `--test-all` set).
