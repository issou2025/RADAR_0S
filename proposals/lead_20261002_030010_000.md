## Agent Brief

**Category:** enhancement
**Summary:** Publish one inventory, per host and per imported category, of what each plugin imports, when, what it costs and what that cost scales with.

**Current behavior:**
No document says, per host, which manifest pointer each imported category is read from, what it becomes in the host, whether it is imported by default, what it costs, and what that cost grows with.

- **Revit** has measured per-step figures, on order `4276ef78` in 2025, 2026 and 2027. Their one home is `SlowStepNotice.Measured(ImportStepKind)` in the Revit core, which feeds the import window's notices. Some step kinds have no entry there.
- **Unreal** has no measured import figures at all.
- The host support matrix (`docs/host-support.md`) states status only, by its own charter ("No cell describes behaviour"), so none of this fits in its cells.

**Desired behavior:**
A new document under `docs/` (for example `docs/import-inventory.md`) holds one table per host. Each table has one row per category that host imports today, with these columns:

| Column | What it holds |
|---|---|
| Manifest source | The pointer read, host block first (`HPS-52`), and the fallback when there is one |
| Becomes | The element or asset it becomes in the host |
| When | Always, on by default, off by default, or on request, as the host's import checklist or picker sets it today |
| Measured cost | For Revit, a citation of the `SlowStepNotice.Measured` entry by its `ImportStepKind`; never the figure restated. For Unreal, the figure itself, with the order, MPB version, Unreal version and plugin commit it was measured on |
| Cost driver | What the cost scales with: element count, pixel count, polygon count, vertex count. Name the manifest field that already publishes that count, if one does |
| Scale axis? | Whether a scale axis plausibly makes sense here, and which one. Marked as a hypothesis; #283's design note decides |
| Lost at lower scales | What a user would give up |

Where a published scale precedent already exists, the row says so. In MPB 1.8.0 these are `landcover.tree_points.point_count` and `hosts.unreal.foliage_points.point_count` (the tree cost driver), `landcover.tree_points.truncated_to_tallest` (present only when the platform capped the layer, keeping the tallest), `buildings.decimated`, and `hosts.revit.surface_dxf.decimated_from_triangle_count`.

**Measuring Unreal.** Measure every category Unreal imports on the same order as Revit. The bundle cached for order `4276ef78` (MPB 1.6.0) carries both the `revit` and the `unreal` host blocks, so both hosts' figures come from one file and no Prepare is needed. Unreal is measured in the consuming project named by `MANTLEPLACE_CONSUMING_PROJECT_ROOT`, with the editor headless. That project's plugin checkout is shared with other sessions, so put it back at its pin when done. Take at least two runs per category and report the range; a single run is labelled as one.

**The one home for each figure.** Revit's figures stay in `SlowStepNotice.Measured`, because the import window reads them at run time; the inventory links to them. Unreal's figures have no home in code, so the inventory becomes their home. A Revit row whose step has no entry in `Measured` says "not measured". If you measure it, the figure goes into `Measured`, not into the document.

**Key interfaces:**
- `SlowStepNotice.Measured(ImportStepKind)`: the Revit figures, cited by step kind, never copied
- The Revit import checklist and Unreal's import path: the source of each row's "When"
- The published MPB schema at `https://mantle.place/.well-known/schemas/bundle-manifest/`: the source of each "Manifest source" and of the cost-driver fields; cite field names, never restate values the schema owns
- The host support matrix: links to the new document from its opening prose, not from a cell

**Acceptance criteria:**
- [ ] A document under `docs/` carries the two tables, with `name` and `description` frontmatter, and passes `ci-public-hygiene` (the references job and the docs-integrity check).
- [ ] Every placement-content pointer that either host reads appears in a row, or is listed under the table as not imported, with the reason.
- [ ] No Revit figure is restated in the document; each Revit cost cites its `ImportStepKind` entry or says "not measured".
- [ ] Every Unreal row carries a measured range with the order, MPB version, Unreal version and plugin commit, or says why the category was not measured.
- [ ] Each row's "When" matches what the host does today, as checked against the code.
- [ ] The host support matrix links to the new document from its opening prose, and its cells are unchanged.
- [ ] Rows where MPB 1.8.0 already publishes a cost driver or a single-scale cap name that field.
- [ ] #283 gets a comment that links the merged document.

**Out of scope:**
- Proposing manifest fields, or choosing between tiers and a rank (#283's design note).
- Any change to import behavior, defaults, the checklist or the picker.
- Whether the platform builds every scale when an order is procured or when a host Prepares it. That is the platform's decision, recorded in #283's open questions.
- The site context view step's unexplained 3 to 4 minutes in 2026 and 2027 (#258).
- New Revit measurements beyond filling a step kind that has no `Measured` entry.
