### Steps to reproduce

The controller is initialized with `Unsent draft` and `[1,5]`, which selects `nsen`. After focus, the controller still reports this range, but native typing appends instead of replacing it.

1. Clone the repository and select the installed DN SDK explicitly if Flutter/FVM is also installed:

   ```sh
   git clone https://github.com/ManmohanTalwar/dartnative-input-selection-repro.git
   cd dartnative-input-selection-repro
   git checkout a5ef6659142fd5ec059cc9264726140db4f949b3
   DN_SDK=/path/to/zero
   "$DN_SDK/bin/dn" --suppress-analytics pub get
   "$DN_SDK/bin/dn" --suppress-analytics run -d DEVICE_ID
   ```

2. **A — initial selection:** tap **Focus input**, allow it to settle, then **Capture state**. Without tapping inside the text field, type `X` through native input, then Capture state again.
3. **Expected:** the range `[1,5]` is active, so typing replaces `nsen` and produces `UXt draft`. **Actual on iOS and Android:** `Unsent draftX`; the controller reported `[1,5]` before input, then `[13,13]` afterward.
4. **B — passing control:** stop the app, then launch a fresh process with `--dart-define=INITIAL_RANGE=false`. Tap Focus input → wait → Capture state → Select range → wait → Capture state → type `X` → Capture state. This distinct assignment after focus correctly produces `UXt draft`, final range `[2,2]`, on both platforms.
5. **C — persistence control:** fresh default launch, Focus input → wait → Capture state → Select range (the same `[1,5]` already reported) → wait → Capture state → type `X` → Capture state. It still appends on both platforms. Equal-value notification suppression is not separately classified as a bug; this shows the original mismatch persists.

Each path used a fresh process and stable State/controller/FocusNode. No hot reload/restart or tap within the field occurred. Focus uses the documented post-frame callback. Capture only prints state; it does not rebuild or change the controller. Original actual typing used RocketSim on iOS and `adb shell input text X` on Android, with no programmatic text replacement.

| Case | iOS 26.5 simulator | Android 14/API 34 arm64 emulator |
|---|---|---|
| A: initial `fromValue` range | `Unsent draftX` (append) | `Unsent draftX` (append) |
| B: text-only, then assign range after focus | `UXt draft` (replacement) | `UXt draft` (replacement) |
| C: initial range, then equal reassignment | `Unsent draftX` (append) | `Unsent draftX` (append) |

All settled pre-type captures report selection `[1,5]` and focus true. The minimal app does not directly query native offsets or native object identity; actual typing provides the functional evidence. The optional Caret zero path was not run.

**Contract question:** should an initial `TextEditingValue.selection` be applied when the native field is mounted/focused? If this requires a different initialization sequence, please document the supported sequence. Otherwise, could initial selection and controller/native state be synchronized? The exact internal cause is not established, and the passing B control is not proposed as a general restoration/refocus workaround.
