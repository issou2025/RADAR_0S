# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Wayfinder map: Modernize the Windows-Hinting architecture**

*Project description:*
## Destination

A phased, agent-executable architecture spec for modernizing Windows-Hinting. Only the user-facing hint workflow (hotkey → labels → type → activate) is inviolable; the named-pipe protocol, preferences format, update channels, UI layer, and interop foundations may all change where justified. The spec lands as migration phases that coding agents can execute, each independently buildable and manually verifiable.

## Notes

- Domain: .NET 10 WinForms tray app; UI Automation via COM tlbimp `<COMReference>` (forces full MSBuild — see `.github/copilot-instructions.md`); CsWin32 for other interop; one overlay form per screen (PerMonitorV2); no automated tests today.
- The named pipe is distrusted (security); Talon Voice will ship an RPC mechanism in the future — external-control design should be forward-looking.
- Skills per session: `/grilling` + `/domain-modeling` for decision tickets; `/research` for research tickets; `/codebase-design` when drawing module boundaries.
- Research subagents resolve their tickets by commenting findings and closing; they do NOT edit this map. The next work session syncs Decisions-so-far from closed tickets.
- This effort is planning-only: decisions and the final spec, no production code changes.

## Decisions so far

<!-- one line per closed ticket: [title](link) — gist -->

- [Research: UIA interop paths beyond the COM tlbimp reference](https://github.com/knausj85/Windows-Hinting/issues/27) — `Interop.UIAutomationClient` NuGet is a verified drop-in escape (csproj swap + namespace change, ~17 files, identical semantics); unblocks `dotnet build`/`test`. CsWin32 and WinRT are dead ends today.
- [Research: Talon's planned RPC and secure local IPC options](https://github.com/knausj85/Windows-Hinting/issues/28) — Talon has no public RPC roadmap; assume a hand-written Python client. gRPC/AF_UNIX die on Python limits; ACL'd named pipes (`CurrentUserOnly | FirstPipeInstance`) close the real vulnerabilities. Current pipe: zero auth, squattable, and the Talon client targets a mismatched pipe name.
- [Research: Overlay rendering alternatives](https://github.com/knausj85/Windows-Hinting/issues/29) — current WinForms per-screen overlay is sound on every hard requirement; only deficiency is no per-pixel alpha. WinUI 3 disqualified, WPF poor fit; if alpha is wanted: `UpdateLayeredWindow` (small) or DirectComposition (best, most plumbing). Draw hints as pixels, never as UI elements.
- [Research: Distribution and update tooling landscape](https://github.com/knausj85/Windows-Hinting/issues/30) — `uiAccess="true"` forces a signed exe under Program Files, clashing with Velopack's per-user model; NetSparkle+WiX stays defensible with cheap wins (silent updates, winget listing); signing via Azure Artifact Signing ($9.99/mo) or SignPath ($0).
- [Decide: HintController decomposition and module boundaries](https://github.com/knausj85/Windows-Hinting/issues/31) — `WindowsHinting.Core` + host split; `HintEngine.Submit(Intent) → Effects` pure state machine as the single funnel; opaque `ElementRef` at the scanner seam; one scan pipeline with `HintSource` seam + rule-driven `ScanPolicy` + compiled-in `IScanStage` hatch; host owns all threading. Initial policies encode today's behavior exactly.
- [Decide: preferences infrastructure](https://github.com/knausj85/Windows-Hinting/issues/39) — preserve+notify on load failure (`.bak` + tray notice, per-field tolerance); explicit `version` + pure migration chain (current format = v0); `preferences.json` + `rules/` directory of per-app files (file = rule list, embedded built-ins, name overrides, rules carry `ScanPolicy`); human-readable key syntax ("Ctrl+Alt+H"); one propagation path (watcher → validate → `OptionsApplied` intent, UI has no privileged write path); pure logic in core, I/O in a host `PreferencesStore` adapter.
- [Decide: UIA interop path](https://github.com/knausj85/Windows-Hinting/issues/32) — CsWin32 `GeneratedComInterface` is the target, hard-gated (no fallback) on a stable CsWin32 release containing PR #1746; an early phase extracts UIA interop into a leaf project (`WindowsHinting.Interop.Uia`) so Core gets `dotnet build`/`test` immediately; tlbimp `<COMReference>` lives in that leaf until the gate lifts. Refines #31: scanner adapter is its own assembly.
- [Decide: preferences UI](https://github.com/knausj85/Windows-Hinting/issues/40) — modern WinForms, restructured; singleton non-modal window with instant apply through the #39 watcher path (live preview *is* the applied change, no OK/Cancel); section pages behind a tiny contract + registry (General, Hotkeys, Click actions, Updates); window rules absent from the UI entirely (hand-edited `rules/` files, docs only); "Start with Windows" becomes a preferences field with host registry reconciliation, eliminating the UI's last privileged write path.

## Out of scope

- Structured window-rules/`ScanPolicy` editor UI — [Decide: preferences UI](https://github.com/knausj85/Windows-Hinting/issues/40) removed the rules surface from settings entirely; rule files are the hand-edited, documented interface. A rich editor would be a fresh effort if ever wanted.
