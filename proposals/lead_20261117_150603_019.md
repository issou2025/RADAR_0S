*Project description:*
## Problem Statement

When running live tabletop roleplaying sessions, relying on periodic 3-second HTTP polling between the Raspberry Pi edge audio pipeline, Google Apps Script, and the browser UI produces perceptible 3-to-6 second latency delays for background music mood changes and rule lookups. In the heat of combat, this delay breaks the cinematic illusion. Furthermore, tracking initiative across 5 to 6 players requires constant verbal turn reminders from the Game Master.

From the players' perspective, joining the Player Companion previously required manual Google Account authentication or cumbersome email logins, creating significant onboarding friction at the physical table. Mobile browsers frequently evict inactive tabs or reload pages when players switch to other apps, wiping their claimed session identity. Curious players inspecting network payloads via mobile DevTools could uncover unrevealed ambush monsters or secret monster statistics if encounter data is delivered in monolithic documents. Finally, distracted players easily miss their combat turns, slowing down table gameplay.

## Solution

A Dual-Engine architecture that splits real-time operational concerns from asynchronous campaign governance:

1. **Real-Time Tabletop Engine (Cloud Firestore & Firebase Web SDK v11)**: Sub-50ms push delivery of Audio Cues, Combat Tracker updates, Table Reactions, and Rule Cards via Firestore `onSnapshot` listeners, replacing all polling loops.
2. **Frictionless Mobile Onboarding**: Zero-friction table QR code onboarding via Firebase Anonymous Authentication with `browserLocalPersistence` (IndexedDB) and atomic character roster claiming via `runTransaction`.
3. **Ambient Player Engagement**: Web Haptics vibration alerts on combat turns, illuminated character status indicators, a 5-emoji live table reaction drawer, and non-intrusive push-to-talk rule card popups with feedback ratings.
4. **Secure Document Partitioning**: Declarative Firestore Security Rules enforcing GM-only administrative writes and strict document partitioning (`combat_gm` private stats vs. `combat` public projection) to prevent DevTools data leaks.
5. **Edge Audio Dispatcher**: Raspberry Pi edge audio pipeline writing directly to Cloud Firestore in <35ms, backed by an 800ms timeout budget with instant failover to local GM Screen LAN webhooks and offline queue spooling.
6. **Asynchronous Campaign Secretary (Google Apps Script)**: Retains exclusive responsibility for heavy Google Workspace automations (Calendar Quorum, Drive audio archiving, Tasks promise extractions).

## User Stories

1. As a Game Master, I want ambient music mood cues to transition in under 50 milliseconds when the edge audio pipeline classifies a scene shift, so that the audio atmosphere at the table matches the narrative tension instantly.
2. As a Game Master, I want hidden ambush monsters and secret monster HP to be partitioned into a private GM-only document, so that curious players inspecting network payloads on their phones cannot spoil upcoming encounters.
3. As a Game Master, I want to advance initiative on the GM Screen and have the active combatant immediately update on all connected devices without polling, so that combat moves swiftly.
4. As a Game Master, I want a 1-click "Force Release" button on my Roster panel, so that I can immediately unassign a character if a player leaves the table or their phone battery dies.
5. As a Game Master, I want table chatter and ambient player laughter to be suppressed at the edge, so that normal table banter does not trigger errant music changes or flood the database with unneeded writes.
6. As a Game Master, I want to see floating real-time emoji reactions from players above the initiative tracker, so that I can gauge party sentiment and excitement during epic narrative moments.
7. As a Game Master, I want campaign scheduling, calendar quorum checks, and post-session Google Drive audio archiving to remain in Google Apps Script, so that my existing campaign management workflows continue uninterrupted.
8. As a Player, I want to scan a physical QR code on the table with my smartphone and be instantly connected without creating an account or typing a password, so that I can join the session in under five seconds.
9. As a Player, I want to select my character from an unclaimed roster with atomic concurrency protection, so that another player and I cannot accidentally claim the same character at the same time.
10. As a Player, I want immediate visual and haptic feedback if another player claims a character a fraction of a second before me, so that I understand why the card was locked and can select an alternative character.
11. As a Player, I want my claimed character identity to persist across mobile browser refreshes and tab switches, so that I don't have to re-select my character every time my phone wakes from sleep.
12. As a Player, I want to receive a tactile vibration pattern and an illuminated screen banner when my combat turn starts, so that I never hold up the initiative order even if I was momentarily looking away from the board.
13. As a Player, I want an ambient 5-emoji reaction drawer at the bottom of my companion screen, so that I can react with swords, shields, dice, cheers, or skulls to dramatic rolls without shouting over the GM.
14. As a Player, I want relevant Rule Cards identified by the audio sniffer to pop up unobtrusively on my companion screen, so that I can quickly reference official 5e rules during tactical disputes.
15. As a Player, I want to rate sniffer rule cards as helpful or irrelevant with a single tap, so that the audio classifier model improves over time without disrupting our game.
16. As a Player, I want to be locked to a single character claim at a time, so that no player can accidentally or maliciously hoard multiple party members.
17. As a Player, I want an explicit confirmation modal when switching to another character, so that I don't release my current character accidentally.
18. As an Edge Audio Dispatcher, I want to write classified audio cues directly to Cloud Firestore via the Python Admin SDK, so that table mood transitions bypass external HTTP polling overhead.
19. As an Edge Audio Dispatcher, I want an 800ms timeout budget for Firestore writes that immediately fails over to the local GM Screen LAN webhook, so that network glitches never stall the edge audio pipeline.
20. As an Edge Audio Dispatcher, I want an offline write-ahead spooling queue in the session audio manifest, so that cues captured during internet dropouts are safely recorded and reconciled once connectivity is restored.
21. As a System Administrator, I want declarative Firestore Security Rules that validate data types, string bounds, and allowed keys, so that rogue client requests cannot corrupt live session state.
22. As a System Administrator, I want client-side Firestore offline persistence configured with multi-tab synchronization and a 100MB LRU cache, so that the web app functions smoothly even across spotty Wi-Fi connections.

## Implementation Decisions

### Modules & Interfaces
- **LiveTabletopClient**: Firebase Web SDK v11 wrapper managing Modular SDK initialization, multi-tab `persistentLocalCache`, `signInAnonymously`, and `onSnapshot` listeners for `audio_cue`, `combat`, `roster`, and `reactions`.
- **RosterClaimManager**: Atomic `runTransaction` handler managing character claiming, local storage caching, 1-PC lock enforcement, and race-loss card animations.
- **CompanionHUD**: Responsive mobile UI delivering ambient combat turn alerts, Web Haptics (`navigator.vibrate`), 5-emoji reaction tray, and floating Rule Card modal.
- **EdgeFirestoreDispatcher**: Python edge module in `scripts/rpi_vad_chunker.py` using `firebase-admin` with 800ms timeout budget, local webhook failover, and banter suppression.
- **FirestoreSecurityRules**: Declarative `firestore.rules` defining role-based access control, document partitioning (`combat_gm` vs `combat`), and atomic transaction safety.

## Testing Decisions

- **Good Test Criteria**: Tests must validate external observable behavior and contracts rather than internal implementation details.
- **Client Tabletop & Companion Seam (`test/client.test.ts`, `test/mobile_ux.test.ts`)**: Tested via JSDOM and `ClientHarness`. Mocks Firestore snapshot streams and validates that DOM elements, turn banners, Web Haptics vibration calls, and 5-emoji reactions update correctly without polling.
- **Edge Audio Dispatcher Seam (`test/vad_chunker.test.ts`)**: Tested via Python CLI subprocess execution. Validates <35ms Firestore write latency, 800ms fallback failover to local webhook, banter suppression, and offline queue spooling.
- **Cloud Firestore Security Rules Seam (`test/firestore_rules.test.ts`)**: Tested via `@firebase/rules-unit-testing` against the Firebase Local Emulator. Validates all 12 security test cases (`SEC-01` through `SEC-12`) including GM write permissions, DevTools leak prevention on hidden ambush monsters, and atomic character claiming without theft.

## Out of Scope

- Streaming raw audio bytes through Cloud Firestore (raw audio streams via WebRTC / Google Drive).
- Migrating Google Workspace governance automations (Calendar Quorum, Drive folder creation, Tasks promise extraction) out of Google Apps Script.
- Vertex AI for Firebase 5e Rules Arbiter structured JSON streaming in the browser (Phase 3).
- Firebase Remote Config parameterization for VAD thresholds and crossfade timings (Phase 4).
