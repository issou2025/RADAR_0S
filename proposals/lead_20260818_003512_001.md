## Why Parsing is +1.7 GB

The 16 MiB parse window and the 64 MB source LRU are not this number. Candidates, in the order I would measure:

1. **Grow-only wasm heap, started early.** Prefix extract tessellates up to 512 products *during parse*. Wasm memory is an `ArrayBuffer` and shows up in `usedJSHeapSize`. The design doc already names this sink (`streaming-federated-loader.md`: “Grow-only wasm geometry heap. ~2 GB on PSB at steady state.”).
2. **THREE preview meshes** retained in the preview group until finish (real vertex payloads, not the unit-cube imposters).
3. **Columnar index + maps** — SoA should be ~16 B/entity ≈ 150–200 MB on PSB, not 1.7 GB. Worth confirming, not the first suspect.
4. **Prefix cap not actually binding** — `StorePreviewChannel` defaults: 512 units / 48 MB copied payload. If either cap is bypassed, parse heap and parse time both go to the durable pump.

A heap snapshot at end-of-parse (before Geometry) answers this in one pass: wasm `ArrayBuffer` vs THREE `BufferGeometry` vs leftover STEP views.

## Remaining levers (evidence order)

These are independent. Do not start a room/floor allocator; spatial structure is for imposters / visit-order / latency hide only.

1. **Attribute the Parse +1705 MB.** Snapshot as above. If it is wasm, prefix extract is “first pixels” bought by pulling Geometry’s heap into Parsing. If it is uncapped preview copies, fix the cap.
2. **Stop paying extract twice.** Prefix tessellates; the durable `ExtractGeometryBatchAsync` pump tessellates the same products again. Either reuse the preview mesh as durable, or skip re-extract for already-emitted express IDs. This is the most plausible reason Share total stayed ~63 s while local Node extract is 23 s.
3. **Explain Share Geometry = 38 s.** Local prefetch is gone. Profile the Share Geometry phase: wasm tessellation vs THREE upload vs any leftover JS walk. Do not assume the 15 s Faces[] walk is still in there.
4. **Reclaim wasm after the JS mesh exists.** That is the actual path to mesh + index + 64 MB. It is M3 on #390 (demand-driven, evictable geometry / per-product reclaim), not another window-size tweak. `window=` is already 61 MB.
5. **#446 lever 2 is still open** (do not construct 9.1 M `IfcIndexedPolygonalFace` entities). #514 stopped *pinning* them for packed extract. If anything still hydrates `Faces[]` as entities, that is still #446, not a new issue.
6. **Network write-through** is Share #1602. This smoke is OPFS-cache only. Do not close #1602.
