# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**CreateStairs rejects multi-segment baselines that turn clockwise (-2130313215)**

*Project description:*
**Tapir version:** 1.5.7 (includes the #444/#445 multi-segment fix) · **Archicad:** 28 (Windows)

Multi-segment stair baselines whose corners turn **clockwise** (right turns) consistently fail with `-2130313215 "Failed to create new Stair"`, while the **mirrored or reversed** polyline of the exact same geometry (turning counter-clockwise) creates fine.

### Repro (empty project, story at 0.00)

```json
// FAILS — L-shape turning right (clockwise)
{ "stairsData": [ { "baseLinePoints": [ {"x": 30, "y": 30}, {"x": 36, "y": 30}, {"x": 36, "y": 24} ],
                    "zCoordinate": 0.0, "totalHeight": 3.0 } ] }

// WORKS — same L mirrored, turning left (counter-clockwise)
{ "stairsData": [ { "baseLinePoints": [ {"x": 30, "y": 40}, {"x": 36, "y": 40}, {"x": 36, "y": 46} ],
                    "zCoordinate": 0.0, "totalHeight": 3.0 } ] }
```

Also reproduced with real U-shaped walklines from a Revit conversion: the clockwise ones fail in every parameter combination we tried (with and without `flightWidth` / `stepNum` / `riserHeight` / `treadDepth`), while their reversed polylines create fine.

### Context

This is a follow-up to #444: since that fix, `CreateStairsCommand::SetTypeSpecificParameters` deliberately leaves `memo.stairBaseLine.edgeData` / `vertexData` null so that `ACAPI_Element_Create` derives them from the baseline geometry. The turn-direction dependency presumably lives in that derivation — the default winder/turning rules appear to solve only one direction. So the straightforward workaround (reverse the polyline) is available to callers, but it silently changes the stair's up direction, which is not always acceptable.

Happy to provide more failing/working polylines, including the real U-shaped ones, if that helps.
