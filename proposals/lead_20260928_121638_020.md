# [Documentation/Bug] Fix for CUDA 13.x / RTX 50-series initialization failure on Windows

### The Problem
On modern Windows machines running newer NVIDIA hardware (RTX 50-series / Blackwell architecture) paired with the **CUDA 13.x Toolkit**, the automated `start_llama_server.ps1` script fails to detect the GPU. It drops straight back to CPU threads, displaying the following error:
`ggml_cuda_init: failed to initialize CUDA: no CUDA-capable device is detected`

This happens because the pre-compiled `llama-server.exe` binaries inside `.\bin\cuda\` are statically bound to CUDA 12 naming structures (looking for files like `cudart64_12.dll` in the flat `bin` folder) which do not match the new CUDA 13 directory layouts (where runtime files like `cudart64_13.dll` are located inside `bin\x64`).

---

### The Working Formula / Solution
To bypass the automation failure and force the backend binary to bind directly onto the GPU under CUDA 13.4, users need to explicitly inject the new runtime subdirectories into their terminal environment before execution.

#### 1. Map the Environment Variables
Run this block inside your standard PowerShell terminal session to bridge the driver gap and target your hardware:
```powershell
# Point the runtime to your active CUDA 13 directory
set "CUDA_PATH=C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.4"

# Force the execution path to look inside the x64 subfolder where the real DLLs live
set "PATH=%CUDA_PATH%\bin\x64;%CUDA_PATH%\bin;C:\Windows\System32;%PATH%"

# Force the engine to target your RTX 50-series card explicitly
set "CUDA_VISIBLE_DEVICES=0"
```

#### 2. Launch Using the Direct Binary Bypass Command
Instead of running the global Python space or the automated setup script, fire the native backend binary directly from the localized repository path:
```powershell
.\bin\cuda\llama-server.exe -m .\models\bonsai2-gguf\27B\Ternary-Bonsai-2-27B-PQ2_0.gguf --mmproj .\models\bonsai2-gguf\27B\Ternary-Bonsai-2-27B-mmproj-Q8_0.gguf -ngl 99 -c 4096 -t 16
```

---

### Verified Performance Benchmarks
After applying this manual configuration, a **Ternary Bonsai 2 27B (`PQ2_0`)** model successfully offloads all layers to VRAM on an **RTX 5060 (16GB)** and a **Ryzen 9 5950X**, achieving highly accelerated local speeds:
* **Prompt Processing / Ingestion:** ~413.25 tokens per second
* **Active Token Generation:** ~43.13 tokens per second
