# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**fix: the app crashes repeatedly while CarPlay is connected**

*Project description:*
Reported from the field: several crashes with CarPlay open.

## What is needed first

Crash logs from the phone. **Settings → Privacy & Security → Analytics & Improvements → Analytics Data**, anything named `Runner-*` or `TailEndCharlie-*` around the time of a ride, plus any `CarPlayTemplateUIHost-*`. Which process dies matters: our app crashing and the CarPlay template host crashing look identical from the driver's seat (the head unit returns to its home screen) and have completely different causes.

## Known adjacent finding, not a substitute

On the **iOS 26.x simulator** any `CPMapTemplate` aborts `CarPlayTemplateUIHost` with

```
-[CPSTemplateInstance vehicleSupportsDestinationSharing]: unrecognized selector
```

That is Apple's code reached via the simulator's incomplete CARSession, it is not reproducible on iOS 17.5, and it is documented in `docs/build-and-run.md`. A real head unit supplies a complete session, so **this is probably not what the field is seeing** — do not close the field report against it.

## Where to look in our code

The CarPlay scene now does considerably more than when it was status-only: an MLNMapView canvas, a live annotation set rebuilt on every snapshot, a CPAlertTemplate for the TEC request, and a CPNavigationSession. Each is a candidate.

- `apps/mobile/ios/Runner/CarPlaySceneDelegate.swift`
- Snapshot publishing in `apps/mobile/lib/features/ride/active_ride_shell.dart`

Rider annotations are removed and re-added wholesale on each snapshot while the map may be mid-style-load; the retained-snapshot replay in `didFinishLoading` is a plausible re-entrancy path worth ruling out first.

Safety-relevant: a rider mounts the phone and rides. A crash mid-ride loses the journal's live surface at the moment it matters most.
