## Required v0.2 work

### 1. Bracketed guest sampling
Upgrade `probe` to a versioned sample schema with an acquisition shape equivalent to:

```text
MONOTONIC_RAW before
REALTIME
MONOTONIC
BOOTTIME (when available)
MONOTONIC_RAW after
```

Record bracket width and preserve missing/unavailable fields explicitly.

Requirements:
- standard-library-only runtime;
- no privilege/elevation;
- no service writes;
- retain legacy v0.1 probe input support in `analyze`;
- document that guest RAW brackets do not create a Windows-host reference.

### 2. Fixed-window, uncertainty-aware analysis
Add reusable pure functions for:
- interval/rate enclosure;
- three-way classification: `WITHIN`, `OUTSIDE`, `INDETERMINATE`;
- fixed windows;
- signed realtime events with uncertainty;
- missing/duplicate/invalid geometry handling.

Important:
- never replace an interval with its midpoint for classification;
- early adverse windows must remain visible even if the full-run average improves;
- thresholds must be explicit parameters or clearly documented historical/example settings, not universal definitions of health.

### 3. Read-only adjtimex observation
Add a Linux read-only kernel-state reader using `adjtimex(modes=0)` or an equally bounded standard-library approach.

Requirements:
- explicit ABI/layout validation;
- initially support only verified Linux x86-64 LP64 layout if necessary;
- unsupported ABI => structured `unavailable`, not guessed parsing;
- expose raw fields needed for interpretation, including `tick`, `freq`, status, error fields where available;
- do not claim a single snapshot proves a pending slew is absent.

Integrate snapshots into `diagnose` and optionally probe samples where cleanly supportable.

### 4. Bounded settle observation
Add a finite read-only observation capability. A dedicated `settle-check` command is acceptable, but it must report observational states, not universal benchmark certification.

Preferred vocabulary:
- `WITHIN_CONFIGURED_BAND`
- `ANOMALY_OBSERVED`
- `INDETERMINATE`

Do **not** emit unconditional `BENCHMARK_READY` / `SAFE` verdicts.

The historical candidate predicate `tick == 10000 && abs(freq/65536) < 100 ppm` over repeated reads may be implemented only as an explicitly named/example policy or test fixture, not as a universal truth.

### 5. Synthetic regression fixtures
Create synthetic fixtures/tests for at least:
- nominal/healthy-looking guest-relative trace;
- D4R2-style early-slew → later-normal trace;
- C1-style periodic sawtooth shape;
- positive step;
- negative step;
- backward realtime;
- missing sample;
- duplicate sample;
- threshold-straddling interval;
- common-mode guest case demonstrating that guest-relative cleanliness does not prove host agreement;
- historical adjtimex-style nominal/non-nominal examples without copying private raw bytes.

Synthetic data must be parameterized/recreated, not copied from private evidence files.

### 6. Method-aware compare/report semantics
Improve `compare` so it records and checks:
- schema version;
- clock pair/reference;
- method/acquisition type;
- window size;
- completeness/coverage;
- thresholds/settings;
- relevant continuity label if available.

Return a comparability status such as:
- `COMPARABLE`
- `DIFFERENT_METHOD`
- `INSUFFICIENT_CONTEXT`

Do not silently compare unlike clock/reference methods as equivalent.

### 7. Documentation/tests
Update README/methodology/limitations for new behavior.
Add focused tests on Python 3.12 and 3.14 CI.
