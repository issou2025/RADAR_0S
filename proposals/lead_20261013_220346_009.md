## What to build

Code generation works again, reproducibly. With the current local Flutter (3.47.x, Dart 3.13), `build_runner` hangs: `riverpod_generator` reports a missing visitor for newer syntax (`visitDotShorthandPropertyAccess`), because the locked analyzer (7.6.0) and generators (riverpod_generator 2.6.5 and others) predate the SDK. Decision: pin the project to **Flutter 3.44.2** now. Upgrading the generators (Riverpod 3 and so on) is a separate, later ticket.

Pin the version so every developer and agent uses it: add an FVM config at the Flutter project root, add a Flutter SDK constraint in the pubspec environment so `pub get` fails clearly on a wrong version, and document it in the development doc. Then regenerate all generated files with the pinned toolchain. That includes the three `.g.dart` files hand-edited in #3 (their hashes are placeholders).

Note: on the main developer machine, the folder named `flutter_windows_3.44.2-stable` actually contains 3.47.7, so a real 3.44.2 install (via FVM) is needed.

## Acceptance criteria

- [ ] `flutter analyze` shows no new issues and `flutter test` passes on the pinned toolchain
