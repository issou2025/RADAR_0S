## Why this exists

## The "adapt, don't literally mirror" call

dengjen-tts's CI/ruleset is built for its own shape (Python wheels via maturin, Java/Go bindings, Kokoro, Sonar, CodeRabbit, 75% code coverage gate). piper-rs has none of that — a single crate plus one workspace member, no Sonar/CodeRabbit configured. Copying dengjen-tts's files verbatim would have shipped a ruleset requiring status checks (`Sonar`, `CodeRabbit`) that would never report, permanently blocking every PR. The fix was: port only the Rust-native jobs that make sense (clippy, fmt, deny, audit, test), and a ruleset requiring only checks that actually run. If tashkeel or another repo ever needs its ruleset rebuilt from scratch, check what integrations are actually configured on that repo before copying another repo's required-status-checks list.

## Gotchas hit along the way (generic, apply anywhere)

- **YAML**: an unquoted colon inside a `name:` step field (`name: cargo test (default features: foo)`) is invalid YAML and fails the whole workflow file with zero jobs registered, no useful inline error — GitHub just reports "likely a workflow file issue." Validate with `python3 -c "import yaml; yaml.safe_load(open('f.yml'))"` before pushing.
- **cargo-deny-action runs with `--all-features` by default.** A license check that passes locally with default features can fail in CI once an optional feature's dependency graph is pulled in. Test with `cargo deny --all-features check ...` locally, not bare `cargo deny check`.
- **Scope license allowances to the crate that needs them.** `cargo-deny`'s `licenses.exceptions` (`{ allow = [...], crate = "name:version" }`) is safer than a blanket `licenses.allow` entry — a global allow silently permits that license for *any* future dependency, not just the one you added it for. CodeRabbit caught this on piper-rs's PR and it was a legitimate fix.
- **`clippy --all-targets` compiles dev-dependencies too** (examples/tests/benches), which can drag in system-library requirements (here: `rodio`'s `cpal` backend needing `libasound2-dev`) that the crate itself never needs. Scope clippy to `--lib --bins` if the crate ships without those deps, matching what dengjen-tts already does for the same reason.
- **`clippy --all-features` can hit a deliberate `compile_error!`** if a crate treats two features as mutually exclusive (piper-rs does this for its `espeak-rs`/`espeak-ng` backends). Lint each feature combination in its own step instead of one `--all-features` pass.
- **espeak-ng's global state isn't thread-safe.** Tests that call into it need `--test-threads=1` or they segfault under parallel execution — dengjen-tts already works around this for its own espeak-ng-backed crates; piper-rs's `espeak-rs` crate needed the same treatment.
- **Enabling CI on a repo that never had it will surface real, pre-existing bugs immediately.** Decide up front whether to fix them as a prerequisite or ship CI with them `#[ignore]`d and tracked separately — don't let that decision silently expand the scope of a "just add CI" task.

  preset, `git-submodules.enabled` for the vendored espeak-ng submodule
- `.github/workflows/zizmor.yml` — lints the Actions workflows themselves; complements
  the existing `cargo-deny` + `rustsec/audit-check` supply-chain checks
- `.github/workflows/publish.yml` + `.github/scripts/wait-for-crate.sh` — automates the
  tiered crates.io publish (espeak-rs-sys → espeak-rs → piper-rs) that was previously
  three manual `cargo publish` commands in BUILDING.md, mirroring dengjen-tts's
  tag-triggered (`publish-*`) pattern
- `.pre-commit-config.yaml` — added `check-ast`/`check-case-conflict`/`check-yaml` + a
  zizmor hook alongside the existing Rust hooks (dengjen-tts runs these two sets as
  separate, complementary repos, not one replacing the other)
- **A real license bug**: `espeak-rs-sys` vendors and compiles espeak-ng's full source
  (GPL-3.0-or-later) as a submodule, including in the default feature set — the compiled
  result is a GPL derivative, but `Cargo.toml` declared MIT on all three crates with no
  `LICENSE` file at all. Fixed: added `LICENSE` (GPLv3), `license = "GPL-3.0-or-later"`
  on all three crates, moved the allowance into `deny.toml`'s main list as the
  workspace's own license instead of a scoped dependency exception. Already-published
  0.2.0 releases on crates.io stay MIT (immutable) — only the next publish is affected.
- `SECURITY.md` — added, adapted from dengjen-tts

### New gotchas for the list above

- **A blanket `*.json` `.gitignore` rule silently swallows any new `.json` config with
  zero error.** `.github/renovate.json` didn't show up in `git status` at all — not
  untracked, not ignored-looking, just absent. `git check-ignore -v <path>` is what
  surfaces it (`.gitignore:3:*.json .github/renovate.json`). Worth grepping any repo's
  `.gitignore` for a bare `*.json`/`*.yaml`/etc. before assuming a new config file will
  actually get committed.
- **Branch protection is increasingly Rulesets, not the legacy endpoint.**
  `gh api repos/{owner}/{repo}/branches/main/protection` returned "Branch not protected"
  (404) on all three repos even though all three have an active ruleset. Check
  `gh api repos/{owner}/{repo}/rulesets` instead, and diff the full JSON
  (`gh api repos/{owner}/{repo}/rulesets/{id}`), not just enforcement/target — the
  interesting differences (required checks, dismissal restrictions, allowed merge
  methods) are inside `rules[]`.
- **"Repo settings" spans several non-file surfaces** — worth checking all of them when
  asked to match another repo: `gh api repos/{owner}/{repo}` (merge/discussions flags),
  `gh api repos/{owner}/{repo}/private-vulnerability-reporting`, `gh secret list -R`
  (repo secrets) *and* `gh api orgs/{org}/actions/secrets` (org secrets — easy to miss;
  `CARGO_REGISTRY_TOKEN` turned out to already be an org secret with `visibility: all`,
  so the new `publish.yml` needed no secret setup at all).
- **Check whether an upstream fork actually shipped a LICENSE file before assuming an
  MIT-relicense needs an attribution NOTICE.** dengjen-tts needed one (Sonata's MIT
  LICENSE had a named copyright holder to retain under GPL). piper-rs's upstream,
  thewh1teagle/piper-rs, has `"license": null` on GitHub's own repo API and no LICENSE
  file — nothing to retain, so no NOTICE was needed here despite the superficially
  similar fork-relicense situation.
