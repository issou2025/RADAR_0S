**Media: resource status and storage analysis (parent)**

*Project description:*
## Problem Statement

The Media page is still a Local Comic metadata-embedding dashboard (ADR-0058). Users need a **Media management overview** that shows resource status/storage, embedding status, and Comic trash summary with clear action entries—without the Media surface taking over other modules’ business rules. Opening Media must not highlight Home in the shell NavigationRail.

## Solution

Rename the internal feature module to **Resource status and storage analysis**. Keep the user-facing page and product label as **Media**.

That module:

1. **Owns** Inventory, Probing, Storage Accounting, and Reconciliation (query-side read model; observation cache; explicit Check).
2. **Assembles** the Media page from (a) its own analysis UI, (b) `resource_metadata` public APIs for embedding status/settings/ops, (c) `comic_trash` public APIs for trash count summary and trash-page/cleanup entry.

It does **not** own Resource metadata embedding execution/opt-in semantics or Comic trash purge rules/failure handling.

A new ADR supersedes ADR-0058’s Media page scope. Embedding policy (ADR-0057) and Comic trash lifecycle (ADR-0023) stay with their owners.

## User Stories

1. As a library owner, I want a Media overview that shows resource health/storage, embedding status, and trash summary together, so that I manage holdings from one place.
2. As a library owner, I want the product label to remain Media while the module is Resource status and storage analysis, so that navigation stays familiar.
3. As a library owner, I want Inventory to list Resources with library, format, size, and catalog links, so that I can see holdings relative to the catalog.
4. As a library owner, I want Catalog entry count, Resource count, File count, and Image page count shown separately, so that I am not misled by a single number.
5. As a Comic library user, I want Catalog entry count to mean visible non-trash Comics, so that trash does not inflate holdings.
6. As an Image set library user, I want Catalog entry count to mean Image sets (not Image set images), so that set-level scale is clear.
7. As a library owner, I want Resource count and Resource total size deduplicated by Resource identity, so that shared carriers are not double-counted.
8. As a library owner, I want File count to count enumerable files without expanding archive internals, so that file scale stays honest.
9. As a library owner, I want Image page count to mean Comic pages or Image set images, so that reading-unit scale is distinct from files.
10. As a library owner, I want Probing with classified failures (path missing, permission denied, Library root unreachable), so that I know what to fix.
11. As a library owner, I want Media observations cached with last checked time, so that opening Media does not walk every directory and does not pretend cache is live.
12. As a library owner, I want an explicit Check action to refresh observations, so that I control I/O cost.
13. As a library owner, I want Media observations distinct from Library resource snapshots, so that sync success is not mistaken for a Media check.
14. As a library owner, I want Storage Accounting to report Resource total size with unknown sizes excluded from sums, so that space figures stay honest.
15. As a library owner, I want copy that does not claim exact disk usage when hard links/sparse/allocation are unhandled, so that precision is not overstated.
16. As a library owner, I want Reconciliation to report only (missing Resource, changed observation, etc.), so that repairs stay in sync/refresh/purge flows.
17. As a library owner, I want Local Comic, Remote Comic, and Local Image set libraries included in analysis, so that one overview covers in-scope catalog kinds.
18. As a library owner, I want Healthy mode and Comic trash exclusion applied to analysis visibility, so that counts match the rest of the app.
19. As a library owner, I want embedding status and Library opt-in on Media via `resource_metadata` public APIs only, so that writeback rules stay in that module.
20. As a library owner, I want a Comic trash summary and trash-page entry on Media via `comic_trash` public APIs only, so that purge rules stay in that module.
21. As a library owner, I want `/media` to leave NavigationRail/Bar with no Home selection, so that shell selection matches the page.
22. As a developer, I want the renamed module to own analysis + Media page composition, so that overview layout has a single owner without absorbing foreign domains.
23. As a maintainer, I want GLOSSARY and a superseding ADR, so that agents share vocabulary.

## Implementation Decisions

- **Media page**: Composition overview — layout and entries; not writeback/trash/analysis write-path owner beyond its own analysis module responsibilities.
- **Module rename**: Internal module = **Resource status and storage analysis** (slug in ADR, e.g. `resource_analysis`); user-facing name remains Media.
- **Module owns**: Inventory, Probing, Storage Accounting, Reconciliation + assembling Media page.
- **Composes externally**: `resource_metadata` (enable, status, writeback ops surfaces); `comic_trash` (count summary, cleanup entry if public, trash page navigation). Purge rules/failure handling stay in `comic_trash`.
- **Libraries in scope (analysis)**: Local Comic, Remote Comic, Local Image set.
- **Architecture**: Query-side read model over catalog + Resource access; not a second catalog. UI presents; Resource access enumerates/stats; accounting dedups/aggregates.
- **Inventory**: One row per Resource; catalog associations are projections.
- **Counts**: Catalog entry / Resource / File / Image page — as previously settled.
- **Probing**: Observation-only; classified failures; dedicated Media observation cache ≠ `library_resource_snapshots`; explicit Check only; open = read cache + last checked + non-live labeling.
- **Storage**: **Resource total size**; unknowns not zero; archive = carrier bytes; no exact disk-usage claim in v1.
- **Reconciliation**: Report-only.
- **Visibility**: Exclude Comic trash from analysis counts; Healthy mode; Image set default visibility.
- **Trash summary on Media**: Comic trash only in v1; summary + entry, not trash lifecycle UI.
- **Navigation**: `/media` → empty shell selection (not Home); fix bar clamp if needed.
- **ADR/GLOSSARY**: Supersede ADR-0058 page scope; GLOSSARY terms Media page, Resource status and storage analysis, Resource total size, Media observation.
- **Primary seams**: Media analysis read port inside the renamed module; WritebackGateway unchanged; `comic_trash` public summary/entry surface (new or extended).
- **Delivery**: Parent + children; revise in place.

## Testing Decisions

- Assert overview composition: analysis, writeback, and trash summary appear; foreign domains not reimplemented in the Media module.
- Assert Media analysis port: counts, dedup, unknown size, failure classes, cache vs live, Check writes cache.
- Assert `/media` does not select Home.
- Assert writeback and trash behaviors still owned by their modules (fakes at public seams).
- Prior art: `media_page_test.dart`, writeback overview tests, `comic_trash` count/service tests, shell empty-selection tests.

## Out of Scope

- Exact disk usage / hard-link / sparse / allocation accounting.
- Format-level corruption / fingerprint verification in Media probe.
- Media-driven catalog mutation, orphan deletion, reparse, purge.
- Media owning embedding executor or Comic purge rules.
- Image set trash (no Comic trash analogue) in the Media summary.
- Adding Media as a NavigationRail destination.
- Remote Image set libraries.
- Treating sync snapshots as Media last-checked without explicit Check.
