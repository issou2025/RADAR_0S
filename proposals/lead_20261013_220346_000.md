# Project Proposal — Pdf To Revit

## Project Understanding
You need assistance with: 
**Scope question: should CADCraft read IFC (BIM), going beyond AutoCAD the way BricsCAD does?**

*Project description:*
Before anyone writes code, a scope question for the maintainers.

CADCraft targets AutoCAD 2027 parity. AutoCAD itself does not read IFC: Autodesk's BIM path is Revit, and IFC comes only with the Architecture toolset (IFC2x3 certified, IFC4 without a Reference View or Design Transfer View guarantee). BricsCAD took the other route: its BIM edition reads and writes IFC natively, next to DWG.

Many architecture and structural-steel offices hand in PDF, DWG *and* IFC, and they receive IFC models from other trades every week. Several issues ask for BIM authoring (#748, #897, #985), which goes far beyond this; reading IFC is the small part of it. Today CADCraft has no IFC path, so those users need a second program beside it. IFC is an open buildingSMART/ISO standard, so unlike RVT or DWG nothing has to be reverse-engineered.

**The question:** is it OK for CADCraft to follow BricsCAD BIM here rather than AutoCAD, and add IFC support beyond AutoCAD parity? Or would you rather keep CADCraft at AutoCAD scope and see IFC in a separate crate or repo?

If yes, this is the small first step we'd propose. It doesn't touch `Drawing` and adds no 3D:

1. A new L0 crate `crates/ifc`: an ISO 10303-21 (STEP) reader with caps for hostile input, and a hand-written subset of IFC2X3/IFC4/IFC4X3 (spatial structure, elements, property sets, quantities, units, materials, types). No geometry, no new dependencies, and it must build for wasm.
2. Commands `ifc.open`, `ifc.tree`, `ifc.query`, `ifc.element`, `ifc.quantities` and matching MCP tools. The IFC model sits beside the drawing; nothing is merged into it. An agent could then answer "which beams are on level 2, with which profiles and lengths" or check a drawing's door schedule against the model.
3. Later, as a separate PR: IMPORT an `.ifc` as a 2D reference (a section of each storey, one layer per storey and class).
4. Export waits for the 3D foundations and its own decision.

Licences: no IfcOpenShell (LGPL), Bonsai (GPL) or openbimrs (AGPL), and we wouldn't port web-ifc or ifc-lite (MPL-2.0). The schema subset would be written from the public documentation. The official EXPRESS schema is CC BY-ND 4.0; we would neither vendor nor modify it.

Rough size: steps 1 and 2 about 12–20 agent hours, step 3 about 30–50 h.

If the answer is yes:
- Is a new L0 crate and an IFC side model in the session (not in `Drawing`) OK?
- Does ADR 0001 constrain this, for example a 3D kernel choice we should know about? (`plan/adr/0001` isn't in the public tree.)

We won't start until there's an answer.
