# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**File size and speed budgets, checked on real projects**

*Project description:*
As the project owner, I want file size and speed budgets checked automatically against real projects, so that `.hito` files stay comparable to the same project's `.rvt` while HITO keeps full history (ADR 0024, spike #156).

### What the check does
1. Imports each corpus project's IFC export into a new `.hito` file.
2. Measures the state's size, the time to open, and the time to undo.
3. Simulates a standard year of realistic edits, using the workload from the #156 prototype (PR #170).
4. Measures the whole file again, plus the history's share of it and the open time.
5. Compares every number with its budget and reports pass or fail, with the numbers.

### Budgets
In `benchmarks/budgets.toml`, so changing a budget means a reviewed PR. The values are set from the first measurements on real projects:
- the HITO state is at most N× the size of the same project's `.rvt`
- a year of history is at most N% of the state
- opening a 100k-element model takes at most N s
- undoing the largest action takes at most N ms

### Corpus
- In this repo under Git LFS, as compressed IFC exports (`.ifc.zst`) plus a metadata file per project. The metadata records the `.rvt` size, the Revit version and where the model came from. The `.rvt` files themselves aren't committed: only their size is needed.
- The founding user's student projects (#152) are committed with her explicit OK, and only if nothing in them belongs to her university.
- Public samples go in only with a clear license. The Revit sample used in #156 has none, so it stays out.
- CI caches LFS objects, keyed by the corpus's hashes, so the weekly run stays within the LFS bandwidth quota.

### Acceptance criteria
- [ ] `hito-benchmarks` runs the check on a corpus folder and writes the results as JSON
- [ ] **Quick check:** a required CI check on every PR that touches the core or storage, using a few small models
- [ ] **Full check:** a scheduled weekly workflow, plus a `workflow_dispatch` button, over the whole corpus. A broken budget opens an issue.
- [ ] The results are charted over time (`github-action-benchmark` on GitHub Pages), and a PR comment flags a regression of more than 10%
- [ ] CONTRIBUTING gets a "Definition of Done" section listing the budgets
- [ ] M1's milestone description lists "the full check passes on the founding user's projects" as an exit criterion

Depends on #47 (save and open) and on the founding user's projects (#152).
