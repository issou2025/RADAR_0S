## SEC-1 — HIGH — Default LAN A2A posture enables peer-to-peer RCE

**CVSS-style:** AV:A/AC:L/PR:N → High. Three default behaviors chain into "any LAN peer can drive the full agent":

1. **Forced `0.0.0.0` bind** — `internal/config/config.go:1571-1572` overrides `A2A.Host` to `"0.0.0.0"` when the configured host is *empty or loopback*. A user who explicitly sets `127.0.0.1` is silently re-widened to all interfaces (documented as needed for mDNS/LAN Chat in `ggcode.example.yaml`).
2. **Public default credential** — `DefaultA2AAPIKey = "ggcode-lan-a2a-v1"` (`internal/config/config.go:535`) is a source-published constant. `LanChatConfig.EffectiveAPIKey()` falls back to it (also `config.go:530/675`), and it doubles as the lanchat `communityKey` (`internal/lanchat/handlers.go:40`, accepted by `AuthMiddleware` when no key is configured, and by the UDP transport at `udp_transport.go:201-202`). Anyone who has read this repository knows the key.
3. **Legacy unauthenticated arm + unrestricted tools** — `internal/a2a/server.go` `authenticateRequest` retains the #125/G3 "same-machine open arm": when nothing is configured and `requireAuth` defaults false, requests pass. `internal/a2a/handler.go` `SkillFullTask` sets `AllowedTools: nil` (entire registry, incl. `run_command`) and reaches full agent execution via `RunStream`. The `WorkspaceGate` (#5597 same-workspace roster) does not stop a peer already in the roster.

**Impact:** a LAN peer sending the public key (or nothing, via the open arm) can execute arbitrary commands through the agent on the victim host.
**Remediation:** (a) bind loopback by default and require explicit opt-in for `0.0.0.0`; (b) generate a per-install random API key on first run instead of a public constant (keep the community key only as an explicitly-chosen "open community" mode with a loud warning); (c) default `requireAuth: true`; (d) give `SkillFullTask` a tool allowlist.
**Verification:** on a default config, `nmap -p <a2a-port>` from another LAN host + a single JSON-RPC `SkillFullTask` request with `X-API-Key: ggcode-lan-a2a-v1` currently succeeds; it must 401 post-fix.

## SEC-2 — MEDIUM — `GGCODE_INSECURE` global TLS kill-switch breadth

`internal/util/transport.go` `WrapTransport` sets `InsecureSkipVerify = true` for `1/true/yes` and is consumed broadly (providers, `internal/a2a/client.go`, `internal/mcp/transport.go`, IM adapters, `internal/tunnel/share_protocol.go`, `internal/relaycatalog/client.go`). Mitigations are real: it's opt-in, documented (`docs/guide/environment-variables.md`), `a2a/client.go:64` deliberately forces `InsecureSkipVerify = false` as an exception, and `internal/agent/insecure_pattern_check.go` flags the pattern in generated code. Recommend: namespace-scoped opt-in (per-provider) instead of one global bit, and a startup banner when active.

## SEC-3 — MEDIUM — No security/SCA scanning in CI

All 11 workflows in `.github/workflows/` were checked: none run `govulncheck`, `gosec`, CodeQL, or dependency review. Lockfiles are in good shape (`go.sum`, `web/pnpm-lock.yaml`, `desktop/.../frontend/package-lock.json`; npm release wrapper verifies SHA-256 via `checksums.txt` — `npm/lib/install.js:323-400`; desktop build scripts pin `npx --yes hyperframes@0.7.84`). ## SEC-4 — LOW — `sessionidxd` unix socket: umask-dependent mode, no auth

`internal/sessionidx/transport_unix.go` creates `~/.ggcode/idxd.sock` via plain `net.Listen` (mode `0777 & ~umask`, typically `0755`, no `Chmod`); the daemon (`internal/sessionidxd/daemon.go:117-120`) serves `/search` and `/status` with no auth — session metadata readable by any local user unless the config dir is already `0700`. Recommend explicit `Chmod(sock, 0600)` + peer-credential check (`SO_PEERCRED`/umask-independent).

## SEC-5 — LOW — Secrets at rest are plaintext (correctly permissioned)

`keys.env` (all provider API keys) is plaintext `0600` inside a `0700` dir (`internal/config/secure_write.go`, `api_keys.go:581-585` — verified by helpers `ensureSecureConfigDir`/`writeSecureConfigFile`); node Ed25519 keys `0600` (`internal/lanchat/nodekey.go`). Keys are exported into process env (`os.Setenv`, `config_keys.go`/`api_keys.go` — visible in `ps -eE` on Linux). One inconsistency: `api_keys.go:327` creates `ConfigDir()` with `0755` for the warning-state file. No hardcoded secrets found anywhere (only `xoxb-xxx` placeholders); `mobile/flutter/.env.example` is an empty template. Consider OS keychain integration as a follow-up; not blocking.

## SEC-6 — INFO — Verified-strong areas (no action)

- **WebUI:** `127.0.0.1:0` bind (`cmd/ggcode/root.go:1586`, `daemon.go:1406`), 32-byte `crypto/rand` token (weak SHA-256 fallback on rand failure), `requireAuth` on all `/api/*` with constant-time SHA-256 compare, `http.MaxBytesHandler` 1 MiB. Minor: `/api/chat/ws` accepts `?token=` in the query string (leaks into logs/proxies — prefer `Sec-WebSocket-Protocol` or header auth).
- **web_fetch SSRF:** private-CIDR/host blocklist (incl. `169.254.0.0/16`, `::ffff:127.0.0.0/104`, `metadata.google.internal`), DNS re-resolution pinning (`resolvePublicDialAddress`; `rejectIfHostResolvesPrivate` under proxy), redirect guard; `AllowPrivate` defaults false with no non-test setter.
- **Path policy:** `internal/permission/sandbox.go` `PathSandbox` is fail-closed (getwd/resolution failure → deny), symlink-resolving, prefix-checked; `allowed_dirs` defaults `["."]`.
- **Dangerous-command guards:** `internal/permission/dangerous.go` deny-lists `python3 -c`/`node -e` embedding OS/subprocess/socket calls (CVE-2026-2256 class); bypass-mode exfil/sensitive-redirect gates in `config_policy.go` (#573-C).
- **Injection:** no unsanitized injection found beyond by-design user-configured shell execution (statusline script, `run_command` with shell resolution in `internal/util/shell.go`); the dummy IM adapter (loopback-only) has a valid random shutdown token, though its optional `port_file` is written `0644` with the token inside (default off — tighten if ever documented).
