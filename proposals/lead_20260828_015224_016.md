## What needs to come across

`client/` on CIRISAgent, commits `103d7bca5..a38e224b8`. 13 files, +465/-27.

### 1. The log buffer dropped entries under concurrency — `commonMain` — **P1 for you specifically**

`DebugLogBuffer.add` was `_entries.value = _entries.value + entry`: a read-modify-write on a shared `StateFlow`, plus a non-atomic `idCounter++`.

This is the buffer the bundles render. On desktop the node's stdout reader logs from `Dispatchers.IO` while view models log from their own scopes — so it loses entries and repeats ids under exactly the concurrency a failing startup produces, which is the only time anyone downloads a bundle. **The feature silently omits the errors it exists to capture,** and the bundle still arrives looking complete.

Now compare-and-set throughout, with the id derived *inside* the `update` block — a counter beside a lambda that re-runs on a lost race would burn ids and hand out duplicates.

Covered by `DebugLogBufferConcurrencyTest`. Worth carrying the test: I verified it by reverting to the pre-fix implementation and confirming both concurrency tests fail, then pass on restore. A concurrency test nobody has watched fail is not evidence of anything.

### 2. The bundle had no credential redaction — `commonMain` — **P1**

The bundle exists to be *sent* to us — pasted into an issue, mailed to support — and nothing scrubbed it.

Nothing logs a credential today; I checked rather than assumed. But the gap between "nothing logs a secret" and "a secret cannot escape" is one future `platformLog("token=$t")` written by someone debugging at 2am, and review would not flag that line, because on its own it is harmless. It only becomes a leak when the buffer is handed to a stranger.

Redaction is applied at `render()` — the single choke point all three screens pass through — so environment rows, the caller's `extra` map and the log buffer are covered by construction rather than by three callers remembering.

The patterns match credential *shapes* (JWT, bearer/`service:` header, assignment to a secret-ish name), never entropy. A redactor that eats ordinary log text destroys the artifact's whole purpose, so that direction is tested as hard as the leak direction: `token exchange failed: HTTP 401` must survive verbatim, and `token: expired` is excluded as a state rather than redacted to nothing.

### 3. Android export left empty files in Downloads — `androidMain` — P2

On Q+ the Downloads row is inserted before `openOutputStream`. If the write fails — full disk, revoked provider — the function returns failure and leaves an empty row behind. **An empty debug bundle is worse than none: someone sends it believing they sent their logs.** Now `IS_PENDING` until the bytes land, and the row is deleted if they don't.

### 4. The bundle registered its content height, not its viewport — `commonMain` — P2

`.testable()` sat *after* `.verticalScroll()`, and `onGloballyPositioned` reports the node's size at its own point in the modifier chain — so it measured the scrollable content. A full bundle registered as **17952px tall**. `/tree` advertised an element taller than any screen, and automation aiming at its centre targets roughly y=10000, on every platform.

Invisible in the code; obvious the moment you read `/tree` during a QA run. Verified on a real build: 17952 → 220.

### 5–7. Desktop-side, listed for completeness

- **Reset Device wiped local state while driving a remote node.** `CIRIS_API_URL` is a supported way to point the client at a node on another host; `PythonRuntime` honours it and never starts a local backend. `wipeLocalData()` never consulted it — so Reset reported success having reset nothing the user was using, while deleting the database, identity and keys of whatever local node shared the disk. This is the **fourth** misresolution in that function and the first above the filesystem layer: the previous three picked the wrong directory, this one picked the wrong machine. Gated on loopback, matched as an address rather than a prefix (`127.0.0.1.evil.com` is an ordinary hostname).
- **Desktop reported the wrong version.** `getAppVersion()` prefers the JAR manifest; the Compose uber-jar writes only `Main-Class`, so `DESKTOP_VERSION_FALLBACK` is the *only* value desktop ever reports. Its name is why it drifted to 2.3.2 while builds shipped 2.9.x — a diagnostics bundle from a 2.9.40 build named 2.3.2 as its version. If you keep a hand-maintained constant here, put a check on it.
- **Tests for the wipe** (`LocalDataWipeTest`). It had four wrong answers and no tests. Every one was a claim about what *survives*, so the tests assert survival against a populated tree — a thesis file, a `src/`, a `.git` — rather than checking the intended targets are gone.

## One thing worth stealing regardless

CIRISAgent's CI ran **zero** Kotlin tests. 390 already existed in `commonTest` and had never once executed in the pipeline; Sonar does not scan Kotlin either. Every Kotlin defect had to be caught by a human reading a diff — which is exactly how the log-buffer race reached review.

Wiring `:shared:desktopTest` into CI took four lines. If your pipeline has the same gap, it is the cheapest quality win available: it does not need anyone to write a test first, because the tests are already there.
