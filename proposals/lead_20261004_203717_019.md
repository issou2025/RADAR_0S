# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**preclose A/B: the workflow arm — a saved preclose-panel workflow that replaces the hand-spawned refuters on its issues**

*Project description:*
## Problem

Today Lane 1 runs the preclose panel by hand (`skills/preclose-check/SKILL.md` steps 3–4):
- It spawns one `preclose-inspection` agent per lens.
- It filters their findings by judgment.
- It writes the findings JSON by hand.

The operator wants an A/B pilot of a Workflow-orchestrated alternative that **replaces** that hand-run panel on the issues assigned to it, never running alongside it. This issue is the workflow arm. The experiment's cost telemetry is harmonic-forge#889 and its arm assignment is harmonic-forge#890, which blocks this one.

## Design

1. **A saved workflow, `workflows/preclose-panel.js`** (new platform directory), invoked as `Workflow({name: "preclose-panel", args})`, with `args` as printed by `preclose_check.py --plan` on the workflow arm: `repo`, `issue`, `base`, `head`, `lenses`.
   - **Find:** one agent per lens with `agentType: "preclose-inspection"`, given only the issue's acceptance criteria (it fetches the body itself), the diff range and the repo, exactly what the manual arm gives. Schema-forced output: a list of `{anchor, scenario, mechanism}`.
   - **Filter (plain code, no agent):** a finding without an anchor matching `\S+:\d+(-\d+)?` or without a scenario is dismissed as "no file:line-anchored failure scenario", the same rule `preclose_check.py` applies. Duplicates are merged on normalized anchor plus normalized mechanism, keeping a count of how many refuters raised each.
   - **Verify:** for each remaining finding, one `preclose-inspection` agent prompted to **refute** it against the code, defaulting to refuted when it cannot confirm. A refuted finding is dismissed with the verifier's reason.
   - **Return:** the findings list in exactly the `--gate`/`--complete` format (survivors, plus dismissed entries carrying a `"dismissed": "<reason>"` field), and the number of agents run.
2. **Distribution (R-0353).** `sync_rules.py` links `workflows/*.js` into each project's `.claude/workflows/`, exactly as it links `agents/` into `.claude/agents/` (auto-discovered, gitignored in the consumer).
3. **Skill branch.** `skills/preclose-check/SKILL.md` steps 3–4 branch on the arm the plan printed:
   - `manual`: unchanged.
   - `workflow`: call the Workflow tool exactly as printed, write its returned list to the findings file, and spawn no refuters by hand. Steps 5–7 (gate, complete, post) are unchanged for both arms.

   The skill states how to obtain `--panel-tokens` and `--panel-ms` for each arm.
4. **No duplication.** On the workflow arm no hand-spawned refuter runs; on the manual arm the workflow never runs. A Lane 1 runtime without the Workflow tool (a Codex Lane 1) takes harmonic-forge#890's recorded override back to `manual`.

## Tooling Exception

Scoped as tooling under ADR-002 / R-0226:
1. The work product is repo-local automation (`workflows/preclose-panel.js`, `sync_rules.py`, `skills/preclose-check/SKILL.md`). Nothing in it is imported by, served by or deployed with application code.
2. Blast radius is the dev machine and repo working state. Its agents are the existing read-only `preclose-inspection` subagents, whose hooks deny GitHub writes.
3. Labelled `infrastructure` + `tooling` + `tooling-exception`, and scoped as tooling work by the operator's instruction of 2026-10-04 ("pilot it on the preclose panel — create an alternate version for a/b testing that uses it and doesn't duplicate with manual refuters").

Split by mechanism under R-0370 from a combined 8-point pilot. **Blocked by harmonic-forge#890** (and through it harmonic-forge#889), whose `--arm`, `panel_arm` and `--panel-tokens`/`--panel-ms` interface this issue consumes. Lane 1 implements.

## Test cases

1. `Workflow({name: "preclose-panel", args})` run against a fixture diff with a planted defect must return a list `preclose_check.py --gate --findings` accepts, with the planted defect among the survivors.
2. A finding with no `file:line` anchor must come back dismissed with the reason "no file:line-anchored failure scenario", and must never reach the Verify stage.
3. Two refuters raising the same anchor and mechanism must produce one finding, not two.
4. A `preclose-inspection` agent run by the workflow that attempts `gh issue comment` must be denied by `deny_advisory_subagent_gh_writes.py`, exactly as it is when spawned by hand.
5. After `python3 sync_rules.py --pull` in a consuming repo, `.claude/workflows/preclose-panel.js` must be a symlink to the platform file, and the consumer's git status must stay clean.
