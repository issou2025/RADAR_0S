# Brand style in the app: Archivo, brand theme and a UI-safety net — implementation plan

**Status:** Approved concept → phased implementation plan

The store creative (#77, `docs/marketing/brand.md`) promises white paper, black ink, Archivo 900 headlines, one teal key phrase, orange for changed values, square corners and black rules. The app is still stock Material 3: `lib/theme.dart` sets only `ColorScheme.fromSeed(blueGrey.shade700)`, a bold `headlineLarge`/`titleLarge` and the sheet drag handle. This issue brings the brand into the app and builds an automated safety net so a user-content-driven UI can be restyled without shipping layout errors.

Concept and options (A–K, grounding, Mermaid diagrams): [brainstorm comment](https://github.com/jonaskeller14/bike_setup_tracker/issues/83#issuecomment-6312643534).

**Branching.** Phases 1–4 change no visuals and land on `dev` first, so the sweeps and the guard test protect every other change while the restyle is in progress. Phases 5–17 live on a long-lived branch `brand-theme` (created from `dev` after Phase 4, `dev` merged into it regularly) and merge into `dev` together once the look is signed off.

| D. Accent words | **D1**: `AccentText` with `*phrase*` markup, hero surfaces only, at most one per screen | Opt-in per string; markup can move into ARB strings with #18 |
| E. Colors | **E1**: keep `ColorScheme.fromSeed`, override surface/outline/on-roles with `copyWith` | Every role stays defined; primary stays `#106681`, so `DialColors.blue` and brand teal stay equal |

Teal vs. ink | **F1** as starting point, **tested against F2** (teal stays the primary control color) side by side in the theme lab (Phase 9). **Links, text buttons, selection and focus stay teal in both**; only `FilledButton` and the FAB differ | Teal on tappable text reads as "tappable". The open risk: D1's non-tappable teal words must not look like links (no underline, hero text only) |
| G. Shape | **G1**: square, 1 px outline, flat, selected = 2 px border; system-shaped controls (`Switch`, `Slider`, `Radio`) keep their shape. **Radius is one token**, decided on lab renders (0 vs. 2 vs. 4 px; default 0) | Maintainer has no preference yet and wants to look first |
| H. Spacing | **H1**: component themes set the baseline + shared spacing constants; per-widget paddings untouched | Large reach without widget edits; tile-family cleanup (#68) stays out of scope |
| I. Leftovers | **I1**: theme first, then a ratcheting guard test and an audit by feature area | Visible progress early; new hardcoded styles cannot sneak in while the branch lives |
| J. Verification | **J1 + J2**: stress-fixture sweep with the real Archivo (components + all pages) that writes a **reviewable summary report**, plus a debug "theme lab" with an Alchemist golden. J4 (debug overflow reporter) and the device pass (J3) before release | A summary replaces opening every page by hand |
| K. Text scale | **K3**: body content unclamped, only inherently dense widgets clamped | Accessibility where it matters, protection where the grid can't wrap |
| Store screenshots | Re-shot at release time, after this lands. Not part of this issue | Maintainer decision |
| Body weight | Default **500**; the lab renders 400/500/600 and the maintainer picks (Phase 9) | Brand says 600 for marketing; dense lists may want lighter |
| Uppercase | Only fixed UI labels via `BrandLabel`, never user content | `ß`→`SS`, wider text, wrong for names |

| Width variant | Narrower Archivo for dense cells **deferred**; revisit only if the sweep shows dense cells can't be fixed otherwise | Avoids a second font family |
| CI budget | Sweeps run in `flutter test` if they add < ~3 min; otherwise tag `overflow` and add a separate CI step (like `golden`) | Decided with the measurement in Phase 2 |
| File structure | `lib/theme.dart` stays (existing extensions untouched) and wires new files under `lib/theme/` | Smallest diff, imports unchanged |
| Summary report | Markdown table in `build/ui_safety/summary.md` + CI artifact; optional local-only contact sheet of page renders (`--dart-define=UI_SAFETY_SHOTS=true`), not goldens | Skim instead of clicking through 45 pages |
| Strava review | No dependency; merge timing decided at release | Maintainer decision |

## Feature flag

None. This is a global look, not a gated feature. Two debug-only pieces exist: the **Theme lab** page is shown in the settings hub only when `appSettings.developerMode` is true (`kDebugMode && _developerMode`), and the **overflow reporter** (Phase 16) is wrapped in `kDebugMode`. Neither ships in release builds.

CI note: `.github/workflows/flutter_test.yml` runs on pushes to `main`/`dev` and PRs to `main` only. For the life of `brand-theme`, add the branch to `push.branches` (removed again in Phase 17) or run targeted tests locally.
