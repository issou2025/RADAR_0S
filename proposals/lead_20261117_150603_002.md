# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Epic: Performance — feel light on an ordinary laptop**

*Project description:*
Make the viewer feel light on any ordinary computer: orbit stays smooth, clicks land instantly and models appear fast, however big the model is. The yardstick is Dalux — it runs well on an office laptop, and so should this.

**Target hardware:** an ordinary office laptop with integrated graphics. Desktop browsers only; phones are out of scope here (see #59).

## Goals

Starting numbers, to be calibrated against the first measured baseline (#72). A change that claims to help performance is measured before and after against this table.

| Area | Goal |
|---|---|
| Orbit, small model (~17k parts, *Snowdon Towers*) | 60 fps |
| Orbit, heavy model (100k+ parts) | at least 30 fps |
| Draw calls per frame | under 500, whatever the model size |
| Click or hover pick | under 10 ms |
| First geometry on screen | under 2 s |
| *Snowdon Towers* fully loaded | under 5 s cold, under 1 s from cache |
| Bulk property read | at least 5,000 elements/s (today 100–200) |
| Colour 20k elements by a parameter | under 2 s |

**Benchmark models:** *Snowdon Towers Sample Structural* (small, public) and a private 340 MB Revit-exported IFC2X3 model as the heavy case. The heavy model is not in the repo and must not be committed.

## What the code does today

From reading the code, not from profiling — each of these is a hypothesis until #72 measures it.

- Every geometry piece is its own mesh, its own geometry and its own draw call, even when thousands of parts share one shape.
- Every mesh recomputes its transform every frame although none of them move.
- Every material is double-sided, so back faces are never skipped.
- The pixel ratio is uncapped with antialiasing on, so a high-DPI screen shades up to four times the pixels.
- Picking walks the whole scene and tests every mesh, on click, at orbit start, on zoom and on every pointer move in the measurement tool.
- Already good: the scene renders only when something changes, materials are shared by colour, and there are no shadows.

## How this meets Data Insight (#65)

Batching (#73) changes how an element maps to something drawable. Colouring (#68), filtering (#70) and hover (#77) all sit on that mapping, so batching should land before them or they get reworked.
