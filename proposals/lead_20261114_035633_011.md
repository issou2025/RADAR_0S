## 7. Trend Signals

The following signals are extracted from community feedback, bug reports, and RFC activity across all five projects. They represent **emerging requirements that AI agent developers should track**:

### 🔴 High-Priority Trends (Already Causing Production Pain)

1. **Credential isolation from model context** — Every project independently discovered that credentials can leak through tool outputs, logs, and persistence layers into the model's context window. The industry is converging on write-only credential stores, scoped references, and egress proxies as the mitigation stack. **Developers building agent frameworks should treat credential containment as a first-class architectural requirement, not an afterthought.**

2. **Scheduled task concurrency safety under SQLite load** — Multiple projects use SQLite for job persistence and are hitting concurrency limits at scale. This is a systemic choice that the ecosystem may need to revisit or engineer around with better busy_timeout tuning, WAL mode optimization, or eventual migration to more concurrent stores.

3. **Windows enterprise reliability** — Both OpenClaw (P0) and QwenPaw have significant Windows-specific bugs affecting managed-service deployments. As agents move from developer laptops to enterprise workstations, Windows parity must become a first-class CI target, not a best-effort afterthought.

### 🟠 Medium-Term Trends (RFCs/Open PRs Indicate Near-Term Adoption)

4. **Plugin-facing extensibility** — QwenPaw's theme extension point (#8071, 13 comments) and plugin CLI support (#8554) indicate that the ecosystem is moving from "plugins as integrations" to "plugins as first-class citizens" with programmatic hooks into theming, lifecycle management, and command registration. OpenClaw already has a mature hosted plugin catalog; others are catching up.

5. **Per-job quality/cost overrides for automation** — Scheduled tasks that default to full-reasoning models impose unnecessary cost and latency. Projects are converging on per-job `thinking_level`, model, and provider overrides, suggesting a standardization of the "automation profile" concept.

6. **Real-time voice integration architecture** — Hermes Agent's RealtimeVoiceProvider RFC (#77111) with 4 competing PRs indicates that voice-first agent interaction is a live development area. A unified ABC would benefit the broader ecosystem and prevent provider-specific lock-in.

7. **Multi-channel session parity** — OpenClaw, QwenPaw, and ZeroClaw all struggle with how sessions map to channels (per-conversation binding vs. per-user binding vs. per-channel binding). This is an unsolved UX and architectural problem that affects notification routing, message threading, and conversation continuity.

### 🟢 Forward-Looking Signals (Early Indicators)

8. **CJK/language-specific optimizations** — QwenPaw's CJK Markdown fix and OpenClaw's CJK bigram tokenizer request suggest that non-English speaker experience is becoming a competitive differentiator, not a nice-to-have.

9. **Supply chain security for plugins** — Hermes Agent's release-age gating for standalone npm packages and OpenClaw's hosted plugin catalog security concerns indicate that plugin distribution is entering a phase where signing, audit trails, and dependency pinning become necessary.

10. **WASM-based plugin sandboxing** — ZeroClaw's WASM plugin architecture with host-mediated dispatch and WASM plugin wake ADR exceptions suggests a longer-term architectural evolution toward memory-safe plugin isolation. If proven stable, this model may influence other projects.
