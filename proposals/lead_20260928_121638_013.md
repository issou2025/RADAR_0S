## 2. Summary

We need `otel_zone` to become a Flutter plugin (Android + iOS; web no-op) exposing `pending()`/`acknowledge()`, and `start()` to drain it into FATAL LogRecords, because a pure-Dart package cannot see native crashes.

Expected result:

> `start()` drains native reports, redacts them, writes them to the spool, then acknowledges them, all behind the "never throws" rule.

---

## 3. Intent

The real intention of this ticket is:

> Create the one Dart↔native contract that the platform tickets implement, and the Dart-side mapping to OTel records.

## 6. Expected Behavior

* `flutter.plugin.platforms` declares android (Kotlin) and ios (Swift, CocoaPods + SwiftPM).
* `pigeons/native_crash.dart` generates the API.
* `start()` → drain → redact → spool → acknowledge; summary line reports the count.

Important technical notes and known constraints:

* `NativeCrashReport { id, kind (jvm|native|anr|nsexception|signal|hang), timestamp, type, message, stacktrace, threads?, sessionId?, attributes }`.
* Map to severity FATAL (21), `event.name` = `device.crash` / `device.anr`, `exception.*` attributes.
* Emit through the spool path directly, not via Talker, so a crash report does not become a breadcrumb.
