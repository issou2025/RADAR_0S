## Problem

`NwcIO.Scene` converts one model file into a scene with one model ([scene.md#L31](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/scene.md#L31)). Five kinds of input or content are not converted yet; four are in the [Limits](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/scene.md#L82-L83). Each has its own cause, some in the engine and some in the adapter, so they are listed separately to be split later.

1. `.nwd` partition trees. The hierarchy parser throws `NotSupportedException` at the first class-32 node ([HierarchyParser.cs#L266](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Internal/Parsing/HierarchyParser.cs#L266)); the class-32 trailer is not decoded ([format-notes.md#L62](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/format-notes.md#L62)). The adapter rethrows it ([NwcSceneReader.cs#L39-L47](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L39-L47)). The workaround the engine message names, `BuildSceneTree = false`, does not help here: `Read(NwcDocument, ...)` rejects a document without a tree ([NwcSceneReader.cs#L75-L78](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L75-L78)). Needs engine work.

2. Linked Revit models. The parser throws when one element index sits on nodes under different parents ([HierarchyParser.cs#L152-L173](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Internal/Parsing/HierarchyParser.cs#L152-L173)). Needs engine work (keep each placement in the tree) and adapter work: the same `SourceId` twice in one model is a `duplicate-source-id` warning in IOScene ([SceneDocument.Validate.cs#L96-L97](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneDocument.Validate.cs#L96-L97)), so a link likely needs its own `SceneModel`.

3. Saved viewpoints. The adapter writes none and reports `viewpoints-skipped`, giving the missing viewpoint id as the reason ([NwcSceneReader.cs#L254-L258](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L254-L258)). `SceneViewpoint.Id` may be null ([SceneViewpoint.cs#L54-L55](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneViewpoint.cs#L54-L55)), so the id does not block it. The engine input does:
   - Only some real saved-view streams are recognised ([public-api.md#L27](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/public-api.md#L27)). The stream classifier looks for a tag-517 record starting in the first 512 bytes only, and both it and the parser accept a record only when the int after the tag is 1 ([StreamClassifier.cs#L155-L160](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Internal/Parsing/StreamClassifier.cs#L155-L160), [ViewpointParser.cs#L56](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Internal/Parsing/ViewpointParser.cs#L56)). The format notes record that int as the projection, 1 for orthographic and 0 for perspective ([format-notes.md#L276](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/format-notes.md#L276)), so perspective records do not match.
   - Every camera read gets `FieldOfView = 60` and `Projection = Perspective` ([ViewpointParser.cs#L84-L93](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Internal/Parsing/ViewpointParser.cs#L84-L93)), although the same format note locates the stored field of view, or the view height for an orthographic view.

   Needs engine work, then adapter work: map `NwcSavedViewpoint` to `SceneViewpoint` in metres with the field of view in radians, an orthographic view's height converted by the rule `SceneCamera` gives ([SceneViewpoint.cs#L30-L34](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneViewpoint.cs#L30-L34)).

4. Level elevations. A `SceneLevel` gets only id, model and name ([NwcSceneReader.cs#L175](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L175)), and a test pins `Elevation` to null ([NwcSceneReaderTests.cs#L101-L102](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/tests/NwcIO.Scene.Tests/NwcSceneReaderTests.cs#L101-L102)). `NwcNode` has no elevation ([NwcNode.cs#L7-L62](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Model/NwcNode.cs#L7-L62)); the level data the adapter sees is the `OST_Levels` parameter tab it already reads for level ids ([NwcSceneReader.cs#L296-L326](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L296-L326)), which the synthetic fixture gives an `Elevation` length property ([RevitSample.cs#L17-L19](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/tests/NwcIO.Scene.Tests/Fixtures/RevitSample.cs#L17-L19)). Needs adapter work, after checking on real files that the tab holds the elevation and which origin it is measured from: `SceneLevel.Elevation` is in scene coordinates ([SceneLevel.cs#L17-L18](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneLevel.cs#L17-L18)).

5. One model per scene, no `.nwf` input. The scene has one model with id 1 ([NwcSceneReader.cs#L19](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L19), [#L87-L99](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L87-L99)), and the only entry points take a path or an `NwcDocument` ([#L30](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L30), [#L66](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO.Scene/NwcSceneReader.cs#L66)). `NwcAssembly` already loads a folder or an `.nwf` into a list of documents ([NwcAssembly.cs#L17](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Model/NwcAssembly.cs#L17), [#L161](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Model/NwcAssembly.cs#L161), [#L192](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Model/NwcAssembly.cs#L192)), but nothing converts it. Three things need deciding:
   - Element ids are scene-wide in IOScene ([SceneDocument.Validate.cs#L69](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneDocument.Validate.cs#L69)), so the per-document preorder ids ([scene.md#L37](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/scene.md#L37)) need an offset per model.
   - Each model needs its own key ([SceneDocument.Validate.cs#L67-L68](https://github.com/IOExtend/IOScene/blob/85257c95cf8fbaa84d31918c8c7a82b24e2d8950/src/IOScene/SceneDocument.Validate.cs#L67-L68)), but a document has no file name ([scene.md#L27](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/docs/scene.md#L27)) and `NwcAssembly` keeps only the documents.
   - `OpenNwf` puts the `.nwf` document itself first in that list ([NwcAssembly.cs#L202](https://github.com/IOExtend/NwcIO/blob/c0ca6e16a00b7e6ee587043c1db97c04551b2ea0/src/NwcIO/Model/NwcAssembly.cs#L202)).

   Needs adapter work, plus either engine work to keep each document's file name on the assembly or keys passed by the caller.

## Proposal

Split into one issue per item:

- Engine: decode class-32 partition nodes (1); keep linked placements in the tree instead of throwing (2); recognise real saved-view records and read their projection and field of view (3); if chosen, keep each model's file name on `NwcAssembly` (5).
- Adapter: `NwcSceneReader.Read(NwcAssembly, NwcSceneOptions)` with one `SceneModel` per model file (5), reused for links (2); write viewpoints (3); write level elevations (4).

Each step removes its part of the Limits in `docs/scene.md`.

## Done when

- `NwcSceneReader.Read` converts a `.nwd` with partition nodes and a model with a linked Revit model, checked on synthetic files.
- A file with saved views gives `SceneViewpoint`s with the stored projection and field of view, and `viewpoints-skipped` reports only views that could not be read.
- Revit levels carry `Elevation` in metres when the file holds it, and the test that pins it to null checks the fixture's value instead.
- A folder or `.nwf` assembly converts into one scene with one model per model file, each with its own key, and `SceneDocument.Validate()` reports no errors.
- The Limits in `docs/scene.md` list only what is left.
