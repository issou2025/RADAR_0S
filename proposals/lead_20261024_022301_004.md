# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Domain gap: schedules — read definitions and cell data, create and edit schedules, place on sheets, export**

*Project description:*
## Goal

Schedules are where EN/EL deliverables end up (device lists, cable lists, panel schedules), and today the connector can only list their names and field names (`ListSchedulesTool`, `ExportScheduleListToExcelTool`). Add the tools to read a schedule's definition and its actual rows, to create and edit schedules from a specification, to put them on sheets, and to export them.

| Tool | Permission | Purpose |
|---|---|---|
| `revit_get_schedule` | ReadOnly | Full definition (fields with parameter ids and formatting, filters, sorting/grouping, itemize, template) and, on request, the table rows as the user sees them, paged |
| `revit_list_schedulable_fields` | ReadOnly | What `GetSchedulableFields()` offers for a category: parameter name, id, field type (instance/type/count/formula…) |
| `revit_preview_create_schedule` / `revit_create_schedule` | ReadOnly / RequiresApproval | Create a schedule from a spec: category, fields in order, filters, sorting, grouping, totals, itemize, template |
| `revit_preview_edit_schedule` / `revit_edit_schedule` | ReadOnly / RequiresApproval | Add, remove, reorder, rename, hide, format fields; replace filters and sorting on an existing schedule |
| `revit_place_schedule_on_sheet` | RequiresApproval | `ScheduleSheetInstance.Create` at a point or next to an existing viewport |
| `revit_export_schedule` | RequiresApproval (writes files) | Revit's own CSV/TXT export (`ViewSchedule.Export`) or an Excel workbook built from the table data |

## Why

The current agent workflow for "make a socket list for level 2" is impossible: it can collect data with `revit_find_elements_by_parameter` and write Excel, but a Revit schedule that updates with the model and sits on a sheet is what the deliverable actually is. `Viewport.Create` (used by `PlaceViewsOnSheetsTool`) does not accept schedules, so even an existing schedule cannot be placed today.

## Design

### Reading

`revit_get_schedule`: `schedule` (id or name via `ViewManagerToolSupport.ResolveViews`-style matching), `include` = `definition` (default) | `rows` | `all`, `page`, `pageSize` (max 500 rows), `document`. Definition from `ScheduleDefinition`: `CategoryId` → name, `IsItemized`, `ShowGrandTotal`, `GetFieldCount`/`GetField(i)` → `{index, name (GetName), columnHeading, parameterId, fieldType (ScheduleFieldType), isHidden, isCalculated, hasTotals, formula? , unit/format summary (GetFormatOptions when not default)}`, `GetFilterCount`/`GetFilter` → `{fieldIndex, filterType, value}` (value read by type: `IsStringValue`, `IsDoubleValue`, `IsIntegerValue`, `IsElementIdValue`), `GetSortGroupFieldCount`/`GetSortGroupField` → `{fieldIndex, sortOrder, showHeader, showFooter, showBlankLine}`. Rows from `schedule.GetTableData().GetSectionData(SectionType.Body)`: `NumberOfRows`/`NumberOfColumns`, `schedule.GetCellText(SectionType.Body, r, c)`; header row from `SectionType.Header`. Element ids per row are not exposed by the API when the schedule is not itemized; when it is, resolve them with `FilteredElementCollector(doc, schedule.Id)` in table order is **not** guaranteed, so return `elementIds` only when `IsItemized` and the collector count equals the row count, else omit and say why. Cap rows by `QueryLimits.MaxPageSize`.

`revit_list_schedulable_fields`: category name (`CategoryResolver`) → a temporary schedule is **not** created; instead use an existing schedule of that category when one exists, else create one inside a `Transaction` that is rolled back after reading `GetSchedulableFields()` (the same rolled-back-group pattern `ExportViewImageTool` uses). Output `{name, parameterId, fieldType, isShared? (parameter is shared), dataType}`.

### Create

Spec (`revit_create_schedule` arguments): `name` (unique via `ViewManagerToolSupport.ResolveUniqueName`), `category` (or `multiCategory=true`, or `keySchedule` with `keyName` → `ViewSchedule.CreateKeySchedule`), `fields[]` of `{parameter (name) | count | formula {name, expression} | percentage, heading?, width?, hidden?, totals?, format? {units, accuracy, suppressTrailingZeros}}`, `filters[]` of `{field, type (equals|notEquals|contains|beginsWith|greaterThan|…, mapped to ScheduleFilterType), value}`, `sort[]` of `{field, descending?, header?, footer?, blankLine?}`, `itemize` (default true), `grandTotal` (`none|title|count|totals|titleCountTotals`), `template` (view template name, optional), `phase?`, `document`.

Implementation (`SchedulePlanner` is pure: it validates the spec against the field catalogue passed in as DTOs and emits an ordered action list; the tool executes it): `ViewSchedule.CreateSchedule(doc, categoryId)` (or `ElementId.InvalidElementId` for multi-category), `view.Name`, for each field `definition.AddField(schedulableField)` matched by `GetName()` (case-insensitive, then `ParameterMatcher.Normalize`), `ScheduleField.ColumnHeading`, `GridColumnWidth` (mm → ft), `IsHidden`, `HasTotals`, `SetFormatOptions`; `definition.InsertFilter(new ScheduleFilter(fieldId, type, value), i)`; `AddSortGroupField(new ScheduleSortGroupField(fieldId, order){ShowHeader…})`; `IsItemized`, `ShowGrandTotal` + `ShowGrandTotalTitle/Count`; `view.ViewTemplateId`. One transaction. Result: `scheduleId`, `name`, fields as created (with any that could not be found listed under `missingFields`), `rowCount` after `doc.Regenerate()`.

Preview resolves the category and every field, reports `missingFields` with the nearest names (reuse `FuzzyNameMatcher`), the filter value type coercion, and what the sort will do; fails when any field is missing unless `allowMissingFields=true`.

### Edit

`revit_edit_schedule`: `schedule`, `addFields[]` (same shape, optional `insertAt`), `removeFields[]` (by name or index), `order[]` (full new order by names), `rename {field: heading}`, `hide[]`/`show[]`, `setFilters[]` (replaces all), `setSort[]` (replaces all), `itemize?`, `grandTotal?`. Uses `RemoveField`, `AddField`, `SetFieldOrder(IList<ScheduleFieldId>)`, `ClearFilters`/`ClearSortGroupFields`. Preview shows before/after field order. Refuses schedules that are `IsTemplate`, `IsTitleblockRevisionSchedule`, or a panel schedule (`PanelScheduleView`), and key-schedule structural changes beyond fields.

### Place on sheet

`revit_place_schedule_on_sheet`: `scheduleId`, `sheet` (id or number), position `xMm,yMm` on the sheet, or `nextTo {viewportId, side: right|below, gapMm}` using `PlacementPointResolver.GetSheetCenter`/outline helpers; `ScheduleSheetInstance.Create(doc, sheetId, scheduleId, point)`; refuses when the schedule is already on that sheet (`ScheduleSheetInstance` collector per sheet) unless `allowDuplicate=true`. Extend `PlaceViewsOnSheetsTool` to route `ViewSchedule` ids here instead of failing in `Viewport.Create`.

### Export

`revit_export_schedule`: `schedule`, `format` = `csv` | `txt` | `xlsx`, `folder` (validated by `FilePathPolicy.ValidateWrite`; default `ExportPathService.ExportDirectory`), `fileName?` (default the schedule name, sanitized like `ExportPathService.ResolveFilePath`). CSV/TXT: `ViewScheduleExportOptions { FieldDelimiter = ";" or ",", TextQualifier, Title, HeadersFootersBlanks }` → `schedule.Export(folder, name, options)`. XLSX: table data via `GetCellText` into ClosedXML with the header row from the header section and a frozen header. Result: `filePath`, `rows`, `columns`.

### Status codes

`schedule_not_found`, `field_not_found` (data: `missingFields`, `suggestions`), `schedule_kind_unsupported`.

## Acceptance criteria

- The docs example produces a schedule identical to what a user would build by hand (fields, headers, filter, sort with headers, itemized, grand total).
- Rows read back match Revit's displayed text, including units and formatting, and are paged.
- Missing field names fail the preview with suggestions, and never create a half-finished schedule unless explicitly allowed.
- A schedule can be placed on a sheet next to a viewport without overlap in the normal case; duplicates are refused by default.
- Exports land only in policy-allowed folders.
- Unit tests green, both targets build, benchmark report committed.
