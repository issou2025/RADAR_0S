## Problem

The reusable managed-CI workflow (#1210, `managed-ci.yml` / `managed-ci-ordinary.yml`) owns the test job itself and exposes only `test_command`, `install_command`, `python_version`, `shards` and `durations_file`. Real adopters need more. wwind123/llm-dialectic#1383 (the migration) is on hold because its `test` job needs:

- service containers (`postgres:16`, `redis:7.4-alpine`, with ports and health checks);
- setup beyond pip: apt build prerequisites, lockfile verification, a pinned-ICU assertion, `actions/setup-node` with `npm ci`, docs checks, and a scope-conditional coverage plugin;
- a **routed matrix** (`include: ${{ fromJSON(needs.route.outputs.matrix) }}`) in which each cell runs a different pytest selection, plus a separate Redis-admission run.

Adding inputs one need at a time (`services` JSON, `setup_commands`, `node_version`, …) leaks suite details into the shared callee and never ends.

**Constraint:** in GitHub Actions a job's `uses:` must be a literal, never an expression. A reusable workflow therefore cannot call back into a caller-supplied test workflow, so the obvious "bring your own test job" callback cannot be built.

## Proposed design: split entry points with exact-head attestation

The **caller** composes three stages in its default-branch workflow:

1. **`validate`**: a reusable `workflow_call` from agent-loop, read-only. It runs today's dispatch validation and outputs `target_sha`, `pr_number`, `nonce`, `run_id` and `attempt`.
2. **Caller-owned test jobs** (`needs: validate`): anything the repository needs, including services, apt, Node and matrix routing, at **read-only** permissions. Each test job checks out `needs.validate.outputs.target_sha` and ends with a pinned agent-loop **attest** composite action that:
   - asserts `git rev-parse HEAD == target_sha`;
   - uploads an attestation artifact naming `target_sha`, `run_id`, `attempt`, the job (and matrix cell) identity and its result.
3. **`publish`**: a reusable `workflow_call` from agent-loop, and the **only** job with `statuses: write`. It downloads the attestations and publishes `final-ci/exact-head` success **only if** every *expected* attestation is present, binds to the validated `target_sha`, this `run_id` and `attempt`, and reports success. Otherwise it publishes failure, or nothing if validation failed, exactly as today.

The existing single-job workflows stay supported (shim or keep), so current adopters, this repository included, are unaffected until they choose to split.

## Security contract (must hold)

- **Trust root is unchanged:** managed dispatch executes the **default-branch** caller, so a PR cannot alter the composition (today's model).
- Only `publish` holds `statuses: write`. `validate` and all caller test jobs are read-only, and caller test code (PR-controlled, as tests are today) never runs with write permission.
- The **set of expected attestations** must not be forgeable by PR code. Derive it from the default-branch caller (for example a declared list or a count input to `publish`, set in the default-branch workflow and not computed by PR-head code), and fail closed when it is missing, duplicated, extra, or bound to another SHA, run or attempt.
- Attestations are only as trustworthy as the job that wrote them, and that job runs PR-head code. Define precisely what the attestation proves (that the exact head was checked out and the job concluded with result X), and that `publish` trusts the **job conclusion from the API** (`needs.*.result`, or the run's jobs API) rather than the artifact's self-reported result where possible.
- Partial, cancelled or skipped expected jobs mean no success status.

## Deliverables (for planning to stage)

- Reusable `validate` and `publish` entry points, plus the `attest` composite action, versioned and pinned like `managed-ci-v1`.
- Docs: the split-adopter template, the security contract, and migration notes for llm-dialectic's routed matrix.
- Tests: the workflow-contract tests extended to the split layout; publisher fail-closed cases (missing, duplicate or foreign-SHA attestation, failed or skipped job); and a cross-repo probe as in #1286 step 1.
- llm-dialectic#1383 is then amended to use the split layout (in that repository).
