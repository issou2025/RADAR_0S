# Project Proposal — Python Automation

## Project Understanding
You need assistance with: 
**Tooling: spec-kitty orientation block always renders 'project: unknown' (3.2.7 regression)**

*Project description:*
## Summary

The SessionStart orientation block renders `project: unknown` for every spec-kitty project. `SessionPresenceManager._build_content()` reads the slug off `AgentConfig`, which has no `project_slug` attribute at all — its only public fields are `auto_commit`, `available`, and `lint_on_edit`. The real slug lives in `.kittify/config.yaml` under `project.slug`. Because the lookup is written as `getattr(self.agent_config, "project_slug", None) or "unknown"`, the wrong-source read is permanently masked: it never raises, it just always falls through to `"unknown"`. This is a regression — our committed `.claude/CLAUDE.md`, generated under 3.2.6, reads `project: kg-automation`, so 3.2.6 resolved it correctly.

## Versions

- **spec-kitty-cli**: 3.2.7 (pinned tag SHA fb4e8fa98) — regression against 3.2.6
- **codex / antigravity / other relevant agent CLI**: Claude Code (Claude Opus 5)
- **OpenClaw** (if relevant): n/a

## Reproduction

### Prerequisites

- Any initialized spec-kitty project (`.kittify/config.yaml` present with a `project.slug`)
- spec-kitty-cli 3.2.7

### Steps

```bash
grep -A3 '^project:' .kittify/config.yaml
spec-kitty session-start
```

### Expected Behavior

The orientation block names the project, as 3.2.6 did:

```text
**Spec Kitty v3.2.7** — project: kg-automation (healthy)
```

### Actual Behavior

```text
**Spec Kitty v3.2.7** — project: unknown (healthy)
```

while `.kittify/config.yaml` plainly contains:

```yaml
project:
  uuid: 2c011d09-8272-470c-b9e2-e9ccf8ad3fbd
  slug: kg-automation
  node_id: 2af64e2d9c0e
```

and the committed `.claude/CLAUDE.md` generated by 3.2.6 reads:

```text
**Spec Kitty v3.2.6** — project: kg-automation (healthy)
```

## Root Cause

`specify_cli/session_presence/manager.py:64`:

```python
slug = getattr(self.agent_config, "project_slug", None) or "unknown"
```

`self.agent_config` comes from `load_agent_config(project_root)`. Introspecting that object on 3.2.7:

```text
type: AgentConfig
has project_slug attr: False
value: <MISSING>
fields: ['auto_commit', 'available', 'lint_on_edit']
```

So `AgentConfig` is simply the wrong source for the slug — the attribute has never existed on it. The `getattr(..., None) or "unknown"` idiom converts a wrong-source lookup into a silent, plausible-looking default, which is why this shipped: nothing errors, and `"unknown"` reads like a legitimate "not set" rather than "looked in the wrong place".

`.kittify/config.yaml` `project.slug` is the correct source; other call sites in the codebase (e.g. `specify_cli/cli/commands/tracker.py` reading `identity.project_slug`) get it from the project identity rather than the agent config.

## Workaround Applied

None — reported rather than worked around. The stale `.claude/CLAUDE.md` in the repo still carries the correct 3.2.6-era string, so nothing local is broken beyond the runtime banner.

## Suggested Fix

Option A: Read the slug from project identity rather than agent config — the same source `tracker.py` uses (`identity.project_slug`), or `.kittify/config.yaml` `project.slug` directly.

Option B: Add `project_slug` to `AgentConfig` and populate it in `load_agent_config()`, if the intent was for agent config to carry it.

Option C (orthogonal, recommended alongside either): drop the `or "unknown"` mask. A missing slug in an initialized project is a real anomaly and should be visible, not smoothed over — this defect survived a release precisely because the fallback made it look like normal output.

## Impact

- **Who hits this**: every user of every project, on every session start.
- **Frequency**: 100%.
- **What breaks**: the orientation block is the first thing an agent reads each session, and it is supposed to establish which project the agent is operating in. It now asserts the project is unknown while the config knows exactly what it is. For anyone running several spec-kitty projects side by side, the one line meant to disambiguate them is identical everywhere.
- **Severity**: cosmetic in mechanism, but it degrades the agent-orientation surface that the block exists to serve — and it is a silent regression from 3.2.6.
