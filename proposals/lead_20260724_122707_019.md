## Context

Caspian normalizes every channel behind one small provider interface. Sized as an **internship hiring challenge**: a real adapter end-to-end (contract + fake + tests). Bar is in [`CONTRIBUTING.md`](../blob/main/CONTRIBUTING.md#adding-a-new-channel-adapter). Bluesky is fully open (AT Protocol), so it's a clean fit.

## Goal

Add a **Bluesky** adapter on the **AT Protocol**. An agent replies to mentions and replies (and optionally DMs).

- Official API: AT Protocol (`com.atproto` / `app.bsky`). Auth with an **app password** via `com.atproto.server.createSession`. Outbound = create a post/reply via `com.atproto.repo.createRecord`. Inbound = **poll** `app.bsky.notification.listNotifications` for mentions/replies with a persisted cursor (DMs via `chat.bsky` if you go further).
- Transport: **polling** with a cursor (the firehose is too broad for one account).
- Best reference: `x.py` (poll + persisted cursor is the same shape).

## Acceptance criteria

- [ ] New module `packages/adapters/src/caspian_adapters/bluesky.py` implementing the provider interface (`provision` / `send` / `reply` / `parse_webhook`)
- [ ] Declares an honest `capabilities` frozenset (never claim `INITIATE` / `BACKFILL` without implementing them)
- [ ] Verifies inbound (signature or token); mismatches raise `WebhookVerificationError`
- [ ] Normalizes payloads into `InboundMessage` (no Bluesky types leak outside the package)
- [ ] Offline fake that consumes realistic Bluesky JSON fixtures
- [ ] Registered in `registry.py` (+ settings in `config.py`)
- [ ] Tests: normalization, verify accept + reject, any routing rules, no live network
- [ ] `uv run pytest` and `uv run ruff check .` pass
