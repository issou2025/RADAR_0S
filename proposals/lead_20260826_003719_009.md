# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**iOS distribution broken: Xcode Cloud's session cannot authenticate with App Store Connect for this app**

*Project description:*
Every p4td Xcode Cloud build since 25 Aug fails at **Prepare Build for App Store Connect**, on both the Production (main) and Development workflows. The one-line UI error hides the real one; the `Xcode Cloud Diagnose` workflow (Actions → Xcode Cloud Diagnose → Run) pulls it from the build's log bundle via the ASC API:

```
IDEDistribution: App Store Connect request for store configuration failed for account
Session Proxy Provider — Unable to authenticate with App Store Connect
(DVTServicesSessionProviderCredentialITunesAuthenticationContextError Code=1)

[MT] Failed to find an account with App Store Connect access for team TV3LZKGB46
```

### What the evidence rules out

- **Not the code or the Xcode project.** Build 543 succeeded on 14 Aug; the first failing builds (544/545, 25 Aug 14:12) built commits containing **zero iOS changes** (backend-only work). The break happened during the 11-day window with no builds at all.
- **Not signing.** The same build's provisioning log shows healthy cloud-managed signing ("is managed and has a portal certificate", 2 distribution certificates on the portal). The development and ad-hoc exports in the failing archive **succeed** — only the app-store export fails, at the ASC authentication step.
- **Not the team, agreements, or Apple outage.** *Mojo and Co*, on the same team, archived and distributed to TestFlight successfully at 16:31 on 25 Aug, between two p4td failures.
- **Not the ASC API key** (used by the GitHub workflows, a separate credential) — verified working by a live metadata download.

What remains is the **internal session credential Xcode Cloud holds for this specific product** ("Session Proxy Provider"): it can no longer authenticate to App Store Connect.

### Things to try, in order

1. **App Store Connect → Users and Access**: did the Apple ID that set up the p4td Xcode Cloud workflows change password, rotate 2FA, or lose its role around mid-August? That's the classic trigger, and would explain why Mojo and Co (if set up by/under a different session) still works.
2. **App Store Connect → Paws 4 Thought Dogs → Xcode Cloud**: look for any warning banner; open each workflow and re-save it, which can re-mint the credential.
3. In **Xcode** (signed in as an Admin): Integrate menu / Xcode Cloud, open the product and re-authorize; recreating the workflow also re-establishes the App Store Connect grant.
4. If none of that changes anything, this needs **Apple Developer Support** — quote build **545**, team **TV3LZKGB46**, and the error text above. This failure signature has needed an Apple-side session reset before.
