# Audit E: architecture, security, pantry, contributing, blog

Checked against jarvis-server main @57aa0ea (2026-10-21), jarvis-pantry, jarvis-node-setup, jarvis-node-mobile and jarvis-developer-toolkit. Paths: server files are relative to `jarvis-server/`, `app/...` and the compose files to `jarvis-pantry/`, and the mobile and node files to their own repos.

## Summary

The architecture pages, rewritten under #383, are mostly accurate: ports, modules, storage, the token design, voice routes and the egress setting names and defaults all match the code. Two security claims overstate the protection, and these matter most:

- **"The server cannot read command secrets."** The node's K2 key passes in plaintext through jarvisd's in-memory relay for every desktop agent and every headless node. The server also stores the encrypted settings.
- **The privacy policy's "AES-256 encrypted database" for node secrets.** This is false for the desktop agent, which keeps K2 and command secrets in plain 0600 JSON files.

The security pages also leave out:

- the secrets the server does hold (remote-LLM API keys, the Twilio token, the HF token, and smart-home OAuth tokens encrypted with a key file that sits next to the database), all of which end up in backups;
- the desktop agent's self-update from GitHub, which is on by default;
- the push relay, as a Jarvis Automation cloud service, in the privacy policy.

`voice-pipeline.md` presents the `voice.*` settings as household settings in the app and the admin, but no household can set them.

**Compliance Roadmap** is pre-jarvisd and wrong throughout. Its "implemented today" list is HS256, Loki, Postgres, Redis, MinIO and SQLCipher, and it lists features that jarvisd already ships as still planned.

**Pantry:** `self-hosting.md` tells readers to repoint nodes with `command_store_url`. On jarvisd the setting is `pantry.base_url`, and the page also leaves out that `pantry.enabled` is off by default. `rejections.md` labels 12 non-blocking codes as `error`.

**Contributing:** all four pages describe only the old Python/Docker/`./jarvis` workflow.

**Blog:** one post, `llm-era-voice-assistant.md`, gives the old install command and port as if they were current.

## pantry/self-hosting.md

**P1. self-hosting.md:105-106, and the diagram at :20** (wrong)
- **Says:** to point a node at a private Pantry, set `command_store_url` in its config.
- **True:**
  - On jarvisd the Pantry address is the setting `pantry.base_url`. It can be overridden per household, falls back to env `JARVIS_PANTRY_URL`, and defaults to `https://pantry-api.jarvisautomation.io` (`internal/modules/cc/packages.go:41-42, 56-59`).
  - jarvisd publishes it in `/services` as `jarvis-pantry`, synced at startup (`cmd/jarvisd/main.go:106`, `internal/modules/config/config.go:134-136`; the app reads it in `jarvis-node-mobile/src/services/configDiscoveryService.ts:72`).
  - jarvisd sends it to nodes as `pantry_url` (`packages.go:538, 694`).
  - `command_store_url` is read only by the node-local CLI (`jarvis-node-setup/scripts/command_store.py:38`).
- **Fix:** tell readers to set `pantry.base_url` (or `JARVIS_PANTRY_URL`) on jarvisd and restart. Relabel the diagram.

**P2. self-hosting.md:3** (misleading)
- **Says:** "The public Pantry is the default store every node reads from."
- **True:** on jarvisd the Pantry is off by default per household. Installs and Forge test installs get 403 `pantry_disabled` until a household admin turns on `pantry.enabled` (`packages.go:44, 59-63, 75-81`).
- **Fix:** say that `pantry.enabled` must be on first.

**P3. self-hosting.md:59, and the quick-start comment at :40** (wrong)
- **Says:** `PANTRY_ADMIN_API_KEY` is blank by default and is not in the quick-start list.
- **True:** the compose file requires it: `ADMIN_API_KEY: ${PANTRY_ADMIN_API_KEY:?...}` (`jarvis-pantry/docker-compose.local.yaml:37`), while `.env.local.example:104` ships it empty. So `docker compose up` fails as the page describes it.
- **Fix:** mark it required and add it to the quick start.

**P4. self-hosting.md:12** (minor)
- **Says:** each optional feature is "off until its variable is set".
- **True:** the shipped compose file turns on local LLM, the upstream URL and the admin key (`docker-compose.local.yaml:37, 40, 42`). The page's own table at :56-57 contradicts the sentence. Only the app's own defaults are off (`app/config.py:45`).
- **Fix:** say "off in the app's defaults; the local compose file turns all three on".

**P5. self-hosting.md:13-15** (minor)
- **Says:** links to the Pantry Store and Pantry Web pages under `../legacy/services/`.
- **True:** the Pantry is a current service, but these links land in the frozen Legacy section with its old-install banner.
- **Fix:** link the repos instead.
- **UNVERIFIED:** whether `jarvis-pantry-web` is public.

**P6. self-hosting.md:120** (minor)

- **True:** the stored author is `_local` (`app/api/local_commands.py:25`); browse shows it as "local" (`browse.py:83`).
