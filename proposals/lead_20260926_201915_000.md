# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Feature request: per-product has-body / representation-type flag without meshing**

*Project description:*
**ifcfast 0.5.3.** Feature request.

### Use case
A model-control tool counts "every IfcProduct with a 3D body representation, excluding IfcFeatureElementSubtraction". That count is the denominator of every per-element check, so it has to be exact. Today ifcfast can only tell whether a product has a body by meshing it (`bundle()` `vertex_count`, `meshes()`). That is a geometry pass the control otherwise does not need.

### Request
A per-product boolean (and ideally the representation identifier) on the products table, for example `has_body` / `body_rep_type`. It would be read from `IfcProductDefinitionShape.Representations`: `RepresentationIdentifier` ('Body', 'Body-FallBack', 'Facetation') and/or a 3D `ContextType` with a solid/surface `RepresentationType`, not from meshing. Spatial elements that carry a body (IfcSite with a terrain or marker body, IfcSpace) would ideally get the flag too.

### Measured differences
I compared ifcfast `products_df` (+ `spaces_df`) with a body-representation count made by another reader on the same files. All files are Revit exports.

With a flag, the counted set is a filter on `products_df`. Without one, the choice is to mesh or to use a second parser.

The files are client data and are not attached. They can be shared privately on request.
