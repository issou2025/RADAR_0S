## Bounded change
A. Extend existing run/lease outcomes with one structured pass-level episode: timeout/incomplete, table-discard children, recovered, auth-required, consent-disabled, unsupported schema and server unavailable. An abandoned result is an expected protected disposition, not another independent API failure. Do not match free-text messages to decide behavior. Preserve table/generation/relative timing and count detail for developers while de-duplicating user-visible incidents. Genuine parsing/auth/server errors stay observable.
B. Prove and fix any late-init gap through the current initializer/retry authority. A late successful init may schedule/coalesce exactly one still-needed pull for the original valid session; it may not resurrect a disconnected backend, bypass revoked consent, overwrite a newer init, or mint another identity. Check before transport and after awaits. Resume, manual retry and late-ready races use the existing coordinator and avoid parallel duplicate passes. A timeout is not cancellation of the underlying Future; explicitly fence abandoned work.
C. Wire actual sync/settings/status UI to the canonical outcomes: show last successful synchronization and current incomplete/pending state, safe retry or reconnect to the affected context. Returning local input unchanged after cancellation must not mark remote data fresh or complete. Preserve local-only retained data and pending deletions. Guidance renderer integration is optional until its shared contract exists; this fix must be independently shippable.
