*Project description:*
## Summary

Enabling live UI development (or switching to the AOT profile runtime) fails on Denial 0.3.1 with NVIDIA, in two distinct ways:

1. `denialctl ui live on` → **"a Flutter output scanout framebuffer is incomplete"** (graceful fallback to packaged UI, no crash)
2. `denialctl ui profile` → **SIGSEGV in `libnvidia-eglcore.so` during `shutdown_engine`** (session ends, SDDM returns)

Changing the second monitor's resolution also ends the session — matching the "A live display-scale change can end the session" entry already in KNOWN_ISSUES.md. All three appear to share one root: **Flutter atlas / scanout-FBO recreation fails on this NVIDIA driver**, and the failure aborts the whole session instead of degrading gracefully.

## Source analysis

- The "scanout framebuffer is incomplete" error comes from `compositor/src/bin/deniald/flutter_runtime/renderer/handler.rs:227`, where `gl.check_framebuffer_status()` returns something other than `FRAMEBUFFER_COMPLETE` after `gl.image_target_texture` (EGL DMA-BUF import) + `framebuffer_texture_2d`.
- The SIGSEGV happens in `shutdown_engine` (`flutter_runtime/platform_dispatch.rs:216`) → `host.shutdown()` → Flutter engine teardown; the crash itself is entirely inside `libnvidia-eglcore.so`.
- `destroy_targets` (`flutter_runtime/renderer/gl.rs:387`) releases FBOs/textures/EGL images via `eglDestroyImageKHR` / `glDeleteFramebuffers` — the crash is in the NVIDIA EGL core, not in Denial's own GL bookkeeping.

This matches the NVIDIA 610-series EGL regressions reported elsewhere (e.g. KWin `GL_FRAMEBUFFER_INCOMPLETE_ATTACHMENT` on driver 610.x, and Flutter embedder teardown segfaults like flutter/flutter#95125). However, Denial's failure handling also looks too aggressive: both the KNOWN_ISSUES "live display-scale change" path and this live-development path abort the entire session instead of degrading gracefully.
