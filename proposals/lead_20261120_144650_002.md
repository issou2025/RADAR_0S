# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Settings IT manages: policies through the registry, GPO/Intune (ADMX) and MSI properties**

*Project description:*
## Goal

In a company, IT sets the rules once and users configure nothing: AnalyseTool works by them from the first start. Without a policy everything stays as it is today. The standard Windows way — like Chrome, Edge and Office — not a format of our own.

## Where the settings come from

- Registry `HKLM\SOFTWARE\Policies\AnalyseTool` (machine) and `HKCU\SOFTWARE\Policies\AnalyseTool` (user), set by IT through **GPO** or **Intune** with an **ADMX/ADML** template we ship.
- MSI properties for silent installs: `msiexec /i AnalyseTool.msi MCP=0 UPDATES=0 /qn` — the installer writes them to the same HKLM key.
- `%ProgramData%\AnalyseTool\policy.json` with the same keys, for setups without GPO or Intune.

## Order and locking

Default → the user's setting (profile of the pane) → policy. HKLM beats HKCU, the registry beats the file. A key the policy sets is **locked**: its value comes from the policy and the user cannot change it.

- The UI shows a lock and «Managed by your organization» on a locked setting.
- Commands and MCP respect it: `SetMcpEnabled`, `SetScriptingEnabled` and the like answer `managed_by_policy` without changing anything. A `GetPolicy` command tells the pages which keys are set and where from.
- Applied at start and without restarting Revit: read again when the key changes (`RegNotifyChangeKeyValue`) or when the pane opens.

## First keys

| Key | Meaning |
|---|---|
| `McpEnabled`, `McpPort` | AI clients may connect to Revit; on which port |
| `ExecuteCodeAllowed` | AI may run any C# (`ExecuteCode`, `DescribeApi`) |
| `UserExtensionsAllowed` | users may create their own buttons and model test suites |
| `ExtensionRoots` (list, each with `readOnly`) | the company's folders of buttons and tests, e.g. `\\server\AnalyseTool` |
| `PackagesAllowed`, `PackageSources` | installing packages, and from where |
| `UpdateCheck`, `UpdateChannel`, `UpdateUrl` | update check, stable/beta, an own address instead of GitHub |
| `TelemetryEnabled`, `TelemetryEndpoint` | telemetry (off by default) and the company's collector |

## In the code

- A configuration source for the registry and the file, added last (`Hosting`, next to `IUserSettings`); `IUserSettings.UpdateAsync` refuses a locked key.
- `ExtensionPaths.GetRoots` adds the roots of the policy, read-only (not the `Dev` zone).
- ADMX/ADML in `build/` and in the MSI; MSI properties in the installer project.
- «For administrators» in `ONBOARDING.md`: the keys, the ADMX, examples for GPO and Intune.

## Tests (tier 1)

Layer order (default / user / HKCU / HKLM / file), locked writes, the `managed_by_policy` answer, read-only roots from the policy — the registry behind an interface, a fake in the tests.
