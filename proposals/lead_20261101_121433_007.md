# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Integrate M-Lab NDT7 speed test for accurate, standardized measurements**

*Project description:*
**Is your feature request related to a problem? Please describe.**
The current speed test implementation provides basic throughput measurements but lacks the standardization, accuracy, and comprehensive metrics that established measurement platforms offer. Users may question the reliability of results compared to commercial speed test services, and we're missing opportunities to contribute to public internet measurement datasets.

**Describe the solution you'd like**
Integrate [Measurement Lab (M-Lab)](https://www.measurementlab.net/) NDT7 protocol into Vernet's speed test feature. M-Lab is a free, open-source internet measurement platform used by researchers, regulators, and commercial services.

**Key integration points:**

1. **NDT7 Protocol Implementation**
   - Use M-Lab's NDT7 client libraries (available for Android, iOS, JavaScript, Go)
   - NDT7 uses WebSocket connections with bidirectional streaming for accurate measurements
   - Measures download speed, upload speed, latency, and packet loss
   - Protocol spec: https://github.com/m-lab/ndt-server/wiki/NDT7-protocol

2. **Server Discovery via Locate v2 API**
   - Use M-Lab's Locate v2 API to find the nearest/lowest-latency test server
   - Endpoint: `https://locate.measurementlab.net/v2/nearest/ndt/ndt7`
   - Returns a list of servers with latency estimates
   - No API key required

3. **Comprehensive Metrics**
   - Download throughput (Mbps)
   - Upload throughput (Mbps)
   - Latency (ms) - RTT to server
   - Packet loss (%)
   - Retransmission rate
   - Server location and metadata

4. **Public Data Contribution** (opt-in)
   - M-Lab publishes all measurement data under CC0 license
   - Contributes to global internet health monitoring
   - Users can opt-in to share anonymized results
   - Helps researchers, regulators, and ISPs improve infrastructure

5. **UI Enhancements**
   - Show real-time speed graph during test (reuse fl_chart from network score feature)
   - Display server location and distance
   - Show all metrics (download, upload, latency, loss) in detail view
   - Compare results to previous tests and network score baseline

**Implementation approach:**

- **Option A (Recommended)**: Use official M-Lab client libraries
  - Android: `com.measurementlab:ndt7-client-android`
  - iOS: `ndt7-client-ios` (Swift)
  - Wrap in platform channels, keep UI in Flutter/Dart
  
- **Option B**: Implement NDT7 protocol in Dart
  - More work but avoids native dependencies
  - NDT7 is well-documented WebSocket protocol
  - Could reuse existing speed test UI logic

- **Option C**: Hybrid approach
  - Use M-Lab's Locate API for server discovery (Dart HTTP call)
  - Implement NDT7 measurement in Dart using WebSocket
  - Full control over implementation, no native plugins needed

**Describe alternatives you've considered**
- Keep current speed test implementation — works but less accurate and doesn't contribute to public datasets
- Integrate commercial speed test API (Ookla/Speedtest.net) — requires licensing, less transparent
- Use iperf3 — requires server setup, not suitable for mobile users
- Build custom measurement protocol — reinventing the wheel, M-Lab is the standard

**Additional context**

**M-Lab Resources:**
- Developer docs: https://www.measurementlab.net/develop/
- NDT7 GitHub: https://github.com/m-lab/ndt-server
- Locate API: https://www.measurementlab.net/develop/api/locate/
- Data explorer: https://www.measurementlab.net/data/

**Benefits:**
- Industry-standard measurements (same protocol as speedtest.net)
- Free, no API keys or licensing fees
- Contributes to public internet measurement (opt-in)
- Comprehensive metrics beyond just throughput
- Well-maintained, open-source infrastructure
- Research-backed accuracy

**Integration with existing features:**
- Speed test results feed into the Network Score reliability dimension (#509)
- Historical comparisons can show speed trends over time
- Server discovery can be cached for faster subsequent tests

**Technical considerations:**
- NDT7 uses WebSocket over TLS (wss://)
- Tests typically run 10-15 seconds
- Requires stable internet connection
- Consider background execution for long-running tests
- Handle server selection failures gracefully (fallback to manual server list)

**Privacy:**
- M-Lab publishes anonymized data under CC0
- IP addresses are truncated in public datasets
- Users should be informed and can opt-out of data sharing
- Comply with GDPR/privacy regulations
