# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**feat(server): check process_models output name collisions before submitting**

*Project description:*
## Symptom

The add-in refuses `revit_process_models` with `save.mode=output_dir` when two sources share a file name (the collision list is returned, also for dry runs). The server sends the job first and only then learns this.

## Expected

The Python tool validates the collision before it submits, so the refusal is immediate and does not use a job slot or wait for the Revit thread. The add-in check stays as the authority.

## Notes

- Only paths given explicitly can be checked on the server. With `folder` and `recursive=true`, the add-in enumerates the files, so the server cannot see the full list. The check would cover the explicit `paths` case.
- Comparison must be case-insensitive, as on Windows.
- Low priority. The add-in refusal works (verified on Revit 2026 with 4 models, two with the same file name, dry and real run).
## Where to start

- `server/revit_model_mcp/actions.py`: `revit_process_models` (around line 1752), before the job is submitted.
- Compare file names case-insensitively for the explicit `paths` case only; skip `folder` runs.
- To test: add a case to `server/tests/test_actions.py`, then `cd server && uv run --with pytest pytest -q`. No Revit needed.
