# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**agent update time grows with every OTHER installed agent (1 s with one agent, 42 s with five, ~160 s per tool in a real store)**

*Project description:*
## Summary

`aware agent update <id>` takes time that grows with **everything else installed**, not with the agent being updated. On a clean `AWARE_HOME` with only `ifc` installed it takes **1 s**; after installing four other registry agents (18,459 files in `agents/`) the *same* `agent update ifc` takes **42 s**. In a real 34-agent store (22,782 files) a single tool update takes **155-164 s**. `agent update --all` does not amortise it (224 s for five already-current agents, about five single updates).

A front door that updates every outdated tool one by one (floless.app does) therefore waits 10-15 minutes per check, with nothing to show for most of it.

## Observed (AWARE 0.156.1, Windows 11, scratch `AWARE_HOME`, nothing copied from a real store)

| Store contents | Command | Time |
|---|---|---|
| empty | `agent install ifc` | 13 s |
| `ifc` only | `agent update ifc` | **1 s** |
| + `revit-2026` (112 s to install), `revit-2025` (109 s), `tekla-2026` (47 s), `sketchup-2026` (35 s); `agents/` = 18,459 files | `agent update ifc` | **42 s** |
| same | `agent refs --json` | 12 s (0 s with `ifc` only) |
| five agents, all current | `agent update --all` | 224 s |
| same | `agent update ifc` | 41 s |

Real store (34 installed, 22,782 files, 83 MB, while other `aware` calls were running): `agent update <tool>` 155-163 s each (from the front door's log); `agent refs --json` 164 s. A copy of that same `agents/` folder in a scratch store: `agent refs` 6 s, `agent update ifc` 62 s.

What it is **not**: the download (a fresh `agent install ifc` is 13 s); the registered workflow folders (a copy of the real `apps/` into a scratch store: `agent refs` 2 s; the two registered roots hold 2,700 files); `agent-store-v2` (123 files, 838 KB).

## Source

On a local clone (`fc8714bed`, 2026-09-23, older than 0.156.1) `update_agent_from_registry` (`cli/src/install/registry.rs:360`) works on one agent's payload only: stage, validate, `copy_dir_recursive`, `tree_digest(&staging)`, atomic swap. Nothing in it walks the other installed agents, so the cost must come from somewhere around it (a post-swap step, a store or index pass, a cache scan). **The mechanism is not identified**; a trace of file reads during `agent update ifc` in the 5-agent store below would settle it.

## Reproduce

```bash
export AWARE_HOME=/tmp/aware-scale   # any empty directory
aware agent install ifc
time aware agent update ifc          # ~1 s
for a in revit-2026 revit-2025 tekla-2026 sketchup-2026; do aware agent install $a; done
time aware agent update ifc          # ~40 s on the machine above
time aware agent update --all        # ~5x the single update
```

## Expected

Updating one agent costs about what updating it in an empty store costs. If a pass over the other agents is needed, it should happen once per `update --all`, not once per agent, and ideally not on a plain single-agent update at all.

## Why it matters

A front door that keeps tools current runs one `agent update` per outdated tool. With a normal store that is 2.5 minutes per tool, so a manual "check for updates" takes 10-15 minutes and cannot show real progress between tools.
