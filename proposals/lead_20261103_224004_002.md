# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**am-param-qa: add a parameter inventory mode (binding, group, GUID, usage)**

*Project description:*
## Context

A user wanted a naming rule for parameters in a workshared project model, and a table of "shared parameter usage, binding and grouping" for review with another team. The session loaded `am-param-qa`. That skill checks only whether required parameters have values (MISSING / EMPTY per element). It does not list the parameters themselves. So the agent wrote three raw `run_query` scripts instead of using `scripts/param_qa.py`.

## What happened

1. **Inventory by hand.** The scripts read every project parameter binding: name, shared or project, GUID, data type, "Group parameter under", instance or type, and bound categories. They also read the shared parameters that exist in the model with no binding.
2. **Findings the user needed, which `am-param-qa` cannot give:**
   - two names that each exist twice with different GUIDs (one bound, one not), so a tag or schedule that uses the wrong GUID shows blanks;
   - two pairs of parameters that do the same job under different names (one pair bound, one not);
   - 24 shared parameters with no binding, brought in by families (title blocks and two model families); they look like purge candidates but are not;
   - 6 parameters grouped under "Other";
   - names with spaces, hyphens and two spellings of one word;
   - no shared parameter file set in Revit, so the `.txt` group of each parameter could not be read.
3. **Usage.** A third script counted where each parameter is used: schedules (fields and filters), view filters and families. One heavily used set fed about 31 schedules each. One parameter had no elements to fill but 2 view filters used it. The script did not check tags, labels or nested families, and the report said so.
4. **Fill rates.** The fill rate per parameter came from the second script. This part overlaps `am-param-qa`, but it ran over all bound categories, not a chosen list.
5. **Output.** The user did not want a static table that goes out of date. They accepted a drafting view with the table only as a **dated snapshot** ("rerun the audit to refresh it"). The report and a CSV with GUIDs went to a notes folder.

## Proposed change

Add an inventory mode to `am-param-qa` (read only), for example "parameter inventory":

- one row per parameter: name, shared or project, GUID, data type, group, instance or type, categories, fill rate;
- flags: same name with two GUIDs, unbound shared parameters (with the family that brings each one), group "Other", names that break a rule the user gives (spaces, hyphens, case), no shared parameter file set;
- usage counts: schedule fields and filters, view filters, families; and a clear list of what is not checked (tags, labels, nested families);
- output as a table, a CSV, and an optional dated snapshot view built in a separate `am-safe-change` step;
- a short note for rule drafting: a shared parameter cannot be renamed in place; a rename is a new GUID plus a value copy and updates of schedules, filters and tags.

## Acceptance ideas

- On a model with one name bound under two GUIDs, the inventory flags it.
- On a model with unbound shared parameters from a title block family, the inventory lists them with that family and does not call them unused.
- The report states which usage sources it did not check.

## Not verified

- Whether reading the group from the shared parameter `.txt` file is possible when no file is set in Revit options.
- The run time on a large model with many families.
