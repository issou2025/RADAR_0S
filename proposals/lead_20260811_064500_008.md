## Zero-Boilerplate Value Equality in Flutter State: BlocSignal Meets fast_immutable_collections

State management frameworks in Flutter live or die by **state de-duplication**. When a state container receives an update, it must determine: *Has the state actually changed?*

In [`BlocSignal`](https://pub.dev/packages/bloc_signals), state transitions propagate **synchronously**. Calling `emit(newState)` immediately checks:
```dart
if (stateValue == newState) return;
```
If `stateValue == newState` evaluates to `true`, `BlocSignal` automatically drops the transition—saving CPU cycles, skipping local `onChange`/`onTransition` hooks, and preventing unnecessary Flutter widget rebuilds.

However, standard Dart collections (`List`, `Set`, `Map`) pose a hidden trap.

---

### The Trap: Standard Dart Collections and Identity Equality

By default in Dart, standard collections do **not** implement value equality:

```dart
final listA = ['apple', 'banana'];
final listB = ['apple', 'banana'];

print(listA == listB); // FALSE! Standard List checks identity (identical memory reference)
```

If your `BlocSignal` or `CubitSignal` holds state containing a standard `List`:

```dart
class CartCubit extends CubitSignal<List<CartItem>> {
  CartCubit() : super(initialState: const []);

  void refreshCart() {
    final items = fetchItems(); // Returns ['apple', 'banana']
    emit(items); // Always triggers rebuilds even if items match stateValue!
  }
}
```

Even if `items` contains identical elements to `stateValue`, `listA == listB` returns `false`. `BlocSignal` is forced to treat every emission as a state change, causing:
1. Signal notification re-runs across all connected `computed()` signals.
2. Unnecessary Flutter widget rebuilds in `BlocSignalBuilder` or `SignalBuilder`.
3. False-positive transitions logged in `BlocSignalObserver`.

#### The Traditional Workarounds (And Their Costs)
Developers usually solve this in one of three ways:
* **`Equatable` / `ListEquality()`**: Requires boilerplate `props` lists or custom `operator ==` overrides on every state class.
* **`freezed` Code Generation**: Requires running `build_runner` and generating thousands of lines of auxiliary code.
* **`SignalOptions(equals: ...)`**: Overriding `equals` on `BlocSignal` manually for every collection type.

Crucially, **none of these options stop developers from accidentally mutating a standard `List` in place** (`state.items.add(newItem)`), which bypasses state reactivity entirely and introduces subtle stale-data bugs.

---

### Enter `package:fast_immutable_collections` (FIC)

[`package:fast_immutable_collections`](https://pub.dev/packages/fast_immutable_collections) by Marcelo Glasberg introduces immutable collection types (`IList`, `ISet`, `IMap`) that solve both problems simultaneously:

1. **Automatic Value Equality**: `IList([1, 2]) == IList([1, 2])` evaluates to `true` out of the box!
2. **Guaranteed Immutability**: Collections cannot be mutated in-place. Methods like `.add()` or `.remove()` return a *new* immutable collection instance.
3. **High Performance**: Built with structural sharing, copy-on-write lazy evaluations, and flush/lock optimizations.

---

### Pattern 1: Pure Collection Cubits with `IList`

By replacing `List<T>` with `IList<T>`, `CubitSignal` de-duplicates identical collections automatically:

```dart
import 'package:fast_immutable_collections/fast_immutable_collections.dart';
import 'package:bloc_signals/bloc_signals.dart';

class TodoCubit extends CubitSignal<IList<Todo>> {
  TodoCubit() : super(initialState: IList());

  void addTodo(Todo todo) {
    // stateValue.add() returns a new IList with value equality
    emit(stateValue.add(todo));
  }

  void removeTodo(Todo todo) {
    emit(stateValue.remove(todo));
  }

  void reorder(int oldIndex, int newIndex) {
    // If indices match, FIC returns an identical IList; emit() drops it!
    final updated = stateValue.removeAt(oldIndex).insert(newIndex, stateValue[oldIndex]);
    emit(updated);
  }
}
```

### Pattern 2: Custom State Classes without `freezed` or `Equatable`

When building state classes that hold multiple fields, using FIC collection types ensures clean `operator ==` implementations without external generators:

```dart
@immutable
class ShoppingCartState {
  const ShoppingCartState({
    required this.items,
    required this.couponCode,
    required this.isCheckingOut,
  });

  final IMap<String, CartItem> items; // Immutable map with value equality!
  final String? couponCode;
  final bool isCheckingOut;

  ShoppingCartState copyWith({
    IMap<String, CartItem>? items,
    String? couponCode,
    bool? isCheckingOut,
  }) {
    return ShoppingCartState(
      items: items ?? this.items,
      couponCode: couponCode ?? this.couponCode,
      isCheckingOut: isCheckingOut ?? this.isCheckingOut,
    );
  }

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is ShoppingCartState &&
          runtimeType == other.runtimeType &&
          items == other.items && // Uses FIC's value equality!
          couponCode == other.couponCode &&
          isCheckingOut == other.isCheckingOut;

  @override
  int get hashCode => Object.hash(items, couponCode, isCheckingOut);
}
```

### Pattern 3: The Ultimate Combo — Dart 3 Records + FIC

Dart 3 records synthesize `operator ==` and `hashCode` automatically by comparing all record fields. Combining Dart 3 records with FIC collections gives you **100% boilerplate-free state containers**:

```dart
// Zero code generation. Zero Equatable. 100% Value Equality & Immutability.
typedef FilteredTodosState = ({
  IList<Todo> todos,
  ISet<String> activeTags,
  bool isLoading,
});

class FilteredTodosCubit extends CubitSignal<FilteredTodosState> {
  FilteredTodosCubit()
      : super(
          initialState: (
            todos: IList(),
            activeTags: ISet(),
            isLoading: false,
          ),
        );

  void toggleTag(String tag) {
    final updatedTags = stateValue.activeTags.contains(tag)
        ? stateValue.activeTags.remove(tag)
        : stateValue.activeTags.add(tag);

    emit((
      todos: stateValue.todos,
      activeTags: updatedTags,
      isLoading: stateValue.isLoading,
    ));
  }
}
```

Because Dart records compare fields using `==`, and `IList`/`ISet` implement value equality, calling `toggleTag` with an already toggled state results in `stateValue == newState => true`. `BlocSignal` drops the emission synchronously in **0ms**!

### Summary

By pairing `BlocSignal` with `package:fast_immutable_collections`:
1. **State de-duplication works as intended**: `BlocSignal`'s synchronous `emit()` check instantly drops duplicate collection states.
2. **Accidental state mutation is impossible**: Immutable collections prevent in-place modification bugs.
