*Project description:*
## Context & Objective

**Background:** This is the only screen in the app where a user can create an account, and it is reached exclusively from the Profile tab (#L14) — never on launch, never in front of onboarding, never as a wall. That placement is the whole design and it is worth restating, because "add a login screen" almost always means "add it to the front" and doing that here would be wrong three times over: it would gate an offline-first app behind reachability, it would kill onboarding activation, and forced registration for features that do not require an account is one of the most common 5.1.1 rejection reasons.

Two Apple-specific presentation rules apply. `SignInWithAppleButton` must use Apple's own widget rather than a custom-styled button — the Human Interface Guidelines require the official mark, size and corner radius, and a hand-rolled lookalike is a review risk. And if a third-party login is offered, Sign in with Apple must be offered as an equivalent option (Guideline 4.8); here Apple is the primary and email OTP the secondary, which satisfies it comfortably.

The Hebrew and RTL requirements are the same as everywhere else in the app: `Directionality` is RTL at the root, Hebrew is primary, minimum touch target 44×44pt, dark-mode-first palette with `#F5A623` accent.

**Objective:** A modal sheet offering Sign in with Apple and email OTP, in Hebrew and RTL, that maps each sealed `AuthException` case onto specific Hebrew copy, treats a cancelled Apple sheet as a silent no-op, and dismisses on success.

**Why Now:** First UI in the milestone; `AccountSection` (#L14) opens it. Blocked by the service.

**Approach summary:** A modal sheet rather than a route, so it composes with the tab shell without touching `app_router.dart` and so dismissal is a gesture rather than a navigation decision. Email OTP is a two-phase form in one sheet (address → code) rather than two routes, because a route change loses the entered address on back-navigation.

## Implementation Plan

### Step 1 — Build the sheet

**File:** `lib/features/auth/presentation/widgets/sign_in_sheet.dart`

**API Contract:**
```dart
/// Account creation and sign-in. Reached only from the Profile tab (#L14).
///
/// Never shown on launch and never placed in front of onboarding: this is an
/// offline-first app, and forced registration for features that do not need an
/// account is an App Store rejection risk under 5.1.1(v).
class SignInSheet extends ConsumerStatefulWidget {
  const SignInSheet({super.key});

  /// Presents the sheet. Resolves to true if a session was established.
  static Future<bool?> show(BuildContext context);
}
```

**Logic / Behaviour:**

- **Layout** (RTL, top to bottom):
  1. Grab handle.
  2. Title — `'שמירת ההתקדמות שלך'`.
  3. Body copy stating plainly what an account does and does not do today: it saves the identity, and diary data stays on the device. Do **not** promise sync or cross-device restore — neither exists in this milestone (see the Epic's scope boundaries), and copy that implies otherwise is a promise the app does not keep.
  4. `SignInWithAppleButton` — Apple's widget, unmodified, `text: 'המשך עם Apple'`.
  5. `'או'` divider.
  6. Email field → `'שלח קוד'` button.
  7. Once a code is sent: 6-digit field → `'אימות'` button, plus a resend affordance disabled for 60 seconds.
  8. Link to the privacy policy (#L18).

- **Two-phase email state:** `_EmailPhase.address` → `_EmailPhase.code`. Keep the entered address in state across the transition and show it above the code field, so the user can see what they typed without going back.

- **Submission:** disable both buttons and show an inline spinner while a call is in flight. Never leave both enabled — a double-tap on Apple opens two authorisation sheets.

- **Error mapping** — exhaustive `switch` on the sealed `AuthException`:
  | Case | Behaviour |
  |---|---|
  | `AuthCancelledException` | **Silent.** Reset to idle and show nothing. Surfacing this as an error is the single most common mistake in an Apple sign-in implementation, and it makes a normal dismissal look like a crash |
  | `AuthNetworkException` | `'אין חיבור לאינטרנט. הנתונים שלך נשמרים במכשיר בכל מקרה.'` — states the reassuring truth, since the app genuinely works offline |
  | `InvalidOtpException` | `'הקוד שגוי או פג תוקף'`, inline under the code field, field stays populated |
  | `CredentialAlreadyLinkedException` | `'החשבון הזה כבר משויך למשתמש אחר'` plus an explicit choice; **never** resolve silently — either branch loses data |
  | `AuthBackendException` | Generic `'משהו השתבש. נסה שוב.'` — never render `message`, which is developer-facing and not localised |

- **Success:** `Navigator.pop(context, true)`. Do not navigate anywhere else — the user came from Profile and returns there.

- **A11y / RTL:** `Directionality` is already RTL at the app root; do not re-wrap. Every tappable ≥ 44×44pt. Give the Apple button and both text fields `Semantics` labels — the sheet is otherwise unlabelled for VoiceOver.

**Integration:**
- Consumes: `authServiceProvider`, `authStateProvider` (#217)
- Opened by: `AccountSection` (#L14)
- Copy source: `design/ui_ux_design.md` §9 conventions; new strings added to the Hebrew string set

### Step 2 — Widget-test the sheet

**File:** `test/features/auth/presentation/widgets/sign_in_sheet_test.dart`

**What to test:**
- `'renders in RTL with the Apple button and email field visible'`
- `'tapping the Apple button calls AuthService.signInWithApple'`
- `'shows a spinner and disables both buttons while a call is in flight'`
- `'pops with true once a session is established'`
- `'a cancelled Apple sheet shows no error and returns to idle'`
- `'a network failure shows the offline copy'`
- `'an invalid code shows inline error copy and keeps the field populated'`
- `'an already-linked credential shows the explicit choice, not a silent resolution'`
- `'a backend failure shows generic copy and never renders the exception message'`
- `'the email phase keeps the entered address visible on the code screen'`
- `'every tappable meets the 44x44 minimum touch target'`

**Test doubles needed:** override `authServiceProvider` with a `MockAuthService` via `ProviderScope.overrides` — the provider-override pattern `design/tests.md` specifies for presentation tests.

> `'a cancelled Apple sheet shows no error and returns to idle'` is the one to write first. It is a behaviour a reviewer will notice immediately and a test is the only thing that keeps it from regressing into a snackbar.
