**Summary / Description:**

On the Billing & Plans screen, if the system fails to open the checkout page, the error toast shows the raw exception text. The code builds the message as 'Error launching payment page: $e', which exposes technical text such as PlatformException(...) or ArgumentError details to the user.

**Why is this ticket needed? (Required)**

This toast appears in the middle of a purchase. Raw exception text is unreadable to users, makes the app look unfinished, and gives no hint of what to do next. A short fixed message and a log entry for developers is the standard pattern.

**Details:**

File: lib/features/credits/presentation/views/buy_credits_view.dart
Line: 154–160 (message string at line 159)
Current behavior: The catch (e) block shows an error toast with 'Error launching payment page: $e'.
Proposed fix: Replace the message with a fixed string such as 'Could not open the payment page. Please try again.'. Log e with AppLogger.w(...), which the project already uses in other files.
Scope: 2–3 lines in one file. No new dependencies.

**Steps to reproduce:**

Sign in and open Billing & Plans (/credits/buy).
Click “Purchase” on a paid package.
Make launchUrl throw, for example with a checkout URL the OS cannot handle or a machine with no default browser.
Observe the error toast.

**Expected result:**

A readable message such as “Could not open the payment page. Please try again.” The technical detail goes to the log only.

**Actual result:**

The toast reads “Error launching payment page: “ followed by the exception’s toString(). Confirmed by reading the code. The failure path was not triggered at runtime.

**Acceptance criteria:**

- The toast no longer includes the exception text.
- The exception is still logged for developers.
- The launched == false toast (lines 147–153) is unchanged.
- Successful checkout launch is unchanged.
- No unrelated code changes; flutter analyze passes.
