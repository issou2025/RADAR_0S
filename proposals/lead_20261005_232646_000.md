# Project Proposal — Dwg To Revit

## Project Understanding
You need assistance with: 
**Multi-document support + reload DWG/IFC links from chat-provided paths**

*Project description:*
## Goal

Let the agent work across multiple open Revit projects autonomously, reload DWG/IFC links in each project from file paths the user gives in chat, remove DWG/IFC links or turn them off in Visibility/Graphics when asked, and save the projects.

Today every tool works only on the active document (`revit_get_connection_status` reports a single document), and no tool lists or switches documents.

## Intended workflow

1. User opens the projects in Revit; the agent lists them.
2. For each project, the user says in chat which files to reload from (1 DWG + 1–2 IFC). The agent matches each file to an existing link and reloads it from the new path.
3. _TBD: follow-up steps after the reload (e.g. checks/exports per project)._

## Proposed tools

### `revit_list_open_documents`
- Read `UIApplication.Application.Documents`.
- Skip linked documents (`doc.IsLinked`) and family documents (`doc.IsFamilyDocument`).
- Return per document: title, path, `IsWorkshared`, central path, whether it is active.

### Optional `document` parameter on existing tools
- Optional `document` (title or path), resolved from `Application.Documents`; defaults to the active document.
- Reads, collectors and transactions work on non-active documents, so the UI doesn't need to switch.
- UI-bound tools still require the active document: selection, active view, `revit_focus_clash`, `revit_select_*`. They should return a clear error if a non-active document is targeted.
- Config/skill overrides (`config_get_project_config`) must resolve per target document.

### `revit_activate_document` (optional)
- `UIApplication.OpenAndActivateDocument(path)`, run via the ExternalEvent handler. It cannot run while a transaction is open.

### `revit_reload_links_from`
- Input: `document` plus a list of `{ link, path }` (link = existing link name/type, path = new file the user gave in chat).
- DWG: `CADLinkType.LoadFrom(path)`.
- IFC: repoint/reload the `RevitLinkType`. **Needs testing:** an IFC link is backed by a cached `.ifc.RVT`. `Reload()` may only reload the cache, so the tool may need to re-run the IFC import/conversion first. Reuse the logic from `ifc_list_links`.
- Must run **outside** a transaction.
- Output per link: old path, new path, status/error.
- Matching: match the files to existing links by type and name. If ambiguous (e.g. 2 IFC links + 2 new files with different names), return the proposed pairing for confirmation instead of reloading. Respect `destructiveActionsRequireManualApproval`.
- Optional: store the expected links per project (e.g. "ITM: 1 DWG, 2 IFC") in `config_set_project_config`.

### `revit_remove_links` (+ `revit_preview_remove_links`)
- Input: `document` plus a list of links to remove (DWG and/or IFC, by name/type).
- DWG: delete the `CADLinkType` (`doc.Delete(typeId)`), which also removes all its instances.
- IFC: delete the `RevitLinkType` behind the IFC link. Optionally also delete the cached `.ifc.RVT` file (off by default).
- Runs inside a transaction (unlike reload). Works on non-active documents.
- Destructive: preview first (list the links + instance counts + views affected), then require manual approval per `destructiveActionsRequireManualApproval`.
- Output per link: name, type (DWG/IFC), instances removed, status/error.

### `revit_save_document`
- Input: `document` (or `all: true` for every open project document), plus optional `syncWithCentral` (default false).
- Non-workshared: `doc.Save()`.
- Workshared local: `doc.Save()` saves the local file. With `syncWithCentral: true`, run `doc.SynchronizeWithCentral(...)` with `TransactWithCentralOptions` + `SynchronizeWithCentralOptions` (comment, relinquish options, `SaveLocalBefore/After`).
- Works on non-active documents. Must run **outside** a transaction.
- Skip/report documents that can't be saved: read-only, detached, unsaved new documents, linked documents.
- Plain save may run without approval. Sync with central requires manual approval (`destructiveActionsRequireManualApproval`).
- Output per document: title, saved / synced / skipped, error message.
- Typical use: after reloading or removing links, save each project before moving to the next.

### `revit_set_link_visibility` (+ preview)
- Turns DWG/IFC links on/off in Visibility/Graphics, without removing them.
- Input: `document`, links (by name/type), `visible: true|false`, and scope: list of views, `allViews`, or view templates.
- DWG (V/G → Imported Categories): `view.SetCategoryHidden(importCategoryId, hidden)` on the DWG's import category. Check whether the existing `revit_set_cad_overrides` already covers this and extend it, rather than duplicating it.
- IFC / RVT links (V/G → Revit Links): `view.HideElements` / `UnhideElements` on the `RevitLinkInstance` ids.
- View templates: if a view's V/G is controlled by a template, change the template, or report the view as skipped. Never silently detach the template. Option `applyToTemplates: true`.
- Runs inside a transaction. Works on non-active documents.
- Preview lists affected views/templates and current state; changes to many views or templates need approval.
- Output per view: link, before → after, skipped (with reason).

## Guards / notes
- Any sync/close tooling (`SynchronizeWithCentral`, `Close`) stays behind manual approval. The API cannot close the active document; another document has to be activated first.
- Memory: several large models open at once in Revit 2026.
