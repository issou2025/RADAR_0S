# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Native apps migration, Phase 0: route choice and feasibility spikes**

*Project description:*
Part of #346. Chooses the route and proves the riskiest requirements can be met **before any feature is ported**. Code here is throwaway and every spike runs on real devices. Decision IDs (D), backend items (B) and risks (R) refer to #346.

Flutter was the preferred framework, but the design requirement is the must-have. Flutter has no released official Liquid Glass and [no public roadmap](https://github.com/flutter/flutter/issues/194350) for it, and glass over its native map view is unproven. React Native with Expo renders real native views and keeps TypeScript, so it is tested against Flutter here.

| Route | iOS and Android | Web | UIs | Shared client code |

| **B** | Expo | Expo | 1, plus separate web chrome and map | All, in TS |
| **C** | Expo | Current Vue app | 2 | Domain, data and schemas as TS packages; state layer per UI |

**Fallback:** three native UIs in one repo (Swift, Compose, current Vue web). It needs no spike here, because the question is its cost, not its feasibility.

## Step 1: Native head-to-head, Flutter vs. Expo

Build the same test screen on both, with the same fixture data, on the same devices. Routes B and C share the Expo result.

- [ ] **S1 Glass over map (iOS 26/27).** Pan a native MapLibre map under real glass buttons, toolbar, sheet and menu. Top risk (R1).
  - Flutter: `maplibre_gl` with native glass views, compared with shader glass. Also check for the open [iOS platform view jank](https://github.com/flutter/flutter/issues/190815).
  - Expo: `maplibre-react-native` with `GlassView` / `GlassContainer`, native toolbar and tabs, `formSheet`.
  - **Pass:** glass visibly refracts or samples the map, stays smooth on the oldest supported iPhone, keeps correct z-order with sheets, works with VoiceOver and Reduce Transparency.
- [ ] **S3 Map parity.** Swisstopo vector style, Classic WMTS, overlays, ski-route vector source, 1,000+ markers with clusters and generated images, tap hit-testing, track drawing with snapping, offline region including labels, a full-Switzerland download above the default tile limit, access with no `Referer`.
  - **Pass:** all work on iOS and Android, and drawing feels direct.

## Step 3: Remaining spikes on the chosen route

- [ ] **S5 Offline core.** SQLite outbox (Drift on Flutter, `expo-sqlite` exclusive transactions on Expo) with kill-during-drain and conflict cases. **Pass:** ported `core/offline` tests are green.
- [ ] **S6 Push.** Worker to both platforms, cold-start tap to deep link, stale token cleanup.
