# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**PRD: One-command local install (make setup) for self-hosters**

*Project description:*
## Problem Statement

job-hunt-crew is open source, but installing it locally today means reading a long README written for its own author: installing Node 22 + pnpm, Python 3.11 + uv and Docker on the host; copying two `.env.example` files (and knowing about a third, undocumented root `.env` that docker-compose interpolates); keeping `INTERNAL_API_SECRET` and `DATABASE_URL` in step across those files by hand; running the seed manually; and discovering that there is no way to sign in as an Administrator at all unless you find `create_admin.py`, which the README never mentions. On top of that, the repo ships real-looking secrets as defaults (a Fernet `SETTINGS_ENCRYPTION_KEY` hardcoded in docker-compose, `INTERNAL_API_SECRET=dev-internal-api-secret`, `AUTH_SECRET="changeme"`), so an installation that never changes them encrypts its stored LLM API keys with a key anyone can read on GitHub. A fresh install also shows Google and LinkedIn sign-in buttons that cannot work, defaults the LLM to an Ollama server that probably isn't running, and has no `LICENSE`, so the code isn't legally reusable.

## Solution

One guided command. Someone with only Docker (and `make`) runs `git clone` + `make setup`: the script checks prerequisites and ports, asks a few questions (first Administrator, LLM provider + key, optional SMTP, OAuth and job-source keys — every optional one skippable with Enter), writes a single root `.env` with freshly generated secrets, builds and starts the whole stack (including a production build of the web app), applies migrations, seeds the base data, creates the first Administrator, waits for the app to be healthy, and prints a summary: the URL, the Administrator's email, the active LLM, which job sources are active vs inactive, and what to do next. Re-running `make setup` is safe and doubles as the upgrade path. Contributors keep today's host-tooling dev loop, documented separately, reading the same root `.env`.

## Implementation Decisions

**Audience and run modes**
- Two install paths: the default **self-hoster path** (Docker + `make` only; everything, including seed and Administrator creation, runs inside containers) and the existing **contributor path** (host Node/pnpm/Python/uv, hot reload), documented under "Develop".
- Scope is a local machine or a single personal server. `APP_URL` is configurable; TLS, reverse proxy, public exposure and the AWS infrastructure under docs/infra are out of scope.

**Setup orchestrator (`make setup`)**
- Written in bash (macOS, Linux, WSL); no Node or Python on the host. Secrets come from `openssl` (or a throwaway container if it's missing). Seed and Administrator creation go through `docker compose run` against the images that already contain Prisma (the `migrate` image) and `py-db` (the `api` image).
- Sequence: prerequisite checks → questions (or env-driven non-interactive mode) → `.env` merge → build → up → `migrate deploy` → seed → first Administrator → health wait (API `/health`, web returns 200) → summary.
- Idempotent: it is also the upgrade path. No separate `make update`.
- Ports stay fixed. A busy port is a hard, named failure, not a reconfiguration prompt.

**`.env` merge (deep module)**
- One entry point takes the `.env.example`, the existing root `.env` (if any), the legacy `apps/web/.env` and `packages/prisma/.env` (if any), the answers collected, and the secrets generated, and produces the new root `.env`.
- Rules: an existing value always wins; a secret is generated only when absent and never regenerated; legacy files are imported only for keys the root `.env` lacks; keys the `.env.example` doesn't know are preserved, not dropped; comments and section layout come from `.env.example`.
- Kept free of prompting and Docker, so it can be tested on files alone.

**Single root `.env`**
- One root `.env` (gitignored) and one root `.env.example`, sectioned as required / generated by setup / optional / advanced. Every advanced variable is commented with its default.
- `apps/web/.env.example` and `packages/prisma/.env.example` are removed. The contributor path loads the root file: `apps/web` via Next's env loading pointed at the repo root, Prisma CLI commands via the root file too.
- `.env.example` is built from an inventory of the variables the code actually reads. A variable nothing reads anymore (e.g. a cap superseded by Plan-scoped quotas, docs/adr/0014) is removed rather than documented.

**docker-compose hardening**
- `AUTH_SECRET`, `INTERNAL_API_SECRET` and `SETTINGS_ENCRYPTION_KEY` become required interpolations that fail with a "run make setup" message. The hardcoded Fernet key and the dev internal secret are removed from the compose file.
- `LLM_PROVIDER` no longer defaults to `ollama`. When no provider is configured, the summary says so and points to Admin → LLM providers (docs/adr/0024); the pipeline's existing "required parameter resolves nowhere" failure names the provider and parameter.
- Postgres, MinIO and ElasticMQ publish on `127.0.0.1` only. Their default credentials (`postgres:postgres`, `minioadmin`) are kept, consistent with the local-only scope.
- `stepfunctions-local` moves behind a `stepfunctions` compose profile.

**Production web (docs/adr/0034, amends docs/adr/0026)**
- A production image for `apps/web` (`next build` + `next start`, `standalone` output) joins the root `docker-compose.yml` as a default service, reaching `api` at `http://api:8000` on the stack network and reading the root `.env`.
- The dev-mode `web` (`make web-up`, `apps/web/docker-compose.yml`) stays standalone and unchanged in purpose; it now reads the root `.env`.

**First Administrator (`create_admin`)**
- Interactive prompts for email, name and a masked, confirmed password; non-interactive inputs via `ADMIN_EMAIL` / `ADMIN_NAME` / `ADMIN_PASSWORD` for that run only. The password is never written to `.env`.
- Runs inside the `api` container.
- Creates a `free` Subscription for a *new* User, aligning with the sign-up path; promoting an existing User still leaves their Subscriptions untouched.
- Exposes "does any Administrator exist?" so the setup can offer to skip this step on re-runs.

**Sign-in page**
- The server computes the configured sign-in methods (Google if its client id is set, LinkedIn likewise, magic link if an email server is set, password always) and the sign-in form renders only those. The Auth.js provider list follows the same rule.

**Seed**
- Unchanged in scope: SiteConfig rows (upserted by the Prisma seed) plus PlanQuotaDefault values (already inserted by migrations), plus the first Administrator. No demo data.
- `SiteConfig.enabled` is not tied to credential presence: whether a site is enabled is an Administrator's decision. The setup summary reports credential-less sources (France Travail, Adzuna) as inactive instead.

**Makefile**
- New targets: `setup` and `reset`. `reset` runs `down -v` (Postgres and MinIO volumes) and keeps `.env`. Without `CONFIRM=1` it only reports, like `clean-analyses` and `archive-scouts`.

**Docs and licensing**
- README: "Quick install" first (prerequisites: Docker; `git clone`; `make setup`; WSL for Windows), then "Develop" with today's setup (contributor path, Step Functions profile, port-3000 exclusivity with the stack's `web`), plus documentation of `create_admin` for adding more Administrators.
- Add `LICENSE` with AGPL-3.0.

## Testing Decisions

- Good tests here exercise external behaviour only: what `.env` comes out for given inputs, what rows exist after `create_admin`, which buttons the sign-in page renders, whether a fresh runner ends up with a working app. Not how the script is structured internally.
- **`.env` merge**: bats tests, run in a container (no host prerequisites), on fixture files. Cases: fresh install; re-run with a complete `.env` (output identical, no secret regenerated); partial `.env` (only missing keys filled); legacy `apps/web/.env` / `packages/prisma/.env` import, with an existing root value winning over a legacy one; unknown keys preserved; generated secrets have the expected shape (valid Fernet key, etc.).
- **`create_admin`**: extend the existing `services/api/tests/test_create_admin_script.py`. New cases: a new Administrator gets exactly one `free` Subscription; promoting an existing User adds none; env-driven non-interactive inputs; the "an Administrator exists" check.
- **Sign-in page**: Vitest, following the existing tests under `apps/web/test/`. With and without Google, LinkedIn and email-server configuration, assert which methods render.
- **Install smoke test in CI**: a new GitHub Actions job runs `make setup` non-interactively on a clean runner, then asserts the API health endpoint answers, the web app returns 200, and the Administrator can sign in with the password given. Prior art for the workflow: `.github/workflows/ci.yml`; for the sign-in check: `apps/web/e2e/auth.spec.ts`.

## Out of Scope

- Exposing an instance on the internet: domain, TLS, reverse proxy, hardened infrastructure credentials.
- The AWS deployment under docs/infra.
- Demo data (sample candidate, CV, Scout). Worth a separate issue.
- A web-based first-run page that creates the Administrator: rejected, because the first visitor to an exposed instance would become Administrator.
- Native Windows support (WSL is the documented path).
- Configurable ports.
- `CONTRIBUTING.md`.
- Re-encrypting stored LLM keys under a new `SETTINGS_ENCRYPTION_KEY`: they're re-entered from the Admin screen, as the README already documents.

## Further Notes

- docs/adr/0034 records the decision to put a production `web` in the root compose and how it amends docs/adr/0026.
- Domain vocabulary: the "admin user" is the **Administrator** (`Role = administrator`) as defined in services/api/CONTEXT.md; their Effective Plan and Subscription follow the existing rules (docs/adr/0017, docs/adr/0018).
- Migration note for existing installations: after the first `make setup`, LLM keys previously saved from Admin → LLM providers become undecryptable (logged as `llm_provider_secret_undecryptable`) and fall back to the environment's keys until re-entered.
