*Project description:*
## Context

A user asked for a softer department diagram: rounded-corner filled regions that follow the areas of one area plan, in one detail group. Later rounds added a gap between shapes and moved the result from a drafting view onto the presentation area plan. No `am-*` skill covers this, so the agent wrote raw `run_query` / `run_modify` scripts. Model: workshared Revit 2026 project model, about 90 areas on one level.

Environment: Windows 11, Revit 2026 (26.3), pyRevit 7.0.0 agent runtime, IronPython 2.7.12, Claude Code desktop app.

## What happened

Five points cost a retry or a round with the user:

1. **Area boundary loops can be open.** `Area.GetBoundarySegments()` returned loops with gaps of 0.17 to 0.61 ft for 5 areas. Revit still calculates these areas, so nothing in the UI warns. The cause: area boundary lines that stop short of each other or overshoot. `CurveLoop` / `FilledRegion.Create` need a closed loop, so those areas were skipped. The fix was to trim/extend 3 boundary lines (dry run first). That fix moved about 5.5 sf between two neighbour areas, so the user had to approve it.
2. **`doc.Create.NewGroup` crashed inside Revit.** To add regions to an existing detail group, the script ungrouped it and passed the ids from `Group.UngroupMembers()` plus the new regions. Revit threw `SEHException` in `ElementGroup.shouldElementBeAddedToGroupByParent`. The member list includes sketch elements of the filled regions. Passing only the `FilledRegion` ids from a view collector worked.
3. **The active view cannot be deleted.** `doc.Delete(view.Id)` failed with "ElementId cannot be deleted" because the agent had opened that view earlier. `uidoc.RequestViewChange(other_view)` in a separate query fixed it.
4. **`FilledRegion.IsValidBoundary` does not exist** in the Revit 2026 API. The agent assumed it. `lookup_revit_api` showed the real members. The agent replaced it with pairwise `Curve.Intersect` checks between loops.
5. **Transparent regions over an area plan do not hide the area color fill.** After the move onto the presentation area plan, the view template still showed the area color fill and boundary lines. The sharp fill shows through the gaps and the rounded corners. The user must choose: change the template (affects other views), duplicate the view, or use masking types.

Things that worked and could be reused: merge collinear boundary segments before filleting; cap the fillet tangent at half of each adjacent segment; offset with `CurveLoop.CreateViaOffset` and pick the sign by the loop area (outer shrinks, hole grows); for a plan view, lift the curves to the level elevation; set a type name with `DB.Element.Name.SetValue`.

## Proposed change

- Add a recipe (for example `am-area-diagram`, or a section in `am-area-report`) that makes a presentation diagram from areas: fill type by color-scheme value, rounded corners, optional gap, one detail group.
- In the recipe, check each boundary loop for gaps first. Report the open areas, and offer a trim/extend of the boundary lines as a separate, approved change.
- Add to the Revit 2026 notes: group only top-level element ids (not `UngroupMembers()` output); switch away from a view before you delete it; `FilledRegion` has no `IsValidBoundary`.
- Before the run, ask the user which view gets the diagram, and say that the area color fill of a template shows through `_TRN` types.

## Acceptance ideas

- A run on a level with an open area boundary lists that area and the gap size. It does not fail silently.
- Adding regions to an existing diagram group works on the first try.
- The recipe asks for the target view before it creates anything.

Not verified: I did not test whether `NewGroup` also crashes with other element types in the list, or only with sketch members.
