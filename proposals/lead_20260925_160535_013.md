## Goal
Make every developer machine and every CI workflow reliably green, so each feature PR gets a trustworthy signal. Most of this is setup and verification, plus small fixes wherever the first real CI runs fail.

## Developer machine (Windows 11)
- [ ] Turn on **Developer Mode** (Settings → System → For developers). Flutter plugins need symlinks.
- [ ] Turn on **Windows Hypervisor Platform** (Windows Features) for the Android emulator.
- [ ] Run `git config --global core.longpaths true`. Gradle paths get long, and `.claude/worktrees/...` paths are long too.
- [ ] Install Android Studio with `winget install Google.AndroidStudio`. In the SDK Manager install:
  - SDK Platform 36/37, Command-line Tools, Build-Tools, Platform-Tools, Emulator;
  - a Pixel AVD with an x86_64 image.
- [ ] Run `flutter doctor --android-licenses`. `flutter doctor -v` should then show a working Android toolchain; Visual Studio isn't needed.
- [ ] Optional: Docker Desktop, to smoke-test the image locally:
  ```
  docker build -t friends-backend:local backend
  FRIENDS_TAG=local docker compose -f deploy/docker-compose.yml up
  ```
- [ ] Run the local backend + app loop from the root README (`uv run uvicorn …`, then `flutter run -d chrome --web-port 5000 --dart-define-from-file=env/dev.json`) and check the health screen shows **API ok**.
