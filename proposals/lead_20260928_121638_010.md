## 2. Summary

We need a debug-only way to induce each crash kind in `example/`, and integration tests that crash, relaunch and assert the drain, because native capture cannot be trusted from unit tests alone.

Expected result:

> CI proves, on an Android emulator, that JVM, native and ANR crashes are drained exactly once; iOS is proven with fixtures plus a documented manual device run.

---

## 3. Intent

The real intention of this ticket is:

> Turn "we think native capture works" into evidence that fails loudly if a platform update breaks it.

---

## 4. Source of Truth

* Parent story; review [webank-mobile#791](https://github.com/ADORSYS-GIS/webank-mobile/issues/791#issuecomment-5867575580)

## 5. Current Behavior

* `example/lib/main.dart` wires the zone only; there are no integration tests.

Evidence:

* [example/lib/main.dart](https://github.com/vaam-apps/flutter-otel-zone/blob/58a420a82a0e8c7cfc51fccd39b02b39be8ed73b/example/lib/main.dart)

## 6. Expected Behavior

* `example/` has a platform channel `crash(kind)` in debug builds only: `jvm`, `native` (raise SIGSEGV), `anr` (block the main thread), `nsexception`.
* `integration_test/` crashes, relaunches via `adb`, and asserts `pending()` contents and no duplicates on the third launch.
