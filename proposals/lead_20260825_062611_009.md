## What OpenStrap actually is

Not a Whoop API client — it contains no OAuth or cloud code at all. It revives a **post-subscription Whoop 4.0 over BLE**: the phone drains the band's raw 1 Hz sensor stream via a reverse-engineered GATT service and computes recovery/strain/sleep on-device. Philosophy is close to ours: local-first, hand-written zero-dependency parsers, returns nothing rather than guessing.

## Knowledge absorbed (no code taken)

Applied in `lib/whoop-metrics.js` — commit `f2bbc7b`:

- **Verbatim CSV headers** for `physiological_cycles.csv`, `sleeps.csv`, `workouts.csv`, `journal_entries.csv`, cross-corroborated from a real Feb-2024 export and an independent importer's alias lists.
- **A cycle runs sleep-onset to sleep-onset**, so `Cycle start time` is when you fell asleep — usually the previous calendar evening. Rows must be dated by `Wake onset`; dating by cycle start shifts every recovery score a day early. This was a live bug in our parser.
- **Energy units come from the header, never magnitude.** Some exports write kJ. A magnitude heuristic rewrites a genuine 4,500 kcal day as 1,076.
- **Timestamps are naive local wall-clock**, with the offset in a separate `Cycle timezone` column (`UTC-05:00`).
- **Naps are ordinary rows** in `sleeps.csv` with a `Nap` flag and earn no recovery; they must not displace the night.
- **Sleep arithmetic identities** — `light + deep + REM = asleep`, `asleep + awake = in bed` — are a far stronger column check than range tests, and are asserted in our tests.

## Whoop API v2, if we ever go that way

Architectural decision tracked in #14. Recorded so it does not need re-researching:

Base `https://api.prod.whoop.com/developer`, paths `v2/cycle`, `v2/recovery`, `v2/activity/sleep`, `v2/activity/workout`. OAuth2 authorization-code; the user registers their own app for a client id/secret. Scopes: `read:profile`, `read:body_measurement`, `read:cycles`, `read:recovery`, `read:sleep`, `read:workout`, and **`offline` — without it there is no refresh token**. Each refresh rotates and invalidates the previous pair, so the Node API must persist the new token atomically or the user is silently logged out. Limits 100 req/min, 10,000/day. Durations are `_milli`, energy is `kilojoule` (the CSV's is kcal), HRV is `hrv_rmssd_milli`. `score_state` is `SCORED` / `PENDING_SCORE` / `UNSCORABLE` and the `score` object only exists when `SCORED`; `user_calibrating` marks untrustworthy early recoveries.

## Deliberately not done
