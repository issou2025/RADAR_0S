## Project Understanding
You need assistance with: 
**fix(pond): `pond disconnect` loses a running daemon's record when `ps` cannot run**

*Project description:*
## Summary

`crabbox pond disconnect <name>` validates each recorded daemon with `ps` before stopping it. When `ps` cannot run, the command reports that the pond has no recorded daemons, deletes `daemon.json`, and leaves the forward running. The report is false, and Crabbox no longer has any record for stopping that process.

## Runtime or environment

Crabbox `main` at `fc7e659c2d3067e16959514c165e0311112bc625` and release v0.82.0 (`6f685f3209bcb64d3d312acc763f43ec858d1c3d`), both built from source with Go 1.27.3 and run on macOS arm64. `internal/cli/pond_mesh.go`, `internal/cli/pond_mesh_daemon.go` and both pond docs pages are identical in the two builds. Both tested builds gave the same results. Line numbers refer to the `main` build. No provider credentials, real SSH server or real lease were involved.

func pondCLI(t *testing.T, args ...string) string {
	t.Helper()
	var stdout, stderr bytes.Buffer
	if err := (App{Stdout: &stdout, Stderr: &stderr}).Run(context.Background(), args); err != nil {

func pondFile(home, name string) string {
	data, _ := os.ReadFile(filepath.Join(home, ".crabbox", "pond", "alpha", name))
	return string(data)
}

func pondDaemon(t *testing.T, home string) (pid, port int) {
	t.Helper()
	var state pondMeshDaemonState
	if err := json.Unmarshal([]byte(pondFile(home, "daemon.json")), &state); err != nil {
		t.Fatal(err)
	}
	return state.PIDs[0], state.Forwards[0].LocalPort
}

func pondDial(port int) bool {
	c, err := net.DialTimeout("tcp", fmt.Sprintf("127.0.0.1:%d", port), time.Second)
	if err != nil {
		return false
	}
	c.Close()
	return true
}

func pondWait(port int) {
	for i := 0; i < 50 && !pondDial(port); i++ {
		time.Sleep(100 * time.Millisecond)
	}
}

func TestPondDisconnectWithoutPS(t *testing.T) {
	home := pondSetup(t)
	pondCLI(t, "pond", "connect", "alpha", "--provider", "forward-boundary", "--export")
	pid, port := pondDaemon(t, home)
	pondWait(port)
	t.Cleanup(func() { _ = syscall.Kill(pid, syscall.SIGKILL) })

	path := os.Getenv("PATH")
	t.Setenv("PATH", t.TempDir()) // an empty directory: ps cannot be found
	var stdout, stderr bytes.Buffer
	err := (App{Stdout: &stdout, Stderr: &stderr}).Run(context.Background(), []string{"pond", "disconnect", "alpha"})
	t.Setenv("PATH", path)
	time.Sleep(200 * time.Millisecond)

	alive := syscall.Kill(pid, 0) == nil
	record := pondFile(home, "daemon.json") != ""
	t.Logf("disconnect: err=%v stdout=%q", err, stdout.String())
	t.Logf("pid alive=%v port %d accepts=%v daemon.json present=%v", alive, port, pondDial(port), record)
	// Passing outcomes: the daemon was stopped and reported, or the failure is visible and the record kept.
	if alive && (err == nil || !record) {
		t.Error("disconnect succeeded or dropped the record while the recorded daemon is still running")
	}
	if !alive && !bytes.Contains(stdout.Bytes(), []byte("disconnected 1")) {
		t.Error("disconnect stopped the daemon without reporting it")
	}
}

// A re-run of --export goes through the same stop path, with only the stub ssh on PATH.
func TestPondExportRerunWithoutPS(t *testing.T) {
	home := pondSetup(t)
	connect := []string{"pond", "connect", "alpha", "--provider", "forward-boundary", "--export"}
	pondCLI(t, connect...)
	firstPID, firstPort := pondDaemon(t, home)
	pondWait(firstPort)
	t.Cleanup(func() { _ = syscall.Kill(firstPID, syscall.SIGKILL) })

	path := os.Getenv("PATH")
	t.Setenv("PATH", filepath.SplitList(path)[0])
	err := (App{Stdout: &bytes.Buffer{}, Stderr: &bytes.Buffer{}}).Run(context.Background(), connect)
	t.Setenv("PATH", path)
	if err != nil { // a visible failure passes when the record of the first daemon is kept
		if pid, _ := pondDaemon(t, home); pid != firstPID {
			t.Errorf("--export failed (%v) and no longer records daemon %d", err, firstPID)
		}
		return
	}
	secondPID, secondPort := pondDaemon(t, home)
	pondWait(secondPort)
	t.Cleanup(func() { _ = syscall.Kill(secondPID, syscall.SIGKILL) })

	t.Logf("first pid alive=%v port %d accepts=%v", syscall.Kill(firstPID, 0) == nil, firstPort, pondDial(firstPort))
	t.Logf("second pid alive=%v port %d accepts=%v", syscall.Kill(secondPID, 0) == nil, secondPort, pondDial(secondPort))
	if secondPID != firstPID && syscall.Kill(firstPID, 0) == nil {
		t.Error("the replaced daemon is still running and no record of it remains")
	}
}

## Expected behavior

`docs/commands/pond.md:199-203` says `pond disconnect` "validates each recorded process" and "reports how many daemons it stopped, or that none were recorded". A record exists here and its process is alive. Being unable to validate it should be visible as a failure rather than reported as no record, and the record should remain until the process has been stopped or shown to be gone.

## Restoration check

Failing result: with `ps` unable to run and a recorded daemon alive, `pond disconnect` exits successfully saying none were recorded, `daemon.json` is gone and the port still accepts connections, and a re-run of `--export` leaves the replaced daemon running with no record. Passing result: the same input either stops the daemon and reports it, or fails visibly and keeps `daemon.json`, and a re-run of `--export` may also keep the recorded daemon with its record; the embedded tests accept these outcomes. Controls: a recorded PID that has exited is still cleaned up, and a live PID whose command line no longer matches its recorded forward is still never signaled, because that check protects against PID reuse. The embedded tests do not exercise these two controls.

## Triage assessment

- Impact level: P2
- Assessment status: supported
- Impact basis: A forward keeps running after a successful-looking disconnect, and its record is deleted. This is limited to macOS or Linux operator hosts where `ps` cannot run, which slim container images make reachable and a normal desktop install does not. A leftover tunnel holds a loopback port and an SSH connection. How common such hosts are is unknown.
- Workaround status: available
- Workaround basis: Install `ps` before disconnecting; the control shows disconnect works when it is available. Otherwise read the PIDs from the pond's `daemon.json` before disconnecting or re-running `--export` and signal them directly, after confirming the process is still that forward, for example through `/proc/<pid>/cmdline` on Linux, because this route skips the check against PID reuse. This second route was not run. Once `pond disconnect` has run, the record is gone and only a search for the listener on the port remains.
