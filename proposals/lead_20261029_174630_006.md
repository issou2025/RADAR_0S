# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[iOS] Flutter content painted after a non-rect-clipped platform view disappears when another platform view covers the background canvas**

*Project description:*
### Steps to reproduce

This needs two platform views on screen at the same time, one of them behind everything.

1. Build a `Stack` on iOS with, in this order:
   - a full-screen platform view (in my case a native map, but any `UiKitView` should do),
   - some Flutter widgets,
   - a second, smaller platform view wrapped in a `ClipRRect`,
   - more Flutter widgets after it: in the sample, an "INFO CARD" and a "MENU" bar at the bottom.
2. Run on a physical iPhone (iOS 27.0.1 here, but I first hit this on iOS 18 too).
3. Look at the widgets that come after the second platform view.
4. Change the `ClipRRect` around the second platform view to a plain `ClipRect`, nothing else, and look again.

The sample below has buttons to switch between `ClipRRect`, `ClipRect` and no clip at all, so you can flip between the broken and working state without rebuilding.

I should say up front: this reproduces in both debug and release, and it is not specific to maps. What matters is that the clip is non-rectangular and that something else covers the background canvas.

### Expected results

Every Flutter widget is visible, whether the second platform view is clipped with a rounded rect or not. The clip should only affect the platform view it wraps.

### Actual results

With the `ClipRRect`, the "INFO CARD" and the "MENU" are **not drawn at all**. The layout is fine (the space is allocated, the page still scrolls) and they are **still hit-testable**: I can tap the menu and it reacts, I just cannot see it. The widgets painted *before* the second platform view stay visible.

Switch that one `ClipRRect` to a `ClipRect`, same geometry, and both come back immediately.

What made this hard to find is that it looks like a "two platform views" problem. It isn't: two platform views with rectangular clips are fine, and one platform view with a rounded clip is fine too. You need both at once.

## What I think is happening

I went digging in the engine and I think the two halves line up, though I have not instrumented a build to confirm which one actually drops the pixels.

In `shell/platform/darwin/ios/framework/Source/FlutterPlatformViewsController.mm`, `HasNonRectClipForUnderlayCutout` returns true for `kClipRRect`, `kClipRSE` and `kClipPath` (`kClipRect` falls through to `default`). The view then goes into `viewsWithUnderlayPreserved`.

In `flow/view_slicer.cc`, when `preserve_underlay` is true, this is skipped:

```cpp
if (!preserve_underlay) {
  background_canvas->ClipRect(full_joined_rect, DlClipOp::kDifference);
}
```

and the slice is rendered into the background canvas as usual. Meanwhile the overlay for that view *is* created, but `ApplyNonRectClipToOverlayCanvas` intersects it with the rounded shape:

```cpp
overlay_canvas->ClipRoundRect((*iter)->GetRRect(), flutter::DlClipOp::kIntersect, true);
```

So the content ends up in exactly one place, the background canvas, and the background canvas sits below every platform view in the `FlutterView` hierarchy. In my case the full-screen map is opaque and covers it, so the content is simply never seen.

The comment above `ApplyNonRectClipToOverlayCanvas` states the assumption out loud:

> Overlay canvas needs to be clipped to the shape of platform view to ensure underlay shows up correctly, so that when there's backdrop filter, the region outside of platform view's shape is blurred. See: https://github.com/flutter/flutter/issues/150660

That assumption, that the underlay is visible, is the thing that breaks. It holds for a single platform view. It does not hold when another platform view, earlier in the composition order, covers the area.

One detail that matched the theory nicely: with **two** non-rect clips in the mutator stack (one around the small platform view, one around the panel containing it), the overlay was intersected with both and almost nothing survived. Removing the inner one brought back the widgets that were inside the outer clip's rounded rect, and only the widget *outside* it, the bottom menu, stayed invisible. That is what the intersect would predict.

## Possible fix

Only preserve the underlay when it can actually be seen: when filling `viewsWithUnderlayPreserved`, skip a view whose `finalBoundingRect` is covered by a platform view earlier in `compositionOrder`. In that case the normal `kDifference` path is the correct one. I have not tried patching the engine, so I may well be missing a reason this is harder than it looks.

As far as I can tell nothing documents a limit on overlapping platform views. `createMissingOverlays:`, the `OverlayLayerPool` and `SliceViews` are all written for an arbitrary number of them, so I filed this as a bug rather than a limitation. Apologies if I missed an existing issue; I searched but the symptom is hard to phrase.

### Code sample


<details>
<summary>main.dart</summary>

```dart
// Repro for the iOS overlay bug: Flutter widgets painted after a second, non-rect-clipped
// platform view vanish when a first platform view covers the background canvas.
//
// pubspec.yaml needs one dependency for the platform views:
//   flutter_unified_map: ^1.0.0
// On iOS it uses MapKit, so no API key is needed. Any UiKitView should do the same.
//
// Run with: flutter run  (debug and release both reproduce)
//
// With clip = rrect: the INFO CARD and the bottom MENU are invisible, but still tappable.
// Tap "rect" (same geometry, rectangular mutator only) and both come back.
// The controls at the top are painted BEFORE the mini map, so they stay visible either way.
import 'package:flutter/material.dart';
import 'package:flutter_unified_map/flutter_unified_map.dart';

void main() => runApp(const ReproApp());

enum MiniClip { rrect, rect, none }

class ReproApp extends StatelessWidget {
  const ReproApp({super.key});

  @override
  Widget build(BuildContext context) =>
      const MaterialApp(debugShowCheckedModeBanner: false, home: ReproPage());
}

class ReproPage extends StatefulWidget {
  const ReproPage({super.key});

  @override
  State<ReproPage> createState() => _ReproPageState();
}

class _ReproPageState extends State<ReproPage> {
  MiniClip _clip = MiniClip.rrect;
  bool _showMini = true;

  Widget _mini() {
    final mini = SizedBox(
      width: 160,
      height: 160,
      child: UnifiedMap(
        options: MapOptions(initialCenter: const LatLng(45.76, 4.84), initialZoom: 11),
        children: const [],
      ),
    );
    return switch (_clip) {
      MiniClip.rrect => ClipRRect(borderRadius: BorderRadius.circular(24), child: mini),
      MiniClip.rect => ClipRect(child: mini),
      MiniClip.none => mini,
    };
  }

  @override
  Widget build(BuildContext context) => Scaffold(
    body: Stack(
      children: [
        // Platform view 0: fullscreen map. It covers the background canvas.
        Positioned.fill(
          child: UnifiedMap(
            options: MapOptions(initialCenter: const LatLng(48.5, 9.0), initialZoom: 5),
            children: const [],
          ),
        ),
        // Controls: painted BEFORE the mini map, so they belong to slices[pv0] and stay visible.
        Positioned(
          left: 8,
          top: 48,
          child: Material(
            color: Colors.black87,
            borderRadius: BorderRadius.circular(8),
            child: Row(
              children: [
                for (final clip in MiniClip.values)
                  TextButton(
                    onPressed: () => setState(() => _clip = clip),
                    child: Text(
                      clip.name,
                      style: TextStyle(
                        color: _clip == clip ? Colors.greenAccent : Colors.white70,
                        fontWeight: _clip == clip ? FontWeight.bold : FontWeight.normal,
                      ),
                    ),
                  ),
                TextButton(
                  onPressed: () => setState(() => _showMini = !_showMini),
                  child: Text(
                    _showMini ? 'hide mini' : 'show mini',
                    style: const TextStyle(color: Colors.white70),
                  ),
                ),
              ],
            ),
          ),
        ),
        // Platform view 1: the mini map.
        if (_showMini) Positioned(top: 120, right: 16, child: _mini()),
        // Flutter content painted AFTER platform view 1 -> lands in slices[pv1].
        Positioned(
          left: 16,
          right: 16,
          bottom: 100,
          child: Card(
            color: Colors.white,
            child: Padding(
              padding: const EdgeInsets.all(16),
              child: Text('INFO CARD', style: Theme.of(context).textTheme.titleLarge),
            ),
          ),
        ),
        Positioned(
          left: 0,
          right: 0,
          bottom: 0,
          child: Container(
            height: 84,
            color: Colors.deepPurple,
            alignment: Alignment.center,
            child: const Text(
              'MENU',
              style: TextStyle(color: Colors.white, fontSize: 24, fontWeight: FontWeight.bold),
            ),
          ),
        ),
      ],
    ),
  );
}
```
