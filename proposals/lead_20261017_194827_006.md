### Exact source inventory (no guessing from v11)

The Android app resolves `flutter_secure_storage 10.3.4`; all four identified credential clients instantiate `FlutterSecureStorage()` without custom `AndroidOptions`. The upstream **signed tag `v10.3.4`** resolves to source commit `692a374a5071c0b60939f624ede58d666b6b645c`. The pinned v11.2.0 commit is `e8eeb449cd512b26153f0a3376dfe374dd39a999`.

Both pinned Java sources support the same four **default** SharedPreferences filenames: `FlutterSecureStorage.xml`, `FlutterSecureKeyStorage.xml`, `FlutterSecureStorageConfiguration.xml` and `FlutterSecureStorageConfiguration:FlutterSecureStorage.xml`. This source-level match does NOT prove all historical installations use defaults; runtime file enumeration and earlier legacy-backend handling remain to be checked.

Both Dart versions have `AndroidOptions.resetOnError=true` by default. v10.3.4 can still migrate deprecated EncryptedSharedPreferences; v11.2.0 removes that legacy backend, so **do not upgrade** based on backup XML checks alone.
