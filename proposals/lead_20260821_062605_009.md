# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**iPhone: build and ship the Flutter app on iOS**

*Project description:*
The app ships on Android from `app/flutter/`. The same code runs on iPhone: the
screens, sync, encryption and the `ais://` deep link are written and iOS-aware.
Two things are missing: the C engine compiled into the iOS binary, and signing.

Flutter draws its own widgets, so the iOS screens are the Android screens. No
UIKit or SwiftUI work, and no Dart, Swift or Objective-C source changes. The
tree has no Objective-C; the two native files in `app/flutter/ios/Runner/` are
Swift and are written.

## Already in the repo

`app/flutter/ios/` is the Flutter scaffold, bundle id `com.aisindex.ais`, the
same as Android.

- `Runner/SceneDelegate.swift`: the `ais/deeplink` channel, delivering an
  `ais://sync?…` pairing link live and at cold start.
- `Runner/AppDelegate.swift`: `ais/backup`, which sets
  `NSURLIsExcludedFromBackupKey` on the index directory (iOS backs up Documents
  to iCloud by default), and `ais/screen`, which holds the screen awake while a
  pairing QR is shown.
- `Runner/Info.plist`: the `ais` URL scheme, microphone and speech usage
  strings. Voice search uses Apple Speech through the same plugin as Android.

## The task: engine into the Runner target

The engine is statically linked on iOS. `lib/ais_ffi.dart` loads it with
`DynamicLibrary.process()`, not from a `.so` or `.dylib`, so the C symbols have
to be inside the app binary.

The Runner target needs:

- every `c/*.c` and `c/crypto/*.c` except `main.c` in Compile Sources (a library
  has no `main`),
- `$(SRCROOT)/../../../c` on Header Search Paths,
- C dialect `c99`,
- default symbol visibility, which is what lets `DynamicLibrary.process()`
  resolve the symbols.

A podspec listing the same sources and header path, referenced from
`ios/Podfile`, is equivalent and is plain text rather than Xcode project state.

The file list has one source of truth: `app/flutter/src/CMakeLists.txt`, the
build Android and Linux use. A hand-maintained second list drifts from it.

`c/crypto/` (`ais_crypto.c` and the vendored `monocypher.c`) is not optional.
Left out, the app builds and launches, then fails with an undefined `aisc_*`
symbol the first time a secret is encrypted or revealed.

## Running

    cd app/flutter && flutter pub get
    flutter run -d <simulator-id>     # no Apple account needed
    flutter run -d <device-id>        # needs signing

Encrypt followed by Reveal is what proves the crypto sources linked.

## Signing

- Personal device, free Apple ID: a personal team under Xcode > Settings >
  Accounts, with Automatically manage signing on the Runner target. Builds
  expire after 7 days.
- TestFlight: paid Developer Program. App record in App Store Connect under the
  same bundle id, then Product > Archive or an uploaded `.ipa`. Builds last 90
  days.
- App Store: the same upload plus the review submission.
- Export compliance: the app carries non-Apple cryptography (vendored
  Monocypher, XChaCha20-Poly1305) for on-device secrets and LAN sync. The App
  Store Connect questionnaire covers it; unanswered, it blocks distribution.

Release builds take their version from the git tag:

    flutter build ipa --release $(sh tool/version.sh)

A flagless build stamps the stale fallback in `pubspec.yaml`, which
`doc/dev/VERSIONING.md` treats as unusable.

## Done when, on a physical iPhone

- a record saved with tags recalls by tag, appears under Recent, survives a tag
  edit, and a delete of it can be undone
- a secret encrypted with a passphrase reveals with it
- a multi-line note stores as a document file and reads back in full
- sync converges both ways: with `./ais --sync --serve` on another machine, the
  phone's Sync & backup > Join crosses records in both directions, and hosting
  from the phone with a join from the other machine does the same
- an `ais://sync?host=…&token=…` link opened from the browser or the camera
  brings up the app with Join prefilled and asks before syncing
- voice search prompts once, then transcribes
- records survive a force-quit, with no iCloud-exclusion warning in the console

## Known traps

- An undefined `aisc_*` symbol on the first encrypt or reveal means a
  `c/crypto/*.c` file is missing from the target. The no-undefined-crypto
  assertion in `app/flutter/src/CMakeLists.txt` names the files.
- An engine built as a separate framework has to be linked into the final
  binary. `DynamicLibrary.process()` resolves nothing from an unlinked one.
- Same engine sources, same `embed.h` seam, index in the documents directory. An
  iOS-only variation breaks sync with the user's other devices.

Optional later: Siri Shortcuts, so "Hey Siri, ask AIS to recall …" reaches
`recall()` through the same seam.
