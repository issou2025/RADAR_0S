## Development workflow safety

The repository currently reports `main` as unprotected with required status checks disabled. With multiple autonomous development lanes running in parallel, this leaves room for an accidental merge before the full merge gate is green.

### Goal
Protect `main` so normal merges require the authoritative CI gate while preserving the current fast parallel workflow.

### Suggested repository settings
- require a pull request before merging;
- require the stable aggregate/authoritative Flutter CI checks before merge;
- require branches to be up to date only if the added re-run churn is acceptable for this fast-moving repository;
- allow auto-merge so a reviewed/approved PR can merge automatically once required checks turn green;
- do not require manual review if that would unnecessarily block this single-owner autonomous-lane workflow, unless desired separately.

### Important sequencing
Finalize the CI check topology first (including #976 and the planned docs-only fast path) so branch protection points at stable check names rather than transient shard-count-specific names.

This is primarily a repository-settings task; the connected GitHub App may not have the administration permission needed to apply branch protection directly.
