# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[ADR] Deliver mobile as an installable web app (PWA) from one TypeScript codebase**

*Project description:*
**What problem or decision does this ADR address?**
The app is a Streamlit web app, which renders on a Python server and cannot run on iOS. Using it on a phone is awkward: the page is built for desktop, is mostly spreadsheet-style grids, and the Community Cloud deployment sleeps unless a keep-awake workflow visits it. The goal is a good phone experience, especially for Quick Expenses, and ideally a single codebase for phone and desktop, all on free tiers.

Options considered:
- a native SwiftUI app alongside Streamlit
- one codebase in Expo / React Native, Flutter or Flet
- a web app wrapped in a native shell with Capacitor
- an installable web app (PWA) built from one codebase

Proposed decision: **replace the Streamlit UI with an Expo (React Native) app in TypeScript, published only as a static web app that can be installed from Safari (a PWA).** Supabase stays as the backend. The Apple Developer Program ($99/year) is not needed. Because Expo can also build native iOS apps from the same code, a native app stays possible later without a rewrite.

**What tools or sources were used?**
- A review of this codebase:
  - the domain, use-case and port layers have no Streamlit imports (~2.9k lines)
  - much of the maths already lives in Postgres views
  - the UI layer (~5k lines) is tied to Streamlit, especially the `st.data_editor` grids
  - authentication signs its own Supabase tokens with the JWT secret on the server, in `SupabaseAuthenticator`
- The free tiers and platform limits of Supabase, Auth0, Expo/EAS, static hosts (Cloudflare Pages, Netlify, Vercel, GitHub Pages) and the Apple Developer Program
- What iOS allows installed web apps to do: installing from Safari, standalone display, and push notifications since iOS 16.4

**Consequences and follow-up**
- The UI is rewritten and the domain and use-case logic is ported from Python/pydantic to TypeScript/zod. Rules that every client must agree on move into Postgres views and functions where they can.
- Authentication moves to Supabase's built-in Auth0 support (the browser holds only the public anon key and the user's Auth0 token), and `public.user_id()` is adjusted to match. This is a prerequisite and worth doing on its own.
- Grids are redesigned for mobile rather than ported one to one.
- Everything stays on free tiers. Static hosting removes the need for `ops/keep_awake.py`. The Supabase free-tier pause after about a week of inactivity still applies.
- No home-screen widgets, Siri Shortcuts or App Store listing. Those return as options if the $99/year is ever worth paying.
- Phased plan: authentication → Quick Expenses as the first PWA screen → the remaining screens → retire Streamlit.
