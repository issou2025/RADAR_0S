# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Add closed command-signature authority for the patch publisher**

*Project description:*
## Origin

Architecture/decomposition action from #177 and PR #195 after exact-head
Copilot review proved that substring-based shell analysis cannot exclude an
alternate cgroup membership reader whose filename is composed inside an
arbitrary program.

## Classification

**Framework capability: closed trusted-shell command authority.**

Accept one typed, default-deny command/signature registry shared by the
workflow-pilot shell parser, recursive helper analysis, and publisher
validators. This is a complete foundation contract, not another publisher
path blacklist.

## Relationships

- **Parent initiative:** #177.
- **Immediate base:** current `master`; independent root.
- **Dependencies:** existing workflow-pilot shell command/control parser and
  exact-tree publisher validators.
- **Dependents:** the publisher phase-machine sub-issue and the final #177
  publisher fix-forward.
- **Conflicts:** PR #195 touches the same validator and tests and remains
  blocked until this contract and its dependent phase contract merge.

## Scope

1. Define one typed signature model for reviewed executables and helpers,
   normalized wrappers/control prefixes, exact argument forms, permitted
   inputs/outputs, security-relevant resource accesses, and emitted semantic
   events.
2. Default-deny unknown executables, interpreters, helper functions, dynamic
   executable paths, aliases, command substitutions, code strings, and
   unmatched argument structures.
3. Represent every production builder command and all reviewed Python
   invocations explicitly. Authorize the isolated membership checker only by
   its exact executable, program, arguments, inputs, outputs, and semantic
   event.
4. Make main-command and recursive-helper analysis consume the same registry.
   Do not retain a second permissive parser, substring fallback, or filename
   marker list as authority.
5. Bind the registry and every consumed parser/helper module to the immutable
   exact tree used for validation.
6. Provide positive, adversarial, mutation, deletion, and drift tests for each
   signature family and for registry completeness.

## Non-goals

- No candidate-launch/export ordering policy; the dependent phase-machine
  issue owns ordering.
- No change to Build topology, triggers, required contexts, publication
  artifacts, gameplay, ROM, save, localization, generated game data, or the
  archival lane.
- No project-selectable flag and no manually curated exception for arbitrary
  program text.

## Acceptance criteria

- Composed Python, shell, awk, Perl, helper, and split-string membership reads
  fail even when no literal `cgroup.procs` token exists.
- Unknown or dynamic commands, helpers, wrappers, paths, arguments, redirects,
  callbacks, traps, and interpreter programs fail closed.
- The exact production publisher builder remains accepted.
- The one fixed membership checker is accepted only under its exact reviewed
  signature; any executable, code, argument, path, cardinality, or output
  mutation fails.
- Recursive helpers cannot recombine safe-looking argument fragments into an
  unauthorized access.
- Both semantic-validator suites consume the same typed inventory and produce
  identical decisions.
- Adding, removing, or redirecting a production command fails until its
  signature and behavioral evidence are updated.
- Exact-head Build, Copilot review, security checks, and the resulting
  exact-master Build pass.
