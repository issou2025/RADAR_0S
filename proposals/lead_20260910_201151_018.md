# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**apus: webhook signature verification fails OPEN when the secret is unset, and the handler it gates rewrites agent and skill definitions**

*Project description:*
## The defect

`execution/daemons/apus/apus.py:401-407`

```python
def _verify_signature(body: bytes, sig_header: str) -> bool:
    """Verify HMAC-SHA256 webhook signature."""
    if not WEBHOOK_SECRET or not sig_header:
        return not bool(WEBHOOK_SECRET)  # if no secret configured, allow all
```

When `APUS_WEBHOOK_SECRET` is unset, every request verifies. The comment states the behaviour outright, so this is a deliberate convenience that became a security posture.

## Why it is not a small default

The handler this gates writes POSTed file content to disk under `.claude/agents/`, `.claude/skills/`, and `docs/`, then commits and pushes as the swarm's git identity. `.claude/agents/` and `.claude/skills/` are the definitions that govern how every other agent in the swarm reasons and acts.

So an unset environment variable is a path to rewriting the swarm's own instructions, landing under an authenticated-looking commit. The blast radius is not "one daemon accepts junk" — it is the prompt corpus the rest of the fleet loads.

## The same repo already does this correctly

`execution/daemons/apis/github_gateway.py` verifies an HMAC on the same primitive and **fails closed** on a missing secret. Two webhook verifiers, one codebase, opposite polarity. The correct one is already written and can be followed directly.

## Design basis

This contradicts invariant 5, fail closed on the safety field, stated in `docs/foundation/failure_posture.md`. Admission is the safety field here: a request is either admitted or it is not, and the unknown case must not resolve to admitted. It also sits against invariant 7 — an absent secret is *unknown configuration*, and the code converts that unknown directly into the conclusion "allow".

## Remedy

Return `False` when `WEBHOOK_SECRET` is unset, and refuse to start the listener at all when the variable is missing — a webhook server that cannot authenticate its callers should not bind a port. Failing at startup makes the misconfiguration loud instead of silent, which is the difference between a caught deployment error and an open door nobody notices.

## Scope

This is one branch in one function plus a startup check. It does not depend on the grant-enforcement work and can land independently.

Found 2026-09-10 during the foundation rollout's ambient-capability inventory (phase A2).

### Design basis

Design basis: docs/foundation/principles.md#fail-closed-on-the-field-that-carries-the-safety-meaning — webhook admission is the safety field; missing secret, missing signature, malformed signature, or HMAC mismatch must resolve to reject, not permit.

### Product / Scope (PM)

**Problem**
Apus currently admits Neotoma mirror webhook requests when `APUS_WEBHOOK_SECRET` is unset, even though an admitted request can rewrite swarm agent, skill, and docs sources and then commit/push those changes under the swarm identity.

**In scope**
- Change Apus webhook admission to fail closed when the secret is unset/empty, the signature header is absent or malformed, or the HMAC does not match.
- Refuse to start/bind the Apus webhook listener when `APUS_WEBHOOK_SECRET` is missing, with an operationally loud error that does not log the secret value.
- Preserve the existing signed-delivery happy path and reuse the existing `execution/daemons/apis/github_gateway.py` fail-closed pattern where it fits.
- Add behavior-level tests for admission and startup refusal.

**Out of scope**
- Grant enforcement or authorization rules for which posted files may be rewritten.
- Redesigning the webhook payload, delivery-id semantics, mirror rebuild flow, commit/push flow, or shared webhook infrastructure.
- Changing generated agent/skill/doc content except as test fixtures require.

**Acceptance criteria**
- [ ] With `APUS_WEBHOOK_SECRET` unset or empty, Apus refuses to start the webhook listener; the test asserts the observable startup effect, not only a helper return value.
- [ ] With the secret unset/empty, a direct verifier/handler test proves webhook admission fails closed and no `.claude/agents/`, `.claude/skills/`, or `docs/` write, commit, or push side effect is attempted.
- [ ] With the secret set and the signature missing, malformed, or incorrect, the webhook POST is rejected and no write/commit/push side effect is attempted.
- [ ] With the secret set and a valid `X-Neotoma-Signature`, the existing accepted-delivery behavior still works aside from the authentication precondition.
- [ ] Tests include both restrictive and permitted branches and the PR records the revert-red result for the fail-closed behavior.
- [ ] All Apus webhook admission surfaces exercised by production are covered in their natural call shape; if implementation reveals an additional entrypoint beyond the verifier/aiohttp handler/startup path, parity coverage is added for it.

**Priority & sequencing**
Priority: immediate security posture repair before any further Apus mirror automation work. Sequence: arch review next for daemon/adaptor contract fit, then implementation, QA, security review. Confidence: high. Key assumption: no supported deployment intentionally accepts unsigned Apus webhook deliveries; deployments without a secret should configure one rather than rely on open admission.

**Open questions**
None blocking for implementation.

### Design / UX

**User goal**
Operator/deployer wants Apus to admit only authenticated Neotoma mirror webhook deliveries (so agent/skill/docs rewrites cannot land unsigned) and to fail loudly when authentication cannot be enforced — before a listener binds.

**Surfaces (keep names)**
- Env: `APUS_WEBHOOK_SECRET` (required; do not rename)
- Header: `X-Neotoma-Signature` (`sha256=<hex>`)
- Routes: `POST /webhook` (admission-gated); `/health` and `/rebuild` unchanged in auth model per PM scope (`/rebuild` remains operator/local — do not imply webhook secret covers it)

**Flow**
1. Startup loads env → if secret unset/empty → log error + exit non-zero → **do not** bind port / register routes.
2. Startup with secret set → bind as today.
3. `POST /webhook` → verify signature → admit or reject; reject must not attempt write/commit/push.
4. Valid signature → existing accepted-delivery behavior.

**Friction / abandonment (severity)**
| Point | Severity | Notes |
|---|---|---|
| Secret unset but process still “healthy” / bound | P0 | Current defect; remove by startup refusal |
| Reject with opaque body and no log of `delivery_id` | P1 | Operator cannot correlate Neotoma retries |
| Docs/`.env.example` still say secret is optional/recommended | P1 | Teaches fail-open mental model |
| HTTP body distinguishes missing vs wrong signature | P2 | Prefer same 401 text; details in logs only |
| Secret value appears in logs/errors | P0 | Forbidden |

**Error / empty contracts**
- **Startup (missing/empty secret):** exit before bind; stderr/log MUST include literal `APUS_WEBHOOK_SECRET`, that the webhook listener will not start, and a fix hint (set the var in the Apus env source — typically `~/.config/neotoma/.env` / launchd plist — to the same value as the Neotoma webhook subscription secret). MUST NOT log the secret value. Replace today’s warning (“verification disabled”).
- **Request — missing/malformed/incorrect signature (secret present):** HTTP **401**; body text aligned with Apis (`Signature mismatch` or equivalent short reject); log warning with `delivery_id`; no side effects.
- **Defense in depth:** if verifier is ever reached with empty secret, return reject (False / 401 or 503), never admit — but primary UX is startup refusal so this path is not the operator-visible steady state.
- **Happy path:** secret set + valid `X-Neotoma-Signature` → unchanged accepted-delivery UX aside from auth precondition.

**Docs / examples that must ship**
- `.env.example`: change Apus secret comment from “recommended” to **required**; blank value must not read as “optional open admission”.
- `execution/daemons/apus/apus.py` module env list: mark `APUS_WEBHOOK_SECRET` required for starting the webhook listener.
- `execution/daemons/apus/install.sh`: after install, print that `APUS_WEBHOOK_SECRET` must be set before the agent will stay up (or fail the install check if readable env is empty — prefer loud post-install note if env is outside install.sh’s control).
- Operator docs that mention Apus mirror setup (`docs/forking.md` mirror/cloud bullet; any Apus runbook that still implies optional HMAC): state secret is required and must match the Neotoma subscription.
- Do not invent new flag names or alternate env vars.

**Copy placeholders (Paradisaea)**
- Startup error line: `[COPY: apus refusing to start — APUS_WEBHOOK_SECRET unset; set it to the Neotoma webhook subscription secret]`
- Reject log line: `[COPY: signature verification failed for delivery <id>]` (keep delivery_id structured)

**Acceptance checklist (UX)**
- [ ] Unset/empty `APUS_WEBHOOK_SECRET` → process exits without binding the webhook listener (observable)
- [ ] Startup/error text names `APUS_WEBHOOK_SECRET` and a concrete fix action; secret value never logged
- [ ] Rejected `POST /webhook` returns 401-class reject and never writes under `.claude/agents/`, `.claude/skills/`, or `docs/`, nor commit/push
- [ ] `.env.example` + Apus env docstring no longer describe the secret as optional/recommended
- [ ] install/forking operator path mentions required secret before “live” claim
- [ ] No rename of `APUS_WEBHOOK_SECRET` / `X-Neotoma-Signature`

### Engineering

**Prior art to reuse (do not reinvent)**
- Admission polarity: `execution/daemons/apis/github_gateway.py` — unset secret rejects; `verify_github_signature` returns False on missing/malformed/`sha256=`-prefix failures; handler returns 401 `Signature mismatch`.
- Test shape: `execution/daemons/apis/test_github_gateway.py` (`test_unset_secret_rejects_delivery_fail_closed`, signature matrix, aiohttp `TestClient`).
- Startup refuse pattern: `lib/daemon_runtime/agent_loader.py` `enforce_status_or_exit` → `log.error` + `sys.exit(1)` before bind/dispatch.
- Keep Apus-local verifier (header is `X-Neotoma-Signature`, not `X-Hub-Signature-256`); copy polarity, do not extract a shared helper in this PR.

**Files / concrete changes**

1. `execution/daemons/apus/apus.py`
   - Module env list (~L34): mark `APUS_WEBHOOK_SECRET` **required** to start the webhook listener.
   - `_verify_signature` (~L402–409): delete fail-open (`return not bool(WEBHOOK_SECRET)`). Behavior:
     - empty/unset secret → `False`
     - missing/empty/`sig_header` not starting with `sha256=` → `False`
     - else constant-time HMAC-SHA256 compare (same `sha256=<hex>` form as today / Apis)
   - `handle_webhook` (~L168–178): remove the `if WEBHOOK_SECRET:` skip branch. Always `await request.read()`, always verify; on failure log warning with `delivery_id` and return `401` / `Signature mismatch`. Must not reach `_apply_and_commit` (or any write/commit/push) on reject.
   - Startup (~L477–506): replace warn-and-continue with refuse-to-start. Add `require_webhook_secret_or_exit()` (name flexible): if `WEBHOOK_SECRET` unset/empty → `log.error` naming literal `APUS_WEBHOOK_SECRET`, that the webhook listener will not start, and a fix hint (set it in the Apus env source — typically `~/.config/neotoma/.env` / launchd plist — to the Neotoma webhook subscription secret); **never** log the secret value; then `sys.exit(1)`. Call it in `main()` **after** status enforcement is fine, but **before** `web.Application()`, route registration, notifier “started”, or `TCPSite.start`.
   - `/health` and `/rebuild`: no auth-model change (per UX/PM).

2. `execution/daemons/apus/test_apus_webhook_auth.py` (**new** — no Apus tests exist)
   - Unit: `_verify_signature` — unset/empty secret → False; missing/malformed/wrong sig → False; valid → True (restrictive + permitted).
   - Handler (aiohttp TestClient, monkeypatch `WEBHOOK_SECRET` + stub `_apply_and_commit` / notifier): bad/missing/wrong signature → 401 and `_apply_and_commit` **not called**; defense-in-depth empty secret on handler path → reject, no side effect; valid signature → auth passes (stub commit returns fake sha → 200).
   - Startup effect: `require_webhook_secret_or_exit()` with empty secret → `SystemExit` non-zero **without** binding; with secret set → returns. Assert the exit/refuse effect, not only a helper bool.
   - PR body must record revert-red for the fail-closed cases on pre-fix main.

3. `.github/workflows/ateles-tests.yml`
   - Add `execution/daemons/apus/**` to `pull_request.paths` and a pytest step: `uv run --extra dev python -m pytest execution/daemons/apus/ -q` (same “tests committed but no lane” class as apis/anthus). Without this, effect tests never gate CI.

4. Docs / operator path (UX checklist)
   - `.env.example` (~L108–109): “(recommended)” → **required**; blank must not read as optional open admission (daemon refuses to start).
   - `execution/daemons/apus/install.sh`: after install, loud note that `APUS_WEBHOOK_SECRET` must be set before the agent will stay up (prefer note over failing install when env is outside script control); do not claim “live” without that caveat.
   - `docs/forking.md` (~L75 Mirror/cloud bullet): webhook secret is required and must match the Neotoma subscription.

**Data / contract**
- No entity schema, OpenAPI, or payload-shape changes.
- Env contract: `APUS_WEBHOOK_SECRET` hard-required for listener process liveness; names unchanged (`APUS_WEBHOOK_SECRET`, `X-Neotoma-Signature`).
