## Overview

As SATE AI expands beyond Flutter, the README and docs need to clearly communicate:

1. What the project architecture looks like across packages
2. Which platforms and languages are supported or planned
3. How someone can contribute a new language SDK
4. The project roadmap with milestones

Right now, the README describes SATE AI primarily as a Flutter package. This undersells the vision and discourages non-Flutter developers from exploring it.

---

## Changes Needed

### README.md

- Update the headline to reflect the broader vision, for example:
  **"Fault injection framework for on-device AI across Flutter, CLI, Android, Web, and more"**
- Add a **Platform Support** table showing current and planned SDKs:

  | Platform | Language | Status |
  |---|---|---|
  | Flutter | Dart | ✅ Available |
  | CLI (any OS) | Dart | ✅ Available |
  | Android Native | Kotlin | 🗺️ Planned |
  | Web / Node.js | TypeScript | 🗺️ Planned |
  | iOS Native | Swift | 🔭 Future |

- Add an **Architecture** section explaining the `sate_core` / `sate_ai` / `sate_cli` split
- Update the CI/CD section with the `dart pub global activate` example (no Flutter needed)

### CONTRIBUTING.md

- Add a section: **"Adding a New Language SDK"**
- Explain the pattern: implement `FaultInjector`, `StressRunner`, `StressReport`, and at least one `ModelAdapter` in the target language
- Link to the Kotlin and TypeScript issues (#121, #122) as reference implementations
