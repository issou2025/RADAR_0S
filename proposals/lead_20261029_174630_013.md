## Summary

Add automatic tag pagination to the Python library and command-line interface (CLI), using the pagination protocol in the Open Container Initiative (OCI) Distribution Specification.

The existing `list_tags()` operation and `regshape tag list` expose one-page requests through `page_size` / `--n` and `last` / `--last`. Add `list_tags_all()` and an opt-in `regshape tag list --all` that retrieve and aggregate all remaining pages. Keep the existing single-page behavior unchanged.

## Authoritative specification

Implement against the released [OCI Distribution Specification v1.1.1, Listing Tags](https://github.com/opencontainers/distribution-spec/blob/v1.1.1/spec.md#listing-tags), particularly endpoints `end-8a` and `end-8b`. [Release reference](https://github.com/opencontainers/distribution-spec/releases/tag/v1.1.1).

The following are protocol requirements or guidance from that specification, not new RegShape conventions:

1. Tags are retrieved with `GET /v2/<name>/tags/list`. A successful response for an existing repository is HTTP 200 with a tag-list object containing the repository name and tags. An empty repository may return an empty list.
2. The specification requires lexical ordering, described there as case-insensitive alphanumeric ordering. Preserve the received ordering and exact tag spelling when aggregating pages; do not lower-case or independently re-sort tags before selecting a continuation cursor.
3. `n` requests a number of tags: `/v2/<name>/tags/list?n=<int>`. The specification permits fewer than `n` results when the repository has fewer tags or a `Link` header is supplied; otherwise it requires `n` results. A short page alone is therefore not a sufficient end-of-list signal when a continuation link is present.
4. A registry **MAY** provide a continuation `Link` header when more tags are available. When provided, its syntax must follow [RFC 5988, Web Linking](https://www.rfc-editor.org/rfc/rfc5988.html), with relation `next`. The header is optional, so absence of `Link` must not by itself end a full-sized, cursor-paginated response.
5. `last` is an exclusive cursor containing a tag value, not a numerical offset: `/v2/<name>/tags/list?n=<int>&last=<tagname>`. That tag is excluded from the following page. A numeric-looking tag remains a tag value; do not interpret it as an offset.
6. `n` is optional when `last` is supplied.
7. With `n=0`, the registry must return an empty tag list and must not include a `Link` header.
8. The specification advises clients to prefer a supplied `Link` header over deriving pagination from `last`. This matters both for older registries that omit links and newer registries that use links to return shorter pages.

The specification defines the wire protocol. It does **not** mandate a CLI `--all` flag, a library helper, or a particular default page size; those are client conveniences.

## Required client behavior

- Add and export `list_tags_all()` using the existing authenticated `RegistryClient` and `TagList` model. Reuse the current tag operation, error handling, and telemetry patterns where appropriate; do not make a breaking change to `list_tags()`.
- Add `--all` to `regshape tag list`. Without it, preserve the current request count, flags, output, and pagination semantics.
- In all-pages mode, `--n` controls each requested page, not the total number of returned tags. If omitted, use a documented positive default page size (proposed: 100). This default is a RegShape policy, not an OCI requirement.
- Support an initial `last` / `--last` cursor: in combination with `--all`, retrieve all tags after that cursor, not the tags preceding it.
- Prefer a valid `rel="next"` link on every page, even when the page is shorter than requested or empty. Resolve relative links against the actual response URL, select the correct relation from headers containing multiple links, and preserve the linked path and query rather than rebuilding them from stale parameters.
- When a next link is absent and a positive page size was used, continue from the last returned tag after a full-sized page. Stop on a short or empty page without a next link. Handle exact multiples of the page size, which may require a final empty request.
- Use the effective page size of the current request when falling back to cursor pagination; a server-provided link may change it. Cover transitions between linked and cursor-only pages without losing tags or stopping early.
- As a RegShape input-validation policy, reject zero/negative page sizes for `list_tags_all()` and `--all` before network access. Do not remove existing single-page `--n 0` support: its OCI-defined empty result is not a request for all tags.
- Detect repeated continuation URLs, cursor cycles, or lack of pagination progress and report a clear error rather than hanging or returning an apparently complete partial result.
- Treat continuation links as untrusted input. Reuse transport safeguards where available; do not forward registry credentials to another origin or silently downgrade a secure connection. Reject unsafe links explicitly. These are client safety requirements, not additional OCI pagination clauses.
- Return one aggregated `TagList`, preserving the existing `{"name": ..., "tags": [...]}` shape. Keep `--json`, `--output`, authentication, `--insecure`, and telemetry behavior consistent with other commands.
- If a later page fails, propagate the repository-standard error. The CLI must exit nonzero without reporting success or emitting/writing an incomplete result as if it were the full list.

## Examples

```bash
# Fetch every tag, using the all-pages default
regshape tag list -i registry.example.com/team/image --all

# Fetch every remaining tag after v1.0, requesting 100 per page
regshape tag list -i registry.example.com/team/image --all --n 100 --last v1.0

# Save the aggregated response
regshape tag list -i registry.example.com/team/image --all --json -o tags.json
```

Successful JSON retains the existing shape, for example `{"name":"team/image","tags":["v1.0","v1.1","v2.0"]}`. Invalid all-pages page sizes should produce a usage error; later-page failures should produce the normal tag-operation error and a nonzero exit.
