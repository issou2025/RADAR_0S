### Describe the issue

Hi Pikafish team,

First of all, thank you for maintaining this amazing xiangqi engine.

I'm a Flutter developer integrating Pikafish into an Android app. My app bundles Pikafish as a native `.so` library (arm64-v8a) placed in `jniLibs/`, and it works perfectly on Android 14 and below.

However, starting with Android 15, Google introduced a requirement that all native libraries must be aligned to 16KB page size (instead of the traditional 4KB). Apps that ship 4KB-aligned `.so` files will fail to load them on devices with 16KB page size enabled.

I checked the latest release (Pikafish 2026-09-06), and the release notes didn't mention anything about 16KB page alignment. I inspected the provided `Pikafish-Android-arm64-universal` binary, and it appears to still be 4KB-aligned (ELF LOAD segment alignment = 0x1000).

Is there any plan to provide official 16KB-aligned Android binaries in future releases? Alternatively, could you share the recommended build flags (e.g., NDK version, linker flags) so that users can compile from source with proper alignment?

Reference: https://developer.android.com/guide/practices/page-sizes

Thank you!

### Expected behavior

The provided Android ARM64 binaries (e.g., `Pikafish-Android-arm64-universal`) should have ELF LOAD segments aligned to 16KB (0x4000), so that they can be loaded on Android 15+ devices that use 16KB memory pages.


### Steps to reproduce

1. Download the latest release (Pikafish 2026-09-06), Android arm64 binary.
2. Inspect the ELF program headers of `Pikafish-Android-arm64-universal`, e.g.:

   readelf -l Pikafish-Android-arm64-universal | grep LOAD

3. Observe that the LOAD segment alignment is 0x1000 (4KB), instead of 0x4000 (16KB).
4. Integrate the library into an Android app and submit to Google Play.
5. Google Play Console shows a warning that the app is not compatible with 16KB page size devices.

### Anything else?

This alignment requirement is documented here:
https://developer.android.com/guide/practices/page-sizes

Building with NDK r28+ should produce 16KB-aligned binaries by default.
