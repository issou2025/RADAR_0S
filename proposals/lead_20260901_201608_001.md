# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Load Document: .rvf offered in file filter but rejected; spurious 'file has changed' warning in release builds**

*Project description:*
Two small independent defects in `Load Document` (new in 1.36), both in `DocumentLoad.cs`.

**1. `.rvf` is offered in the file dialog and then rejected**

The component's own `Param_FilePath` filter advertises it (`DocumentLoad.cs:38`):

```csharp
FileFilter = "Files (*.rte, *.rvt, *.rfa, *.rvf, *.ifc, *.ifczip)|*.rte;*.rvt;*.rfa;*.rvf;*.ifc;*.ifczip"
```

but the accepted set omits `.rvf` (`:80`):

```csharp
static readonly ISet<string> FileExtensions = new HashSet<string>(PathExtension.Comparer){ ".rte", ".rvt", ".rfa", ".ifc", ".ifczip" };
```

So a file picked through the component's own browser fails with *"'.rvf' is not a supported extension."* The extension check runs before `File.Exists` (`:114-119`), so the path need not even resolve to see it.

Either add `.rvf` to `FileExtensions` (and a `LoadDocument` branch for it) or drop it from the filter.

**2. "File has changed" warning fires when the file has not changed**

The unchanged-file fast path sits inside `#if DEBUG` (`DocumentLoad.cs:157-163`):

```csharp
#if DEBUG
    if (File.GetLastWriteTimeUtc(uri) == document.File.LastWriteTimeUtc)
    {
      _currentDocs[uri] = document;
      return true;
    }
#endif

    if (load != true)
      AddRuntimeMessage(GH_RuntimeMessageLevel.Warning, $"File '{uri}' has changed since last time it was loaded.");
```

In a release build that early return is compiled out, so any re-solve served from `_cachedDocs` while `Load` is not currently `true` emits the warning regardless of the file's timestamp. The timestamp comparison only ever runs in debug builds.
