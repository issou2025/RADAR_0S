## Problem Statement

The **Worker Pool** runs **Revit Tests** with three operational limits that slow multi-agent development and risk premature test cancellation:

1. **Sequential Multi-Version Execution:** When a developer or agent runs **Revit Tests** across all **Revit Versions**, the test executor runs one **Revit Version** at a time. A single long fixture (~283–340 s) occupies one active **Standby Worker** while the remaining workers stay idle for ~3.5–4 minutes per **Revit Version** before the next **Revit Version** starts. A full 5-version sweep takes ~25+ minutes.
2. **Fragile Lifecycle Ownership:** When a coding agent command lazy-starts the **Worker Pool** supervisor, the supervisor inherits the shell command's Windows Job Object because `DETACHED_PROCESS` detaches only the console, not the Job Object. When that first command exits, the host harness closes the Job Object, terminates the supervisor, and kills all active **Standby Workers** serving other agents. In addition, an unguarded `drain` call immediately cancels active **Revit Tests** from sibling agents.
3. **Underutilized Workstation Capacity:** The **Worker Pool** caps resident workers at `4`. Each shimmed **Standby Worker** uses under `2 GiB` of RAM on a 64 GB RAM / 20-core workstation (~33.7 GB free during normal work), leaving significant concurrency unused while multi-version and multi-agent workloads queue.

## Solution

Deepen the **Worker Pool** **Module**, the test executor **Module**, and agent workflow skills across three coordinated areas so coding agents declare *what* to test while the tooling owns *how* to shard fixtures, parallelize **Revit Versions**, and manage **Standby Workers**:

1. **Parallel Multi-Version Execution and Makespan-Aware Sharding:** Run **Logic Tests** first in isolated subfolders, then execute all selected **Revit Versions** concurrently in **Worker Pool** mode with isolated per-version builds, pipelined dispatch, and hybrid per-version plus combined reporting. Partition each **Revit Version** into balanced fixture-level **Test Shards** using makespan-aware auto-sharding decoupled from the host worker ceiling.
2. **Detached Supervisor Ownership and Safe `drain`:** Launch the **Worker Pool** supervisor through a detached launch **Seam** using a per-user interactive Windows Scheduled Task **Adapter** (with `CREATE_BREAKAWAY_FROM_JOB` fallback) so the supervisor survives any command exit without flashing a console window. Protect active runs by making plain `drain` refuse while work is in flight, adding a distinct `DrainingWhenIdle` state (`drain --when-idle`) plus immediate zero-grace `drain --force`, and updating agent skills with positive prompting so coding agents run only the test executor.
3. **Safe 8–10 Worker Capacity Scaling:** Raise the default host-wide **Worker Pool** cap to `8` resident workers (configurable `1..10`), protect interactive Revit sessions with a **RAM admission guard** (`>= 10 GiB` free physical RAM minus `2 GiB` per booting worker above a guaranteed floor of `4` resident workers) and a concurrent cold-boot throttle (`MaxConcurrentBoots = 4` for ~2 smooth boot waves), and preserve the `+1` lookahead **Standby Worker** rule.

## Implementation Decisions

### 1. Detached Supervisor Launch Seam and Adapters
- Introduce an internal supervisor-launch **Seam** (`ISupervisorLauncher`) in the **Worker Pool** launching **Module** (consolidating duplicate process-launch P/Invokes and argument quoting, and replacing the ad-hoc spawn delegate) with a composite detached launcher evaluating two **Adapters** in priority order:
  1. **Per-User Interactive Scheduled Task Adapter (Primary for default production pipe):** Registers and updates a per-user Windows Scheduled Task (`Synthetic\RevitWorkerPoolSupervisor`) configured with `InteractiveToken` logon (Session 1, no elevation), `MultipleInstancesPolicy = Parallel`, battery restrictions disabled, and a hidden non-console bootstrap so launching `<OutputType>Exe</OutputType>` never flashes a console window or steals focus. Forwards resolved supervisor arguments (`--max-workers`, `--no-shim`, `--idle-ttl-minutes`, `--pipe-name`, `--project-root`) explicitly rather than relying on Task Scheduler environment inheritance. Registration lives solely in this C# **Adapter** (removed from the tooling build script so temporary worktree builds never skew the host task path).
  2. **Breakaway Process Adapter (Fallback, and primary for custom `--pipe-name` test supervisors):** Invokes `CreateProcessW` with `CREATE_BREAKAWAY_FROM_JOB | CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS | CREATE_UNICODE_ENVIRONMENT`. Checks Job Object breakaway failure (`ERROR_ACCESS_DENIED`) and fails closed without falling back to an attached launch.
- Fail closed with an aggregated diagnostic error if both detached **Adapters** fail.
- Keep lazy auto-start enabled for all callers because the detached **Adapter** isolates supervisor lifetime from caller command exit.
- Update the tooling build script to drain an idle supervisor safely (or fail with a clear diagnostic when tests are active) before removing output binaries.
- Honor each run's own `ProjectRoot` when launching workers so concurrent multi-worktree agents execute against their own repository root.
- Consolidate the duplicate diagnostic pipe client factory into the single primary pipe client factory **Adapter**.

### 2. Safe `drain` Interface, `DrainingWhenIdle` State, and Mode-Mismatch Guidance
- Extend the `drain` command **Interface** on the **Worker Pool** CLI and IPC protocol:
  - **Plain `drain`:** Refuses shutdown (`exitCode = 2`) and returns structured `activeRuns`, `queuedRuns`, and `activeWarmCalls` counts whenever in-flight runs (including runs inside plan preparation), active warm calls, queued shards, or active workers exist. Drains immediately when only idle `ReadyStandby` workers remain.
  - **`drain --when-idle`:** Transitions the supervisor into a distinct `DrainingWhenIdle` state (separate from terminal `Draining`) that: (a) lets in-flight runs and their already-queued **Test Shards** complete while halting `warm`, `StandbyTarget`, and `Lookahead` boots; (b) rejects newly arriving `run` and `warm` calls fail-closed with `"Supervisor is draining when idle; retry after drain completes or run --no-pool"`; (c) keeps the IPC server open for `status` and preempting `drain --force`; (d) stays latched even if the calling `drain --when-idle` client disconnects; and (e) prevents `EnsureSupervisorRunningAsync` from spawning a competing second supervisor on the same pipe while `DrainingWhenIdle` is active.
  - **`drain --force`:** Cancels in-flight runs immediately with **zero grace wait**, terminates all workers cleanly, releases the bundle lease, and exits. Supervisor disposal (`DisposeAsync`) also invokes force-drain explicitly.
- Update the `--no-shim` / shimmed mode mismatch diagnostic to instruct callers to wait with `drain --when-idle` or run `--no-pool` instead of immediate `drain`.

### 3. Host-Wide Capacity Scaling, RAM Admission Guard, and Boot Throttling
- Raise default host-wide `MaxActiveWorkers` from `4` to `8`, configurable across `1..10` via `--max-workers <1-10>` (accepted on `--supervisor`, `warm`, and `run`) and `SYNTHETIC_WORKER_POOL_MAX_WORKERS`. Reject values outside `1..10` with exit code `2`. When a supervisor is already running with a different cap, emit a diagnostic warning and proceed using the active supervisor's cap without disrupting sibling agents.
- Add a **RAM admission guard** inside the supervisor scheduler **Module** using the existing `IMemoryProbe` **Seam**, evaluated over **non-terminating resident slots** (`Booting + ReadyStandby + Active`):
  - Guarantee a baseline floor of `min(4, MaxActiveWorkers)` resident slots regardless of free RAM. When `< 10 GiB` free RAM prevents scaling above slot `4` and idle wrong-version `ReadyStandby` workers occupy floor slots, evict idle wrong-version standbys so active demand reaches the guaranteed floor.
  - Before launching workers `5` through `MaxActiveWorkers` (for both demand runs and `warm` standby targets), require `effectiveAvailableBytes >= 10 GiB`, where `effectiveAvailableBytes = ullAvailPhys - (bootingAboveFloorCount * 2 GiB)` to prevent 4-boot TOCTOU memory oversubscription.
- Add a global **Concurrent Boot Throttle** (`MaxConcurrentBoots = 4`) across all scheduler boot paths (demand, standby target, and lookahead). Fix multi-wave boot continuation so `BootWorkerAsync` and `WarmAsync` launch and await subsequent waves (`5..10`) without stalling when `PendingCount == 0`.
- Preserve the `+1` lookahead **Standby Worker** (`TotalResident <= MaxActiveWorkers + 1`) under the existing four guards (`Active == MaxActiveWorkers`, queued work exists, **Clean-Launch Shim** enabled, free RAM `>= 12 GiB`); `MaxConcurrentBoots = 4` governs globally without needing a redundant 5th lookahead condition.

### 4. Makespan-Aware Per-Run Test Shard Allocation
- Decouple the per-run auto-**Test Shard** ceiling (`4`) from host-wide `MaxActiveWorkers` (`8`–`10`) in the duration-weighted LPT sharder **Module**, removing the hardcoded clamp to `4` so explicit `--shards` requests scale up to `min(fixtureCount, hostMaxActiveWorkers)`.
- Compute fixture weights before resolving shard count. Enable makespan-aware shard reduction **only when 100% of matched fixtures have positive observed timings** in the per-version timing cache: simulate LPT for $k = 1 \dots \min(\text{fixtureCount}, 4)$ and pick the smallest $k$ whose makespan matches the $\min(\text{fixtureCount}, 4)$ makespan. Fall back to `min(fixtureCount, 4)` whenever any matched fixture is unseen or has zero duration.

### 5. Parallel Multi-Version Execution in the Test Executor Module
- Update the test executor **Module** so that:
  - `--version` accepts a single target or a comma-separated list (`2025,2026,2027`), trims and deduplicates repeated or overlapping tokens (such as `Logic,LegacyMock`), preserves deterministic order, and fails fast on empty or unknown tokens. Omitting `--version` selects all discovered targets.
  - When `Logic` or `LegacyMock` is selected alongside **Revit Versions**, execute `Logic` and `LegacyMock` first in their own isolated `<RunBuildRoot>\<TargetKey>` subfolders so headless failures fail fast before booting Revit.
  - Run `TestTemplate` upgrade preflight sequentially in ascending **Revit Version** order before parallel builds.
  - In **Worker Pool** mode with multiple **Revit Versions**, give every target its own `<RunBuildRoot>\<TargetKey>` isolated build subfolder, cap concurrent `dotnet build` processes at `2`, and dispatch each **Revit Version** to the **Worker Pool** immediately upon build completion. Keep cold `--no-pool` mode sequential.
  - Remove obsolete `--next-version` (`PipelinePrewarm`) plumbing from both the test executor and **Worker Pool** supervisor.
  - Return structured per-version result records with captured build logs (keeping `sys.exit()` strictly at the top-level coordinator) and flush one concise, thread-safe completion line as each **Revit Version** finishes: `[TESTS] Revit <Ver>: <PASS|FAIL> (<passed> passed, <failed> failed, <clean|dirty> journal, <duration>s)`.
  - Run all selected **Revit Versions** to completion by default and print one combined Markdown summary covering test, build, pool (`exitCode == 2`), and journal cleanliness failures while preserving failed build roots. Support `--fail-fast` to cancel only unstarted builds and dispatches so in-flight workers finish and pass `--worker-id --assert-clean`.
- Verify `RicaunBundleLease` `net10.0` priority so live Revit `2027` runs work seamlessly alongside `2023`–`2026`.

### 6. Agent Skills, Architecture Docs, and Zero-Decision Test Ergonomics
- Remove test-parallelism and pool-lifecycle decisions from coding agents: coding agents simply declare *what* to test via the test executor, and the test executor plus **Worker Pool** handle fixture sharding, multi-version parallelism, and detached worker spawning automatically.
- Apply `writing-for-agents` principles (positive prompting, single source of truth, progressive disclosure):
  - Keep `implement` skill free of pool lifecycle commands (positively invoking only the test executor).
  - Keep multi-agent concurrency guidance (`4–8 implementer subagents` matching the `8–10` worker pool cap) and orchestrator `warm` / `drain --when-idle` / `drain --force` solely in `implement-spec`.
  - Prune `warming or draining` from `revit-tests` frontmatter, guide agents to use single multi-version commands instead of manual `--version` loops, and replace stale CLI/constant tables with `--help` and ADR 0030 pointers.
  - **Execution requirement:** Skill revisions must be performed by a `coder` subagent explicitly following the `writing-for-agents` skill.
- Leave `GLOSSARY.md`, `.agents/AGENTS.md`, and `CODING_STANDARDS.md` unchanged (audit verified zero stale limits or missing domain terms).
- Update **ADR 0030** with an addendum explicitly addressing all superseded clauses: detached supervisor launch (retaining `JobObjectContainer` for child workers), safe `drain` / `DrainingWhenIdle` / zero-grace `--force`, `8`–`10` worker cap with `10 GiB` RAM admission guard and `2 GiB`/boot reservation, `MaxConcurrentBoots = 4`, `TotalResident <= MaxActiveWorkers + 1` lookahead, makespan-aware sharding, parallel multi-version execution (retiring `--next-version` pipelining), and `RicaunBundleLease` `net10.0` priority.

## Testing Decisions

A good test exercises public **Interfaces** at high-leverage **Seams**, verifies observable behavior and invariants (exit codes, resident slot counts, RAM admission decisions, merged reports, and **Revit Journal** cleanliness), and avoids coupling to private internals.

1. **Headless Tooling Seams (`RevitWorkerPool.Tests`):**
   - *Supervisor launch **Seam**:* Test primary Scheduled Task **Adapter**, auto-registration when missing, custom `--pipe-name` routing to breakaway **Adapter**, `CREATE_BREAKAWAY_FROM_JOB` fallback, fail-closed error when both fail, and real Win32 breakaway / Task Scheduler XML (`MultipleInstancesPolicy = Parallel`, non-console hidden launch) verification.
   - *Supervisor scheduler and IPC **Seam**:* Update and extend `SupervisorLifecycleTests`, `SchedulerLookaheadPipelineTests`, and `ProgramTests` (using `StubWorkerProcessLauncher` and a fake `IMemoryProbe`) to cover: `MaxActiveWorkers = 8` default, `--max-workers` validation (`1..10`, exit `2` out of range, warning on running-supervisor mismatch), floor `4` + wrong-version eviction under `< 10 GiB`, `2 GiB`/boot reservation above slot `4`, `MaxConcurrentBoots = 4` wave-2 continuation (`warm --count 6..10`), `+1` lookahead under `>= 12 GiB`, plain `drain` refusal schema (`activeRuns`, `queuedRuns`, `activeWarmCalls`) + idle-standby immediate drain, `drain --when-idle` (rejects new `run`/`warm`, prevents duplicate supervisor spawn, stays latched on client disconnect, allows `status` and preempting zero-grace `drain --force`), per-run `ProjectRoot`, and updated `--no-shim` mismatch message.
   - *Sharder **Seam**:* Update and extend `ShardingAndTrxMergerTests` to verify auto-shard cap `4` decoupled from host cap `8`–`10`, explicit `--shards` up to host cap, 100%-cached-timing guard (cold/partial cache falls back to `min(N, 4)`), and non-binary makespan cases (`300s/350s -> 3` shards, `[100, 70, 70, 40] -> 4` shards).
2. **Python Test Executor Seams (`tests/Tools/test_test_executor.py`):**
   - Update existing sequential/pipelining assertions and add unit tests with fake build and **Worker Pool** runners covering: comma-separated `--version` deduplication and validation, `Logic`/`LegacyMock`-first execution in isolated `<RunBuildRoot>\<TargetKey>` subfolders, sequential ascending `ensure_test_template_ready` preflight, max `2` concurrent builds + immediate pipelined dispatch, thread-safe `[TESTS] Revit <Ver>: ...` completion lines, combined Markdown summary (build/pool/journal errors + failed build root preservation), `--fail-fast` cancelling only unstarted targets, sequential `--no-pool` preservation, and real concurrent 2-process `dotnet build` verification (`2026+2027` and `LegacyMock+2027`).
3. **Live Revit Tests Seam (`LiveRevitEndToEndSmokeTests` + Multi-Version Smoke):**
   - Isolate `LiveRevitEndToEndSmokeTests` onto dedicated test pipe names (or `--force`), and execute a live multi-version `RevitSmoke` run (`--version 2026,2027 --category RevitSmoke`) confirming detached supervisor survival after caller command exit, concurrent multi-version execution, and `--worker-id --assert-clean` **Revit Journal** gating on every consumed **Standby Worker**.
