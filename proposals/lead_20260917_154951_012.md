### ROADMAP — multi-speed JIT (still this issue, not v0 close, not P0, no new ticket)

Law:

> Novelty is interpreted. Repetition is compiled.
> Nika amortizes reasoning into software.
> Never ask a model to emit structure the compiler can construct itself.

Primary pipeline (generative YAML is the **fallback**, not the main path):

```
HUMAN INTENT
    → IntentContract          (deterministic; already ships)
    → structural fingerprint  (CONCEPT; not a public YAML key)
        ├ HOT      exact / cached skeleton + bind slots     1–10 ms *target, unmeasured*
        ├ WARM     BM25 top-K + ONE decision pass           ~1 RTT *target, unmeasured*
        ├ COLD     generative SEMANTIC SKETCH → assembler   slower
        └ EXPLORE  authoring agent → sketch → assembler     last resort
    → CONSTRAINT ASSEMBLER    (deterministic; intelligence selects, compiler constructs)
    → candidate .nika.yaml    (4 verbs only)
    → Check                   (#1636; compiler authority = NONE)
    → human review
```

- [ ] **HOT PATH — zero intelligence.** Detail: [#1665](https://github.com/supernovae-st/nika/issues/1665). `IntentContract` → structural fingerprint → exact/cached skeleton or prepared workflow → bind typed inputs → Check. No Jev. No GPT. No network. Today's exact-name + high-margin BM25 route is the embryo. Success = intent→program in milliseconds **when the structure is known**. Intent→*result* in milliseconds only if the program is local/deterministic. Do not claim TypeSafe 70–500 ms as this path.
- [ ] **WARM PATH — one System One impulse, not a DAG generator.** When BM25 top-K is inside the honest-ambiguity band: capability filter → BM25 top-5 → **one** decision-seat request answering *small semantic questions in parallel* (archetype, needs-exploration Noul, needs-generation Noul, lookup-is-deterministic Noul, output family, review pattern). Jev (or any compatible seat) **does not build the DAG**. A deterministic assembler does. Ranking ≠ grant (#1639). Hard-coding TypeSafe is forbidden.
- [ ] **Descriptive vs normative ambiguity.** Descriptive (« classify-and-route vs gate-and-act? ») **may** use intelligence. Normative (« may we auto-send the email? ») **must not**. Normative gaps → questions (#1657), never a model guess. Mixing them is a failed test.
- [ ] **COLD PATH — semantic sketch, not 400 lines of YAML.** If known skeletons cannot satisfy the contract: a generative model emits an **internal** sketch (`goal / inputs / outputs / step semantic-need / depends / approval-condition`). Not a public IR. Not a spec key. The assembler lowers the sketch onto existing verbs + existing skeletons. Neighbour class (do not import scores): Prompt2DAG (arXiv:2509.13487) hybrid 78.5% vs LLM-only 66.2% vs direct 29.2% on Airflow DAGs — models select better than they emit combinatorics.
- [ ] **EXPLORATORY PATH — agent is the compiler of last resort.** Agent may inspect docs/tools/environment and **propose a sketch**. Then the small assembler + Check resume. The agent does not mint an admitted run.
- [ ] **CONSTRAINT ASSEMBLER.** Intelligence returns choices/Nouls. The assembler is a constraint solver over the skeleton algebra, types, and available authority. Invalid graphs are not emitted as « almost right YAML ».
- [ ] **SKELETON ALGEBRA** — child [#1666](https://github.com/supernovae-st/nika/issues/1666). Factor the 22 into composable units, *conceptually* (authoring-registry metadata, **not** new YAML verbs): Archetypes (`chain` `classify-and-route` `gate-and-act` `fanout` `agent-loop` `human-gated-ship` …) + Guards + Transforms + Decision patterns + Effects + Recovery. A workflow = `ARCHETYPE + 0..N GUARDS + 0..N TRANSFORMS + DECISION PATTERNS + EFFECT + RECOVERY`. Connections are solved, not invented. Stress-to-ratchet: a recurring unmatched intent **earns** a new pattern via human PR.
- [ ] **Typed skeleton contracts in the authoring registry** (derived or metadata; `.nika.yaml` unchanged): input/output contract, effect signature, authority requirements, cognitive requirements, composition rules, golden + failure fixtures, proof expectations, bench evidence. Solving « which patterns satisfy this IntentContract without exceeding available authority? » is constrained program synthesis, not prompt engineering.
- [ ] **PREPARED WORKFLOW / semantic cache.** Child [#1665](https://github.com/supernovae-st/nika/issues/1665). Separate *structure of intent* from *data of execution*. « Résume https://foo.com » and « Résume https://bar.com » are one program `website-summary:vX` + binding `url=…`. Fingerprint the structural contract (`goal: summarize, source: url, output: text, effect: none`), not the utterance string. Subsequent calls: lookup prepared → bind → validate → run.
- [ ] **COMPILE UNCERTAINTY, don't hide it.** Every candidate carries: KNOWN / INFERRED / UNKNOWN / REQUESTED AUTHORITY / UNRESOLVED POLICY. UX: « I can compile 85% of this workflow. I need three human decisions. » Invented policy numbers remain a failed test.
- [ ] **PREPARED AUTHORITY** (admission accelerator, not a Check bypass). If an org has already approved a profile and `candidate_authority ⊆ approved_profile`, Check may admit fast. If `⊄`, STOP and show the delta. Instant ≠ ungoverned. Comparison owned by #1636 / #1637; this issue *emits* the requested set.
- [ ] **LEAST COGNITION PRINCIPLE** — child [#1667](https://github.com/supernovae-st/nika/issues/1667). jq → code → decision seat → schema infer → generative LLM → agent. Pass #1 of any compilation: **can I delete an AI call?** TypeSafe jaggedness jev-1.13 (*keep arithmetic in code*) is this law, not a Jev feature.
- [ ] **Logical plan ≠ physical plan.** Child [#1668](https://github.com/supernovae-st/nika/issues/1668); invariant [#1637](https://github.com/supernovae-st/nika/issues/1637). Four independent DECIDE nodes on shared state may be one System One HTTP (`questions_per_call=N`, #1655). Proof still names four answers. Flattening the semantic DAG to save a round-trip is a #1656 BATCHING **loss** if observability dies. Physical optimizer may fuse calls; it may not change policy, authority, outputs, or program meaning.
- [ ] **Do not grow a public sketch format.** The semantic sketch is compiler-internal. Public artifacts remain `.nika.yaml` + CheckReport + ExecutionSnapshot + Proof. No `CognitiveIR`, no `sketch:` key, no One SDK L0 noun.

## Partial evaluation — the compiler deletes intelligence

Given a giant prompt that currently does five jobs, the compiler searches for work that can leave the model:

```
parse date          → COMPUTE (code)
VAT                 → COMPUTE (code)
threshold compare   → POLICY (#1657 / nika:decide)
risk                → DECIDE  (bounded seat)
email               → GENERATE
```

This is the opposite of « add more AI ». It is also the opposite of DSPy (which compiles *prompts and weights* of an already-authored graph). Nika would compile *structure under Check*. See competitive audit on [#1654](https://github.com/supernovae-st/nika/issues/1654).
