## Goal

For an **independently, code-proven `GreenhouseJobAlias` only**, admit an otherwise unsupported **visible reCAPTCHA Enterprise anchor iframe** solely when its whole current parent-DOM signature matches the #72 r07 R visible-badge predicate. Remove only that individual qualifying iframe from the Greenhouse `PAGE.unsupported_frames` failure condition, or provide equivalent narrowly scoped code-owned classification with the same strict Gate behavior; leave the ordinary non-entry inventory contract and all other actionable visible frames fail-closed. Preserve ordinary Greenhouse `PAGE` behavior for every hidden/non-visible iframe, including Enterprise anchor/bframe shapes and near-matches; add no Greenhouse hidden-R recognition, hidden-frame hardening or root-dependent hidden Gate. Do **not** transplant Lever/Ashby `ApplicationEntryProvenance` entry waits, H/W/X exceptions, token quarantine or scoped navigation changes wholesale to Greenhouse.

The exception is **read-only recognition, not captcha interaction**. No iframe navigation, focus/click/type, CAPTCHA response-field or token/sitekey inspection, challenge-solving, implicit human approval or bypass of any existing guarded application step.

## Binding surface

1. **Typed provenance fence and narrow PAGE selection.** In `src/tools/browser_skill_apply.py`, select the new classification only after the existing persisted/tracked alias and route checks independently establish `isinstance(provenance, GreenhouseJobAlias)` and a still-current same-job mapping. Page URL text, iframe attributes, a Greenhouse-looking host, a fixture assertion, or a model suggestion cannot manufacture this authority. Ordinary `PAGE.unsupported_frames` behavior for `VendorRedirectProvenance`, other non-entry paths, no provenance and all other page consumers remains unchanged; `ApplicationEntryProvenance` retains #72's separate implementation. Do not add a Greenhouse entry wait, a second navigation or an ATS/alias shortcut.
2. **Exact visible R source and native-root proof.** Inspect each relevant actionable visible top-document iframe itself using its raw `getAttribute('src')`, not the normalized `e.src` or a string alone from `unsupported_frames`. For the visible anchor exception and visible bframe precedence, its parsed origin must be **exactly** `https://www.recaptcha.net` **or** `https://www.google.com`; the visible-anchor exception requires pathname **exactly** `/recaptcha/enterprise/anchor`, while the visible-challenge precedence recognizes **exactly** `/recaptcha/enterprise/bframe`. These checks neither reclassify nor Gate any Greenhouse hidden/non-visible frame. Prove **one unique inspectable native application `<form>`/root** belonging to the current Greenhouse application using code-owned form/receiver/route evidence in the current parent DOM, not an arbitrary form, body, URL string, untrusted page marker alone, or an assumed empty root. The visible-anchor candidate must be demonstrably **outside** that proven root by actual parent-DOM containment. Missing, ambiguous, changed or unreadable root cannot satisfy `outside`; `!root` is not proof. Do not read/store query, hash, title as identity, child frame contents, page prose, response values, sitekeys or token values.
3. **Exact style and sole visible exception.** Every Greenhouse hidden/non-visible iframe retains its existing ordinary `PAGE` treatment regardless of Enterprise origin/path, badge, root or rectangle: this Issue adds neither a hidden-R allowance nor a hidden-R rejection and does not borrow #72's entry-path hidden classifier. The **only visible** admission is an exact-origin, exact-`/recaptcha/enterprise/anchor` iframe, outside the proven root, with its own computed `visibility === 'visible'` and `display !== 'none'`, demonstrably contained by an **ancestor `div.grecaptcha-badge`**, and its **own** readable finite `getBoundingClientRect().width === 256` and `.height === 60` CSS px. Equality is exact, **no tolerance or rounding**. Neither title nor badge nor dimensions alone is a provider identity signal. One matching iframe never blesses a sibling.
4. **Disqualification and Gate precedence.** An exact-origin/path **visible Enterprise bframe** always takes the **existing named visible reCAPTCHA Enterprise challenge Gate first**, whether inside/outside a root or before any root can be proven. It is never a visible-anchor candidate. Any disqualified actionable visible anchor (including bad/missing badge ancestor or rect, rootless/inside-root placement or wrong origin/path), or other unmatched observed actionable visible frame takes the **existing named unknown/untrusted application frame Gate**, not a wait, an applicant control or a silent exemption. Retain ordinary unsupported-frame behavior for every other iframe, including unrecognized visible widgets and other provider families; do not use a generic `iframe` ignore-list, generic hidden-frame trust or H/W/X exceptions. Preserve existing ordinary Greenhouse PAGE treatment of **all** hidden/non-visible frames, including Enterprise-shaped frames, without a new root-dependent reject path.
5. **Same predicate on every inventory, no cached trust.** The scoped Greenhouse reader/classifier must be selected for the initial actionable inventory and **every fresh subsequent PAGE / `_inventory_ok` observation**, including nested independent witness re-PAGE, form checks, selected-value/receipt verification, pre-fill, pre-action, Continue and pre-submit paths. On each such read, re-prove typed current provenance; for each actionable visible-anchor candidate re-prove the unique native root, exact per-iframe URL/style/ancestor/rect and outside-root placement, without applying those conditions to hidden/non-visible frames. A hidden-to-actionable-visible unmatched frame, actionable valid-to-wrong-size or relocated frame, new actionable visible sibling or newly visible exact bframe Gates **before the next mutating IPC**; a transition to hidden/non-visible instead retains ordinary Greenhouse PAGE behavior. Do not rely on the first snapshot or a prior cached `unsupported_frames` list; preserve independent fixed-witness parity, route, native receiver and destination checks. No between-observation atomicity claim.
6. **Unchanged security authority.** `unsupported_frames` never becomes approval. Existing `inventory_verified`, `truncated`, `opaque_controls`, `shadow_roots`, unknown/foreign controls, exact approved-answer grants/readbacks, current tracked row and provenance, native form action/override, attachment/seed, dispatch/duplicate/resume, protected-answer checks, Submit/Continue hold, confirmation and `uncertain` outcomes remain enforced **in code**. No direct frame evaluation, CAPTCHA response-control inspection, token reads, solver, new browser driver, model-based gate or actual application action.

Reject independently isolated **actionable visible** look-alike origin (wrong scheme, host or port) and path (prefix, suffix, trailing slash, different product), plus rootless/ambiguous-root or inside-root **visible-anchor** candidates, under the existing unknown/untrusted frame Gate. Every hidden/non-visible Greenhouse iframe, including Enterprise anchor/bframe shapes, near-matches and rootless/inside-root frames, retains today's ordinary PAGE treatment without new R-specific hidden exemptions or rejection. Do not use title/rect as identity or broaden other frame treatment.
3. **AC3 — Exact 256×60 visible badge positive:** With a single code-proven Greenhouse native form and a badge ancestor `div.grecaptcha-badge` **outside** it, a visible Enterprise **anchor** from an allowed origin with own readable finite rectangle exactly width 256, height 60 CSS px is admitted. The fake DOM must execute the real production reader and show the individual frame's admission, unchanged other inventory checks, and no CAPTCHA response, child-frame or token access. Require **two distinct production-reader fake-DOM visible positive cases**: one raw source at exact `https://www.recaptcha.net/recaptcha/enterprise/anchor` and another at exact `https://www.google.com/recaptcha/enterprise/anchor`, each with identical independent typed Greenhouse/root/outside-badge/computed-visible/display/own finite-exact 256×60 conditions. 4. **AC4 — Isolated visible anchor negatives:** Separate fake-DOM cases holding all other conditions valid must Gate unknown/untrusted for (a) look-alike origin and (b) look-alike anchor path; (c) wrong badge parent/ancestor; (d) badge anchor **inside the form/root**; (e) no uniquely proven root; (f) oversized width-only **300×60**; (g) oversized height-only **256×61**; (h) undersized **255×60** or **256×59** tested independently; (i) fractional **256.5×60**; (j) missing/throwing/unreadable rect; and (k) non-finite `NaN` or Infinity geometry. Other nonempty unsupported frames, opaque controls, site shadow roots, malformed/truncated inventory, untrusted destination or changed provenance continue to Gate. Preserve ordinary `check_form`, independent witness, authorization/readback/submit hold and no automatic retry.
7. **AC7 — Offline guard sensitivity and regression:** Use `tests/tools/test_browser_skill.py` with actual production JS under synthetic Node fake DOM and fake sessions only, no network/browser/Redis/ChatGPT subscription. **Each distinct new origin, path, provenance, root uniqueness/outside, actionable-visible style, badge ancestry, own finite-exact width/height, bframe priority and freshness safety guard has an isolated negative that fails when that specific guard is removed and passes on restoration.** Independently assert hidden/non-visible Greenhouse Enterprise and near-match parity (no new allow/reject behavior).
