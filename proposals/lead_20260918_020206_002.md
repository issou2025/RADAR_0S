# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Revit: a staged import that stays responsive, shows progress and can be cancelled**

*Project description:*
**Host:** Revit
**Parent:** #147. Phase A item 3. May run in parallel with item 2. Item 9 builds on the window this creates.

**The problem**

The import runs synchronously on Revit's main thread. Revit reports "not responding" for minutes on a large bundle, nothing can be cancelled, and `SlowStepNotice` records a decision that a progress bar is not available because the cost sits inside one commit. That decision is reversed here, and the file's reasoning is rewritten: a commit cannot yield, but the steps between commits can.

**The change**

- One step per `ExternalEvent` raise, driven by the existing `BundleImportEventHandler`, so Revit repaints between steps.
- A modeless import window, one for the vault path and the local path, showing the step list, the current step, and per-chunk progress for buildings and trees. Its words are a new `HPS-51` row, since the Unreal plugin will need the same surface; the standard moves first.
- Buildings and trees are chunked: N elements per transaction, N a Core constant with a test, tuned by measurement. Subdivisions and the terrain stay one commit each.
- Cancel is honoured between steps and between chunks. Completed work stays, stamped, so a re-import of the same build reuses it under ADR 0004. No `TransactionGroup` rollback.
- The unattended path (`MANTLEPLACE_BUNDLE_ZIP`, journals) stays synchronous and log-only, because a modeless window in a playback never closes.

**Done when**

- Revit's window repaints and Cancel is clickable throughout an import of the largest bundle in the cache.
- Cancelling mid-way leaves stamped, reusable elements and a log saying which steps completed.
- The unattended path produces the same log it does today.
- `SlowStepNotice` says what still cannot be shown (inside a commit) and why, rather than that nothing can.
