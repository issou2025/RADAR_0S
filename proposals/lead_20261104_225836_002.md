## Research findings

### Summary
The home page (`Components/Pages/Home.razor`) renders up to seven module cards (six always, plus a Settings card for project admins). They're `FluentCard` components laid out in a wrapping horizontal `FluentStack`. Each card's size comes only from an inline `Style="max-width: 400px; padding: 24px;"` plus its content: a 48px icon, an `h3` title, a description paragraph, and an accent button. No CSS file styles these cards. "Reduce at 60%" is read here as "shrink to 60% of the current size": max-width 400px→240px, padding 24px→~14px, inner gap 16→~10, and icon `Size48`→`Size28`. The change is confined to `Home.razor`, and no tests cover this page.

### Key discoveries
- All seven cards share the same inline style: `Components/Pages/Home.razor:18,33,48,63,78,93,110` use `<FluentCard Style="max-width: 400px; padding: 24px;">`. The Settings card (`:110`) only renders when `_isAdmin` (`:108`, set at `:143-144`).
- Each card's inner layout is a vertical `FluentStack VerticalGap="16"` (`Home.razor:19,34,49,64,79,94,111`) holding a 48px icon (`Icons.Regular.Size48.*`, `:20,35,50,65,80,95,112`), an `<h3>`, a `<p>` and a `FluentButton` with a `Size20` icon.
- The cards sit in `<FluentStack Orientation="Orientation.Horizontal" HorizontalGap="20" Wrap="true">` (`Home.razor:17`). FluentStack defaults to `Width="100%"` and `VerticalAlignment.Top` (Fluent UI XML docs), so the cards wrap and are top-aligned, with heights set by their content.
- The `fluent-card` web component (Fluent UI 4.14.3, `Microsoft.FluentUI.AspNetCore.Components.lib.module.js`) sets `:host { width: var(--card-width, 100%); height: var(--card-height, 100%); }`. Each card therefore fills its slot and is capped only by the inline `max-width`, so in practice it's exactly 400px wide on a wide viewport. The inline `padding: 24px` overrides the component's scoped default `padding: calc(var(--design-unit) * 5px)` (`FluentCard.razor.rz.scp.css`).
- `FluentCard` also has `Width`/`Height` parameters ("must be a valid CSS measurement"), but this repo never uses `Width`. The established pattern is inline `Style` (`Home.razor`, `Settings.razor:39`, `RevitWebhooks.razor:47`, `CreateModels.razor:71`).
- Icon sizes: `Size28` exists for all seven home icons (`DocumentAdd`, `TableSimple`, `DocumentOnePageMultiple`, `Cube`, `Alert`, `ChatMultiple`, `Settings`), but `DocumentAdd` has no `Size32` (checked against `Microsoft.FluentUI.AspNetCore.Components.Icons.Regular.dll` 4.14.3). 48×0.6 = 28.8, so `Size28` is the right and only consistent choice.
- `Wrap="true"` and FluentStack's `flex-wrap: wrap` mean narrower cards will automatically fit more cards per row. No layout code has to change for the grid to reflow.

### Detailed findings

#### Card content and typography
- The title is a bare `<h3>`, styled by Fluent's `reboot.css` (`h3 { font-size: var(--type-ramp-plus-3-font-size); line-height: var(--type-ramp-plus-3-line-height); }`, imported at `wwwroot/app.css:1`).
- The description is a `<p style="color: var(--neutral-foreground-hint);">`. In `reboot.css` it gets the base type ramp and `margin-bottom: 1rem`.
- Buttons are `Appearance.Accent` with `Size20` start icons (for example `Home.razor:25-29`). Keep them at their default size so click targets stay accessible. At 240px card width minus ~14px padding on each side (~212px of content), the longest label ("Revit Webhooks" plus a 20px icon, about 160px) still fits on one line.
- The longest description ("Get notified when Revit links are added or removed using Webhooks and the AEC Data Model API.", `Home.razor:83`) will wrap to more lines at 240px. That's acceptable because heights are content-driven and top-aligned.

#### Styling approach and CSS isolation
- `Home.razor` has no `.razor.css` file. Global `wwwroot/app.css` has no card or home rules.
- If the plan moves the sizing into an isolated `Home.razor.css`, note that `<fluent-card>` carries FluentCard's scope attribute, not Home's. A rule would need a plain HTML wrapper rendered by Home plus `::deep`, the same way `SignIn.razor.css:81` (`.signin-welcome ::deep .signin-card`) targets `<FluentCard Class="signin-card">` (`SignIn.razor:52`). `FluentStack` is a component too, so it can't serve as the scoped ancestor.
- The simplest change that matches the surrounding code is to edit the seven inline `Style` strings and attributes in place. Optionally, hoist the repeated style into a `private const string` in the `@code` block (`Home.razor:128`), though nothing else in the repo does that.
- Not recommended: CSS `zoom: 0.6` shrinks text to ~60% (about 8–9px), which hurts readability and accessibility. `transform: scale(0.6)` doesn't shrink the layout box, so it leaves 400px gaps.

#### Related page with the same card pattern
- `Components/Pages/Settings.razor:38-53` uses identical card markup (`max-width: 400px; padding: 24px;`, `VerticalGap="16"`, `Size48.Bot`). It isn't the home page, so it's out of scope unless consistency is wanted (see open questions).

#### Verification
- `ApsSamples.Tests` has no bUnit or Home page tests, so verification is `dotnet build` plus a manual visual check.
- Unauthenticated users get redirected from `/` to `/signin` (`Home.razor:133-137`), so checking the page needs a signed-in session. Seeing the Settings card needs a project-admin user.

### Open questions
- **Meaning of "at 60%"**: assumed to mean "to 60% of the current size" (400px→240px). The alternative, "by 60%" (to 40%, 160px), would leave ~130px of content width, too narrow for button labels like "Revit Webhooks" with an icon. If that was intended, the buttons and text would need to change too.
- **What "size" covers**: assumed to mean the card's footprint (width, padding, gaps, icon). Body text and button sizes stay as they are for readability. Shrinking the `h3` title is left as an optional step for the plan to decide.
- **Rounding**: 60% of 24px is 14.4px and of 16 is 9.6, rounded to 14px and 10. Using 16px and 8 would keep a 4px/8px rhythm if preferred.
- **Settings page cards** (`Settings.razor:39`): assumed out of scope because the issue names only the home page.

# Reduce home page card size to 60% Implementation Plan

## Overview
Shrink the seven module cards on the home page to 60% of their current footprint so more cards fit per row. The change is a markup-only edit to `Components/Pages/Home.razor`: card max-width, padding, inner gap, icon size, and the gap between cards.

## Current State Analysis
- All seven cards use `<FluentCard Style="max-width: 400px; padding: 24px;">` at `Components/Pages/Home.razor:18,33,48,63,78,93,110` (the Settings card at `:110` renders only when `_isAdmin`).
- Each card wraps its content in `<FluentStack Orientation="Orientation.Vertical" VerticalGap="16">` at `Home.razor:19,34,49,64,79,94,111`.
- Each card icon is `Icons.Regular.Size48.*` at `Home.razor:20,35,50,65,80,95,112`.
- The cards sit in a wrapping horizontal `FluentStack HorizontalGap="20" Wrap="true"` at `Home.razor:17`, so narrower cards reflow with no layout code changes.
- The repo's established pattern is inline `Style` on `FluentCard` (also used in `Settings.razor:39`). No `Home.razor.css` exists, and nothing else hoists the style into a constant.
- No tests cover this page, so verification is `dotnet build` plus a manual visual check.

## Desired End State
On the home page every card is at most 240px wide, with 14px padding, 10px inner gap, and a 28px icon. The cards are 12px apart. Titles, descriptions, and button sizes are unchanged. More cards fit per row on a wide viewport. The project builds with no new warnings or errors.

## What We're NOT Doing
- Not changing `Settings.razor` cards (the issue names only the home page).
- Not using CSS `zoom` or `transform: scale`, which hurt readability or leave the layout box unchanged.
- Not shrinking the `<h3>` titles, description text, or button sizes (readability and click targets).
- Not adding a `Home.razor.css` file or hoisting the style into a constant.
- Not adding tests (no bUnit infrastructure exists in `ApsSamples.Tests`).

## Implementation Approach
Edit the inline attributes in place, matching the surrounding code.

Assumptions (taken from the research recommendations):
- "At 60%" means "to 60% of the current size": max-width 400→240, padding 24→14 (14.4 rounded), inner gap 16→10 (9.6 rounded), icon `Size48`→`Size28` (28.8, and `Size28` is the only size that exists for all seven icons).
- The outer card gap goes from 20 to 12 so spacing scales with the cards.
- Titles stay at their current size.
