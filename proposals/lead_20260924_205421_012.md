# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Epic: User & Profile 2.0 — account, preferences, privacy and synced interests**

*Project description:*
## Context

FutBeat already has a Profile screen with:
- email/password sign-up and sign-in
- display name
- followed teams/competitions/players/matches
- competition ordering preferences
- hour format
- notification preferences

The next step is to turn this into a complete product account/profile system and make it the canonical source for user interests used by feed ordering, notifications, news personalization and the Quota Governor.

## Goals

1. A complete account lifecycle.
2. Persistent/synced profile and preferences across devices.
3. Privacy and account deletion support for store compliance.
4. Explicit interests usable by matches, notifications, news and provider scheduling.
5. Keep guest/anonymous use possible where practical; account creation should add sync/personalization rather than block basic use.

## Account lifecycle

- Email verification status and resend verification.
- Forgot/reset password.
- Change email/password securely.
- Sign out.
- Delete account + associated user data.
- Provide a web-accessible account deletion request path as required for Google Play apps that allow account creation.
- Session restore and clean handling of expired/revoked sessions.
- Later-ready OAuth architecture for Google/Apple without making them mandatory for MVP.

## Profile

- Display name.
- Optional avatar/profile photo with safe storage/cropping/default initials.
- Country preference separate from detected country.
- Language preference.
- Time format/timezone preference.
- Optional favorite team / primary club.
- Do not collect unnecessary personal data such as birth date, gender or phone number unless a future feature truly requires it.

## Interests / follows

Canonical synced follows:
- team
- competition
- player
- match

Add:
- per-follow notification controls where useful
- favorite/priority vs ordinary follow if needed
- aggregate counts server-side for Governor/news personalization
- no provider calls per individual user

## Notification settings

Maintain current settings and expand cleanly for:
- kickoff
- goals
- final
- cards
- lineups
- substitutions
- VAR
- missed penalties
- followed-player events
- news / breaking news
- quiet-hours support later

Settings should support global defaults plus optional entity-specific overrides without creating an unmaintainable matrix.

## Privacy / data controls

Profile should show:
- what FutBeat stores for the user
- followed entities
- notification preferences
- sign-out
- delete account
- link to Privacy Policy / Terms when available

Deletion must remove/anonymize user-owned profile/preferences/follows/push tokens according to the retention policy, while retaining only data that is legitimately non-user-specific/aggregated.

## UX

- Clean profile header.
- “Siguiendo” summary (teams, leagues, players, matches).
- Preferences grouped logically.
- Account/security section.
- Avoid technical/AI explanatory copy.
- Loading/error states must remain recoverable.

## Acceptance criteria

- Existing guest/basic match browsing still works.
- Authenticated preferences sync across reinstalls/devices.
- Follows feed the existing interest strategy and can feed the Governor/news ranking without querying each user on every cycle.
- Password recovery and account deletion paths exist.
- No secrets or auth tokens are exposed in Flutter logs or public endpoints.
- Tests cover account/settings/follow synchronization and deletion-related behavior.

## Notes

Google Play currently requires apps that allow account creation to provide an in-app account deletion path and a web resource for account deletion requests.
