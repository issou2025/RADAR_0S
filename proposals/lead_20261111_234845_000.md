## B. Done only by a workaround

| # | Asked | Problem | Workaround / side effect |
|---|---|---|---|
| B1 | A main roof that meets the wing in a valley | A3 + A2 | Flat 7-sided roof, ridge line and valley points raised with `EDIT_SLAB_SHAPE`. Works, but Revit warns *"Thickness of this Roof may be slightly inaccurate due to extreme Shape Editing"* and draws shape-edit seams on the faces |
| B2 | Set porch posts' Top Level / Top Offset | `WRITE_ELEMENT_PARAMETERS` and `SET_PARAMETER_VALUES_BY_ID` both refuse: *"two parameters on it are called Top Level"* (M_Rectangular Column, an architectural column). The suggested `{GUID}` form cannot apply - both are built-in | Deleted the posts and re-placed them with `PLACE_FAMILY_INSTANCES structuralType=column topLevelName=...`, which read back correctly |
| B3 | Place an architectural column with a top level | `PLACE_FAMILY_INSTANCES` refuses `topLevelName` unless `structuralType=column`, and says nothing was placed | Same as B2 |
| B4 | Cut an open doorway into a closet wall | `CREATE_OPENING` is DRAFT, refused on the live model | Placed a 762 door instead |
| B5 | Cut away a stray piece of roof | `CUT_GEOMETRY` is DRAFT (and roof-by-roof cutting may not be possible anyway) | Deleted and rebuilt the roofs |
| B6 | Attach porch posts to the roof | `ATTACH_COLUMNS` is DRAFT (only try-once on a saved model) | Posts stop at the plate |
| B7 | Make a door/window type at an exact size | `DUPLICATE_TYPE` needs a placed instance; a type cannot be duplicated from the type itself | Placed a seed instance per size, duplicated, set Width/Height, then `CHANGE_ELEMENT_TYPE` the seed - 4 calls per size, and each type change raises Revit's delete box (C1) |
| B8 | Place furniture facing a wall | `PLACE_FAMILY_INSTANCES` has no rotation for level-based families | A separate `ROTATE_ELEMENTS` per group; facing then checked with `REPORT_LOCATION` |

## C. Things that went wrong or misled

| # | What happened | Why it matters |
|---|---|---|
| C1 | Revit's "delete these elements?" box appears on `CHANGE_ELEMENT_TYPE` (windows, doors, columns), `REPLACE_MATERIAL` (window frames: 16 elements each time), `SET_PARAMETER_VALUES_BY_ID` (a column's Material) and `CREATE_WALL` (1 element) - none names *what* would be deleted | The modeller cannot judge the delete. With nobody at the keyboard the box times out, Heron stops, **and the box stays open, so every later call is refused as "Revit is busy"** until someone closes it - unattended work stalls completely |
| C2 | A mistyped id (`1609101`, meant `1594101`) resolved through `FILTER_ELEMENTS_BY_ID` to a `(no category) "Bench"` element, and `MOVE_ELEMENTS` then "ran" and reported it *unverified* | A non-model element should be refused at the filter, not handed on to a write |
| C3 | `ROTATE_ELEMENTS` with `angleRadians=-1.5707963` prints `normalised 1.5707963` | Read as a +90° turn; the rotation was actually correct (REPORT_LOCATION showed 270°). Misleading output |
| C4 | Every `LOAD_FAMILY` of a new family reported `materialsChanged`: project **Glass** 0,0,255 / 75% → 245,245,243 / **100%**, Default Light Source 75% → 100%, Poche appearance asset swapped | Either the project's Glass really became fully transparent on load, or the report is wrong. Needs checking - it would affect every window |
| C5 | A family built in the **Metric Casework** template, drawn in project coordinates and placed at 0,0,0, came out **45 mm short in X**, and its bounding box reached back to (-405, -600) - a corner with no visible geometry | Template origin or default content not where expected; a fixed family placed at the origin is off |
| C6 | `heron_lookup` for "attach the tops of these walls to the roof" and "set the top level of these columns" both returned **ATTACH_COLUMNS** first; ATTACH_WALLS was only mentioned as "not offered on 2024" | The answer should say plainly that the job cannot be done on this release |
| C7 | `revit_view_image` of a floor plan pictures the whole crop/annotation extent - the house was a small patch in the middle of the sheet; there is no way to frame a region of a plan | Plans could not be checked visually; a 3D element picture was used instead |
| C8 | Every lookup warned *"The knowledge store does not match this checkout: 3 card(s) ... (dimension-views-by-rules, draw-mep-schematic, tag-views-by-rules)"* | Store needs a rebuild from the main checkout |
