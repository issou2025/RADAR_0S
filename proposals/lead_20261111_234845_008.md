### Bug Description

`_rule_stuck_in_blocked` is the only diagnostic that looks at `blocked`, the human-wait state.
On `main` (`6a0d2d12815c`), `hermes_cli/kanban_diagnostics.py:594-620` treats **any** `commented`
event newer than the last `blocked` event as a discharge:

```python
# Any comment / unblock after the block breaks the "stale" signal.
if any(_event_kind(ev) in {"commented", "unblocked"} and _event_ts(ev) > last_blocked_ts
       for ev in events):
    return []
```

That suppressor has no age term, so a single comment written minutes after the park exempts the
card from the rule **permanently**, even though nothing was resolved. The notice says the card is
"waiting for human input"; one acknowledgement, and the only detector that watches for a cold
human wait stops looking at it forever.

## Relationship to #140663 / #140705

Adjacent, not duplicate. #140663 (and the open #140705 implementing it) filters which *author* may
reset the clock — an automation reminder should not count as a human acknowledgement. This report
is about the *age* of the engagement: a comment from anyone, a maintainer included, silences the
rule forever today. The two changes touch the same function and would conflict textually, so it is
reasonable to land the author filter first; the age term then rebases on top of it and applies to
whatever comments still qualify.

### Proposed Fix (optional)

Age the staleness clock from the newest of the `blocked` event and the card's newest comment,
and keep `unblocked` as a hard suppressor, since that is a real discharge:

| newest event after the park | today | proposed |
|---|---|---|
| comment, 2 h old | silent | silent — the human just engaged |
| comment, 29 h old | silent forever | reported, naming the comment that did not resolve the block |
| `unblocked` | silent | silent — real discharge |

`kanban.diagnostics.blocked_stale_hours` keeps its meaning (default 24), so a comment buys one
window rather than an exemption. The diagnostic would also carry `blocked_hours` (age since the
park) and `comment_at` next to the existing `age_hours` (age since the re-arm point), and its title
would state the true blocked duration instead of the re-armed window. No schema change, no new
config key, no task mutation.
