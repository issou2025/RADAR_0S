**🐞 Describe the bug**

pyRevit ships `LibGit2Sharp` **0.31.0**, which bundles native **libgit2 v1.8.4**. libgit2 v1.8.6 is a security release fixing multiple CVEs, and LibGit2Sharp 0.32.0 (released July 2026) packages it. All libgit2 v1.8-line users are advised to upgrade.

The version is pinned in two projects:
- `dev/pyRevitLabs/pyRevitLabs.Common/pyRevitLabs.Common.csproj` → `<PackageReference Include="LibGit2Sharp" Version="0.31.0"/>`
- `dev/pyRevitLabs/pyRevitLabs.PyRevit/pyRevitLabs.PyRevit.csproj` → `<PackageReference Include="LibGit2Sharp" Version="0.31.0"/>`

The vulnerable native `git2-*.dll` is deployed to `bin/` by the `DeployDependencies` target and shipped in both installers (`release/pyrevit.aip`, `release/pyrevit-cli.aip`). The same DLL is also loaded in-Revit by `pyrevitlib/pyrevit/coreutils/git.py`, so the extension manager and updater are affected too — not just the CLI.

CVEs in v1.8.6 that map directly onto pyRevit's attack surface:

- **CVE-2026-53586** — credentials callback receives the original host after an offsite redirect, so the returned credential is sent to the redirected host. pyRevit passes a `CredentialsProvider` into `CloneOptions.FetchOptions` in `GitInstaller.Clone` for private extension repos — exactly this code path.
- **CVE-2026-53584** — submodule path traversal (`../`) can write outside the working tree. `pyrevit extend` clones arbitrary third-party extension repos.
- **CVE-2026-53585** — unbounded memory allocation from a delta object's claimed result size (DoS via malicious remote during clone/fetch).
- **CVE-2026-53587** — heap out-of-bounds read in `smart_pkt.c` during the smart protocol handshake (malicious/compromised remote).
- **CVE-2026-53583** — inverted IP SAN comparison in the OpenSSL backend enabling MITM on IP-literal HTTPS URLs.
- Plus a 1-byte heap-buffer-overflow in bundled PCRE reachable via `:/<pattern>` revspecs.

**Additional context**

- The native DLL filename embeds a libgit2 build hash (currently `git2-3f4182d.dll`) and is referenced by that exact name in `release/pyrevit-cli.aip` — the Advanced Installer project file entries will need refreshing after the bump.
- The `DeployDependencies` target copies the native lib via wildcard (`lib\win32\x64\*.dll` / `runtimes\win-x64\native\*.dll`), and `Directory.Build.targets` excludes `git2-*.dll` by wildcard, so no build-script changes should be needed beyond the two `PackageReference` version bumps.
- CI already includes a "verifies LibGit2" step (`dotnet run -- ci`), which should exercise the new version automatically.
- References: LibGit2Sharp 0.32.0 release notes; libgit2 v1.8.6 security release notes.
