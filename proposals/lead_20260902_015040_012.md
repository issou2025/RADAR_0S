# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**chore(app-check): shared debug token via dart-define — install-and-run on any device, no per-install registration**

*Project description:*
## Problem

App Check enforcement is live (#274/#276), and `AndroidDebugProvider()` with no
argument generates a **new random debug token per install**. Every fresh
`flutter run`, cleared-data install, new device, or CI runner breaks the daily
call until someone scrapes the token from logcat and registers it in the
console. Owner: "we can't be authenticating a new token every install — install
and use, for any Android device."

## Fix: one shared debug token, injected at build time

`AndroidDebugProvider({this.debugToken})` accepts a fixed token (verified in
`firebase_app_check_platform_interface` 0.4.2+1). Inject it the same way the
other secrets flow:

1. Generate one UUID, register it **once** in the App Check console
   ("Dytty shared debug token").
2. `.env`: `APP_CHECK_DEBUG_TOKEN=<uuid>` (gitignored, add to `.env.example`).
3. `AppCheckConfig.forBuild` (from #276): when `isDebug` and the dart-define is
   present, use `AndroidDebugProvider(debugToken: ...)` /
   `AppleDebugProvider(debugToken: ...)`; when absent, fall back to the
   per-install token (current behavior) so a build without the define still
   works the old way.
4. Pass `--dart-define=APP_CHECK_DEBUG_TOKEN` in: `ci.yml` debug builds (Gates
   1/2, new GitHub secret), `voice-nightly.yml`, `scripts/device-test.sh`,
   `scripts/maestro-test.sh`, and the acoustic harness build.

Result: **any** debug-channel install — local run, Gate 2 APK from the
developers group, Gate 1.5 phone, nightly runner, a brand-new device — attests
immediately with zero registration steps.

This supersedes the per-runner token-registration checklist in #277 (item 3):
one token covers every debug surface.

## Security tradeoff (accepted, documented)

The token is baked into debug APKs; anyone holding such an APK can attest as the
app. Acceptable for a small closed tester pool, and strictly better than the
pre-#274 state (no attestation at all). Mitigations:

- Debug channel only. **Release builds keep Play Integrity** — never ship the
  debug provider or token in a release build (locked by #276's tests; extend
  them to assert the token is not read in release config).
- Rotate by generating + registering a new UUID and revoking the old one if it
  leaks. Registration API (no console needed):
  `POST firebaseappcheck.googleapis.com/v1/projects/dytty-4b83d/apps/<appId>/debugTokens`
  with `x-goog-user-project: dytty-4b83d` (403 without that header).
