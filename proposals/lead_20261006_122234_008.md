# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[Enhancement]: tool/release_notes.dart compiles the whole flutter_smartschool graph for one heading constant**

*Project description:*
### Current behavior

`tool/release_notes.dart` imports `package:smartschool_mcp/src/update_check.dart` only for `UpdateChecker.notesHeading`. That file imports `cache_folder.dart`, which imports all of `package:flutter_smartschool`, so `dart run tool/release_notes.dart` JIT-compiles the library graph (HTTP client, HTML parser, ...) to write a Markdown file. Measured on 2026-10-06 on a developer's PC under its usual background load: 35 s for a cold run, 21 s for a repeat; `dart run tool/check_version.dart`, which imports only `pub_semver` and `yaml`, takes about 3 s.

That cost is why the script test in `test/release_notes_test.dart` needed a 5-minute timeout (#119), and it slows the release workflow's "write the notes" step by the same amount.

### Proposed improvement

Let the tool and the update check share the heading without the library graph: move `notesHeading` (and `notesSection`, if the tool ever needs it) to a leaf file with no package imports, e.g. `lib/src/release_notes.dart`, and have `update_check.dart` and the tool import that. Then `dart run tool/release_notes.dart` compiles in seconds like `check_version.dart`, and the timeout from #119 is slack rather than needed.

### Rationale

A release tool should not compile the whole server. The test in #119 keeps working either way; the budget stays as a ceiling.
