# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Profile a family's anatomy, content-free, and report where a generated family falls short of a reference one**

*Project description:*
## Why
Steer #836. The owner will provide highly detailed Revit families as the bar: *"these are how all families should be generated into detail … Every generation needs to be exact/similar in regards to how these will portray"*.

To hold generation to that bar we need an instrument that says, aspect by aspect, **what a reference family has that ours does not**. Examples: more forms and of which kinds, voids, reference planes and labelled dimensions, parameter groups and formulas, types, visibility and detail-level control, subcategories, nested families, connectors, materials. We already decode both sides: `tools/famdiff.py` diffs two families field by field in decoded object space, and every file carries its own schema. What is missing is a **profile of the whole family**, and a comparison that turns a reference into a ranked list of gaps.

## DONE
1. **`tools/family_anatomy.py profile X.rfa --json out.json`** reads any `.rfa` the engine can decode (Revit-born or ours) into an anatomy made of **counts and kinds only**:
   - forms by kind (extrusion / blend / sweep / revolve / swept blend), solid vs void;
   - reference planes, and how many are named or have a reference strength;
   - dimensions, labelled vs not, and EQ;
   - family parameters by group, type vs instance, spec kind, with or without a formula, shared or not;
   - number of types;
   - visibility: per-form visibility parameter bound, detail-level flags, view-specific elements;
   - subcategories, material parameters, nested and shared families, connectors by domain, symbolic lines and annotation, views.
   
   Each aspect says whether it was **decoded** or is **not yet readable**. Nothing is guessed.
2. **`compare REFERENCE.rfa OURS.rfa`** prints a fidelity report: reference has / ours has / gap, ranked by size of gap. `--json` writes the same data.
3. **Content-free by construction.** The profile holds no parameter names, no string values, no coordinates, no element ids and no GUIDs. A test profiles a generated family and asserts that none of its parameter names or string values appear in the JSON. The profile is a fact *about* a family, never a copy of it (hard rule 3).
4. **It runs and is tested from a fresh clone.** Every archetype and catalog family we generate is profiled. Two of our own families of different richness are compared, and the report names the known differences. `ours vs ours` is identical with 0 gaps.
5. **Quarantine.** Owner-supplied reference families live only in `samples/reference-families/`, which is git-ignored because the repo is public (rule 6). A test asserts that path is ignored and that `tools/sync_plugin.py`'s deny-audit refuses anything from it.

## Territory
New `tools/family_anatomy.py` and a new `src/rvt/famgen/anatomy.py` if the reader belongs in the engine. It reuses the decoders `famdiff.py` / `rvt_inspect.py` already use. Plus a new `tests/test_family_anatomy_<n>.py` with a shard drop-in, and a record in `docs/inbox/family-anatomy.md`.

## Not this issue
Closing any gap. Each gap the report finds on a real reference family becomes its own issue (see the follow-up, which waits on the owner's files). Every "behaves" claim still needs a desktop verdict (hard rule 4).
