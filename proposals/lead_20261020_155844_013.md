**Concept primer — requirements versus hypotheses:**
1. *CII physical bytes*: fixed-width FORTRAN neutral-file records. In the supplied example, `#$ ELEMENTS` groups **15 physical lines per element**. Numeric FROM/TO node identifiers are **file-local**. The first numeric element record holds FROM, TO and signed DX/DY/DZ. The supplied version's Line Number is a length-prefixed text record at **physical record 11** within an element (blank can be encoded `0`); record 10 is another text field. Node Names reference `NODENAME` records through an element pointer. Independently verify version/field semantics from original bytes/specs before relying on these observations.
2. *Connectivity*: element is a multigraph edge. Going FROM→TO adds its signed vector; reverse traversal subtracts it. Build adjacency by IDs, never by sequence in the file or numeric sort. Cyclic displacement must close within defensible numerical tolerance. Connected component means node reachability; it does **not** itself define a piping line, logical branch, flow direction or allowable T1 scope.
3. *Line Number*: a strong semantic line/run label; it does not physically join disconnected elements and may be blank or shared by several runs. Suffix-only or common-prefix grouping is a hypothesis to prove, not a given.
4. *Branch*: parent/child/tee traversal, roots, directions, and which upstream branch an anchor selects require an **explicit engineering definition**. An edge's stored FROM→TO orientation is not automatically the actual fluid-flow direction.
5. *Source–target geometry*: independent signed coordinate graphs, possibly differently numbered/discretized. Registration may require a proper rigid transform `pT = R pS + t`; apparent node or segment proximity does not prove physical identity. Some components may lack absolute coordinates. Compare line/junction/geometry/length evidence and record competing correspondences.
6. *Weighted Tab 2*: proposed Line 70 / Node Name 30 is an uncalibrated evidence display, **not** a physical-confidence probability, and must not override mandatory selector failures.
7. *Edits*: each accepted rule produces read-only proposals tied to exact TARGET0 byte offsets, original SHA-256 and exact field-width preimage. Only a separate common writer creates immutable TARGET1. Shared NODENAME pointers, overlap, overflow, ambiguous geometry, revision or incomplete search must block unsafe output.
