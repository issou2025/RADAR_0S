### Steps to reproduce

Environment: DartNative `3.45.0-0.1.pre` (framework `277f9a8c93`, engine `98a127957cb5`, Dart `3.12.0-192.0.dev`), Xcode 26.1.1, iOS 26.0 simulator (iPhone 16 Pro Max). Android not checked.

An infinite list: 20 items per page, each item followed by a separator row, so `itemCount` grows by 40 per page. The next page loads when the visible range nears the end. `FastList`'s own docs suggest `keepAliveCount` for exactly this ("combine with pagination"). Scrolling is driven by `scrollToItem` so no touch input is needed. This is the example of our paging package reduced; the reduced snippet has not been run on its own.

```dart
import 'dart:async';

import 'package:dartnative/dartnative.dart';

void main() => runApp(const KeepAliveRepro());

const _ink = TextStyle(color: Color(0xFF111111), fontSize: 15);

class KeepAliveRepro extends StatefulWidget {
  const KeepAliveRepro({super.key});

  @override
  State<KeepAliveRepro> createState() => _KeepAliveReproState();
}

class _KeepAliveReproState extends State<KeepAliveRepro> {
  final _controller = FastListController();
  int _items = 20; // two rows per item: the item and a separator
  bool _loading = false;
  Timer? _timer;

  @override
  void initState() {
    super.initState();
    _timer = Timer.periodic(const Duration(milliseconds: 500), (_) {
      _controller.scrollToItem(_items * 2 - 1);
    });
  }

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  void _onVisibleRange(int first, int last) {
    if (_loading || _items >= 300 || last < _items * 2 - 10) return;
    _loading = true;
    Future<void>.delayed(const Duration(milliseconds: 200), () {
      setState(() => _items += 20);
      _loading = false;
      print('items=$_items rows=${_items * 2}');
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      backgroundColor: const Color(0xFFFFFFFF),
      body: FastList(
        controller: _controller,
        itemCount: _items * 2,
        keepAliveCount: 30,
        onVisibleRange: _onVisibleRange,
        itemBuilder: (_, i) => i.isOdd
            ? Container(height: 1, color: const Color(0xFFDDDDDD))
            : SizedBox(height: 56, child: Text('Item ${i ~/ 2}', style: _ink)),
      ),
    );
  }
}
```

**Expected (as in Flutter's lazy lists):** `keepAliveCount` only releases the content of far-away rows. The list always has `itemCount` rows, so paging reaches all 300 items.

**What happens:** after about 10 appends the native table has fewer rows than `itemCount`: 382 native rows against 400. `scrollToItem` past that logs the error below, the visible range never reaches the trigger again, and paging stalls at 200 of 300 items. Without `keepAliveCount` the same list loads all 300 items in order (15 page requests, `loaded rows=300 unique=300 inOrder=true`).

**Workaround we use:** `keepAliveCount` stays off on every paged list, so every row stays built (O(N) memory). Our paging package passes the parameter through but its README says to leave it off for now.
