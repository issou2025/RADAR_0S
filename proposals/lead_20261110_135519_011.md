## Facts these pages state

### recipes/feature-development-loop.md

#### #what-you-build
From `recipes/feature-development-loop.md` › (intro):
- The recipe plans a feature and revises the plan until you approve it, implements it, then reviews the result and lets you pick the findings to fix.

#### #before-you-start
From `recipes/feature-development-loop.md` › (intro):
- Agent steps run in the worktree, so the loop needs a Git worktree (one clause linking `guides/running-blueprints.md#run-in-place-without-a-worktree`).

#### #the-blueprint
From `recipes/feature-development-loop.md` › The Blueprint:
- Create `.dovo/catalog/blueprints/feature.yml`.
- The blueprint takes a required `feature` input, aliased `-f` and `--feature`.
- `plan-loop` runs at most 3 iterations until `approve` selects `approve`, asking you when the limit is reached.
- `plan` writes `PLAN.md` from the feature, the previous plan (`{{ artifacts.plan.content }}`) and the reviewer's comment, may read and write, and publishes `PLAN.md` as artifact `plan`.
- `approve` is a `select` ask showing the `plan` artifact, with options approve (no comment), revise (comment required) and deny (`fail: true`).
- `implement` is an agent step that may read, write and run shell commands, given the approved plan.
- `review-loop` runs at most 3 iterations until `triage` selects nothing, asking you at the limit.
- `review` writes findings to `review.json` and publishes it as artifact `review`.
- `triage` is a `multiselect` ask whose options come from `review.json` (`findings`, value `id`, label `summary`), with an optional comment.
- `fix` fixes only the selected findings, with their details and the comment, and changes nothing when the list is empty.
- `cleanup` runs `rm -f PLAN.md review.json`.

#### #run-it
From `recipes/feature-development-loop.md` › Running the Recipe, What happens:
- Run it with `dovo run feature --feature "<description>"`.
- Review the result with `dovo diff`, then apply it with `dovo worktree apply` (in the termynal session after the run).

#### #how-it-works
From `recipes/feature-development-loop.md` › What happens:
- `plan` writes `PLAN.md`, published as the `plan` artifact, and `approve` shows it.
- Choosing `revise` with a comment plans again with that feedback; `approve` ends the loop; `deny` fails the run.
- `implement` builds the approved plan.
- `review` writes findings to `review.json`, `triage` lists them for you to pick, and `fix` addresses only those.
- Selecting nothing makes `selected_count` `0` and ends the loop; otherwise it reviews again, up to `max_iterations`. Because `until` is checked after the whole iteration, `fix` runs once more with the empty selection before the loop ends (verify at the head).
- `cleanup` deletes the working files so they are not part of the diff.

#### #add-quality-gates
From `recipes/ai-code-patcher.md` › (intro), The Blueprint:
- You can put lint and test steps between the agent steps, so a change that breaks them never reaches review.
- A lint step runs your linters, asserts exit `0`, and retries twice 1000 ms apart before asking you.
- A test step runs your tests and asserts exit `0`.

### recipes/ci-cd-automation.md

#### #what-you-build
From `recipes/ci-cd-automation.md` › (intro):
- The same blueprints run on your machine and in CI.

#### #the-workflow
From `recipes/ci-cd-automation.md` › Example: GitHub Actions Workflow:
- Create a workflow file under `.github/workflows/`, triggered on pushes and pull requests to `main`, named for what the job does.
- The workflow checks out the code and sets up Python 3.13.
- It installs Dovo with `pip install devexhq-dovo`.
- It runs `dovo config validate`.

From `guides/failure-handling-and-resume.md` › Non-Interactive & CI/CD Execution:
- In CI or other unattended runs, pass `--no-tty`, so the run never waits for input.
- A step or loop that must fail the job should use `abort`.

#### #read-the-result
From `guides/failure-handling-and-resume.md` › Non-Interactive & CI/CD Execution:
- Read `session_status` or `paused_prompt_id` from the `--format json` run result to tell a paused run from a completed one.

From `recipes/ci-cd-automation.md` › Key CLI Flags for CI/CD:
- To fail the job on a paused run instead, check `session_status` in the `--format json` run result, or use `abort` in the blueprint.

#### #answer-a-paused-run
From `guides/failure-handling-and-resume.md` › Non-Interactive & CI/CD Execution:
- With `--no-tty`, a `prompt_user` decision pauses the run and exits `0`, as an `ask` step does, so the job never waits; answer it later with `dovo resume --answer` (linking `guides/prompts.md#answer-a-headless-run`).
