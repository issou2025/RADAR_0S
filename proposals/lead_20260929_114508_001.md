# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**feat(addin): update the Revit add-in automatically**

*Project description:*
## Problem

The add-in never updates itself. Users must download and run a new MSI or run `winget upgrade`, and nothing tells them a new version exists. Loaded assemblies are locked while Revit runs, so the update cannot replace files in place.

## Change

1. **Check.** After Revit starts, off the Revit API thread, at most once per 24 hours and with a short timeout, read the latest stable GitHub release through the system proxy. Never block startup.
2. **Download and verify.** Download the MSI that matches the installed scope and verify its SHA256 against the published checksum before use.
3. **Apply.** Per-user installs: a small updater process waits until the last Revit process exits, runs the per-user MSI silently (no elevation), and writes the result to a log. The MSI stays the only owner of installed files, so uninstall, WinGet and Apps and Features keep showing the right version.
4. **Per-machine installs** need elevation and are never updated silently. They show "update available" in the activity pane with a link.
5. **Tell the user.** After an update, the activity pane shows the new version once with a link to the release notes. A failed or rejected update is shown there with the reason.
6. **Opt-out at three levels:** an MSI property for IT deployment, a machine setting under ProgramData, and a user setting in `settings.json`. Machine settings win.
7. An update never changes settings, including the workstation read-only gate.

## Acceptance

- A per-user install of 0.x.0 runs the new stable release after Revit is closed and started again, with no user action.
- Several Revit processes: nothing is installed until the last one exits.
- A checksum mismatch installs nothing and the activity pane says why.
- With updates disabled at any level, nothing is checked or downloaded.
- Pre-releases are never installed automatically.
- Tests cover version comparison, the throttle, checksum verification and opt-out precedence.

## Open questions

- Signing: apply to SignPath Foundation (free for open source, signs in CI); fall back to a Certum open source certificate. Unsigned binaries trigger SmartScreen and may be blocked by corporate policy.
- Verify on a live Revit before implementing: does Revit ask the unsigned add-in security question again after every update, and does a signed build avoid it.
- Alternative to 3: versioned add-in folders with the `.addin` path switched at next start. It needs no wait for Revit to close, but the files then live outside the MSI and uninstall must clean them. Chosen against for now; revisit if waiting for close proves too slow in practice.


Depends on #87 for the complete bundle manifest. Releases already publish `SHA256SUMS.txt`.
