## Goal (user story)
As a user, I tap the mic and speak in Arabic, Hebrew or English (whatever I choose, not only the app language). The transcript appears in the text box, I fix it if needed, and only then do I submit it for analysis.

## Current state (verified, file:line)
- **Flutter** (the functional reference only):
  - `mobile/lib/services/speech_to_text_capture_service.dart` wraps `speech_to_text`: it initializes, reports `unavailable` / `permissionDenied`, and listens with partial results (lines 21-48). It never checks that the locale is supported.
  - The locale is the bare app language tag (`mobile/lib/features/capture/capture_composer_screen.dart:84`), but iOS expects region tags (`ar-SA`, `he-IL`) and Android can report Hebrew as `iw-IL`.
  - The feature is off by default (`ENABLE_PILOT_VOICE`, `mobile/lib/config/app_config.dart:70-73`), with a kill switch (`:90-93`).
  - The transcript lands in the editable field and is never auto-submitted (`capture_controller.dart:222`).
- **React Native:**
  - UC-2.R2 (#172) step 9 defines `src/features/capture/voice/VoiceButton.tsx` and an injected `SpeechCaptureService` interface (`start()`, `stop()`, `onPartial`, `onFinal`, `status`). Its default is a `NoopSpeechCaptureService` that reports `unavailable` behind `features.voice=false`.
  - **This issue supplies the real implementation.**
- Launch decision: on-device recognition via `expo-speech-recognition` (a config plugin over `SFSpeechRecognizer` and Android `SpeechRecognizer`).

## Implementation steps
1. **Install and native config:** `npx expo install expo-speech-recognition`. In `app.config.ts`:
   ```ts
   ['expo-speech-recognition', {
     microphonePermission: 'MaybeSitter uses the microphone only while you hold the mic button to dictate a reminder.',
     speechRecognitionPermission: 'Your device turns your speech into text. MaybeSitter never receives the audio.',
     androidSpeechServicePackages: ['com.google.android.googlequicksearchbox', 'com.google.android.as'],
   }]
   ```
   - The plugin adds `RECORD_AUDIO` and the Android `<queries>` entry for `RecognitionService`.
   - Localize the iOS permission strings through Expo's top-level `locales` config: `locales: { ar: './locales/ios/ar.json', he: './locales/ios/he.json' }`, each holding `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription`.
2. **Flag:** `features.voice` defaults to **true**. `EXPO_PUBLIC_KILL_SWITCH_VOICE=true` hides the mic (read in `src/config/env.ts`).
   - **Decision:** a new launch name, not the pilot names; RN has no legacy tests tied to them.
3. **Locale resolver:** a pure `src/features/capture/voice/speechLocale.ts` with `resolveSpeechLocale(language: 'ar'|'he'|'en', available: string[], onDevice: string[]): { kind: 'supported', localeId, onDevice: boolean } | { kind: 'unsupported', language }`.
   - Get `available` and `onDevice` once per session from `ExpoSpeechRecognitionModule.getSupportedLocales({})` (`locales`, `installedLocales`).
   - Normalize for matching only (`_` → `-`, `iw` → `he`), but return the platform's original id string.
   - Preference order:
     - ar: `ar-PS, ar-JO, ar-IL, ar-LB, ar-SY, ar-SA, ar-AE`, then any `ar-*`
     - he: `he-IL`, then `iw-IL`
     - en: `en-US, en-GB`, then any `en-*`
   - Within that order, prefer a locale present in `onDevice`.
4. **`ExpoSpeechCaptureService`** in `src/features/capture/voice/expoSpeechCaptureService.ts`, implementing `SpeechCaptureService`:
   - `start({ language })`:
     1. `requestPermissionsAsync()`. If denied → `permissionDenied`.
     2. Resolve the locale. If unsupported → `localeUnavailable` (a new status value added to UC-2.R2 (#172)'s union); don't start the recognizer.
     3. Otherwise `ExpoSpeechRecognitionModule.start({ lang: localeId, interimResults: true, continuous: false, addsPunctuation: true, requiresOnDeviceRecognition: onDevice })`.
   - Wire `useSpeechRecognitionEvent('result' | 'error' | 'end')` to `onPartial`, `onFinal` and `status`.
   - Map errors: `not-allowed` → `permissionDenied`; `language-not-supported` → `localeUnavailable`; `audio-capture`, `service-not-allowed` and `network` → `unavailable`.
   - **Decision:** prefer on-device recognition. If the language isn't installed on-device, use the OS recognizer (Apple or Google) under the disclosure in step 7. On Android, offer `androidTriggerOfflineModelDownload({ locale })` as an optional action in the banner.
5. **Speech language chip:** `VoiceLanguageChip.tsx` next to the mic shows "عربي / עברית / English". It defaults to the app language, and the choice persists in AsyncStorage under `speech.language.v1`.
6. **Fallback UX** in the composer banner (design system `Banner`), localized in ar, he and en:
   - `localeUnavailable`: "Voice in Arabic isn't available on this device. You can type, or switch voice language." It has an action that opens the chip.
   - `unavailable`: "Voice isn't available right now. Type instead."
   - `permissionDenied`: an explanation plus a button that calls `Linking.openSettings()`.
   - Whatever the failure, the field keeps any transcript and stays editable.
7. **Disclosure:**
   - On Android, before the first mic use, show a one-time sheet: "Your device's speech service turns your voice into text. The audio is not sent to MaybeSitter." Remember it with the AsyncStorage flag `speech.disclosureShown.v1`.
   - On iOS, the system permission string covers it.
8. **Editable, never auto-submitted.**
   - On `onFinal`, append the transcript to the field, focus it (`ref.focus()`), and set `writingDirection` from the transcript's first strong character, using a `detectDirection(text)` helper added to UC-1.R3 (#156)'s `src/i18n/bidi.ts`.
   - Nothing calls `useCapture()` automatically.
9. **Analytics**, only with analytics consent, via `useRecordAnalytics()`: `voice_abandoned` (no text) and `voice_locale_unavailable` (`{ language }` only).

## Out of scope

- Any change under `mobile/`.

## Acceptance criteria

- [ ] Resolver unit tests:

  - `[ar_SA]` with ar gives `ar_SA`
  - `[en_US]` with ar gives unsupported

- [ ] With an unsupported locale, the banner shows, `start` is never called, and the field stays enabled.
- [ ] After dictation the transcript is editable, and `useCapture` isn't called until Analyze is tapped (RNTL spy).
- [ ] An Arabic transcript renders right to left in the field (`writingDirection: 'rtl'`).
- [ ] The prebuild iOS project includes the localized `ar` and `he` `InfoPlist.strings`.

## Privacy & security impact
Audio is processed by the OS speech service (on-device where available, otherwise Apple or Google), never by MaybeSitter servers. Only the edited text is sent, under the same rules as typed text. The disclosure copy must match the privacy policy and the App Store label ("Audio Data: not collected by developer" stays true only if we never upload audio).
