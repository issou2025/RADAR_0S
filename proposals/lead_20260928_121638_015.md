# Project Proposal — Autocad Drafting

## Project Understanding
You need assistance with: 
**User Story: every uncaught Dart error is reported exactly once, and nothing is lost when the app is backgrounded**

*Project description:*
## 1. Story Statement

As a developer reading crash telemetry from an `otel_zone` app,
I want each uncaught Dart error to appear exactly once, locally and on the wire, and to be flushed before the OS can kill a backgrounded app,
so that the counts I see are real and the last fault before a kill is not lost in memory.

---

## 2. Real Intent

The real intention behind this story is:

> The four-channel wiring is the package's core promise. Two of the channels currently misbehave (double console dumps, a clobbered handler), and nothing flushes the batch queue when the app goes to the background.

---

## 3. Background and Context

Currently:

* `FlutterError.onError` chains to the previous handler, which by default *is* `FlutterError.presentError` ([Flutter assertions.dart](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/foundation/assertions.dart), `static FlutterExceptionHandler? onError = presentError;`). `presentFlutterErrors: true` dumps twice; `false` still dumps once ([otel-zone.dart#L218-L227](https://github.com/vaam-apps/flutter-otel-zone/blob/58a420a82a0e8c7cfc51fccd39b02b39be8ed73b/lib/src/otel-zone.dart#L218-L227)).
* `PlatformDispatcher.instance.onError` is overwritten, not chained ([#L232](https://github.com/vaam-apps/flutter-otel-zone/blob/58a420a82a0e8c7cfc51fccd39b02b39be8ed73b/lib/src/otel-zone.dart#L232)). A handler an app or plugin installed earlier silently stops running.
* No `AppLifecycleListener`. The `BatchLogRecordProcessor` queue (1 s delay) dies with a process the OS kills in the background.

We need to change this because:

* Parity work in Stories 2–4 builds on these channels.
* Double records inflate error counts on dashboards.

## 5. Acceptance Criteria

### Functional Criteria

* [ ] Given `presentFlutterErrors: false`, when a framework error occurs, then nothing is printed by `otel_zone` and the error is reported once.
* [ ] Given `presentFlutterErrors: true`, when a framework error occurs, then it is presented exactly once.
* [ ] Given a `PlatformDispatcher.onError` handler installed before `runGuarded`, when an error escapes the engine, then both the report and the previous handler run.
* [ ] Given pending records, when the app moves to `paused` or `detached`, then the log provider is force-flushed.

### Negative / Edge Cases

* [ ] Given a custom (non-default) previous `FlutterError.onError`, when an error occurs, then it is still called.
* [ ] Given OTel never started, when the app is paused, then the flush is a no-op and does not throw.

### Non-Functional Criteria (Quality Attributes)

* [ ] Performance: the flush is fire-and-forget and does not block the lifecycle callback.
* [ ] Compatibility: no public API change.

## 9. Implementation Notes

* Skip the chained call when `previousOnError == FlutterError.presentError`.
* Chain `PlatformDispatcher.onError` and OR the results.
* Use `AppLifecycleListener(onPause:, onDetach:)` inside `start()`, guarded by `safely`.

Constraints: the package's rule: telemetry never throws into the app.

These notes are guidance, not unquestionable truth.
