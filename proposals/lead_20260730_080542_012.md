# Project Proposal — Python Automation

## Project Understanding
You need assistance with: 
**status executions/execution return hardcoded placeholder data instead of the event store**

*Project description:*
## Summary

`ooo status executions` and `ooo status execution <id>` are placeholder stubs that print hardcoded example data instead of reading the event store. They return the same output even when no database exists, so the CLI silently reports fabricated execution history.

## Reproduce

```bash
PROBE_HOME=$(mktemp -d)
mkdir -p "$PROBE_HOME/.ouroboros" "$PROBE_HOME/.codex"
printf 'orchestrator:\n  runtime_backend: codex\nllm:\n  backend: codex\npersistence:\n  enabled: true\n  database_path: ouroboros.db\n' > "$PROBE_HOME/.ouroboros/config.yaml"
printf '{}\n' > "$PROBE_HOME/.codex/auth.json"

HOME="$PROBE_HOME" ouroboros status executions --limit 1
```

No `ouroboros.db` is created in this HOME.

### Actual

```
   Recent Executions
┏━━━━━━━━━━┳━━━━━━━━━━┓
┃ Name     ┃  Status  ┃
┡━━━━━━━━━━╇━━━━━━━━━━┩
│ exec-001 │ complete │
│ exec-002 │ running  │
│ exec-003 │  failed  │
└──────────┴──────────┘
```

`ouroboros status execution exec_fixture --events` prints:

```
Would show details for execution: exec_fixture
Would include event history
```

### Expected

Executions read from the configured event store, or an explicit "no executions found" / "database unavailable" message. Never fabricated rows.

## Cause

`src/ouroboros/cli/commands/status.py` (confirmed on `main` @ `debb9d07`):

- L261-265 `# Placeholder implementation with example data` — `exec-001/002/003` literal list
- L289-292 `# Placeholder implementation` — `print_info(f"Would show details for execution: {execution_id}")`

## Impact

Operators cannot distinguish a healthy run, an empty store, and an unreachable database. Any automation or human decision based on `ooo status executions` reads fabricated state as real. This is more damaging than a plain error because it fails silently and looks successful.

Related: `ooo status health` reports `Database: ok` based on `exists()`/`is_file()`/readability only, so a 0-byte file also passes. An empty-but-present store therefore looks healthy while executions show fake rows.

## Suggested direction

Query the persisted event store, and if the placeholder must remain temporarily, make it fail loud (non-zero exit plus an explicit "not implemented" notice) rather than emitting plausible-looking data.
