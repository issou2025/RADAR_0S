# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Several views of one drawing: split view, a second window, and editing dimensions and notes on a sheet**

*Project description:*
**Feature idea (2026-10-28), from the decision on several open drawings.** Today a drawing has one canvas: the model, or a sheet as it prints. Three related things build on each other:

1. **Split view in one window:** the model on one side and a sheet (or another part of the model) on the other, both live.
2. **A second window on the same drawing:** for example the model on one monitor and its sheet on the other. It has to be a second window in the same Drift process (an egui viewport), not a second Drift, because two processes can't share one drawing or its undo history. A tab dragged out of the planned tab bar still opens a different file in its own window.
3. **Editing through a view on a sheet:** drag a dimension's label or extension lines, edit its value, move a note or its leaders, all on the sheet. Today the sheet editor only moves, crops and deletes views; dimensions and notes are edited in the model.

**Why it matters:** Revit users work with the model on one screen and the sheet on the other, and edit annotations on the sheet. SolidWorks, Illustrator and Affinity all offer a second window on the same document.

**Sketch**
- Each canvas is a *view* with its own camera (screen → paper → model for a sheet view), over one shared drawing: one undo history and one selection. A pick on the sheet highlights in the model. A gesture belongs to the view it started in.
- Sheet editing maps the pointer through the view's scale and centre to model coordinates and reuses the model canvas's hit tests and gestures, so the tools aren't written twice. An edit is an ordinary model edit: one undo step, seen in every view.
- To enter a view: double-click it (like Revit's Activate View or AutoCAD's MSPACE), or click inside to pick contents and the frame or title to pick the view. Decide when this is built.
- Dimensions and notes first. Model geometry stays read-only on sheets at first, so it can't be moved by accident.
- Placement is shared: moving a label on a 1:10 detail also moves it in the model and on a 1:50 plan. The existing "only in these views" setting keeps a crowded dimension off one view. Per-view position overrides (Revit-style) would need a file-format addition and are left until users hit the clash.

**Costs to measure first**
- The sheet preview rebuilds the page after every change. On a big imported drawing a live sheet view may need to refresh on pointer-up rather than during drags.
- The canvas renderer holds one set of buffers, so two model canvases in one frame need per-view buffers (about a day). Model beside sheet doesn't hit this, because the sheet is drawn differently.
- A second window reruns the app's pass for each window, so the second window should draw only the canvas. Keyboard and text entry in a second window need testing on macOS.

**Prerequisite:** the planned tabs refactor splits per-drawing state from per-view state (camera, sheet shown, view drags), so this work doesn't need a second refactor.

**Rough size:** L (split view about a week; second window 3–4 days plus Mac testing; sheet editing of dimensions and notes 1–1.5 weeks). Estimates, not measured.

**Status:** filed during the usability/bug-fix phase, after tabs. Rank against the roadmap (#5) before starting.
