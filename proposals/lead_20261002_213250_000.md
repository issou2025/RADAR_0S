# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Benchmark token usage before and after graph-first/tool-routing changes**

*Project description:*
## Goal

Measure whether the model graph and future tool-surface changes actually reduce token usage and tool-call overhead in realistic Revit workflows.

## Why this is needed

The graph was introduced specifically as a cheap routing layer, but there is currently no repeatable benchmark showing how much context/result volume it saves versus broad live queries.

## Proposed benchmark scenarios

Include representative workflows such as:

1. Find all fire alarm sounders on a level and inspect loop assignments.
2. Find everything fed by a selected panel.
3. Locate devices in a specific room/space.
4. Inspect a category across a large model.
5. Find a target in a linked model once linked-graph support exists.

For each scenario compare:

- broad live-query workflow
- graph-first workflow
- graph-first + reduced/dynamic tool surface

Capture:

- tool-schema/context token estimate
- tool result size
- number of tool calls
- elapsed time
- graph build/update cost
- number of live Revit elements actually fetched

## Acceptance criteria

- A repeatable benchmark harness or script exists.
- Results can be reproduced against at least one small and one large sample model.
- Before/after metrics are recorded in a simple report.
- Benchmarks separate tool-schema cost from tool-result cost.
- Future graph/router PRs can use the benchmark to detect regressions.
