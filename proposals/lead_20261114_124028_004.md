# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Long-running tools time out after 30 s while Revit keeps working**

*Project description:*
## What happens

Every tool uses `DEFAULT_TIMEOUT = 30.0` ([`main.py` L35](https://github.com/Demolinator/revit-mcp-server/blob/3de7db6a20637d15cf5e3d2b97e2fd8aae09c419/main.py#L35)). The only exceptions are the status check (10 s) and view images (60 s).

On large models, `export_ifc`, `check_clashes`, `export_document`, `get_material_quantities` or `analyze_model_statistics` can take longer than 30 s. The tool then returns "Revit did not answer within 30s" while Revit is still working, and possibly still changing the model.

The AI is told the call failed, and its next call can overlap with the one still running, which is the situation in #23.

## Expected

Slow operations get enough time, the timeout can be configured, and the timeout message says the operation may still be running.

## Suggested fix

- Pass a per-tool `timeout` for the slow tools (e.g. 300 s).
- Add a `REVIT_TIMEOUT` environment variable for the default, documented with the others in `main.py` and the README.
- Reword `TIMEOUT_HINT` to say the operation may still be running in Revit, and to check before retrying.

## How to check

Point the server at a slow fake endpoint (see `tests/test_offline.py` for how the HTTP client is tested) and confirm each tool's timeout.
