# Project Proposal — Pdf To Revit

## Project Understanding
You need assistance with: 
**H5.1 — define minimal executable Observation Bundle Candidate contract**

*Project description:*
Parent: #607

## Objective

Turn the already-documented Project Anatomy `Observation Bundle Candidate` exchange seam into the smallest executable governed contract needed by H5 qualification.

Do not create a new execution-result authority, persistence owner, workflow engine or adapter framework.

## Verified current state

`PROJECT_UNDERSTANDING_ADAPTER_CONTRACT.md` already defines the semantic chokepoint:

```text
Task Contract + bounded source/project context
-> external adapter/runtime
-> Observation Bundle Candidate
 + Evidence Pack Candidate
```

It explicitly states that `Observation Bundle Candidate` is the APU specialization of the generic bridge `result_candidate` slot and that the executable schema is currently non-implemented.

`pantheon-mvp` already owns append-only typed execution results and review dispositions. `execution_results.py` stores candidate payloads with false authority posture and already carries APU-oriented kinds such as `spatial_observation`, `apu_object_mapping` and `relation_candidate`.

Therefore H5.1 should add one bounded typed result contract, not a second persistence owner.

## Contract responsibility

Add a stable responsibility-based schema for one Observation Bundle Candidate. Version/generation belongs in schema metadata/content/Git history, not the active filename.

The contract should remain an exchange/candidate shape and validate at least the information required to test H5 scenarios.

## Minimal top-level shape

Candidate fields, subject to inventory of existing shared refs/vocabularies before implementation:

```text
observation_bundle_id
project_ref
task_contract_ref
basis
method
observed_at
scope
coverage
limitations
source_representations[]
attribute_claim_candidates[]
relation_claim_candidates[]
gaps[]
withheld[]
warnings[]
operational_outcome
authority
```

Reuse existing Project Anatomy V0.2 schemas/typed refs wherever possible. Do not duplicate their primitive definitions inside this contract.

## Basis

Must preserve exact source/baseline context where available without inventing missing provenance:

```text
source_artifact_refs
source version refs / exact digests
revision_set_ref only when an admitted/reviewed baseline exists
```

No requirement that every source has every metadata field.

```text
missing metadata != guessed metadata
```

## Method provenance

Bounded method data should resolve at least:

```text
capability_id
binding_id
operation_id when applicable
adapter/runtime identity/version
run/request correlation ref
```

Do not place hidden reasoning, full logs or provider routing state in the bundle.

## Coverage

Coverage must support H5 absence-safety scenarios without becoming a universal completeness engine.

It should be able to declare bounded dimensions such as:

```text
source snapshot/version
levels/zones
categories/classes
phases when source semantics require them
sheets/pages/regions
views
property groups
measurement modes
```

The contract must distinguish enough posture to express at least:

```text
complete for declared scope
partial for declared scope
unknown completeness
```

Do not infer absence from `partial` or unknown coverage.

## Candidate primitives

### source_representations

Validate against the active canonical `source_representation` contract. Unresolved stable identity is valid.

### attribute_claim_candidates

Validate against active canonical `attribute_claim` semantics. Claims may target source representations or already-known stable objects where bounded context supports that target.

Requirements/prescriptive material must not be encoded as observed claims.

### relation_claim_candidates

Validate against active canonical `relation_claim` semantics.

`identity.represents` remains candidate-only and may target only a stable object already supplied by governed context. Bundle validity must not create or accept identity automatically.

## Operational material

`gaps`, `withheld`, `warnings` and `operational_outcome` remain result-state information, not project facts.

Initial closed outcome vocabulary should reuse documented semantics where possible:

```text
success
withheld
blocked
refused
failed
cancelled
rolled_back
```

Do not create synthetic `unknown` attribute claims for operational gaps.

## Authority boundary

The contract must explicitly preserve:

```text
is_fact = false
is_evidence = false
is_decision = false
is_memory = false
is_apu_write = false
authorizes_external_effect = false
```

or equivalent existing bridge authority semantics after exact inventory.

A valid bundle is only a candidate result.

## Required contract fixtures

Implement examples/tests covering at least:

1. complete simple source observation;
2. unresolved source representation with no stable object;
3. partial coverage where absence is not asserted;
4. conflicting source observations retained as separate candidates;
5. candidate `identity.represents` toward a known stable object;
6. requirement-like/prescriptive observation refused as ordinary observed claim where schema semantics allow that check;
7. gap/withheld state without synthetic project claim;
8. failed/refused operational outcome with zero APU authority;
9. multi-granularity bundle (e.g. system + component observations) without forcing one source occurrence per stable object;
10. exact source digest/version provenance retained.

## Compatibility / non-duplication checks

Before adding fields, inventory and reuse:

- active APU V0.2 shared refs;
- generic bridge/result-candidate semantics;
- execution result authority fields;
- existing coverage/freshness shapes in Revit observation docs/contracts;
- existing Evidence Pack Candidate separation.

Do not create parallel synonyms for existing concepts.

## Out of scope

- PostgreSQL persistence owner;
- adapter ingestion API;
- automatic application to Project Anatomy;
- new stable-object creation command;
- Evidence/Proof admission;
- Revit/IFC/PDF implementation;
- semantic lens engine;
- Profile/Predicate Registry unless a fixture demonstrates an actual missing governed vocabulary.

## Exit criteria

H5.1 Next side is complete when:

- one canonical schema + examples/tests are green;
- existing V0.2 primitive schemas are reused, not copied;
- coverage can safely express H5 partial/unknown cases;
- candidate identity and claims remain non-authoritative;
- adapter contract documentation points to the executable schema and no longer calls it non-implemented;
- no new persistence/runtime owner is introduced.

After merge, `pantheon-mvp` should add `observation_bundle` as a typed existing Execution Result kind and validate the vendored exact contract there, reusing existing append-only storage/review.
