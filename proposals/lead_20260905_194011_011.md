## Problem

`OpenTarget` is `"android" | "ios-sim"` only (`packages/cordierite/src/cli/open-target.ts:16`). A physical Android phone over USB works through `adb reverse` + `am start`, but a physical iPhone can only be paired by a human scanning the QR code. `cordierite_connect`'s auto-detection therefore never finds a wired iPhone, and the docs do not say so explicitly.

## Expected

1. Investigate whether Xcode 15+ `xcrun devicectl` can open a URL / launch the app with a URL payload on a wired or paired iPhone (e.g. `devicectl device process launch ... --payload-url`, or `devicectl device info apps` + an intent equivalent). Record the findings in the issue.
2. If it can: add `--open ios-device` (and `target: "ios-device"` for `cordierite_connect`), with device enumeration via `devicectl list devices --json-output` and the same ambiguity rules as the simulator path. The advertised address must **not** be forced to `127.0.0.1` for a physical device; it should use the normal LAN detection, since there is no `adb reverse` equivalent on iOS.
3. If it cannot: document clearly in `packages/cordierite/README.md` and the skill that physical iPhones use the QR/deep-link flow, and make `cordierite_connect`'s "none detected" note mention it.

## Acceptance

- Either a working `ios-device` target with unit tests over the injectable `ExecFn` seam (no Xcode needed in CI), or the documentation update, plus the investigation notes on this issue.
