## Observed gap
At `kaori/review/staging-uat@4f5f098214d40296037ad6e941f65626c8ad0df4`, normal successful Local/LDAP/SSO authentication uses `record_successful_authentication` and `establish_authenticated_session` but does not advance `User.auth_session_version`. The loader checks the generation, yet a second login does not invalidate the first browser. Activity Audit records user/provider/IP/browser but no per-login correlation reference. A shared account consequently can be concurrently used with ambiguous activity attribution.

## Outcome
Enforce **one active authenticated login generation per human KAORI user** across local credentials, LDAP, and browser SSO using the existing session-generation architecture; new login replaces the prior login. Generate one non-secret, opaque login-session correlation reference for authentication audit. Avoid new auth frameworks, schema or provider dependence.

## Scope / architecture
- Login success advances `auth_session_version` **atomically** in PostgreSQL; avoid read-modify-write lost updates and account for racing concurrent logins. Retain correct generation minted by the exact transaction even if another login completes before browser session establishment.
- Bind the resulting authenticated Flask-Login session/remember cookie to the issued generation. Old sessions and remember cookies become invalid on next authenticated request, across browsers/web instances; new login wins. No per-page external LDAP/SSO calls.
- Preserve password-change/session invalidation, disable-provider revocation (#2982), local break-glass admission, and role/RBAC checks. Reject disabled/deleted accounts on admission, with DB-failure rollback and no usable new authenticated session.
- Add a non-credential random session reference to successful sign-in/sign-out Activity Audit (including normalized replaced-session reason where feasible). Never store cookie, password, token, raw authorization code, or raw SSO payload in audit.
- Update canonical authentication security/test documentation and focused positive, negative, concurrency, remember-cookie and regression tests. Preserve CSRF, current logouts, normalized errors.
- Perform risk-based Dev Container UAT with two browsers: Local/LDAP/SSO where available, alternating logins, old-session denial, latest-session continuity, remember-cookie denial, logout, audit correlation. Capture exact SHA and sanitized evidence.

## Acceptance criteria
1. Two independent logins for one User cannot **both** remain authorized after both login transactions complete; one issued generation is authoritative, regardless of response ordering.
2. A new login revokes old sessions/remember cookies on their next request. Other user accounts and Local Database break-glass are unaffected by somebody else's login.
3. Disabled user, failed login, unavailable DB and interrupted issuance do not generate a successfully usable new login session. Old generation invalidation is commit-consistent.
4. Authentication Activity Audit preserves exact actor/provider and a non-sensitive per-login correlation reference; failed attempts never impersonate a target actor.
5. Focused code/style/security tests and guided human two-browser UAT evidence are recorded; no claims of PASS before execution.

## Out of scope / follow-ups

- Cryptographic device binding: copied identical signed session cookies are not distinguished by generation enforcement. Single-login-generation is not a guarantee of one physical person.
