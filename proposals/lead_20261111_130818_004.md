# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Inspect Hive (hive_ce) boxes, including your own objects**

*Project description:*
Many Flutter apps keep settings, caches and offline data in Hive boxes. This issue adds `xray_hive_inspector`, a small package that shows an app's `hive_ce` boxes in xRay's **Database** tab (see #56), including custom objects, which no file-based viewer can show. Setting it up is one line in the app.

## Background

xRay has two sides: the **SDK**, which you add to your Flutter or Dart app, and the **desktop app**, which shows what is happening inside that app. Each kind of data has an **inspector** you list in `XRayInspectorServerConfig(inspectors: [...])`. #56 adds the Database tab and the shared database support; each database engine then needs its own inspector package.

Hive is a key-value database: a **box** holds entries, each with a key and a value. Values can be custom objects written by the app's `TypeAdapter`, which stores fields by number, not by name. Hive boxes can't be opened twice (that corrupts them), so a viewer must go through the boxes the app already opened. Only [`hive_ce`](https://pub.dev/packages/hive_ce) is in scope: the original `hive` package is unmaintained.

## User story

As a Flutter developer whose app uses Hive, I want to pass my open boxes to an xRay inspector, so that I can see and fix their entries, including my own objects, from the desktop app while the app runs.

## Current behaviour

There is no way to see Hive data in xRay or in a regular viewer: a box file can't safely be opened outside the app, and custom objects are unreadable without the app's adapters.

## Expected behaviour

1. The app adds `xray_hive_inspector` and registers `XRayHiveInspector(boxes: [settings, users])` with the boxes it already opened, lazy boxes included.
2. Each box shows in the Database tab as a collection with a `key` and a `value` column, with its entry count.
3. Primitives, lists and maps show as JSON and can be edited.
4. A custom object shows as JSON with field names when it has a `toJson()`, or as its `toString()` otherwise. Registering an `XRayHiveCodec<T>(toJson: …, fromJson: …)` makes that type editable; the value is stored again through the app's own `TypeAdapter`.
5. Search replaces the Query view (Hive has no query language). Keys sort in natural order (`item2` before `item10`).
6. Read-only by default; `allowWrites: true` turns on adding, editing and deleting entries. The app's `box.watch()` and `ValueListenableBuilder`s fire on every edit.

## Acceptance criteria

- [ ] `XRayHiveInspector(boxes: [...])` lists every passed box, regular and lazy, with entry counts.
- [ ] A model with `toJson()` shows its fields without any setup; one without shows its `toString()`.
- [ ] With a codec and `allowWrites: true`, editing an object stores it through the app's adapter, and `box.watch()` fires.
- [ ] Without a codec, custom objects are shown read-only.
- [ ] Encrypted boxes show decrypted values, and edits are encrypted by the box.
- [ ] The package is published on pub.dev with a docs page and an example.

## Out of scope

- The original `hive` package.
- Listing boxes the app has not opened (Hive can't list boxes without opening them).
- Editing objects without a codec.

## Edge cases

- A lazy box with many entries → only the visible page is read, unless a search or a sort by value needs them all.
- An object whose `toJson()` throws → it falls back to `toString()` instead of breaking the box.
- Keys of mixed types (int and String) → all shown, sorted in a stable order.
