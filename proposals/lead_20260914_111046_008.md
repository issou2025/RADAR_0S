### Surface

Desktop app (macOS), sidebar Search / command palette Recent sessions. macOS `26.6.2 (25G83)`, Apple Silicon / arm64, English dark UI.

### Agent provider (if relevant)

Multiple / cross-provider. The recorded list included both Codex and Claude sessions; the fallback is provider-independent.

### Steps to reproduce

1. Have multiple eligible, unarchived sessions whose associated agents have no nonempty `metadata.name` / display name.
2. Open sidebar Search without entering a query.
3. Inspect the Recent sessions primary labels.
4. Try to distinguish the sessions or search for one using the visible project/workspace context.

### Expected behavior

Every Recent sessions row should have a recognizable user-facing primary label. Prefer the explicit session/agent name, then a safe task or first-user-prompt summary. If no usable text exists, show an explicit unnamed-session fallback plus provider/context and only a shortened secondary identifier. Visible project/workspace context should participate in matching.

### Actual behavior

Unnamed sessions use the complete internal agent UUID as the primary title. Multiple rows therefore look nearly identical and cannot be identified by task. The row's searchable text is also only that label, so project/workspace text displayed underneath does not help find the session.

### How often does it happen?

Every time an eligible session's associated agent has a null, empty, or whitespace-only display name. Multiple affected rows were visible together in the recorded macOS list.

No runtime error is emitted.

### Additional context

#### Summary

Recent sessions leak full internal agent UUIDs into the most prominent title position when a display name is missing. In a list containing several unnamed sessions, users cannot tell which task they are about to open, and the search index does not include the visible project/workspace context.

#### Spec context

Recent sessions is a recognition and navigation surface, not an identifier inspection tool. Internal IDs may remain available as secondary diagnostic detail, but the primary label needs to identify the user's task or explicitly communicate that the session is unnamed.

#### Scope IN / OUT

IN: Recent-session fallback labels, safe summary selection, shortened identifiers, searchable project/workspace context, and deterministic coverage for unnamed sessions.

OUT: Rewriting conversation history, forcing metadata generation where no usable prompt exists, changing provider output, Developer features still under development, and Codex import-source title extraction.

#### Implementation notes

Do not globally replace `AgentClientModel.displayName` without auditing its other consumers. Prefer a command-palette-specific presentation fallback or introduce a shared user-facing session-label helper with explicit semantics. A reasonable fallback order is: nonempty name, safe first-user-prompt/task summary, localized “Unnamed <provider> session”, then a shortened ID as secondary metadata. Expand search text to include the displayed project and workspace without exposing private paths.

#### Acceptance criteria

- [ ] A named session continues to display its current name.
- [ ] An unnamed session never uses a full UUID as its primary title.
- [ ] A safe prompt/task summary is used when available and is length-bounded.
- [ ] A session with no usable summary displays an explicit localized unnamed fallback.
- [ ] A shortened identifier remains available only as secondary detail when needed to distinguish rows.
- [ ] Searching by the visible project or workspace context can match an eligible unnamed session.
- [ ] Multiple unnamed sessions remain distinguishable enough to avoid blind activation.
- [ ] Tests cover named, prompt-derived, fully unnamed, Loose-workspace, and same-context multiple-session cases.

#### Dependencies

Related but not duplicate:

- getheca/heca-issues#37 covered new and renamed sessions being omitted from Search entirely.
- getheca/heca-issues#43 covered title extraction in the Codex Import session source list.

Neither issue covers the command palette's full-UUID fallback and restricted search text.

#### Definition of done

Implement a privacy-safe recognizable fallback, broaden matching to the visible context, add focused widget/unit coverage, verify the recorded multi-session macOS scenario, run the required Flutter checks, and link the fixing PR to this issue.
