# Duplicate-helper audit: consolidate shared implementations across bash and Python

## Why

AI-generated code is documented in the literature to favour re-implementing a
helper locally over finding and reusing a shared one. HOS already has the
principle against this (D41, "one invocation site"; CLAUDE.md's mandatory
search-first rule) but enforces it behaviorally, not mechanically — and it has
already bitten once: `check_suspension.sh` carried its own copy of the
suspension regex, "that duplication caused HOS#105" (per the script's own
header, fixed by delegating to `suspension_manager.py` under HOS#337).

A read-only audit on 2026-09-11 (working tree slightly behind `main`; counts
approximate — re-measure on `main` before starting) found the pattern is
widespread. Findings below are grouped by confidence. **Documented-deliberate
duplications are listed separately and are NOT in scope to remove** — they
need an annotation the new duplication gate (companion issue, filed alongside this one) recognizes, not a refactor.

Companion issues: the gate that stops this re-accruing is filed separately;
the protected-surface matcher divergence (a correctness bug, not hygiene) is
its own bug. `_load_audit_log` (×4) is already covered by #1289 — do not
re-scope it here.

Sourcing must stay bash-3.2-clean and allowlist-friendly (`source` of a *committed, literal* path is fine; the CLAUDE.md prohibition is on sourcing runtime-named files).

## C. Tests

`_run` ×24, `_git` ×15 (**≥6 different bodies** — different `check`/`text`/`cwd` conventions), `_write_exec` ×12, `_tmpfile` ×8, `_side_effect` ×10. `tests/conftest.py` defines **no** shared fixtures or helpers today. Lower priority than A/B, but the `_git` variants are exactly the kind of thing that makes a test pass in one file and fail in another for non-obvious reasons. Target: shared fixtures in `tests/conftest.py`.

## D. Documented-deliberate — annotate, do not remove

- `require_tier_ceiling.py:_score_to_tier` — "duplicated deliberately so this trusted-base gate imports nothing from `scripts/oversight/validators/` (whose modules mutate `sys.path`)". Valid.
- `astro_check.sh`/`type_check.sh:_astro_marker_present`, `lint_check.sh:_eslint_config_present` vs `detect_stack.sh` — "duplicated, not sourced — same _js-sibling independence convention (ADR-032)". Valid as documented.
- Every validator's `analyse_files()` / `main()` — the per-validator entry-point contract (`main()` → `analyse_files(files)`), not duplication.

Each of these needs the annotation the gate issue defines so the gate stays green without an allowlist that drifts.

## Not in scope

- `_load_audit_log` ×4 → #1289.
- The protected-surface matcher divergence → its own bug issue (correctness, not hygiene).
- Any behavior change beyond "one implementation, same behavior" — where two copies currently *differ* (`err`, `fail`, `rank`, `_git`), the consolidation PR must state which semantics won and why.
