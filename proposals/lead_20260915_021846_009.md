# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Proposal: bundled Auto Steam Calculator extension with reusable skin API and Streamline integration**

*Project description:*
I’d like to propose an optional **Auto Steam Calculator** extension bundled with decaid and **disabled by default**, with Streamline.js as its first supporting skin. If the approach is acceptable, I’d prepare upstream PRs for both projects.

I previously used [[Damian’s DSx2](https://github.com/Damian-AU/DSx2)](https://github.com/Damian-AU/DSx2) steam calculator and found it particularly useful: weigh the pitcher and milk, calculate the steaming time from a personal calibration, and let the machine stop at that time. I’m bringing that experience to decaid while keeping Streamline’s existing steam controls familiar. 

Damian deserves credit for the original feature, calibration approach, and pitcher-selection heuristics. The implementation includes attribution in its settings UI, manifest, and documentation. This is a new JavaScript implementation rather than a port of the Tcl interface.

**Setup and calibration**

In Streamline, users access the extension through **Settings → Extensions → Auto Steam Calculator**, enable it, and select **Open settings**.

The shared settings page uses three compact tabs:

* **General:** scale weight mode, starting pitcher selection, default steam flow, and a configuration summary.
* **Pitchers & Auto:** empty weights for small, medium, and large pitchers, with nearby scale-tare and **Set from scale** controls. Users can enter weights manually or capture them from the connected scale.
* **Calibration:** single-flow or multiple-flow calibration, using either manually entered measurements or a guided workflow.

At least one pitcher must be configured. Only configured pitcher sizes are offered on the main screen.

Automatic pitcher selection is separately opt-in. It requires all three pitcher weights, the usual milk weight per drink, and the small or medium pitcher normally used for one drink. It uses Damian’s heuristics to infer the pitcher from the gross scale weight. Users can instead select a pitcher explicitly.

The scale mode can be **pitcher plus milk** or **milk only**. Automatic pitcher identification requires pitcher-plus-milk weighing.

Steam flow is configurable from **0.4 to 2.5 ml/s**, with **0.4 ml/s** as the default. The flow controls in General and Calibration edit the same setting.

**Single-flow and multiple-flow calibration**

For **Single flow**, users record a milk weight and the steaming time needed to reach their preferred milk temperature at one flow setting. Auto mode then uses that fixed flow and scales the duration in proportion to milk weight.

For **Multiple flows**, users choose their usual flow range and record **2, 3, or 4 measurements**, with three recommended. The wizard includes the minimum and maximum flows and spaces additional readings between them.

The calculator normalizes each measurement to seconds per gram and uses linear interpolation between adjacent measured flows. It does not extrapolate beyond the calibrated range.

Both paths support guided calibration:

1. Tare the empty scale.
2. Select a configured pitcher, add cold milk, and capture the pitcher-plus-milk weight.
3. Review the calculated milk-only weight.
4. Prepare calibration, which applies that reading’s actual flow to the machine.
5. Start steam and stop when the milk reaches the desired temperature.
6. Review the recorded steaming time and save, or continue to the next reading.

The guided counter uses the machine’s steaming time, excluding warm-up. Multiple readings should use fresh milk with similar starting conditions. Previously active steam settings are restored after the guided run.

This remains a **calibrated time estimate**, not temperature sensing. It does not compensate for changes in heater temperature or starting milk temperature. Consistent milk, heater settings, and technique matter.

**Keeping the Streamline experience familiar**

The integration adds an **Auto** mode while preserving the existing manual Flow and Time functionality.

With the extension enabled, tapping the existing Steam area cycles through **Auto, Flow, and Time**. The compact label is **Auto | F | T**, with the selected mode highlighted in blue.

When Auto is selected:

* The existing preset area shows configured **S, M, and L** choices, plus **Auto** only when automatic pitcher selection is enabled and fully configured.
* Tapping a pitcher selection calculates and applies the steam duration using fresh, stable scale readings and the saved calibration.
* The selection is remembered. Tapping the same selection again recalculates for the next pitcher of milk.
* The calculated duration is displayed before steaming, and the corresponding flow is applied to the machine.
* With single-flow calibration, only the **+ and − icons** disappear. Their gray boxes remain visible, and the buttons are disabled.
* With multiple-flow calibration, **+ and −** adjust flow within the measured range. Changing flow resets the duration to Off and requires another pitcher tap to calculate a new time.
* Entering Auto mode and completing a steam cycle reset the duration to **Off**, prompting a fresh calculation for the next drink.

Normal use does not start steam automatically: users calculate first, then start steaming through the usual controls.

Selecting Flow or Time restores the previous manual steam settings and normal adjustment controls. Disabling the extension removes the additional Auto mode. Incomplete extension setup leaves Auto Off with a setup reminder; manual operation remains available.

**Off is a reminder, not a hard start interlock.** The machine may still produce a brief steam burst if started before calculation.

**Why bundle this with Decaid?**

The calibration settings, calculation, input validation, and pitcher-selection logic are useful beyond Streamline. A shared Decaid extension would let other skins adopt the feature without maintaining separate copies of the calculator or calibration interface.

The responsibilities are separated:

* **Decaid extension:** owns settings, validation, calculations, the shared settings page, and the guided calibration session.
* **Streamline or another skin:** presents its own everyday steam controls, requests calculations, and applies the resulting steam settings.

The calculation endpoint itself does not change machine settings or start steam. Guided calibration is a separate, user-operated workflow that prepares the machine and provides explicit Start and Stop controls.

[[Skin developer documentation](https://github.com/pponce/decaid/blob/feature/calibrated-steam-timer/doc/CalibratedSteam.md)](https://github.com/pponce/decaid/blob/feature/calibrated-steam-timer/doc/CalibratedSteam.md) covers discovery, readiness, available pitchers, flow capabilities, settings navigation, and integration behavior. Other skins can reuse the shared settings page rather than building their own. DYE2 is neither required nor modified.

Bundling the extension disabled by default would make it accessible to interested users while preserving the existing experience for everyone else. The implementation uses Decaid’s existing plugin structure and has no third-party JavaScript dependencies.

I also want to be transparent about maintenance: I don’t want to take on long-term management of a separate extension repository and release process. My hope is that this is general enough to be maintained within Decaid’s existing project structure. It was a very popular capability in DSX2. I understand that bundling still creates maintenance work, and I’m open to simplifying the implementation or adjusting its API and scope to fit the decent teams preferences.
