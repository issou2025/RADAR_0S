## Notable Papers & Research

### SplatAnything: fixing what feed-forward 3D reconstruction has been normalizing wrong
**arXiv [2611.08264](https://arxiv.org/abs/2611.08264)** — Hao Yu, Zhenwei Wang and nine co-authors, including **Sida Peng** (ZJU3DV) and **Chunchao Guo** (Tencent). Submitted **November 5**; the **inference code, weights and demo were released November 9**. The paper's claim is a specific diagnosis: existing feed-forward 3D Gaussian Splatting methods predict Gaussian attributes in a space normalized by a *global radial statistic*, which carries no information about how far apart neighbouring Gaussians actually are — so the supervision signal for Gaussian **scale** is ambiguous. Their fix, **Gaussian Spacing Normalization (GSNorm)**, normalizes by local spacing instead. Reported results: strongest **DISTS** on ETH3D, competitive LPIPS, reconstruction in **a few seconds from any number of input images**, plus a new cross-dataset benchmark spanning scales, resolutions, camera setups and view sparsity. [arXiv](https://arxiv.org/abs/2611.08264) · [GitHub](https://github.com/zju3dv/SplatAnything) · [hyper.ai summary](https://hyper.ai/en/papers/2611.08264)

**Why it earns the slot.** This digest's standing topic is world models and spatial intelligence, and that conversation is dominated by generative systems — Atlas, Genie, Cosmos — whose outputs are judged by eye. This is the unglamorous half: a normalization bug in the reconstruction stack that made one geometric quantity systematically under-determined, named and corrected. It also arrives with code on the day of release, which almost nothing else in this edition does. **What to hold against it:** arxiv.org was unreachable from this session, so the abstract, author list and figures above come from search results, a third-party summary site and the project's GitHub page, not from the paper. All numbers are the authors' own and nothing here is peer-reviewed or independently replicated.

### Google: two more eighth-generation TPUs, and the interesting one is about who can see your inference
**November 9.** Google announced **TPU 8tx** and **TPU 8i Max**, the third and fourth systems in its eighth-generation line, alongside April's 8t and 8i. **TPU 8tx** reuses the 8t silicon paired with **AMD EPYC** hosts and is aimed at **confidential computing** for regulated industries and government; Google claims up to **2× the speed (or 2× lower latency — coverage renders the same claim both ways) on some operations** versus the 8t. **TPU 8i Max** packages **two 8i chips together**, which Google says **doubles compute, on-chip SRAM and HBM bandwidth** relative to the 8i, targeting long-context and multi-agent inference. [Google Cloud on X](https://x.com/googlecloud/status/2119792125197836330) · [Digitimes](https://www.digitimes.com/news/a20261110VL202/tpu-google-training-silicon-security.html) · [mlq.ai](``https://mlq.ai/news/google-adds-tpu-8tx-for-confidential-ai-and-a-two-chip-tpu-8i-max-its-third-and-fourth-tpu-systems-this-year/``) · [CryptoBriefing](https://cryptobriefing.com/google-unveils-tpu-8tx-tpu-8i-max/)

**Why the 8tx is the one to watch.** A confidential-computing accelerator is a bet that the blocker on enterprise and government AI adoption is no longer capability or price but **whether the cloud operator can see the workload** — and the day's other stories make the case for it. ### Fireworks AI: a second disclosure, and the weights were in scope

## Trending Open-Source Projects

**Method and caveat.** GitHub's **daily and weekly trending pages** (all-languages, Python, TypeScript, Rust) were read **directly today**, and so was **every repository page below** — the licenses, commit counts and README caveats are from the repos themselves. Star deltas are GitHub's own computation. The **GitHub search API returned 502** on every attempt, so **creation dates could not be verified** and none is asserted below. The highest-velocity repositories on today's pages (**NVIDIA/auto-ontology** at +10,159 this week, **vercel-labs/agent-desktop** at +12,120, **pingdotgg/t3code**, **cloudflare/security-audit-skill**, **meta/astryx**, **anthropics/skills**, **Scrapling**, **claude-mem**, **impeccable**) were all featured in recent editions and are skipped per the config's no-repeat rule. The four below are the fastest risers this digest has **not** previously covered, which means the velocities are more modest than last week's; that trade-off is stated rather than hidden.

**1. [elie222/rakazo](https://github.com/elie222/rakazo)** — *"Open-source Grok Bot alternative. Choose your own model and sandbox."* TypeScript/React/Electron/Expo, Apache-2.0, **7,723 stars, +1,013 this week** (~13% of its total in seven days, the highest relative velocity here), 1.4k forks, **3,299 commits**. Persistent AI "teammates" with their own memory and routines, triggered on a schedule or by email or webhook with run history; each bot gets a browser, terminal, files and desktop you can take over; group chats where bots work together; delegation and subagents; shareable live dashboards and documents; voice calls; any model with your own keys; thousands of app integrations plus MCP and OpenAPI tools; sandboxes in Docker, in the cloud or on your own machine; and web, Electron, iPhone and Android clients against one server. *Why it's trending:* the README names **Grok Bot, Meta Muse, OpenAI Dots, Instinct, OpenClaw, Hermes Agent and Claude Duet** as what it competes with — a self-hosted substitute for the entire persistent-agent product category, which is the fastest-commoditizing layer in the industry right now. *Caveats:* **Node 24.15.0+ or 26+, and 25.x is explicitly unsupported**; the Linux AppImage needs FUSE 2; "This computer" mode looks for the `docker` CLI and **won't detect Podman**; `docker compose down -v` **deletes all Postgres state**; Railway sandboxes need `PRIVATE` networking and a workspace token, are metered, and **destroy the sandbox when a computer is stopped**; enabling model credits bills each call at **provider cost plus 20%**; and several secrets must each be set independently and randomly.

**2. [garrytan/gbrain](https://github.com/garrytan/gbrain)** — *"Give the agent you already use a memory you control."* TypeScript on Bun, MIT, **32,267 stars, +216 today**, 4.8k forks, **13,965 commits**. A self-hostable memory layer storing explicit facts with sources, supporting corrections, and shared across agents via CLI or MCP; keyword and semantic search plus a `gbrain think` command returning cited, synthesized answers **that name the gaps in what the brain knows**; a typed knowledge graph for relationship queries; two storage engines (PGLite by default, ~50K pages; Postgres with pgvector above that); sync from Markdown repos with the database as a rebuildable index; customizable schema packs; optional scheduled enrichment jobs. Built by **Garry Tan**, YC's president and CEO, to run his own OpenClaw and Hermes agents. *Why it's trending:* it is the counter-position to `claude-mem` — explicit, cited, correctable facts rather than compressed conversation history — and it is the direct practical answer to **MemoryDojo**, the agent-memory-poisoning benchmark in today's arXiv batch. *Caveats, and they are substantial:* **not distributed on npm** (the npm `gbrain` package is unrelated; install from GitHub with Bun 1.4.4+, and the README tells you to read its shell installer before running it); configured embedding, reranking, extraction and synthesis providers **can receive your text**, and the harness model sees recalled memory even in keyless mode; a Markdown export is **not** a full backup; the README states sources **do not isolate** local-file or shared-database-credential callers and that its authorization tests cover specific paths, **not every possible leak**; background enrichment wants a server with **8GB+ RAM** and its own API spend; page counts are self-reported and the **BrainBench** gain (R@5 0.6626 → 0.7241) is the author's own, with the 0.9791 figure explicitly an upper bound rather than a product score. Lowest velocity in this section, on a very mature codebase.

**3. [Crosstalk-Solutions/project-nomad](https://github.com/Crosstalk-Solutions/project-nomad)** — An offline-first knowledge and education server. Apache-2.0, **43,054 stars, +1,219 this week**, 4.4k forks, **851 commits**. Runs on your own hardware with no internet after setup: local AI chat via **Ollama** or any OpenAI-compatible server (LM Studio, llama.cpp) with document upload and **RAG through Qdrant**; offline Wikipedia, medical references and ebooks via **Kiwix**; Khan Academy courses with progress tracking via **Kolibri**; offline maps (ProtoMaps), CyberChef, FlatNotes, a hardware benchmark, a "Supply Depot" app catalog; and a web Command Center managing Docker installs with opt-in updates. Runs under 1 GB RAM on its own (**2 GHz dual-core, 4 GB RAM, ~10 GB disk** minimum), **~25 GB with AI**, recommended **32 GB RAM and an RTX 3060-class GPU with 250 GB+ SSD**. *Why it's trending:* the complete inverse of this digest's top stories — where Anthropic buys 1.7 GW of generators and Google sells confidential-computing silicon, this is a self-contained AI-plus-library appliance for a Raspberry-class box with no network. *Caveats:* **no authentication at all** — anyone who can reach the instance can use it, and the README says not to expose it to the internet; **Debian-based systems only** (Windows via community-supported WSL2); the install script needs **root**; a connectivity check contacts Cloudflare's 1.1.1.1 by default; only minor and patch versions auto-update; and remote Ollama requires you to run `OLLAMA_HOST=0.0.0.0` and secure that host yourself.

**4. [homeassistant-ai/ha-mcp](https://github.com/homeassistant-ai/ha-mcp)** — An MCP server letting Claude, ChatGPT and other assistants **configure, build and debug** a Home Assistant install rather than just toggle devices. MIT, **6,119 stars, +31 today** — the weakest velocity here, included because the security design is unusually honest — 299 forks, **3,453 commits**, **87 MCP tools**. Entity search and device control, but also creating and editing automations, scripts, scenes, helpers, dashboards, areas, zones and blueprints; debugging via automation traces, history and logs; backup/restore, HACS and registry management; **Read Only Mode**, per-tool enable/disable and tool security policies; search-based tool discovery for small-context models; bundled agent skills served as MCP resources. *Why it's trending:* agents that write and debug home-automation config, rather than call a light-switch API, are the first mass-market case where an agent's mistakes have physical consequences. *Caveats, which the README states itself:* a long-lived token on your own admin account **"works from anywhere if it leaks,"** so it recommends a dedicated HA-MCP admin account and says **"Never use your own login"**; the Secret URL is the simplest remote credential and Home Assistant sign-in is **optional**, though remote and local access both start disabled; the **stdio transport has known connection problems** (issue #1713) and is recommended only for demos; duplicate installs across two methods hang connections; **YAML editing and file read/write/delete are beta, off by default** behind feature flags; failed template-helper restores intentionally keep both the new helper and the source backup, so inspect before retrying; and anonymous usage stats are planned though absent today.
