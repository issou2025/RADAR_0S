### Type

### Summary

Since 0.23.0 (#290) `fsp doctor` reports what the generated `main()` wires and why, and what is out of line around it: the fespalier refs of the app against the `fsp` you run, `pubspec.lock`, `go_router` and Flutter. It prints rows in three sections (`wiring`, `versions`, `checks`), as text or, with `--json`, one object per row. It exits 1 only when a row is an error.

To know Flutter's version it runs another program: `flutter --version --machine`, with the `flutter` it finds on `PATH`.

The tests cover the rows without a real Flutter:
- Unit tests feed `doctor` any set of facts, including the output of `flutter --version --machine`.
- A CLI test runs the binary with a stand-in `flutter` script (Unix only), and checks the text, the JSON keys and the exit codes.
- The Windows lookup of `flutter.bat` (`PATHEXT`) is tested as a function, not on Windows.

No test has run `fsp doctor` against a real Flutter on Windows, under FVM or puro, on a Flutter below the floor, or while another flutter command was running. This ticket is that check.

Expected result: a report on each case below, per operating system.

### Intent

Make sure `fsp doctor` tells the truth about the Flutter an app really uses, on the setups developers have, and never leaves a person waiting with no word. These are the "run it through the SDK the project uses" claims of `docs/cli.md`, "fsp doctor".

### Current Behavior

Checked by tests only:
- Every row's text, status and subject, from made-up facts (`cli/src/doctor_tests.rs`).
- `Toolchain::parse` of `flutter --version --machine`, including a notice line before the JSON, a pre-release, and Dart's `(build ...)` suffix.
- The binary, with a stand-in `flutter` script: text output, JSON lines with every key, exit 1 on an error row, 0 without one, and the message for a project folder that is not there.
- `resolve_windows`: `flutter` becomes `flutter.bat` through `PATHEXT`.

Not checked:
- A real `flutter` on Windows (`flutter.bat`), in PowerShell, cmd and Git Bash.
- FVM and puro.
- A Flutter below the floor.
- A `flutter` that is slow, or waits for another flutter command.
- How the marks `✓ · ! ✗ -` look in a Windows console.

### Expected Behavior

- **A healthy app** prints the header `fsp doctor 0.23.0 (<the app folder>)`, three sections, rows with marks, a closing line `Nothing out of line.`, and exits 0.
- **The marks** are `✓` ok, `·` info, `!` warning, `✗` error and `-` skipped. Only `✗` makes the exit code 1.
- **The `flutter` and `dart` rows** come from the `flutter` on `PATH` when `fsp doctor` runs. Under FVM or puro, run it through the project's SDK (`fvm exec fsp doctor`), so that it is the project's Flutter that is checked.
- **A missing `flutter`** is a skipped row, never a failure: `` `flutter` is not on PATH: Flutter and Dart are not checked ``.
- **`--json`** prints one object per row, one per line, on stdout, with the keys `section`, `check`, `subject`, `status` and `message`, always, in that order. Nothing else is on stdout.
- **Exit codes.** 0 when no row is an error. 1 when one is. 2 for a usage error (an unknown flag).
- **It writes nothing.** `fsp` never reads the pub cache or `.dart_tool/`, never reaches the network. The `flutter` it runs is another program: it may reach the network (its analytics, or the download of its Dart SDK on a fresh install) and write its own cache.

What we do not know, and want to learn: in 0.23.0 `fsp doctor` has no timeout of its own. It waits for `flutter --version --machine` and hides flutter's messages (Flutter prints `Waiting for another flutter command to release the startup lock...` when another flutter command is running). Case 12 asks how long a person waits, and whether they are told anything. PR #293 (in the release after 0.23.0) stops flutter after 30 s and shows the `flutter` row as skipped with a message; if you test a build of `main` that has it, say so in the report.

### Technical Context

**Setup.**

1. You need Flutter 3.35 or newer on `PATH`, `git`, and a network (`fsp create` runs `flutter pub get`).
2. Install `fsp` 0.23.0 or later (`install.sh` or `install.ps1` from the README; `docs/getting-started.md`, "Install fsp"), or build it from `main`:
   ```sh
   git clone https://github.com/fespalier/fespalier
   cd fespalier/cli && cargo build --release
   ```
   Then put `cli/target/release` on `PATH`. `fsp --version` should print `fsp 0.23.0`. A build of `main` before the release prints `fsp 0.22.1`, because the release tooling bumps the number when it cuts the release. Then read `0.22.1` and `v0.22.1` wherever this ticket says `0.23.0` and `v0.23.0`, and `v0.22.0` (the release before) wherever it says `v0.22.1` (cases 8 and 9).
3. Make a demo app with one companion package, and keep a copy in git so you can see that `fsp doctor` changes nothing:
   ```sh
   fsp create doctordemo --features storage
   cd doctordemo
   git init -q && git add -A && git commit -qm base
   ```
4. How to read the exit code: `echo $?` in sh, bash and zsh; `echo $LASTEXITCODE` in PowerShell; `echo %ERRORLEVEL%` in cmd.
5. For case 4: FVM (https://fvm.app). For case 5: puro (https://puro.dev). For case 6: a second Flutter below 3.35 (FVM or puro can install one, for example `3.32.8`).

### The cases

1. **A healthy app, as text.** In `doctordemo`: `fsp doctor`, then the exit code. Expect exit 0 and output like this (the versions, the folder, the number of routes and the rows marked `...` are yours; the other texts are exact):
   ```text
   fsp doctor 0.23.0 (/path/to/doctordemo)

   What the generated main() wires, and why
     ✓ main         lib/app.main.g.dart is written: ...
     ...
     · telemetry    off: nothing is reported (`telemetry: true` turns it on)
     · otel         off: the generated main() starts no OpenTelemetry SDK
     · forms        no action has a form()
     · deferred     no page loads its code on demand
     ✓ tasks        ...

   Versions
     ✓ fespalier    fespalier: git, ref v0.23.0, the version of this fsp
     ✓ companion    fespalier_storage: git, ref v0.23.0, as fespalier
     ✓ lock         pubspec.lock resolves fespalier 0.23.0, the version of this fsp
     ✓ go_router    go_router 18.1.0 (pubspec.lock), in what fespalier supports, >=17.2.3 <19.0.0
     ✓ flutter      Flutter 3.35.7, at or above fespalier's floor, 3.35.0
     ✓ dart         Dart 3.9.2, at or above fespalier's floor, 3.9.0

   Checks
     ✓ main_dart    lib/main.dart calls AppMain.run()
     ✓ fsp_check    `fsp check`: 2 routes, no errors

   Nothing out of line.
   ```
   A `!` or a `✗` on a fresh app is a finding: paste the row. Then `git status --short`: expect nothing (it writes nothing).
2. **As JSON.** `fsp doctor --json`. Expect one object per line, nothing else on stdout, and every object has `section`, `check`, `subject`, `status`, `message`, in that order. For example:
   ```text
   {"section":"wiring","check":"main","subject":null,"status":"ok","message":"lib/app.main.g.dart is written: lib/app/app.dart exists"}
   ```
   To check that every line parses: `fsp doctor --json | python3 -c "import sys,json; [json.loads(l) for l in sys.stdin]; print('all lines parse')"`. In PowerShell: `fsp doctor --json | ForEach-Object { $_ | ConvertFrom-Json } | Format-Table section,check,status`.
3. **Windows, where `flutter` is `flutter.bat`.**
   - In PowerShell, `where.exe flutter`: the first line should end in `flutter.bat`.
   - Repeat case 1 and case 2 in **PowerShell** and in **cmd**. Expect the `flutter` and `dart` rows `ok`, not `skipped`, and exit code 0.
   - Expect the marks `✓ · ! ✗ -` to show as marks. Report how they look in Windows Terminal, and in the old console (cmd.exe with the default code page). Report whether the folder in the first line starts with `\\?\`.
   - Run `dart run fespalier doctor` in the app folder: it should print the same report.
   - If you use Git Bash, repeat case 1 there.
4. **Under FVM.**
   ```sh
   fvm use 3.35.7 --skip-pub-get
   fvm exec fsp doctor
   fsp doctor
   ```
   (`--skip-pub-get` keeps `fvm use` from running `flutter pub get`. If your FVM does not know the flag, run `fvm use` without it and ignore a `pub get` failure.) Expect the first `flutter` row to say `Flutter 3.35.7, at or above fespalier's floor, 3.35.0`. The second one is the Flutter that is on your `PATH` (or `` `flutter` is not on PATH: Flutter and Dart are not checked `` when there is none). Report both, and the `dart` rows. On Windows do it in PowerShell and cmd.
5. **Under puro.** In `doctordemo`: `puro use 3.35.7`, then `puro flutter --version` (it should say 3.35.7). Run `fsp doctor` the way puro runs a command with the project's SDK first on `PATH`. If plain `flutter --version` in the app folder already prints puro's version, plain `fsp doctor` is enough. Write down the exact command you ran. Expect the `flutter` row to name puro's Flutter, not another one. On Windows do it too.
6. **Below the floor.** Make the app with your current Flutter first (step 3), then run `fsp doctor` in a shell where a Flutter older than 3.35 is first on `PATH` (for example `fvm use 3.32.8 --skip-pub-get` and `fvm exec fsp doctor`). Expect exit 1, two error rows, and the closing line `2 errors.`:
   ```text
     ✗ flutter      Flutter 3.32.8 is below fespalier's floor, 3.35.0: upgrade Flutter
     ✗ dart         Dart <version> is below fespalier's floor, 3.9.0: upgrade Flutter
   ```
   If you have a Flutter checkout that reports `0.0.0` (no release tags), run it too: the `flutter` row should say `Flutter does not know its own version (it reports 0.0.0)`. If you have a 3.35 beta, report what it says (a pre-release of the floor counts as below it).
7. **No `flutter` on `PATH`.** Start a shell where `fsp` is on `PATH` and `flutter` is not.
   - sh: `env PATH="$(dirname "$(command -v fsp)"):/usr/bin:/bin" fsp doctor`
   - PowerShell: `$env:PATH = (Split-Path (Get-Command fsp).Source) + ";C:\Windows\System32"; fsp doctor`
   Expect exit 0 and a skipped row, with the rows of `fsp` itself still there:
   ```text
     - flutter      `flutter` is not on PATH: Flutter and Dart are not checked
   ```
   If `flutter` still resolves (some systems have one in `/usr/bin`), trim `PATH` further.
8. **A companion out of line.** In `pubspec.yaml`, change the `ref:` of `fespalier_storage` (only that one) to `v0.22.1`. Do not run `flutter pub get`. Run `fsp doctor`. Expect exit 1, `1 error.` at the end, and:
   ```text
     ✗ companion    fespalier_storage: ref v0.22.1, and fespalier's is v0.23.0: give every companion fespalier's url and ref, or move them together with `fsp upgrade --app`
   ```
   Put the file back with `git checkout pubspec.yaml`.
9. **An app one release behind.** Change every `ref: v0.23.0` in `pubspec.yaml` to `ref: v0.22.1`, in your editor or with `perl -pi -e 's/ref: v0\.23\.0/ref: v0.22.1/' pubspec.yaml` (do not run `pub get`). Expect exit 1 and:
   ```text
     ✗ fespalier    this app pins fespalier v0.22.1; fsp 0.23.0 writes code for v0.23.0. Move the refs of fespalier and every companion to v0.23.0 with `fsp upgrade --app`, or run `dart run fespalier` to use the fsp that matches the pin.
   ```
   Put the file back with `git checkout pubspec.yaml`.
10. **No `pubspec.lock`.** Delete the file. Expect exit 0 and a skipped row:
    ```text
      - lock         no pubspec.lock: run `flutter pub get`; the versions it resolves (fespalier's, go_router's) are not checked
    ```
    Put it back with `flutter pub get`.
11. **A usage error.** `fsp doctor --nope`, then the exit code. Expect exit 2 and a message from the argument parser.
12. **A Flutter that is busy.** `flutter --version --machine` can wait for another flutter command. Try either, and report the one you could do:
    - **A Flutter that has never run.** Unpack a fresh Flutter SDK, or `git clone https://github.com/flutter/flutter.git -b stable ~/flutter-fresh`, and do not run it. Put its `bin` first on `PATH` and time the command: `time env PATH="$HOME/flutter-fresh/bin:$PATH" fsp doctor` (PowerShell: `$env:PATH = "C:\flutter-fresh\bin;" + $env:PATH; Measure-Command { fsp doctor }`). Its first run downloads the Dart SDK and builds its tool.
    - **Two terminals.** In terminal A start a long flutter command that holds the startup lock (for example `flutter precache --force` on a fresh install). In terminal B, a few seconds later, run `fsp doctor`.
    Report: whether `fsp doctor` printed anything while it waited; how long it waited in total; whether it finished, and with what `flutter` row, once the other command ended; and what Ctrl-C did (the exit code too). If you cannot make flutter wait, write "not run".
13. **Optional: an adapter that is not configured.** `adapters: auto` (since 0.23.0) is every first-party adapter package under `dependencies:`. Add this under `dependencies:` in `pubspec.yaml`, and `adapters: auto` under `fespalier:`, and run `fsp doctor` (no `pub get` needed):
    ```yaml
      fespalier_push:
        git:
          url: https://github.com/fespalier/fespalier
          path: packages/fespalier_push
          ref: v0.23.0
    ```
    Expect a warning row (`!`) that starts like this:
    ```text
      ! adapter      fespalier_push: on, found by `adapters: auto` under `dependencies:`, and no Dart file under lib/ calls `FespalierPush.configure(...)`: unconfigured, ...
    ```
    Put the file back with `git checkout pubspec.yaml`.
