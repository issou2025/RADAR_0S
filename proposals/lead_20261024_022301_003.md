# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Domain gap: view creation — plans, sections, callouts, 3D from a box, drafting views, legends by duplication**

*Project description:*
## Goal

The connector can list, duplicate, rename, crop and template views and put them on sheets, but it cannot **create** one except the clash review 3D view (`ClashReviewViewService`) and a floor plan inside the IFC pipeline (`BoundaryViewResolver`, 2026 only). Add a general view creation tool so an agent can build the plan set for a level or a detail view for a device on its own.

| Tool | Permission | Purpose |
|---|---|---|
| `revit_list_view_family_types` | ReadOnly | Available `ViewFamilyType`s per `ViewFamily` (floor plan, ceiling plan, section, detail, 3D, drafting, …) with their default template |
| `revit_preview_create_views` / `revit_create_views` | ReadOnly / RequiresApproval | Create views from a list of specs: `floorPlan`, `ceilingPlan`, `structuralPlan`, `areaPlan`, `section`, `callout`, `threeD`, `drafting`, `legend` (by duplicating an existing legend) |
| `revit_set_view_extent` | RequiresApproval | Crop region / section box / view range from a room, elements, a bounding box or a scope box, on an existing view |

## Why

A typical EN plan sheet set is "one floor plan per level per discipline, with template X, scope box Y, named by the company pattern, placed on sheets". Every step except the first exists (`revit_duplicate`, `revit_rename`, `revit_apply_view_template`, `revit_set_view_crop_regions`, `revit_create_sheets_from_table`, `revit_place_views_on_sheets`). Sections and callouts are needed for device mounting details; 3D views from a box are needed for the review pages (#100) and clash handoff.

## Design

### View family types

`revit_list_view_family_types`: `FilteredElementCollector(doc).OfClass(typeof(ViewFamilyType))` → `{id, name, viewFamily, defaultTemplateId, defaultTemplateName}`; filter `viewFamily`. Replace the three ad-hoc "first of family" lookups (`ClashReviewViewService`, `BoundaryViewResolver`, and the new code) with one `ViewFamilyTypeResolver.Resolve(doc, ViewFamily, nameOrId?)` that prefers an exact name, then the document's default for that family (`doc.GetDefaultElementTypeId(ElementTypeGroup.ViewTypeFloorPlan…)`), then the first.

### Create views

Arguments: `views[]` (max 100 per call) of a common part `{kind, name, viewFamilyType?, template?, scale?, detailLevel?, discipline?, phase?, scopeBox?, placeOnSheet? {sheet, xMm, yMm}}` plus kind-specific fields; `ifNameExists` = `suffix` (default, via `ViewManagerToolSupport.ResolveUniqueName`) | `skip` | `fail`; `document`.

Per kind:

- `floorPlan` / `ceilingPlan` / `structuralPlan` / `areaPlan`: `level` (name or id, or `levels[]` to fan out one view per level with `{level}` in the name); `ViewPlan.Create(doc, vftId, levelId)` (`areaPlan` → `ViewPlan.CreateAreaPlan(doc, areaSchemeId, levelId)` with `areaScheme`); `viewRange?` `{topOffsetMm, cutOffsetMm, bottomOffsetMm, depthOffsetMm}` via `PlanViewRange` (`SetOffset`, levels kept); `cropTo?` (see extent below).
- `section`: `from {x,y,z}` and `to {x,y,z}` in mm (the section line in plan), `depthMm` (default 3000), `heightMm`/`bottomMm` (default: the level range of the nearest levels to the points), `flip?`. Build the `BoundingBoxXYZ` with a `Transform` whose origin is the midpoint, `BasisX` along the line, `BasisY` up, `BasisZ` the view direction (`BasisX × BasisY`); `Min = (-length/2, bottom, 0)`, `Max = (+length/2, top, depth)`; `ViewSection.CreateSection(doc, vftId, box)`. Pure math in `SectionBoxMath` (tested).
- `callout`: `parentView` (plan or section), `from`/`to` corner points in mm (or `aroundElements[]` / `aroundRoom` with `paddingMm`); `ViewSection.CreateCallout(doc, parentViewId, vftId, p1, p2)` for a detail callout of a plan, `CreateReferenceCallout` when `referenceView` is given; the view family type must be a Detail or FloorPlan type compatible with the parent (validate, list compatible types in the error).
- `threeD`: `box {min, max}` mm, or `aroundElements[]` / `aroundRoom` + `paddingMm` (union of bounding boxes, `ClashBoundingBoxHelper.Expand`), `isometric` (default true) else `View3D.CreatePerspective`; `SetSectionBox` + `IsSectionBoxActive`; `orientation?` (`ViewOrientation3D` from eye/forward/up, with presets `iso-ne|iso-nw|iso-se|iso-sw|top`). Reuse `ClashReviewViewService.SetSectionBox` by extracting its box-union into `ViewExtentService`.
- `drafting`: `ViewDrafting.Create(doc, vftId)`; `scale`.
- `legend`: Revit has no API to create a legend; `sourceLegend` (name or id) is duplicated with `view.Duplicate(ViewDuplicateOption.WithDetailing)` and renamed. Without a source legend in the model the spec fails with `legend_source_required` and the message explains the API limit.

Common post-steps, each inside the same transaction: `view.Name`, `ViewTemplateId` (name via `ListViewTemplatesTool` lookup), `Scale` (ignored when the template controls it; report that), `DetailLevel`, `Discipline`, `phase` (`VIEW_PHASE` parameter, via `ElementRoomSupport.TryResolvePhase`), scope box (`VIEWER_VOLUME_OF_INTEREST_CROP` parameter to the scope box element id), `placeOnSheet` → `Viewport.Create` after `doc.Regenerate()` (sheet by number via the existing sheet lookup). One transaction per call, `SubTransaction` per view so one failure keeps the rest (`atomic=false` default; `atomic=true` rolls everything back as in `MoveElementsTool`).

Preview resolves every reference (level, type, template, scope box, parent view, source legend, sheet), computes the unique names, the section box geometry (returned in mm so the agent can sanity-check), and reports per view `willCreate | skipped | invalid` with reasons.

Result per view: `{index, name, viewId, kind, level, templateApplied, sheetId?, viewportId?, warnings[]}`.

### Set extent on an existing view

`revit_set_view_extent`: `viewId`, one of `room` (id; polygon from `RoomSourceService` → bbox), `elements[]`, `box {min,max}`, `scopeBox` (id or name), with `paddingMm` (default 500). Plan/section: crop box (`view.CropBox`, `CropBoxActive`, `CropBoxVisible` = false by default) — the existing `ViewCropRegionToolSupport.Apply` is reused for plans; 3D: section box. Linked-model rooms are transformed with `RoomSource.ToHostMm`. Preview is `revit_preview_set_view_crop_regions`-style and part of the same tool pair convention (add `revit_preview_set_view_extent`).

### Status codes

`view_family_type_incompatible` (data: compatible types), `legend_source_required`, `level_not_found`, `view_name_exists`.

## Acceptance criteria

- One spec creates a full per-level plan set with correct level, template, scope box and sheet placement, with company-pattern names and no duplicates.
- Sections and callouts face the intended direction (documented convention: looking from `from` towards `to`, the view looks to the left/right as specified by `flip`), with the preview reporting the box in mm.
- 3D views around elements or rooms have a tight, padded section box; the clash review view keeps working through the shared service.
- Every reference failure (type, level, template, parent, sheet) is reported in the preview before anything is created.
- Unit tests green, both targets build, benchmark report committed.
