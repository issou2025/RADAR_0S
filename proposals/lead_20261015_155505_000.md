### 🐞 Describe the bug

The dockable Python Shell pane is registered once, at Revit startup, with the editor flag taken from the configured shell mode at that moment (`Shell.RegisterDockablePane(uiapp, paths, _get_shell_mode() == "Docked Editor")` in `pyRevitCore.extension/startup.py`). `ShellDockablePaneRegistration.Register` returns early when the pane already exists (`DockablePane.PaneIsRegistered`), and the pane captures `useEditor` in its constructor.

So if the mode is changed with Shift+Click on the Python Shell button after Revit has started, the next plain click opens the pane in the old layout. Pressing pyRevit Reload does not help, although the docs (`docs/python-shell.md`) say the next plain click uses the new mode. Only a Revit restart picks the choice up.

Observed on the bench: mode was unset (Modeless) at Revit start, I chose "Docked Editor" with Shift+Click, and the docked pane opened console only, with no editor. After Reload it was still console only (same pane instance, the banner text was kept). After restarting Revit the same click opened the pane with the editor (New / Open / Save and a code area above the console).

### ♻️ To Reproduce

1. Windows, Revit 2026, pyRevit develop. Make sure `[Python Shell_config]` has no `mode` (default Modeless) and start Revit.
2. Open any project (docked modes need one).
3. Shift+Click the Python Shell button (pyRevit tab, pyRevit panel slide-out) and pick "Docked Editor" in "Python Shell Mode". Press OK.
4. Plain click the Python Shell button. The pane opens with the console only.
5. Close the pane, press pyRevit Reload, plain click the button again. Still console only.
6. Restart Revit, plain click the button. The editor is there.

The opposite direction (registered with the editor, then switched to "Docked") mismatches the same way.

### ⏲️ Expected behavior

Either the pane is built from the current configured mode each time it is shown, or, if Revit really only allows registration at startup, the button tells the user that a Revit restart is needed and the docs and the "Reload pyRevit" advice in the error dialog are corrected.
