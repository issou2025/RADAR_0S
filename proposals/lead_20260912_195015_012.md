## Falsification tests / acceptance criteria
1. **Same-SHA conflict test:** record PASS then a later independently reproducible FAIL for the same exact SHA. Canonical status must become `FAIL` or `VERDICT_CONFLICT`, never remain `READY_FOR_INTEGRATION_REVIEW`.
2. **Fail dominance:** an unresolved FAIL tied to an exact SHA blocks promotion regardless of older PASS count, reviewer role, or comment recency elsewhere.
3. **No orthogonal laundering:** fixing CI/workflow reachability without changing the product code must not clear the product FAIL.
4. **Repair-SHA isolation:** only a new product SHA that fixes the failing regression may request fresh PASS; no verdict transfers from the failed SHA.
5. **Cross-thread ingestion:** verdict synthesis must consume PR comments, verifier issues, and durable evidence records relevant to the exact SHA rather than relying on a single thread/checkpoint summary.
6. **Breaker preservation:** the exact failing regression must remain in the repaired candidate's required suite and pass before the FAIL is cleared.
7. **Fresh-worker equivalence:** a fresh supervisor given the exact SHA and durable verifier records must independently derive the same current status (`FAIL`/conflict), not the earlier PASS.
8. **Audit provenance:** retain both historical PASS and FAIL records, but mark which one is superseded for routing purposes and why; do not delete evidence.
