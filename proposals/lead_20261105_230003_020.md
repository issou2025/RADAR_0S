## Work plan and acceptance gates

### A — Make pilot trustworthy (current two PRs)
- [ ] Verify current exact PR head/base, all mandatory checks, full changed-file scope and reviews; reconcile stale PR prose about earlier HEADs with current evidence.
- [ ] Independently examine rendered GitHub pages/images for both labeled docs, SVG text clipping, contrast, alt text, links and anchor preservation; document unsupported render observations as UNKNOWN. Automated SVG/Markdown tests cannot substitute for independent visual/human domain review.
- [ ] Review and harden label contract/renderer: 3 orthogonal axes, status validation, stable deterministic assets, common palette, escaping/injection/unsupported input tests, no semantic PASS claims.
- [ ] Preserve codeQA current Samuel immutable pin; an upgrade requires separate consumer reviewed approval.
- [ ] Submit scoped implementation and regression fixes to existing branches (where safe and within reviewable change size), read back actual commits and re-run exact-HEAD CI; never merge based on CI alone.

### B — Roll out top-of-document labels responsibly
- [ ] Provide reproducible inventory of **all current** managed codeQA Markdown documents (baseline catalog counted 111; do not freeze that number).
- [ ] Define/validate status fields in catalog and make three chips mandatory for the chosen managed set; gradually cover all docs via small reviewed PRs, preserve published URLs/headings/anchors.
- [ ] Every declared `ADOPTED`, `IMPLEMENTED` or `REVIEWED` requires versioned exact source evidence (ADR/accepted decision; source+tests/coverage; reviewer), with owner and scope. Default to `NOT_EVALUATED` where not proven; `NOT_IMPLEMENTED` is NOT a synonym for `NOT_EVALUATED`.
- [ ] Handle mixed/historical/proposed documents explicitly, preserving at-revision truth and not silently promoting a draft because an issue is closed.
- [ ] Ensure no shadow normative copy, mass relocation, broken links/fragments, or unauthorized public-contract change.

### C — Portable Samuel evidence-aware Consistency QA
- [ ] Extend beyond badge display integrity with separately versioned, read-only evidence/claim review: structured declared vs verified status, evidence revision and exact-SHA provenance, missing/stale witness detection, changed-code revalidation queue, conflict report including UNKNOWN/NOT_EVALUATED. - [ ] Define portable consumer-neutral schema/API, failure taxonomy, deterministic validator with adversarial tests, and integration with existing `documentation-refinement` without adding to `INIT` or changing mutation authority.
- [ ] Qualify against real codeQA snapshot first and another distinct repository with independently corroborated sample; avoid asserting domain judgments without reviewer evidence.
- [ ] Record exact HEAD CI and negative evidence, not just the counts of passing tests.

### D — Complete under governance
- [ ] Obtain independent owner/technical review on Samuel and codeQA PRs and actual rendered-page approval before any merge. Do not impersonate independent reviewer.
- [ ] No unilateral protected-branch merge, cross-repo pin update, schema/public API policy change, or bypass of denied GitHub mutation routes. Work within approved per-repo mutations; when separate explicit approval is necessary, record a precise review question/blocker instead of claiming completion.
- [ ] Close only milestones with readback verified exact-HEAD acceptance; keep unresolved semantic or external-link checks explicitly `NOT_EVALUATED`.
- [ ] Deliver final report with modified PRs, SHAs, exact checks, doc count covered, evidence coverage and remaining independent decisions; stop recurring Controller only after independently verified terminal state (two fresh checks), not on one empty scan.
