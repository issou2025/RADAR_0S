**Fix: Downgrade automation decision logs from WARNING to INFO (supersedes #37)**

*Project description:*
## Summary

Decision-outcome logs — "Applying classification: ...", "Set temperature to ...", "Action recorded: ..." — currently log at WARNING even though they represent normal successful operation, not problems. Per project owner decision, these should log at INFO. Surfaced by #582.

## Background

`docs/06-LOGGING-GUIDELINES.md:36-42` (Level Semantics table) already defines INFO as correct for "lifecycle milestones and meaningful state transitions: setup complete, HVAC mode changes, briefings sent, records saved…" — the doc's own scheme supports this change.

These lines were deliberately elevated `.info()` → `.warning()` in commit `10e5019` ("Issue #37 Logging Fix") specifically because Home Assistant's default log viewer hides INFO-level custom-component logs unless the user adds a `logger:` override in `configuration.yaml`. The motive was visibility, not warning-worthiness (confirmed via commit message and `tests/test_reason_logging.py:4`'s docstring).

## Why this is safe now (was not obviously safe before investigation)

A fully independent, structured data source already exists for the AI Investigator's automation-activity visibility: `ai_skills_context.py:2489-2494` (`build_activity_timeline_context`) builds the ACTIVITY TIMELINE section from `coordinator._event_log`, fed by `coordinator._emit_event()` (`coordinator.py:6332-6347`) via `self._emit_event_callback(...)` calls at the same decision points as the WARNING logs (`automation.py:1037-1038, 1085-1086, 1173-1174`). This is separate from the WARNING-only `log_capture.py` ring buffer that feeds the Investigator's SYSTEM LOG RECORDS section. Downgrading these three log lines to INFO removes them from SYSTEM LOG RECORDS but does NOT reduce the Investigator's visibility into automation decisions.

**Also confirmed: the dashboard's user-facing Activity view is completely unaffected.** The Activity Record tab (`frontend/index.html:666`, `_runActivityRecord()`) calls `GET /api/climate_advisor/activity_record` (`api.py:718-752`), building its table from `coordinator._event_log` — not the Python logger. Setpoint/action data reaches the dashboard through `_last_action_reason`/`_last_action_time` and the `comfort_band_applied` event, also independent of the logger. Daily Briefing narrates from the `DayClassification` object directly. HA's core Logbook is not used by this integration at all. Net effect: a user looking at the Activity Record tab, Daily Briefing, or HA Logbook sees zero change. Only Settings > System > Logs and the Investigator's SYSTEM LOG RECORDS block (both developer/diagnostic surfaces) lose these lines.

## Fix

Change `.warning` → `.info` at `automation.py:835`, `1819-1820`, `2441`.

## Required companion changes (not optional)

All 12 tests in `tests/test_reason_logging.py` filter on `levelno == logging.WARNING` for these exact messages and must be updated to `logging.INFO`: `test_heat_mode_logs_reason` (L143), `test_cool_mode_with_precool_logs_band_reason` (L169), `test_off_mode_logs_reason` (L189), `test_door_open_logs_reason` (L214), `test_door_closed_logs_reason` (L232), `test_occupancy_away_heat_logs_reason` (L287), `test_occupancy_away_cool_logs_reason` (L318), `test_occupancy_home_logs_reason` (L332), `test_bedtime_heat_logs_reason` (L371), `test_bedtime_cool_logs_reason` (L390), `test_morning_wakeup_heat_logs_reason` (L426), `test_morning_wakeup_cool_logs_reason` (L445). Update the module docstring (line 4) to reference this issue's supersession of #37's rationale.

## Optional, not blocking

Note in release notes that HA's default log viewer will no longer surface these by default; users wanting visibility without the Activity Timeline can add `logger: default: info` for `custom_components.climate_advisor`. Consider adding a note to `docs/06-LOGGING-GUIDELINES.md`'s "Thermostat Adjustment Logging" section explaining the #37 → this-issue history so a future session doesn't re-elevate these without checking the Activity Timeline exists first.
