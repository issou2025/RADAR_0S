# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**chameleon_cli: Let developers choose state management (Bloc, Provider, Riverpod) when creating an app**

*Project description:*
## Problem
`chameleon create` currently only supports `--state bloc|cubit` (both flutter_bloc-based). CLAUDE.md's own stack guidance treats Bloc as the *default*, not the *only* option — Provider and Riverpod should be selectable too.

## Proposed scope
- Extend `bricks/chameleon_app`'s `state_management` brick var to accept `bloc` (default) / `cubit` / `provider` / `riverpod`.
- For `provider`/`riverpod`, mirror the existing bloc/cubit example feature's shape (same placeholder feature, same DI wiring philosophy) so the generated app is equally complete regardless of choice — new template work with no reference implementation to port, similar in scope to how `auto_route` support was added.
- `pubspec.yaml` deps conditional per choice (`flutter_bloc` vs `provider` vs `flutter_riverpod` + codegen deps as needed).
- `--state` CLI flag gains the two new allowed values; `chameleon_cli` help text and README updated.
- `.claude/CLAUDE.md` and `docs/architecture.md` in the generated app reflect whichever option was chosen.

## Acceptance criteria
- [ ] All four `state_management` values generate an app that passes `flutter analyze`/`flutter test`/`dart run custom_lint`.
- [ ] `e2e/run_matrix.sh` gains a variant covering at least one non-default state management choice.
- [ ] README documents all four options with a one-line description of when to pick each.
