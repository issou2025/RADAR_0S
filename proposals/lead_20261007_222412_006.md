## Summary

SaaS `3226a92` (*fix(priv): gate vote writes behind the PRIV-12 roadmap surface gate (#618) (#646)*, 2026-10-07 19:23 +0800) landed **15 minutes after** this repo's latest commit `236f627` (19:08 +0800), so the skills were never synced. `POST` and `DELETE /api/v1/feature-requests/:id/vote` are now gated behind the PRIV-12 roadmap surface gate:

- Both routes call `requirePublicSurfaceAccess(c, appId, "roadmap")` immediately after the `allowPublic` check and **before** the feature-request existence lookup and before the `allowAnonymousVote` check (`apps/api/src/domains/feature-requests/routes.ts`, vote POST ~L400 / DELETE ~L523 post-change).
- On a board with `allowAnonymousRoadmap=false`, an **anonymous** vote POST/DELETE now answers the uniform `401 {"error": "Sign in is required to view this roadmap", "code": "authentication_required"}` — no `voteCount` in the body, no ballot row, no `end_users` row, and missing vs. approved request ids are indistinguishable (the gate runs ahead of the existence lookup).
- This holds **even when `allowAnonymousVote=true`** — previously the vote flag was the only gate, so `allowAnonymousRoadmap=false` + `allowAnonymousVote=true` still allowed anonymous vote writes. Signed-in voters keep voting under both vote-flag states.

The bundled skills still teach the pre-gate contract:

- `skills/cupthread-api/SKILL.md:79-80` (vote POST/DELETE endpoint rows) document insert-only semantics, idempotency, rate limits and `shipNotifyEmail`, but never mention the roadmap surface gate.
- `skills/cupthread-api/SKILL.md:401-412` — the **Per-App Anonymous-Access Enforcement (PRIV-12)** table explicitly promises enforcement "on every surface of the family", yet lists only the four reads (`GET` board listing, columns, versions, comments) and changelog subscribe. The two vote-write rows are missing.
- All four SDK skills teach "custom voting UI on top of the client" with no gated-board behavior: `skills/cupthread-swift-sdk/SKILL.md:206`, `skills/cupthread-android-sdk/SKILL.md:209`, `skills/cupthread-react-native-sdk/SKILL.md:217`, `skills/cupthread-flutter-sdk/SKILL.md:196` (each describes the 20/min vote `429` and `shipNotifyEmail`, nothing about a `401 authentication_required` on gated boards).

The CLI itself has no vote commands (verified: no `/vote` call sites under `internal/`), so the drift bites through the skills: SDK developers following them will build anonymous voting UI that starts failing with `401` on gated boards with no guidance to surface a sign-in flow, and agents using `cupthread api request POST /api/v1/feature-requests/{id}/vote` will misread the new `401` as a credentials problem. (The CLI's `unauthorizedHints` in `internal/api/client.go:279-281` already maps `authentication_required` generically, so no CLI code change is needed — this is a documentation/truthfulness gap, the same class as #77.)

## Suggested fix

1. **`skills/cupthread-api/SKILL.md` — PRIV-12 table** (~line 404): add two rows:
   - `POST /api/v1/feature-requests/:id/vote` | anonymous write, `allowAnonymousRoadmap` off | `401` `authentication_required` (uniform body, no `voteCount`; missing and approved ids indistinguishable)
   - `DELETE /api/v1/feature-requests/:id/vote` | anonymous write, `allowAnonymousRoadmap` off | `401` `authentication_required` (same)
2. **Vote endpoint rows** (`skills/cupthread-api/SKILL.md:79-80`): add one sentence noting the roadmap gate and its ordering — on a board with anonymous roadmap view disabled, anonymous vote writes fail with `401 authentication_required` even when anonymous voting is enabled, and the check precedes the feature-request existence lookup.
3. **Client guidance** (end of the PRIV-12 section, ~line 417): extend the sign-in-flow guidance to the vote writes — treat `401` + `code: "authentication_required"` on a vote POST/DELETE as "sign-in required" and surface the host app's sign-in flow, not a hard error.
4. **Four SDK skills** (one sentence each in the vote section): "On boards with anonymous roadmap view disabled, anonymous vote POST/DELETE answer `401 authentication_required` (even when anonymous voting is enabled) — surface the sign-in flow instead of retrying."
