## Project Understanding
You need assistance with: 
**[Ticket]: Check typed app configuration (config/app.yaml and profiles) in real Android, iOS and desktop builds, with flavours, and in fsp dev**

*Project description:*
### Type

Spike / Investigation

### Summary

Since 0.24.0 (#299) an app can keep its own values (an API address, a feature that is on in staging only) in `config/`, and read them as typed constants:
- **`config/app.yaml`** holds the values of every build. **`config/app.<profile>.yaml`** (`app.dev.yaml`, `app.staging.yaml`, ...) changes some of them.
- `fsp gen` writes **`lib/app.config.g.dart`**: a class `AppConfig` with a `static const` for every value, and `AppConfig.profile`, the name of the profile the build has. Every profile's values are in the file, and one compile-time constant picks among them, so the compiler leaves out the others.
- The profile is picked in this order: `--dart-define=FSP_PROFILE=<name>` (what `fsp dev --profile` and `fsp build --profile` pass); else the flavour (`flutter run --flavor`), when a profile has its name; else `dev` in a debug build, when there is a `config/app.dev.yaml`; else `default`, which is `config/app.yaml` alone.
- `fsp dev` hot restarts the app when a file of `config/` changes. A name that is no profile stops the build with a compile error.

The tests cover a lot without a device:
- A test writes the generated file into a scratch Dart package, analyzes it, and runs it with `dart run -DFSP_PROFILE=staging`, `-DFLUTTER_APP_FLAVOR=staging`, `-Ddart.vm.product=true` (a release build) and `-DFSP_PROFILE=stagng` (it must stop on `_fspProfileNamesNoFileOfConfig`). It also compiles it with `dart compile js -O2` in release mode and checks that only the profile's own values are in the JavaScript. CI runs it (`The app configuration compiles and picks its profile`).
- CLI tests run `fsp build` and `fsp dev` against a stand-in `flutter` script (Unix only) and check the profile line, the `--dart-define` flutter gets, and the restart when `config/` changes.

No test has built an app with `flutter build apk` or `flutter build ipa`, installed it, and looked at the screen. No test has used a Gradle flavour or an Xcode scheme. No test has edited a file of `config/` while `fsp dev` ran on a phone. This ticket is that check, and it is the `UNCHECKED` line of `docs/app-config.md`.

Expected result: a report on each case below, per operating system and device.

### Intent

Make sure a developer who writes `config/app.staging.yaml` gets the staging values in the app they really build and install (APK, IPA, desktop), that a build with no flag gets the production values and a debug run gets `dev`, that a flavour picks its profile with no second flag, that a mistyped profile stops the build instead of shipping the wrong values, and that editing `config/` in `fsp dev` restarts the app with nothing stale. These are the claims of `docs/app-config.md`, "Profiles", "Running and building with a profile" and "Flavours and profiles".

### Current Behavior

Checked by tests only:
- The generated file: its Dart analyzes clean, and on the Dart VM and in a release JavaScript build it picks the profile the defines name, as above.
- `fsp build apk --profile staging` and `fsp dev --profile staging` print the profile line and hand `--dart-define=FSP_PROFILE=staging` to a stand-in `flutter`.
- `fsp dev` restarts (not reloads) when `config/app.staging.yaml` changes, with a stand-in `flutter`.
- The refusals of `fsp` itself (`--profile` names no file, `--profile release`, a profile and a define both).

Not checked:
- `flutter build apk` / `flutter build ipa` with the define, and what the installed app shows.
- A release AOT build (Android, iOS): does it hold only its own profile's values?
- That `flutter run` (a debug build) picks `dev` and Flutter's profile mode (`flutter run --profile`, on a device) does not: the test sets the defines by hand.
- `flutter run --flavor staging` with a Gradle `productFlavor` and an Xcode scheme picks `staging` (the generated file reads Flutter's `FLUTTER_APP_FLAVOR`).
- The text of the compile error of a build whose `FSP_PROFILE` names no profile, in Flutter's tool.
- A save of `config/app.staging.yaml` in `fsp dev` on a phone.
- Desktop (Windows, macOS, Linux) and Windows in general.

### Expected Behavior

- **A staging build.** `fsp build apk --profile staging` prints `profile staging (FSP_PROFILE): config/app.staging.yaml over config/app.yaml`, builds, and the installed app shows `profile: staging` and the staging address. The same for `fsp build ipa --profile staging`, and for the desktop targets.
- **No flag.** `fsp build apk` prints `profile default: config/app.yaml`, and the app shows the values of `config/app.yaml`. `flutter run` (a debug build) shows `dev`.
- **A flavour.** `flutter run --flavor staging` shows `staging` with no `--profile`, on Android and iOS. A flavour no profile is named after is no error.
- **`fsp dev`.** Saving `config/app.staging.yaml` prints `hot restart: lib/app.config.g.dart changed` (`[fsp] hot restart: ...` in plain output), the app restarts, and every value on the screen is the new one, including a value that the code read once into a `final`. The profile stays `staging`. A save that does not touch `config/` is a hot reload, as before.
- **A profile that is not there.** `fsp` refuses it before Flutter runs. Flutter, given the define by hand, stops with a compile error that names `_fspProfileNamesNoFileOfConfig`, and no app starts with wrong values.

That `fsp` prints `fsp 0.23.1`, because the release tooling bumps the number when it cuts the release, and `fsp create` then pins `v0.23.1` (that tag exists, and has the same packages): **read `0.23.1` and `v0.23.1` wherever this ticket says `0.24.0` and `v0.24.0`.**

### The cases

**1. A staging build (Android, and iOS on a Mac).**

1a. `fsp build apk --profile staging`. Expect, before Flutter prints anything, these two lines on stderr:
   ```text
   ✓ 2 routes, lib/app.g.dart, lib/app.main.g.dart, lib/app.config.g.dart unchanged
   profile staging (FSP_PROFILE): config/app.staging.yaml over config/app.yaml
   ```
   (The first may say `→` and name the files it wrote: it starts with `✓ 2 routes`.) Then Flutter's own build, and exit 0 with the APK at `<apk>`. Install it (setup 8). The screen must show:
   ```text
   Config demo
   profile: staging
   api: https://staging.example.com
   api (read once): https://staging.example.com
   ```
   Take a screenshot.

1b. *Optional, macOS and Linux.* The other profiles' values should not be in the release build. We have not looked at an APK:
   ```sh
   unzip -p build/app/outputs/flutter-apk/app-release.apk lib/arm64-v8a/libapp.so | strings | grep -c "staging.example.com"
   unzip -p build/app/outputs/flutter-apk/app-release.apk lib/arm64-v8a/libapp.so | strings | grep -c "localhost:8080"
   unzip -p build/app/outputs/flutter-apk/app-release.apk lib/arm64-v8a/libapp.so | strings | grep -c "https://api.example.com"
   ```
   We expect a number above 0 for the first and 0 for the other two. Report the three numbers, whatever they are. If the path does not exist, `unzip -l <apk>` lists what is there.

1c. *On a Mac:* `fsp build ipa --profile staging -- --export-method development`. Expect the same two lines (the first may differ), then Xcode's build. (`--export-method` is Flutter's; if your Flutter names the methods differently, `flutter build ipa --help` lists them. The default, `app-store`, makes an IPA that cannot be installed on a device.) Flutter prints where the IPA is (under `build/ios/ipa/`). Install it on an iPhone (Xcode, Window, Devices and Simulators, select the phone, `+` under Installed Apps, choose the file) and open it. The screen must show the same four lines as 1a.
   - If the build stops on signing, paste the error and do this instead: `fsp build ios --profile staging -- --no-codesign`. Expect the two lines and exit 0, and mark the screen check *not run*. If you can sign with a free personal team, `flutter run --release -d <iphone> --dart-define=FSP_PROFILE=staging` shows the same four lines (it does not go through `fsp`).

**2. No flag: release is the default, debug is `dev`.**

2a. `fsp build apk`. Expect `profile default: config/app.yaml` as the second line, exit 0. Install `<apk>`. The screen must show:
   ```text
   Config demo
   profile: default
   api: https://api.example.com
   api (read once): https://api.example.com
   ```
2b. `flutter run -d <id>` (a debug build, no `fsp`). The screen must show `profile: dev` and `api: http://localhost:8080`. Press `q` to quit.
2c. `fsp dev --no-tui -- -d <id>`. Expect the line `[fsp] profile dev (a debug build): config/app.dev.yaml over config/app.yaml`, and the same screen as 2b. Press `q` to quit.
2d. *Optional, a physical phone (profile mode does not run on emulators):* `flutter run --profile -d <id>`. Flutter's profile mode is not a debug build, so we expect `profile: default`. Report what the screen shows.

**3. `fsp dev --profile staging`: edit `config/` while the app runs.**

3a. `fsp dev --no-tui --profile staging -- -d <id>` (plain lines are easier to paste than the full-screen view; in the full-screen view the same lines are in the `fsp` pane, without the `[fsp]`). Expect, among the first lines:
   ```text
   [fsp] profile staging (FSP_PROFILE): config/app.staging.yaml over config/app.yaml
   ```
   Wait for the app. The screen shows `profile: staging`, `api: https://staging.example.com` and `api (read once): https://staging.example.com`.
3b. Change `config/app.staging.yaml` to `base_url: https://staging2.example.com` and save. Expect this line, soon after:
   ```text
   [fsp] hot restart: lib/app.config.g.dart changed
   ```
   Flutter then restarts the app (it says so in its own words; paste them). The screen must now show `profile: staging`, `api: https://staging2.example.com` **and** `api (read once): https://staging2.example.com`. The last one is the point: a value read once into a `final` keeps its old value through a hot reload, and a restart reads it again. If it still says `staging.example.com`, that is a fail.
3c. Change `app_name` in `config/app.yaml` to `Config demo 2` and save. Expect the same `hot restart` line and the new name on the screen.
3d. Change a word in `lib/app/page.dart` (`'api: ` to `'API: `) and save. Expect **no** `hot restart: lib/app.config.g.dart changed` line: it is a hot reload (Flutter says `Reloaded ...`), the new word shows, and `api (read once)` is unchanged.
3e. Press `q`. Expect exit 0 and the prompt back. Put `config/` back (`staging.example.com`, `Config demo`) before the next cases.

**4. A profile that is not there.** `nope` names no file in `config/`.

4a. `fsp build apk --profile nope`. Expect exit 1, and this one line, with no Flutter output after it:
   ```text
   `--profile nope`: there is no config/app.nope.yaml; the profiles are default, dev, staging
   ```
4b. `fsp build apk -- --dart-define=FSP_PROFILE=nope`. Expect exit 1 and:
   ```text
   `--dart-define=FSP_PROFILE=nope`: there is no config/app.nope.yaml; the profiles are default, dev, staging
   ```
4c. Past `fsp`, with Flutter alone: `flutter build apk --dart-define=FSP_PROFILE=nope`. Expect a non-zero exit and a compile error, with no new APK. `docs/app-config.md` says the compiler reports `Constant evaluation error` at `_fspProfileNamesNoFileOfConfig`. **Paste the whole error**, and say whether it names `lib/app.config.g.dart` and a line.
4d. `flutter run -d <id> --dart-define=FSP_PROFILE=nope` (a debug build). Expect a compile error too, and that the app on the device is not started with other values. Paste the error.
4e. *Optional.* `flutter test --dart-define=FSP_PROFILE=nope` and `flutter build web --dart-define=FSP_PROFILE=nope` (needs Chrome support): both should stop the same way. And `flutter run -d <id> --dart-define=FSP_PROFILE=` (an empty value means `default`): the screen should show `profile: default`.

**5. Flavours.** Do this after cases 1 to 4: it changes the native projects. Flutter's pages (Source of truth) are the reference; this is the least that works. Afterwards a plain `flutter run` or `flutter build apk` stops and asks for a `--flavor`: that is Flutter, not `fsp`.

*Android.* In `android/app/build.gradle.kts`, inside the `android { ... }` block, add:
   ```kotlin
   flavorDimensions += "env"
   productFlavors {
       create("staging") { dimension = "env" }
       create("prod") { dimension = "env" }
   }
   ```
*iOS (on a Mac).* Open `ios/Runner.xcworkspace` in Xcode.
   1. Click the blue `Runner` project in the left list, then the `Runner` project (not the target) in the middle, and the Info tab. Under Configurations, click `+` and Duplicate each of `Debug`, `Release` and `Profile`, and name the copies `Debug-staging`, `Release-staging` and `Profile-staging`.
   2. Product, Scheme, Manage Schemes. Select `Runner`, click the gear and Duplicate. Name it `staging` and make sure Shared is ticked.
   3. Edit the `staging` scheme (Product, Scheme, Edit Scheme): Run uses `Debug-staging`, Test `Debug-staging`, Profile `Profile-staging`, Analyze `Debug-staging`, Archive `Release-staging`.

5a. Android: `flutter run --flavor staging -d <android id>`, no `--profile`. The screen must show `profile: staging` and `api: https://staging.example.com`. (A debug build with the flavour `staging`: the flavour comes before `dev`.)
5b. iOS: `flutter run --flavor staging -d <iPhone or simulator id>`. The same screen. If you did not set up iOS, mark it *not run*.
5c. A release build with a flavour, through `fsp`: `fsp build apk -- --flavor staging`. Expect the profile line
   ```text
   profile staging (the flavour): config/app.staging.yaml over config/app.yaml
   ```
   and exit 0. Install `build/app/outputs/flutter-apk/app-staging-release.apk` (Flutter prints the path; the name may differ) and open it: `profile: staging`.
5d. A flavour no profile is named after: `flutter run --flavor prod -d <android id>` must start with no error and show `profile: dev` (a debug build). `fsp build apk -- --flavor prod` must print `profile default: config/app.yaml` and the installed release app shows `profile: default`.
5e. *Optional.* The explicit profile wins over the flavour: `fsp build apk --profile dev -- --flavor staging` must print `profile dev (FSP_PROFILE): config/app.dev.yaml over config/app.yaml`, and the installed app shows `profile: dev`.

**6. Desktop (optional).** On Windows, macOS or Linux, for your own system. (Flavours are not needed. Case 5's Gradle and Xcode edits do not touch these projects.)

6a. `fsp build windows --profile staging` / `fsp build macos --profile staging` / `fsp build linux --profile staging`. Expect the two lines of 1a, exit 0, and Flutter prints the path of the app. Run it. The screen must show the four lines of 1a with `staging`.
6b. `fsp build windows` (macos, linux) with no flag, run: `profile: default`. And `flutter run -d windows` (macos, linux): `profile: dev`.
6c. On Windows, say if anything differs: the paths in the messages, `fsp` finding `flutter.bat`, the `[fsp]` lines.
