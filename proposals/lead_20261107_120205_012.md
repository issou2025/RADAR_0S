# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Deliver workflow log analysis reports through a pull request, and purge only processed docs**

*Project description:*
## Summary

Since 2026-10-26 the ruleset "Required checks for default branch" (id 25851281) requires the `lint` and `ai-review/head-gate` checks on `main`, with no bypass actors. `workflow-log-analysis.yml` still pushes its report straight to `main`, so every dispatched run since 2026-10-27 fails at "Commit and push report" with GH013 (31 failed runs, for example 42318132836). No analysis doc has landed since `analysis/workflow-optimization-2026-10-25.md`, so the apply-analysis loop is consuming a backlog that no longer refills.

This change does two things in one PR:
1. Each run commits its report, and any appended sections, to a branch for that run. A final job opens one pull request into the default branch, which CI and the review workflow merge. This is the route the nightly self-test already uses (#8225, #8229).
2. The 30-day purge deletes a doc only once `analysis/recommendation-processing-report.md` lists it. The failed 11-07 run would have purged 5 unprocessed docs (10-06-2 and 10-07 through 10-07-4). The 09-24 and 09-24-2 docs were already lost this way in commit `0fcc49b2`.

## Context

- Three jobs in `.github/workflows/workflow-log-analysis.yml` push to `main` directly:
  - `analyze-commit-notify`, step "Commit and push report" (~L1445–1606, push at ~L1583).
  - `deep-audit`, steps "Sync latest report from target branch" (~L1827) and "Commit and push deep audit section" (~L2156, push at ~L2203).
  - `api-redundancy`, steps "Sync latest report from target branch" (~L2426) and "Commit and push API redundancy section" (~L2754, push at ~L2796).
- Both later jobs re-sync the report from `main` and append to the file named by `needs.analyze-commit-notify.outputs.report_file`.
- Reference implementation: `.github/workflows/nightly-validation-selftest.yml`, job `commit-selftest-status` (~L187–472). It pushes a new per-run branch with GH_PAT through a one-shot credential helper, lints the PR body with `scripts/lint_pr_body_auto_close.py`, runs `gh pr create`, and logs stable `VALIDATION_SELFTEST_STATUS outcome=...` lines. Its tests are in `tests/test_nightly_validation_selftest_workflow_contract.py`.
- Purge today: inside "Commit and push report". It deletes `analysis/workflow-optimization-<date>(-N).md` older than `WORKFLOW_LOG_ANALYSIS_REPORT_RETENTION_DAYS` (default 30), except docs that open apply-analysis projects still read (`APPLY_ANALYSIS_IN_FLIGHT_DOCS=true bash scripts/apply_analysis_on_main.sh`).
- "Processed" already has a definition in `scripts/apply_analysis_on_main.sh` `unprocessed_docs()` (~L332): the doc's basename appears in `analysis/recommendation-processing-report.md` (`grep -qF`).
- The report filename is chosen in the analyze step from the local checkout. Concurrent or overlapping runs can pick the same `-N` suffix, which is why the current push loop renames on collision with `origin/main`.

## Goals

- Dispatched runs deliver the report to the default branch again, without bypassing the ruleset.
- A run's report and its deep-audit and API-redundancy sections land together in one PR. If a later job fails or is skipped, the PR still carries whatever completed.
- No unprocessed analysis doc is ever deleted by the purge.
- Failure modes are logged with stable, searchable prefixes.

## Non-goals

- Changing the ruleset, adding bypass actors, or adding a review bypass for report PRs.
- Deduplicating findings against the processing report, or adding consumer-repo coverage. These are separate, later work.
- Changing the report filename format, the doc glob, or `scripts/apply_analysis_on_main.sh` dispatch behaviour.
- Changing `comprehensive-test-and-release.yml` or the release gate dispatch in `test-and-mark-stable.yml`.

## Constraints

- §6: keep every existing step `name:`/`id:`, job id, output (`report_file`, `analysis_status`, `audit_status`, `api_redundancy_status`), env var (`WORKFLOW_LOG_ANALYSIS_REPORT_RETENTION_DAYS`) and log prefix. Add new outputs and log values alongside them.
  - `WORKFLOW_LOG_ANALYSIS_PURGE_SKIPPED doc=${old_report} reason=in_flight_project` must stay byte-identical, because `tests/test_apply_analysis_on_main.py:568` asserts it.
- §9: YAML uses 2-space indentation; shell scripts use tabs, with opening braces on a new line.
- §15: no new per-item API loops. The delivery job may make 1 open-PR list call (`pulls?state=open&base=<default>&per_page=100`, paginated) and 1 PR create. Collision checks against other report branches use `git fetch`, not the API.
- §19: lint the PR body with `scripts/lint_pr_body_auto_close.py` before the push.
- §23.E: authenticate the push only through a credential helper that reads the token from env. Never print the token.
- §27: `workflow-log-analysis.yml` is about 142 KB. Put the new delivery logic in a script, not inline YAML.
- §20 and §30: add one `changelog.d/` fragment and one `agents.d/` fragment. Never edit `CHANGELOG.md` or `agents.md` directly.

## Approach

### 1. One branch per run

- Branch name: `auto/workflow-log-analysis-report-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}`.
- **Commit and push report:**
  - Keep the purge (changed per §3 below), the commit, and the existing rename-on-collision check against `origin/<default>`.
  - Replace the `git pull --rebase` + `git push origin HEAD:${TARGET_BRANCH}` loop with a push of `HEAD` to `refs/heads/<run branch>`. This is a branch creation, so it is always a fast-forward. Retry transient failures with the existing backoff.
  - If the push output matches `GH006|GH013|protected branch|push declined|repository rule`, log `WORKFLOW_LOG_ANALYSIS_REPORT_DELIVERY outcome=failed reason=push_rejected_by_ruleset branch=<b>` and exit 1.
  - Add job outputs `committed` (true/false) and `report_branch` to `analyze-commit-notify`.
- **Sync latest report from target branch** (both later jobs): when `needs.analyze-commit-notify.outputs.report_branch` is non-empty, fetch and check out that branch instead of the default branch. Otherwise keep the current behaviour.
- **Commit and push deep audit section / API redundancy section:** push to the run branch, not `TARGET_BRANCH`. Only this run writes the branch and the jobs run one after another, so drop the rebase onto `main`.

### 2. New `deliver-report` job

- Header:
  - `needs: [analyze-commit-notify, deep-audit, api-redundancy]`
  - `if: ${{ always() && github.event_name != 'schedule' && needs.analyze-commit-notify.outputs.committed == 'true' }}`
- Steps: checkout with the GH_PAT token, fetch the run branch, then run the new `scripts/workflow_log_analysis_deliver_report.sh`. The script:
  1. Lists open PRs into the default branch (1 paginated call). For each head ref starting with `auto/workflow-log-analysis-report-`, other than this run's, it `git fetch`es the branch.
  2. If `report_file` exists on `origin/<default>` or on any of those branches, it `git mv`s the file to the next free `-N` suffix across all of them, commits, and pushes to the run branch.
  3. Writes the PR body, which states the run URL, the report path, the purged docs, and why the report comes through a PR. It lints the body with `scripts/lint_pr_body_auto_close.py`.
  4. Runs `gh pr create --base <default> --head <run branch>` with GH_PAT. If create fails, it falls back to `gh pr list --head` the way the self-test does.
  5. Logs `WORKFLOW_LOG_ANALYSIS_REPORT_DELIVERY outcome=pr_opened branch=<b> pr=<n> file=<path>`. Failure values are `reason=pr_body_lint_failed|pr_create_failed|token_missing|push_rejected_by_ruleset`.
- Fail closed: the job fails if GH_PAT is empty, because PRs created with `github.token` do not trigger CI.
- Leave the run branch in place after the PR opens. The ruleset blocks branch deletion.

### 3. Purge only processed docs

In the purge loop, after the in-flight check and the date check, skip the doc unless its basename appears in `analysis/recommendation-processing-report.md`. Use the same `grep -qF` test as `unprocessed_docs()`. A skipped doc logs `WORKFLOW_LOG_ANALYSIS_PURGE_SKIPPED doc=<path> reason=unprocessed`, an additive new reason value. If the processing report is missing, skip the whole purge with a warning. Deletions ride in the report PR.

### 4. Notifications and docs

If the "Send Telegram notification" text in `analyze-commit-notify` says the report was pushed to the branch, change it to say a report PR is being opened.

## Phases & Merge Strategy

There is one phase and one PR, by design. Delivery and the purge rule must land together: delivery without the purge rule would immediately delete 5+ unprocessed docs through the first report PR. Before merge the workflow is broken (GH013), and after merge it works, so the PR is production-safe on its own. Rollback is reverting the PR, which returns to the current failing state with no data loss.

- The in-flight purge log line is unchanged, the `reason=unprocessed` skip exists, and it is checked before `git rm`.

Behaviour tests for the script, using a local bare git remote and a stubbed `gh` on `PATH`:
- No collision: the PR opens and `outcome=pr_opened` is logged.
- Collision with the default branch, and collision with another open report PR's branch: the file is renamed to the next free suffix.
- Missing token: exit 1 with `reason=token_missing`.
- PR create fails, but `gh pr list` finds the PR: success.

Purge behaviour: a doc that is old but unprocessed is kept; an old, processed doc is deleted; an in-flight doc is kept; a missing processing report means no purge.

## Risks & Mitigations

- **Overlapping runs pick the same filename.** Mitigation: the delivery job checks the default branch and every open report branch before it opens the PR. A remaining race at merge time shows up as a merge conflict on the later PR, not as lost data.
- **Each report PR costs a CI and AI review cycle** on 70–90 KB of markdown. ACCEPTED: this is the same route the self-test PRs take (for example #8948 merged about 52 minutes after it opened). Cheapening the review path is out of scope.
- **Report PRs pile up if review does not merge them.** Mitigation: the delivery log line names the PR, so stuck PRs are visible. No auto-close is added.
- **Docs are never purged while unprocessed, so the backlog can grow.** ACCEPTED: user decision Q2:A. Deduplication is planned separately.
- **The deep-audit and API-redundancy jobs read the run branch** instead of the default branch. Mitigation: they fall back to the current behaviour when `report_branch` is empty.
