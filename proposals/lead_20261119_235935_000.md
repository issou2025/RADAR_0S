# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Excel VBA macro workbooks: add a read, diagnose and safe-edit skill**

*Project description:*
## Context

A user asked for help with an Excel macro workbook (.xlsm) that manages keynotes for drawing sets. A button in the workbook failed with a VBA compile error. No am-* skill covers Excel VBA, so the session used ad-hoc steps. Related, but not the same: #170 (keynote file editor), #182 (project documents as task input).

Environment: Windows 11, Excel (Microsoft 365, 16.0), Claude Code desktop. No Revit in this session.

## What happened

1. **Diagnosis from a screenshot was quick.** "Compile error: Variable not defined" with `Option Explicit` on. One local variable was used but not declared.
2. **Finding the workbook cost time.** A recursive search of Downloads, Desktop, Documents and OneDrive timed out (OneDrive is large). The Excel MRU list and Recent folder did not list the file. A search of Downloads only (depth 3) found it at once. The user had to say "in Downloads".
3. **Reading the VBA source needed a custom tool.** `oletools` and `olefile` were not installed. The agent wrote a small CFB reader plus MS-OVBA decompressor (about 150 lines of Python) to dump all modules, then a heuristic scan for undeclared variables. This worked, but it is not reusable today.
4. **Excel blocked live access.** In VBA break mode, `GetActiveObject("Excel.Application")` failed (MK_E_UNAVAILABLE).
5. **Editing the code needs "Trust access to the VBA project object model".** The agent correctly did not change this security setting and asked the user to do it.
6. **The first attempt to enable it did not save.** The registry value `HKCU\...\Excel\Security\AccessVBOM` was missing. In PowerShell COM, `$wb.VBProject` then returned `$null` and gave a misleading "cannot call a method on a null-valued expression" error, not an access-denied error. After the user re-ticked the box and clicked OK in both dialogs, `AccessVBOM = 1` and the fix worked.
7. **Fix flow that worked:** back up the file, open in a hidden Excel with `AutomationSecurity = 3` (macros disabled), `CodeModule.InsertLines`, run "Compile VBAProject" (VBE control id 578), save, then read the saved file back with the custom reader to confirm the line is there.

## Proposed change

Add a small skill, for example `am-excel-vba`, for macro workbooks that architects use beside Revit (keynote masters, sheet lists):

- Locate the file: ask for the path, or search Downloads and Desktop first (shallow), never a full OneDrive recursion.
- Ship the read-only VBA dump script (CFB + MS-OVBA decompress, no third-party packages) and the undeclared-variable scan.
- Before any COM edit, check `AccessVBOM` in the registry. If it is not 1, tell the user the exact clicks (tick, OK in Trust Center, OK in Excel Options, close Excel). Treat a `$null` VBProject as "trust access off".
- Edit flow: backup, hidden Excel with macros disabled, insert lines, compile, save, read back from the saved file.
- After the fix, remind the user to turn trust access off again.

## Acceptance ideas

- The dump script prints every module of a test .xlsm with no extra packages.
- The skill stops with a clear message when `AccessVBOM` is not 1, and does not change it.
- A one-line fix ends with a read-back that shows the new line in the saved file.

Not verified: the compile step reports errors only as a modal dialog. In this session the project had no other errors, so the case "compile finds another error in hidden Excel" (possible hang) was not tested.
