## The one real behaviour change — call it out in the PR body

Event-driven saw **every** run. A poll sees only the **latest** run per workflow, so a failure that
self-heals between polls is missed.

This is an acceptable, arguably better fit: the rolling issue answers *"is this workflow currently
broken?"*, which is exactly what latest-run state models. Do not add cursor/state tracking to chase
the transient case — it trades the simplicity that makes this verifiable for little value.
