# Add opt-in Fleet activity observations to the Argus exporter

Argus currently reads legacy Agamemnon agents/tasks. It cannot report whether
the Fleet read model recently observed an admitted logical agent doing model or
tool work. Add this read-only observation slice to support the first-worker
demonstration.

The result measures **recently observed activity**, not exact current occupancy,
tool success, independently approved completion, or the 108-agent acceptance goal.

## Observation semantics

Count distinct logical `agentId` values, not processes or resource rows. Active
observations require a current matching worker generation, claimed admission,
`observationState=observed`, positive source sequence, consistent identity and
lifecycle, and `activity` equal to `model_working` or `tool_running`. Conflicting
admitted rows for one agent cannot inflate the count.

Both worker `lastActivityAt` and controller `lastActivityReceivedAt` must be valid,
timezone-aware, not future, and at most 60 seconds old. Unclaimed/released, idle,
and waiting records never earn activity credit. Missing, stale, disconnected,
cold-hydrated, awaiting-observation, old-generation, or inconsistent potentially
admitted records make classification incomplete. Never reuse an earlier good
scrape as current evidence.

Merged Hephaestus `ce29bd8732cceaadcd958d0b58586be81a4de73f` refreshes activity on
matching provider events, at most once per five seconds; it has no periodic
heartbeat guarantee. Quiet work can remain active beyond 60 seconds. Treat that
silence as unknown, not idle. Worker/controller/exporter clock skew can also
make classification unknown; fresh receipt alone cannot repair an old worker
observation. These three list reads are not an atomic occupancy snapshot.

## Metrics

All new metrics are gauges with documented HELP/TYPE. Use only fixed labels:

| Metric | Meaning |
|---|---|
| `homeric_exporter_fleet_enabled` | Explicit opt-in, always present. |
| `homeric_exporter_fleet_fetch_success{resource}` | Three resources: `workers`, `sessions`, `executions`; bounded valid list read succeeded. |
| `hi_fleet_activity_complete` | Every potentially admitted agent can be classified under the recent-observation policy. |
| `hi_fleet_recently_observed_active_agents{activity,work_kind}` | Four series: `model_working`/`tool_running` × `issue`/`interactive`; distinct qualifying logical agents. |
| `hi_fleet_observation_exclusions{reason}` | Per-scrape record counts for fixed exclusion reasons. |

Use these eleven reasons: `inactive_claim`, `unobserved`,
`reconciliation_required`, `stale`, `invalid_timestamp`, `generation_mismatch`,
`missing_worker`, `invalid_record`, `ambiguous_agent`, `unknown_activity`,
`disconnected`. Expected inactive claims alone do not make completeness false.
The maximum is 20 new series per exporter. Do not label metrics with task,
prompt, credential, workspace, agent, worker, host, pool, provider, or event IDs.

With Fleet enabled, emit four zero counts only for a complete empty/nonactive
observation set. Omit count samples when classification is incomplete and expose
the completeness/diagnostic signals. Document a query gated by current
`hi_fleet_activity_complete == 1` to prevent Prometheus lookback from displaying
old counts. Never replace unavailable data with `or vector(0)`.

`work_kind=issue` requires a valid canonical `taskId` link; that link alone does
not verify GitHub issue eligibility. No approved-completion metric is added.
Manual resolution with `verifiedApproval=false` never establishes approval.

## Observable acceptance criteria

- Default opt-out makes no Fleet requests and preserves legacy output. Enabled
  collection performs exactly the three GETs with authentication confined to
  Agamemnon; fetch/configuration failures leave legacy metrics available.
- A complete empty set yields completeness 1 and four zeros. Failed reads,
  envelope mismatch, malformed data, duplicate IDs and input-limit overflow
  produce incomplete/unavailable Fleet data without invented zero counts.
- One valid claimed issue agent running a tool counts once; two agents sharing
  one runtime count two; conflicting rows cannot count one agent twice.
  Interactive observations remain separate.
- Deterministic clock fixtures cover fresh, exactly 60-second, stale, future,
  malformed, and delayed-delivery timestamps. Cold hydration, awaiting activity,
  old generation, absent worker, invalid sequence and quiet work never become
  active credit. A later valid scrape can recover without cached success.
- Provider completion, successful command acknowledgment and manual resolution
  cannot create approved-work credit. Prompt/key/workspace canaries never appear
  in metric labels, metric bodies, or diagnostic logs; input cannot enlarge the
  fixed label domains.
- Focused tests exercise public `collect()` behavior in `tests/test_exporter.py`,
  plus the authenticated fetch/TLS boundary. Documentation explains the read-only
  component boundary, opt-in dependency, unknown/zero distinction, query gate,
  event-driven cadence and first-worker acceptance limits.
