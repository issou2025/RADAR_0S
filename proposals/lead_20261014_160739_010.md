## Context

The hackathon rules require build and run instructions, and they are deliverable 2 of #4. `README.md` already carries the description, the architecture, the on-chain testnet evidence and the 8 demo agents, but it never says how to clone the repo and get it running. A judge scoring *does it work* (30%) has no path to run it.

#4 has no owner and PR #157, which touches `README.md`, is blocked with CHANGES_REQUESTED. This issue splits the README work out so it can be assigned and closed on its own.

## Deliverables

1. A build-and-run section in `README.md` with:
   - prerequisites with the CI versions: Flutter 3.44.4, its bundled Dart, Docker
   - `docker compose up -d postgres_test redis_test` for the local database and cache
   - the `.env` setup from `.env.example`, naming which values are needed and which are secret
   - how to run the server, and how to run the Flutter web app against it
   - the quality gates: `dart analyze --fatal-infos`, `dart test test/unit test/hire test/ledger`, `flutter analyze --fatal-infos`, `flutter test`, `flutter build web --release`

## Acceptance criteria

- [ ] A developer who has never seen the repo reaches a running server and app following only the README
- [ ] The versions match the ones the CI uses (Flutter 3.44.4)
- [ ] Every command is copied from one that actually runs, not written from memory
- [ ] It names the variables required to boot and points to `.env.example`
- [ ] Running it locally needs no real secret, and none is printed in the README

## How to verify

```bash
git clone https://github.com/Zer0-Knowledge-Hack/puls3 /tmp/puls3-clean
cd /tmp/puls3-clean
```

Then follow only the README, and confirm `health/check` answers on the local server and the web app loads against it.
