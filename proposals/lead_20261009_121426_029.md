# bug 9 — `app_canvas` is completely non-functional (one-line fix)

**Environment:** Altium Designer 25.8.1.18 Professional, Windows 11,
Python 3.14, eda-agent 0.6.1. Measured 2026-10-08.

## Symptom

Every `app_canvas` click and drag fails:

```
NameError: name 'wintypes' is not defined
```

No pointer automation in the package can execute.

## Cause

`ui/windows.py` does `import ctypes` (line 49) but never imports
`ctypes.wintypes`. That is a SUBMODULE and is not pulled in by `import
ctypes`. Both pointer entry points use it:

- `drag()` — line 996, `wintypes.POINT()`
- `click_at()` — line 1049, `wintypes.POINT()`

`ui/controls.py` (line 35) and `ui/menu.py` (line 54) import it correctly,
which is why `app_click_menu` works and `app_canvas` does not.

## Fix

```python
from ctypes import wintypes
```

in `ui/windows.py`.

## Why it mattered

`app_canvas` is the only route to Altium controls that own no window handle.
UIA (`app_invoke_element`) sees only the top-level frames inside the Properties
panel, so with this dead there was no way to reach the 3D-body Opacity field at
all — which is what sent us looking for the scripting route in the first place
(see feature 4).
