# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**PRD: Ship `design` — the first per-domain skill plugin, marketplace, gate, and critic**

*Project description:*
## 1. Problem

The owner is not a designer, builds UI and visual work across several separate codebases — the owner's own companies (Audiora, DJPRAGUE, Wedly) and client work — and has no repeatable way to carry design judgment between them, nor any guarantee of being grilled on a design before UI code gets written. Today the only mechanism is copy-on-clone: a skill copied into a clone never receives another update, and projects that are not template clones never receive it at all. Copying also carries no subagent or hook, so even when a skill's prose travels, the adversarial UI review and the "no UI code before a design is approved" gate cannot. Separately, this template's own autonomous BUILD LANE (`/ship`) has no concept of design at all: an implementer can write and merge UI code with no rendered review and no check that a human ever approved a direction. The grill session on 2026-09-23 (owner = repo owner, not a designer) resolved that these are the same problem — a distribution mechanism for a per-domain skill library — and that `design` ships first, alone, so its 8 skills, its one subagent (`ui-critic`), and its gate hook can be hand-built and dogfooded (rule #3) before `skill-foundry` (PRD 4) automates making more of them. The old standalone "propagation" PRD is absorbed here: the marketplace + plugin packaging IS how design ships, to any repo, not only template clones.

## 2. Goal / Success criteria

Ship a Claude Code plugin named `design`, distributed from a marketplace hosted in this repo, installable at user (account-wide) scope pinned to a commit sha, usable in any repo — carrying 8 design skills, the `ui-critic` subagent, and a design-approval gate hook that blocks UI-code edits in an opted-in repo until a human has approved a `DESIGN.md`. This template repo itself carries no brand and does not opt into the gate.

## 3. Non-goals / Out of scope

- **Graphics, print, and video skills** — separate PRDs 2–3; research already done 2026-09-23.
- **`skill-foundry`** — PRD 4; rule #3 requires hand-building and dogfooding design's own skills before automating skill-making.
- **Logo creation** — no evidence-backed seed exists for it, and it's identity work a real designer should do; `design-system` instead builds a kit FROM an existing logo.
- **Handoff tooling, native mobile apps, and 3D** — locked out of scope by the grill; no seed, no owner need identified.
- **Uploading skills to claude.ai** — Anthropic's docs do not document Claude Design using Agent Skills, so the brand's Claude Design design system carries the rules instead (Q20); a test upload is tracked separately as issue #1552.
- **An entry/router command** — skills fire automatically by description (Q19); a router adds a hop nothing needs.
- **`ui-critic` as a `pr-merge` merge gate, or as advisory-only** — Q6 rejected both extremes; it blocks via the standard critic round-cap before the reviewer, while the reviewer stays the sole merge gate.
- **Widening `ui-critic` to judge graphics or video** — out of scope per Q18; those get mechanical preflight + the owner's own blind picks instead.
- **A CI backstop for Bash-written UI files that bypass the Edit|Write gate** — rejected in Q4 as a second enforcement mechanism; accepted, documented gap.
- **Rewriting shadcn** — installed and consumed upstream, as-is.
- **Copying Vercel or other unlicensed/unconfirmed-licence sources** — reference-only per the sourcing policy; never distilled into shipped rule text.
- **Any real brand content (DJPRAGUE, Audiora, Wedly, or a client) inside this template** — Q13; this template holds no brand.
- **Reproducing the lost `design-skills-multisource-v3.csv` dataset** — Q15; it survives only as a claude.ai chat attachment with no recorded score formula, so the `skill-foundry` PRD (4) passes on coverage of the locked seed list instead.
- **Propagating the agent PIPELINE itself to clones** — tracked separately at #1295; unrelated to shipping the skill library.
- **The repo-name sweep** — tracked separately at #1296; unrelated to this feature.

## 4. Appetite / Constraints

Slice budget 8–11 (large: 8 skills + 1 subagent + 1 hook + an eval harness; the slicer owns the exact cut per rule #16). Time appetite 4–6 sessions. Per-slice cap ≤600 runtime LoC (R-LOC, per ADR-0077 D1). No new runtime dependency for THIS repo's own CI: Playwright Python is already installed by `bootstrap.sh` per ADR-0050; Node/axe-core are used only inside `ui-critic` runs and the eval harness, and only in the consumer repo where the plugin is enabled — never as a dependency of this repo's own `tools/ci-checks.sh`. Guardrail ack (CLAUDE.md rule #4, ADR-0070 D4): today `dashboard/health.py::_is_guardrail_path` matches critic prompts only under `.claude/agents/`, so `plugins/design/agents/ui-critic.md` is NOT yet guardrail-classified. This PRD extends the classifier to `plugins/*/agents/*-critic.md` (criterion 31, per ADR-0093 D6); from then on, promotion of any batch touching `ui-critic.md`, `tools/ci-checks.sh`, `.claude/settings.json` or the classifier itself requires the operator's `.claude/PROMOTE_OK` ack — including the batch that lands the extension, since it changes the promotion gate. Whether the plugin's gate hook (`plugins/*/hooks/**`) should also be guardrail-classified is NOT decided here (see §6).

## 5. Solution sketch

- `.claude-plugin/marketplace.json` (repo root) — lists plugin `design`, source `./plugins/design`.
- `plugins/design/.claude-plugin/plugin.json`; `plugins/design/README.md` (install at user scope, pin to a sha, update = bump the sha, how a consumer repo opts in).
- `plugins/design/skills/<8 skills>/SKILL.md` (+ `references/` where needed: `ui-build`'s `app-patterns.md`, `page-sections.md`).
- `plugins/design/agents/ui-critic.md` — the one subagent this plugin ships (ADR-0093).
- `plugins/design/hooks/` — the plugin's own PreToolUse hook config + gate script (ADR-0092); independent of `.claude/hooks/pre-tool-edit.sh`.
- `plugins/design/SOURCES.md` — seeds, pinned 40-hex commits, SPDX licences, reference-only markers.
- `plugins/design/evals/` — T1–T8 task specs, fixtures (scripted persona answers, a reference screenshot, planted-defect + clean-control screens), machine-check scripts, the blind-pair generator.
- `.claude/skills/ship/SKILL.md` — build-lane hookup: dispatch `ui-critic` before the reviewer on UI-touching slices in opted-in repos.
- `bootstrap.sh` — a UI opt-in step for a fresh clone (writes the gate's marker).
- `dashboard/health.py` `_is_guardrail_path` — extended to classify `plugins/*/agents/*-critic.md` as guardrail machinery (ADR-0093 D6 extending ADR-0070 D4).
- `tools/gen_rules.py` — statements for PIP-035…PIP-039 and HOK-010/HOK-011 in `_RULE_STATEMENTS`, `RULE_IDS_BASELINE` +7, and the `hooks` scope's `paths:` gaining `plugins/*/hooks/**` (ADR-0092 D8); regenerate `.claude/generated/` and `.claude/rules/`.
- `dashboard/_constants.py` `KNOWN_CRITICS` (+ CHECK 7(a)'s discovery, extended to also glob `plugins/*/agents/*.md`); `tools/check-verdict-presence.py` (CI CHECK 23), extended to require a `CRITIC: ui-critic` verdict on a merged PR whose diff touches an opted-in repo's UI globs; CLAUDE.md's critic count 6 → 7.
- `tests/` — regression coverage for the gate hook (including the subagent-write-deny path) and the verdict-presence extension, plus `tests/test_design_plugin.py` for the plugin's shape (skill set, SOURCES.md rows, skill-foundry not shipped, upstream skills not vendored).
- `plugins/design/evals/run.py` — the eval harness entry point (`--task T1…T8`).
- `decisions/0091-*.md`, `0092-*.md`, `0093-*.md` — the three ADRs below, indexed in `decisions/README.md`, shipping in slice 1's PR per ADR-0003 D8.

**Walking skeleton (slice 1, rule #2 + rule #22):** `.claude-plugin/marketplace.json` + `plugin.json` + the design-gate hook + a minimal `design-brief` that writes an approved `DESIGN.md` + the README's install/pin/opt-in instructions + all three ADR files (0091, 0092, 0093, per ADR-0003 D8), all in one PR. This closes the loop end-to-end: one approved `DESIGN.md` traverses `design-brief` → the gate → an allowed UI edit. Machine verification runs in a scratch opted-in repo (the Production check above); the rule-#22 REAL datum is the owner running `design-brief` once for a real brand in that brand's own repo, which — because it touches a brand the machine cannot judge — is recorded as an ADR-0040 human residual (`needs-human-check`), not a blocking gate on this PRD's closure. ADR-0093's file lands in slice 1 with the other two; `ui-critic`'s implementing code is not required for the walking skeleton to close the loop and lands in a later slice.

This PRD consumes no upstream pipeline feed (hook-fires/workflow-events/trace-v3) — PC-LIVE-FEED does not apply; every criterion above is self-contained to the plugin's own new artifacts and CI checks.

## 6. Rabbit-holes & Open questions

**Rabbit-holes (don't chase):**
- Don't build a router/entry-point skill (Q19) — skills fire on description alone.
- Don't make `ui-critic` judge graphics or video quality (Q18).
- Don't copy text out of reference-only sources (e.g. Vercel's `web-design-guidelines`) into a shipped skill.
- Don't wire the gate into `.claude/hooks/pre-tool-edit.sh` — its first preserved step allows any subagent context, which is exactly the writer the gate must see (ADR-0023 D3; ADR-0092 D1).
- Don't put any real brand's content into this template.
- Don't chase a CI backstop for Bash-written UI files that bypass the Edit|Write gate (Q4).
- Don't let the gate scan the filesystem in an unopted repo — it runs on every Edit/Write on the machine and must stay cheap; check the marker's existence and exit, nothing else.

**Open questions (flag, do not answer):**
- The exact `subagent_type` string a plugin-shipped agent is addressed by from `/ship` (e.g. `design:ui-critic`?) — verify against current Claude Code plugin docs before slicing.
- Which mechanism actually writes a brand's Claude Design design system from Claude Code — the Artifact "Design System" type, vs. the user-driven `/design-sync` tool, whose own guidance says only the user may drive it.
- Whether `claude plugin eval` can host the T1–T8 machine checks instead of a hand-rolled harness (the locked decision named skill-creator's baseline-vs-with-skill runs).
- `DESIGN.md`'s exact frontmatter/body shape — whether to adopt `google-labs-code/design-md`'s structure, contingent on its licence.
- The user-level brand registry's file path (maps brand name → workspace folder + Claude Design project id).
- The default UI-glob list the gate ships with and that a repo's opt-in marker may override.
- Whether the plugin's own gate hook (`plugins/*/hooks/**`) should join the guardrail set that requires the operator's PROMOTE_OK ack. It runs on every Edit/Write in every opted-in repo on the owner's machine, which argues yes; it was never grilled, so this PRD does not decide it — it is filed as a captured issue for the owner.
- The T8 thresholds in criterion 13 (≥10 of 12 planted defects found; ≤2 high-severity findings on the clean control) are drafting defaults, not grilled values. If the first eval run shows them mis-set, amend them append-only per ADR-0066 D3 with the run's report as evidence — do not silently retune.
