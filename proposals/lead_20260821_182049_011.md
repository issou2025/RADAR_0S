# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Change default server port to 28081 and enforce mDNS discovery as primary device location method**

*Project description:*

## Problem Statement

The user is operating a Xiaomi Mi Box S / Android TV remote control system (`mibox_ctl`) and needs two specific adjustments to the existing CLI and server behavior:

1. The API daemon server (`server/`) currently listens on port `8080` by default. The user needs to change the default server port to **`28081`** across the server entry point, the Flake.nix configuration, and any documentation references, so that it does not conflict with common services and aligns with organizational port conventions.

2. The Mi Box (and other Android TV devices) must be automatically **discovered on the local network via mDNS** using the `_androidtvremote2._tcp.local.` service type. The discovery mechanism (`core/discovery.py`) already exists using `zeroconf`, but it needs to be confirmed, hardened, and made the primary discovery method across the CLI (`cli/commands.py`), so that the user never needs to manually type an IP address if the device is on the network.

These changes affect the CLI's host resolution flow, the server's default port binding, the NixOS service module configuration, and integration documentation.

## Solution

The solution involves two coordinated changes across the codebase:

1. **Port migration**: Change the default API server port from `8080` to `28081` in `server/__main__.py`, `server/api.py` (if hardcoded), `flake.nix`, and the NixOS `services.mibox-server` module default. The `--port` CLI argument remains configurable so users can override.

2. **mDNS discovery as default**: Ensure that the CLI (`cli/commands.py`) and the server daemon (`server/service.py`) always attempt mDNS discovery of `_androidtvremote2._tcp.local.` services *before* falling back to manual IP input or saved configuration. The discovery timeout, error handling, and multi-device selection logic should be robust so that the user experience is seamless — ideally, the TV is found automatically and the saved IP is updated in `~/.config/mibox_ctl/config.json`.

No new modules need to be created. The changes are configuration-level and flow-adjustment level within existing modules.

## Implementation Decisions

- **Default port change**: The default API server port changes from `8080` to `28081`. This is a single constant-like value that appears in:
  - `server/__main__.py` — `argparse` default for `--port`
  - `flake.nix` — `mibox-server` app program definition and NixOS module default for `services.mibox-server.port`
  - `server/api.py` — the `ApiServer.__init__` default and `run_server` default
  - All `curl` / documentation examples referencing `localhost:8080`

- **mDNS service type**: `core/constants.py` defines `MDNS_SERVICE_TYPE = "_androidtvremote2._tcp.local."` and `DEFAULT_REMOTE_PORT = 5184`. These remain unchanged. The discovery logic in `core/discovery.py` uses `zeroconf.ServiceBrowser` with this service type and should remain the single source of truth for network discovery.

- **CLI host resolution flow (in `cli/commands.py`)**: The `resolve_host()` function order of precedence is:
  1. Explicit `--ip`/`--host` argument
  2. `MIBOX_IP` environment variable
  3. Saved host from `default_config.get_host()` (i.e., `~/.config/mibox_ctl/config.json`)
  4. mDNS discovery via `discover_android_tvs(timeout=4.0)`
  5. If discovery returns 0 devices → prompt user for manual IP input
  6. If discovery returns 1 device → auto-select, save to config, return IP
  7. If discovery returns >1 devices → list and prompt for selection, save selected IP to config

- **Server daemon discovery (in `server/service.py`)**: The `RemoteDaemon.get_or_connect()` method already falls back to `discover_android_tvs()` when no host is configured. This behavior is confirmed as correct and will be the default. No code changes needed beyond confirming it's wired correctly.

- **NixOS module**: `services.mibox-server` gets a new default `port = 28081`. The `ExecStart` uses `${toString cfg.port}` so it respects overrides.

- **Flake.nix**: `apps.server` program references `mibox-server` which uses `python3 -m server` — the default port change in `__main__.py` propagates automatically. No additional `--port` flag needs to be hardcoded in the flake wrapper (since the default is correct), so the flake wrapper remains clean.

- **No new modules or files**: All changes are within existing files. No new Python modules, no schema changes, no new API endpoints.

## Testing Decisions

- **Good tests verify external behavior**: Testing should confirm that (a) the server listens on port 28081 by default, (b) the CLI discovers devices via mDNS when no host is provided, and (c) the NixOS module uses port 28081 by default.

- **Testing seams**: The ideal single seam is the **CLI `run_cli()` function** in `cli/commands.py`, which orchestrates: argument parsing → host resolution → mDNS discovery → connection → command dispatch. This is the highest-level entry point that covers the user-facing flow end-to-end. Secondary seam: the **server entrypoint `main()`** in `server/__main__.py`, which parses `--port` and calls `run_server`.

- **Mocking network**: Since real mDNS and TV hardware can't be assumed in CI, tests should mock:
  - `core.discovery.discover_android_tvs()` to return a canned list of `DeviceInfo` objects
  - `core.remote.MiBoxRemote.connect()` / `send_key()` / `get_status()` to avoid real network I/O
  - `argparse` output to simulate `--ip`, `--port`, and subcommand arguments

- **Prior art**: There are currently **no existing tests** in the repository (no `tests/` directory, no `conftest.py`, no pytest configuration in `pyproject.toml`). This is the first spec introducing testing conventions. The testing approach should be:
  - Use `pytest` as the test runner (add to `pyproject.toml` dev dependencies)
  - Structure tests under `tests/` mirroring the package layout: `tests/cli/`, `tests/server/`, `tests/core/`
  - Use `unittest.mock.patch` for mocking network calls and `AsyncMock` for async methods
  - Example test shape: `test_resolve_host_finds_via_mdns` — patches `discover_android_tvs` to return `[DeviceInfo(name="MiBox-Sala", ip="192.168.1.50")]`, asserts that `resolve_host(None)` returns `"192.168.1.50"` and that the IP is saved to config

- **Test modules to cover**:
  - `cli/commands.py`: `resolve_host`, `connect_and_pair`, `run_cli` command dispatch (send, text, app, info, pair)
  - `server/__main__.py`: `main()` argparse defaults for `--port`
  - `server/service.py`: `RemoteDaemon.get_or_connect` fallback to discovery
  - `core/discovery.py`: `discover_android_tvs` returns proper `DeviceInfo` list
  - `core/remote.py`: `MiBoxRemote.send_key` resolves friendly name → Android keycode via `KEY_MAPPINGS`

## Out of Scope

- No changes to the Flutter app (`flutter/`) source code — the Flutter app communicates with the server via HTTP REST and doesn't have hardcoded ports (it connects to whatever host:port the user configures). The `flutter/` README and configuration remain as-is; only the server port default changes.
- No changes to the Android TV Remote Protocol v2 implementation in `core/remote.py` — the TLS/Protobuf connection logic is correct and unchanged.
- No new CLI subcommands or features beyond port change and mDNS-first discovery.
- No WebSocket or MQTT support (this is in the future roadmap, not part of this spec).
- No UI changes to the interactive TUI (`cli/interactive.py`) — the TUI already receives a connected `MiBoxRemote` instance and doesn't need port or discovery changes.
- No changes to `core/models.py` data structures.
- No GitHub Actions CI setup — while tests are proposed, CI pipeline configuration is out of scope (though the Nix devShell already provides `pythonEnv`, `flutter`, and build deps).
- The `main.py` legacy launcher is noted but not modified (it just delegates to `cli.__main__`).

## Further Notes

- The project uses **Nix Flakes** exclusively for environment management. The `devShells.cli` flake provides a Python-only environment (`pythonEnv` with `androidtvremote2` and `zeroconf`). Developers should run tests from within `nix develop .#cli` to ensure dependencies are available.
- The `flake.nix` defines `packages.default = mibox-ctl`, `packages.mibox-server`, `apps.default` (CLI), and `apps.server` (daemon). The `nixosModules.default` provides `services.mibox-server`.
- The server uses Python's built-in `asyncio.start_server` (no external framework like FastAPI/Starlette) — it's a lightweight custom HTTP/JSON server with hand-rolled CORS headers in `server/api.py`. This makes testing the server's port binding straightforward by checking the `ApiServer` constructor defaults.
- The NixOS module sets `DynamicUser = true` and `StateDirectory = "mibox_ctl"` — the state directory maps to `/var/lib/mibox_ctl/`, which is different from the user-level `~/.config/mibox_ctl/`. For system-level daemon usage, the config/certs would be stored under the state directory. This is an existing design and not changed by this spec.
- The `DEFAULT_CLIENT_NAME = "MiBox Controller"` in `core/constants.py` is used for TLS certificate CN. No change needed.
- The `KEY_MAPPINGS` dictionary in `core/constants.py` maps friendly names (e.g., `"UP"`, `"VOLUME_UP"`) to Android TV keycodes. The CLI's `send` subcommand uses `choices=list(KEY_MAPPINGS.keys()) + list(set(KEY_MAPPINGS.values()))` so users can use either form. No change needed.
- The `POPULAR_APPS` dictionary maps friendly app names (e.g., `"youtube"`, `"netflix"`) to package names or URLs. The CLI's `app` subcommand accepts either a key from this dict or a raw package name. No change needed.
- This spec represents a **configuration and flow-hardening** change, not a feature addition. The core architecture described in `docs/ARCHITECTURE.md` and the future roadmap in `docs/FUTURE_ROADMAP.md` remain valid and unchanged.
