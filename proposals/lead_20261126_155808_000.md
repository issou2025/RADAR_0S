### 🐞 Describe the bug

I am experiencing an issue with panel visibility when using bundle.yaml in a custom pyRevit extension.

My extension contains multiple .panel folders inside the same .tab directory. I use bundle.yaml to explicitly define which panels should be displayed in the Revit ribbon and in which order.

However, pyRevit continues to display additional panels that physically exist in the extension directory but are NOT listed in bundle.yaml.

My understanding is that, following PR #3111, the C# loader should treat the layout property as a strict allowlist, meaning only the components explicitly listed should be displayed.

PR reference:
https://github.com/pyrevitlabs/pyRevit/pull/3111

This change is included in the pyRevit 7.1.0 release, but the behaviour still appears to occur in my installation.

My bundle.yaml

layout:
  - Start[beforeall:]
  - Setup
  - Modify
  - Maintenance
  - Model & Data Export
  - VIP

My extension folder structure

pyEPR_BDI.tab/
│
├── BIM Quiz 2026.panel/
├── Documents.Panel/
├── Maintenance.panel/
├── Model & Data Export.Panel/
├── Modify.Panel/
├── Parameters.Panel/
├── Setup.panel/
├── Sheet Views +.Panel/
├── Start.Panel/
├── VIP.panel/
│
├── app-idling.py
└── bundle.yaml

The additional panels are intentionally kept in the extension directory because I may need them in the future. I do not want to rename or remove these folders just to prevent them from appearing in the ribbon.

I want bundle.yaml to control panel visibility independently of which panel folders physically exist in the extension.

### ⏲️ Expected behavior

The layout property in bundle.yaml should act as a strict allowlist.

Only panels explicitly included in the layout should be loaded and displayed in the Revit ribbon.

Unlisted panels should remain hidden, even when their .panel directories exist in the extension.

This should be consistent with the behaviour described in PR #3111 and the Python-based loader.
