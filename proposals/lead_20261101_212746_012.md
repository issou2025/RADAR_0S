# Project Proposal — Flutter App

*Project description:*
## Goal
A minimal Flutter app in `app/` builds, analyses and passes a widget test and a Chrome integration test, locally in the dev container and in a required CI job. This gives later jobs (PR 10, PR 11) a working base for the web, iPhone and Android front end.

This goal governs: if the details in this issue are stale or don't work in practice, meet the goal and say what changed in the build notes.

## Problem
The repo has no front end and no Flutter toolchain, so the account form and handoff UI (PRs 10 and 11 in `first-build-pr-sequence.md`) have nothing to build on.

## Scope
- Install a pinned Flutter SDK, plus Chrome and a matching chromedriver for web tests, in the dev container image and the CI toolchain image.
- Add `app/` with a minimal Flutter app that shows a placeholder screen, a widget test, and an `integration_test` smoke test run on Chrome with `flutter drive` and chromedriver. Add `app/README.md` saying how to run each check.
- Add an `app` CI job (Linux, web target only) that runs `flutter analyze`, `flutter test`, `flutter build web` and the integration test. Add it to `ci`'s `needs:`. Follow the workflow safety rules in `docs/conventions.md`.
- Widen the factory allowed paths to include `app/(lib|test|integration_test)/.+\.dart` and `app/README.md`. Keep `.claude/skills/factory/SKILL.md` and `.claude/agents/approver.md` identical.
- List `app/` and the `app` job in `AGENTS.md` "Where things are" and in `docs/conventions.md`.

## Out of scope
- Android and iOS builds, signing and CI for them.
- Calling the registry API or any real screens (PR 10: account form and waiting state; PR 11: direct handoff).
- Lefthook pre-commit steps for Dart.

## Acceptance criteria
- [ ] `flutter --version` in the dev container and the CI image reports the pinned version.
- [ ] In `app/`, `flutter analyze` reports no issues and `flutter test` passes the widget test, which finds the placeholder text.
- [ ] `flutter build web` succeeds in `app/`.
- [ ] `flutter drive --driver=test_driver/integration_test.dart --target=integration_test/<smoke>.dart -d web-server` with chromedriver running passes, and fails if the placeholder text is changed.
- [ ] The `app` CI job runs those checks on the PR, passes, and is listed in `ci`'s `needs:`; actionlint and zizmor pass on the workflow.
- [ ] The allowed-paths pattern in `SKILL.md` and `approver.md` is identical, accepts `app/lib/main.dart` and `app/README.md`, and rejects `app/pubspec.yaml` and `app/web/index.html`.
- [ ] `AGENTS.md` and `docs/conventions.md` describe `app/` and the `app` job.
- [ ] Existing CI jobs still pass.
