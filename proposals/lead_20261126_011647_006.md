# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**chore(agents): skill and agent operation audit — token efficiency, lazy loading, script centralization, and prompt offloading**

*Project description:*
## Goal

Execute a repository-wide **Skill & Agent Operation Optimization** program based on the 2026-11-25 audit of `.agents/`, `AGENTS.md`, `scripts/agents/`, `scripts/github/`, `scripts/ci/`, `make/ai.mk`, `.github/workflows/`, `lib/`, and recent T3 Code interaction flows.

The objective is to:
1. **Cut always-loaded context and per-run prompt tokens** via strict lazy loading, skill audience demotion, description pruning, progressive disclosure, and deduplicating headless workflow context.
2. **Centralize repeatable, multi-step processes into single-command deterministic scripts** (AI cost/quota evaluation, development bottleneck discovery, static guideline compliance, PR/queue/review-thread operations, and doc-drift audits) so agents spend LLM tokens on reasoning rather than shell choreography or mechanical lint sweeps.
3. **Offload recurring user prompting overhead** into lightweight repository conventions and skill flows without increasing context load or introducing unnecessary operations.

### Non-Negotiable Constraints

- **No net context/operation bloat:** Prune and consolidate before adding. Do not introduce new standalone skills when a CLI subcommand, disclosed reference file, or existing skill update suffices. Target a **net reduction** in always-loaded tokens (`AGENTS.md` + `audience: agent` skill descriptions).
- **Strict lazy loading:** Zero always-loaded cost for human-only or infrequent skills (`disable-model-invocation: true`), terse pointer descriptions (`<= 160` chars), and progressive disclosure (`references/`) for branch-specific material.
- **Zero duplication with in-flight work:** Reuse and integrate with `#444`/`#447`–`#452` (telemetry/cost), `#445` (git bisect), `#460`/`#492` (quota resilience), `#464`/`#466` (Dart refactors), `#468` (attribution), `#494` (nightly audit), `#495` (domain-partitioned `make`), `#496` (CI workflow consolidation), `#497` (manual bypass/freeze), `#498` (intent/core invariants), `#499` (batch-aware merge gate), `#500` (runtime control plane), and `#502` (`spec-intake-alignment`).

## 3. Prompting Structure Analysis & Input-Offloading Flows

Analysis of recent T3 Code user threads (`9bfc2b26`, `4e3658c5`, `e5d23206`, `78d6ba69`, `9b1a4ff4`, `e28a9380`, `27d0110e`, `aff2774d`, and this audit session) revealed five recurring places where the user repeatedly supplies boilerplate intent or executes multi-turn handoffs that should live in skills or `AGENTS.md`:

### Observed Prompting Friction

| Recurring User Pattern | Evidence from Recent Threads | Root Cause in Current Setup |
| --- | --- | --- |
| 1. Two-step spec + triage dance | User types `"$to-spec create issue"` then manually follows up with `"run neon triage on issue"` (`#496`, `#497`, `#498`). | `to-spec/SKILL.md:21` stamps `triage/ready-for-agent` with *"no need for additional triage"* while skipping duplicate search AND skipping the durable `## Agent Brief` comment that `triage` produces. |
| 2. Explicit duplicate & applicability checks | `"$to-spec create issue if applicable"` (`#499`), `"New issue or comment on existing ones?"` (`9bfc2b26`). | `issue-creator` checks duplicates, `to-spec` does not, and neither defaults to comment-on-existing vs create-new without being asked. |
| 3. Prefix mismatch & manual invocation boilerplate | User types Codex-style `$to-spec` in Antigravity/T3 (which projects `/to-spec`), and appends `"create issue"` even though publishing is `to-spec`'s sole purpose. | `to-spec` is `audience: human` with no cross-prefix normalization (`$skill` vs `/skill`) and no implicit draft handoff when a conversation converges on a spec. |
| 4. Paragraph-long urgent rollout / preemption prompts from mobile | `"Rollout all fixes, open epic issue, add sub issues and go through the intended triage route, prioritize these fixes in front of current batch... freeze..."` (`#461`). | No compact shorthand preset links `to-spec` -> epic/sub-issues -> `triage` -> `queue-planner` freeze + `merge/priority`. |
| 5. Repeating standing engineering guardrails & ad-hoc audit prompts | Repeating *"do not introduce more context/operations than needed"*, *"lazy load skills"*, *"preserve desired git state"*, *"without breaking active batch"*; repeatedly prompting ad-hoc bottleneck/workflow/modularity audits. | Standing preferences are not encoded as concise invariants in `AGENTS.md`, and audits lack 1-command `agentctl audit` scripts. |

### Concrete Offloading Actions (Minimal Context Cost)

- [ ] **In `AGENTS.md` (~4–5 concise lines, net-negative total lines after Section 1.6 pruning):**
  - **Minimalism & lazy-loading invariant:** Prefer deterministic scripts and disclosed references over prose or always-loaded context; consolidate before adding skills, workflows, or targets.
  - **Implicit issue/spec hygiene:** Whenever opening or spec'ing an issue (via skill or natural language), always search open/closed issues and PRs first (comment/enrich on match; open new only if net-new) and include attribution (`#468`).
  - **Implicit spec-to-draft handoff:** When a design/audit/spec discussion converges on concrete actions, automatically finish with a compact **Draft Issue Candidate** (proposed title, duplicate check result, labels, and whether to enrich an existing issue or open a new one) so the user can trigger publication with a 1–2 word confirmation instead of re-prompting `$to-spec create issue`.
  - **Cross-harness skill prefix alias:** Treat `$skill` and `/skill` identically as explicit user invocation of `.agents/skills/<skill>/SKILL.md`.
- [ ] **In `to-spec/SKILL.md` + `issue-creator/SKILL.md` + `triage/SKILL.md` (zero always-loaded cost for human skills):**
  - Upgrade `to-spec` to run duplicate + ADR/overlap verification first (aligned with `#502`), decide automatically between **enrich existing issue** vs **create new issue** vs **no-op**, and generate the durable `## Agent Brief` inline (or via an explicit triage pass) before applying `triage/ready-for-agent` — eliminating the manual `"run neon triage on issue"` second turn.
  - Add a compact **Urgent Preemption Rollout** flow reference in `queue-planner/references/` (linked from `implement`) so a terse prompt like `"urgent rollout ahead of batch"` executes freeze -> epic/sub-issues -> footprint-safe `merge/priority` PR automatically.
- [ ] **In `agentctl audit` (zero always-loaded cost):**
  - Map natural diagnostic prompts (`"bottlenecks"`, `"AI cost"`, `"guideline drift"`, `"context budget"`, `"doc drift"`) to 1-command scripts so short prompts yield grounded, deterministic reports in a single turn.
