# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[P2] Ship IFC viewing, object/property inspection and bounded model coordination**

*Project description:*
Parent: #410
Phase: P2

## User outcome
An architect can open a supported IFC for viewing/coordination, inspect element identity/class/properties and locate objects in 3D without ARQ pretending the imported IFC is a fully editable native BIM project.

## In scope
- safe worker-based IFC open through the existing adapter direction;
- model tree/class/property inspection;
- 3D visibility/isolate/select and cross-highlight in the IFC inspection surface;
- source coordinates/units metadata;
- property/search basics needed for coordination;
- clear reference-vs-native distinction in UI;
- file provenance, load/cancel/error states;
- bounded caching that is disposable;
- fidelity/load report listing unsupported schema/features where known.

## Out of scope
Full IFC authoring, arbitrary native semantic round trip, full Revit parity, structural/MEP editing.

## Safety
Imported IFC renderer objects are not ARQ canonical building elements unless a separate reviewed conversion operation exists. Untrusted IFC must remain behind parser/worker/resource limits.

## Acceptance
- [ ] IFC open/view/property workflow is user-reachable.
- [ ] Source objects retain stable inspection identity for the loaded reference.
- [ ] Reference IFC cannot be confused with editable native ARQ objects.
- [ ] Load/corrupt/unsupported cases fail without harming the open native project.
- [ ] Units/coordinates/schema limitations are visible in the import report.
- [ ] Product copy does not claim full IFC authoring.

- Technical validation and quality checks.
- Incorporation of review feedback.
