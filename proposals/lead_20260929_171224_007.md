## 2. Summary

We need the README's `spoolDirectory: getApplicationSupportDirectory` example to be valid Dart, because `getApplicationSupportDirectory` (`path_provider`) returns a `Future<Directory>` and `OtelZoneConfig.spoolDirectory` is typed `Directory Function()?`, so the documented snippet does not type-check.

Expected result:

> The snippet in the README compiles as written, and something in the repository's own gates compiles it, so it cannot rot again.

---

## 3. Intent

The real intention of this ticket is:

> An adopter should be able to copy the documented configuration. Today they must write a bridge that resolves the directory before `start()` and hands the synchronous callback the stored value.

---

## 4. Source of Truth

* Found while adopting v0.3.1 in [vaam-apps/vaam-apps#534](https://github.com/vaam-apps/vaam-apps/pull/534), which worked round it in `mobile/app/lib/core/observability/spool-directory.dart` (its header says the plugin's README shows the second passed as the first, "which does not type-check").
* [README.md](https://github.com/vaam-apps/flutter-otel-zone/blob/2c88bfc/README.md), "Faults recorded offline": `spoolDirectory: getApplicationSupportDirectory,`
* [lib/src/config.dart](https://github.com/vaam-apps/flutter-otel-zone/blob/2c88bfc/lib/src/config.dart): `final Directory Function()? spoolDirectory;`, whose own doc comment names `getApplicationSupportDirectory` as the intended provider.

---

## 5. Current Behavior

* The field is `Directory Function()?`, read once in `OtelZone.start()` (`directory: spoolDirectory()`), which is already `async`.
* The README and the field's doc comment both name `getApplicationSupportDirectory` as the provider to pass. Passing it fails: `The argument type 'Future<Directory> Function()' can't be assigned to the parameter type 'Directory Function()?'`.
* The example app avoids the problem with a synchronous `Directory.systemTemp` closure, and no test compiles the README's shape.

Evidence:

* Error message: reproduced by the new test against `2c88bfc`.

---

## 6. Expected Behavior

After this ticket is completed:

* `spoolDirectory` accepts `FutureOr<Directory> Function()`. Existing synchronous callers still compile unchanged. `getApplicationSupportDirectory` is accepted as it is, and `start()` awaits it before building the spool.
* A test compiles the README's snippet shape and runs it through `start()`.
