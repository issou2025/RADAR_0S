# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**audit what Tapir leaves out of the Archicad API**

*Project description:*
Why
The API coverage page shows 100%: every applicable DevKit item is used. That count leaves out 670 items marked "not applicable" and 30 skipped, decided one category at a time (tools/api_coverage_rules.json). It also says nothing about the scripting environment around the API. For Revit, pyRevit is the reference: a toolbar built from script folders, rich output, a forms library, an API helper module, event hooks, batch runs and an extension manager. Tapir has some of this (the palette, script headers, ShowScriptUI, ShowAlert, the Get…FromUser commands, six shortcut slots, the marketplace, aclib). Nobody has compared the two.
Step 1: the audit, as comments on this issue (no pull request)
A. The left-out API items. Read every notApplicable and skip entry in tools/api_coverage_rules.json and the items it marks, in the DevKits of devkits.json. Judge each category again, and each item where a category is mixed, with this rule: useful if a script or a Grasshopper definition would call it and get a result it can't get today. Pay most attention to:
the toolbox and tool settings (ACAPI_Toolbox_*, the 44 MEP tool-settings dialog items), for example a command that activates a tool;
the event handlers and notifications (selection, tool change, new or changed element, reservation, project open or close), together with #1813 and #1825;
the user-input items not already used by the Get…FromUser commands (arcs, rubber-band feedback, highlighting elements);
the dialogs a script could reuse (file pickers, attribute pickers).
Post one table: item or category, today's reason, your verdict (useful, not useful, not possible), and one sentence of evidence from the header.
