## Problem

Working on this repo from a different machine or IDE setup currently produces noise and confusing failures. I had some issues with providing a PR and to avoid these small little annoyances I decided to propose some cleanup. After that, I'm more than happy to provide some PRs which are already in my pipeline:

- **Formatting churn:** the repo defines no formatter settings, so `dart format` uses each developer's IDE line length. Saving a file reformats the whole file. Measured on `main`: with the default width 80, `dart format` would change 92 of 129 Dart files, so the code base has never been formatted consistently.
- **Different Flutter versions:** CI uses the version from `pubspec.yaml`, but nothing pins the version for developers.
- **Stale generated mocks:** 9 of the 18 committed `*.mocks.dart` files are out of date. For example, `getSources` and `selectSource` are missing in `MockSpeakerApiService`. CI hides this because it regenerates the mocks. Locally, tests still compile and silently fall back to `noSuchMethod`. Restoring committed mocks via git (checkout, stash, merge) also confuses `build_runner`'s cache: it reports "0 outputs" until you run `build_runner clean`.
- **Line endings** depend on each developer's `core.autocrlf` setting, because there is no `.gitattributes`.
- **CI doesn't enforce `pubspec.lock`**, so it can resolve different package versions than developers have locally.
- **CONTRIBUTING.md** only describes Android and doesn't mention `build_runner`.

## Proposed changes

| # | Change | Reason |
|---|--------|--------|
| 1 | Ignore `.vscode/` | Holds personal settings. FVM writes a machine-specific SDK path there. |
| 2 | `formatter: page_width: 80` in `analysis_options.yaml` | Same formatting result for CLI, every IDE and CI, regardless of personal line-length settings. 80 matches the existing code: 97.8 % of lines are ≤ 80 characters. |
| 3 | CI step `dart format --output=none --set-exit-if-changed lib test` | Keeps the code formatted once it is formatted. |
| 4 | Pin Flutter with FVM (`.fvmrc`, `.fvm/` ignored) | Every developer uses the same Flutter version as CI. |
| 5 | Renovate `packageRules` group for `flutter` | `.fvmrc` (developers) and `pubspec.yaml` (CI) get updated in the same PR, so they cannot drift apart. |
| 6 | Stop committing `*.mocks.dart` (ignored, generated by `build_runner`) | Mocks cannot go stale, and no more `build_runner` cache problems. CI already generates them before analyze and test. |
| 7 | `.gitattributes` with `* text=auto eol=lf` | LF everywhere, independent of `core.autocrlf`. All text files are already LF, so no file changes. |
| 8 | `flutter pub get --enforce-lockfile` in all workflows | CI fails if `pubspec.yaml` and `pubspec.lock` don't match, instead of silently resolving other versions. The current lockfile matches. |
| 9 | CONTRIBUTING.md: FVM setup (incl. Developer Mode on Windows), generated mocks, JDK 17, setup for Linux/macOS/Windows, `dart format` before committing | New contributors can set up any platform without guessing. |

## Action needed from the maintainer

The format check (3) intentionally fails until the code base has been formatted once. I left that out of my changes so the formatting commit is yours and contains nothing else:

```shell
dart format lib test
git commit -am "style: format code base with dart format"
# keep git blame readable:
echo "<hash of that commit>" >> .git-blame-ignore-revs
```

After pulling (6), the mock files disappear from the working tree. Regenerate them once:

```shell
dart run build_runner clean
dart run build_runner build --delete-conflicting-outputs
```

## How to verify

- **Formatting (2, 3):** set a different line length in your IDE (e.g. `dart.lineLength: 120`) and run `dart format -o none lib test`. The result must be the same as without that setting. After the formatting commit, CI's "Check formatting" step passes. Changing a line to more than 80 characters makes it fail.
- **Flutter version (4):** `fvm install` and then `fvm flutter --version` show 3.44.8, the same as `flutter:` in `pubspec.yaml`.
- **Renovate group (5):** the next Flutter update shows up as a single PR changing both `.fvmrc` and `pubspec.yaml`. The Dependency Dashboard issue lists it under the group "flutter".
- **Mocks (6):** after a fresh clone and `build_runner build`, `flutter analyze` and `flutter test` pass, and `git status` stays clean.
- **Line endings (7):** `git add --renormalize .` produces no changes. `git ls-files --eol` shows `i/lf` for all text files.
- **Lockfile (8):** change a dependency constraint in `pubspec.yaml` without updating `pubspec.lock`. CI's `pub get` step fails.
- **Overall:** `flutter analyze` reports no issues and all 819 tests pass. I checked this on Windows; CI checks it on Linux.
