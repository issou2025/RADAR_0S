# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[GPT QA] Distill prompt generation reports success when checkpoint discovery fails**

*Project description:*
## Finding
Distill's supported lesson-plan prompt generator converts ComfyUI checkpoint-discovery failure into an empty checkpoint list, then completes normally and writes a valid-looking zero-prompt manifest. An unavailable or malformed external service therefore produces a successful research artifact instead of a failed run, allowing downstream automation or a researcher to mistake infrastructure failure for a legitimate empty lesson plan.

## User/System Journey
1. A researcher invokes the documented `python scripts/generate_prompts.py --per_checkpoint ...` journey with a valid wildcard directory.
2. ComfyUI is temporarily unavailable, times out, or returns a response that cannot provide the expected checkpoint list.
3. `get_checkpoints()` catches the exception, prints a warning, and returns `[]`.
4. `main()` accepts the empty list as normal discovery, generates no per-checkpoint prompt files, and writes `manifest.json` with `total_prompts: 0` and an empty `checkpoints` list.
5. The command reaches its normal `DONE` path rather than signaling failure to the operator/caller.
6. The same behavior occurs for ordinary external-service failure variants that reach the broad exception handler; retrying or downstream consumption cannot distinguish discovery failure from a genuinely empty checkpoint inventory from the artifact/exit result alone.

## Files in scope
- `projects/distill/scripts/generate_prompts.py::get_checkpoints` — collapses request/response/discovery exceptions to an empty list.
- `projects/distill/scripts/generate_prompts.py::main` — treats zero discovered checkpoints as successful generation and writes the normal manifest.
- Distill lesson-plan manifest/output boundary consumed by subsequent image-generation work.

## Expected behavior
Failure to discover the teacher checkpoint inventory from the required ComfyUI dependency should be distinguishable from a successful prompt-generation run. The CLI should fail clearly (or use an explicitly defined retry/offline contract) rather than publishing a normal success artifact representing zero work.

## Actual behavior
Checkpoint discovery failure becomes `[]`; the generator writes a zero-prompt manifest, prints `DONE`, and returns normally. External-service failure is therefore represented as successful research output.

## Correction direction
Preserve the distinction between successful discovery and discovery failure at the ComfyUI boundary. Propagate a typed/error result to the CLI and make required-dependency failure produce a non-successful run without publishing a normal completed manifest. If an empty checkpoint inventory is itself supported, represent that separately from transport/schema failure. Add journey coverage for timeout/unreachable/malformed discovery responses and successful empty/non-empty discovery.
