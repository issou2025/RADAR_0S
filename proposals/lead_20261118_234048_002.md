# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**CLI: pyrevit mcp install cannot connect the ChatGPT desktop app when the codex command is missing**

*Project description:*
## Summary

`pyrevit mcp install` can register the agent runtime with Claude Code, Codex, Cursor, VS Code and OpenCode. A user who has only the ChatGPT desktop app, and not the Codex command line tool, has no automatic way to connect it.

## Current behavior

The Codex client (`CodexMcpClient` in `dev/pyRevitLabs/pyRevitCLI/McpClients.cs`) registers the server by running Codex's own command line tool: `codex mcp add pyrevit -- "<pyrevit.exe>" mcp`. Without `codex` on PATH or in its usual install folders the command stops with:

```
Could not find the 'codex' command on PATH or in its usual install folders. Install it or add its folder to PATH, then retry. To register by hand, run: codex mcp add ...
```

The same command runs from Revit (Settings, Agent Runtime), so a desktop-only user gets the same error there. There is no `chatgpt` client.

## Why this is fixable

OpenAI documents that the ChatGPT desktop app, the Codex CLI and the Codex IDE extension share one MCP configuration, stored by default in `~/.codex/config.toml` (https://learn.chatgpt.com/docs/extend/mcp?surface=cli). Each server is a `[mcp_servers.<name>]` table. A stdio server takes `command` (required), `args`, `env`, `env_vars` and `cwd`. The desktop app's Settings, MCP servers screen reads the same file. The entry that `pyrevit mcp install codex` writes already looks like this:

```toml
[mcp_servers.pyrevit]
command = 'C:\path\to\pyrevit.exe'
args = ["mcp"]
```

On a Windows machine with the desktop app, `~/.codex` also holds the app's own files next to `config.toml`. So the entry only has to exist; the missing piece is creating it without the command line tool.

## Preferred fix

When `codex` cannot be found, `pyrevit mcp install codex` falls back to writing the `[mcp_servers.pyrevit]` block into `~/.codex/config.toml` itself. `pyrevit mcp install chatgpt` is accepted as another name for the same entry.

- Edit the file in place and keep everything else in it. Replace only the `[mcp_servers.pyrevit]` table. Leave its `tools.*` sub-tables untouched: Codex or the app may add them for per-tool approvals.
- `pyrevit mcp uninstall codex|chatgpt` removes only that block, and `uninstall --all --owned` keeps an entry that points at another pyRevit install, as the other clients do.
- Set `tool_timeout_sec` to a value that covers Revit's approval prompt and long runs. Codex defaults to 60 s, while the agent run timeout defaults to 300 s (capped at 3600 s). `startup_timeout_sec` defaults to 10 s, which should be enough for `pyrevit.exe mcp`.
- Do not set `default_tools_approval_mode`. The model's own approval and the approval prompt in Revit are separate; leave that choice to the user.
- Add a short note to `docs/agent-runtime.md` that the ChatGPT desktop app and Codex share `~/.codex/config.toml`.
- Tests with a temporary home folder: creates the file, preserves other tables and comments, replaces its own block, uninstalls only its own block, and keeps a foreign entry with `--owned`.

## Other options considered

- A separate `chatgpt` client with the same writer: clearer in the help text, but `uninstall --all` would touch the same file twice.
- Docs only (Settings, MCP servers, Add server, STDIO, the `pyrevit.exe` path, argument `mcp`): no code, but not automatic.
- A remote server for ChatGPT on the web: out of scope. The web app only reaches remote servers, so it would need a tunnel and an authenticated HTTP endpoint, and the agent runtime is local and unauthenticated by design.

## Open questions

- Does the desktop app on Windows pick up an entry that was written directly to `~/.codex/config.toml` without restarting? (OpenAI's page describes a Restart button in Settings.) To be tested on a machine with the app.
- Is there a deep link to add an MCP server to the desktop app, like the one Cursor has? Not found; it would be an alternative.
