# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[Bug]: Context menu position doesn't update when the window is resized**

*Project description:*
### Bug Description

The context menu position is calculated once, right after the menu is shown (post-frame, via `calculateContextMenuBoundaries()`), and is never recalculated when the window/screen size changes. If the user resizes the window (desktop/web) — or the available space changes for any other reason (orientation change, keyboard/soft-input, split-view) — the open menu keeps its original offset. As a result, the menu can end up partially or entirely outside the visible viewport, clipped by the window edge, or overlapping the safe area.

### Steps to Reproduce

1. Add `flutter_context_menu` to a desktop (macOS/Windows/Linux) or web app.
2. Wrap a widget with `ContextMenuRegion` (or call `showContextMenu()` directly) with a menu containing a few entries.
3. Run the app in a resizable window and right-click near the right or bottom edge of the window to open the menu.
4. While the menu is still open, resize the window to be significantly smaller (drag the bottom-right corner inward).
5. Observe the menu.

### Expected Behavior

The menu should stay visible while the window is resized:

- On every window size change, the position should be recalculated so the menu remains fully visible (as much as possible) within the new viewport and safe area.
- The original (user-requested) position should be remembered. The adjusted position overrides it only while it's needed — as soon as the window grows back enough for the original position to fit again, the menu should return to it.
- Submenus should follow the same rule and stay anchored correctly to their parent item.

### Actual Behavior

The position is computed only once when the menu opens and is not updated on resize. After shrinking the window, the menu stays at the stale offset — it gets clipped by the window edge or moves out of view entirely, and it never returns to a sensible position even after the window is enlarged again.

### Proposed Solution

- While the window is being resized, update the menu position so it stays visible as much as possible within the new viewport.
- Save the original position and let the adjusted position override it, falling back to the original as soon as it can fit again.

Implementation notes:

- Listen for viewport size changes for the open menu (e.g. `MediaQuery.sizeOf` / a `WidgetsBindingObserver.didChangeMetrics`) and re-run `calculateContextMenuBoundaries()` in `ContextMenuState`.
- Keep the original requested offset as the source of truth; store the clamped/flipped offset separately so it can be discarded when no longer needed.
- Apply the same recalculation to open submenus so they remain anchored to their parent item.
