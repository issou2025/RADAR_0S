# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**feat(settings): link account portability flow from mobile**

*Project description:*
## Problem

Divine Exit is the standalone web flow for account portability: a user can sign in, export their Divine archive, and eventually move their account/content to infrastructure they choose.

Mobile currently has related account surfaces: Nostr settings, key management, relay settings, Blossom settings, and account deletion. It does not have a clear entry point to the portability flow, so a mobile user who wants to move their account has no in-app path to find it.

This should be an always-available account feature, not a suspension-only flow.

## Goal

Add a mobile app entry point that opens the hosted Divine Exit web flow from account/settings surfaces.

For v1, mobile should link to the web flow rather than reimplement owner export, archive generation, media mirroring, or relay publishing natively.

## Scope

In scope:

- Add an authenticated settings entry point for account portability.
- Place it where users already manage Nostr/account infrastructure, likely Settings > Nostr settings.
- Open the hosted divine-exit URL in the appropriate browser surface.
- Add the final Divine Exit host to trusted external-link handling if needed.
- Add user-facing copy and l10n strings.
- If the app has a suspension/account-restriction notice surface, add a secondary link there to the same flow.
- Add tests for visibility, routing/link behavior, copy, and trusted-host handling.

Out of scope:

- Native mobile implementation of owner-export cursor walking.
- Native archive ZIP generation.
- Native destination Blossom mirroring.
- Native destination relay publishing.
- Event URL rewrite/re-sign.
- Key export changes. Existing key export surfaces remain separate.
- Account deletion changes. Moving does not delete anything.

## Proposed UX

Settings row:

- Title: Move your account
- Subtitle: Download your archive and move your posts and videos to another relay or media server.
- Destination: hosted Divine Exit URL.

Copy rules:

- Plain and neutral.
- Do not frame this as only for suspended users.
- No retention prompt.
- No "are you sure."
- Make clear that moving does not delete anything from Divine.

If linked from a suspension/account-state notice, use direct copy such as:

> You can still use your Divine identity on other infrastructure. Move your account or download your archive.

## Implementation Notes

Useful existing mobile surfaces:

- `mobile/lib/screens/settings/nostr_settings_screen.dart`
  - Existing Nostr/account hub; likely best settings entry point.
- `mobile/lib/router/routes/settings_routes.dart`
  - Settings route registration.
- `mobile/lib/utils/external_link_launcher.dart`
  - Trusted external-link host policy and launcher behavior.
- `mobile/lib/screens/key_management_screen.dart`
  - Existing key-management surface; do not merge the portability flow into key export.
- `mobile/lib/services/nip98_auth_service.dart`
  - Existing NIP-98 signing infrastructure, if a future native implementation needs it.

The web flow owns its own sign-in. Mobile should not pass keys, tokens, nsecs, pubkeys, npubs, or event IDs through the URL.

## Acceptance Criteria

- [ ] An authenticated user can reach the Divine Exit flow from mobile settings at any time.
- [ ] The entry point is not hidden behind developer options or suspension state.
- [ ] The entry point opens the hosted Divine Exit URL.
- [ ] No key material, bearer token, pubkey, npub, nsec, or event ID is added to the URL.
- [ ] The Divine Exit host is treated as a trusted Divine-owned destination, if applicable.
- [ ] User-facing copy is plain, neutral, and does not imply the user is being removed from Divine.
- [ ] Moving is not described as deletion.
- [ ] Existing account deletion and key export flows remain separate.
- [ ] If a suspension/account-restriction notice surface exists, it links to the same portability flow.
- [ ] Tests cover settings-row visibility and link launching.
- [ ] Tests cover trusted-host handling for the final Divine Exit host.
- [ ] L10n keys are added consistently across app_*.arb files or handled according to the repo's l10n debt policy.
