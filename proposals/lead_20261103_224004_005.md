# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**In-model standards view: one note per section, one writer, proposal only (no status or history)**

*Project description:*
## Context

During the naming cleanup (see the naming-standards issue), the user asked for one drafting view in the model that holds every naming rule, as the single source of truth for the team. No `am-*` skill covers a view like this. The agents built and maintained it by hand. #58 / `am-issue-board` keeps issues in a text note, but not a rule document.

## What happened

1. **Build.** The user said each section should be its own text note, so different sessions can work on different sections. The agent made one note per section in fixed slots in two columns, with bold headings. It checked note sizes and overlaps, and used `capture_view` to confirm the layout. It pointed four older rule notes in other reference views to the new view, and deleted ten old rule fragments.
2. **Maintain.** Later the agent merged two sections, renumbered all sections, and updated the cross-references to section numbers. Each change needed its own dry run, read-back and Keep.
3. **Status text in the model.** The agents wrote status lines into the view: "rule agreed (date)", "renames done (date, session name)", "not renamed yet", old-form remarks. The user corrected this twice: first "say proposed, do not say agreed", then "do not show progress in the naming rules, just show what is proposed, no history". The agent removed every status line, moved the progress tracking to a notes file outside the model, and added a script check that no history words remain.
4. **Status from a peer, not from the model.** One session wrote "renames done" for a category before that rename happened, because a peer said it would do it. The peer had to send a correction.
5. **Single writer.** Several sessions needed to change their own section. The agents agreed by hand that one session writes the view, and the others read it with `run_query` and send exact line changes.
6. **A note vanished.** A note that the agent created was gone before the next run. No session claimed it. The script guard found it missing and stopped. The user decided not to recreate it.

## Proposed change

A recipe (in `am-issue-board`, `am-safe-change`, or a small skill) for a sectioned standards view:

- Create: one note per section, fixed slots, headings, overlap check, and a find-by-first-line rule (not by element id).
- Maintain: add, merge and renumber sections; update cross-references; repoint pointer notes in other views.
- Content rule: the view shows only the proposed rules and the open questions. Never write "agreed" before sign-off. Keep progress, dates, run ids and session names out of the model.
- Status from the model only: write a status after a read-back, never from what a peer says it will do.
- One writer per view (or per section). Others send exact changes.

## Acceptance ideas

- A standards view built by the recipe has no status or history words. A check confirms it.
- Renumbering sections updates every "see section N" reference.
