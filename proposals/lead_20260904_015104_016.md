# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Pre-build validation: static check for obviously invalid build targets before burning loop iterations**

*Project description:*
## Strategic Improvement

The build stage currently discovers fundamental problems (missing test command, no package manifest, unparseable goal) only after spending one or more full loop iterations. Add a fast pre-build validation step in sw-loop.sh that checks for these conditions up front and fails fast with an actionable message, saving iteration budget and cost on runs that can never succeed.

### Acceptance Criteria
- - New pre-build validation function runs before the first loop iteration and checks: test command resolves, package manifest exists (if applicable), goal/spec is non-empty
- - On validation failure, the loop exits immediately with a structured error (not a generic timeout/exhaustion failure) and does not consume an iteration
- - Validation failures are logged to error-log.jsonl distinctly from build failures
- - Unit tests added to scripts/sw-loop-test.sh covering pass and fail cases
