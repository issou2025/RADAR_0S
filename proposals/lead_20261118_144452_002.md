## Context

Related: #50 and the feedback doc from PR #48. The detail-views recipe in `am-safe-change` copies an existing section. These sessions made **new** detail sections from a reviewer's PDF markup on a floor plan (about 20 new sections in one session). Several findings from the PR #48 doc are still not in any skill: the CreateDetail direction, the filter category rule, `capture_view` with a sheet number, and `ActiveView` becoming the sheet.

## What happened

- **CreateDetail look direction.** `ViewSection.CreateDetail` reads the input box `BasisZ` as the look-into direction. The new view's `CropBox.BasisZ` points the other way (towards the viewer).
  - One session: all 20 new views were flagged "view direction differs from mark". 4 test dry runs to fix.
  - Another session: the reversed view was found only when the user asked for a resize. Cost: a delete and a re-create.
  - **Possible bug:** `skills/am-safe-change/scripts/apply_detail_views.py` line 153 passes `source.CropBox` straight into `CreateDetail`. That may flip the copy. I did not test it in Revit.
- **Silent empty result.** After `RequestViewChange`, `doc.ActiveView` was the sheet. A query then found no floors at all 4 marks, with no error.
- **Markers show in every view.** A detail section shows in every view that cuts it, and it has no "Show in" setting. The user wanted the markers on the finish floor plans only. What worked: set "Hide at scales coarser than" to 12" = 1'-0" on the real sections, and add a view-specific reference section on each finish floor plan at the same spot. To move a cut later, set the scale back, move it, then set it again.
- **Duplicate cuts.** The user had to circle 2 new markers that sat next to existing cuts. Then the user said "never cut the same spot twice", which removed a third duplicate. Check for existing markers near each new cut first.
- **Filter rule.** `ArgumentException: One of the given rules refers to a parameter that does not apply to this filter's categories.` The markers' own category offers only Workset. What worked: a filter on the Sections category with "Sheet Number does not equal <sheet>". The template change reached 12 plans.
- **Viewport larger than the crop.** Level heads, grid bubbles and other views' markers made the viewports too big. 4 extra runs. Fix: hide grids, levels and other section markers in the new detail views.
- **Wrong first guess.** The agent assumed the red marks were existing model markers. About 10 queries to disprove it. A "views not on sheets" filter in the plan template made the guess look plausible.
- **The markup.** The PDF was flattened (0 annotations), so marks were found by color only. 30 of the 53 marks were drawn mirrored against the head/tail rule; the agent used the side of the thick bar as the look direction. `am-markup-intake` did not load (see #253), and the computer had no PDF tools (see #254).

## Proposed change

- `skills/am-safe-change/recipes/detail-views.md`: add a "new section from a markup" path:
  - check the look direction after `CreateDetail`, and flip if needed;
  - check for existing markers near each cut before you create one;
  - offer "markers on the finish floor plans only" (hide-at-scale + reference sections);
  - hide grids, levels and other markers in new detail views;
  - use the target view id in queries, not `doc.ActiveView`.
- Check `apply_detail_views.py` line 153 for the direction flip, and add a test.
- `am-markup-intake`: a fallback for flattened PDFs (find marks by color) and a note on mirrored section marks.
- Move the remaining PR #48 doc findings into the recipe and `am-revit-api-docs`, so a skill reads them.
