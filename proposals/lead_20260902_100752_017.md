## Confirmed bugs / content gaps

### 1. A DragonRealms companion app's fantasy icon set has no dragon

`PinEditor`'s icon filter, tested live: typing "dragon" into the 372-icon picker returns **"Icon(0 of 372)"**. So do wyvern, griffin, phoenix, unicorn, elf, dwarf, orc, troll, giant, demon, angel, vampire, werewolf, goblin, skeleton, zombie, witch, wizard, knight, dungeon, treasure, rune, spell, potion, cauldron, throne, tower, bridge, waterfall, volcano — every one of those, zero matches. ("castle" returns 1, confirming the filter itself works and this is a content gap, not a search bug.)

Root cause, verified against `lucide-react`'s full 1,790-icon export list: **it has no fantasy-creature icons at all.** Not "few" — zero matches for any of the above across the entire library. The 372-icon curation pass (this session's own earlier work, to be self-critical about it) picked good icons from what Lucide offers, but Lucide is a generic UI icon set with no monster/creature glyphs, so no amount of curation inside it could ever produce a dragon for a game called DragonRealms. This is exactly the gap the ongoing Magnific/image-generation work should target first — generated creature icon art, not another pass through the same library.

### 2. Zone `33a`, "Road to Therenborough," has zero exits anywhere

Checked every one of its 48 rooms' exit lists: none leave the zone, none reach Therenborough (zone `42`) despite the name. Not a missing-gateway-tag issue — I checked plain room-to-room exits too, and it's a fully closed loop. (Therenborough itself is fine and properly reachable, via zone `40`, "Langenfirth to Therenborough" — this is specifically about the redundant-looking `33a` chunk.)

### 3. "1 saved pins" — singular/plural grammar bug in `MapPinBar`

`aria-label={`${pins.length} saved pins`}` doesn't branch on count. Trivial, but it's the first thing a screen reader announces for that control.

## Verified as working (so nobody re-investigates these)

- **Gateway traversal**: clicked a real gateway room live (Crossing → Northern Trade Road), zone changed, breadcrumb appeared, Back worked correctly.
- **Zone dropdown**: selecting a zone from the combobox navigates identically to a gateway click, and integrates with the same Back/browsing stack.
- **Keyboard navigation**: arrow keys move `aria-activedescendant` between rooms correctly; confirmed via direct DOM inspection, not just visually.
- **Click-to-place pin workflow**: selecting a palette brush (e.g. "Home") then clicking a room does create a real pin (confirmed in `localStorage`) and clears the brush afterward. I initially got a false read on this from a testing-environment glitch on my end (a hung headless-tab timing issue, not the app) and re-verified cleanly before trusting it — flagging that so nobody trusts a first impression here without redoing it.
- **Pin editor dialog**: properly labelled via `aria-labelledby`/`aria-describedby` (not a bare unlabelled dialog, which is what it looked like from a shallow check), icon filter works correctly for terms that should match, label field sensibly pre-fills with the room's title.
- **Zoom in/out and "back to whole zone" reset**: all work and persist correctly across idle time (not reset by any background re-render).
- **Level toggle** (multi-z-level zones like Crossing's underground): switches correctly.
- **Demo/mock-mode watermarking**: the "Demo cartography — not your location" warning is correctly *not* showing during a consistent mock-bridge simulation (it's gated on a genuinely-degraded live response, not on mock-vs-real), which is the right behavior, not a bug I almost mis-filed as one.

## Thin, not confirmed broken

- **22 of 27 map-stamp kinds have only 2 art variants each** (5 have 3) — reused often enough across an 85-zone, 17,750-room map that repetition is likely visible, though I didn't measure per-kind reuse frequency precisely.
- **A handful of zones plausibly under-connected**: `90a`/`99a` (Tethloren Island), `90e` (Basalt Isle and Jeihrem's Barrow) have zero outgoing gateways and no obvious reason (unlike Wyvern Arena, Microcosm, etc., which are legitimately instance/teleport content). `66` ("Shard to Gondola Area") and `40a`/`98` (Siksraja/Snow Gobs) have names implying a connection my automated check couldn't resolve either way — could be real gaps or could be sub-areas inside another zone's file. Needs a human who knows the geography, not more grep.

## Not tested — say so rather than imply coverage

Whoever picks this up should specifically check `MapWindow.tsx` against everything above, since it duplicates `MapPanel.tsx`'s pin/traversal/keyboard logic in a separate file and there's no structural guarantee the two stay in sync.
