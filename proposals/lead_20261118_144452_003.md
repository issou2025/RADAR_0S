## Context

Related: #23 (turn on auto-update), #39 (comment with the same parse error), #62 and #70 (out-of-date plugin), #84 (gotchas do not reach sessions). Windows 11, Windows PowerShell 5.1, Claude Code desktop app 2.1.309 to 2.1.326.

## What happened

- At install time, the user asked to "turn on auto-update". The agent did not use `/plugin` or the `extraKnownMarketplaces` route in the README. It edited `~/.claude/plugins/known_marketplaces.json` directly in Windows PowerShell 5.1:
  `$j | ConvertTo-Json -Depth 10 | Set-Content $p -Encoding utf8`
- In PowerShell 5.1, `Set-Content -Encoding utf8` writes a UTF-8 byte-order mark (BOM, the bytes `EF BB BF`). After that, Claude Code could not read the file. The file still showed `"autoUpdate": true`, so the setting looked correct.
- From then on, the archi-magic plugin did not load at all. Evidence:
  - 9 sessions over 3 weeks listed no `archi-magic:` skills. Only two personal skill copies showed.
  - `/reload-plugins` in one of them printed `Reloaded: 1 plugin · 13 skills · 7 agents · 0 hooks` and `3 errors during load. Run /plugin for details.` Nobody noticed it.
  - `claude plugin install` failed with the same parse error the day after the edit. That was posted as a comment on #39, with the cause unknown.
  - After the fix below, `/reload-plugins` printed `Reloaded: 4 plugins · 59 skills · 8 agents · 8 hooks`.
- **Impact:** most script errors in those 9 sessions already had a fix in `am-revit-api-docs` (for example `IntegerValue`, `ElementId(int)`, `.Name`, non-ASCII results, slow scans). No session-start notice or hook could warn, because the hooks did not load either.

Failure records:

- tool: `claude plugin marketplace update archi-magic` and `claude plugin update archi-magic@archi-magic`
  - signature: `Failed to load marketplace configuration: JSON Parse error: Unrecognized token '<BOM>'`
  - retries: 1. cost: about 3 weeks with no archi-magic skills or hooks. fix: remove the first 3 bytes of the file (keep a backup), then run the two commands again.
  - loaded: no `am-*` skill or README step warns against a direct edit of this file. This is a documentation gap.
- tool: `claude plugin marketplace update archi-magic` (after the BOM fix)
  - signature: `EPERM: operation not permitted, rename '<plugins>\marketplaces\archi-magic..clone' -> '<plugins>\marketplaces\archi-magic'`. The SSH fallback also failed: `Host key verification failed`.
  - cost: none in the end. `claude plugin update archi-magic@archi-magic` still installed the latest commit, and `git pull --ff-only` in the marketplace clone said "Already up to date".
- Side effect: to work around the missing plugin, two skills were copied into the personal skills folder. Both copies are still listed next to the plugin copies, and they drift (see the contributor-workflow issue).

## Proposed change

- `README.md` (For AI agents, step 2), `am-welcome` and `am-pyrevit7-setup`: say "Do not edit files under `~/.claude/plugins/` by hand. Use `/plugin`, or the `extraKnownMarketplaces` entry in `settings.json`."
- House rules / `CONTRIBUTING.md`, PowerShell 5.1 notes (#71 covers only the JSON-as-argument trap): to write JSON or other UTF-8 text, use `[IO.File]::WriteAllText($p, $text, (New-Object Text.UTF8Encoding $false))`. `Set-Content -Encoding utf8` and `Out-File -Encoding utf8` add a BOM in 5.1.
- `am-doctor`: check that `known_marketplaces.json`, `installed_plugins.json` and `settings.json` have no BOM and parse as JSON. Offer the one-step fix.
- `am-doctor`: report personal skill copies with the same name as a plugin skill.
- `hooks/update-check.ps1` cannot help here, because no hook loads. A check outside the plugin is needed, for example a line in the README "If `/reload-plugins` shows errors or no `archi-magic:` skills, run the doctor script by path."

## Acceptance ideas

- With a BOM in `known_marketplaces.json` in a throwaway `CLAUDE_CONFIG_DIR`, the doctor script reports an error and the fix.
- No README or skill text tells an agent to edit `known_marketplaces.json` directly.
- The PowerShell 5.1 notes include the BOM trap and the `UTF8Encoding $false` pattern.
