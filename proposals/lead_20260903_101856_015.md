### Issue

### Automated calls

Seems like the "test feature" is not working correctly, for example:

> ~❯ cecli --test-cmd "cd axiom ; ./verify.sh build ; cd .." --auto-test --auto-commits --yes BUGS.md *.go   --message "fix the next BUG from the list"

Actually this command does:
- run cecli with my request
- runs a commit uppon the modifications made
- run the test-cmd (this is wrong IMHO, the test should be run before to commit, so if the AI mode has made wrong changes, they should be fixed before to commit the work, every commit is ideally a full -working- change in the source code)
-  if the test command returns failure, AI should be feed with the issue and try to fix it

### manual test

Why running /test alone doesn't fix the bugs (instead, it just give some ambiguity text), maybe it has a wrongly defined prompt passed ? 

### Exit status of test-cmd

I think that the fixes (or more exactly the AI request) should be requested ONLY when the output of the test-cmd command exit non-successfully, for example if we run the command "make" it can be verbose, but nothing should be considered from it if it ends successfully, we should request something only when it fails.

If i run /test and it exit successfully, there's a request send to AI, which IMHO should not happen and is a waste of resource, especially if the test-cmd is run at each loop
