*Project description:*
## Summary
Move the project from **Flutter 3.44.3** to **3.50.0** (the new stable) and, if 3.50 supports it, finish the Android **built-in Kotlin** migration.

## Background
- We build with Flutter 3.44.3 (Dart 3.12). `flutter upgrade --verify-only` reports 3.50.0.
- On the Android side we moved to Android Gradle plugin 9.1 (needed by newer androidx libraries) but had to keep the **legacy Kotlin setup** (`android.builtInKotlin=false`, the Kotlin Gradle plugin declared in `android/settings.gradle.kts`, Kotlin 2.2.20): Flutter 3.44's templates still expect it, and enabling built-in Kotlin broke the plugin projects ("The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0"). Every release build prints a warning that plugins `engine_hooks` (our local plugin) and others apply the Kotlin plugin.
- A previous contributor PR (#176, closed) tried AGP 9.3.1 with built-in Kotlin on a newer toolchain; that route needs the newer Flutter.

## Plan
1. Read the Flutter 3.50 release notes and breaking-change list (especially "migrate to built-in Kotlin").
2. `flutter upgrade`, `flutter pub get`, `dart run build_runner build --delete-conflicting-outputs`, `flutter analyze`, full test suite.
3. Android: try `android.builtInKotlin=true`, remove the Kotlin plugin from `android/settings.gradle.kts`, from the car add-on module (`android/carvideo/build.gradle.kts`) and from our local plugin `packages/engine_hooks/android/build.gradle`; keep `kotlin { compilerOptions … }` blocks only where still valid.
4. Check each third-party plugin still builds (the warning lists those that apply the Kotlin plugin; upgrade or report them).
5. Update the README developer-setup table (Flutter/Dart versions).

## Test plan
- Release APK + car add-on build; `tools/check-apk-sqlcipher.sh` passes.
- **Upgrade test over the previous release on the emulator** (a toolchain change can affect the database library): install the last release, let it create an encrypted database with data, install the new build over it, confirm `[OTV-db] opened (encrypted)` and matching row counts.
- Smoke test on a Pixel and the Chromecast: launch, guide, playback, search, Settings, casting, backup/restore, Android Auto if available.
- Performance sanity on the Chromecast (guide scrolling, startup) since the rendering engine changes with Flutter.

## Risk
Medium to high: a Flutter version jump touches rendering, plugins and the Android build. Do it in its own PR and keep the old toolchain available to roll back.

## Acceptance criteria
Clean build on 3.50 without the Kotlin-plugin warnings (or with a documented reason for any that remain); tests pass; devices smoke-tested; README and changelog updated.
