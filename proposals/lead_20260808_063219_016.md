# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Detect unreachable code paths across the client/server boundary as a pre-push and CI gate**

*Project description:*
## Context

While re-scoping #243 we found `backend/engine/course_analyzer.py` — three complete,
well-formed functions (`analyze_cycling_climb`, `analyze_running_climb`,
`analyze_mountain_objective`) with **zero callers anywhere in the repository**. Dead
since it was written.

Nothing in the current check stack caught it:

- **`vulture`** scores unused *functions* at 60% confidence, below our configured
  `min_confidence = 80` (`pyproject.toml`), so it never reported them. Lowering the
  threshold globally is not the answer — it floods on FastAPI handlers, Pydantic
  validators, and protocol implementations.
- **`knip`** covers dead exports, but only on the TypeScript side.
- **`ruff`** only sees unused imports/locals within a module, never cross-module reachability.

So we have a real blind spot: **Python symbols that are exported, tested-adjacent, or
plausible-looking, but that no execution path actually reaches.**

## The bigger version of the same gap

This repo owns both ends of the wire, which means reachability is checkable in ways a
single-language linter can't manage:

1. **FastAPI endpoints with no client caller.** Every `@app.post("/api/engine/...")` in
   `api/index.py` should be reachable from `lib/agent/coach-tools.ts` (the
   `executeDeterministicEngineTool` path table), `lib/coach-api.ts`, or a `app/` route.
   An endpoint reachable from none of those is either dead or an undocumented external
   contract — both worth knowing about.
2. **Coach tools defined but never routed.** `coachToolDefinitions` entries that fall
   through to `status: "pending_implementation"` are invisible today; the model can call
   them and silently get a stub back.
3. **Client calls to endpoints that don't exist.** The inverse direction — a path string
   in `coach-tools.ts` with no matching FastAPI route — is exactly the #352 failure mode
   (404 at runtime, discovered from a Vercel log).
4. **Engine/service modules with no inbound edge**, the `course_analyzer.py` case.

## Proposal

Add a reachability check that runs as a **pre-push step in `lefthook.yml`** and a **CI
gate in `.github/workflows/ci.yml`**, matching how `cpd`, `knip`, and `ast-grep` are
already wired.

Sketch of an approach, to be validated during implementation:

- Extract the FastAPI route table by importing the app and walking `app.routes` (no
  parsing needed — the routes are introspectable at runtime).
- Extract the client-side path set structurally with `ast-grep` (we already depend on it,
  and the paths live in object literals and string arguments that are easy to match).
- Diff the two sets in both directions; report unmatched entries.
- For intra-Python reachability, evaluate whether a targeted `vulture` allowlist plus a
  lower threshold scoped to `backend/engine/` and `backend/services/` is enough, or
  whether an import-graph walk from the FastAPI entrypoint is needed.

Per SCRIPTS.md this is durable, configurable, dependency-owning tooling, so it belongs as
a Typer CLI under `tools/` in the uv workspace rather than as one-shot glue in `scripts/`.

## Acceptance criteria

- [ ] A check exists that fails on a FastAPI endpoint with no client caller, and on a
      client path with no matching endpoint.
- [ ] A check exists that fails on an unreachable module under `backend/engine/` or
      `backend/services/`.
- [ ] It is wired into both pre-push (`lefthook.yml`) and CI (`.github/workflows/ci.yml`).
- [ ] Suppressions are supported and, per AGENTS.md, each one carries a nearby comment
      explaining why the rule does not apply.
- [ ] Running it against the tree *before* #243's fix flags `backend/engine/course_analyzer.py`.
      That is the regression fixture — if it doesn't catch the case that motivated it, it
      isn't done.
- [ ] Documented in AGENTS.md alongside the other pre-push checks.

## Notes

The last criterion matters most. It is easy to build a reachability checker that is
technically correct and catches nothing real; pinning it to a known-dead module we
actually shipped keeps it honest.
