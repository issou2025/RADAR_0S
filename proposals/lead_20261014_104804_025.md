## Confirmed defects

### D1. `swarm-automation` test target is not feature-gated; `--all-targets` and the manual full qualification are red

`cargo check --locked --workspace --all-targets` exits 101 with 15 errors,
all in the `swarm-automation` lib test target: test code in
`crates/swarm-automation/src/lib.rs` (e.g. line 1103) uses items gated behind
`#[cfg(feature = "qualification-faults")]` (`ATTEMPT_ONE_MARKER`,
`write_qualification_admit_attempt`, `QualificationFaultWitness`, …) without
being gated itself. The same target compiles clean with
`--features swarm-automation/qualification-faults`, and
`--workspace --lib --bins` is clean without it. Consequences: (a) the manual
`Full existing qualification` workflow job, which runs `cargo test` for owned
packages with no feature flags, is red on current main; (b) automatic CI
never runs `--all-targets` or unit tests at all (see P3), so this class of
breakage is invisible. Fix by gating the test code or moving the helpers
behind `cfg(any(test, feature = "qualification-faults"))`.

### D3. CheckRunner "conditional reuse" is documented `implemented` but cannot complete (tracked as #150)

`crates/swarm-kernel-host/src/store/acceptance.rs`, line 422 takes `source`

## Process problems

### P1. The 17 remainder PRs are a dead parallel track

Every `task/audit-*` remainder PR is a single added Markdown file under
`docs/remediation/` (+251…+490, zero Rust), 1 commit ahead and 372 commits
behind main; each PR body itself states the branch "is not a merge
candidate". Main has since implemented several remainders by reference
(commits citing PR49/51/52, PR56, PR64, PR40); #56 (GM fencing) is
substantially done on main (`gm_public_matrix_tests.rs` contains nearly the
whole closure matrix; three main commits cite "PR56") yet remains open.
#42 is actively harmful to merge: dirty/unmergeable, and it is the only
remainder PR that modifies existing files (`modules/claude/README.md`,
`UPDATE.md`) from the 40591a2 base over main's newer bridge.5 state.
Recommendation: one receipt pass over all 17 (done / still-open / superseded),
close the track, and keep remainders as issues instead of PRs.

### P2. Verification corpus is self-certification and unfalsifiable from the repo

57 `*VERIFICATION*.json` files (~17.5k lines of the docs tree's ~35.9k added
lines in the window; `docs/remediation` alone is 173 files / 35,286 lines at
HEAD) are authored by the same pipeline they certify and cite receipts/logs
that are not in the repository — hashes only, so no claim can be checked from
the repo itself. The records are carefully scoped (`PARTIAL_PROGRESS`,
`full_v27_qualified: false`), which is honest, but no document warns that the
evidence is self-produced and externally unfalsifiable. Extreme case: commit
`01298c7` ("fix(opencode)") is 81% its own VERIFICATION.json (4,166 of 5,141
lines).

### P3. "CI green" does not mean the gates are green

Push/PR CI (`.github/workflows/rust.yml`) is deliberately scoped: fmt fails
only on files in the diff, Clippy fails only on changed lines, tests run
only for changed integration targets; the full fmt/Clippy/test/qualification
shape exists only in the manual workflow_dispatch job (currently red, D1).
In the window, 189 Rust push runs on main = 181 success / 8 failures —
broken code reached main 8 times and was always fixed forward (zero reverts).
Of 22 sampled claim-bearing commits, only 5 had their own Actions run; the
rest were never individually CI-verified, because CI runs per push tip, not
per commit.

### P4. Least-auditable landing channel: patch application via self-deleting temp workflows

Five `github-actions[bot]` landings in the window (code fixes, e.g. mailbox
delivery identity, watch notice indexes) arrived through temporary
`temp-*.yml` workflows that apply patches and delete themselves, duplicating
the subjects of PRs #103/#104, with ≥25 failed temp-workflow runs. This path
bypasses PR review shape entirely and leaves the weakest audit trail of any
channel used. Related coordination cost: two parallel TaskPrompt tracks
(owner PR series vs the V27 line) were both built and then collided/merged in
`9952374`, including duplicate rustfmt passes over the same files.

### P5. Mega-commit checkpointing persists

Commit `7dc8617` alone is 23.4% of the window's churn (61,822 lines, 167
files, empty body) and was repaired the same day by `d5ed4292` (113 files);
the top two commits are ~30% of the window. The median commit is disciplined
(190 lines, 2 files), and `[skip ci]` usage dropped to zero in this window —
both genuine improvements — but the tail still lands unreviewable,
self-integrated checkpoints. Hottest file in the window is not code:
`CURRENT-AUDIT.md`, 60 touches.
