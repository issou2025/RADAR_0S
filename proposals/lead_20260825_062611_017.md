## What is wrong

The suite is at 481 tests and growing, much of it added quickly by several agents working in parallel. Test count is not the goal. A test that does not say why it exists is a maintenance cost with no payoff: the next person cannot tell whether a failure means a real regression or a stale assumption, and cannot tell whether the test is safe to delete.

Every test needs a comment saying **what would break in the real world if this stopped passing**.

## What a good comment says

Name the failure the test prevents, not the mechanics of the assertion. The code already says what it asserts.

Bad, because it restates the code:

```python
def test_dry_run_deletes_nothing(self):
    # Runs the sweeper in dry-run mode and checks no files are deleted.
```

Good, because it names the consequence:

```python
def test_dry_run_deletes_nothing(self):
    # The whole safety model rests on --execute being the only path that
    # deletes. If a refactor ever makes the dry run fall through to the
    # delete branch, this is the test that catches it before a bucket does.
```

## What to do

Review every test in `tests/`. For each one:

- If it prevents a real failure, add or improve the comment so it names that failure. Where the test came from a specific bug, say so.
- If it exists only to raise the count, or duplicates another test's coverage, delete it. Fewer tests that each mean something beat a large suite nobody trusts.

The project rule that every behaviour gets a use case and an abuse case still holds. This is not a reason to drop the abuse cases. It is a reason for each abuse case to say what abuse it is modelling and why that abuse is plausible.

Pay particular attention to files written in bulk: `test_oci_stdlib_client.py` (75), `test_doc_paths_and_links.py` (42), and the recent additions to `test_oci_repo_sweeper.py` and `test_snapshot_sizes.py`.

## Acceptance

- Every test in `tests/` carries a comment naming the real-world failure it prevents.
- Redundant and count-padding tests are removed, with the removals listed in this issue.
- The suite still passes, and the mutation checks that already exist still bite.
