*Project description:*
Part of #256. Clayton found https://db4tarkov.com/ ("Database for Tarkov": gun builder, gun tier maker, presets, flea, quest tracker, **items to keep**, interactive maps, crafts/barters; also iOS/Android apps by dvcstudiox) and asked whether we can pull, scrape or sync its info.

## What it is (checked 2026-09-17 from its public web bundle)
- A Flutter web app (`main.dart.js`, ~18 MB). No `robots.txt`, no documented public API, no data licence; the bundle says "All rights reserved".
- **Base game data comes from `json.tarkov.dev`**, the same source we use (its own build notes: "generate items_json.dart from json.tarkov.dev", "json.tarkov.dev (R2) → adapt GraphQL shape"). Nothing new to gain there.
- Quest/item prose links to the EFT Fandom wiki (~4,700 links, images from `static.wikia.nocookie.net`), which #379 already covers.
- Its **own curated content** (items to keep, gun tiers, meta builds/presets, ammo picks) is served from private backends (`eft-cdn.dvcstudiox.workers.dev/json`, a Supabase project) and map assets from its CDN plus third-party map sites (re3mr, tarkov.help).

## Constraints
AGENTS.md: prefer structured public data (`json.tarkov.dev`), don't scrape websites when structured data exists, preserve attribution/licences, no copying without a licence review. Scraping db4tarkov's private endpoints would violate those and likely its terms.

## Options, cheapest first
1. **Link out**: a "db4tarkov" action next to "Wiki" on items/keys/ammo/quests (same `IWikiLinkOpener` allowlist pattern, #379), where its page adds value (gun builder, tier lists).
2. **Build our own equivalents from tarkov.dev data** we already have: "items to keep" = current/future quest + hideout + craft/barter needs (#274 recommendation engine already computes most of this); ammo tiers from penetration/damage per calibre (#285); weapon/meta builds are harder (needs mod compatibility + stats; tarkov.dev exposes weapon properties/presets).
3. **Ask the developer** (their Discord is linked in the app) for permission or a data feed for the curated lists; only integrate with written permission and attribution.

Not started. Pick an option when the rough V2 lands; option 2's "items to keep" overlaps work that already exists.
