# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Model shared with a second firm: check text notes for internal wording, personal paths and names**

*Project description:*
## Context

A workshared project model will also be used by a second firm. The user wanted the in-model standards and coordination notes to be "friendly" to that team: joint wording, no wording that only one firm understands, no internal references. No `am-*` skill covers a text review like this, so the agent searched the text notes by hand.

## What happened

1. **Scope.** The agent read all text in the standards view, the reference sample views and the sync start view (where the in-model issue board from `am-issue-board` lives).
2. **Search noise.** A search for the first firm's short abbreviation matched the same letters used as a common word abbreviation in many notes outside the scope. A whole-word, case-sensitive search was needed.
3. **Missed notes on the first read.** The first read of the start view found no issue board notes. A second, targeted search found the two board notes; their owner view had the start view's name. The cause of the miss is not confirmed (inferred: a second view with the same name, for example of another view type, or a read that took the first match by name). A read by element id, or of every view that matches the name, would avoid it.
4. **What the review found and changed (after the user approved the list):**
   - the title and header now say these are proposed joint project rules, "for review";
   - "office line styles" became "project line styles";
   - two personal cloud-sync folder paths in board notes became "personal cloud folder (full path in the link's Manage Links properties)";
   - a first name became the person's Revit user name, like the other board entries.
   The user decided that `@` user names on the board stay, because they are project coordination notes.
5. **Listed, not changed:** a note with a typo that an outside reader would not understand, and a sketch note with a firm prefix in a working view outside the scope.

## Proposed change

A small read-only check (in `am-issue-board`, or a new "shared model text check"):

- scope: the standards view, reference views, start or sync views, issue board notes, and optionally every text note;
- whole-word search for terms the user gives (firm names and abbreviations, internal tool names, office-only words) and for personal paths (drive letters, user folders, cloud-sync folders) and email addresses;
- a list of `@` names and first names for the user to decide on;
- output: a change list for the user; any change goes through `am-safe-change`.

For `am-issue-board`: when a finding includes a file path from a personal folder, write a neutral form by default, because the board may be read by other firms.

## Acceptance ideas

- A search for a short firm abbreviation does not match common words that contain the same letters.
- A board note that holds a personal sync-folder path is listed.
- Issue board notes are found on the first read, whatever view they sit in.

## Not verified

- How the check should treat text inside families, schedules and title blocks.
- Why the first read missed the board notes (point 3).
