# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[Feature]: Leerlingvolgsysteem: a switch, find a pupil and read the overview of their file**

*Project description:*
### Problem / motivation

A teacher preparing a class council, a talk with parents or a lesson wants to ask Claude "how is this pupil doing?": results, behaviour, educational needs, absences. All of that is in the pupil tracking system (LVS, "leerlingvolgsysteem", `/?module=LVS`), which every teacher with LVS access can read for the pupils they may see.

This issue is the base of the LVS tools: a switch, finding a pupil, and the overview of a pupil's file. The follow-ups read the parts: notes (#154), results (#155), support plan (#156), absences (#157).

Library: yvanvds/dartschool#160 (base), and the privacy rules of yvanvds/dartschool#159. Blocked until a flutter_smartschool release has `LvsService`.

### Proposal

**A switch, off by default: "Leerlingvolgsysteem".** The opt-in switches (`OptInTools`, `lib/src/opt_in.dart`) are for tools that need extra rights. Most teachers have LVS access, so by that rule these tools would be offered to everyone, like the gradebook tools. They are not, on purpose: the LVS holds the most sensitive data about pupils (care, behaviour, educational needs, sometimes health), and a teacher (and their school) must choose to let an AI assistant read it. So:
- `Setting.lvs` ("Leerlingvolgsysteem", `SMARTSCHOOL_LVS`, `lvs`, `isSwitch: true`), in `manifest.json`'s `user_config` and the credentials file, off by default; its description says what it opens up and links to the privacy section of the guide (#158).
- `lvsOptIn` in `lib/src/lvs/lvs_opt_in.dart`; `checkAccess` reads the root of the LVS tree (classes only, no pupils) and grants when it lists a class.
- Update the doc comment of `OptInTools`: a switch is for extra rights **or** for data sensitive enough that it needs an explicit choice.

**Two read tools** (`readOnlyHint: true`):
- **`search_lvs_pupils`**: `query` (part of a name) → the matching pupils, one line each: name, class, `pupil_id`, `class_id`. Several matches: Claude asks the user which one, it never picks. No match: a sentence, not an error.
- **`read_lvs_pupil`**: `pupil_id`, `class_id` → name, class, the class's teachers, today's attendance, and the **parts of the file that hold something**: note categories (with sub-categories) and the other parts (results, support plan, absences, ...), with "new" where the LVS marks new notes. This tells Claude which follow-up tool to call and with which category.

**Privacy, for all LVS tools** (this issue sets it up; the follow-ups follow it):
- **Read-only.** No LVS write tool, now or later, without a new issue that discusses it.
- **Nothing on disk.** No cache folder, no downloads, no message-cache-like store for LVS answers; in memory only what a call needs.
- **Nothing in the log.** `server.dart` logs `tool $name failed: $error`; for LVS tools the logged error is the error's type and HTTP status only, never its message (it may still hold a name). Claude Desktop's MCP log is a file people attach to bug reports.
- **Errors** shown to the user name what to do, not what the answer held.
- **Tool descriptions** say: use only when the user asks about this pupil; do not copy LVS content into files, artifacts, messages or other tools unless the user asks; the data is confidential.
- **One pupil per call.** No tool reads a whole class's notes or results.
- **Tests** use a fake LVS in `test/support/` with the fakes and the guard test of yvanvds/dartschool#159 (a smartschool-mcp copy of that guard over `test/`).

**Where it goes:** `lib/src/lvs/` (`lvs_access.dart` with `withLvs(session, action)` and the error mapping; `lvs_format.dart`), the tools in `lib/src/tools/`.

**Docs:** README *Tools* (and the manifest test's order), `manifest.json` tools with Dutch descriptions. The guides come in #158.

### Acceptance criteria

- With the switch off (the default), no LVS tool is offered; `smartschool_status` says the switch is off.
- With it on, both tools are offered, and `smartschool_status` reports whether the account can read the LVS.
- `search_lvs_pupils` handles none, one and several matches; `read_lvs_pupil` lists the parts with content.
- No LVS tool writes to disk; a failing LVS tool logs no message text (a test feeds an error whose message holds a fake name and checks the log).
- Tests against the fake LVS, with fake data only; the guard test passes. `dart analyze` and `dart format` clean.

### Alternatives considered

- **No switch** (like the gradebook): simpler, but then every user who installs the extension gives Claude access to the LVS without choosing to.
- **One tool that reads everything about a pupil:** too much sensitive data in one go, most of it not needed for the question; separate tools per part keep each answer to what was asked.
- **Tools that take a pupil's name instead of ids:** names are not unique; the search step makes Claude confirm the pupil.
