# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Legacy IFC profile: GlobalIds of type-level material relations depend on the STEP entity number**

*Project description:*
In the legacy IFC profile the GlobalId of the type-level IfcRelAssociatesMaterial relations (and of the layer set relations) is hashed from the STEP entity number of the relating material (the seed strings are "type-materials:N" and "type-layer-set:N"). Any change that adds or removes one entity before them changes all of these ids again; in 0.2.0 the 11 mullion Span values of the Revit 2022 rac basic sample moved 45 of them. The current profile does not have the problem (its seed is the project GlobalId and the GlobalId of the first related object).

Needed: seed the legacy relations from a stable input, for example the Revit material or layer set element id or the GlobalId of the first related type, as the seed of the materials relation already does, and keep the current ids where they are already stable. The change moves ids once more, so it belongs in a release that says so in the changelog.
