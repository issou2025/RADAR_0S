# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Transport Auggie task instructions through private --instruction-file inputs instead of argv**

*Project description:*
Parent-Issue: #1964
Blocked-By:

## Objective

Deliver Auggie instructions through files without reclassifying them as context.

## Context

`AuggieClient._run_auggie_cli()` appends the complete prepared instruction to argv and then streams the child process output. It has the same task-size argument risk as the other inspected adapters.

Auggie's official automation documentation distinguishes the initial instruction from data supplied on stdin: stdin is additional context. The documented `--instruction-file <PATH>` mechanism supplies the instruction itself. Therefore simply piping the task to stdin would not establish the intended input contract even if it avoided E2BIG.

This child owns Auggie's instruction role and private temporary-file lifecycle. It is an independent root and does not require the shared stdin extension.

## Requirements

REQ-001: Every AuggieClient task invocation, through either _run_llm_cli or its delegated _run_auggie_cli path, must use non-interactive print mode and exactly one adapter-owned --instruction-file argument naming a regular file containing the task instruction; the instruction body must not appear in argv, environment variables, an intervening shell command, supplemental stdin context, or a short prompt asking the agent to read the file.
REQ-002: For this transport-only change, the prepared instruction is the input prompt with each '@' replaced by one backslash followed by '@', then leading/trailing whitespace removed using Python str.strip semantics; the file must contain exactly its UTF-8 bytes, without further escaping, added newline, truncation, or splitting into separate task invocations, for both short and long prompts in edit and no-edit modes.
REQ-003: Each execution attempt must use its own exclusively created, owner-only read/write regular file on supported POSIX systems, outside the target worktree and Git metadata; active attempts must not share a path or contents, and an unsafe configured temporary directory must cause selection of a safe external location or failure before task launch rather than a worktree modification.
REQ-004: The instruction file must be complete, flushed, and closed for writing before task launch, remain readable until the direct task child has exited or been terminated and reaped, and be removed with its handles closed before handled return or exception on completion, nonzero exit, launch failure, timeout, interruption, or usage-limit failure; cleanup failure must be reported without hiding the primary failure or presenting the operation as clean success.
REQ-005: Instruction-file preparation/finalization failure must prevent task launch and produce an explicit failure; unsupported --instruction-file handling or task failure must not trigger an argv fallback, reclassification as stdin context, task truncation, or an additional transport-induced invocation; competing configured instruction sources, including --instruction or another --instruction-file, must fail before task launch rather than override or duplicate the adapter-owned instruction.
REQ-006: Input transport must forward already-resolved model/options, executable override, backend identity, cwd/env, non-input extra arguments, and any explicit continuation identity unchanged; options_for_noedit is selected when is_noedit is true and that list is nonempty, otherwise options is selected, and file transport must not introduce permission-bypass flags, a different session, or an additional daily-usage-counting attempt.
REQ-007: The adapter must retain live output observation during task execution and return the CLI's text result rather than a new protocol envelope; input, startup, or cleanup failures must not be reported as successful task output, and transport diagnostics must not print the instruction-file contents.

## Acceptance Scenarios

### A1 — Instruction-file delivery from the production entrypoint (REQ-001, REQ-002, REQ-003, REQ-006)

Given real backend configuration and a real test executable selected with `AUTOCODER_AUGGIE_CLI` or PATH, call AuggieClient._run_llm_cli and let it reach the actual subprocess path. The child verifies print mode, exactly one --instruction-file, a private regular file outside the workspace, and the absence of the body from argv/env. It reads the file and reports the complete byte count/digest. Exercise short prompts and prepared instructions over 256 KiB and 2 MiB, including Unicode, '@', quotes, shell-looking text, internal CR/LF, and no final newline. Compare with independently calculated REQ-002 bytes, not a production normalization helper.

### A2 — Instruction is not supplemental context (REQ-001, REQ-005)

Use a CLI test harness that exposes its instruction input and stdin-context input as distinct observations. The entire task appears in the former through the named file, never only in the latter. Separately verify the supported real Auggie release's --instruction-file behavior and record version/documentation or smoke-test evidence. A fake that merges every input source into one string cannot detect this bug and is insufficient.

### A3 — File lifetime, isolation, and workspace safety (REQ-003, REQ-004)

The child delays before opening its file and can still read the complete instruction. Distinct attempts, including isolated overlapping harness processes, observe distinct files with the correct contents. Files disappear after handled completion. A temporary directory configured inside the workspace is either bypassed for a safe external location or rejected before launch, and the transport never dirties the repository.

### A4 — Errors and interruption clean up (REQ-004, REQ-005, REQ-007)

Exercise preparation/write failure, missing executable, CLI nonzero exit, recognized usage-limit failure, handled timeout, and interruption. No partially written file is passed to a task, the direct child is finished before its file is removed, and no file/handle remains on handled exit. Inject unlink failure and verify an explicit cleanup diagnostic retaining any primary error, not clean success. No alternative argv or stdin-context task starts.

### A5 — Configuration and streaming are not bypassed (REQ-006, REQ-007)

Exercise edit/no-edit option selection, model options, aliases, executable override, non-input extra arguments, and a supplied continuation identifier. The child observes the effective values unchanged, and an output marker is visible while the child is still running. The change does not generate a second usage-counting attempt. A competing configured --instruction or --instruction-file is rejected before the task writes a startup marker.

## Non-goals

Changing Auggie's daily usage policy, context indexing, session-selection policy, model context limits, historical prompt preparation, permission-model redesign, converting other providers, a shared persistent file service, or restart scavenging after SIGKILL/machine failure.

## Implementation Notes

- Inspect `src/auto_coder/auggie_client.py`, including the `_run_llm_cli()` delegation, usage accounting, direct Popen ownership, output loop, and exception paths.
- `tests/test_backend_cli_options_integration.py` currently includes command-recording doubles. Keep those tests but add real adapter-to-subprocess checks that independently observe instruction-file contents and input role.
- A private regular temporary file and structured cleanup are sufficient. This provider need not wait for shared stdin support.
- [Official CLI reference](https://docs.augmentcode.com/cli/reference) documents --instruction-file as the initial instruction source.
- [Official automation guide](https://docs.augmentcode.com/cli/automation/overview) explicitly describes stdin as additional context and demonstrates --instruction-file separately. That distinction is stated explicitly in REQ-001, rather than inherited as an unstated external convention.

Only this issue's Requirements define its implementation obligations.
