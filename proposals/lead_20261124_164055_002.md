# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Plugin sets process-wide ja_JP.utf-8 locale on Revit startup, breaking creation of projects from templates (ArchiveException corruptData)**

*Project description:*
## Summary

`usd_exporter_revit_core_startup()` (called from `App.OnStartup`) changes the C/C++ locale of the whole Revit process:

```cpp
// source/cpp/Core.cpp
static constexpr char localeName[] = "ja_JP.utf-8";
std::setlocale(LC_ALL, localeName);
std::locale::global(std::locale(localeName));
```

This runs inside the host process at Revit startup, so it affects Revit itself, not only the exporter. With the add-in loaded, Revit fails to create a new project from some templates. In our case it is a Russian-localized architectural template with families that use lookup tables. Revit shows "Cannot complete the operation due to an unknown error".

## Environment

- Plugin: v2.0 release (commit f44fc6e), installers `UsdExporterRevitSetup2024` / `UsdExporterRevitSetup2026`
- Revit 2026.5.1 (Build 20261015_1515), RUS UI
- Revit 2024.3.6 (Build 20260709_1515), RUS UI
- Windows 11 <version / build from winver>
- Template: public BIM2B architectural template `ADSK_RU_Шаблон_АР_BIM2B_r2026_v2.2.3.rte` / `ADSK_RU_Шаблон_АР_BIM2B_r2024_v2.2.3.rte`

## Steps to reproduce

1. Install the exporter for Revit 2024 or 2026.
2. Start Revit, File → New → Project, select the BIM2B AR template.
3. Revit shows "Cannot complete the operation due to an unknown error".
4. Disable the add-in (move its `.addin` out of the Addins folder) and repeat: the project is created normally.

No export command is involved. The failure happens only because the add-in is loaded.

## Revit journal excerpt (Revit 2026.5.1)

```
Create project with template C:\_Work\Revit\Templates\R26\ADSK_RU_Шаблон_АР_BIM2B_r2026_v2.2.3.rte
DBG_INFO: An ArchiveException 105 corruptData is raised at line 1637 of ...\Foundation\Utility\Archive\DataDict.cpp: can't load container field m_mapSizeTables
Assertion failed: line 364 of ...\Revit\RevitDB\ElemTable\Unmarshaller.cpp
...ADocumentUpgrade::docUpgrade

```

`m_mapSizeTables` points to family lookup (size) tables. These are text data, which is consistent with a locale-dependent parsing failure.

## A/B verification (Revit 2024.3.6, same template)

| Add-in | Result |
|---|---|
| Original exporter from `C:\Program Files\Omniverse\UsdExporterRevit2024` | `corruptData`, unknown error |
| Same files, only `ja_JP.utf-8` in `usd_exporter_revit.dll` replaced by `C` (copy outside Program Files) | Project created successfully |
| Add-in not loaded | Project created successfully |

On Revit 2026.5.1 the project is also created normally with the add-in disabled. The failure also reproduces on Revit 2024 (.NET Framework 4.8), so it is not related to .NET 8 / .NET 10. The process-wide locale change is the cause.

## Expected behavior

An add-in should not change the global locale of the host process. Templates should open normally with the add-in loaded.

## Suggested fix

The UTF-8 locale is probably needed so narrow-string CRT/USD file APIs handle non-ASCII (e.g. Japanese or Cyrillic) paths. Simply removing it may regress that, so instead:

- Do not change the process-wide locale in `usd_exporter_revit_core_startup()`, which runs inside Revit at startup.
- Apply the UTF-8 locale only for the duration of an export. Save the previous value (`setlocale(LC_ALL, nullptr)` / `std::locale()`) and restore it afterwards. Alternatively, run export work on a thread with `_configthreadlocale(_ENABLE_PER_THREAD_LOCALE)` and set the locale only there.
- Longer term, convert paths explicitly (`MultiByteToWideChar(CP_UTF8, ...)`, or `std::filesystem::path` from `char8_t`) instead of relying on the global locale.
