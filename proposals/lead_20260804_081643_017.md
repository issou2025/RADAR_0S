## Summary

The AI Investigator has grown expensive, slow, and prone to hallucination. Root-caused via direct measurement (not theory) during a design session — supersedes #443, which only addressed frontend streaming parity.

## Root cause (confirmed, measured)

`KNOWN_FIXES` in `const.py` has 169 entries and grows by one every issue closed. `_fix_is_relevant()` (`ai_skills_context.py:915`) is supposed to version-scope which entries get sent to the AI, but its first rule (`if fix.get("scope_not_covered"): return True`) matches essentially every entry, because the release checklist requires every entry to document a `scope_not_covered`. Verified: **169 of 169 entries currently pass this "filter."** This block is ~327,000 characters of source (~80,000+ tokens) sent on **every single investigator run**, and it grows forever. This is the dominant driver of the "runs slower every time" complaint.

Audited every field in a KNOWN_FIXES entry: all except `version_fixed` have exactly one functional consumer in the whole codebase (this same rendering function), and no test enforces their presence.

## Fixes in scope

1. **Purge `scope_not_covered`** from the KNOWN_FIXES schema, all 169 entries, and the CLAUDE.md release checklist requirement (with a pre-delete check that no genuinely-still-open gap gets silently lost — migrate to a GitHub issue if so).
2. **Bound `_fix_is_relevant()`** to a real version window now the escape hatch is gone.
3. **Stop rendering `title`/`scope_covered`** to the AI (both duplicate what `RELEASE_NOTES` already says, more concisely, in occupant-outcome language) — use the matching `RELEASE_NOTES[version_fixed]` bullet instead. Keep the fields in the dict for human/dev-stack readers.
4. **Trim the GitHub-issues cache** to only the fields rendered, instead of full raw API responses.
5. **Consolidate duplicated deterministic checks** — delete the THERMAL PIPELINE HEALTH and Issue #205 prompt-text rule blocks (`ai_skills_investigator.py:131-163`); wire the existing `_build_timing_correlations()` output and `investigation_fallback()`'s checks into an always-included pre-computed context section instead of asking the model to re-derive them.
6. **Restart-cause filtering** — narration only surfaces `cause == "unknown"` (crash-like) restarts; `user_restart`/`version_changed` never get flagged as problems.
7. **Merge AI Activity Report's AI-narrative half into the Investigator** as one skill (the separate deterministic Daily Record tab is untouched). Single model config (`ai_model` only, drop `ai_investigator_model`/`_MAX_TOKENS`/`_REASONING`).
8. **Occupant-first output contract** — every section leads with occupant-outcome language, not `[source: key, value: X]` citation syntax.
9. **Streaming UX** — shared SSE runner (per #443's already-validated design), real step narration instead of an elapsed-seconds counter, progressive fill into final layout instead of raw markdown painted char-by-char.
