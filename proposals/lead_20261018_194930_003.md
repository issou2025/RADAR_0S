# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[web] `_flutter.loader.load()` can't be retried under a CSP `trusted-types` directive without `'allow-duplicates'`**

*Project description:*
### Steps to reproduce

1. `flutter create --platforms web bug && cd bug`, with no changes to `lib/main.dart`.
2. Add the `web/flutter_bootstrap.js` below. Its first `load()` points at a missing path, standing in for a failed `main.dart.js` download. A capturing `error` listener then retries with a second `load()`. The listener is needed because `load()` resolves before the download fails and never reports it (#102265).
3. `flutter build web`
4. Save `serve.py` below in the project root, then `cd build/web && python3 ../../serve.py`. It serves the folder with `Content-Security-Policy: require-trusted-types-for 'script'; trusted-types flutter-js flutter-engine`.
5. Open http://localhost:8000 and check the console.

### Expected results

The retry starts the app. It does when served with no CSP (`python3 -m http.server 8000`), and with `'allow-duplicates'` added to the list (`python3 ../../serve.py "'allow-duplicates'"`). Retrying in place matters for an app embedded in a larger page, where a reload would lose the host page's state.

### Actual results

The second `load()` rejects with a `TypeError` because the `flutter-js` policy already exists, and the app never starts. Same in Chrome 155, and in Playwright's Firefox 157 and WebKit 27.2 builds. It also happens with `trusted-types *`, and without `require-trusted-types-for`. Two `load()` calls in a row throw the same way on the second.

`load()` runs `new FlutterTrustedTypesPolicy()` on every call ([loader.js#L160](https://github.com/flutter/flutter/blob/56f0dcbb3313e4d463444c958ded61cdf54bb87d/engine/src/flutter/lib/web_ui/flutter_js/src/loader.js#L160)), and the constructor calls `trustedTypes.createPolicy('flutter-js', ...)` each time ([trusted_types.js#L21](https://github.com/flutter/flutter/blob/56f0dcbb3313e4d463444c958ded61cdf54bb87d/engine/src/flutter/lib/web_ui/flutter_js/src/trusted_types.js#L21)). It reproduces on master at 56f0dcb too. Creating the policy once and reusing it across calls would fix it. Related: #187983, about the same policy's URL checks.

```js

// load() doesn't report a failed main.dart.js download, so watch for it.
document.addEventListener('error', (event) => {
  if (event.target instanceof HTMLScriptElement) {
    console.log('Failed to load', event.target.src, '- retrying');
    _flutter.loader.load();
  }
}, true);

// The first attempt fails, standing in for a network error.
_flutter.loader.load({ config: { entrypointBaseUrl: 'missing/' } });
```

`serve.py`:

```python
import http.server, sys

CSP = "require-trusted-types-for 'script'; trusted-types flutter-js flutter-engine"

class Handler(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header("Content-Security-Policy", CSP + " " + " ".join(sys.argv[1:]))
        super().end_headers()

http.server.test(Handler, port=8000)
```
