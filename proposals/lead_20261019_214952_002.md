# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**feat(notifications): Add opt-in Android local notification infrastructure**

*Project description:*
**labels:** `enhancement`, `android`, `privacy`, `reminders`  
**Priority:** P1

## Problem
Existing in-app reminders are not sufficient for users who want device-level alerts while the app is closed.

## Scope
- Evaluate a maintained local-notifications package compatible with current Flutter/Android tooling.
- Add a clearly labelled, default-off notifications setting and request Android notification permission only after an explicit user action (Android 13+).
- Use on-device scheduling only; no Firebase Cloud Messaging, developer server, analytics or account required.
- Create a minimal notification channel, localization and sensible deep-link contract.
- Preserve existing in-app reminders for users who decline permission and for Web.

## Acceptance criteria
- [ ] Android users can opt in/out without affecting in-app reminders.
- [ ] Notification permission is requested contextually and denials are handled.
- [ ] No network service or personal data collection is introduced.
- [ ] Notification text avoids sensitive animal data on the lock screen where configurable.
- [ ] Android tests and a documented manual device test plan are included.

## Quality gates
- [ ] `dart format` / `flutter analyze` pass.
- [ ] Automated tests pass and new cases are covered.
- [ ] User-facing documentation and DE/EN copy are updated as needed.
