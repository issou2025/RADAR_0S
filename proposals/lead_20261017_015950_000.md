# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Revit: "Can't keep elements joined" reaches the curator as a modal during the site-model steps**

*Project description:*
**Found:** 2026-10-15, revit-0.1.0 release gate, zip built from `ed63792`. **Reproduced in Revit 2025.4, 2026.5 and 2027**: the dialog appeared twice in each, and in each the import finished "Bundle imported." with no context buildings and no site-model link.

## What happens

On an import of order `8337803e…` (6,148 context buildings, IFC4 site model), Revit stops twice on its own failure dialog: **"Error - cannot be ignored — 2 Errors, 0 Warnings: Can't keep elements joined."** OK is disabled and no resolution button is offered, so **Cancel** is the only choice.

1. **ContextBuildings** (`OpenIFCDocument`): the dialog appeared after about 3 minutes. After Cancel, the log reads *"Could not open the site model to copy its buildings (Site/Site.ifc): Transaction committing failed"* and *"The import was rolled back: Revit refused it with "Can't keep elements joined." (id 6650b20b-592d-41a0-9f52-51f5f26e3fc3)"*. No context buildings are imported.
2. **LinkSiteIfc** (`RevitLinkType.CreateFromIFC`): the same dialog appeared again about 4 minutes later.

The run was unattended (`MANTLEPLACE_BUNDLE_ZIP`), where the add-in promises that no dialog is raised. An attended curator sees the same modal and loses the buildings.

## Why the existing handling misses it

`ImportFailurePolicy.Decide` lets Revit resolve `CannotKeepElementsJoined` only when Revit offers a resolution (`hasResolutions`). Here Revit offers none, so the decision is **RollBack**. The session-wide `OnFailuresProcessing` hook returns `ProceedWithRollBack`, yet Revit still shows the modal. Two possibilities to rule out:

- Is a `FailuresProcessing` result honoured for the IFC importer's own transaction?
- Does the rollback need `FailuresAccessor.RollBackPendingTransaction()` as well?

The order this was first fixed against (1,319 buildings) offered "Unjoin", so it took the resolve path.
