# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**feat(ai): add a portable use-dust Agent Skill**

*Project description:*
## Problem

Dust is built for developers and AI coding agents, but agents currently have to rediscover installation, feature selection, annotation setup, generation commands, compatibility rules, and validation from multiple guides. There is no reusable Agent Skill that can guide Codex, Claude Code, and other compatible agents through using Dust in a Dart or Flutter application.

## Goal

Add one vendor-neutral `use-dust` skill based on the open Agent Skills format. The same canonical bundle should work in Codex, Claude Code, and other tools that consume `SKILL.md`, without maintaining divergent instruction copies.

## Scope

- Create one canonical `use-dust` skill directory with a concise `SKILL.md`.
- Trigger for adding, migrating, validating, or troubleshooting Dust in Dart/Flutter application projects.
- Cover feature selection for derive, SerDe, validation, HTTP, routing, state, i18n, and Database.
- Route agents to the correct package, imports, authoring guide, and `dust build` / `dust check` workflow.
- Preserve the CLI/package compatibility contract and distinguish normal generation from DB and i18n modes.
- Add only the minimal bundled reference material needed when repository docs are unavailable.
- Add Codex UI metadata in `agents/openai.yaml` if it remains valid and ignorable by other Agent Skills hosts.
- Document copy/install paths for Codex (`.agents/skills`) and Claude Code (`.claude/skills`) while keeping one canonical source.

## Out of Scope

- Instructions for contributing to Dust engine internals.
- A plugin, MCP server, marketplace submission, or automated publication.
- Duplicate Claude-specific and Codex-specific skill bodies.
- New Dust runtime behavior or public Dart APIs.

## Tasks

- [ ] Define representative trigger and non-trigger prompts.
- [ ] Initialize the skill with the repository skill-creator workflow.
- [ ] Write concise imperative instructions and focused references.
- [ ] Add portable installation/discovery guidance.
- [ ] Validate the skill structure and frontmatter.
- [ ] Forward-test direct, indirect, incomplete, non-trigger, and troubleshooting prompts.
- [ ] Update the root documentation with the skill location and supported hosts.

## Acceptance Criteria

- [ ] One `use-dust` skill bundle follows the Agent Skills `SKILL.md` specification.
- [ ] The description activates for Dust adoption and troubleshooting tasks and excludes Dust engine contribution tasks.
- [ ] The skill selects Dart versus Flutter commands correctly.
- [ ] The skill distinguishes `dust build` / `dust check`, DB generation/checks, and i18n workflows.
- [ ] Examples are valid against current Dust 0.1.x APIs and do not advertise planned features as available.
- [ ] Codex and Claude Code can install or discover the same canonical skill without divergent instruction copies.
- [ ] No secrets, machine-specific paths, dependency changes, generated output, or unrelated files are committed.

## Validation

- `quick_validate.py <skill-directory>`
- Agent Skills reference validation when available
- `cargo fmt --all -- --check`
- `dart analyze` / `flutter analyze` for any bundled Dart examples in a temporary fixture
- Forward-test at least five representative prompts covering activation boundaries and output correctness

## Risks

- Feature snippets can drift from the current documented API; derive from public guides and keep references minimal.
- Host-specific discovery paths differ; keep the skill format portable and installation guidance separate from workflow instructions.
- A broad description may trigger on Dust engine contribution work; make the application-project boundary explicit.
