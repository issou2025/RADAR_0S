# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Localize the full dashboard and mobile app in Sinhala and Tamil**

*Project description:*
## Request

Make English, Sinhala and Tamil work throughout the Sarvodaya Connect dashboard and Flutter app. When a user chooses a language, all application-owned interface text on every screen available to that user should use it consistently. Cover every supported role and state, not only HQ home or sign-in.

## Current gap

Localization is partial. The dashboard sign-in form has a local language switch, but the authenticated dashboard is largely English. Mobile stores a selected language in `DemoStore` and translates parts of the home experience, while the app shell and many screens still contain English literals. The preference is not applied through a shared localization system across the full journey.

## Implementation

- Define stable message keys and reviewed `en`, `si` and `ta` catalogs. Use Flutter ARB files with generated localizations on mobile and locale dictionaries/providers for Next.js App Router on the dashboard. Replace scattered inline language branches and English UI literals with these messages.
- Make the selected locale apply to server-rendered and client-rendered dashboard content, Flutter `MaterialApp`, navigation, dialogs and overlays. Set the web document `lang` attribute and Flutter's supported locales and localization delegates.
- Persist the user's choice across navigation, refresh, sign-out and app restart. Define how the preference works before sign-in and after sign-in, and how a user changes it later. English may be the initial fallback until a choice is made; a missing translation must be visible to developers, not silently leave mixed-language screens.
- Cover application-owned copy: navigation, headings, tabs, filters, form labels, hints, validation, loading/empty/error states, confirmations, notifications, accessibility names/tooltips, dates, numbers, currency, plurals and dynamic templates. Keep API identifiers, enum values, routes and database values language neutral; map them to localized display labels.
- Handle server-generated or API-provided copy with structured codes and data where practical, then format localized messages in the client. Include SarvoAI interface copy; when SarvoAI is enabled, instruct it to answer in the selected language and evaluate Sinhala/Tamil output separately.
- Keep society names, user-entered text, uploaded documents, audit records and other stored content in their original language. Do not automatically translate or overwrite them. Propose a separate policy if translated record content is needed.
- Use human-reviewed Sinhala and Tamil translations. Machine translation may assist drafting but must not translate live interface text at runtime or be shipped without review. Preserve brand names, acronyms and official terminology.

## Screen and role audit

Create a checklist from the actual dashboard and mobile screen catalogs. Audit every accessible screen and state for HQ, DM, DDM, SPC and Society Officer on each platform where supported, including authentication, first-time setup, account administration, society records, activities, emergencies, documents, reports, SarvoAI and settings. Record any platform/role combination that does not exist. Include representative screenshots for each language on dashboard and mobile.

## Acceptance criteria

- [ ] Selecting Sinhala yields Sinhala application-owned UI throughout every applicable journey; selecting Tamil yields Tamil; switching back yields English.
- [ ] Language choice persists across page changes, reloads and app restarts, with a clear sign-in/sign-out behavior.
- [ ] Every supported role and screen/state is accounted for in the audit checklist; no mixed English UI remains except intentional names, acronyms, user content and documented exceptions.
- [ ] Validation errors, API failure states, notifications and accessibility text follow the selected language.
- [ ] Dates, numbers, currency and plural messages display correctly for each locale without changing underlying stored values.
- [ ] Sinhala and Tamil speakers review terminology and representative journeys. Text remains legible without clipping on small screens and with larger text settings.
- [ ] Dashboard and mobile localization checks cover language switching, persistence and representative screens for all roles. Existing English behavior remains covered.
- [ ] No change to authorization, society data, API identifiers or SarvoAI enablement is bundled into this work.
