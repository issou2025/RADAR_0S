## Problem Statement

To say anything to a Session, the user has to type into a terminal. The plan of record (Phase 4,
#387/#403) is to put SwiftTerm's `LocalProcessTerminalView` in the Dock and let the user drive the
agent through it. That means the cockpit's primary input surface is a terminal emulator: no
attachment affordance, no send button, no draft that survives a glance away, no way to queue a
second thought while the first is running, and a visual register that belongs to a different
application than the one around it.

It is also redundant. Argo already reads everything the agent does from the transcript — the feed
is built from `TranscriptReader`, never from terminal output. The terminal is therefore not an
observation surface at all. It is an *input device* that happens to also draw a picture of what
Argo has already parsed and rendered better.

Three things make the obvious fix — go headless and use a real protocol — the wrong one:

1. **Billing.** Since ~2026-07-10 Anthropic bills programmatic Claude usage separately from
   interactive. The Agent SDK (TypeScript and Python), `claude -p`, GitHub Actions and third-party
   Agent-SDK apps form one group drawing a capped monthly credit at API rates, and stop when it is
   spent. Only **interactive Claude Code in a terminal** draws the subscription allowance. Argo
   must run on subscription-included tokens.
2. **Permission.** `codex exec` closes stdin and cannot surface approvals at all; a `never` policy
   simply fails the operation back to the model. A cockpit that cannot answer a Permission does not
   lose a feature — the Session stalls against a prompt nobody can see.
3. **Codex differs from Claude.** Codex splits on *auth method* (ChatGPT sign-in vs API key), not
   on surface, so its headless mode is billing-safe where Claude's is not.

So the two CLIs cannot share one transport, and neither can use the clean headless one.

## Solution

A **composer** — an ordinary multi-line text field with an attachment affordance and a send
control — becomes the way the user speaks to a Session. The terminal disappears from the Session
experience entirely.

Behind it, a single **session-drive port**: one protocol the cockpit talks to, with one adapter per
`cli`. Each adapter picks whichever CLI surface keeps included tokens *and* can raise a Permission:

- **`claude`** — the real interactive TUI in a PTY Argo owns, **never rendered**. Hidden is not
  headless: the process is interactive, so it bills as interactive, while the user sees a composer.
  Input arrives by bracketed paste; a `PreToolUse` hook Argo installs carries Permission.
- **`codex`** — Codex's own programmatic server surface, which is billing-safe under ChatGPT
  sign-in, with approvals routed back to the cockpit.

The feed is unchanged. `TranscriptReader` already serves both CLIs and is the source of everything
the user reads; this work adds a write path beside it and touches nothing on the read path.

A **Permission** raised by either adapter surfaces in the cockpit as a first-class blocking state:
the Session shows *needs input* and holds there until the user answers, exactly as an agent UI
should.

SwiftTerm survives — the visible `LocalProcessTerminalView` is re-pointed at the agent-less
**scratch Terminal** in the Code room (#274), which is the one place a real terminal is still the
right answer.

## Implementation Decisions

- **One new seam: a `SessionDriver` protocol in `ArgoEngine`.** The cockpit-facing contract is
  `send(turn)`, `attach(file)`, `interrupt()`, an `AsyncStream` of pending Permissions, and
  `decide(id, decision)`. Permission travels on the same protocol rather than a second one, so the
  cockpit has exactly one thing to talk to. Everything below — bracketed paste, the hook socket,
  the MCP client — is invisible above the seam. Recorded as ADR-0024.
- **Two conformances, one per `cli`.** A Claude adapter owning a hidden interactive PTY, and a
  Codex adapter driving Codex's programmatic server surface. The existing `SwiftTermProcessHost`
  is the Claude adapter's PTY host; it is reused, not replaced.
- **Observation is not on this port.** `TranscriptReader` and the projection layer are untouched.
  This work adds a write path only.
- **`send` on the Claude adapter uses bracketed paste** (`ESC[200~ … ESC[201~`) followed by a
  carriage return. Without the paste framing each newline submits separately, which is the whole
  multi-line story.
- **`interrupt` on the Claude adapter is `ESC` to the PTY.** Verified: it stops a running Turn,
  leaves the process alive, and the transcript records `[Request interrupted by user]` as its own
  entry — so the interrupt is observable from the feed, not only from the PTY. The composer must
  be cleared afterwards or leftover text concatenates onto the next turn.
- **`attach` differs by adapter and that is deliberate.** Claude receives a path: Argo writes the
  file into the Workspace and injects its absolute location, and the agent's own `Read` pulls it
  in, which puts the bytes in the transcript at the point the agent looked. Codex receives content
  through its tool call. Both remain DERIVED at the feed.
- **Permission on Claude is a `PreToolUse` hook Argo owns.** The hook receives the tool name and
  input, blocks, and calls back to Argo over a local socket; the cockpit raises the Permission and
  the answer returns as the hook's `permissionDecision`. The hook must return `allow` or `deny` and
  **never `ask`** — `ask` falls through to the hidden TUI's own dialog, which has no reader.
- **The hook's `timeout` is the cockpit's patience window.** A blocked hook is what holds the UI on
  *needs input*, so that value is chosen deliberately rather than left at its default. Verified
  behaviour on expiry: the tool comes back an error, the Turn ends cleanly, and the agent asks in
  prose — it fails closed, with no silent fall-through and no stall.
- **Permission on Codex must impose its own deny-on-timeout.** Codex's server hangs indefinitely if
  the client never replies (openai/codex#11816), so the adapter cannot rely on the CLI to fail
  closed the way Claude's hook does.
- **Both Permission paths are DIRECT.** Argo owns the channel and the decision at both ends. This
  is the tier `CONTEXT.md` already assigns Permission — no new tier, only a second source for an
  existing one.
- **`CLAUDE_CODE_CHILD_SESSION` is scrubbed from the spawn environment.** Inheriting it silently
  disables transcript persistence, which would kill the feed with no error anywhere.
- **Mode maps to the CLI's standing permission stance**, and remains distinct from Permission. A
  baseline stance is required so ungated tools do not pay a round trip per call.
- **The visible terminal is re-pointed, not deleted.** `LocalProcessTerminalView` in the single
  `NSViewRepresentable` becomes the scratch Terminal in the Code room (#274). Sessions get the
  hidden PTY and the composer; the Dock no longer hosts a Session terminal.
- **Adapter capability is declared, not discovered at the point of use.** The composer asks the
  adapter what it supports and omits affordances that cannot work, rather than offering them and
  failing.

## Testing Decisions

A good test here asserts **external behaviour at the seam** — what the cockpit can observe and what
a driven CLI actually did — never the shape of the bracketed-paste bytes or the socket framing.
Prior art is the table-driven `swift-testing` suites in `ArgoEngineTests` (for example
`EvidenceTests`), which assert a projection's output and the byte-exact preservation of its
evidence; the same style applies.

- **`SessionDriver` conformance suite.** One table-driven suite run against every adapter, plus an
  in-memory fake: a sent turn arrives once and whole; multi-line text is one turn; an interrupt
  stops the Turn and leaves the Session usable; a Permission appears on the stream and `decide`
  resolves it; an unanswered Permission resolves to denied. This is the highest seam and carries
  most of the value.
- **Cockpit tests use the fake.** Composer state, draft persistence, queueing, *needs input*
  rendering, and roster propagation are tested against the in-memory conformance with no CLI
  launched, so they stay fast and deterministic.
- **Claude adapter integration tests** against the real CLI, marked as such so they can be excluded
  from the default run: the bracketed-paste round trip, `ESC` interrupt with the transcript
  entry as the assertion, the hook allow path, and the hook timeout denying.
- **Feed regression.** Existing transcript fixtures must produce identical projections before and
  after, proving the read path was not touched.
- **Environment scrubbing** is asserted directly: a spawned Session writes a transcript even when
  the parent environment carries `CLAUDE_CODE_CHILD_SESSION`.
- **No PTY leaks.** A test that spawns and tears down Sessions asserts no surviving child
  processes.
- **Codex adapter tests are gated on the adapter working at all** — see Further Notes. Until the
  approval round trip is demonstrated, the Codex conformance runs against the fake only, and that
  gap is stated rather than papered over.
- Visual states (composer, attachment chips, Permission prompt, *needs input*) get `Specimen` cases
  and are rendered before the PR, per the repo's visual verification rule.

## Out of Scope

- Any headless transport for `claude` — `claude -p`, the Agent SDK in either language, and
  GitHub Actions are all on the metered side of Anthropic's billing line and are excluded by the
  subscription constraint, not by preference.
- Changing the feed, the transcript parser, the projection layer, or the domain model.
- Rendering a Session terminal anywhere in the cockpit. The scratch Terminal in the Code room
  (#274) is separate work and keeps the visible view.
- Voice / Concierge input (ADR-0007, unbuilt).
- Gate — Argo's own automation policy for Delivery steps — which is a different actor and axis
  from Permission and is untouched here.
- Steering a Session Argo did not spawn. External Sessions stay read-only.
- Re-establishing steering for an orphaned Session; the channel dies with the owning process
  (ADR-0016 unchanged).
- A third CLI adapter.
- Provider-side usage accounting or spend display.

## Further Notes

**Verified on 2026-08-10** against `claude` 2.1.226: long-lived multi-turn input, image handling,
transcript persistence with embedded bytes, the `PreToolUse` hook round trip blocking on an
external decision, hook-timeout-denies, and `ESC` interrupting a running Turn with the session
surviving and the transcript recording it.

**The Codex adapter is the open risk and should be treated as unproven.** `codex mcp-server` exists
and exposes `codex` / `codex-reply` with `approval-policy` and `sandbox` arguments, but no approval
elicitation could be observed across three configurations (default, `mcp_servers={}`, and a fully
isolated `CODEX_HOME`): every `tools/call` stalled after `session_configured`. The server's
`initialize` reply advertises only `capabilities: {tools: {listChanged: true}}` — it declares no
elicitation capability, and approvals appear to travel as `codex/event` notifications rather than
MCP `elicitation/create`. This matches the known defects (openai/codex#18268, #11816, #23383).
`codex app-server` is the next thing to try. Until a Codex approval round trip is demonstrated,
the Claude adapter should ship first and the Codex one should not be assumed.

**This billing rule is volatile.** It changed three times between February and July 2026 (ban →
split → pause → reinstate) and Anthropic has said it is being reworked. That volatility is the
reason for the port: when it changes again, the change is one adapter rather than a cockpit
rewrite. Verify the current state against the account before relying on the rationale above.
