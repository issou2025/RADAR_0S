## Goal (user story)
As a user with a Google account, I tap "Continue with Google", pick my account, and I'm signed in on iOS and Android. That includes the Play-signed store build, not only development builds.

## Current state (verified, file:line)
- **Flutter** (the functional reference only): there's no Google sign-in. Its ids `com.maybesitter.maybesitter_mobile` (`mobile/android/app/build.gradle.kts:19`) and `com.maybesitter.maybesitterMobile` aren't the launch id, and its release build is debug-signed (`build.gradle.kts:32`).
- **React Native:**
  - `mobile-rn/` uses `com.maybesitter.app` on both platforms (UC-1.R1 (#154)).
  - The Android signing keys are EAS-managed (UC-1.6a (#150)), and Play App Signing re-signs the store build with a Google-held key. Each key that signs an installable build needs its SHA fingerprints registered.
  - UC-1.7 (#151) adds Firebase, the committed `mobile-rn/firebase/google-services.json` / `GoogleService-Info.plist`, `AuthRepository` and the button slot.
- `@react-native-google-signin/google-signin` docs:
  - `GoogleSignin.configure({ webClientId })` must run once before any other call.
  - `signIn()` returns the user and an `idToken`, and `addScopes()` requests more scopes later.
  - The Expo config plugin needs `iosUrlScheme` only when Firebase isn't used; with Firebase, it reads the reversed client ID from the Google services plist.

## Implementation steps
1. **Firebase console** → Authentication → Google → Enable.
   - Public-facing name: "MaybeSitter".
   - Support email (owner step): a Google account or Google Group the owner controls, the same one as the UC-1.8 (#152) branding. Don't write it in the repo or in issues.
   - Firebase creates a **Web** OAuth client (client_type 3). Its client ID is the `webClientId` below.
2. **Register SHA-1 and SHA-256** for every signing key. A missing one gives `DEVELOPER_ERROR` (code 10).
   - The EAS keystores used by the `development`, `staging` and `production` profiles: `eas credentials -p android` shows the fingerprints.
   - Local `npx expo run:android` builds, signed with the prebuild debug keystore: `keytool -list -v -keystore mobile-rn/android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android`.
   - The Play App Signing key: Play Console → App integrity → App signing (available after the first internal-track upload, UC-1.6a (#150)).
   - Add them all under Firebase → Project settings → Android app `com.maybesitter.app`. Re-download `google-services.json` into `mobile-rn/firebase/` and commit it. Add the SHA-1s to the Android API-key restriction (UC-1.7 (#151) step 2).
3. **Install and plugin:** `npx expo install @react-native-google-signin/google-signin`, then add `'@react-native-google-signin/google-signin'` to `plugins` in `app.config.ts`.
   - Check the prebuild `Info.plist` for a `CFBundleURLSchemes` entry equal to `REVERSED_CLIENT_ID`, next to the existing `maybesitter` scheme.
   - If the installed version doesn't derive it from `ios.googleServicesFile`, pass `{ iosUrlScheme: '<REVERSED_CLIENT_ID>' }`. This is a public identifier.
4. **Config:** add `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` as an EAS env var for all profiles (UC-1.6a (#150) step 5) and as a placeholder in `mobile-rn/.env.example`. `env.ts` reads it as optional.
   - **Decision:** when it's empty, hide the Google button, and in `__DEV__` log why.
5. **One-time init:** `src/auth/googleSignIn.ts` exports `configureGoogleSignIn()`, called once from `app/_layout.tsx` before the first render: `GoogleSignin.configure({ webClientId: env.googleWebClientId })`.
6. **`signInWithGoogle()`** in `firebaseAuthRepository.ts`:
   ```ts
   await GoogleSignin.hasPlayServices({ showPlayServicesUpdateDialog: true }); // no-op on iOS
   const res = await GoogleSignin.signIn();
   if (res.type === 'cancelled') return;
   const idToken = res.data.idToken;
   if (!idToken) throw new AuthFailure('generic');
   await signInWithCredential(getAuth(), GoogleAuthProvider.credential(idToken));
   ```
   - `signOut()` also calls `GoogleSignin.signOut()`, so the account chooser shows next time (UC-1.7 (#151) step 8).
   - **Decision:** ask for no Google API scopes at sign-in. Calendar access is requested later with `GoogleSignin.addScopes({ scopes })` (the UC-1.8 (#152) demo, then UC-3.3 (#187)).
7. **Errors** in `src/auth/authErrorCopy.ts`, localized:
   - `statusCodes.SIGN_IN_CANCELLED` → silent.
   - `statusCodes.IN_PROGRESS` → ignore the second tap.
   - `statusCodes.PLAY_SERVICES_NOT_AVAILABLE` → "Google Play services are needed for Google sign-in. Use Apple or email instead."
   - `DEVELOPER_ERROR` → the generic copy, plus a `__DEV__` warning naming a missing SHA fingerprint as the likely cause.
   - `auth/account-exists-with-different-credential` → the same copy as UC-1.1 (#145).
   - `auth/network-request-failed` → `errors.network`.
8. **UI:** "Continue with Google", following Google's branding guidelines. Take the official "G" mark from Google's branding kit and save it as `mobile-rn/assets/icons/google-g.svg`, rendered with `react-native-svg`. Place it directly **below** the Apple button at the same size (guideline 4.8).
9. **Docs:** add a "Google Sign-In troubleshooting" section to `mobile-rn/README.md`: where each fingerprint comes from, and the code-10 checklist.
