# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**feat(ui): prompt the player to reload when a new build is deployed**

*Project description:*
Found while implementing #76 (QE-8). Evidence and measurements:
[`docs/quality/sw-update.md`](docs/quality/sw-update.md).

## Problem

A player with the game open never learns that a new build has been deployed.

Measured on production (2026-10-23):

- GitHub Pages serves **every** asset with `cache-control: max-age=600`,
  including `version.json`, `flutter_service_worker.js` and `main.dart.js`.
- Flutter 3.47's generated `flutter_service_worker.js` (784 bytes) caches
  nothing. It calls `skipWaiting()`, then **unregisters itself** on activate and
  reloads its clients. There is no service worker left to check for updates.

So there is no out-of-band update channel. A client can serve a superseded build
for up to 600 s, and a tab left open is on the old build indefinitely — nothing
prompts it to reload. `test/quality/sw_update_check.py` proves this: after a
deploy, a normal reload reports `transferSize: 0` for `main.dart.js` (no network
request at all) while the server already serves the new build.

The only user-side escape hatch is a hard reload, which nobody will guess.

## Proposed

Show an in-app prompt ("A new version is available — Reload") when a newer build
is deployed, with a `Reload` action.

## Constraints (from the measurements)

- `version.json` already ships in the build output with `app_name`, `version`
  and `build_number`. No new build step is needed.
- Any poll of `version.json` **must bypass the HTTP cache**
  (`cache: 'reload'` or `'no-store'`). With the default policy it reads a
  ten-minute-old answer and the prompt would fire ten minutes late — or never.
- The prompt cannot rely on a service worker; there is none.
- Polling must be cheap and must not disturb a game in progress. Suggested:
  check on the start screen and on a timer while idle, never mid-shot.

## Acceptance criteria

- [ ] When a newer `version.json` is deployed, an open client shows an update
      prompt within a bounded time
- [ ] The prompt never appears while a game is in progress
- [ ] Activating the prompt loads the new build (a reload that bypasses the
      cache, not a plain `location.reload()`)
- [ ] The poll bypasses the HTTP cache — verified against `max-age=600`
- [ ] Dismissing the prompt does not re-show it until a further deploy

## Out of scope

- Changing GitHub Pages' cache policy (not under our control).
- Re-introducing a caching service worker.
