## Summary

The SquareDesk 1.2.1 macOS app bundle is **~450 MB on disk** (173 MB as a DMG). About two-thirds of that is Qt WebEngine (Chromium). Everything is already arm64-only and stripped, so the size comes from the components we ship, not from build settings.

## Why WebEngine is in the bundle

`QWebEngineView` is used for four things:

1. **Taminations**: `mainwindow_taminations.cpp` loads the Flutter app from the local `QHttpServer`.
2. **Cuesheets/lyrics in `.txt` / `.htm` / `.html`**: `mainwindow.cpp`, around line 5838.
3. **Markdown lyrics**: converted to HTML via `markdownToHTMLlyrics()` and passed to `setHtml()`.
4. **PDFs**: displayed through the bundled pdf.js viewer (`Resources/minified/web/viewer.html`).

Only #1 needs a full browser engine (Flutter web needs WebAssembly and a modern JS engine).

## Proposed changes

### Phase 1: Trim the bundle, keep WebEngine (saves ~60–80 MB, low risk)

Post-deploy steps in `deploy_macos.pri`:

- [ ] Delete every `qtwebengine_locales/*.pak` except `en-US.pak` (**−44 MB**)
- [ ] Delete `qtwebengine_devtools_resources.pak` unless the web inspector is needed (**−11 MB**)
- [ ] Delete Taminations `*.js.symbols` files (**−8 MB**)
- [ ] Investigate deleting CanvasKit variants Chromium never loads (**−15–20 MB**; test first, since Flutter picks a renderer at runtime)
- [ ] Delete unused Qt plugins: `platforminputcontexts/libqtvirtualkeyboardplugin`, `position/*`, unused `imageformats/*`, unused `tls` backends

### Phase 2: Remove WebEngine entirely (bundle → ~100–150 MB)

- [ ] **PDFs**: replace pdf.js + WebEngine with `QPdfView` (QtPdf is already in the bundle), then drop `Resources/minified`
- [ ] **txt / md / simple HTML cuesheets**: replace with `QTextBrowser` (native HTML subset + Markdown). Test against real cuesheets for CSS fidelity.
- [ ] **Taminations**: open it in the user's default browser with `QDesktopServices::openUrl()`, pointed at the existing local `QHttpServer`. Trade-off: Taminations is no longer an in-app tab.
- [ ] Remove `webenginewidgets` from `QT +=` in `test123.pro`, and confirm the Quick/QML/Positioning/WebChannel/VirtualKeyboard frameworks drop out of the deployed bundle

## Notes

- Phase 2 would likely also reduce RAM use and startup time substantially (Chromium runs a separate helper process), but those haven't been measured yet.
- For comparison: the Rust "Crafting Apps" (e.g. SoundCraft, a full DAW) ship well under 100 MB, mostly because they bundle no browser engine.
