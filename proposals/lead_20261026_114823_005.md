### Description

Since `firebase_in_app_messaging` 0.10.0, any Flutter Android app that depends on the plugin fails to build. Gradle cannot resolve the app's `debugCompileClasspath` because `com.google.firebase:firebase-inappmessaging` and `com.google.firebase:firebase-inappmessaging-display` are requested **without a version**.

**Expected:** `flutter build apk` succeeds on a freshly created app with only `firebase_core` and `firebase_in_app_messaging` added (as it does with 0.9.4).

**Actual:** The build fails with `Could not find com.google.firebase:firebase-inappmessaging:.` / `Could not find com.google.firebase:firebase-inappmessaging-display:.`

#18586 changed the plugin's `android/build.gradle` to expose the Firebase artifacts as `api`, while the Firebase BoM is still declared as `implementation platform(...)`:

```groovy
dependencies {
  api firebaseCoreProject
  implementation platform("com.google.firebase:firebase-bom:${getRootProjectExtOrCoreProperty("FirebaseSDKVersion", firebaseCoreProject)}")
  // `api` so app Java compilation can resolve FirebaseInAppMessagingDisplay,
  // which the plugin class implements.
  api 'com.google.firebase:firebase-inappmessaging'
  api 'com.google.firebase:firebase-inappmessaging-display'
  implementation 'androidx.annotation:annotation:1.7.0'
}
```

The versionless `api` dependencies are exported to the consuming app's compile classpath, but the BoM is an `implementation` dependency, so its version constraints are not. As a result, the app sees `firebase-inappmessaging` and `firebase-inappmessaging-display` with an empty version.

Results with Flutter 3.47.8 (AGP 9.1.0, Gradle 9.3.1, KGP 2.4.0):

| firebase_in_app_messaging | firebase_core | Kotlin app (`flutter create`) | Java app (`flutter create -a java`) |
| --- | --- | --- | --- |
| 0.9.4 | 4.15.2 | ✅ builds | ✅ builds |
| 0.10.0 | 5.1.0 | ❌ fails (`:app:processDebugResources`) | ❌ fails (`:app:processDebugResources`) |
| 0.10.1 | 5.1.0 | ❌ fails (`:app:compileDebugKotlin`) | ❌ fails (`:app:processDebugResources`) |

**Workaround:** add the Firebase BoM to the app module:

```kotlin
// android/app/build.gradle.kts
dependencies {
    implementation(platform("com.google.firebase:firebase-bom:35.1.0"))
}
```

### Reproducing the issue

1. `flutter create --platforms android iam_repro`
2. `cd iam_repro`
3. `flutter pub add firebase_core firebase_in_app_messaging` (resolves `firebase_core` 5.1.0, `firebase_in_app_messaging` 0.10.1)
4. `flutter build apk --debug`

No Dart code changes or `google-services.json` are needed to reproduce; the failure happens while Gradle resolves dependencies.

### Additional context and comments

Possible fix:

- Revert `firebase-inappmessaging` and `firebase-inappmessaging-display` to `implementation` (as in 0.9.4), so they are not exported to the app.
- Stop having `FirebaseInAppMessagingPlugin` implement `FirebaseInAppMessagingDisplay` directly, and instead set a private property (for example, a lambda) as the display component, so the plugin class's public API no longer references Firebase In-App Messaging types and the app can compile `GeneratedPluginRegistrant` without them.
