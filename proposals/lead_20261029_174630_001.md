# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Node model like IFCX: one row per object, relations as columns**

*Project description:*
The first `BimDataFrame` has one row per element, with instances expanded so every element carries its own mesh in model coordinates. Elements without geometry are rows too, with a null mesh.

Later, the frame could follow the node model of IFC5's IFCX format instead: one row per object, not per element.

## What changes

- **Every object is a row.** This covers elements with and without geometry (site, building, storeys, rooms, groups, type objects), but also geometry-only objects such as display meshes and instance definitions. `class` is null for geometry-only rows; `mesh` is null for rows without geometry.
- **Relations become columns.** `children` (list of ids), `display` (ids of the geometry rows an element shows), and `definition` + `transform` for instances. This mirrors IFCX's `children` and `inherits`, and `explode` turns any of them into an edge table for joins.
- **Instances stay instances.** A mesh is stored once and referenced with a transform. A function such as `resolve_geometry(frame)` composes world-coordinate meshes per element when simple features, a viewer or glb export need them.

## Why

- IFCX is a flat list of nodes, each with a path, `children`, `inherits` and namespaced attributes (`bsi::ifc::class`, `usd::usdgeom::mesh`, a transform, properties). A node needs none of them. A frame shaped like this reads and writes IFCX with little translation.
- Speckle v3 is the same: DataObjects, Collections, Meshes and instance definitions are objects that reference each other by id. A Speckle bundle already stores this as `envelope.nodes` and `envelope.relations` plus the eav properties.
- In the Revit advanced sample (arch), 5,817 instances would no longer copy their definition meshes.
