### What happened?

Phone remote-access setup fails silently and only recovers with manual steps: turn "Remote access on this phone" off and on at home, then force-quit and reopen the app. Brandon hit this on his iPhone with v0.55.0, and nothing merged since then fixes the flow. Per Brandon's standing rule, setup and recovery should be handled **in code first**, with a clear in-app explanation only where code can't fix it. Users should never need manual steps. Related: #3612 (iPhone never pairs), #3613 (diagnostics), #3611 (fixed by #3622). This ticket is the end-to-end fix for the flow. Checked at main c0f4eef (v0.56.2).

**Problems in the code today:**
1. A pairing refusal is silent. A 409 is dropped and a 503 retries quietly (`lib/controllers/connection_controller.dart:420-427`).
2. The phone can get stuck with a pairing but no connection. If it saves the pairing but its connection fails to start, the error is only logged (`:403-414`). The phone then has a stored pairing with nothing to start from (`embedded_tunnel_io.dart:158-160`), and it never pairs again because a pairing exists (`:375`). This is the likely cause of the toggle-and-restart workaround.
3. When the box rejects the phone's key, re-pairing waits until the next visit home (`:360-368`).
4. The "Remote access on this phone" switch shows on even when the phone never paired (`this_phone_card.dart:32`).
5. Away from home with no pairing, the phone shows only the generic "can't reach your Quark" screen (`:264-278`).
6. A leftover comment at `connection_controller.dart:339-341` still says "this build does not offer it yet".

**Expected (acceptance criteria):**
- [ ] When the stored pairing can't start a connection, the app throws it away and pairs again automatically on the next home Wi-Fi check. No toggle and no restart needed.
- [ ] A rejected key causes an immediate re-pair while the phone is on home Wi-Fi, instead of waiting for the next visit.
- [ ] 409 and 503 refusals show the user a plain-language status with the next step. Examples: "Your Quark is full on remote devices" or "Your Quark isn't connected to remote access yet. We'll keep trying."
- [ ] The phone switch and card show the real state: not set up yet, setting up, ready, or not working, with the reason.
- [ ] Away from home with no pairing, the app says "Open Quark once on your home Wi-Fi to finish setting up remote access" instead of the generic error.
- [ ] Changes that currently need a restart take effect without one. If a restart is truly unavoidable, the app says so.
- [ ] Each step is logged in a way the #3613 diagnostics can show.
- [ ] Tests cover each of the failure paths above.
- [ ] No vendor names in UI text.
