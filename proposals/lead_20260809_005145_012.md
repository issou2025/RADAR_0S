## Problem Statement

The user currently orchestrates a document-to-workbook data migration by hand. In the original workflow (run as two Cowork conversations over the "7) Practicum Courses" sheet: 39 rows, 777 cells, 144 source files across 11 program folders), the user had to: hand source folders + rules + workbook to a filling agent, answer its scoping questions mid-conversation, collect the draft workbook + handoff + provenance, hand everything to an independent QA reviewer, ferry the review findings back to the filler for revision, adjudicate rebuttals, and manually finalize.

This manual orchestration is slow, non-repeatable, and unsafe by convention only: agents edit the workbook directly, nothing enforces that PASS cells stay frozen, provenance stays in sync, or that an interrupted run can resume without duplicating writes.

## Solution

A local-first CLI workflow engine that automates the orchestration while treating Claude Code and Codex as full agent runtimes (never rebuilding their inner agent harness). The user runs one command with a source folder, an Excel workbook, and rule files. The engine then:

1. Inventories the source workspace into a hashed manifest (unsupported/encrypted/corrupt files flagged, never silently dropped).
2. Runs a Claude Code **scoping pass** that emits only a question list (row granularity, program/period mapping, scope completeness), pauses the workflow, and resumes after the user edits an answers file. Skipped when answers are pre-provided.
3. Runs the Claude Code **Filler**, which returns structured cell proposals with evidence, confidence, and status — it never touches the workbook.
4. Validates proposals deterministically (Pydantic + hardcoded rules) and writes only authorized cells to a draft workbook via openpyxl, recording cell-level provenance.
5. Renders a bilingual (EN/ZH) single-file offline **review explorer** from the draft + provenance.
6. Runs the Codex **Reviewer** (read-only sandbox, different vendor by design) under a configurable review policy (strict fields, confidence-stratified sampling, completeness audit), producing PASS/WARN/FAIL/UNRESOLVED findings.
7. Routes only non-PASS findings to Claude Code **Revision** (PASS cells frozen; explicit confirmation-bias mitigation; actions ACCEPT/FIX/REBUT/CLEAR/NO_CHANGE/UNRESOLVED, with an optional `note_append` companion edit into the row's Notes cell).
8. Applies authorized revisions deterministically, then runs **exactly one** Codex targeted re-review round over rebutted cells (WITHDRAWN closes the finding; UPHELD escalates to UNRESOLVED).
9. Emits human-review artifacts for anything still unresolved, regenerates the review explorer (v2), and finalizes the workbook plus a full audit trail (SQLite + JSON artifacts).
10. Supports `resume` after interruption without duplicating workbook mutations, with lenient retries (2x, then UNRESOLVED).

## User Stories

1. As a workflow operator, I want to start a full run with one CLI command pointing at a source folder, a workbook, and rule files, so that I no longer ferry materials between agents by hand.
2. As a workflow operator, I want the engine to copy inputs into a per-run workspace and never modify my original files, so that a bad run cannot damage source material.
3. As a workflow operator, I want a hashed file manifest that flags UNSUPPORTED/ENCRYPTED/CORRUPT files instead of silently skipping them, so that I know exactly what the agents could and could not read.
4. As a workflow operator, I want the Filler to first ask me scoping questions (row granularity, program mapping, "is this folder set complete?") and pause until I answer, so that a first run on a new dataset does not produce a wrongly-structured sheet.
5. As a workflow operator, I want the scoping pause to be skipped when I pre-provide the answers file, so that re-runs on known datasets go straight through.
6. As a workflow operator, I want my scoping answers recorded in the audit trail, so that structural decisions are traceable to me, not to agent guesses.
7. As a data steward, I want every filled cell backed by a structured proposal with evidence citations, an evidence-type tag, and a confidence score, so that no value enters the workbook unsupported.
8. As a data steward, I want the Filler to distinguish not-found vs ambiguous vs conflicting instead of guessing, so that uncertainty is visible rather than hidden in plausible-looking values.
9. As a data steward, I want constructed fields (assembled IDs) and mapped fields (controlled-vocabulary judgments) capped at medium confidence, so that all subjective values are forced into review sampling.
10. As a data steward, I want deterministic validation (required fields, controlled vocabularies, ID patterns, date formats, types) to run before any write, so that rule compliance does not depend on agent discipline.
11. As a data steward, I want only Python — never an agent — to mutate the workbook, and only on allowlisted cells, so that workbook safety is enforced by code rather than by prompt.
12. As an auditor, I want cell-level provenance (source file, location, evidence text, evidence type, rules applied, confidence, actor, run id) for every AI-written value, so that any cell can be traced to its sources years later.
13. As an auditor, I want web-sourced evidence tagged `external_web` and never silently mixed with archival evidence, so that the provenance trail distinguishes archive facts from internet facts.
14. As a data steward, I want a handoff report summarizing processed sources, unreadable files, confidence distribution, ambiguities, conflicts, and areas needing extra review, so that the reviewer and I know where to look first.
15. As a human reviewer, I want a bilingual (EN/ZH) single-file offline review explorer rendered directly from the draft workbook and provenance — folder sidebar with row navigation and merged-folder jump links, an overview page with archival findings and a master table, per-row detail with per-cell provenance and collapsed empty fields, and full-text search with highlighting — so that I can inspect all rows and citations without opening Excel or trusting a hand-made page.
16. As a data steward, I want an independent Reviewer running on a different vendor (Codex) with read-only access, so that verification is adversarial rather than self-graded.
17. As a data steward, I want review depth driven by configuration (strict fields always verified, low confidence fully verified, medium prioritized, high spot-checked, plus a folder completeness audit for missed data), so that review effort is a policy I control, not agent whim.
18. As a data steward, I want every non-PASS finding to state what is wrong, what evidence was checked, and a recommended correction when determinable, so that findings are actionable.
19. As a data steward, I want Revision to receive only non-PASS findings with PASS cells frozen, so that verified values can never regress during correction.
20. As a data steward, I want Revision to re-verify against re-opened original sources and respond to every finding with ACCEPT/FIX/CLEAR/REBUT plus evidence and justification, so that corrections are as accountable as the original fill.
21. As a data steward, I want a CLEAR action to optionally move explanatory prose into the row's Notes cell (`note_append`) in the same authorized mutation, so that cleaning a data field does not destroy sourced context.
22. As a data steward, I want exactly one targeted re-review round where Codex re-examines only rebutted cells and returns WITHDRAWN or UPHELD, so that rebuttals get independent adjudication without an unbounded dispute loop.
23. As a workflow operator, I want everything still unresolved (including upheld rebuttals) exported as human-review artifacts showing the cell, current value, competing interpretations, both agents' arguments, and why automation stopped, so that my manual decisions are quick and informed.
24. As a human reviewer, I want the review explorer regenerated after revisions (v2), so that what I browse always matches the final workbook exactly.
25. As a workflow operator, I want `workflow resume` to continue an interrupted run from its last checkpoint without duplicating workbook mutations, so that a crash or laptop sleep does not corrupt the workbook or waste completed agent work.
26. As a workflow operator, I want transient failures retried up to twice and then converted to UNRESOLVED rather than aborting the run, so that one flaky call cannot kill a long run.
27. As a workflow operator, I want stage-level progress on stderr (files found, proposals count, verdict counts, revision actions), so that I can tell what a long-running workflow is doing.
28. As an auditor, I want an SQLite audit trail of runs, stages, mutations (old/new value, actor, source proposal), and findings, so that every workbook change is queryable.
29. As a privacy-conscious operator, I want no hidden model chain-of-thought logged — only structured operational data — so that audit artifacts are safe to share.
30. As a subscription user, I want the engine to prefer subscription auth (Codex `auth.json`, Claude OAuth with API-key env vars cleared), warn when it cannot verify, and never silently fall back to API billing, so that runs do not surprise me with usage charges.
31. As a workflow operator, I want per-role web-access configuration (default ON) so that I can run archive-only tasks (as the original workflow required) by switching a config flag.
32. As a developer, I want fake agent runtimes that replay fixture JSON through the entire engine, so that I can develop and test every deterministic behavior without spending agent quota.
33. As a developer, I want runtime-specific invocation isolated behind an adapter protocol, so that CLI changes in Claude Code or Codex touch one module only.
34. As a data steward, I want a labeled benchmark from manually verified historical work evaluating accuracy, unsupported-fill rate, missed-data rate, provenance coverage, and review effectiveness, so that I can trust the engine before using its output.

## Implementation Decisions

- **Two harness layers.** Claude Code and Codex keep their inner agent harness (planning, file tools, search, optional native subagents — allowed, never forced). The application owns only a thin deterministic outer harness: state machine, role contracts, validation, workbook mutation, provenance, routing, retries/resume, audit, termination.
- **Stack.** Python ≥ 3.12 managed with uv; thin LangGraph for orchestration with SqliteSaver checkpoints; Pydantic/JSON Schema contracts; openpyxl for all workbook access; SQLite for audit; JSON/JSONL as authoritative machine artifacts with Markdown/HTML renderings for humans.
- **Roles and vendors.** Filler and Revision run on Claude Code (`claude --print --json-schema`); Reviewer and the targeted re-review run on Codex (`codex exec --output-schema`, `--sandbox read-only`) — cross-vendor by design for adversarial verification. Each invocation is self-contained; no reliance on conversational memory; all context passes as explicit artifacts.
- **Two-phase Filler.** First invocation returns only a scoping question list; the workflow pauses via a LangGraph interrupt; the user edits an answers file and resumes; answers feed the extraction invocation and the audit trail. The phase auto-skips when answers are pre-provided.
- **Data contracts.** `Evidence` (with `evidence_type` including `external_web`), `CellProposal` (status: proposed/not_found/ambiguous/conflict), `ReviewFinding` (verdict: PASS/WARN/FAIL/UNRESOLVED, `missed_data` flag), `RevisionDecision` (action semantics below, plus optional `note_append`), `ReReviewVerdict` (WITHDRAWN/UPHELD). Action semantics:

  ```text
  ACCEPT       adopt Reviewer's recommendation
  FIX          found a better correction independently
  REBUT        disagrees with Reviewer → one targeted re-review round
  CLEAR        clear cell value (correct value undeterminable)
  NO_CHANGE    PASS cells, no action needed
  UNRESOLVED   cannot determine correct action
  ```

- **Deterministic workbook boundary.** Agents propose; Python validates (Pydantic, then hardcoded rules), authorizes against a mutation allowlist, and writes. The revision allowlist automatically includes the Notes cell of every flagged row so `note_append` companion edits are always authorized. PASS cells are frozen. Cell addresses are stable within a run (no mid-run workbook edits assumed).
- **Bounded re-review.** REBUT triggers exactly one Codex re-review over rebutted cells only; it cannot mutate the workbook or add findings. WITHDRAWN keeps the original value and closes the finding; UPHELD escalates to UNRESOLVED and human fallback. No second rebuttal.
- **Confidence policy.** Numeric thresholds (low < 0.60 ≤ medium < 0.85 ≤ high) drive review sampling; constructed fields (format-assembled IDs) and mapped fields (controlled-vocabulary or judgment-scale values) are capped at medium.
- **Review policy is configuration** (YAML): strict fields, thresholds, high-confidence spot-check count per record group; the Reviewer must independently access sources and never trust the handoff.
- **Review explorer.** Rendered deterministically (no agent) from draft workbook + provenance JSON in EN and ZH variants; single self-contained offline HTML; folder sidebar with row navigation and merged-folder jump links; overview page (archival findings from the handoff + master row table with fill rates); per-row detail with Excel column letters, per-cell provenance chips, collapsed empty fields, and prev/next paging; full-text search with highlighting. Generated after the draft write and regenerated as v2 after revisions.
- **Workbook schema is hand-authored** configuration in V1 (sheets, writable columns, key fields, controlled vocabularies, references); no auto-detection.
- **Rules.** A small hardcoded deterministic rule set in V1 (required fields, controlled vocabulary, ID patterns, date formats, types); semantic judgments stay with agents via prompts.
- **Auth and network.** Subscription auth preferred: Codex via `auth.json` (runtime-enforced), Claude best-effort (API-key env vars cleared); the engine warns rather than fails when unverifiable, and never silently falls back to API billing. Web access defaults ON for all roles, per-role switchable; web evidence must be tagged `external_web`.
- **Resilience.** SqliteSaver checkpoints around agent calls; `resume` command; idempotent mutation application (per-run "already written" check); transient failures retried twice then marked UNRESOLVED; contradictory evidence and deterministic rule failures are never blindly retried.
- **Audit.** SQLite records runs (config, input hashes, auth mode, network policy), stages, mutations, findings, and runtime events; no hidden chain-of-thought is ever logged.
- **CLI first.** `workflow run` / `workflow resume`; stage progress to stderr; the engine package is UI-agnostic (desktop UI later must call the same package).

## Testing Decisions

- A good test asserts **external behavior only**: the artifacts a run produces, the cells a workbook ends up with, the routing decisions visible in outputs — never internal call sequences or module internals.
- **Primary seam (the only broad one): the workflow engine entry point with `FakeAgentRuntime` injected.** Integration tests drive `run`/`resume` end to end on fixture agent outputs and assert on: artifact presence and schema validity; only-allowlisted cells written; PASS cells untouched after revision; REBUT routing into exactly one re-review; scoping pause/skip behavior; resume idempotency (no duplicate mutations); UNRESOLVED and human-review artifact generation; explorer v1/v2 regeneration and content consistency with the workbook.
- **Secondary seam (deliberate exception): the deterministic workbook mutation layer**, unit-tested directly with hostile inputs (unauthorized cells, type violations, duplicate writes, allowlist edge cases) because its failure modes must be enumerated exhaustively and are safety-critical.
- No other seams: LangGraph node functions, prompt files, and runtime adapters are covered through the primary seam. Live `claude`/`codex` structured-output behavior gets separate smoke tests excluded from normal CI.
- Fixtures should be derived from the real Practicum Courses artifacts (handoff, QA review, revision log, provenance) so routing tests exercise realistic verdict/action distributions (e.g. a review round with 1 FAIL, multiple WARN, 7 rebuttals).
- No prior test art exists in this repo (greenfield); pytest is the chosen framework.

## Out of Scope

- Any custom inner agent harness: planners, tool-selection loops, subagent schedulers, context compaction, generic ReAct loops.
- Unbounded review/dispute loops (the single targeted re-review round is the ceiling).
- Docling or any preprocessing/normalization layer (manifest reserves a `normalized_path` field for later).
- Automatic workbook schema detection; config-driven rule engines; vector databases / custom RAG.
- Desktop UI (Tauri + React is V2, after the engine is trustworthy); cloud deployment; multi-user SaaS.
- Direct agent editing of the workbook, in any role.
- Interactive human-review UI (V1 human fallback is file-based: read `human_review.md`, edit `final.xlsx` manually).

## Further Notes

- The authoritative detailed reference is `project_plan_v3.md` (v3.1) in this repo, including its frozen architectural decisions (§44) and implementation guardrails (§49). This spec summarizes it; where they diverge, the plan wins.
- The design was validated against the artifacts of the original manual workflow (two Cowork conversations over the "7) Practicum Courses" sheet). The v3.1 amendments — scoping pause, bounded re-review, medium-confidence cap for constructed/mapped fields, `note_append`, and the bilingual review explorer — exist specifically to close the fidelity gaps found in that comparison.
