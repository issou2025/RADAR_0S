> **[All]** `-LiteralPath` stops wildcard expansion, but it does not make a backslash literal. The PowerShell FileSystem provider treats a backslash as a directory separator on every platform. If one is present, code **MUST** report the name instead of reading it through the provider. Preserve the original name; do not replace its literal backslash to make the check pass. Use forward slashes for directory boundaries in repository-relative names. When converting a native filesystem path to that form, replace only the platform directory separator, `[System.IO.Path]::DirectorySeparatorChar`, with `/`. On Linux and macOS, do not convert a literal backslash within a name to `/`.

This rule concerns raw external names and their representation, not a ban on native Windows path separators or intentional wildcard patterns. A Git name is already repository-relative; do not first rewrite its characters as if it were a native path. A checked valid path still follows the existing **Resolving Paths for .NET Static Methods** rule when it is passed to a .NET filesystem API.
