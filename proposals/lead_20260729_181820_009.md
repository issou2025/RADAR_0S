# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**PrivacyInfo.xcprivacy declares NSPrivacyCollectedDataTypePhotosOrVideos instead of the correct NSPrivacyCollectedDataTypePhotosorVideos**

*Project description:*
**Description of the new feature**

The bundled iOS privacy manifest (`ios/background_downloader/Sources/background_downloader/PrivacyInfo.xcprivacy`) declares a data-collection type as `NSPrivacyCollectedDataTypePhotosOrVideos` (capital "O", capital "V" in "Or"/"Videos"). Apple's actual enum value is `NSPrivacyCollectedDataTypePhotosorVideos` (lowercase "or"). Because the declared string doesn't match Apple's recognized constant, Xcode's Privacy Report tool (Product > Archive > Distribute App > Generate Privacy Report) can't map it to its proper category — it falls through to an "Additional Data" bucket as a raw, unresolved string instead of appearing under "User Content → Photos or Videos" alongside the app's own declarations.

**Describe how you'd implement it**

Fix the casing of the key in `PrivacyInfo.xcprivacy`:

```diff
- <string>NSPrivacyCollectedDataTypePhotosOrVideos</string>
+ <string>NSPrivacyCollectedDataTypePhotosorVideos</string>
```

That's the only change needed — the surrounding purpose (`NSPrivacyCollectedDataTypePurposeAppFunctionality`), tracking (`false`), and linked (`false`) values are already correct.

**Describe alternatives you've considered**

- **Leave it as-is** — rejected; consuming apps' aggregate Privacy Reports will keep showing this entry unresolved under "Additional Data," which makes it harder for app developers to reconcile their App Store Connect "App Privacy" answers against what's actually declared in the binary.
- **Have consuming apps override/patch the manifest locally** — rejected as a workaround; it's not persisted across `pod install`/`flutter pub get`, so every consumer would have to reapply it, whereas fixing it once upstream fixes it for everyone.

**Additional context**

Found while integrating `background_downloader` 9.5.2 into an iOS app and reviewing Xcode's Generate Privacy Report output against the package's other declared data types. Apple's full list of recognized `NSPrivacyCollectedDataType*` values is documented at https://developer.apple.com/documentation/bundleresources/privacy_manifest_files/describing_data_use_in_privacy_manifests — `PhotosorVideos` is the listed casing under "User Content."
