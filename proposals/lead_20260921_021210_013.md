# Project Proposal — Python Automation

## Project Understanding
You need assistance with: 
**[system] doctor and creds-check read one of four .env tiers, so live credentials read as missing**

*Project description:*
## Summary
The runtime resolves a credential across four `.env` tiers (host → root → fleet → bot). `claudlobby doctor` reads **one** of them, `claudlobby validate` reads **two**, and `lib/creds-check.sh` reads **one** — and all three reach for `Paths.env_file`, the property whose own docstring names that use as the #1226 defect. Any fleet that places a credential at `~/.env` — the tier the scaffolder itself suggests — therefore gets a health check that FAILs a working configuration and a daily credential check that reports a live token as undeclared. The fix is one rule enforced everywhere: every door reads the four-tier cascade through `paths.env_resolved()` / `env_tier_present_files` — the doors `credentials.py` and `start-bot.sh` already use — so a stranger's `doctor` matches a stranger's runtime by construction.

## Why this matters
`doctor` is the pre-flight gate a new operator is told to run. It reports a correctly configured fleet as broken, and `validate`'s remedy text ("add it at any tier … conventionally fleet") sends them to write a credential that already exists — which creates a second copy that then **shadows** the first, because the most specific assignment wins. That is a health check manufacturing the defect it exists to catch, on a fully supported configuration: `host` is a first-class tier (`claudlobby/known_values.py:137` — `ENV_TIERS = ("host", "root", "fleet", "bot")`, with only `root` marked deprecated at `:143`), and placing a credential at the one tier the registry does **not** deprecate is what makes `doctor` lie.

The compounding cost is attention: the same `validate` run carries 38 warnings, two of which are real, and the one signal that does move severity (`[FAIL] env-vars`) is disputed by a sibling door on the same host at the same second. An operator who learns that `doctor` lies about credentials discounts the whole run — and `lib/creds-check.sh:66-70` already records that exact outcome happening once before ("an operator learned to disbelieve the checker"). From tomorrow's 06:00 run, the daily checker will also say `skip — not declared` about two tokens that work, on three fleets, forever, and a `skip` alerts nobody.

## Proposed fix
Four edits, all onto doors that already exist. No new resolution logic anywhere.

1. **`claudlobby/doctor.py` — `check_env_vars` (`:73-107`).** Replace the single-file merge with the runtime resolver, and disclose an unreachable resolver instead of falling back (the `freshbox.py:345-350` pattern verbatim):
   ```python
   # before
   effective_env = dict(os.environ)
   if paths.env_file and paths.env_file.is_file():
       for k, v in dotenv.read(paths.env_file).items():
           if k not in effective_env:
               effective_env[k] = v
   # after
   from .env_tiers import ResolverUnavailable
   try:
       effective_env = {n: r.value for n, r in paths.env_resolved().items()}
   except ResolverUnavailable as e:
       report.add("env-vars", "warn", f"env resolver unreachable — not read: {e}")
       return
   for k, v in os.environ.items():          # ambient is a FALLBACK, never an override
       effective_env.setdefault(k, v)
   ```
   Keep the ambient merge *below* the cascade: an ambient empty must not mask a real fleet value (#948's half), and an ambient real value must not hide a tier that has nothing (which is how today's caller-dependent verdict arises).
2. **`claudlobby/validator.py` — `_validate_bots` (`:523-524`).** Replace `{**os.environ, **fleet_env, **bot_env}` with `paths.env_resolved(bot_name=bot_name)` plus the same `setdefault` ambient fallback, and delete the stale "full 3-tier env" comment at `:659-662`. `fleet_env` is still needed at `:1887` for `_warn_dead_flags` (that one is correctly a *file* read — it warns about lines written in a file); leave it.
3. **`claudlobby/commands/_helpers.py` — `_load_env` (`:63-69`).** Make it load the whole cascade (`paths.env_resolved()`), keeping the `if k not in os.environ` guard so an operator's ambient override still wins. This is the single edit that fixes the other seven commands that merely need the values present.
4. **`lib/creds-check.sh` (`:74-95`).** Replace the single `ENV_FILE` with the cascade door `start-bot.sh:176` already uses, and delete the mirroring comment so the next reader cannot restore it:
   ```sh
   # before
   ENV_FILE="${ENV_FILE:-$CLAUDLOBBY_ROOT/.env}"
   parse_env_file "$ENV_FILE"
   # after — most specific tier wins, exactly as the runtime merges them
   while IFS= read -r _cc_tier; do
       [ -n "$_cc_tier" ] && parse_env_file "$_cc_tier"
   done < <(env_tier_present_files "" "${FLEET_ARG:-}")
   ```
   `CLAUDLOBBY_ENV` stays an explicit single-file override for tests.
5. **`claudlobby/paths.py:534-549`** — leave the property, rename nothing, but add `# noqa`-free guard rails: after edits 1–4 the only remaining readers are `validator.py:1887` (correct) and any new code. Add a one-line test asserting the read-door call count, so a future `paths.env_file` read in a value position fails the suite rather than the estate.

Dependencies: none — all four doors exist today. Sits beneath the empty-MCP-credential issue (that issue's `if/elif` fix only becomes visible once the false `missing` list is gone) and beside #1213 (which owns `creds-check`'s skip-vs-fail and its host-global state file).

## Rollout & risk
Risk: **medium**. Three of the four edits only widen what a read-only door can see, and widening cannot turn a working fleet broken. The one with teeth is `lib/creds-check.sh`, which runs on a daily fleet timer and can alert: a fleet whose token was previously invisible will now be probed for real, so a genuinely bad credential that used to `skip` will start to `fail` — that is the intended behavior change and it is loud on purpose.

Rollout, per the `canary-rollout` protocol: land the Python edits first and run `doctor` / `validate` / `creds-reconcile` on one fleet by hand, diffing against the pre-change capture. Then land the `creds-check.sh` edit and run it **manually** for one fleet before the 06:00 timer sees it (`bash lib/creds-check.sh <fleet>` and read `state/creds-check-state.json`), because #1213's host-global state file means one fleet's run overwrites another's row — a surprise there is cheapest when nobody is asleep.

Backout: each edit is independent and revert-only; there is no state migration. `CLAUDLOBBY_ENV=<file>` pins `creds-check` back to single-file behavior without a revert if the cascade misbehaves on a host.

- **The empty-credential `if/elif`.** Its own issue. Note the ordering: fix this one first or you cannot see that one.
- The specific wrong turn: **do not "simplify" by deleting `Paths.env_file`.** It is the correct *write* target and `validator.py:1887`'s dead-flag scan legitimately reads the file as a file. Deleting it forces a hand-rolled fleet-vs-root rule back into the callers, which is the #1104 shape one layer down. The second wrong turn is merging `os.environ` *over* the cascade — that preserves today's caller-dependent verdict while looking like a fix, and every local test would pass because the test shell has no ambient credentials.
