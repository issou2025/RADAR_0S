*Project description:*
## Goal
Ship standalone `itqan` executables that run **without Python installed**, attached to each GitHub Release. Many people using Itqan assets build Flutter, iOS/Android or JavaScript apps and don't have Python. These binaries are also what the Homebrew, npm and GitHub Action channels install.

## Scope
- Build a single-file executable per platform in CI, e.g. with PyInstaller. The bundling tool is open to discussion; it must handle `click`, `requests` (with certificates) and `pyyaml`.
- **Target platforms:**
  - macOS arm64 and x86_64
  - Linux x86_64 and arm64
  - Windows x86_64
- Build on matching GitHub runners, and smoke-test each binary with `itqan --version` and `itqan --help`.
- Attach them to the GitHub Release created by the PyPI release workflow (#1), with predictable names (`itqan-<version>-<os>-<arch>[.exe]`, possibly archived) and a `SHA256SUMS` file.
- **macOS:** decide whether to sign and notarize. Directly downloaded unsigned binaries are blocked by Gatekeeper; Homebrew and npm installs mostly avoid this. Notarizing needs an Apple Developer account.

## Done when
- [ ] A `vX.Y.Z` tag produces all five binaries plus `SHA256SUMS` on the GitHub Release.
- [ ] Each binary runs `itqan init` and `itqan install` against the registry on a machine without Python.
- [ ] The README documents downloading and running a binary.

Depends on #1 (release workflow and tags).
