# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Re-clarification surfaces never offer the planned queue, so a queued Action can only be promoted from task detail**

*Project description:*
## User Story

As a user who has queued planned Actions on an Outcome, I want them offered to me at the moment the app asks what's next, so I can promote one in a tap instead of leaving the flow to find them.

## Observed Behaviour

`CONTEXT.md:178` specifies the re-clarification move:

> **Promotion from `planned` to `current` is an explicit clarifying act, never automatic.** When the current Action terminates, the Outcome enters the "no current Action" state until the user re-clarifies and **either promotes a planned Action, edits one, or creates a new one**.

Three moves. The implementation offers **one** — *creates a new one* — plus a silent title fallback. *Promote a planned Action* and *edit one* exist only on the Outcome detail screen, which no re-clarification surface links to.

Walk it. An Outcome has three planned Actions queued. The user completes its current Action in a sprint:

1. `completeCurrentAction` flips the row to `done` and promotes nothing (`action_dao.dart:239-249`). The Outcome is now Actionless with three planned rows.
2. `ReclarifyPromptSheet` floats (`active_focus_screen.dart:160`). The user taps **"More to do…"**.
3. `OutcomeSubject` passes no `currentActionText` (`reclarify_prompt_sheet.dart:102`), so `NextActionDialog` opens **empty** — a bare text field. **The three planned Actions are not shown, not offered, not mentioned.** The button says "Update next action…"; the dialog headline says "Set next action", because it knows there is nothing to update.
4. Saving it blank calls `mirrorTitleIfActionless` (`process_to_handlers.dart:881`) — the Outcome's **title silently becomes its current Action, overriding the queue the user built.**

The same hole exists in the DPR Task Review step. Worse there: `_ReviewCard` has no `InkWell`, no navigation, and `ProcessAction.reclarify` is not in its `include` set (`task_review_step.dart:244-277`), so the planned queue is not merely unlinked but unreachable from that surface by any route. Meanwhile the card brands the Outcome amber **"No next action defined"** and withholds the "Still relevant" button (`showKeep = !isActionless`, `:135`).

Net effect: an Outcome with a three-step plan the user wrote is told every morning that it has no next action, offered a blank box, and denied a way to say "I know" — while the plan sits on a screen the card does not link to. Adding planned Actions does not help: `applyAddPlannedAction` stamps `last_clarified_at` (`action_dao.dart:944`) but the queue is keyed on the *current* Action, so thinking harder about the Outcome moves it not one inch.

To actually drain the queue the user must abandon the ritual, go to Now, tap the row through to `/task/:id`, scroll to PLAN, and tap an up-arrow.

## Scope

- Widen `NextActionDialog` to return **either a new phrase or a planned-Action id**, rather than only a `String`.
- Offer the Outcome's planned queue wherever the app asks what's next:
  - `ReclarifyPromptSheet` → "More to do…" (`reclarify_prompt_sheet.dart:110`)
  - DPR Task Review → "Update next action…" (`task_review_step.dart:252`)
  - `ClarifyCard`'s Next arm (`clarify_card.dart:1007-1009`)
- Promote through the existing primitives — `promotePlannedAction` / `applySupersedeAndPromote` (`action_dao.dart:996`, `:1015`) via `task_detail_provider.dart:302`. No new DAO work; every primitive exists.
- Fix the copy mismatch: the button reads "Update next action…" while the dialog headline reads "Set next action" (`next_action_dialog.dart:56-57`).
- Keep the title fallback as the blank-save behaviour, but it must no longer be the *only* thing standing between a queued Outcome and a fabricated Action.

## Acceptance Criteria

- [ ] From the post-sprint re-clarify sheet, an Outcome with planned Actions offers them; choosing one promotes it to `current`.
- [ ] The same holds from the DPR Task Review step's "Update next action…".
- [ ] The same holds from `ClarifyCard`'s Next arm.
- [ ] Creating a brand-new Action from any of those surfaces behaves exactly as today.
- [ ] Promotion remains an **explicit clarifying act** per ADR-0004 — it stamps `last_clarified_at`, and nothing promotes automatically.
- [ ] An Outcome with an empty planned queue behaves exactly as today, including the blank-save title fallback.
- [ ] Replacing a *current* Action from these surfaces still routes through the existing "Replace current action" confirmation rather than silently superseding.
- [ ] Journey test drives the full path — queue two planned Actions, complete the current one in a sprint, assert both are offered on the re-clarify sheet, promote one, assert it is `current` and the other remains `planned` — proven to fail without the fix.
