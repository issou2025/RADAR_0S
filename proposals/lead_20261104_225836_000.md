# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Shared Site Sync and Shared Site Link Repositioning Commands**

*Project description:*
## Problem Statement

When designing multi-story residential towers in Revit, teams typically maintain a central host (main) model containing all major project levels alongside separate unit floor-plate models (e.g., one unit model for floors 3–12, another for floors 13–16). Inside each unit model, **Level-Based Shared Sites** (`ProjectLocation` elements) are used to position the Survey Point at different vertical elevations corresponding to levels in the host model so that each unit model can be linked into the host model by Shared Coordinates at multiple floors.

When level elevations change in the host model, the linked unit models do not automatically update their **Level-Based Shared Sites** or their physical placement in the host model. Currently, a user must manually open each unit model, activate each named Shared Site one by one, and move the Survey Point vertically to match the updated level elevation—repeating this error-prone manual calculation across every floor. Afterward, in the host model, the user must also manually reposition each linked unit model instance to move to its updated Shared Coordinates.

## Solution

Introduce a new **SharedCoordinates** module providing two coordinated Revit commands on the Synthetic ribbon (`Model Management` panel, grouped as a `SplitButton` or `StackedGroup`):

1. **Sync Shared Sites to Levels** (**Shared Site Sync**, executed inside a unit model): Opens a unified dialog where the user selects a loaded linked host model from a dropdown, selects a **Reference Datum Level** from the active unit model (defaulting to the level closest to internal `0'-0"`), and checks target levels from a list sorted by elevation (with levels that already match an existing **Level-Based Shared Site** in the unit model automatically pre-checked). Upon submission, the command creates or updates the corresponding **Level-Based Shared Sites** (`ProjectLocation`s) in the active unit model so each site's vertical elevation aligns the **Reference Datum Level** with the target level's shared coordinate elevation while preserving existing East/West, North/South, and True North Angle coordinates.
2. **Move Links to Shared Sites** (**Shared Site Link Repositioning**, executed inside the host main model): Opens a checklist dialog of loaded linked models (all checked by default) displaying how many link instances will be repositioned. Upon confirmation, the command inspects each selected link instance's assigned Shared Site, calculates the full 3D Shared Coordinate alignment transform (East/West, North/South, Elevation, and Angle) between the host model's active `ProjectLocation` and the linked model's matching **Level-Based Shared Site**, and repositions out-of-sync link instances (automatically unpinning prior to transformation and re-pinning afterward, while skipping and reporting any `<Not Shared>` instances in a post-execution summary).

## User Stories

1. As a BIM Coordinator working in a unit model, I want to launch the **Sync Shared Sites to Levels** command from the Synthetic ribbon, so that I can create or update **Level-Based Shared Sites** from a linked host model without manually moving the Survey Point for each floor.
2. As a BIM Coordinator working in a unit model, I want a unified dialog with a dropdown of loaded linked models at the top, so that I can choose the linked host model even when it is hidden in the active view or when "Select Links" is disabled in Revit.
3. As a BIM Coordinator working in a unit model, I want the linked model dropdown to auto-select the linked model if one is already pre-selected in the viewport or if only one loaded linked model exists in the document, so that I don't have to make redundant selections.
4. As a BIM Coordinator working in a unit model, I want a dropdown in the **Shared Site Sync** dialog to specify the active unit model's **Reference Datum Level**, so that unit models drawn at a non-zero internal level elevation still align accurately with the target host levels.
5. As a BIM Coordinator working in a unit model, I want the **Reference Datum Level** dropdown to default automatically to the level in the active unit model whose internal elevation is closest to `0'-0"`, so that standard unit models require zero extra configuration.
6. As a BIM Coordinator working in a unit model, I want the checklist of levels from the selected linked host model to be sorted by elevation, so that I can easily review and select floor ranges (such as floors 3 through 12) in natural vertical order.
7. As a BIM Coordinator working in a unit model, I want any level from the linked host model that already has a matching **Level-Based Shared Site** (by exact name) in the active unit model to be automatically pre-checked when the linked model is selected, so that updating existing floor sites after a level elevation change is a one-click operation.
8. As a BIM Coordinator working in a unit model, I want each row in the level checklist to display the level's name, its shared coordinate elevation, and an indicator of whether a matching **Level-Based Shared Site** already exists in the active unit model (e.g., Create vs. Update), so that I have full visibility before submitting.
9. As a BIM Coordinator working in a unit model, I want `Select All` and `Select None` actions (plus text search/filtering) on the level checklist, so that I can quickly select or clear subsets of levels in high-rise towers.
10. As a BIM Coordinator working in a unit model, I want the command to update the `ProjectPosition` elevation of existing **Level-Based Shared Sites** that match selected level names while preserving their existing East/West, North/South, and True North Angle values, so that horizontal shared alignment is never disturbed.
11. As a BIM Coordinator working in a unit model, I want the command to create new **Level-Based Shared Sites** by duplicating the active `ProjectLocation` for any selected level that does not yet have a matching Shared Site, naming it identically to the target level and setting its vertical elevation, so that new floors can be added seamlessly.
12. As a BIM Coordinator working in a unit model, I want unselected existing Shared Sites in the unit model to remain untouched when I run **Shared Site Sync**, so that custom or unrelated sites are never accidentally deleted.
13. As a BIM Coordinator working in a unit model, I want the target `ProjectPosition` elevation at the internal origin to be computed as the target level's shared coordinate elevation minus the **Reference Datum Level**'s internal elevation, so that when linked by Shared Coordinates into the host model, the unit model's **Reference Datum Level** lands at the exact elevation of the target level.
14. As a BIM Coordinator working in a unit model, I want a post-execution summary after **Shared Site Sync** completes showing how many **Level-Based Shared Sites** were created and how many were updated, so that I can verify the changes made to the unit model.
15. As a BIM Coordinator working in the host (main) model, I want to launch the **Move Links to Shared Sites** command from the Synthetic ribbon, so that I can batch-reposition linked unit model instances to match their updated **Level-Based Shared Sites**.
16. As a BIM Coordinator working in the host model, I want a checklist dialog of loaded linked models with all links checked by default and displaying the count of instances to be repositioned, so that I can confirm or narrow down which unit models to update.
17. As a BIM Coordinator working in the host model, I want **Shared Site Link Repositioning** to align each checked link instance in full 3D Shared Coordinates (East/West, North/South, Elevation, and True North Angle) according to its assigned Shared Site in the linked document and the host document's active `ProjectLocation`, so that any coordinate drift is completely corrected.
18. As a BIM Coordinator working in the host model, I want **Shared Site Link Repositioning** to automatically unpin any pinned `RevitLinkInstance` prior to moving/rotating it and re-pin it immediately afterward, so that pinned unit links update cleanly without throwing Revit errors or losing their pinned status.
19. As a BIM Coordinator working in the host model, I want **Shared Site Link Repositioning** to skip any `RevitLinkInstance` that does not have an assigned Shared Site (`<Not Shared>`) or whose assigned site cannot be resolved, and report those skipped instances in the post-execution summary, so that unshared links are not corrupted and I am informed of any unassigned instances.
20. As a BIM Coordinator working in either model, I want all modifications within each command to execute inside a single atomic Revit transaction, so that a single Undo reverts the entire operation cleanly if needed.

## Implementation Decisions

- **Module Organization & Ribbon Registration**:
  - A new cohesive presentation and domain module (`SharedCoordinates`) will be created under the shared project's modules namespace, exposing two `IExternalCommand` entry points: `CmdSyncSharedSites` (**Sync Shared Sites to Levels**) and `CmdMoveLinksToSharedSites` (**Move Links to Shared Sites**).
  - Both commands will be registered on the `Model Management` ribbon panel in the declarative ribbon configuration as a `SplitButton` or `StackedGroup` available across all supported Revit versions (2022–2026).
- **Single Seam Architecture (`ISharedCoordinatesAdapter`)**:
  - Following the codebase's deep-module principles and ADR 023, a single seam (`ISharedCoordinatesAdapter`) will sit at the Revit database boundary.
  - The adapter interface will expose snapshot retrieval and batch execution operations using pure C# POCO models (`LinkedModelSiteSyncSnapshot`, `HostLevelItemModel`, `UnitDatumLevelModel`, `SharedSiteSyncRequest`, `SharedSiteSyncResult`, `LinkedModelRepositionGroupModel`, `LinkInstanceRepositionResult`), keeping all Revit API types (`Document`, `RevitLinkInstance`, `ProjectLocation`, `Level`, `Transform`) encapsulated inside the concrete `RevitSharedCoordinatesAdapter`.
  - An in-memory `FakeSharedCoordinatesAdapter` will satisfy the same seam for headless unit and ViewModel testing.
- **Shared Site Sync Calculation & Execution (`SyncSharedSitesViewModel` + Adapter)**:
  - For each loaded linked model in the active unit document, the adapter extracts all `Level` elements from the linked document and computes each level's shared coordinate elevation using the linked document's active `ProjectLocation` (`ActiveProjectLocation.GetProjectPosition` at the level's internal Z elevation).
  - The adapter also extracts all `Level` elements from the active unit document (as candidates for the **Reference Datum Level**) and all existing `ProjectLocation` names and elevations in the active unit document.
  - `SyncSharedSitesViewModel` defaults the selected linked model to the currently selected link (if any) or the sole loaded link (if only one exists), and defaults the **Reference Datum Level** to the active document level with the smallest absolute internal elevation (`|Elevation|`).
  - When a linked model is selected, `SyncSharedSitesViewModel` populates the level checklist sorted ascending by elevation and automatically sets `IsChecked = true` on any level whose name matches an existing `ProjectLocation` name in the active unit document (case-sensitive exact match, with case-insensitive fallback check for duplicate prevention).
  - Upon confirmation, for each checked target level, the target `ProjectPosition.Elevation` at `XYZ.Zero` in the unit model is calculated as `TargetLevelSharedElevation - ReferenceDatumLevelInternalElevation`, while `EastWest`, `NorthSouth`, and `Angle` are preserved from the existing `ProjectLocation` (if updating) or the active `ProjectLocation` (if creating via `ProjectLocation.Duplicate`). Unselected `ProjectLocation` elements in the unit model are left untouched.
- **Shared Site Link Repositioning Calculation & Execution (`MoveLinksToSharedSitesViewModel` + Adapter)**:
  - In the host model, the adapter inspects all loaded `RevitLinkInstance` elements grouped by their `RevitLinkType`.
  - For each `RevitLinkInstance`, the adapter reads the assigned Shared Site name from `BuiltInParameter.GEO_LOCATION` (or parses the instance name suffix if needed). If the instance is `<Not Shared>` or unassigned, it is flagged as skipped (`UnassignedSite`).
  - For each assigned instance, the adapter resolves the matching `ProjectLocation` in `linkInstance.GetLinkDocument()` and constructs the 3D coordinate `Transform` mapping link internal coordinates to shared coordinates ($T_{\text{link} \to \text{shared}}$) and the host document's `ActiveProjectLocation` transform mapping host internal coordinates to shared coordinates ($T_{\text{host} \to \text{shared}}$).
  - The expected placement transform of the `RevitLinkInstance` in host internal coordinates is $T_{\text{expected}} = T_{\text{host} \to \text{shared}}^{-1} \circ T_{\text{link} \to \text{shared}}$.
  - Comparing $T_{\text{expected}}$ against `linkInstance.GetTransform()` determines whether the instance is out of sync (beyond a standard floating-point tolerance of `1e-5` feet / radians).
  - `MoveLinksToSharedSitesViewModel` displays all loaded `RevitLinkType` groups checked by default with total, out-of-sync, and unassigned instance counts.
  - Upon confirmation, within a single transaction, the adapter iterates through all checked out-of-sync instances: if `linkInstance.Pinned` is `true`, it sets `Pinned = false`, applies the rotation delta (if any) and translation delta via `ElementTransformUtils`, and restores `Pinned = true`. Finally, a post-execution summary dialog reports the counts of repositioned, already-aligned, and skipped (`<Not Shared>`) instances.
- **WPF UI & Theme Compliance**:
  - Both modal windows (`SyncSharedSitesWindow` and `MoveLinksToSharedSitesWindow`) will use `SyntheticTheme.xaml` design tokens and `RevitWindowHelper` owner binding to match existing Synthetic dialogs.

## Testing Decisions

- **What Makes a Good Test**:
  - Tests must exercise external behavior through the highest module interface (`SyncSharedSitesViewModel`, `MoveLinksToSharedSitesViewModel`, and pure coordinate transformation math) across the single `ISharedCoordinatesAdapter` seam, asserting observable outputs and state transitions rather than internal implementation details.
- **Modules to be Tested**:
  - **Tier 1 Headless Tests (`SyntheticTests.Logic`)**:
    - `SyncSharedSitesViewModel` tested against `FakeSharedCoordinatesAdapter`:
      - Auto-selection of linked model when only one exists or one is pre-selected.
      - Default selection of the **Reference Datum Level** closest to internal `0'-0"` (including when all levels are non-zero, e.g., `+0'-6"` vs `-2'-0"`).
      - Sorting of linked model levels by elevation and automatic pre-checking of levels that match existing **Level-Based Shared Sites** in the unit model.
      - Elevation math verification (`TargetLevelSharedElevation - ReferenceDatumInternalElevation`) for both zero and non-zero **Reference Datum Levels**, ensuring East/West, North/South, and Angle are preserved and unselected sites remain untouched.
    - `MoveLinksToSharedSitesViewModel` & 3D Transform Alignment Engine tested against `FakeSharedCoordinatesAdapter`:
      - Default checking of all loaded link groups and accurate tallying of out-of-sync vs. `<Not Shared>` instances.
      - Full 3D coordinate transform calculation (East/West, North/South, Elevation, and True North Angle rotation) between host active site and link named site.
      - Preservation of `Pinned` state (unpin -> transform -> re-pin) and skipping/reporting of `<Not Shared>` instances.
    - Ribbon configuration validation tests ensuring both new command classes are registered and resolvable.
  - **Tier 2 Integration Tests (`SyntheticTests.Shared`)**:
    - Adapter integration tests verifying `ProjectLocation` duplication, `ProjectPosition` mutation, and `RevitLinkInstance` transform delta calculation against the Revit API / mock harness.
- **Prior Art in the Codebase**:
  - Follow the ViewModel + Adapter/Service test patterns established in the `StandardsManagement` logic test suite and the `RibbonTests` validation suite.

## Out of Scope

- Automatically opening unloaded linked models from disk or Autodesk Construction Cloud (ACC) in the background to modify their Shared Sites from the host model (Command 1 operates inside the active unit model; Command 2 operates inside the active host model).
- Deleting existing Shared Sites in the unit model that are unchecked in the **Sync Shared Sites to Levels** dialog.
- Assigning a Shared Site to `<Not Shared>` link instances in the host model (due to Revit API read-only constraints on initial Shared Site assignment; unassigned instances are skipped and reported).
