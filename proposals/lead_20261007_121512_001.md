## Project Understanding
You need assistance with: 
**Managed providers need an independent host-configured private authority-store binding**

*Project description:*
Managed model-reference providers need an independent host-configured private authority-store binding, separate from the conversion request's authorityStorePath. This is a verified integration capability gap; the reader already transports authorityStorePath correctly in protocol-2 convert stdin.

Current main evidence: cli-connection-reader/model-provider.mjs blob aec3fe06d08e764d237d0933404b8bebc22ab02f, verified against GitHub main on 2026-10-07 and the identical local source blob. minimalProviderEnvironment permits only SYSTEMROOT/WINDIR/COMSPEC/TEMP/TMP on Windows (HOME/TMPDIR on other platforms). describeManagedProvider/convertModelReference build provider environment from that minimal list. convertModelReference correctly adds authorityStorePath to convert stdin, but neither operation supplies a separately configured provider authority-store binding.

Why a request field alone is insufficient: a provider must authenticate its installation's signed private store independently, then compare the untrusted request's requested store with that binding. Using the request itself to choose the trusted store would weaken this boundary; retaining only the default shared installation store prevents a safely isolated authenticated host from using its own store.

Observed consumer repro: https://github.com/pawellisowski/floless.app/issues/2048. A normal signed licensed isolated FloLess server, checkout-built Revit SEA and a genuine native-picker RVT import reach protocol-2 conversion with the correct isolated authorityStorePath. The reader's minimal environment lacks a host-bound store configuration; the provider resolves its normal installed default instead and rejects the mismatch with xeorvt-request-invalid before source hashing, credential reads or network work. Actual operation 2c9574eb-6b7a-403b-9163-fc4aad97d574 / AWARE run 46792fbc-8619-4dbb-9e35-74b6a7a91520 retain the failure. Credential-free guard controls reproduce the requested/default mismatch; changing only the expected-store injection advances to a deliberately missing-source error, with zero network calls. These controls are reconstructed guard requests, not a claim that retained raw convert stdin exists.

Expected AWARE capability: accept an explicit canonical host-configured authority-store path through a generic managed-provider configuration seam and propagate its independent binding consistently to describe and convert. Validate private canonical path/case aliases and keep the environment minimal. Do not permit stdin to select trust, copy arbitrary ambient credentials/environment, bypass signed authority checks, or add a FloLess-specific policy to AWARE. Preserve the existing correct authorityStorePath transport.

FloLess caller/provider signed-store compatibility repair belongs in the linked FloLess issue; it is not evidence that AWARE's current transport is malfunctioning. The generic AWARE propagation change is in progress independently, with reader/bridge version bumps and focused tests; no merge or real model conversion pass is claimed.

Implementation in progress uses generic AWARE_MODEL_PROVIDER_AUTHORITY_STORE_DIR: a separate protocol-2 environment builder validates its canonical absolute path and equality with the requested authorityStorePath before describe/convert. ASCII Windows aliases collapse only when identical, conflicts reject. No configuration retains default compatibility; protocol-1/package-v3 paths remain unchanged. Planned reader 0.8.1 / bridge 0.5.4. Final review and genuine model QA remain pending.
