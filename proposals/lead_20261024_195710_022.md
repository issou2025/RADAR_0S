## Origin

Follow-up enhancement suggestions from @voravin after **v0.16.5 fixed the original Philips HDMI regression (#67)**. These are **new UI and usability requests**, not unverified regressions.

## Requests

1. **Live camera UI parity:** Let `kellies_voice.show_live_camera` accept `show_header: false` to remove the title/subtitle from the live popup, and `image_fit: fit` to show the entire frame (like `show_camera`). Currently the HA action rejects those option names because only the snapshot service schema supports them. Preserve old defaults for callers that omit the options.
2. **Short live views:** The current `duration_seconds` minimum is **15 seconds**, while this tester's automations show about **6-second** popups. Consider allowing e.g. 4–14-second live durations while ensuring the HLS decoder, pending requests, snapshot fallback and timer are safely released on timeout; or clearly document the enforced minimum and use `hide_camera` for shorter views.
3. **Refresh the placeholder snapshot during stream startup** until the first real video frame renders. Test that refresh cancels immediately when live begins or the popup closes, no pending URL or stale bitmap can change a different popup, and no redundant polling continues. It should not delay HLS startup or capture user audio.
4. **Documentation:** tester observed ~7 seconds before HLS frames on Philips with **Preload camera stream** off and almost immediate start with the relevant HA camera's preload setting enabled. Document this optional HA setting and potential resource tradeoffs instead of promising instant live video.

## Acceptance

- [ ] Same behavior on onn 4K Pro and both Philips models without HDMI / foreground app decoder loss.
- [ ] `show_live_camera` supports/validates optional header and fit fields in HA service schema, HACS strings/translations, scoped alert allowlist and Android renderer.
- [ ] Old scripts with no new arguments behave unchanged.
- [ ] Both short and normal durations stop correctly and don't keep resources alive.
- [ ] Pre-first-frame snapshot refresh is bounded, cleared on dismissal/first frame, and never mistaken for real live playback.
- [ ] Update docs/INSTALL.md and camera guide; add automated tests and seek Philips field QA before considering confirmed.
