# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Revit: import an adjacent bundle without resetting the shared coordinates**

*Project description:*
## What

Importing a second, adjacent Mantle Place bundle into a Revit project that already holds one resets the project's shared coordinates. `SetSharedCoordinates` (`revit/src/MantlePlace.Revit.Addin/RevitBundleImporter.SharedCoordinates.cs:32-37`) calls `SetProjectPosition` from each manifest's survey point unconditionally, so the second import moves the survey point to its own origin: the first bundle's elements then report the wrong shared coordinates, and the two bundles are built about the same internal origin.

## Why

Users building a larger area from several bundles ordered side by side want them to fit together with no manual move. The Unreal side of the same request is #565.

## Scope

- First, confirm the behaviour live: import two adjacent bundles and record where each lands and what the survey point reads after each import.
- When the project already holds a Mantle Place import, do not reset the project position. The project's existing position is the **anchor**. Build the new bundle at its offset from the anchor: its published survey-point easting, northing and elevation minus the anchor's, converted with the units each side states. Both are numbers the manifests publish; nothing is reprojected and nothing is re-derived (spec §6; the thin-client boundary in `CLAUDE.md`).
- Offset only when both bundles name the same EPSG code and the same published angle to true north. A different angle means a rotation the plugin must not compute. Otherwise, or when the offset is beyond a precision limit the PR states and justifies, refuse the import with one clear message naming the reason, consistent with how Revit refuses a conflicting re-import (ADR 0004 (`docs/adr/0004-revit-terrain-identity.md`)). The existing project is never moved.
- The decision lives in `MantlePlace.Revit.Core` (the planner) with a headless test; the add-in only applies the plan (CONTRIBUTING "Style and shape"). ADR 0004's re-import rules are unchanged: a different order is a new stem.
- Leave out: matching heights across tile seams (platform-side work).

## Acceptance criteria

- [ ] Two bundles from an adjacent order, imported one after the other into one project, sit edge to edge with no manual move, and the first bundle's shared coordinates are unchanged by the second import.
- [ ] A third adjacent bundle lands correctly against the first two.
- [ ] Bundles with a different EPSG code or angle, or too far apart, are refused with a single clear message and the project is untouched.
- [ ] A headless test covers the anchor and offset decision, including every refusal.
- [ ] **Verified live:** the host-harness Revit check imports two adjacent test bundles (generated, never committed) and reports the measured edge offset and the survey point after each import.
