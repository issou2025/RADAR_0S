Acceptance criteria

- Partial findings are posted and explicitly labeled partial, including completed vs incomplete scope.
- Any completed validated edits are committed/pushed through the existing safe path; if there are no validated edits, the comment still lands and the run still ends green/neutral.
- A later run has a persisted state artifact/ledger/comment to build on, even if the full resume consumer lands in the next issue.
- Tests cover finalize-on-deadline and green-on-partial behavior.

Implementation constraints
- Stay inside files_touched.
- Keep the partial-comment text additive and machine-readable enough for later resume/no-progress logic.
- Update README additively under the existing review/autofix docs; document the partial-completion contract and non-failure exit semantics.
- Do not rename existing workflow steps, job names, or check-run names.
