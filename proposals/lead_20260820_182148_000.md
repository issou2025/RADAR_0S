# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Nothing prevents a sixth unguarded entity-reference walk in ifc-lite-geometry**

*Project description:*
## What

`rust/geometry` walks file-supplied entity references in at least five places. Each one is guarded, and each guard was rediscovered independently at its own site:

| site | guard | what a cycle means there |
|---|---|---|
| `router/layers.rs` `item_has_identity_position` | visited set | `false` |
| `processors/boolean/mod.rs` `collect_polygonal_chain` | visited set | `break`, use current as base |
| `processors/boolean/mod.rs` `process_with_depth` | visited set | `Err("cyclic boolean FirstOperand chain at #N")` |
| `router/voids/probe.rs` (rect parametric) | `FxHashSet` + `MAX_EXTRUSION_EXTRACT_DEPTH` | `None` |
| `router/voids/probe.rs` `extract_extrusion_direction_recursive` | `FxHashSet` + depth loop | `None` |

Plus depth caps in `profile_extractor.rs`, `router/processing.rs`, `router/content_hash.rs`, `processors/surface.rs`, and a memo sentinel in `content_hash.rs`.

Every walk we checked is now guarded, so the immediate class looks swept. The problem is that nothing *prevents* a sixth. The guard is a review convention, and review conventions are not gates.

## Why it matters

The failure mode is not a bad render, it is a process abort. A Rust stack overflow is `SIGABRT`, not a catchable panic, so nothing upstream can turn it into a load error. In the wasm geometry worker it takes down the whole instance. #2866 was exactly this, from one self-referential `IfcBooleanResult.FirstOperand`.

Two guards are not interchangeable and picking the wrong one has its own failure mode. A depth cap on an eligibility probe (#2872, first attempt) silently drops layer slicing on files that render today, because #960 records Revit chains 42 `DIFFERENCE` nodes deep. Getting this right per site, from memory, five times, is not a stable equilibrium.

## Proposal, in preference order

**1. A structural gate, in the spirit of `module_size_ratchet`.** An allowlisted test that fails when a loop or self-recursion under `rust/geometry/src` reaches `decode_by_id` / `resolve_ref` without a `visited` or `depth` binding in scope. That turns "remember the guard" into CI, which is the move the file-size rule already made. Cheapest, and it fits how this repo already enforces things.

**2. A `RefWalk` handle in `ifc-lite-core`** that owns the visited set and is the only way to follow a reference in a loop. Closes the class properly, but only once every site adopts it. Cross-crate migration, and the five sites disagree on what a cycle *means*, so each caller re-maps the result anyway.

**3. A one-shot acyclicity pass over boolean `FirstOperand` edges at load.** Recording this to reject it: ifc-lite decodes lazily by id, and a whole-model pre-pass is the wrong trade against the load-time budget.

## Notes

Option 1 is the one worth doing. The shared *lines* between these walks amount to about four (insert, resolve); the thing worth sharing is the invariant, not the code.
