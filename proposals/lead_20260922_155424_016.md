## Project Understanding

**Live proof: run_import (ImportExport/RunNowImport) has never been fired - needs a throwaway import**

*Project description:*
`run_import` queues a configured Linnworks import to run now (`ImportExport/RunNowImport`). It has never been fired. Its sibling `run_export` uses the same endpoint family and was proven live on 18 Sep 2026 (v1.55.5).

## Why it was left alone

Every one of the 126 imports configured on this tenant writes to real catalogue data, and 9 of them delete things (`DeleteImages`, `DeletePrimaryImages`, `DeleteSuppliersFromItems`, `RenameSKU`, `DeleteComposition`). The one plausible candidate, id 353 "temp", maps an S3 CSV onto item extended properties for every SKU in the file. Its source URL returns 403 to an anonymous request, but that doesn't prove the file is gone, because Linnworks fetches it with its own credentials. None of the existing imports is safe to fire just to test the trigger.

## What's needed: a throwaway import

1. Create a test item, e.g. `ZZZ-MCP-TEST-IMPORT-1`, with `create_or_update_inventory_item`.
2. Make a one-row CSV that changes one harmless field on that SKU only, such as its title, or an extended property like `ImportTest=1`.
3. Put the CSV somewhere Linnworks can fetch it, or use whatever source the import screen offers.
4. In the Linnworks UI, create an **Inventory** import that points at that file and maps only those columns. No schedule.
5. Get its id from `get_import_list`.

## Steps

1. Dry-run `run_import(import_id)` and check the config preview is the throwaway import.
2. Run it live.
3. Don't read too much into the immediate read-back. On the export proof the read-back said "not queued" and the job ran 15 seconds later. The real proof is the `started` timestamp moving on from `started_before`. The response's `how_to_verify` explains this.
4. Check the test SKU changed as the CSV said.
5. Tidy up: delete the import in the UI and delete the test SKU (`delete_inventory_item`).

## After

Update the `ImportExport/RunNowImport` row in CLAUDE.md, and the `run_import` row in the Import / Export tools table (it still says "spec-based, not yet live-tested"), with the date and the result either way.
