## 1. Premise check, verified 2026-11-19 against origin/develop @ a9c03dc

The naive version of this brief ("Matchline needs a typed JSON building model and validation") is false:

| Claim the naive brief would make | What develop actually has |
|---|---|
| No canonical typed model | `building_model.py` defines the canonical dataclass tree (Space, Zone, EnvelopeWall, BimElement, BimOpening, Level) with `BuildingModel.to_json()` / `from_json()` round-trip, a model_version, and a Provenance record on every derived fact. |
| No validation before export | The `validate/` battery plus `bem/export_gate.py` block export on errors. The gate measures, it never repairs (see also #1406, the validate/repair/revalidate spike, which owns the repair-loop question; this spike does not duplicate it). |
| No BIM/IFC path | `ifc_import.py` imports IFC4 to the canonical model (Tier 0), and `bem_export.py` exports gbXML 6.01 and IFC4 from it. |

**What is genuinely missing (the narrowed premise):**

1. **No authoring or proposal interface.** The canonical model is only ever produced by the extraction pipeline (drawings in, model out). Nothing lets a human or an agent *propose* a model in a typed document and have a deterministic checker accept, reject, or build it before it becomes canonical. Grep for a proposal interface on develop returns only detector region proposals, nothing at the model layer.
2. **No constructive wall topology.** `geometry_simplify.py` simplifies footprint rings (area-budgeted, Douglas-Peucker style). Spaces carry polygons, envelope entries are wall runs, openings are records attached after the fact. Nothing constructs rooms from a wall graph, cuts an opening into a host wall, or joins touching walls. Floorkit's claimed kernel does exactly those three operations.
3. **No evaluated clean-digital upstream.** Matchline exists to recover models from messy drawings. If an agent-native authoring tool can emit a clean model Matchline can ingest directly, that is a second input lane worth one measurement, not an assumption.

## 2. What Floorkit/OpenGeometry actually is (verified from its own docs, 2026-11-19)

- Stack: OpenGeometry is a Rust geometry kernel compiled to WebAssembly with a TypeScript API. Floorkit (`@opengeometry/floorkit`) is a browser TypeScript SDK for editable building models, floor plans, and drawing sheets. Ploterr is the waitlisted end-user app on top.
- The building is a typed JSON document. An agent proposes it, Floorkit checks and builds it. The host app owns UI, Three.js rendering, storage, accounts, workflow, and AI provider.
- Exports today: PDF for sheets, GLB for the 3D model. **IFC and DXF are stated as coming in the next release, not shipped.** No energy semantics anywhere: no zones as thermal objects, constructions, schedules, or BEM export.
- Licensing: Floorkit is **proprietary**. Local development is free with no key (the "made with floorkit" badge stays visible). Every deployed hostname, including public prototypes and non-commercial demos, needs a hostname key; a trial key runs 14 days; paid pricing is not published. Without a valid deployed key, views stop after five seconds and SDK exports throw LicenseError.

That licensing line is why this spike can never end in "adopt Floorkit as a Matchline dependency." Matchline is open source under the standing no-side-revenue, DOE/lab funding strategy. The most a Go can mean here is: keep Floorkit as an optional external authoring front end, evaluated from outside the repo, or mine its document contract into Matchline's own model layer.

## 3. Scope

**Phase 0, premise and format check (desk work, 2h ceiling, no code, no install):**

1. Is Floorkit's saved JSON document format documented or inspectable enough to map field by field to `BuildingModel` (spaces, levels, envelope walls, openings, with units and coordinate frame stated)? The y-down drawing frame vs Floorkit's frame must be settled on paper, not discovered in code.
2. Does the local-development license tier permit this evaluation with no key, no deployment, and no purchase? If evaluation requires deploying to a hostname or buying a key, stop and report; that is a Kill, not a purchase request.
3. Is there any export path today (GLB, PDF, raw JSON) that carries rooms, walls, and hosted openings as data, not as a rendered picture? If the only outputs are PDF and GLB geometry with no element identity, record that; Phase 1 then tests raw JSON only, or closes.
4. Write the field mapping and the kill/continue call into the spike report before any Phase 1 work.

**Phase 1, only if Phase 0 passes all four checks (scratch work, 8h ceiling):**

- One small fixture only: a 2-room single-level plan with 1 exterior door, 2 windows, stated dimensions, and hand-computed ground truth areas.
- An agent (or a hand-written document standing in for one) proposes the fixture as a Floorkit JSON document. Floorkit checks and builds it locally. No deployment, no hostname key, no spend.
- Map the result into `BuildingModel` JSON in a scratch directory outside the Matchline package, attach Matchline Provenance records at mapping time (Floorkit carries no provenance; unmapped or unprovenanced facts are a finding, not a silent gap), then run the existing `validate/` battery and export gate on the mapped model.
- Baseline for comparison: the same fixture built through Matchline's own synth path, scored the same way.
- Deliverable is a REPORT.md with the mapping table, the validation results, and a Go / No-go against the gates in section 4. No Matchline production code changes, no new dependency in `pyproject.toml`, nothing vendored.

## 4. Pre-registered gates

Kill (any one is enough):
- Phase 0 finds no inspectable JSON document format, or evaluation needs a paid key, a deployed hostname, or any spend.
- The mapping loses element identity for rooms, walls, or openings, or cannot state a coordinate-frame conversion.
- Mapped model fails the existing validation battery on room closure or area conservation, where the synth baseline passes.
- Room areas differ from hand ground truth by more than 1 percent, or any hosted opening lands on the wrong wall or outside its host wall interval.
- Provenance cannot be attached at mapping time without inventing sources.

Go (all required, and Go means only what section 2 says it can mean):
- Fixture maps completely, validation battery and export gate pass, areas within 1 percent, openings correctly hosted.
- The agent-proposal contract (typed document in, deterministic check/build, JSON diagnostics out) is documented well enough to reimplement against `BuildingModel` natively, without the proprietary SDK, if Alex wants that lane.
- Report states the license boundary explicitly, so a later reader cannot mistake a Go for permission to depend on Floorkit.
