## 背景

当前 main 已经明确采用 **geometry-first / progressive semantics** 的方向，但生产状态模型和 agent-facing contract 里仍残留一部分 semantic-first 约束，会让 Agent 误以为“先把对象分类成 Wall / Component，再开始几何建模”。

本 issue 只清理这些残留，不删除 wall / grid 等专业能力，也不新增第二套状态模型。

核查基于当前 main `e46cf701f1f67190a3a66c865caec1aee2c460d5`。

相关已完成方向：
- #125：geometry 可先于完整语义存在，`unknown` 是合法状态；producer != ontology。
- #134 / PR #141：Wall 已支持 project-local point reference，不再要求 GridAxis。
- #136：generic geometry 不应自动分类成 Wall。

## 当前残留

### 1. Component@1 仍强制语义存在

`archflow/state/state_record.py` 当前仍要求每个 `Component@1` 至少有 `semantic_kind` 或 roles/conditions：

```python
if kind is None and not (roles or conditions):
    raise StateRecordError(...)
```

这与 #125 的原则冲突：

> A design entity may exist before its full meaning is known.

Stage 1 / early modeling 应允许稳定 identity + geometry + provenance 存在，而 architectural / structural / material semantics 暂时 unknown / absent。

### 2. sketch 创建新 Component 时仍强制 semanticKind

`apps/archflow-studio/api/archflow_studio_api/application/intent.py::sketch_prism_proposal` 当前对新 component 返回：

```text
COMPONENT_KIND_REQUIRED
<component> is new: say what it is as semanticKind
```

这会把几何创建变成“先回答它是什么，再允许它存在”。

正确目标：

```text
geometry creation
→ stable identity
→ optional/unknown semantic facets
→ later enrichment when justified
```

### 3. Agent response schema 仍把 Component 设计成 semantic-first

`apps/archflow-studio/api/archflow_studio_api/application/intent_agent.py` 的 Component schema 仍主要暴露 `semantic_kind`，会强化“新对象必须先分类”的模型先验。

### 4. producer contract 仍有 wall-first / 手写枚举残留

`monkeyarch/capabilities/element_producers.py` 当前显式保留：

```python
# The wall stays first ...
return {"wall": {...}, "prism": {...}, ...}
```

注释称顺序不是 contract，但对 LLM 来说 schema variant 顺序本身会形成 anchoring。

同时 `apps/monkeyhub/api/monkeyhub_api/chat.py` 的 agent tool description 仍手写：

```text
producer (e.g. prism, loft, wall, planar-surface)
```

以及 `studio_schema` producer field 只列 `prism / loft / wall / planar-surface`，而当前 producer signatures 已包含 `curve`。这既有旧语义倾向，也已出现事实漂移。

### 5. 历史 bug 测试名仍容易误导源码型 Agent

当前两个 `test_grid_free_wall.py` 的内容是有价值的：它们验证“已经明确为 Wall 的对象也能用 project-local points，不要求 GridAxis”。

但命名仍以历史 bug 为中心，Agent 阅读源码/issue 时容易把 “grid-free wall” 当成当前架构特殊路径。

建议改为正向 capability 命名，例如：

```text
test_wall_project_point_authoring.py
test_wall_explicit_point_reference.py
```

测试语义保留，不降低覆盖。

## 架构目标

核心规则：

> **Geometry first. Meaning accumulates. Identity persists.**

早期对象应允许：

```text
Entity X
  stable identity
  geometry realization
  provenance / dependencies
  semantic facets = unknown / absent
```

之后同一实体可逐步增加：

```text
+ architectural role
+ material identity
+ structural role
+ fabrication / analysis facets
```

不要因为 producer 从 prism 变成 wall、或后续获得 wall/enclosure semantics，就强迫对象重生为新的 canonical identity。

### Producer 与 ontology 的边界

保留 `wall` producer。

它仍适用于：
- 用户明确要求 Wall；
- 当前状态已经建立 Wall / enclosure / opening-host 等语义；
- hosted openings / thickness / support relations 等专用行为确实需要它。

但 `wall` 是 realization capability，不是 early-modeling default ontology。

同理保留 GridAxis：
- grid 是可用 reference system；
- 不是普通几何创建的默认前置条件。

## 实施范围

1. **允许 Component@1 在早期合法地无 architectural semantic classification**
   - 允许 semantics absent / unknown；
   - 不引入假的 `generic` / `unknown-wall` semantic alias 来满足旧校验；
   - 保持已有已分类 Component 的兼容性。

2. **移除普通 geometry creation 对 `semanticKind` 的强制前置**
   - 新 component / geometry 可以先创建；
   - 只有某个 capability 确实需要语义时才返回 readiness / enrichment requirement；
   - 用户没有提供语义时不要让 Agent 猜。

3. **调整 intent / response schema**
   - 表达 optional / deferred semantic enrichment；
   - 不把 Component schema 设计成“必须先选 semantic_kind”；
   - 保持后续显式 semantic upsert / enrichment 可用。

4. **清理 producer 暗示**
   - 不依赖 `wall` 位于 schema 第一个 variant；
   - agent-facing producer list 从真实 `producer_signatures()` / capability owner 生成，不手写四项；
   - 默认说明明确 early modeling 优先使用最低充分表达（例如 sketch / prism / planar-surface / curve），只有 meaning 已建立时才使用 specialized producer。

5. **重命名历史 bug 测试**
   - 保留 grid-free Wall 能力与回归；
   - 改成正向 capability 命名；
   - 不删除 Wall explicit-point / opening / restart / identity 覆盖。

6. **补 agent-contract regression**
   至少验证 fresh empty project 下：
   - 一般“做一个体块 / 边界 / 面”不会先要求 Wall / GridAxis / semanticKind；
   - “做一段普通几何墙状体”在未明确语义时可先用 generic realization；
   - 用户明确说“这是一堵墙并开窗”时可直接走 wall producer，且无需 GridAxis；
   - 后续为 generic geometry 增加 wall/enclosure/structural semantics 时保持 stable identity，而不是重新创建 canonical object。

## 非目标

- 不删除 wall producer；
- 不删除 GridAxis / Level / Datum；
- 不把所有对象永久保持 generic；
- 不新增第二份 canonical state、BIM hierarchy 或 semantic-maturity 状态机；
- 不自动从形状猜 Wall / Slab / Beam；
- 不让 downstream analysis / Revit projection 成为 canonical identity；
- 不重写 #125 的 Stage / FEA 实验。

## 验收

- [ ] 一个新 geometry entity / component 可以在没有 architectural semantic classification 的情况下合法保留。
- [ ] `POST /api/proposals/sketch` 创建新几何时不再因为缺 `semanticKind` 阻塞。
- [ ] StateRecord 可区分“尚未建立该语义”与“已有明确 semantic facet”，且不需要虚构 alias。
- [ ] 后续 semantic enrichment 保持同一 entity/component identity、history、dependencies。
- [ ] Generic geometry 不会自动变成 Wall。
- [ ] 明确 Wall 请求仍可使用 wall producer、hosted opening、project-local point references，且不要求 GridAxis。
- [ ] Agent-facing producer/capability 列表来自当前真实 contract，不再手写过期四项。
- [ ] schema/提示不再通过 variant 顺序暗示 wall-first。
- [ ] 原 grid-free wall 回归以正向 capability 名称保留并继续通过。
- [ ] fresh Claude / Codex 在同一空项目基线下，不因普通 geometry request 主动要求 GridAxis 或 semanticKind。
- [ ] affected tests + `python tools/archcheck.py` 通过。

## 最终原则

```text
producer != ontology
geometry != semantic commitment
reference system != creation prerequisite
unknown != invalid
```

让 early modeling 真正成为：

```text
make geometry
→ keep identity
→ add meaning only when the project has earned it
```
