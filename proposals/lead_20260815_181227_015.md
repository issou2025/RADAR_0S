## Project Understanding

*Project description:*
# Oxy AI website and commercial platform epic

## Summary

Rebuild the public Oxy website so it accurately explains, markets and converts the new shared AI platform being built across Oxy, the inference data plane and Alia.

The website must present **Oxy AI as the umbrella offering**, **Oxy Inference as the public unified inference service**, managed/dedicated inference as infrastructure services, and Alia/Codea as products built on top of that platform. It must give developers and companies a clear path to learn, evaluate, start building, request access and contact sales without duplicating the control-plane responsibilities of Oxy Console.

This is a website/content/commercial epic. It does **not** make this repository the source of truth for accounts, applications, credentials, model availability, routing, usage, pricing or billing.

Companion platform epics:

- **Oxy control plane:** https://github.com/OxyHQ/oxy/issues/972
- **Alia migration:** https://github.com/OxyHQ/Alia/issues/139

Every PR implementing this epic should reference this issue and identify which checklist items it completes.

## Product taxonomy to use

Until a later naming review explicitly changes it, use this public structure:

```text
Oxy AI                    umbrella for Oxy's AI platform, products and services
├── Oxy Inference         unified API, catalogue, routing and usage-based service
├── Managed Inference     selected models served on infrastructure managed by Oxy
├── Dedicated Inference   private endpoints, reserved capacity and enterprise deployments
├── Alia                  assistant/product for people and teams
├── Codea                 coding and agent product
└── Alia Models           future real model family, only after genuine releases exist
```

`Relay` remains a provisional **internal data-plane name**. Do not make it the main public brand or expose it throughout marketing copy unless a separate naming decision approves that.

### Terms that must remain distinct

- **Oxy AI** is not a model.
- **Alia** is not the generic inference API.
- **Oxy Inference** is not a second control plane or second developer account system.
- **Oxy-hosted** means Oxy serves a model; it does not mean Oxy created that model.
- **Publisher**, **model**, **model revision**, **serving provider**, **deployment** and **routing profile** are different objects.
- `Automatic`, `Fast`, `Balanced`, `Quality`, `Coding` and similar modes are routing/product profiles, not models.
- `alia/*` is reserved for real Alia-owned or Alia-derived model releases with an artifact, revision and model card.

```text
Website
  → understand Oxy Inference
  → inspect models and pricing
  → read quickstart
  → open Oxy Console
  → create/select an Oxy Account
  → create an Oxy Application

  → add funds/configure limits

```

### Enterprise buyer

```text
Website
  → understand shared, managed and dedicated options
  → review trust/data/region information
  → submit sales or private-evaluation request
  → qualification/onboarding
  → Oxy Account/Application/contract created in the Oxy control plane
```

### Product user

```text
Website
  → learn about Alia or Codea
  → visit the product
  → select a product plan there
```

The website explains and converts. **Oxy Console configures and bills. The inference data plane executes. Alia consumes the platform.**

## Current state to replace carefully

The current site contains valuable visual and technical foundations, but its AI messaging no longer matches the target architecture:

- `src/pages/AIPage.tsx` describes Oxy AI as private/open models that can be inspected, fine-tuned and self-hosted, and makes broad training/privacy claims that cannot safely describe every third-party route.
- `src/components/ai/AIPageContent.tsx` is visually centered on a giant Alia mark and a prompt box, followed by only Alia, a generic API card and a duplicate developer-docs card.
- `src/data/ai.ts` defines the AI proposition as `Alia AI`, `API` and `Developer Docs`; it has no accurate representation of routing, providers, managed deployments, BYOK, pricing, regions, enterprise or future model publishing.
- `src/pages/AIPricingPage.tsx` calls `https://api.alia.onl/billing/plans?product=alia`; `/ai/pricing` is therefore Alia product-plan pricing rather than inference pricing.
- `src/data/content.ts` describes Oxy AI as `Private models, API and SDKs`, which is not accurate for a multi-provider platform.
- `src/pages/DevelopersPage.tsx` explains the general Oxy platform but does not provide a clear AI/inference quickstart or conversion path.
- AI/Alia wording is repeated across the homepage, navigation, footer/CMS seed, SEO, structured data and every locale.
- The app is prerendered, indexed with Pagefind and served from one repository for both `oxy.so` and `fairco.in`; new AI routes/content must preserve those constraints.

Do not discard the page's useful visual work by default. Reuse or repurpose components where they support the new story, but remove misleading product semantics.

# Non-negotiable invariants

- [ ] Oxy AI is presented as the umbrella platform, not as a fake model or only as Alia.
- [ ] Oxy Inference is presented as the public inference service.
- [ ] Oxy Website does not create a second account, organization, application, credential, balance or billing system.
- [ ] All configuration and customer billing CTAs ultimately enter Oxy Console/the Oxy control plane.
- [ ] Operational model, deployment, availability, policy and pricing data comes from an Oxy-owned customer-safe source of truth, not hand-maintained website constants.
- [ ] The site never exposes provider secrets, internal route IDs, wholesale costs or private commercial contracts.
- [ ] A model available internally to Alia is not automatically listed as publicly purchasable.
- [ ] A routing profile is never rendered as a model.
- [ ] Old aliases such as `alia-v1`, `alia-v1-pro` and `alia-lite` are not advertised as real Alia models.
- [ ] `alia/*` entries are not published until genuine model artifacts and release documentation exist.
- [ ] Route-specific provider, retention and training policies are not turned into false platform-wide claims.
- [ ] `zero retention`, `no training`, `EU-only`, `dedicated`, `SLA`, `SOC 2`, `HIPAA`, uptime, latency, throughput and similar claims appear only when verified and scoped correctly.
- [ ] No fake customer logos, testimonials, benchmarks, certifications or model counts are introduced.
- [ ] Prices are never invented or duplicated manually when the pricing service is authoritative.
- [ ] Every public capability has an explicit availability state.
- [ ] Essential content is present in prerendered HTML and does not depend on canvas or hydration.
- [ ] Reduced-motion, accessibility, mobile performance and SEO are first-class release gates.
- [ ] AI routes/content remain unavailable on the `fairco.in` host except for intentional cross-brand links.

# Availability and claim model

Create one shared vocabulary for services, models and capabilities:

```ts
type Availability =
  | 'available'
  | 'beta'
  | 'private_preview'
  | 'coming_soon'
  | 'internal_only'
  | 'deprecated'
```

Required behavior:

- [ ] `available` → show `Start building` or the real purchase/configuration CTA.
- [ ] `beta` → clearly label beta and link to the beta path.
- [ ] `private_preview` → show `Request access`/`Request evaluation`.
- [ ] `coming_soon` → show a waitlist/announcement CTA, not a checkout CTA.
- [ ] `internal_only` → do not expose as a purchasable public service/model.
- [ ] `deprecated` → show replacement and sunset information.
- [ ] Availability must be supplied by the public catalogue/content source, not inferred from whether a frontend route exists.
- [ ] Add a content/claims review checklist for every service before changing it to `available`.
- [ ] Add automated checks preventing `internal_only` catalogue objects from entering prerendered pages, sitemap, Pagefind or structured data.
