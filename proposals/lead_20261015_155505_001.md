### 🐞 Describe the bug

`UIManagerService` reads `PyRevitConfig.Load().RocketMode` in its constructor. The `SessionManager` is created per load before `LoadSession`, and the config cache is only cleared later (`ClearParserCaches`, then the "Re-read config" path in the UI build pass). If `rocketmode` is changed in `pyRevit_config.ini` from outside Revit (text editor, `pyrevit configs rocketmode disable`) and pyRevit is reloaded, the assembly build and the startup scripts run with the old value, and the new value only shows up afterwards in the UI pass. A second reload is needed to get a consistent session. Edits made in the Settings dialog go through the in-process service and are not affected.

Observed on the bench (rocket mode on, then `rocketmode = false` written to the INI while Revit was running, then Reload):

- the first line of the reload still says `Rocket mode: True` (constructor, no "Re-read config" prefix),
- the startup scripts of pyRevitCore and pyRevitTools ran on the shared `__pyrevit_session__` engine (`Engine cache hit for '...:IronPython:__pyrevit_session__'`), which is the rocket mode behaviour,
- only about 6 seconds later `Re-read config - ... Rocket mode: False` appears.

On the next reload, with no further edit, the constructor line says `Rocket mode: False` and the startup scripts get their own engines (`Engine cache cached a new engine for '...:IronPython:pyRevitCore'`).

### ♻️ To Reproduce

1. Enable debug logging and file logging. Start Revit with rocket mode on (the default) and open any project.
2. Edit `%APPDATA%\pyRevit\pyRevit_config.ini` outside Revit: add `rocketmode = false` under `[core]`.
3. Press pyRevit Reload.
4. In `%APPDATA%\pyRevit\<year>\pyRevit_<year>_<pid>_runtime.log` find the reload: the first `Rocket mode:` line says `True` and has no "Re-read config" prefix, the startup scripts hit the shared session engine, and `Re-read config ... Rocket mode: False` comes later.
5. Reload again: the first line now says `False`.

### ⏲️ Expected behavior

A reload reads the configuration once, before any service that depends on it is built, so assembly build, startup scripts and UI all use the same current value. Clearing the config cache at the top of the session load would be enough.
