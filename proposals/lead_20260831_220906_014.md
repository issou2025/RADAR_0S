## Context

Filed from lived experience driving `relay-xyz` against a vendored `.xyz/` install this session (aegis-sleuth-slack-bot repo, three QA rounds on a PR — agy, then Codex after a CommandCode/DeepSeek attempt hung). The harness worked correctly every time, but the **resolution path to get there** — find the harness, pick a gateway (turn-taker), pick a model within it — was slow, manual, and re-done from scratch on every single shell invocation. Three concrete friction points:

### 1. `find-harness.sh` has no memory across invocations
Every new Bash call in this session needed the full sequence again:
```bash
L="$HOME/.claude/skills/relay-xyz/find-harness.sh"
eval "$("$L" --env)"
cd "$HARNESS"
```
`$HARNESS`/`$TICK` are plain env vars — they don't survive into the next shell — so this ran a dozen-plus times in one session. Each run also unconditionally re-does a vendored-vs-live diff and prints `find-harness: vendored copy differs from or can't be compared to the live harness.` even when nothing has changed since the last check seconds earlier. There's no cached "I already resolved this, and nothing invalidating has happened since" state anywhere.

### 2. Picking a gateway (turn-taker) means reading source, not looking anything up
Each gateway — `agy-turn.sh`, `codex-turn.sh`, `commandcode-turn.py`, `aider-turn.sh` — has its own bespoke env-var contract (`AGY_AGENT` vs `CODEX_AGENT` vs `COMMANDCODE_AGENT`, `AGY_MODEL` vs `COMMANDCODE_MODEL` vs `AIDER_MODEL`). There's no single "what gateways exist, what do they need, what can they do" lookup — I had to `grep` `commandcode-turn.py` and `aider-turn.sh` mid-session to even discover the model-selection env var each one uses. That's tribal knowledge re-derived per session, not resolved once and reused.

### 3. Two disjoint, non-cached model catalogs
- `relay-automation/openrouter-model-aliases.yml` — a hand-maintained static file, fuzzy-matched by `resolve-model-alias.sh`, used only by the Aider/OpenRouter lane. Adding a model means manually appending a line **and** a test assertion (per the file's own header comment).
- CommandCode's model list is *only* discoverable live, via `cmd --list-models` (62 models, several sub-catalogs) — no static file, no alias table, nothing shared with the OpenRouter table even though several models overlap (e.g. `deepseek/deepseek-v4-pro` exists in both ecosystems under the same slug).

Resolving "I want DeepSeek v4 Pro" today means knowing *which* of two totally different mechanisms applies depending on which gateway you picked first — and neither result is cached for the next call.

## Net effect
"Harness -> gateway -> model" is three separate manual/re-derived lookups per session instead of one resolved-and-cached path. None of this is a correctness bug (the harness itself worked fine all three QA rounds) — it's pure resolution latency and repeated tribal-knowledge lookup that a cache layer would remove.

## Proposed strategies (pick one to sharpen, or combine)

**A — Cache `find-harness.sh`'s own resolution (narrowest, cheapest)**
Hash the resolution inputs (`$XYZ_HARNESS`, cwd, `.xyz/` presence + its version marker) and skip the vendored-diff comparison entirely when the hash matches a small cache file (e.g. `.tick/find-harness-cache.json` or `~/.cache/xyz-forge/...`, TTL or mtime-gated). Fixes friction #1 only. Small, safe, immediately useful regardless of what happens with B/C.

**B — One `resolve.sh` entrypoint spanning all three layers (medium)**
`resolve.sh --gateway <name> --model "<query>" --env` prints one block of exported env vars (harness + the chosen gateway's specific env-var contract + the resolved model id), built on top of A's cache. Replaces the current "locate script, eval, cd, then go read source to find the right env var name" dance with one call. This is the one I'd start with — it directly targets the actual dance I did by hand this session, and subsumes A as an implementation detail.

**C — Unify the two model catalogs (broadest)**
Merge `openrouter-model-aliases.yml` and CommandCode's live catalog into one registry (static file + a `refresh-models.sh` that repopulates it from each gateway's live listing, cached with an explicit refresh step rather than a live call every time). `resolve-model-alias.sh` becomes gateway-aware instead of OpenRouter-only. Highest payoff (one lookup mechanism instead of two, catches cross-gateway model-name collisions) but the largest surface — probably a phase-2 on top of B, not a first cut.

## Not proposing
Rewriting any existing turn-taker shim's actual execution/safety logic (path-allowlist, commit-bypass guard, worktree isolation) — none of that was the friction; it's purely the lookup path *before* a turn-taker ever runs.
