# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Early spatial plates never fire on Revit exports whose rel/units records trail the file — relax the prefix-walk guard**

*Project description:*
Follow-up to #518/#519, from the [1.519.1471 PSB smoke](https://github.com/bldrs-ai/Share/pull/1753): the smoke's wins landed (preview streams from the start; plates come out clean and correctly rotated — #517 confirmed; Total 53.4 s, the best PSB number yet), but **the plates still appear only after parsing**, not seconds in.

## Why

`maybeEmitEarlySpatialPlates_` gates on the prefix type-index holding `IfcProject` + `IfcUnitAssignment` + `IfcBuildingStorey` + `IfcRelAggregates`. The spatial *entities* sit at PSB's head (`IFCSITE` is record #211), but if the *relationship* records (`IfcRelAggregates`) — or the units pair — trail the file the way Revit writes most rel records (92–97% depth was measured for voids/materials), then no prefix generation ever qualifies and only the end-of-parse refresh emits. That matches the observed behaviour exactly.

**To confirm which gate binds** (needs the file, one line):

```
for t in IFCRELAGGREGATES IFCUNITASSIGNMENT IFCBUILDINGSTOREY IFCRELCONTAINEDINSPATIALSTRUCTURE; do printf '%s: ' $t; grep -obm1 "=$t(" PSB.ifc | cut -d: -f1; done
```

against the file size (902,406,xxx bytes) gives each record's depth fraction.

## Fix directions, by which gate binds

- **If `IfcRelAggregates` is the late one:** drop it from the guard and let the walk run on a *flat* tree — with no aggregates there is no parentage, so `parentOf` is empty, every spatial node is a root, and storeys (guaranteed present by the guard) emit as sibling plates banded on their placements + elevations. Coarse but structurally honest, and the refresh corrects hierarchy/collapse. The walk already tolerates an empty `childrenOf`; needs a test that a prefix with storeys-but-no-rels emits per-storey plates.
- **If `IfcUnitAssignment` is the late one:** the #519 units guard (added for the forward-reference case, Codex P2) is doing its job but the cost is the whole skeleton. Options: accept it (correct-but-late beats early-but-1000×), or resolve the scaling factor without the full prep — the units chain (`IfcProject → IfcUnitAssignment → IfcSIUnit`) is 3 records; a targeted early probe for just those, independent of generation prep, would unlock the walk without weakening the scale guarantee.
- Either way the re-emission/replace-by-expressID contract (#519) already covers the correction pass; no Share change needed.
