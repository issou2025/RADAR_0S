## Project Understanding
You need assistance with: 
**[SEC-006] Hardcoded Places API key — replace with build-time injection when ijudi ships**

*Project description:*
**Type:** Security — Hardcoded API Key
**Priority:** P1 — exposed credential in source, potential for unauthorised billing
**Related to:** SEC-001 (izinga-android key, separate instance)

**File:** `lib/components/ijudi-address-input-field.dart`
**Pattern:** `static const kGoogleApiKey = "AIzaSy..."` — Places API key hardcoded as a Dart constant, used in both `PlacesAutocomplete.show()` and `GoogleMapsPlaces` instantiation.

**Risk:** If this repo is public, the key is exposed in version history and to any reader. Even in a private repo, hardcoded keys in source are a security anti-pattern — rotation requires a code change + redeploy.

**Required actions:**
1. Confirm current repo visibility (public or private).
2. In Google Cloud Console, apply API restrictions to this key: scope to Places API and Geocoding API only — remove any open/unrestricted access.
3. Assess whether to move the key out of source into a build-time injected config (e.g. `--dart-define` or a CI secrets store) rather than a hardcoded Dart constant.
4. If the repo is or has ever been public, treat the current key as compromised: rotate it and apply the restrictions to the new key.

**Note:** Do not address this in the INF-005 cost-fix PR — this is a separate concern and should not block INF-005's merge. Track and fix independently.

**Identified by:** iZinga Security carry-forward audit, 2026-10-01
