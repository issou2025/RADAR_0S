<html><head></head><body><h2>Proposal: Add a Codebase Maturity Matrix</h2>
<h3>Motivation</h3>
<p>It would be valuable to have a simple maturity matrix that describes the current state of the codebase and provides a clear path for improvement.</p>
<p>The goal is not to introduce additional bureaucracy or strict requirements, but to make the project's strengths, gaps, and priorities easier to understand, especially for new contributors.</p>
<p>A maturity matrix could also help contributors identify areas where they can make meaningful improvements.</p>

<h3>Benefits</h3>
<p>A maturity matrix could help us:</p>
<ul>
<li>Make the current state of the project easier to understand.</li>
<li>Provide a shared definition of what "mature" means for the project.</li>
<li>Prioritize technical improvements.</li>
<li>Help new contributors find areas where they can contribute.</li>
<li>Track progress over time.</li>
<li>Turn broad technical goals into concrete, actionable issues.</li>
</ul>
<h3>Open questions</h3>
<p>Some things we could discuss before implementing this:</p>
<ul>
<li>Which dimensions should be included?</li>
<li>How many maturity levels make sense?</li>
<li>Should the matrix be maintained as documentation or generated from automated checks?</li>
<li>Should each level have objective, measurable criteria?</li>
<li>Should the matrix be used as a roadmap for future improvements?</li>
</ul>
<p>This is intended as a starting point for discussion rather than a prescriptive framework. I'd be happy to help draft the initial matrix and iterate on it based on the project's needs.</p>
