## Is your feature request related to a problem? Please describe

The `family-editing` skill covers opening a family, parameters, types, formulas and loading it back. It does not cover creating family content, which is where an agent needs the most help. Everything below was found by trial and error while building parametric families from scripts. Checked against `upstream/develop` (784c29d37): the skill has no section on geometry, and a search of `pyrevitlib/pyrevit/agent` for `ReferencePlane`, `NewExtrusion`, `NewAlignment`, `FamilyLabel` and `AssociateElementParameterToFamilyParameter` finds nothing. `pyrevit.revit.db.query.get_family_label_parameters` and the shared-parameter helpers in `ensure.py` exist, but there is nothing that creates labelled planes or locked sketches.

Missing topics:
- **Geometry:** reference planes, dimensions with `FamilyLabel`, locking sketch edges with `NewAlignment`, extrusions whose start/end are associated with parameters, and the need for short "sliver" edges to pin vertices of sloped solids.
- **Shared parameters in families:** `app.SharedParametersFilename` must be set to read definitions and should be restored afterwards (it is a user setting); `fm.AddParameter(ExternalDefinition, group, isInstance)`; GUID stability.
- **Visibility and graphics:** `FamilyElementVisibility` (detail levels, plan/section flags), subcategories, line patterns, materials with appearance assets (`AppearanceAssetEditScope`).
- **Nested families:** `LoadFamily(host_doc, handler)` outside a transaction, `NewFamilyInstance`, aligning references, `AssociateElementParameterToFamilyParameter`, `IS_VISIBLE_PARAM`.
- **Limits that surprised me:**
  - A category such as Stairs cannot be assigned to a loadable family (`ArgumentException: The input category id cannot be assigned as the new category for this family`).
  - Revit formulas have no `<=` / `>=`.
  - `FamilyManager.CurrentType` and `Document.Regenerate()` need an open transaction in the family document.
  - `Visible = No` forms still have geometry in the family editor; only placed instances show the effect.
  - A family loaded from an unsaved family document is named after the document title (`Family24`) and must be renamed afterwards; nested shared families have the same problem and must be renamed before the host is loaded.
  - `FamilyManager.SetFormula` raises `ArgumentException: It is an invalid formula string.` without naming the parameter or formula, so a batch of formulas gives no hint which one failed.

## Describe the solution you'd like

- A new `family-geometry` skill under `pyrevitlib/pyrevit/agent/skills/` (the build already validates skills) with working snippets for the topics above, and a short pointer to it from `family-editing`.
- Optionally, small helpers in `pyrevit.revit.db.create` / `update` for the patterns that every family build repeats: a labelled reference plane, a dimension with `FamilyLabel`, a locked sketch, `set_formula(fm, param, formula)` that re-raises with the parameter name and formula, and `load_family(fdoc, doc, name=...)` that renames the loaded family.

## Describe alternatives you've considered

- Only expand `family-editing` instead of adding a skill. That would make a skill that is loaded for every simple "add a parameter" task much larger; a separate skill keeps the common case small.
- Leave it to the agent to discover the API. This is what happens now, at several debugging runs per topic.
