# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**place_family: wall-hosted doors/windows placed at wrong location + ID-read crash on some hosts**

*Project description:*
Found while drawing a test building via the MCP client (2026-07-30).

**Bug 1 — silent mis-placement:** `place_family` (revit_mcp/placement.py) for wall-hosted
families (doors placed via `doc.Create.NewFamilyInstance(point, symbol, host_wall, level, StructuralType.NonStructural)`)
ignores the requested `location` and places the instance near wall-curve origin instead.
Reproduced twice (garage door + facade door on a perimeter wall) — `Actual Location` in the
response even self-reported the wrong point (0,0,~0) instead of the requested x.

**Bug 2 — crash on interior walls:** for doors/windows hosted on *interior* partition walls,
the same call throws `ValueError: Cannot read ID value from: FamilyInstance` after creation,
which appears to roll back the transaction (element does not exist afterward). Reproduced on
3/3 interior doors and 3/3 windows in the same session.

**Workaround used:** bypass `place_family` entirely, call `execute_revit_code` with raw
`doc.Create.NewFamilyInstance(...)` directly — placement then lands exactly on the
requested point (verified by reading `Location.Point` back). This confirms the bug is in
the `place_family` route, not the underlying Revit API pattern.

Likely a Revit 2027 API-overload resolution issue (see the existing `ElementId`/`Int64`
note already in `code_execution.py`) — `get_element_id_value()` or the overload picked by
`NewFamilyInstance` may need the same 2027-safe treatment.

Not fixed in this session — flagging so it doesn't get re-discovered from scratch next time.
