# Summary
- **Context**: The `/typeset` page is a live typography playground: seven `<select>` controls drive a JS-side state object that styles a preview (`assets/typeset-preview.js`) and generates copyable code snippets. The state lives in a `<head>` IIFE that persists across client-side navigations, while the page DOM is remounted by React on every SPA navigation.
- **Bug**: The page's `on_mount` script re-applies the persisted JS state to the preview and code blocks but never syncs the freshly mounted select controls to that state, and the syncing function is not even exported on `window.typesetPreview`.
- **Actual vs. expected**: After the user changes selections (or clicks Shuffle) and then navigates away and back, the preview and "Get Code" output show the persisted (non-default) state while all seven selects display the Python defaults again — expected behavior, demonstrated by the sibling `/create` page, is that `on_mount` syncs the controls to the persisted state.
- **Impact**: The controls, the live preview, and the copyable code output visibly disagree after any SPA round-trip; a user who tuned settings, left, and returned sees default-looking selects while the preview/code silently use their previous choices, and any copy they make does not match what the controls appear to say.

# Explanation
- `assets/typeset-preview.js` stores state in a `<head>` IIFE (`window.typesetPreview.state`), so it persists across SPA navigations.
- When navigating away and back, React remounts the `/typeset` DOM, creating new `<select>` elements that start at their `default_value` (uncontrolled inputs).
- `native/pages/typeset.py`’s `on_mount` hook reruns on each SPA visit and calls `applyAll()` and `renderCodeBlocks()`, which update the preview and code output from the persisted JS state.
- Because there is no `on_mount` call that sets the selects’ `.value` from the persisted state (and the sync function isn’t exported), the UI controls display defaults while preview/code reflect prior selections.

## Codebase Inconsistency
The sibling `/create` page previously had the same pattern and was fixed by exporting and calling a `syncAll()` API in `assets/theme-preview.js` and invoking it from `native/pages/create.py` `on_mount`. `/typeset` never received the equivalent `syncAll` export/call.

# Recommended Fix
Export a sync entry point from `assets/typeset-preview.js` (mirroring `theme-preview.js`'s `syncAll`) and call it from `on_mount` after the registries are injected:

```js
window.typesetPreview = {
    ...,
    syncAll: function () {
      if (!ensureDefaults()) return;
      syncSelectsToState();  // <-- FIX 🟢 pulls the persisted state back into the remounted selects
      applyAll();
      renderCodeBlocks();
    },
};
```

```python
if (window.typesetPreview) {
    window.typesetPreview.syncAll();  // <-- FIX 🟢 replaces the bare applyAll() call
}
```

# History
This bug was introduced in commit e6118b (e6118bff4d450e0cdbf3d644576c527f86d27e6d), the commit that created the `/typeset` typography playground (`native/pages/typeset.py`, `assets/typeset-preview.js`, plus registry/CSS/navbar wiring). The feature shipped with the broken lifecycle pattern from day one: the `on_mount` script only calls `window.typesetPreview.applyAll()` on remount, and although the IIFE defines `syncSelectsToState()` (and even calls it once at boot, where it's a no-op on the not-yet-mounted DOM), the `window.typesetPreview` export object exposed only `state`, `applyAll`, `shuffle`, and `getCode` — so the freshly remounted uncontrolled selects (seeded with `default_value=` Python defaults) could never be re-synced to the persisted JS state after an SPA navigation.

Later commits (`5ffa9e5`, `8d7027f`, `c1722fd`, etc.) reworked the preview JS and page but preserved the identical broken pattern — `on_mount` kept calling only `applyAll()`/`renderCodeBlocks()`, and `syncSelectsToState` was never added to the export object — so none of them introduced or fixed the bug. Notably, the sibling `/create` page had the same defect and was fixed in `a7c0cdb` (adding `syncAll()` to `theme-preview.js` and its `on_mount`), but that fix was never ported to `/typeset`.
