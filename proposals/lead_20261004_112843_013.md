## Description

Adopt [Maestro](https://maestro.dev) (free & open source, Apache-2.0) to author scripted, repeatable walkthroughs of key user workflows and record them as demo videos. The intended loop: a scenario is described → a Maestro YAML flow is written → `maestro record` produces a video (with built-in tap indicators + captions) → a developer reviews and edits the on-screen hints → the clip is shared.

This was evaluated against two alternatives:
- **Recording the existing `integration_test/` suite as-is** — rejected: tests force `setSurfaceSize(1600×4000)` (not a phone), drive many actions via direct `onPressed!.call()` / `setShadFormValues` (state changes with no visible cause), use synthetic pointers (no visible tap), and `pumpAndSettle` collapses animations. Output is not demo-grade.
- **A bespoke Flutter-native demo layer** (pointer-ripple overlay + caption overlay + phone surface, recorded via `adb screenrecord`) — viable and stays in the Dart stack, but ~2-3 days of harness work plus per-scenario authoring, and we'd reimplement tap indicators/captions Maestro gives for free.

Maestro chosen: free for local authoring + `maestro record` (only Maestro **Cloud** is paid, and not needed here); polished recorder out of the box; simplest per-scenario authoring.

**Why deferred:** Maestro is accessibility-tree based and **cannot see Flutter `ValueKey`s**. Non-text controls must expose `Semantics(identifier:)` / `Semantics(label:)` (Flutter 3.19+; we're on 3.41.9). The notable controls in the target flows — the venue `ShadSelect`, the schedule `ShadTimePicker`/date pickers (the same controls our Dart tests already bypass as "fragile") — need semantic identifiers added across many widget files. High blast radius → schedule deliberately, not as a drive-by.

## Scope

**In scope (later):**
- Add Maestro as a dev tooling dependency + a `justfile_maestro.just` (or similar) with record/run recipes, pointed at the disposable isolated test server (`scripts/start_test_server`).
- Add `Semantics(identifier:)`/`label:` to non-text controls in the target flows (venue select, time/date pickers, icon-only buttons) — additive, behavior-preserving.
- Author Maestro flows (`.maestro/` dir) for the initial scenarios:
  - Create a new camp event
  - Reschedule a single occurrence
  - Reschedule an event (incl. behavior when an occurrence is already overridden)
- A short developer guide (`docs/`) for: scenario → flow → `maestro record` → edit hints → share, including target device/screen size (phone-class emulator).

**Out of scope:**
- Maestro Cloud / hosted parallel execution.
- Replacing the existing `integration_test/` assertion suite — Maestro flows are for **demos**, not a substitute for functional tests.
- iOS recording setup (revisit once the Android path is proven).

## Acceptance criteria

- [ ] Maestro installed and a documented `just` recipe records a phone-sized video against the isolated test server.
- [ ] `Semantics` identifiers added to the controls the initial flows touch (venue select, schedule pickers, icon-only affordances), with no behavioral change and existing tests still green.
- [ ] At least the three flows above authored and each produces a reviewable `maestro record` video.
- [ ] Developer guide in `docs/` covering the scenario → flow → record → edit-hints → share loop.

- Maestro Flutter support: https://docs.maestro.dev/platform-support/flutter (keys unsupported; use `Semantics` identifier/label)
- Pricing: https://maestro.dev/pricing (core CLI + `maestro record` free; Cloud paid)
- Existing scenario coverage to mirror: `app/integration_test/workflow_createcamp_camp_create_test.dart`, `workflow_editevent_section_editors_test.dart`, and the camp-schedule reschedule work on `feature/705-camp-schedule-section-editor`.
