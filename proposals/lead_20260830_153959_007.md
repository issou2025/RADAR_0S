*Project description:*
## Problem Statement

Users have low-resolution images (compressed, screenshots, old photos) and want to enlarge them without cloud upload or quality artifacts (blur). Existing solutions require internet, send images to servers, or bundle heavy models in the app with no choice. They need an on-device, privacy-preserving Upscale for single images on Android (Flutter) with downloadable Models they can choose, stored locally, verifiable, and removable.

## Solution

A Flutter cross-platform app (Android-first MVP) that lets users pick an image from Gallery / Camera / Share-intent (single image, max 4096×4096), choose a Model from a versioned Catalog hosted on GitHub Releases, Download the Model on demand (with resume, SHA256 verification, delete/clear cache), and Upscale it on-device via the TFLite Engine. The default CatalogEntry `realesr-general-x4v3 FP16 3.5MB` is bundled so the app works offline; `x4plus 16.7MB` is on-demand. Large images are processed as Tiles (128×128 input → 512×512 output, Scale 4, overlap 32, tilePad 10) sequentially in an Isolate with progress, then stitched and saved to Gallery as PNG (with EXIF preservation option) and shareable. UI is two tabs (Upscale / Catalog) built with impeccable design tokens. Permissions are scoped and requested on demand; settings expose GPU delegate toggle and cache limit.

## Implementation Decisions

- **Modules:**
  - `CatalogService` — fetch `catalog.json` from `raw.githubusercontent.com` (24h cache), list CatalogEntry, Download with Range resume to `getApplicationSupportDirectory()/models/`, SHA256 verify, delete/clear, version check. Single source of truth.
  - `TfliteEngine` — wraps `tflite_flutter` Interpreter; `load(modelPath)`, `infer(tile)` (NHWC 0-1 float32 `[1,128,136,3]`→`[1,512,512,3]`), GPU delegate (`GpuDelegateV2`) with XNNPACK CPU fallback (4 threads), Isolate execution.
  - `UpscalePipeline` (highest seam) — orchestrates: validate 4096 limit → split into Tiles (128, overlap 32, pad 10) → sequential Engine inference → feather blend stitch → save. Reports progress per tile. Handles OOM fallback (tile 64) and error mapping.
  - `ImageIoService` — pick via `image_picker`, `receive_sharing_intent`, decode/encode via `image` package, EXIF handling, save via `MediaStore` scoped storage.
  - `SettingsService` — persists GPU toggle, cache limit, refresh interval.
  - UI: two tabs `Upscale` / `Catalog` with impeccable tokens (design system: typography, spacing, color, icons), not templated defaults.

- **Interfaces:**
  - `CatalogService.fetchCatalog() -> List<CatalogEntry>`; `download(entry, onProgress) -> File`; `verify(File, sha256) -> bool`; `delete(id)`; `clearCache()`.
  - `TfliteEngine.load(path)`, `setUseGpu(bool)`, `run(tileBytes) -> tileBytes`, `close()`.
  - `UpscalePipeline.upscale(imageBytes, catalogEntryId, onProgress) -> upscaledBytes` — the primary test seam.

- **ADRs respected:** ADR-0002 (GitHub Releases Catalog), ADR-0003 (TFLite with Isolate), ADR-0004 (CatalogEntry schema + bundled general-x4v3 FP16 3.5MB + x4plus w8a8 16.7MB + tile 128/32), ADR-0005 (resumable Download + impeccable two-tab UI + OOM handling), ADR-0006 (Flutter cross-platform `lib/core` + `lib/features`).

- **Schema contracts:**
  - `catalog.json` (hosted in Release): `Array<CatalogEntry>` where `CatalogEntry = {id, name, scale:4, type: 'general'|'anime'|'face', inputSize:128, fileSize, sha256, url, license, version, bundled?:bool}`. Verified by SHA256; `fileSize` matches asset. Example in `docs/catalog.example.json`.
  - Image I/O: input max 4096×4096, tile input 128×128 RGB 0-1 NHWC, tile output 512×512, stitched full output (e.g., 1024→4096).

- **Specific interactions:**
  - Catalog refresh on app open (if cache expired) + manual pull; Download shows progress, supports cancel/resume; mismatch → delete file + toast retry.
  - Upscale flow: pick image → select active Model (defaults to bundled) → upscale button disabled until Model ready → Isolate tiler → progress 0..1 per tile → preview slider → save to Gallery (PNG default) → share via `share_plus`.
  - Permissions: request Gallery/Camera only on action; denial shows rationale.
  - Attribution: `assets/NOTICES` aggregates BSD-3 (Real-ESRGAN) + Apache-2 etc., linked from About and per CatalogEntry `license`.

## Testing Decisions

- **What makes a good test:** Only test external behavior at seams, not internal tiling loops or interpreter internals. Assert on observable outcomes: `fetchCatalog` returns entries, `download` writes verified file, `upscale` returns upscaled bytes of expected dimensions (e.g., 128→512) with seam-free stitch for synthetic pattern, and error paths (over-size, corrupt model, OOM) map to user-visible messages. Do not assert on widget internals or file paths; use fakes for HTTP/disk/interpreter.

- **Modules to be tested:**
  - Primary: `UpscalePipeline` (highest seam) — integration of tiling + engine fake + catalog fake.
  - Secondary: `CatalogService` — fetch, download resume, SHA256 failure, delete/clear.
  - Secondary: `TfliteEngine` — load, GPU fallback, `run` shape contract (stub interpreter).

- **Prior art:** No prior tests in this codebase (greenfield). Follow Flutter conventions: `flutter_test` for pipeline, `fake` HTTP via `http_mock_adapter` or hand fake, temp dir via `path_provider` mock, stub interpreter via interface (no real `.tflite` in unit tests). Add one golden image test for tiler feather blend and one for 4096 OOM fallback behavior (simulated by fake engine throwing OOM).

## Out of Scope

- Batch processing of multiple images (single image only in MVP).
- Anime and face Models (RealESRGAN anime_6B / GFPGAN) — deferred; catalog will list only 4x general models in MVP.
- Cloud/remote Upscale or Firebase/CDN catalog — GitHub Releases only.
- Video upscaling.
- ×2 / ×3 Scales (all verified TFLite are 4x; no native ×2 TFLite per research).
- Monetization, analytics, crash reporting.
- iOS/Desktop builds (structure is cross-platform but MVP builds/tests Android only).

## Further Notes

- Research: `docs/research/tflite-catalog.md` verifies all trusted TFLite are 4x 128→512; anime has no official TFLite (requires custom ONNX→TFLite). General-x4v3 is ~12× faster than x4plus (1-2ms vs 13-133ms per tile) — hence the bundled default.
- Impeccable UI: leverage `ui-ux-pro-max` skill for tokens; avoid templated defaults.
- Future work: pipeline to convert ONNX anime model to TFLite FP16, add `realesr-anime` on-demand entry after validation.
