# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Flutter: every call throws MissingPluginException on macOS (and other non-mobile platforms), leaving the app on a black screen**

*Project description:*
## Summary

`feedbackkit_flutter` declares only Android and iOS in its `flutter.plugin.platforms`, but its Dart API calls the `feedbackkit` method channel unconditionally. In a Flutter app that also builds for **macOS** (and presumably Windows, Linux and web), every call throws `MissingPluginException`. If the app awaits `FeedbackKit.configure()` before `runApp()`, as the README setup does, the app never draws its first frame: **the macOS window stays black**.

## Environment

- `feedbackkit_flutter` from git, `flutter/feedbackkit_flutter` at `e9068358c71f75ac84adcfe4c489a68c624c9c14`
- Flutter 3.47.6 (stable), macOS 27 release build (sandboxed, Developer ID signed)

## Reproduce

1. Create a Flutter app with macOS enabled and add `feedbackkit_flutter`.
2. In `main()`:
   ```dart
   Future<void> main() async {
     WidgetsFlutterBinding.ensureInitialized();
     await FeedbackKit.configure(const FeedbackKitConfiguration(endpointUrl: '…', projectKey: '…'));
     runApp(const MyApp());
   }
   ```
3. `flutter run -d macos` (or a release build).

**Expected:** the app runs on macOS with feedback features unavailable (a no-op), or the package documents that it must be guarded.

**Actual:** black window. Running the app binary from a terminal shows:

```
[ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception: MissingPluginException(No implementation found for method configure on channel feedbackkit)
#0      MethodChannel._invokeMethod (package:flutter/src/services/platform_channel.dart:364)
#1      main (package:…/main.dart:21)
```

## Affected API

Everything that goes over the channel, not just `configure`. In our app these all needed guarding: `configure`, `setTheme`, `enableFixVerification`, `enableShakeToReport` / `disableShakeToReport`, `setUser`, `setCurrentScreen`, and `FeedbackKitNavigatorObserver` (which calls `setCurrentScreen` on every route change).

## Suggested fix

Any of these would prevent it:

1. **Make unsupported platforms a no-op in the Dart layer** (preferred): check `defaultTargetPlatform` / `kIsWeb` once and short-circuit every method (and the navigator observer), or catch `MissingPluginException` in the channel wrapper. Perhaps expose `FeedbackKit.isSupported` so apps can hide feedback UI.
2. Register stub implementations for macOS / Windows / Linux / web in `pubspec.yaml`.
3. At minimum, say in the README that the package is Android/iOS-only and that calls must be guarded on other platforms.

## Workaround (what we shipped)

```dart
// FeedbackKit only ships Android and iOS implementations.
final bool feedbackAvailable = Platform.isIOS || Platform.isAndroid;

if (feedbackAvailable) await FeedbackKit.configure(...);
navigatorObservers: [if (feedbackAvailable) FeedbackKitNavigatorObserver()],
```

Found in Waypack's Mac app, where it affected every macOS build since FeedbackKit was added (fixed on our side in tianhaoz95/waypack@fbd2323).
