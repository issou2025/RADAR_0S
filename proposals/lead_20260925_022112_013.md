# Project Proposal — Python Automation

## Project Understanding
You need assistance with: 
**feat(cli): expose installed commands and executable versions**

*Project description:*
Use `narwhal --help` as a discovery point for the installed command suite and provide an executable `--version` interface. This is an interface enhancement for operators and automation.

At the referenced repository snapshot, [pyproject.toml declares six entry points](https://github.com/athrael-soju/Narwhal/blob/1317f131deecd249195c191f505509324c6663a2/pyproject.toml#L56): `narwhal`, `narwhal-engine`, `narwhal-check`, `narwhal-attest`, `narwhal-serve` and `narwhal-profile`. The [root parser](https://github.com/athrael-soju/Narwhal/blob/1317f131deecd249195c191f505509324c6663a2/src/narwhal/dev/cli.py#L17) exposes only the `dev` command. Operators looking for production serving, profiling or deployment checks must find those executables through the documentation or shell environment.

The six parsers currently offer help but use packaging tools for version discovery. The [installation guide](https://github.com/athrael-soju/Narwhal/blob/1317f131deecd249195c191f505509324c6663a2/docs/Install-from-PyPI.md#L5) tells operators to run `python -m pip show narwhal-inference`. That reports the distribution selected by the invoked Python interpreter; an executable version command would identify the Narwhal installation behind the executable actually selected by the shell. This matters when router and development environments coexist.

A bounded implementation can add a short installed-command inventory to root help while preserving the existing command paths. Evaluate forwarding subcommands separately if they would improve the supported interface. Use distribution metadata as the single version source, with a clear behavior for source checkouts whose package metadata is unavailable.

Acceptance and regression criteria:

- `narwhal --help` names all six installed entry points and their operator-facing purposes.
- Each installed executable accepts `--version` and exits successfully before reading fleet files, probing ports or importing GPU runtime packages.
- Version output identifies the distribution and version for that executable's environment.
- Existing flat commands and `narwhal dev` invocations preserve their behavior.
- Installation and CLI references use the executable version interface where it helps identify the active installation.
- Cover version output from an installed wheel and help/version operation in a CPU-only environment.

The proposal targets the pinned repository interface.

Audit scope: the CLI implementation reviewed in PR #100 at commit `1317f131deecd249195c191f505509324c6663a2`. Linked source lines identify the audited version for triage.
