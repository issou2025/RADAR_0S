# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**多 Library 与 WebDAV 远程库源**

*Project description:*
## Problem Statement

用户希望在应用内使用自建 WebDAV（NAS / Nextcloud 等）作为漫画来源，而当前产品只有单份 Library、多个本地 Saved path，扫描与阅读均绑定本机文件系统。无法登记远程根、无法按库隔离配置，也无法在线流式阅读远程 Comic。

## Solution

引入趋近 Komga 的多 Library 模型（一个 Library root = 一个 Library，Local 或 WebDAV Remote），在 Rust core 经统一 Resource access 对接本地 FS 与 `reqwest_dav`。用户可切换 Current library、为每库配置 Supported resource formats，对远程库做可达时的 Library sync 与纯流式阅读；浏览/搜索默认当前库，Reading history 全局。

## User Stories

1. As a user, I want multiple Libraries, so that different roots can have different settings.
2. As a user, I want each Library to have exactly one Library root, so that the mental model matches Komga-style libraries.
3. As a user, I want to create a Local library from a folder on disk, so that my existing workflow still works.
4. As a user, I want existing Saved paths migrated into Local libraries, so that I do not lose my library after upgrade.
5. As a user, I want to create a Remote library by entering a WebDAV root URL, username, and password, so that I can use my NAS or Nextcloud.
6. As a user, I want passwords stored in platform secure storage, so that credentials are not kept in plaintext settings.
7. As a user, I want HTTPS by default, so that credentials and content are protected in transit.
8. As a user, I want to explicitly allow HTTP for a Remote library, so that LAN NAS without TLS still works.
9. As a user, I want to switch Current library, so that browse and search show one library at a time.
10. As a user, I want Reading history to remain global across Libraries, so that I can resume recently read comics regardless of which library is selected.
11. As a user, I want Series never to span Libraries, so that folder-based series stay within one root.
12. As a user, I want per-Library Supported resource formats, so that one library can allow PDF while another only allows archives.
13. As a user, I want Remote library first-slice formats to be archive + PDF + EPUB (no remote image folders), so that streaming stays tractable.
14. As a user, I want Library sync to default to the Current library, so that I do not hammer every WebDAV root at once.
15. As a user, I want an option to sync all Libraries, so that I can refresh everything when I choose.
16. As a user, I want Remote Library sync to add/update/remove comics when the root is reachable, so that the catalog mirrors the remote tree.
17. As a user, I want unreachable Remote libraries to be skipped without deleting their comics, so that a network blip does not empty my library.
18. As a user, I want sync to register remote comics lightly (path, size, mtime, etc.) without fully parsing every file, so that sync is affordable on large remotes.
19. As a user, I want page counts and richer metadata filled on first open when needed, so that I can still read without a heavy sync.
20. As a user, I want comicId derived from a normalized WebDAV URL for remote comics, so that identity stays location-stable like local paths.
21. As a user, I want to open a remote Comic and read pages via online streaming, so that I do not need a full local copy.
22. As a user, I want remote reading to go through the same Read session model (comicId only), so that UX matches local reading.
23. As a user, I want cover/list thumbnails for remote comics to use placeholders until generated, so that sync stays light.
24. As a user, I want thumbnails generated on first need into the existing local thumb cache, so that list UI stays unified with local comics.
25. As a user, I want Flutter cover and reader widgets to stay unified behind ports, so that local vs remote is not two UI stacks.
26. As a user, I want to remove a Library and have only that library’s comics/series cleared, so that other libraries are unaffected.
27. As a user, I want clear errors for auth failure, TLS problems, and unreachable hosts, so that I can fix WebDAV settings.
28. As a user, I want to cancel an in-progress Library sync, so that a slow WebDAV listing does not block me.
29. As a developer/agent, I want a single Resource access seam (list/stat/open-stream) with Local and WebDAV implementations, so that sync and reader tests do not need a real server.
30. As a developer/agent, I want WebDAV implemented in Rust core with reqwest_dav, so that I/O stays aligned with ADR-0002.
31. As a user, I want Healthy mode to still hide r18 comics in browse/search/history, including remote-origin comics.
32. As a user, I want Metadata field locks and Metadata refresh to keep working for remote comics once a resource can be opened via Resource access.
33. As a user, I do not need WebDAV backup of settings/DB in this delivery, so that scope stays focused on remote library source.
34. As a user, I do not need remote image-folder comics in the first slice, so that PROPFIND/page streaming complexity stays bounded.

## Implementation Decisions

- Introduce multi-Library domain model: one Library root per Library; kinds Local | Remote (WebDAV). Saved path remains a legacy alias for a local root only.
- Migrate today’s many Saved paths under one implicit library into one Local library per former root (or an explicit migration mapping documented in implementation), preserving comics where identity still matches.
- Move Supported resource formats from a single app-global preference to per-Library configuration; Remote libraries default to archive + pdf + epub enabled, folder disabled / unavailable.
- Current library selection is persisted; browse/search default to Current library; Reading history is global; Series membership is library-scoped.
- Library sync targets Current library by default; optional sync-all; per remote root, on transport/auth failure skip that library and do not orphan-delete its comics.
- Amend comic identity (ADR-0001): comicId from normalized location key (local path or WebDAV resource URL). Local thumb cache paths never participate in identity.
- Add Resource access port in core: list, stat, open-stream. Local FS implementation preserves current behavior; WebDAV implementation uses reqwest_dav with Basic auth.
- Remote read is pure streaming through Resource access into existing format backends where feasible; no whole-comic disk mirror as the primary model.
- Sync for remote is lightweight registration; deferred parse/page_count on first successful open with write-back under existing metadata lock rules where applicable.
- Thumbnails: no generation during remote sync; on first need, stream enough to build cover, store in existing local thumbnail cache; do not adopt cached_network_image for the main remote path.
- Credentials: Basic only for v1; HTTPS default; explicit user opt-in for HTTP; secrets in platform secure storage; core receives secrets at use-time via FRB without persisting plaintext in SQLite.
- UI: library switcher / management; add Remote library form (URL, username, password, allow HTTP); reuse existing cover/reader widgets against unified providers/ports.
- Documentation already updated as part of grilling: CONTEXT.md, product-positioning.md, ADR-0001 revision, ADR-0008.
- Out-of-band: WebDAV backup of settings/DB is a separate future issue.

## Testing Decisions

- Good tests assert external behavior at the highest seam: Resource access (list/stat/open-stream) and Library sync / Read session outcomes — not reqwest_dav XML parsing internals or Flutter widget trees for protocol details.
- Prefer a fake/in-memory Resource access implementation for core tests of: lightweight remote sync plan (add/update/delete when “reachable”), skip-without-delete when marked unreachable, deferred page_count write-back, streaming open for reader backends that accept streams/bytes.
- Reuse prior art: Rust TempDir + scan/plan/writer style tests for Local path; Dart LibrarySyncCoordinator + injectable FRB adapter for progress/cancel orchestration; do not require a live WebDAV server in CI.
- Optional contract tests against a mocked HTTP layer (e.g. wiremock) for reqwest_dav adapter only if kept thin; keep them at the WebDAV client adapter boundary, not duplicated through UI.
- Migration tests: former Saved paths become Local libraries; existing comicIds for local paths unchanged.

## Out of Scope

- WebDAV backup/restore of settings, SQLite, or reading history
- Official cloud accounts, storefront, or hosted sync
- Remote image-folder (dir) comics in the first slice
- Digest auth, client certificates, OAuth/OIDC
- Whole-comic disk mirroring as the primary remote mode
- Using cached_network_image (or Flutter HTTP ImageProviders) as the main remote page/cover pipeline
- Changing content-hash identity
- Web as a target platform for WebDAV CORS scenarios
