# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Ship a sideloadable biotope APK so reviewers can run the app without a toolchain**

*Project description:*
Judges and reviewers currently have no way to run biotope without a full Flutter + Android SDK toolchain. nao is a URL and needs nothing; biotope is a build-from-source wall. Hosting it as a web app is deliberately deferred (#283), so a **sideloadable APK is the only realistic path** to putting the app in a reviewer's hands.

Findings below are measured against `main` @ `5a5af7c` on 2026-08-02, in support of #328 / PR #374.

## The build itself

Must run on the **Windows** host — WSL has Flutter 3.41.4 but no Android SDK (`cmdline-tools component is missing`), and the SDK lives in the Windows toolchain.

```powershell
. .\scripts\biotope-env.ps1          # flutter, java, android-sdk on PATH for this shell only
cd apps\biotope
flutter pub get
flutter build apk --release
```

Output: `apps\biotope\build\app\outputs\flutter-apk\app-release.apk`

Prefer the plain universal APK over `--split-per-abi` — one file that works on any device beats three files plus an explanation of which to download.

## Four traps, in priority order

### 1. The backend is baked in at build time 🔴

`.env.public` is a **bundled Flutter asset** (`apps/biotope/pubspec.yaml:85`), loaded at runtime by `dotenv.load(fileName: '.env.public')` (`lib/main.dart:22`). Whatever it contains at build time is permanent in that APK.

It currently reads `SUPABASE_URL=https://bewwvcksgpxoomyjavjp.supabase.co` — correct. But if anyone flips it to `10.0.2.2:54321` for local dev and then builds, the APK silently points at a localhost that does not exist on a reviewer's phone, and the failure looks like broken auth rather than misconfiguration.

**Verify `.env.public` immediately before every demo build.** Worth a preflight check in whatever script we land.

### 2. Release builds are signed with debug keys 🟠

`android/app/build.gradle.kts:34-40` is still the Flutter template default:

```kotlin
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        signingConfig = signingConfigs.getByName("debug")
    }
}
```

No keystore exists in the repo. Consequences:
- Sideloading works fine — **acceptable for judging**
- Cannot ship to Play Store as-is
- Debug keystores are generated **per machine**, so an APK built on one box cannot upgrade over one built on another; reviewers would need to uninstall first

**Decision needed:** generate a real keystore now, or accept debug signing for the hackathon and build every demo APK on one machine. Recommend the latter for time, but it should be an explicit decision, not an accident of the template.

### 3. Build-memory envelope 🟠

`apps/biotope/android/gradle.properties` is pinned for the 16 GB Windows host — 1.5 GB heap, 768 MB metaspace, `org.gradle.workers.max=1`, no parallelism, Kotlin in-process. Before building: stop Docker / local Supabase, close any emulator, and run no other Flutter or Gradle command concurrently. Overlapping builds are what #281 was fixing.

### 4. Reviewers must enable "Install unknown apps" 🟡

Android blocks sideloading by default. One line in the demo runbook covers it.

