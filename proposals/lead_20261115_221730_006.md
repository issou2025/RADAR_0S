## Direction (owner ruling, 2026-11-15)

Generated output should not contain anything the compiler reads back from its own previous output, and should not carry a tool-named folder. Artifacts belong in proper places in the generated tree. This is the "pending owner design" group of #5942 (D-NO-TOOL-NAME).

## What `.loom/` and the markers are today

From the writer/reader table in `docs/decisions/D-NO-TOOL-NAME.md` (PR #5957; researched by reading `src/`, three rows spot-checked):

| Reader | What it reads |
|---|---|
| The compiler, on the next run | `manifest.json` (every emitted path + `scaffoldOnce` flags); the `loom:scaffold-once` marker in files; the `loom:unrendered [loom.<code>]` comments (re-scans its own output); `locales/.loom/source.lock` + `stale/`; `migrations/` |
| Developer tools (`ddd trace`, `ddd breakpoints`) | `sourcemap.json`, `loom:sourcemap-begin/-end` markers |
| The generated app at runtime | only the `-- loom:no-transaction` first line of a migration (renamed by #5942) |
| Nobody | `snapshots/*.loomsnap.json`, `verification.*`, `frontend-contract.json` |
| People, and the playground | diagrams (`*.mmd`, `architecture.c4`), `asyncapi.yaml`, traceability/coverage/gaps, `datasources.md`, `messages.<lang>.json`, `wire-spec.json`; `traceability.json` by the playground tests panel |

The i18n lock and the migrations chain already live beside the `.ddd` source, not under `-o`.

## Target

1. **Documentation artifacts → `docs/`** in the generated tree: diagrams, C4 model, AsyncAPI, traceability/coverage/gaps, data-source routing.
2. **No manifest, no scaffold-once marker.** The generator owns its output folders outright, except paths the user's ignore file names. A scaffold-once file is written only when absent. Decide and state how stale files from a previous run are removed without a manifest (owned-folder wipe vs. deterministic path set), and what happens to a file the user edited without listing it.
3. **The unrendered-primitive list** comes from the walker's return value, not from re-scanning emitted comments.
4. **Source map** stays opt-in and is written beside build output as a debug artifact; its begin/end markers are reconsidered with it.
5. **Artifacts with no reader** each get a real home or are dropped: verification reports (reports/docs), provenance snapshots (where the consumer that needs them looks — name that consumer or drop the output), `frontend-contract.json` (per the Frontend Contract lane, #5429).
6. **`wire-spec.json`**: decide its place now that the declared records are the wire source (#4886 closed) — a `docs/` or contract artifact, or dropped in favour of `ddd diff`.
7. **The source-side tool state** (`locales/.loom/`, snapshots beside the `.ddd`) is named and placed deliberately; it is not generated output, but it should not need the folder name either.

## Acceptance

- A decision record states the rule in the present tense and the regeneration semantics that replace the manifest.
- `generate system` writes no `.loom/` directory and no marker the compiler later reads; the tool-name census (#5942) has no "pending" group.
- `ddd trace` / `breakpoints` / `verify` / `diff` / `snapshot`, the playground and the docs are updated to the new locations; `docs/loom-artifacts.md` is rewritten or retired.
- Regeneration behaviour is covered by a test: a user-edited ignored file survives; a file the model no longer produces is removed; a scaffold-once file is not overwritten.
