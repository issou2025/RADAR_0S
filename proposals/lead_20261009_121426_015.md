# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**[web] Focus traversal from _ViewState.didChangeViewFocus reads the FocusScopeNode of a route popped in the same frame (semantics enabled): "Cannot get renderObject of inactive element"**

*Project description:*
### Steps to reproduce

1. `flutter create --platforms web bug` and replace `lib/main.dart` with the code sample below (no packages beyond the SDK).
2. `flutter build web --release`, serve `build/web` (e.g. `python3 -m http.server --directory build/web 8765`) and open it in Chrome. (`flutter run -d chrome` shows the debug assertion instead.)
3. Enable the semantics tree the way a screen reader does: run `document.querySelector('flt-semantics-placeholder').click()` in DevTools, or Tab to the "Enable accessibility" placeholder and activate it.
4. Click **Open form**.
5. Click **Save**. The button's child becomes a `CircularProgressIndicator`; ~300 ms later the app pops back to **List**.

Each of these is required (verified in isolation): the semantics tree is on; the popped route has a zero-duration transition; the app uses `MaterialApp.router` (`MaterialApp(home:)` hides it, see below); the page is wrapped in `Semantics(scopesRoute: true, explicitChildNodes: true)`, as `MaterialPageRoute.buildPage` does; the button is disabled while loading (`onPressed: null`). Typing in the `TextField` is not needed.

### Expected results

No exception. The form pops and the list is shown.

### Actual results

Every time, one error is reported through `FlutterError.onError` while dispatching `WidgetsBindingObserver.didChangeViewFocus`:
- release: `Null check operator used on a null value`, from `RenderObject.getTransformTo` (`rendering/object.dart:3687`, the `owner!`);
- debug: `Cannot get renderObject of inactive element. … The findRenderObject() method was called for the following element: _FocusScopeWithExternalFocusNode`.

The app keeps working; the error is caught in `WidgetsBinding.handleViewFocusChanged`.

#### Mechanism (Flutter 3.44.0 sources)

1. Clicking **Save** gives DOM focus to the button's `<flt-semantics role="button">`. When its child becomes a spinner, the spinner's `SemanticsRole.loadingSpinner` is merged into the button's node (`semantics/semantics.dart:6808`), so the engine role changes button → loadingSpinner. `SemanticsObject._updateRole()` (engine `semantics/semantics.dart:2314-2358`) creates a new DOM element and removes the old one without moving focus → `focusout` with `relatedTarget: null`, `activeElement: <body>` → `ViewFocusBinding` emits `ViewFocusEvent(unfocused)`. (A button that stays enabled is re-focused by the engine because the merged node is still `isFocused`, which hides the bug — hence `onPressed: null` while loading, the common pattern.)
2. The pop with `transitionDuration: Duration.zero` completes synchronously; the popped `OverlayEntry` is removed in a post-frame callback, so in the next frame the list route comes back onstage and the form route's elements are deactivated in the same build.
3. In that frame, `flushSemantics` → engine `updateSemantics` creates the list route's `SemanticRoute`, whose one-time post-update callback (`semantics/route.dart:26-48`, run from `EngineSemanticsOwner._finalizeTree`, `semantics.dart:3156`) focuses the first focusable DOM node of the route → `focusin` → `ViewFocusEvent(focused)`, delivered synchronously, still inside `drawFrame`, **before** `BuildOwner.finalizeTree()` unmounts the deactivated elements.
4. `_ViewState.didChangeViewFocus` (`widgets/view.dart:254`) runs `ReadingOrderTraversalPolicy.findFirstFocus`, which reads `FocusNode.rect` for every node it sorts (`focus_traversal.dart:1399` → `focus_manager.dart:862`). The popped route's `FocusScopeNode` is still in the focus tree (its `_FocusState.dispose`, which detaches it, only runs at unmount), its element is inactive and its render object detached → `getTransformTo` dereferences `owner!`.

`MaterialApp(home:)` does not show it because it wraps the `Navigator` in `FocusScope('Navigator Scope')` (`widgets/app.dart:1692`), and `_sortAllDescendants` uses `_getDescendantsWithoutExpandingScope`, which does not descend into nested scopes, so the route scopes are never measured. With `MaterialApp.router` they are. Replacing the route instead of popping (both pages attached in the same frame) does not throw either.

This looks like the same unguarded `FocusNode.rect` read from `didChangeViewFocus` as #193287 / #191508 (`RenderBox was not laid out` on a just-mounted overlay) and #186562 (null directionality), with a different precondition: an inactive element whose render object is already detached.

Possible fixes: skip nodes whose element is not mounted / whose render object is not attached when sorting (or guard `FocusNode.rect`), and/or defer the traversal in `didChangeViewFocus` when it is called during `drawFrame`; on the engine side, transfer focus to the replacement element in `_updateRole()` when the removed element is `document.activeElement`, and/or run the route default focus outside the semantics update.

#### Workaround

Keep the merged node a button while loading, so the engine does not swap the element:

```dart
FilledButton(
  onPressed: saving ? null : save,
  child: saving
      ? Semantics(
          label: 'Save',
          excludeSemantics: true,
          child: const SizedBox.square(
            dimension: 20,
            child: CircularProgressIndicator(strokeWidth: 2),
          ),
        )
      : const Text('Save'),
)
```

Measured: the node stays `role="button" aria-disabled="true"`, DOM focus never leaves the Flutter view, no error. (The sample applies it with `--dart-define=WORKAROUND=true`.)

### Code sample

```dart
import 'package:flutter/material.dart';

/// Build with `--dart-define=WORKAROUND=true` to apply the workaround
/// (keep the button's semantics role while the spinner is shown).
const bool kWorkaround = bool.fromEnvironment('WORKAROUND');

void main() => runApp(const ReproApp());

class ReproApp extends StatefulWidget {
  const ReproApp({super.key});

  @override
  State<ReproApp> createState() => _ReproAppState();
}

class _ReproAppState extends State<ReproApp> {
  final AppRouterDelegate _delegate = AppRouterDelegate();

  @override
  void dispose() {
    _delegate.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    // MaterialApp.router: no 'Navigator Scope' FocusScope between the View's
    // scope and the routes (MaterialApp(home:) adds one and hides the bug).
    return MaterialApp.router(routerDelegate: _delegate);
  }
}

/// A page with a zero-duration transition (a common "no transition" page).
class NoTransitionPage<T> extends Page<T> {
  const NoTransitionPage({required this.child, super.key, super.name});

  final Widget child;

  @override
  Route<T> createRoute(BuildContext context) {
    return PageRouteBuilder<T>(
      settings: this,
      transitionDuration: Duration.zero,
      reverseTransitionDuration: Duration.zero,
      // Same wrapper as MaterialPageRoute.buildPage (and other routing packages):
      // it is what makes the web engine create a route node for the page.
      pageBuilder: (_, _, _) =>
          Semantics(scopesRoute: true, explicitChildNodes: true, child: child),
    );
  }
}

class AppRouterDelegate extends RouterDelegate<Object>
    with ChangeNotifier, PopNavigatorRouterDelegateMixin<Object> {
  @override
  final GlobalKey<NavigatorState> navigatorKey = GlobalKey<NavigatorState>();

  bool _formOpen = false;

  void openForm() {
    _formOpen = true;
    notifyListeners();
  }

  void closeForm() {
    _formOpen = false;
    notifyListeners();
  }

  @override
  Future<void> setNewRoutePath(Object configuration) async {}

  @override
  Widget build(BuildContext context) {
    return Navigator(
      key: navigatorKey,
      pages: <Page<void>>[
        NoTransitionPage<void>(
          key: const ValueKey<String>('list'),
          name: '/',
          child: ListScreen(onOpenForm: openForm),
        ),
        if (_formOpen)
          NoTransitionPage<void>(
            key: const ValueKey<String>('form'),
            name: '/form',
            child: FormScreen(onSaved: closeForm),
          ),
      ],
      onDidRemovePage: (Page<Object?> page) {
        if (page.key == const ValueKey<String>('form')) {
          _formOpen = false;
        }
      },
    );
  }
}

class ListScreen extends StatelessWidget {
  const ListScreen({required this.onOpenForm, super.key});

  final VoidCallback onOpenForm;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('List')),
      body: Center(
        child: FilledButton(
          onPressed: onOpenForm,
          child: const Text('Open form'),
        ),
      ),
    );
  }
}

class FormScreen extends StatefulWidget {
  const FormScreen({required this.onSaved, super.key});

  final VoidCallback onSaved;

  @override
  State<FormScreen> createState() => _FormScreenState();
}

class _FormScreenState extends State<FormScreen> {
  bool _saving = false;

  Future<void> _save() async {
    setState(() => _saving = true);
    // Simulates a remote write; then pops back to the list.
    await Future<void>.delayed(const Duration(milliseconds: 300));
    if (!mounted) {
      return;
    }
    widget.onSaved();
  }

  @override
  Widget build(BuildContext context) {
    Widget spinner = const SizedBox.square(
      dimension: 20,
      child: CircularProgressIndicator(strokeWidth: 2),
    );
    if (kWorkaround) {
      // Keeps the merged semantics node a button: no role swap in the engine.
      spinner = Semantics(
        label: 'Save',
        excludeSemantics: true,
        child: spinner,
      );
    }
    return Scaffold(
      appBar: AppBar(title: const Text('Form')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: <Widget>[
            const TextField(decoration: InputDecoration(labelText: 'Name')),
            const SizedBox(height: 16),
            FilledButton(
              // Disabled while saving (common pattern): the button's FocusNode
              // can no longer hold focus, so the engine does not re-focus the
              // swapped DOM element and document focus stays on <body>.
              onPressed: _saving ? null : _save,
              child: _saving ? spinner : const Text('Save'),
            ),
          ],
        ),
      ),
    );
  }
}
```
