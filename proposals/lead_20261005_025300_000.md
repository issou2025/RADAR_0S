# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Unreal: choose a fidelity level per category at import**

*Project description:*
**Host:** Unreal. This is Unreal's slice of the fidelity-level map #283, which closes with Revit done (#300). It is the home for Unreal's level choosers from now on.

Bundles publish **fidelity levels** (RAW, MAX, MED, MIN; MPB 1.9.0, see `CONTEXT.md`) per category. Revit offers a level per category at import. Unreal reads none of them: `levels` is ignored, and every import is MAX.

**This needs a grilling before it is built.** The questions below were raised on #283 and deliberately left open, because the work was focused on Revit.

## Open questions

1. **Where the chooser lives.** The full import picker (#93) is not built. Unreal's only import control today is the Landscape / Mesh / Both mode combo in the vault panel. The choice is between waiting for #93, or adding a small level control now (one "set all to" control plus one control per category that publishes `levels`) that #93 later folds in.
2. **What a tree level does before the scatter exists.** Unreal builds the tree-points data table and places no trees, so a level only pays off in the scatter (#76). One option is to cut the table to the chosen rank prefix now: it costs almost nothing and the scatter would inherit it. The other is to show trees as "Same as MAX" until #76 lands.
3. **Which categories, and at what default.** Revit's defaults were set by measurement against a 5-minute budget. Unreal has neither a budget nor a measurement (see below). Candidates from the platform's levels: the heightmap (one landscape size down per level, with the paint weights and coverage rasters following it), the terrain mesh, the buildings mesh (leaves out the smallest footprints), and the drape. The Cesium stream is MAX only.
4. **Which view to download.** This overlaps #301. Unreal could download every level, so that changing level needs no second download (a re-import replaces, ADR 0002), or only the chosen level.
5. **Re-import at another level.** This is expected to replace wholesale, following ADR 0002. Confirm it.

## Facts found on 2026-10-04

- **No Unreal import cost is measured.** Every native-import row in `docs/import-inventory.md` says "Not measured"; only Cesium staging is timed. The reference order cached locally carries no Unreal formats, so measuring needs a fresh complete order that includes Unreal's files.
- **Unreal downloads the whole bundle.** It requests `format: bundle` with no view. Revit requests a host view, and the platform's view takes **one level per entry**: MAX carries the cut levels (row prefixes) but not pointer levels. Unreal's heightmap and mesh levels are pointer levels, so "every level in one download" may need a platform change.
- **Levels on Unreal deliverables are verified only in a fixture.** The conformance corpus case `manifest.fidelityLevelsIgnored` puts `levels` on `hosts.unreal.mesh_alternative` and `hosts.unreal.foliage_points`. No real Unreal bundle has been checked for levels on the heightmap, the buildings mesh or the drape.
- **Revit's model to reuse:** `revit/src/MantlePlace.Revit.Core/FidelityLevels.cs` (pointer, row cut, field cut, `same_as`) and the per-level time estimate, which is `cost_driver` × the measured unit cost.
