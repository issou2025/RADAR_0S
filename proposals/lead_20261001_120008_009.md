# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**ios_target.rb: RunnerUITests links Foundation.framework at a fixed SDK path, and the project file gets cosmetic rewrites**

*Project description:*
Found while integrating harness 2.1.0 into an app on Swift Package Manager (xcodeproj gem 1.28.1, Xcode with the iOS 26.5 SDK).

1. **Broken framework reference.** `ios_target.rb` creates `RunnerUITests` with the xcodeproj gem's `new_target`, which links `Foundation.framework` by a path with a fixed SDK version:

   ```
   path = Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS26.0.sdk/System/Library/Frameworks/Foundation.framework; sourceTree = DEVELOPER_DIR;
   ```

   The installed SDK is 26.5, so the reference points to nothing (Xcode shows it in red). The build still works, because Foundation is linked implicitly. The file reference and its build file are not needed. Expected: no fixed-SDK framework reference in the app's project, for example by removing the Foundation build file that `new_target` adds.

2. **Cosmetic rewrite.** Saving the project with the gem renames the comment of Flutter's package reference from `XCLocalSwiftPackageReference "Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage"` to `XCLocalSwiftPackageReference "FlutterGeneratedPluginSwiftPackage"`. Flutter may write it back on a later build, which leaves noise in the app's diffs. Expected: the setup script changes only what it needs, or the docs say this rewrite is harmless.

Both changes came from the first `patrol_bootstrap.sh` run; a second run changes nothing.
