### Steps to reproduce

Using DartNative 1.4.0:

```sh
git clone https://github.com/ManmohanTalwar/dartnative-manual-selection-repro.git
cd dartnative-manual-selection-repro
git checkout f929f47dd19ead5bcf1bc49512cf25717c130260
dn --suppress-analytics pub get
dn --suppress-analytics run --no-pub -d DEVICE_ID
```

Configure your own framework license locally as required for a custom app; none is published here. Use the intended SDK's `dn` executable.

1. Tap **Focus input**, then **Capture state** after focus settles. Case A starts with `Unsent draft` and selection `[1,5]`.
2. Use native long-press/Select to select `draft`. On iOS the first long-press may only position the caret; repeat if needed, then **Select**.
3. **On iOS dismiss the native menu by tapping the heading first:** Cut can overlap the app's Capture state button. Confirm the selected highlight remains. Tap **Capture state**, then **Capture in 5s**, and leave selection unchanged until the passive trace prints. Both selection reads remain `[1,5]`, listener count 0.
4. Type uppercase `X` using native input. It correctly replaces `draft`: `Unsent X`, selection `[8,8]`. The listener fires once, before `onChanged`.
5. Manually select `Unsent` in the edited text. Repeat the settled/timed captures. Both Dart ranges remain `[8,8]`; listener count stays 1.
6. Type uppercase `Y`. It correctly produces `Y X`, `[1,1]`, listener count 2 followed by `onChanged` count 2.
7. Terminate and run a **fresh process** with `--dart-define=INITIAL_RANGE=false`. This uses a text-only controller initially reporting `[-1,-1]`. Repeat the sequence: the first selected-word captures stay `[-1,-1]`, and all post-edit results are identical. Do not hot reload/restart between controls.

**Actual:** manual selection changes which text native input replaces, while both `controller.value.selection` and `controller.selection` stay stale and the ordinary listener receives no selection-only notification. Successful text edits update the getters and notify correctly. This reproduces on both platforms with both initialization controls, including after an edit.

**Expected / clarification requested:** code reading or listening to the controller should receive the current native selection when the user changes it without changing text. Selection-dependent app actions otherwise see an obsolete range. Does DartNative support this through the controller, or is another public API required? The public controller table documents typing updates before `onChanged`, but does not explicitly define selection-only notification timing. We have not established the private cause or whether it shares a cause with #80.

**Environment and limits:** SDK 1.4.0, vendor `75bc07e9b49`, packaging Git `5b4c8d07dfe4f089a9d1c56b8a66b75c7e5ee0c9`, engine content `ed0d71411e76bf9558f1c4dc8078f3222e364497`, Dart `3.12.0-192.0.dev`; Xcode 26.6 / 17F113. iPhone 17 Pro / iOS 26.5 simulator and Android 14 / API 34 arm64 emulator with Gboard. Debug, official Light presentation, one qualified fresh process per platform/control. iOS used actual software Shift + X/Y taps; Android used native `input text X` / `Y`, not software-key taps or controller assignments. Native range is evidenced by original highlight/handles plus replacement, not a native offset getter. No physical-device, release, complex composition or full-theme claim.
