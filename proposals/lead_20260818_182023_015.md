## Summary

`setup-python-suite` installs Python dependencies only. The **system** packages ansible installs on every backend host are not installed on CI runners, so any test needing one either skips or fails for the wrong reason — and a skip is indistinguishable from a pass.

Found while landing #13896: `pytesseract` was installed from `requirements.txt`, the `tesseract` binary was not, `ocr_availability()` returned false, and **every end-to-end OCR test skipped**. The visible symptom was an unrelated-looking assertion, `assert (1, 2, 3, 4) == (3, 4)`.

That is #13885's exact shape reproduced in CI: the binding present, the binary absent, and a green run that proved nothing.

## The general gap

`autobot-slm-backend/ansible/roles/backend/tasks/main.yml` installs these on hosts, each because some feature does not work without it:

```
xvfb, x11-utils, x11-apps        GUI / VNC automation
ffmpeg, libsndfile1, portaudio   audio / voice / Whisper
espeak-ng, espeak-ng-data        TTS (#10566: "no speech voices installed" without it)
tesseract-ocr, libtesseract-dev  OCR / CAPTCHA (#206)
python3-tk                       matplotlib GUI backend
postgresql-client                pg_dump for pre-migration backup
```

#13896 adds `tesseract-ocr` to the runner. **The others are unaudited** — for each, either its tests are skipping in CI today, or nothing tests it at all. Both are worth knowing, and neither is currently visible.

## Why a skip is worse than a failure here

Every one of these features is guarded by an optional import that degrades to a message. That is correct at runtime and blinding in a test suite: the gate is always closed, the tests never run, and the suite is green. #13885 survived months on exactly that.

## Scope

- [ ] Audit each system package above: does a test need it, and does that test currently run or skip in CI?
- [ ] Install the ones with real test coverage on the runner (cheap; `tesseract-ocr` added in #13896 as the first)
- [ ] For each capability whose tests are `skipif`-gated on a system dependency, add the counterpart guard #13896 introduces — assert the provisioning when `CI` is set, so an always-closed gate fails loudly instead of passing quietly
- [ ] Where a capability genuinely cannot be exercised in CI, record that explicitly rather than leaving a permanently-skipping test that reads as coverage

## Note

The pattern worth copying is the guard, not the apt line: `test_ci_actually_has_the_ocr_toolchain` in `autobot-backend/tests/test_ocr_fallback_13896.py`. It turns "these tests skipped" from an invisible non-event into a failing assertion.
