## A — Correct observation/freshness contract; independently deliverable first
- Inventory runtime clocks and reuse an existing suitable authority. Define observation ID, connection generation, clock epoch, query/receive timestamps, discontinuities and UTC display metadata. Preserve ECU measurement time only when it was actually provided; receive time is not ECU measurement time.
- Specify whether the monotonic clock advances during deep sleep. Android elapsedRealtime does; native/Dart units being equal does not establish a shared origin. Measure or explicitly map clocks, bound mapping uncertainty and reset the epoch across process/boot changes.
- Migrate live Reading/valueOf/isStale, adapter-voltage expiry, formula dependency age, acceleration/derived consumers and heartbeat expiry together or use an explicit adapter that cannot silently mix authorities. Agree ownership with #80/#90. Do not simply fix the visible gauge while stale inputs continue feeding formulas or exports.
- Define exact TTL boundary behavior, future/unknown timestamps and lost continuity. Negative/unknown elapsed age must not become proof of freshness. Heartbeats may age observations but never create a new observation ID or renew its timestamp.
- Keep authoring previews distinct from live caches: a missing clock/preview input is not an observed sample. Audit nullable-copy invalidation for scalar values; an expired voltage/acceleration must be clearable rather than retained by an implicit `newValue ?? oldValue`. Inspect actual callers before claiming an end-user defect.
- Preserve old records/constructors using documented legacy timing semantics. Do not create invented source timestamps or rewrite historical recordings to look more precise. UTC-only older records may still be displayed as historical, not promoted into the live epoch.

## B — Shared bounded acquisition demand
- Introduce a small `TelemetryDemand` contract for owner lease, channel/definition, target/responder, requested period and priority. Union dashboard/recording/trip/alert demand and release retired owners.
- Separate wire-request identity from decoded-channel identity. Several compatible formulas can use one raw response while retaining separate provenance/units. The same PID on different ECUs is not the same channel. Verify addressing and response contracts before sharing or batching.
- Respect documented per-command limits and available scheduler capacity; expose requested versus achieved rate. Prevent starvation, duplicate polling and unbounded queues. Exclusive diagnostic work retains its single command owner, and potentially completed state-changing operations are never blindly retried.

## C — Measured acquisition/rendering performance; not an A/B prerequisite
- Measure connect tap → transport → handshake → first valid observation, then queue/write/response/parse/publication/render latency. Separate requests, frames, decoded channels and UI redraws; repeated values received in genuinely new responses are new observations, while replaying an old response is not.
- Report actual per-channel cadence, sample count, p50/p95/p99, errors/loss/gaps and resource use. Document the quantile method and minimum samples; empty or inadequate runs are not PASS.
- Profile build/raster time and jank in profile mode. Rendering decimation may reduce paints, not discard raw acquisition evidence or alter freshness. Declare a baseline and regression budgets before optimization, not after a failure.
- Exercise 1/6/20 channels, CAN/legacy, mixed priority/ECUs, delay/jitter/chunking/batch refusal, recording and export contention. Keep fixtures independent of production encoders.
- Competitor comparison is a separate optional lane: matched device/OS, adapter unit/firmware, bus/channel set and conditions; sequential connections, counterbalanced order, multiple runs, all failures and limitations. Without that evidence, publish only Telltale's own measurements.
