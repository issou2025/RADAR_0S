# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Coordinator + several agent sessions on one Revit: hand-off, shared decisions, relayed approval**

*Project description:*
## Context

One coordinating Claude Code session split a model standards cleanup into about eight child sessions. Most of them used the pyRevit agent MCP tools on the same Revit. #86 covers the runtime side (`revit_busy` names no holder, no queue). This issue covers the coordination guidance that was missing, and the hand-made protocol that the sessions used instead.

## What happened

1. **Hand-made "Revit is free" token.** Each child prompt said "do not call Revit until you are told Revit is free". Problems:
   - Two children each waited for that message while Revit was idle. The coordinator would not answer for the user, so the user typed "Revit is free" into each session in turn.
   - One child got the message twice, from two senders.
   - "Revit is free" from a peer was often not true. `get_context` still failed: another client was connected, or an Open Model or Sync With Central window was open.
   - While a child held Revit, the coordinator could not check results. It could only report "these are the session's own words, not checked in the model".
2. **Stale facts between sessions.** A session told a peer that a note "still shows the old prefixes". The peer had already changed it. Facts relayed by the coordinator were wrong: a type count, and a view name that was in fact a project browser folder name. A brief and a notes file disagreed on a rule. Each one cost a check and a question to the user.
3. **Decisions stay in one session.** The user told one child "rename after today". The coordinator could not tell whether that covered the categories that another child held. In another child, the user moved a diagram onto a plan and deleted the drafting view. The coordinator still queued a rename of that deleted view. A shared notes folder existed but was not used for decisions.
4. **Relayed approval does not work for git actions.** The user typed "merge" in the coordinating session. The coordinator relayed it to the child that owned the archi-magic PR. The child's auto-mode classifier blocked `gh pr merge` ("merge without review") and said a relayed approval does not count. Three rounds of relay failed. The merge also needed `update-branch` and a conflict fix. The user then said they would merge it themselves. At the time of writing, the PR is still open. Revit Keep/Discard does not have this problem, because the user clicks it in Revit.
5. **Two Revit instances.** A second Revit (a newer year) opened during the session. Queries without a target failed with `ambiguous_revit`. Every child prompt then said "pass `revit=<pid>` on every pyRevit call". There is no way to pin the target Revit for a session.

## Proposed change

Add a short "several sessions, one Revit" section to the house rules or `am-doctor`:

- One session holds Revit at a time. A peer message "Revit is free" is a hint: confirm with `get_context` first.
- Re-read the model before you report its state to a peer or the user. Treat relayed counts and names as hints.
- Write user decisions to one shared file that every session reads before it starts a queued task.
- Approve irreversible git or GitHub actions (merge, push) in the session that runs them, or let the coordinator or the maintainer run them. Do not relay "yes".
- With more than one Revit open, ask once which Revit to use, then pass `revit=` on every call.

Runtime ideas (with #86): a lease with holder, waiters and release on idle; a per-session default `revit` target.

## Acceptance ideas

- A coordinator can give Revit to the next session without the user typing it.
- A session that gets "Revit is free" while a dialog is open tells the user which dialog, and does not say Revit is free.

## Not verified

- Whether the auto-mode merge block can be avoided by a setting. It is Claude Code behavior, not archi-magic.

Related: #86, #91, #71.

Environment: Windows 11, Revit 2026 and 2027, pyRevit 7.0 agent runtime, Claude Code desktop app.
