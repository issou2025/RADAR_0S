# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Overall height and width of doors follow the nominal Revit value where the reference exporter writes the measured extent.**

*Project description:*
Since the door and window dimensions change (door and window height and width are taken from the parameters before the bounding box), the IfcDoor OverallHeight and OverallWidth of some doors differ from the reference output, while 0.1.0 matched it:

- Revit 2025 architecture sample: 57 single flush doors, OverallHeight 7.0 feet (the nominal 84 inch) where the reference and 0.1.0 give 7.333; 4 double doors, OverallWidth 6.0 where the reference and 0.1.0 give 6.333.
- Revit 2024 DACH sample: 15 doors, OverallHeight 2.135 (the type height) where the reference and 0.1.0 give 2.315; the Height quantity of 9 doors is 2.03 where the reference and 0.1.0 give 2.04.

In the same samples several hundred other door and window values moved closer to the reference, so the rule is right for most elements. The cases above are the ones where 0.1.0, which used the bounding box, and the reference give a value larger than the nominal one.

Needed: a rule that tells when the reference uses a measured extent instead of the parameter, derived from the data of the file. The rule is not provable from the current samples.
