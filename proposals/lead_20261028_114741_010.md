# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**fix(mobile): build_dev_apk.sh builds an APK that crashes at startup (AppConfig.validate rejects production env + dev API)**

*Project description:*
## Problem

`apps/mobile/scripts/build_dev_apk.sh` builds a debug APK pointed at the shared dev backend by passing only:

```
--dart-define=YOURTJ_API_BASE_URL=https://dev.yourtj.de
--dart-define=YOURTJ_OIDC_ISSUER=https://dev.yourtj.de/api/oauth
--dart-define=YOURTJ_OIDC_CLIENT_ID=yourtj-mobile
```

It does **not** pass `YOURTJ_ENVIRONMENT=dev`, so `AppConfig.environment` defaults to `production`. `AppConfig.validate()` (`apps/mobile/packages/forum_app/lib/src/app_config.dart:34-36`) then throws `StateError('Dev API requires the dev environment')`, and since `main()` calls it unconditionally at `apps/mobile/packages/forum_app/lib/main.dart:12`, **the resulting APK crashes immediately on launch**.

The script is the documented way to get a dev-backend APK (`apps/mobile/packages/forum_app/README.md:77`, referenced in `docs/operations/mobile-releases.md:352`), so the current instructions produce a broken build.

## Verification

Reproduced with a probe test invoking `AppConfig.validate()` under the script's exact define set (temporary test file, removed afterwards):

- With the script's defines (production env + dev API URL): `validate()` throws `StateError` — startup crash.
- With default defines (local build, no overrides): `validate()` returns normally.

Note the current `validate()` contract also requires `YOURTJ_PREVIEW=true` for any `ENVIRONMENT=dev` build ('Dev builds require dev API, OIDC and preview distribution', `app_config.dart:26-33`), which additionally opts the APK into the `PreviewStatusHost` old-candidate banner (`lib/src/updates/preview_status.dart`) — worth reconsidering whether a plain developer build against the shared dev backend should carry the preview flag and banner, or whether the script should instead target a local backend.

## Suggested fix direction

Either:
1. Add `--dart-define=YOURTJ_ENVIRONMENT=dev --dart-define=YOURTJ_PREVIEW=true` to `build_dev_apk.sh` (matches the enforced contract; APK installs as `tj.yourtj.forum_app.dev` with the DEV badge), and accept the preview banner, or
2. Relax/extend `AppConfig.validate()` so a debug-mode developer build may point at the dev backend without the preview flag, keeping preview semantics for QA distribution only.

Option 1 is the minimal fix; option 2 needs a product decision on the dev/preview binding.
