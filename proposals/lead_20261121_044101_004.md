## Summary

Auditing `BatchPrint` (`src/SyntheticShared/Modules/BatchPrint/`) during [Platform Kernel, Feature Slice Seams & Legacy Allowlist Policy](https://github.com/amcgoey/Synthetic-Revit/issues/158) surfaced three latent runtime defects in `PrintBatchMultiDoc.Execute`:

1. **Linked-document sheet sets and print settings queried from host `doc` before opening linked `currentDoc`** (`src/SyntheticShared/Modules/BatchPrint/Commands/PrintBatchMultiDoc.cs` lines 90–138):
   - `ViewSheetSet` and `PrintSetting` collectors run against `document` (the `DocumentModel` / host `doc` wrapper) on lines 90–100 *before* `if (document.IsLinked)` opens `currentDoc` on lines 103–138, causing linked-model print batches to resolve sheet sets and print settings against the wrong document.
2. **Unguarded Bluebeam Windows Registry restore on exception** (`PrintBatchMultiDoc.cs` line 183 & `BBPrinterSettingsUtils.cs` lines 24–25, 84–91):
   - `BBPrinterSettingsUtils` mutates `HKCU\SOFTWARE\Bluebeam Software\21\Brewery\V45\Printer Driver` registry keys before printing, and `defaultBB.SetRegistryKeys()` at line 183 is not inside a `try/finally` block—leaving the user's workstation Bluebeam printer settings mutated if printing or linked-document opening throws.
3. **Title-string equality check when closing linked documents** (`PrintBatchMultiDoc.cs` line 167):
   - Uses `if (currentDoc.Title != doc.Title)` before closing `currentDoc`, which can skip closing a linked model sharing a title or behave unexpectedly compared to tracking an explicit `bool openedLinkedDoc` flag.
