## What this unblocks

**13 passive tree nodes and 1 capstone option are dead and cannot be brought to life, because three guards refuse the data rows that would do it.** The nodes grant increased minion damage, health or attack speed — Chained Will, Deeper Pact, Obedience, Long Servitude, Sharp Claws, Numbers, Yoke, Held Fast, Brood, Hardy Stock, Driven On, Restless, Goaded — and `Bound Servants`, which is one of three permanent choices on `Ritualist_capstone_25` and currently pays out nothing at all.

The work itself is **15 rows in `game/Data/PassiveEffects.csv`**. No new mechanism: the code that reads all three stats is merged and tested as of [#1724](https://github.com/sdubois777/Cataclysm/pull/1724) and [#1732](https://github.com/sdubois777/Cataclysm/pull/1732).

## THE CENTRAL POINT: a guard's stated reason stopped being true

`Cataclysm.Passives.EveryStatAPassiveNodeGrantsHasAnAttributeBehindIt`, in `game/Source/Cataclysm/Tests/CataclysmPassiveTreeTests.cpp`, gives its reason as:

> "`UCataclysmPlayerClassStats::ApplyTo` loops over `StatToAttribute` rather than over the modifiers, so a passive node granting a stat missing from that map applies nothing."

**That has not been true since #1724 merged.** `ApplyTo` now has a third pass that loops over a named list instead, recording those stats without writing any attribute — `game/Source/Cataclysm/Character/CataclysmPlayerClassStats.cpp:1116`:

```cpp
static const TArray<FString> WithoutAnAttribute = {
    TEXT("minion_damage"), TEXT("minion_health"), TEXT("minion_attack_speed"),
};
```

**So this is not a request to add a validation rule. It is a request to make three guards agree with what the code already does.** The carve-out exists; the guards have not been told.

## The three guards, and what each does today

| Guard | What happens now |
| :-- | :-- |
| `validate_passive_effects` in `tools/generate_datatables.py:4276` | **the sheet refuses to be written**, so `game/Data/PassiveEffects.csv` never regenerates. This fails first |
| `test_every_stat_is_one_the_game_supplies` | fails on all 15 rows |
| `Cataclysm.Passives.EveryStatAPassiveNodeGrantsHasAnAttributeBehindIt` | fails — these stats have no attribute, by design |

**All three would be right by their current rules.** A stat with no base and no attribute normally *is* worth nothing, silently. These three are the exception: purpose-written code reads their increases directly rather than multiplying them against a base.

## Why the existing exemption must not be used

`ENGINE_SUPPLIED_BASES` in `tools/generate_datatables.py:4219` would silence all three. **Every entry in it names where a base is put on the character**, for example *"UCataclysmDamageConversion::BaseWindowSeconds, put on the character by UCataclysmPlayerClassStats::EngineSuppliedBases"*.

The minion stats have no base and can have none. **Adding them there would be a false statement in a file whose entries are statements.**

[#1025](https://github.com/sdubois777/Cataclysm/issues/1025) is what that costs. An exemption named a constant nothing ever applied, so The Breaking Point converted damage for **zero seconds** — and that starved five further Masochist nodes that counted what the player was carrying. One inert exemption, six dead nodes.

## How big is this category? Three today, and six later decisions that are not six later mechanisms

`StatsNoAttributeIsWrittenFrom` in `game/Source/Cataclysm/Tests/CataclysmEquipmentTests.cpp:1302` lists every stat with no attribute behind it. Its own header:

> "The list is exact in both directions: a stat missing an attribute that is not named here fails the test, and a stat named here that now has one fails it too."

Its contents are the three minion stats; issues #894, #895 and #897 struck out everything else as those stats gained attributes. **So a fourth stat with no attribute would already be failing a currently-green test.** The size of this category is not an assertion anybody has to defend.

**That fixes the count among stats the game already grants. It says nothing about stats that do not exist yet**, and that distinction matters for how you rule.

Of the 62 unbuilt nodes in the two new trees, **30 are per-point stat modifiers** — the only kind that could ever need a stat name; the other 32 are rule changes, triggers and keystones no stat could express. Of those 30, **21 name a quantity that already has an attribute** and are blocked on conditions and scales rather than on this. **Nine name a quantity with no attribute: the three minion stats, and six more.**

| Node | What it increases | Nearest existing stat |
| :-- | :-- | :-- |
| Deeper Hurt | duration of Cripple and Weaken you apply | none — `dot_duration` is damage-over-time, not crowd control |
| Dragging Weight | magnitude of Cripple you apply | `cripple_chance` only, a different quantity |
| Sapped | magnitude of Weaken you apply | `weaken_chance` only, same |

**Those six are not six more members of this category.** A stat with no gameplay attribute has **two** legitimate homes: `test_every_stat_is_one_the_game_supplies` accepts a **flat row in the effects file** as supplying a base — *"a flat row is the base. The three Fervour rates are the case"* — so each of the six will be a base from a flat row, a new attribute, or this exemption, and **nobody has decided which for any of them.** This issue is not the place to.

**The honest statement of scope:**

> Three members today, held at three by a green test. Six unbuilt nodes name quantities with no stat yet, and each will need a decision when its node is built. **The mechanism is the same size either way** — one list, three guards reading it, one keeper. Six later decisions are not six later mechanisms.

## The proposal

**One shared definition, read by everything, plus a check that keeps its promise.**

| Piece | File |
| :-- | :-- |
| extract the existing list to a public accessor beside `StatToAttribute()` | `CataclysmPlayerClassStats.h` / `.cpp` |
| the passive guard reads it as its exception | `CataclysmPassiveTreeTests.cpp` |
| the equipment test reads it instead of its own duplicate | `CataclysmEquipmentTests.cpp` |
| **a probe-table test that keeps the promise** | new file under `game/Source/Cataclysm/Tests/` |
| generator vocabulary and its Python restatement | `generate_datatables.py`, `test_passive_effects_match_the_node_text.py` |

**Why a shared definition is also the answer to "will this exemption go inert?"** The list being extracted is not a new list written to silence a check — **it already exists and already does work**, so adding a name to it has an immediate effect: that stat starts being recorded onto characters. A dead entry of the #1025 kind therefore cannot exist in it. **That is only half the promise** — recording is not reading, and `minion_damage` was recorded but unread between #1724 and #1732 — which is why the keeper below is still required.

**Three lists currently name these same three stats** — the one that records them, the one that says they have no attribute, and the one this would add. Unifying them removes a drift that exists today rather than creating one. Their contents have been measured as identical, so unifying changes no behaviour.

### The promise-keeper is the part that matters

Without it this is #1025 again. **A Python check cannot hold this promise, and the project already wrote down why** — `test_every_engine_supplied_base_names_code_that_exists`:

> "It CANNOT check that the code is ever called, which is exactly what went wrong — `BaseWindowSeconds` existed the whole time. That half is held in the engine by `Cataclysm.PlayerStats.EveryEngineSuppliedBaseReachesACharacter`, which spawns a character and reads the value back off its attribute."

**And that method does not transfer**, because these stats have no attribute to read back. Each is observed differently, so the keeper is a table of probes:

| Stat | Probe |
| :-- | :-- |
| `minion_attack_speed` | grant it; assert `UCataclysmCommand::AttackIntervalScaleFor` returns a shorter interval |
| `minion_damage` | grant it; summon a minion; assert its blow grows |
| `minion_health` | grant it; summon a minion; assert its maximum health grows |

**The discriminating failure is "no probe registered for this name."** Add a name nothing reads and the test names it and fails. Proof: add a fourth unread name, run the group, show it caught.

## THREE QUESTIONS FOR YOU

1. **Approve this at all?** It changes what three guards accept, and those guards exist to catch silently-worthless stats. The argument that this is a correction rather than a loosening is the one above: the code already carves these three out, and a green test already fixes the category at three.

2. **One change or two?** The guards and the 15 rows are separable. **Recommendation: one.** Landing the guards alone creates an exemption with no member using it, which is exactly the inert state #1025 warns about.

3. **Is parsing a C++ literal list from Python acceptable here?** The Python vocabulary must agree with the C++ list. It could restate it — the existing pattern, held honest only by a symbol-existence check — or parse the C++ and assert equality, making drift impossible rather than merely detectable. **Recommendation: parse it.** 102 Python test files in `tools/tests/` already read C++ source, so reading is established; parsing a literal list is a step within that pattern rather than a new kind of coupling.
