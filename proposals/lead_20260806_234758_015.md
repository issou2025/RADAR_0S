*Project description:*
## Problem Statement

When I look at an exported comparison workbook and see something worth pointing
at — a window where two series stop tracking each other, a recurring feature in
the water level, a stretch where a logger looks fouled — I have no way to record
it.

The only mechanism available today is to resize worksheet columns behind the
chart and fill them with colour. That works at all only by accident: the chart
is drawn with `noFill` on both the chart space and the plot area, so the sheet
shows through it. Everything about it is wrong:

- The mark's position is a function of column widths. Change a width, change the
  meaning. Regenerate the workbook at a different `cm/day` or a different
  interval and every mark is silently wrong or gone.
- A cell fill carries no label, no reason, no author and no timestamp. What the
  band meant lives only in my head, and only until I forget.
- Marks die with the workbook. The same study re-exported at 30 min instead of
  1 h loses all of them.
- Handing the workbook to a colleague or to an agent hands them coloured
  rectangles. They can reverse-engineer where the bands sit by reconstructing
  chart geometry, but they can never recover what I meant by them.
- Placing a band accurately means dragging column borders by eye against a chart
  whose x-axis is labelled `mm-dd`, so I cannot see the hour I am aiming at.

There is a second, larger problem underneath. When I compare two series and they
diverge, I want to know what else might explain it. Today the only way to ask
that question is to export a different comparison, look at it separately, and
hold both pictures in my head at once.

## Solution

A **view module**: a Tk window that opens on the z-score chart of exactly two
selected series, where I can look at the shape, drag across a region to mark it,
give the mark a label and a reason, and save.

Marks are saved into the study as data — not as pixels, not inside a generated
workbook. A saved **annotation set** is identified by the **pair** it was drawn
from (`LJAC1.sea_water_temperature × LJAC1.water_level`), carries my label and my
reason, and holds a list of UTC intervals.

Because a set is identified by its pair, it can be reused. When I later view a
different pair that shares one series with a saved set — say `LJAC1` temperature
against `46254` temperature, where the saved set was `LJAC1` temperature against
`LJAC1` water level — that set is offered in a dropdown and its bands can be
overlaid on the current chart. Foreign bands are drawn differently from native
ones and the legend names their source pair, and the absent partner (water level)
is drawn as a faint dashed ghost line so I can see what it was actually doing
inside each band.

That is the point of the whole feature: where the two temperatures fail to line
up, I can see whether those windows coincide with the windows I marked on water
level, and decide whether water level explains the divergence. The correlating
is done by my eye, deliberately, rather than by a statistics engine.

Output is a **landscape PDF**, produced by the view module and written to the
study's `outputs/`. It has an overview page showing the whole window with every
band, one detail page per mark drawn at a single fixed scale so pages stay
comparable to each other, and a final page listing the marks with their times and
reasons alongside the provenance of every series shown.

## Implementation Decisions

### New modules

- **`identity`** — a pure module, importing no I/O, UI or plotting library. Holds
  the series colour table, the colour assignment rule and the legend label
  builder. Both the workbook exporter and the view module import it; neither
  imports the other. This exists because colour is the only thing tying a line on
  one chart to the same line on another, and the exporter already records that it
  cannot be assigned per chart. A PDF that coloured series independently would
  break that guarantee across artifacts rather than across sheets.
- **`annotations`** — the on-disk store. Pure Python plus a path; no UI, no
  plotting. Reads and writes annotation sets, and validates them.
- **`view`** — the Tk window and its matplotlib canvas. A thin shell: every
  decision it makes is delegated to a pure function that lives outside it.

### Existing modules changed

- **`exporter`** — loses the colour table, the colour assignment rule and the
  legend label builder to `identity`, and the z-score expression to `sensorkit`.
  No behavioural change, no output difference.
- **`sensorkit`** — gains the standardisation function. It is one expression
  today, and the `ddof=0` in it is precisely the detail that will drift if the
  view module reimplements it.
- **`compare`** — gains a **View…** button beside Generate. The button snapshots
  its Tk variables on the main thread, runs the build in a worker, and receives
  the result back through the existing queue-based result mechanism. Generate is
  not modified.
- **`study`** — its documented rule that only a producer's `outputs/` may change
  after creation is amended to name a second mutable path.

### Study layout

Annotation sets live in a new `annotations/` directory inside the producer's
namespace, beside `outputs/` and `cache/`. The rule that a study is immutable
once created is amended rather than broken: it exists to protect **evidence** —
what the feed said and when — and an annotation is **interpretation**, which is
expected to accumulate. Keeping the two in separate directories keeps the rule
crisp instead of eroding it with an exception inside the evidence directory.

A directory rather than a single file, so that adding a set never rewrites an
existing one.

`annotations/` is not scanned as input to a data build. It is read only by the
view module, which is consistent with the existing rule that generated outputs
never become sources.

### Annotation set schema

- Timestamps are stored as **UTC with an explicit offset**, and rendered in local
  time for display. Naive local timestamps are rejected on load. This is the
  single most expensive lesson in this project and the schema encodes it.
- A set records the **pair** it was drawn against as two series references. Each
  reference carries both the stable resolvable key (`file::table::column`, which
  is what allows the absent partner to be re-fetched for the ghost line) and the
  display label (`table.column`, which is what a human or an agent reads, and
  which still communicates if a source file is renamed and the key stops
  resolving).
- A set carries a name, a reason, a colour, a creation timestamp, and the study
  it belongs to.
- Intervals are `start_utc` / `end_utc` pairs. An optional per-interval series
  field is reserved in the schema, unset meaning "applies to all series", so that
  narrowing a mark to one series later is a data change rather than a migration.
  Nothing reads it in this PRD's scope.

### View window

- Exactly two series. The button is disabled otherwise, with a message saying
  why. This is deliberate: the scatter chart in the exporter used to take the
  first two selected columns whatever they were, and that bug is recorded in the
  code as fixed.
- The shared-unit restriction that governs the exporter's scatter chart is
  **deliberately not inherited**. Temperature against water level is the intended
  use, and it is legitimate here because this is a standardised chart, not a
  scatter.
- matplotlib is embedded in a Tk `Toplevel`. Its span-selection widget provides
  drag-to-select, edge handles for adjusting an existing region, date axes and
  autoscaling. matplotlib is added as an **optional, guarded import**, in the way
  the Excel automation dependency already is, so that the headless workbook
  export path is unaffected by its absence.
- All Tk variables are read on the main thread before any worker starts, and
  workers touch only a queue. The threading contract already documented on the
  existing progress dialog governs this window too; getting it wrong hangs the UI
  with no error, because the exception lands inside the error handler.

### Overlay

- **Eligibility:** a saved set is offered when it shares **exactly one** series
  with the currently viewed pair. Sharing both means it is the same comparison
  and is loaded as native marks instead; sharing neither means it has no bearing
  on what is on screen.
- **Presentation:** native bands are solid; foreign bands are outlined or
  hatched. The legend names the source pair of every foreign set explicitly.
- **Ghost line:** the member of the foreign set's pair that is not on the current
  chart is fetched and drawn as a faint dashed line, standardised over the
  current window so it is comparable to the plotted series. It is labelled as
  context, not as a compared series.
- **Clipping:** intervals falling outside the current window are not drawn, and
  the number omitted is reported in the window and on any PDF produced. Nothing
  is dropped silently.
- **Scope:** same study only. The series key is study-scoped, so a cross-study
  overlay would be resolving a key against a different snapshot.

### PDF

- Landscape.
- Page 1: overview — the full window compressed to one page with every band.
- Pages 2..n: one detail page per mark, all drawn at a **single fixed scale** in
  cm per day. The page window is the mark plus context, padded when the mark is
  short. A per-mark zoom-to-fit is explicitly rejected: the exporter already
  records that varying magnification makes side-by-side pages compare
  magnifications rather than curves.
- Final page: the mark table — set, local and UTC start/end, reason — plus
  provenance: study, window, interval, aggregation, and every series with unit,
  depth and reference frame.
- Every page states the scale it was drawn at, matching the existing rule that an
  artifact must never claim a scale it was not drawn at.
- Written to the study's `outputs/`.
- The page **plan** — how many pages, and each page's window and scale — is
  computed by a pure function, separately from rendering.

### Ordering

Slices, in dependency order:

1. Extract series colours and legend labels into `identity`. Pure refactor.
2. Extract standardisation into `sensorkit`. Pure refactor.
3. Annotation store, schema and validation; `annotations/` declared mutable in
   the study rule.
4. Read-only view window, opened by a View… button gated on exactly two series.
5. Marking: drag, label, reason, save, edit, delete.
6. Overlay: eligibility dropdown, foreign band styling, ghost line, clip
   reporting.
7. Landscape PDF export.

Slices 1 and 2 are prerequisites for 4. Slice 3 is a prerequisite for 5, which
is a prerequisite for 6, which is a prerequisite for 7. Each is committed on its
own.

## Testing Decisions

A good test here asserts the property that actually matters, not that code ran
without raising. This repo has shipped two bugs past exactly that reasoning — a
dialog that was fully populated but withdrawn, and a refresh that "succeeded"
while keeping the previous cached table — and the standard it settled on is: a
window is *viewable*, not merely constructed; a parser produced the *right
value*, not merely no exception.

There is no test framework in this repo. Gates are module CLIs run by hand that
exit non-zero on failure — the clock check, study validation and archive rebuild
all follow this shape. New gates follow it too rather than introducing a
framework as a side effect of this feature.

The controlling design decision is that **all feature logic lives in pure
functions and the window is a thin shell over them**. Without that, the only way
to test the overlay rule is to open a window.

### Seams tested

- **Colour assignment and legend labels.** Already pure. The gate is that a
  workbook regenerated after the extraction has identical series colours and
  identical legend text to one generated before it.
- **Standardisation.** Pure. Same-input-same-output against the pre-extraction
  expression, including the `ddof=0` behaviour.
- **Annotation store.** Round-trip a set and get identical intervals back. A file
  with zone-less or ambiguous timestamps is rejected, and the rejection names the
  problem. A set whose series key no longer resolves fails visibly.
- **Overlay eligibility.** A pure function from (saved sets, current pair) to
  offered sets. Sets sharing exactly one series are offered; sets sharing both
  are treated as native; sets sharing neither are not offered.
- **Interval clipping.** A pure function returning both the kept intervals and
  the number omitted, so that "nothing is dropped silently" is an assertion
  rather than an intention.
- **Span to UTC.** The conversion from the span widget's numeric x to a UTC
  interval, isolated from the widget. A span over a known region yields the
  expected interval to within one sample.
- **PDF page plan.** A pure function returning the page list. Assertions are on
  page count, each page's time window and each page's scale — never on pixels.
  All detail pages share one scale.

### Seams requiring a display

- **View window visibility.** A gate that constructs the window against a real
  study and asserts it is viewable, not merely constructed.

### Existing gates that must still pass

- Clock check on `sources/`, unchanged.
- Study validation, after `annotations/` is introduced.
- The deliberately corrupted `+7 h` fixture still failing.
- Archive rebuild producing a union, not a sum.
- The import gate: the exporter and sensor toolkit import with `tkinter`
  blocked. **Extended** by this work — `identity`, `annotations` and the page
  planner must import with **both `tkinter` and matplotlib blocked**, so the
  headless export path can never quietly acquire a UI dependency.

## Out of Scope

- **Automatic correlation detection.** An earlier version of this idea computed
  all-pairs correlations at study creation and surfaced series correlating with
  exactly one of the viewed pair. It was dropped deliberately: it collides with
  the config section that enumerates which pairs mean something and which do not,
  it would compute the surface-versus-5 m pair that the invariants say is a
  stratification index and not a correlation, and raw-level correlation between
  series that share tidal and diurnal harmonics produces confident nonsense. The
  human eye does the correlating in this feature.
- **Rendering marks inside the .xlsx.** Chart user-shapes were considered and
  rejected once the output became a PDF. The workbook export is untouched.
- **Column-fill highlighting of any kind.** The technique this feature replaces.
- **Cross-study overlay.** Series keys are study-scoped.
- **Per-interval series narrowing.** Reserved in the schema, not built.
- **More than two series in the view window.** The pair is the unit.
- **Harvesting marks from existing hand-shaded workbooks.** Reading a generated
  workbook as input is forbidden, and the labels were never recorded anyway.
- **Introducing a test framework.** Gates follow the existing module-CLI shape.
- **Marking on the raw-value or stratification charts.** The z-score chart is the
  marking surface because it is the only one where series with different units
  share a scale.

## Further Notes

- The column-fill technique being replaced works only because the exported chart
  is drawn with no fill on both the chart space and the plot area, so the sheet
  shows through it. That is a property of the current exporter, not a documented
  guarantee, which is part of why marks built on it are fragile.
- Recurring marks in real use have been observed spaced roughly 22–27 hours
  apart. That is close to the lunar day and squarely in the territory the
  invariants care about: any timing claim derived from marks must be reported
  alongside the ±12.42 h M2 alias, exactly as the lag scan already does. This
  feature does not make timing claims itself, but it produces the evidence
  someone will make them from.
- Series coverage is routinely unequal — a pair where one member ends days before
  the other is normal, not exceptional. Marks near the end of a window may sit
  where only one series has data. The clip-and-report rule is the mechanism that
  keeps this visible.
- Excel automation requires Excel closed, and a `~$name.xlsx` file beside a
  workbook means it is open or crashed and left a lock. PDF export has no such
  constraint, which is one practical advantage of the chosen output format.
- The view window is the first place in this repo where a long-lived interactive
  window coexists with the main application window. The existing progress dialog
  is modal and short-lived. Its threading contract still applies, but the
  lifetime question — what happens to unsaved marks if the main window closes
  first — is new and needs a defined answer during slice 4.
