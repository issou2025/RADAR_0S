### Describe the issue

My LLM Vision snapshots were fine yesterday. This morning, all but one were gone. Retention is set to 7 days, and I didn't delete anything or change that setting.

There is only one JPEG left in `/media/llmvision/snapshots`. The strange part is that `llmvision.get_events` still returns 1,328 events from September 16–19, with image paths pointing into that folder. The remaining image belongs to the latest event, at 05:45 this morning. Pictures from yesterday are missing too.

The logs have a lot of `database is locked` errors around the same time, along with cleanup warnings. Could a failed database read be making cleanup treat the existing pictures as unused?

Looking at [timeline.py in v1.7.2](https://github.com/valentinfrlch/ha-llmvision/blob/v1.7.2/custom_components/llmvision/timeline.py#L595), `load_events()` clears the event list before reading the database and catches the error if that read fails. Cleanup then uses that list to decide which images to delete. That seems like a possible explanation, but I haven't reproduced it to confirm.

I'm running:

- LLM Vision and LLM Vision Card v1.7.2
- Home Assistant Core 2026.9.2 / HA OS 18.2, amd64 VM
- Python 3.14.6

My automations take four snapshots about a second apart and send them to `llmvision.image_analyzer`, with `expose_images` and `store_in_timeline` both enabled.

I found #676, #684, #550 and #558 while searching. They look related, but I couldn't find a report of older pictures disappearing while the event history stays intact.
