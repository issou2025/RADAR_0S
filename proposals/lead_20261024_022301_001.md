# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**Domain gap: geometry queries — element geometry, elements in a box or radius, nearest surface, line of sight, clearance**

*Project description:*
## Goal

Give the agent the spatial questions it keeps needing and currently answers by hand from parameter reads: where exactly is this element and which way does it face, what is inside this box or within this distance, what is the nearest wall or ceiling from here, is there a clear line between two points, how much room is there around a device. The pieces exist in private form (`AlignmentService` ray casting, `RoomSourceService.ElementsInRoom`, `ClashBoundingBoxHelper`, several anonymous mm payloads); this issue exposes them as tools with one shared geometry DTO.

| Tool | Permission | Purpose |
|---|---|---|
| `revit_get_element_geometry` | ReadOnly | Location point/curve, bounding box, facing and hand orientation, rotation, host, level, room, owner view, link transform — in mm, for up to 100 ids |
| `revit_find_elements_in_box` | ReadOnly | Elements whose bounding box intersects (or lies inside) a box, with category filter, host and links |
| `revit_find_elements_near` | ReadOnly | Elements within a radius of a point or of an element, sorted by distance |
| `revit_find_nearest_surface` | ReadOnly | Nearest wall / ceiling / floor / roof / any face from a point in given directions, with hit point, normal and distance (ray cast, links included) |
| `revit_check_line_of_sight` | ReadOnly | Whether a straight line between two points is blocked, by what, and where |
| `revit_measure_clearance` | ReadOnly | Free distance around an element or point in the six axis directions (or custom), and the blocking element per direction |

## Why

Placement rules in the company skills (detector spacing from walls, camera sight lines, socket heights, tray clearance to ceilings) are spatial, and today the agent approximates them from level and offset parameters. `QueryGuard.ValidateGeometryQuery` and `QueryLimits.MaxGeometryElements` exist but are unused; this issue is where they earn their keep.

## Design

### Shared DTOs (`RevitMCP.Addin/Geometry/GeometryDto.cs`, pure)

`PointMmDto {x,y,z}` (0.1 mm rounding), `BoxMmDto {min, max, sizeMm, centerMm}`, `DirectionDto {x,y,z}` unit vector, `HitDto {elementId, category, name, documentTitle, linkInstanceId?, pointMm, normal, distanceMm}`. Converters from `XYZ`/`BoundingBoxXYZ` live in `GeometryConvert.cs` (Revit) and use `MoveElementsMath.MmPerFoot`. Replace the anonymous payloads in `InspectSelectedElementsTool`, `GetLinkedElementsInRoomTool` and `DeviceRecord.PointPayload` with these DTOs (same field names so existing clients keep working: `location {x,y,z}`, `bbox {minX..maxZ}` are kept as aliases via a `legacy=true` default for one release and documented).

### `revit_get_element_geometry`

`elementIds[]` (≤ 100, `QueryGuard.ValidateGeometryQuery` logic reused: refuse unscoped), `linkInstanceId?` (ids in that link, transformed to host via `RevitLinkInstance.GetTotalTransform`), `includeSolidsSummary` (volume mm³, face count, from `ClashSolidExtractor.TryExtract`; default false). Per element: `location` (`LocationPoint.Point`/`Rotation`, or `LocationCurve` endpoints and length), `bbox` (model bbox or view bbox for view-specific elements, `get_BoundingBox(ownerView)` as `MoveElementsService.TrackingPoint` does), `facing`/`hand` (`FamilyInstance.FacingOrientation`, `HandOrientation`, `Mirrored`), `host {id, category}` (`FamilyInstance.Host`), `level` (the `RevitGraphExtractor.LevelOf` logic extracted to `LevelResolver`), `room` (via `ElementRoomSupport`, default phase), `ownerViewId`, `isPinned`, `groupId`.

### Boxes and radius

`revit_find_elements_in_box`: `box {min,max}` mm, or `aroundElementId` + `paddingMm`, or `roomId` (bbox of the room polygon, `RoomSourceService`), `categories[]` (required unless `maxResults` ≤ 200, to respect the geometry caps), `mode` = `intersects` (default) | `inside`, `includeLinks` (default false; per link `linkNameFilters[]`), `levels[]?`, `maxResults` (default 200, max 2000). Host: `FilteredElementCollector(doc).WherePasses(new BoundingBoxIntersectsFilter(outline))` (`BoundingBoxIsInsideFilter` for `inside`) with `OfCategory` per category, excluding types; links: iterate `RevitLinkInstance`, transform the box into link coordinates with the inverse of `GetTotalTransform`, run the same filter in the link document, report `linkInstanceId`. Result rows: `{elementId, category, name, bbox, distanceToBoxCenterMm, link?}`.

`revit_find_elements_near`: `point` or `elementId` (its location or bbox center), `radiusMm` (≤ 50 000), `categories[]`, `includeLinks`, `maxResults`; implemented as an in-box prefilter (cube of side 2r) then exact bbox-to-point distance (`ClashBoundingBoxMath` gains `DistancePointToBox`), sorted ascending.

### Ray casts

All three ray tools use one `RayCaster` built from the `AlignmentService` code: `ReferenceIntersector(view3D) { TargetType = Face, FindReferencesInRevitLinks = includeLinks }`, `NearestHit` on `Proximity`, `ResolveTarget(Reference)` for linked elements, category filtering **after** the hit (the service's own comment explains why no ElementFilter). View choice through `AlignmentRequest.ResolveSearchView` (argument `searchViewId`, else active 3D, else first non-template 3D; the result carries a warning when a section box limits the search). Extract the shared parts of `AlignmentService` and `FacePlacementService` into `Geometry/RayCaster.cs` and make both use it.

- `revit_find_nearest_surface`: `point` (mm) or `elementId` (bbox center), `surfaces[]` = `wall|ceiling|floor|roof|any` (classified with `AlignmentMath.ClassifySurface` by hit normal plus the hit element's category), `directions` = `horizontal` (default: 8 or 16 compass directions, `AlignmentMath.SearchDirections`) | `up` | `down` | `all` | explicit `[{x,y,z}]`, `maxDistanceMm` (default 10 000), `categories[]?` restrict blockers, `includeLinks` (default true). Result: best hit per requested surface kind plus `hits[]` per direction.
- `revit_check_line_of_sight`: `from`, `to` (mm), `blockingCategories[]` (default walls, floors, ceilings, roofs, doors, structural columns/framing, curtain panels, generic models), `ignoreElementIds[]` (the camera and its target), `includeLinks` (default true). Cast from `from` towards `to`; a hit with `Proximity < distance - 1 mm` on a blocking category = blocked. Result `{clear, distanceMm, blockedBy: HitDto?, hits[] (first 10)}`.
- `revit_measure_clearance`: `elementId` or `point`, `directions` (default the six axis directions, from the bbox faces: the ray starts at the bbox face center, not the element center, so the clearance is the gap), `maxDistanceMm` (default 5 000), `ignoreElementIds[]` (defaults to the element itself and its hosted children), `categories[]?`. Result per direction `{direction, freeMm, hit: HitDto?}`, plus `minFreeMm` and the direction.

Caps: `QueryLimits.MaxGeometryElements` (100) ids per call for geometry reads; 32 directions per ray tool; `maxResults` ≤ 2 000 for collectors. Every tool rejects a call with no scope (`QueryGuard.ValidateGeometryQuery`'s result shape, status `geometry_query_too_broad`).

### Status codes

`geometry_query_too_broad`, `no_3d_view_for_raycast` (hint: create one with the view creation tool), `link_not_found`.

## Implementation order

1. DTOs, `BoxMath`, `ClearanceMath`, `SurfaceClassifier`, `LevelResolver` + tests; refactor the extractor to `LevelResolver`.
2. `revit_get_element_geometry`; migrate the two anonymous payloads.
3. `revit_find_elements_in_box`, `revit_find_elements_near` (host, then links).
4. `RayCaster` extraction with `AlignmentService`/`FacePlacementService` regression check (the `revit_align_elements` and `revit_place_on_face` manual tests from their docs still pass); then the three ray tools.
5. Bridge, groups, docs, benchmark.
6. Manual test (2026 and 2024) on an EN model with a linked ARH model: geometry of a detector (facing, host ceiling in the link, room); elements in a room box; luminaires within 3 m of a panel; nearest wall from a socket in 16 directions (distance matches Revit's measure within 5 mm); line of sight camera→door blocked by a wall vs clear through a doorway; clearance around a panel (front ≥ 1 000 mm rule).

## Acceptance criteria

- Every output is in mm with 0.1 mm rounding, host coordinates, link elements carry `linkInstanceId`, and all distances agree with Revit's Measure tool within 5 mm.
- Unscoped geometry queries are refused with `geometry_query_too_broad`; scoped ones respect the caps.
- Ray tools work without an active 3D view by using the first 3D view and say which view they used; `revit_align_elements` and `revit_place_on_face` behave as before after the refactor.
- Existing payload fields of `revit_inspect_selected_elements` and `revit_get_linked_elements_in_room` remain readable by old clients for one release.
- Unit tests green, both targets build, benchmark report committed.

## Out of scope

Solid-to-solid clearance (true minimum distance between geometries; bbox and rays are the approximation here), visibility analysis over areas, room coverage (exists in `revit_check_coverage`), geometry export.
