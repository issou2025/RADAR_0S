## Project Understanding

**iOS: render GFM tables and task lists in bot messages**

*Project description:*
## Background

The iOS companion already renders a subset of Markdown in bot bubbles. `Markdown.blocks` splits paragraphs, headings, lists, quotes, rules, and fenced code, and `MarkdownText` draws them. Inline emphasis, code spans, strikethrough, and links go through Foundation `AttributedString`.

Desktop bot bubbles use react-markdown plus remark-gfm, so tables and task lists are structure. On the phone they are not:

1. A pipe table mixed with prose stays literal `| col | col |` text. The block splitter has no table case.
2. A message whose every non-empty line is a pipe table never reaches `MarkdownText`. `TextBubble.parsedTable` replaces the whole bubble with `SQLResultTableView` ("DATA TABLE", monospace cells, Copy CSV). That chrome is wrong for a comparison or research table, and desktop does not do it.
3. A task item (`- [ ]`, `- [x]`, `- [X]`) matches the bullet rule, so the checkbox stays in the text as brackets.

People reading the same reply on the phone and on the computer do not see the same message.

## Acceptance

- A bot message that contains a GFM table renders a header, body rows, and column alignment (`---`, `:---`, `---:`, `:---:`), whether prose surrounds the table or the table is the whole message.
- Cell text still gets inline markdown (emphasis, code spans, links).
- A message that is only a markdown table uses that table. It does not use `SQLResultTableView`.
- A one-line run-on table (`| A | B | |---|---| | 1 | 2 |`) and a delimiter row whose width does not match the header still become a table, matching the repairs desktop already applies before remark-gfm.
- Pipes inside a fence stay code. A line with pipes but no delimiter row stays a paragraph. User messages stay literal, same as desktop.
- Task items show a checked or unchecked marker. The bracket syntax is not the visible label. `- [x]no-space` stays an ordinary bullet, because GFM requires whitespace after `]`.
- Streaming prefixes do not drop cell text or item text. An open fence still wins over anything inside it.
- Walkie does not read a delimiter row aloud, and it does not read checkbox brackets. Cell and item text are still spoken.
- `cd ios && swift test` covers the new block cases. Removing the table parse or the task parse fails those tests.
- The iOS app target still builds (`xcodebuild` for the simulator).

## Non-goals

- Rendering the person's own messages as Markdown.
- Images, @mentions, thread-ref chips, syntax highlighting, spoilers, or raw HTML.
- Tables nested inside lists or blockquotes.
- Changing the desktop renderer or `repairMarkdownTables`.
- A Copy CSV action on ordinary markdown tables.
- Android. The same gap is tracked in #1707 and stays out of this change. The Kotlin copies are not compiled with the iOS tests.

## Constraints

- The splitter stays in CompanionCore (Foundation only) so `swift test` covers it without a simulator.
- Drawing stays in the app target.
- Do not pair against a live desktop or mutate a real transcript. UI checks use the offline thread-preview fixture.
