### Owner-protected standing rules
- **Never delete / never automatically reclassify L5**: original GPT-4-era ChatGPT conversation archive (~1GiB), photos, independent ~40GiB Mac disaster-recovery copy, original financial/recovery/escrow evidence. Level 1 is the only possible automated class, and even then only for proven disposable exact-target entries under a scoped owner policy; L2 requires informed category consent, L3 item consent, L4 human only. No automatic Finder reindex or L5 cleanups.
- **Do not conflate code and reality**: `IDEA → QUEUED → ASSIGNED → BRANCH_WIP → EXACT_SHA_TESTED → INDEPENDENT_REVIEWED → MERGED → DEPLOYED_BUILD_ID → LIVE_VERIFIED`. A CI green or DocsV2 green never advances a host or money status by itself.
- **Do not confuse website W1 with funded War Satchel**: W1 is nonfinancial; separate signer/reserves, consent, actual legal compliance, historical liabilities, original financial source and one explicit user Keplr signature must qualify funded mainnet actions.
- **Never suppress history or discard WIP**: no reset/clean/force-rebase on another agent's branch; exact parent SHA and paths preserved. No silent merging of parallel unfinished features into frozen release.
- **No 24/7 chat illusion**: ChatGPT session tabs operate only when the owner wakes them. Hourly Six-Lane Watch summarizes material GitHub events, but does not actuate sessions or remotely modify hosts. Installed background services need explicit owner permission and real rollback.

## Standing scheduling algorithm — for every Central Command conversation
1. **Read this issue**, then newest [Central #934](https://github.com/Emaren/app-prodn/issues/934) and six original lane issues plus source heads/current CI. Use exact source paths and receipts, not saved memory or old frozen example SHAs.
2. **Capture each new owner idea in the queue first.** Include desired outcome, next small deliverable, rough P0–P3, dependencies, planned branch and a measurable completion test. Don't reassign an occupied engineer.
3. **Check real occupancy** using owner updates in the current conversation/issue; if uncertain mark `UNKNOWN/OCCUPIED`. A merged PR isn't a license to interrupt ongoing work.
4. **When a lane reports FREE**, choose highest-impact unblocked entry matching that lane's repository/skill, verify exact worktree/branch occupancy and file ownership, then post a narrowly scoped order in the lane's original issue. The owner pastes it into that tab. Mark `ASSIGNED` with source issue link.
5. **Require return receipts**: what changed, exact branch and SHA, tests/CI, original-source comparison, actual host proof if applicable, unresolved external decision and one next action. Review independently before merge; run postmerge CI.
6. **Keep W1 production critical path at top** until LIVE_VERIFIED. Release a lane for a queued item rather than inventing busywork. When all six remain occupied, only update this priority queue and the central ledger; do not start unbounded parallel features.
7. **Every future session startup**: user may type `⚔️ Resume Central Command. Read the standing priority queue and #934. Preserve the six active assignments; select the next unblocked queue item only when a lane is free.`
