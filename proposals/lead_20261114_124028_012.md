# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
****Title: Deploy the FastAPI backend and Flutter builds so testers can use them without the laptop****

*Project description:*

**Problem**

The backend runs only on the developer's laptop. Testers can't reach it unless the laptop is on, awake, and either on the same Wi-Fi or behind a temporary tunnel. Builds are installed by hand, and every API change risks breaking older app versions already on people's phones. Nothing is deployed from `main`, so there's no repeatable release process. The server has no authentication yet, so a public URL needs a rate limit and a budget guard before wider sharing.

**Solution with AWS**

- Run the server as a container on **EC2** behind **nginx** on ports 80 and 443. The container listens only on `127.0.0.1:8080`, and the security group allows 80 and 443 only.
- Push images to private **ECR**, tagged with the commit SHA and `latest`.
- Deploy from `main` with **GitHub Actions**, using OIDC to assume an IAM role. The workflow builds, pushes, then restarts the container on EC2.
- Keep runtime secrets on the instance in an env file (or in **SSM Parameter Store** later), never in the repo or the image.
- Add a **Route 53** domain and a **Certbot** or **ACM** certificate for HTTPS, so the Flutter release build can use `https://`.
- Set an **AWS Budgets** alert on the account.
- Distribute the phone build through **Firebase App Distribution**, and the web build through **S3 + CloudFront** if you need a browser version.

**Solution with open source**

- Use **Docker Compose** on the server, with the FastAPI service and **Caddy** as the reverse proxy. Caddy handles HTTPS certificates automatically.
- Use **GitHub Actions** with the Docker build and an SSH deploy step, or push to **GHCR** instead of ECR.
- For a free demo host, **Render** or **Fly.io** can run the container, but both sleep or cost money past their free limits.
- For temporary sharing without a server, use **Cloudflare Tunnel** or **ngrok** from the laptop. This is a demo only, since it depends on the laptop staying on.
- Use **Firebase App Distribution** for Android builds and **Firebase Hosting** for the web build, both free.

**Acceptance criteria**

- Pushing to `main` builds, tests, and deploys the backend without manual steps, and the deployed `/health` returns OK.
- The Flutter release build points at the HTTPS URL, and a tester can ask a question from their phone with the laptop off.
- Plain HTTP and port 8080 are not reachable from outside.
- Secrets appear nowhere in the repo, the image, or the CI logs.
- An API change is versioned, so the previous app build keeps working until testers update.

**Priority**

Medium-high. It's needed before anyone outside your laptop can try the app, but it depends on the ingestion fix, since a deployed server that crashes on multi-page PDFs isn't worth sharing. Do it before multi-tenant is fully rolled out to external users, and before chat memory, so the deployed version includes the auth and data isolation changes.
