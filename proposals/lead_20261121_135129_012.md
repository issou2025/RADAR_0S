# Project Proposal — Flutter App

**feat(adhkar): add opt-in Morning and Evening reminders**

*Project description:*
## Goal

Add respectful, opt-in local reminders for the Morning and Evening Adhkar collections. Reminders should help users remember their chosen routine without creating pressure, implying religious obligation, or repeatedly interrupting them.

This is the next Adhkar Phase 2 task after Explore/Search, Personal Routines, and Independent Tasbih.

## Scope

### 1. Independent reminder preferences
- Provide separate Morning and Evening reminder settings.
- Each reminder is disabled by default and enabled only after the user explicitly opts in.
- Let the user choose a local time for each enabled reminder.
- Allow either reminder to be disabled independently.
- Provide a clear global control to disable all Adhkar reminders.
- Saving or scheduling a personal routine must not silently enable a reminder.

### 2. Notification behavior
- Use local notifications; the reminders must work without an internet connection.
- Schedule at most one notification for each enabled reminder at its selected local time.
- Do not send repeated follow-ups when a notification is ignored or dismissed.
- Use calm, neutral wording. Do not say or imply that the user missed an obligation, failed, or is behind.
- Tapping a Morning reminder should open the Morning collection; tapping an Evening reminder should open the Evening collection.
- Do not create reminders for other collections or personal routines in this task.

### 3. Permissions and time handling
- Respect Android notification permission requirements and denial.
- Explain when permission is needed; do not repeatedly prompt after denial.
- Keep the user's selected preferences even if permission is denied, while clearly showing that notifications are unavailable until permission is granted.
- Schedule using the device's local time and handle relevant rescheduling after app restart, device reboot, or time/time-zone changes where supported by the platform.
- Avoid duplicate scheduled notifications when preferences are edited, toggled, or rescheduled.
- Respect configured quiet hours if the app already has a reusable quiet-hours preference; otherwise implement a simple quiet-hours setting only if needed to satisfy the parent issue, without expanding into a general notification framework.

### 4. Persistence and reliability
- Persist reminder preferences locally.
- Keep reminder configuration separate from Adhkar content, reading sessions, bookmarks, routine progress, Tasbih state, and completion history.
- Ensure disabled reminders are cancelled.
- Handle notification scheduling failures visibly and safely; do not falsely show a reminder as active if scheduling failed.
- Preserve preferences through app restart and the existing backup/restore approach where appropriate. Do not make backup compatibility fragile.

### 5. UX and accessibility
- Add a clear entry point to reminder settings from the Adhkar experience or app settings.
- Show each reminder's enabled state and selected time.
- Explain that reminders are optional and can be changed or disabled at any time.
- Support Arabic RTL and larger text scaling without overflow.
- Keep setup lightweight and avoid a lengthy onboarding flow.

## Out of scope
- Prayer-time notifications or Salah reminders.
- Automatic reminders for personal routines.
- Repeated notifications, escalating reminders, streaks, scores, badges, or guilt-based messaging.
- Server push notifications, accounts, or internet-dependent scheduling.
- New religious content or AI-generated religious text.
- General-purpose notification scheduling framework beyond what this feature needs.

## Acceptance criteria
- Morning and Evening reminders are independently configurable and disabled by default.
- User can choose a local time for each reminder.
- User can disable either reminder or all Adhkar reminders.
- Notification permission denial is handled gracefully and preferences are retained.
- Each enabled reminder schedules no more than one notification at its chosen time; ignored notifications do not trigger follow-ups.
- Tapping a notification opens the correct collection.
- Editing settings does not leave duplicate or stale scheduled notifications.
- Preferences survive app restart; scheduling is restored appropriately after reboot/time changes where supported.
- Scheduling failures are surfaced safely and state is not misrepresented.
- Reminder behavior is isolated from routines, Tasbih, sessions, bookmarks, and history.
- Tests cover scheduling, cancellation, permission states, duplicate prevention, deep-link navigation, persistence, and RTL/large text where applicable.
- Developer reports Flutter tests, analyzer, and formatting results in the PR.
