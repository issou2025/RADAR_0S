# Store screenshot automation — implementation plan

**Status:** Approved concept → phased implementation plan

The goal is to regenerate every store `*_raw.png` with one command per platform. Every run uses the same seeded data, the same status bar, and the exact output sizes that `assets/store/screenshots.af` links to. The brainstorm and decisions are in the issue comments.

## Resolved open questions

- **Driver: Maestro (A2).** It captures the full device screen, including the status bar, and has built-in `startRecording`, so App Store previews stay possible.
- **State: a dedicated entry point (B1).** It seeds `assets/data/20260925_sample_simple.json` on launch.
  - The data ends on 2026-06-20 and there is no clock abstraction (119 `DateTime.now()` calls), so dates are **shifted to "now"**. Otherwise "Due now" (06) and Calendar (08) drift.
- **Strava: mock only `SubscriptionService.hasStravaEntitlement` plus the Strava DB tables** (athlete, gear, activities).
  - No sync, OAuth or purchase logic is mocked.
  - These rows feed screen 07 (map + activity sheet) and the Strava-derived component stats on screen 01.
- **Firebase:** the screenshot entry point calls only `Firebase.initializeApp()`, so `StravaService` stays idle without a signed-in user.
  - No App Check, Crashlytics, Analytics or FCM, and no dependency on the debug token.
- **Map:** live OpenStreetMap / CyclOSM tiles with a generous wait. No offline tiles.
- **Devices (C1):**
  - Two dedicated Android AVDs: a 1080×2400 phone and a 1200×1920 tablet. These replace the resizable emulator.
  - The existing iPhone 17 Pro Max and iPad Pro 13" (M5) simulators.
  - Status bar fixed via Android SystemUI demo mode and `xcrun simctl status_bar`.
- **Selectors:** `Semantics(identifier: …)`, not visible text, so localization (#18, coming soon) doesn't break the flows.
- **Location: everything under `tool/screenshots/`.** No new root directory.
- **Output (F1):** overwrite `*_raw.png` in place, followed by a size check and a changed-files report.
  - Affinity links the raws, and recomposition is one click.
  - ⚠️ **If any output size differs from the current raw sizes, notify the user**, because the Affinity device frames would need adjusting.

  | Folder | Raw size (px) |
  |---|---|
  | phone | 1080×2400 |
  | tablet | 1200×1920 |
  | iPhone | 1320×2868 |
  | iPad | 2064×2752 |

- **Videos:** App Store previews only. This plan only proves recording works (Phase 6) and does not produce previews.
- **Sample assets in the bundle:** the sample JSON and Strava manifest (~0.2 MB) are declared as pubspec assets, so they also ship in release builds.
  - This is accepted. It is simpler than pushing files onto devices or introducing native flavors.
- **CI (GitHub Actions):** out of scope; possible follow-up.

## Feature flag

None. This is developer tooling, not a user feature. Everything runs from `lib/main_screenshots.dart` (`flutter run -t lib/main_screenshots.dart`).

`lib/main.dart` only gains optional seams on `LoadingGate` (service override and skipping platform services). Their defaults keep today's release behavior unchanged.
