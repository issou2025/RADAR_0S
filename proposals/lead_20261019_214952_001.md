## Problem
When a supported ExotiKeeper export format has been confirmed, users should be able to convert their own files into TerraManager records without cloud services.

## Scope
- Implement a versioned parser for verified user-provided export files only.
- Map species/animals, enclosure links and historical events where representable.
- Preserve timestamps/time zones and make missing or unsupported fields explicit.
- Use safe parsing with strict size, type and malformed-input validation; never execute imported content.
- Plan image attachment handling and duplicate identification based on confirmed format evidence.
- Keep import local and avoid transmitting file contents to developer services.

## Acceptance criteria
- [ ] Valid supported export files parse deterministically with meaningful diagnostics.
- [ ] Known fields map to existing TerraManager entities without silent data corruption.
- [ ] Unsupported fields appear in an import report or are preserved as notes if explicitly accepted.
- [ ] Malformed, incompatible and oversized files fail safely.
- [ ] Fixtures and automated parser/mapping tests are included.
