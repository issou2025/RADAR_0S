# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**MCP: a command saved during a session never reaches tools/list, so the authoring loop cannot be tested**

*Project description:*
Found while field-testing the 1.5 MCP server (#96) in a live Revit session.

After `SaveAsCommand`, the agent could not call `niko.room-sheets.CreateRoomPlanSheets`. It copied the class back into `ExecuteRevitCode` to test it — and that is where the scale bug in the command was found, so testing the saved thing is not optional.

This breaks exactly the loop §7.2 of the authoring guide describes: write → save → run.

## The bug is narrower than it first looked

The plugin log rules out the obvious explanation. Registration works perfectly:

```
23:09:22.837 SaveAsCommand: created command niko.room-sheets.CreateRoomPlanSheets
23:09:23.109 Loaded script extension niko.room-sheets
23:09:23.109 Reload done — 78 commands registered
```

and saved commands are callable from every other transport, immediately:

```
21:52:11.286 Command niko.sheet-creator.GetSheetContext invoked via ribbon
23:15:34.780 Command niko.room-sheets.PickRooms invoked via webview2
```

So the command exists, is registered, and runs. The only thing missing is that **the AI client's tool list is stale** — it was fetched before the command existed and nothing tells it to refetch.

## Fix

Send `notifications/tools/list_changed` when the registry changes. `CommandQueue` already fires `RunningChanged`; extension reloads have a similar moment (`Reload done — N commands registered`) that the bridge can hook and turn into the notification for every connected client.

Worth checking while there: whether the reload fires it once per reload rather than once per loaded extension — the log shows one reload touching eight extensions.
