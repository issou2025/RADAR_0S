# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**The generated readiness check prints a literal instead of the missing asset's name**

*Project description:*
The readiness check `good generate` emits names no asset. It prints the literal
text `${k.source.description}`, once per missing asset.

`packages/good_cli/lib/src/generate/templates.dart:197`:

```dart
'\${missing.map((k) => '  \\\${k.source.description}').join('\\n')}\\n'
```

The inner interpolation is escaped one level too far. `\\` emits a backslash and
`\$` emits a dollar, so the generated file receives `\${k.source.description}` —
and in the generated Dart that backslash-dollar is an escaped dollar, which
means no interpolation happens at all.

The emitted line, from a generated project:

```dart
'${missing.map((k) => '  \${k.source.description}').join('\n')}\n'
```

The outer interpolation over `missing` is correct and does run. So the message
gets one line per missing asset — the count is right — and every line reads
`${k.source.description}` instead of naming the file.

## Why it matters more than a cosmetic slip

This string only ever renders when something is already wrong: an asset is
declared and will not be there at run time. The name is the entire payload. A
list of three identical placeholder lines tells you how many are missing and
gives you no way to find out which, at the one moment the answer is wanted.

It is also invisible to every existing check. The generated file analyzes clean,
because a literal string is perfectly valid Dart, and no test asserts on the
message body.

And it survives `good generate`. Fixing it in a project is pointless — the next
regeneration writes it back.

## Fix

Reduce the escaping so the inner interpolation reaches the generated file
unescaped. Then assert on it: generate a project with a declared-but-absent
asset, run the readiness check, and require the asset's own name in the output.
A test that only counts lines passes today.
