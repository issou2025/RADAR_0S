# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**app_logs buffer is lost when the same device is re-attached after a switch to device mode**

*Project description:*
## Environment
- macOS 27, Xcode 27, iOS 26.4 simulator (iPhone 17 Pro)
- Flutter debug app (prod flavor) attached in flutter mode, plus a second simulator attached in device mode

## What happened
1. I was attached to the app in flutter mode, and it was logging `[EventTracker] ...` lines through the `logging` package.
2. An iOS "Allow Paste" system alert came up (#258). I needed to tap it, so I attached the same device in device mode: `attach device:"<udid>" mode:"device"`. That replaced the flutter-mode session for the device.
3. I tapped "Allow Paste" by x,y. The app went on and logged the event I was testing.
4. I re-attached to the same VM service URI in flutter mode.
5. `app_logs` returned `(no entries)`, with `nextSequence: 0`.

Every line the app logged before the re-attach was gone, including the event I had just triggered. The `flutter run` stdout file didn't have it either, because `logging` records go through `developer.log` and don't reach stdout.

## Expected
Either of these:
- Keep the per-app log buffer across re-attaches to the same app and VM service (the app process didn't restart), or
- Keep capturing app logs while the device is attached in device mode, so a short switch to answer a system alert loses nothing.

At minimum, `attach` should warn that switching modes drops the buffer.

## Workaround
I triggered the flow again with the native prompt avoided: I hardcoded the input in a temporary patch, so the agent never had to leave flutter mode.

## Impact
For event and log verification, this is silent data loss. The agent did the right thing (answered the system alert), and the evidence it needed disappeared without warning. Combined with #258/#265, any flow that hits a native prompt can't be verified from `app_logs` in a single pass.
