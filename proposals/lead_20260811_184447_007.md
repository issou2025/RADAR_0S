## Project Understanding

**AI Analytics UI, Insights and Testing**

*Project description:*
# Build AI Spending Analytics and Prediction User Interface

## Objective

Build the user-facing AI analytics experience that displays predictions and financial insights produced by the AI integration layer.

The interface must clearly communicate:

* Current spending
* Predicted month-end spending
* Prediction confidence
* Expected additional spending
* Budget risk
* Relevant financial insights
* Insufficient-data states
* Loading and error states

The UI must use the existing Mobile Budgeting App visual style and integrate naturally with the existing graphical reports, budget management, and spending insights functionality.

---

## Scope

This task covers:

* Designing and implementing the AI analytics screen.
* Consuming predictions from `AiAnalyticsService`.
* Building reusable prediction widgets.
* Displaying month-end spending forecasts.
* Displaying confidence information.
* Displaying budget-risk messages.
* Handling loading, empty, insufficient-data, and error states.
* Adding navigation to the AI analytics screen.
* Writing widget tests.

This task does **not** include training the TensorFlow model or directly querying Drift transaction tables.

The UI must consume the AI service layer created by the integration developer.

```text
lib/views/ai_analytics/
```

```text
    └── insufficient_data_card.dart
```

The exact structure may be adjusted to match existing project conventions.

# Part 2 — Main Spending Forecast

The screen should prominently show the user's current and predicted spending.

Example:

```text
AI Spending Forecast

Current spending
R2,950

Predicted month-end spending
R7,180

Estimated additional spending
R4,230
```

The values should come from:

```dart
SpendingPrediction
```

and not be calculated independently in the UI.

---

# Part 3 — Prediction Confidence

Display the confidence level returned by the prediction layer.

Possible representations:

```text
Prediction confidence
78%
```

or:

```text
High confidence
Medium confidence
Low confidence
```

Suggested mapping:

```text
0–39%   -> Low
40–69%  -> Medium
70–100% -> High
```

The UI should not imply certainty.

Avoid wording such as:

```text
You will spend R7,180.
```

Prefer:

```text
You are currently projected to spend approximately R7,180 this month.
```

---

# Part 4 — Budget Risk

Where budget data is available, compare predicted spending against the user's budget.

Example:

```text
Monthly budget
R6,500

Predicted spending
R7,180

Projected difference
R680 over budget
```

Possible visual states:

```text
Within budget
Approaching budget
Likely to exceed budget
```

The UI should clearly distinguish a prediction from an actual recorded amount.

---

# Part 5 — Spending Insight Messages

Generate simple deterministic insight messages from structured prediction data.

Examples:

```text
Your current spending trend suggests that you may exceed your monthly budget.
```

```text
Your spending is currently tracking below your recent monthly average.
```

```text
You have already used 82% of your expected monthly spending.
```

```text
Your spending pace is higher than last month.
```

These messages should initially be generated from calculation rules.

Do not require generative AI for the first implementation.

---

# Part 6 — Historical Context

Where available, display comparison information such as:

```text
Previous month
R6,700

3-month average
R6,300

Predicted this month
R7,180
```

Possible insight:

```text
Projected spending is 14% higher than your 3-month average.
```

The values should come from the application service layer rather than requiring the UI to directly query Drift.

---

# Part 7 — Loading State

While the application is calculating features or running AI inference, display a proper loading state.

Example:

```text
Analysing your spending...
```

The interface should not appear frozen.

Loading widgets should follow the current app theme.

---

# Part 8 — Empty State

If there are no transactions:

```text
No spending data available yet.
```

Provide helpful context such as:

```text
Add transactions to start receiving AI-powered spending forecasts.
```

The screen should not show:

```text
R0 predicted
```

as if that were a meaningful AI prediction.

---

# Part 9 — Insufficient Data State

When the prediction service determines that history is insufficient, display a clear message.

Example:

```text
More spending history needed

We need more transaction history before we can provide a reliable spending forecast.
```

Optional supporting message:

```text
Keep recording your transactions and your predictions will improve over time.
```

---

# Part 10 — Error State

If model loading or inference fails, the UI must not crash.

Example:

```text
Spending forecast unavailable

We could not calculate your prediction right now.
```

Provide a retry option where appropriate.

The UI should not expose technical errors such as:

```text
Tensor allocation failed
Interpreter error
Invalid input tensor
```

to the end user.

---

Create a reusable component for spending predictions.

Possible content:

```text
MONTHLY FORECAST
```

The card should follow the app's existing visual language.

# Part 12 — AI Labelling

The interface should clearly indicate which values are AI-generated predictions.

Possible labels:

```text
AI Forecast
AI Spending Insight
Predicted Spending
```

Actual financial data and model predictions should remain visually distinguishable.

For example:

```text
Actual spending: R2,950
AI forecast: R7,180
```

Possible button:

# Part 14 — Overall Monthly Forecast

The first required implementation should focus on the user's overall monthly spending.

Required display:

* Current monthly expenses
* Predicted month-end expenses
* Prediction confidence
* Additional expected spending
* Previous-month comparison
* Three-month comparison where available
* Budget-risk indicator if budget information exists

# Part 16 — Widget Testing

Write widget tests for the major UI states.

Required scenarios:

* Current spending
* Predicted spending
* Confidence
* Expected additional spending

### Loading state

Verify loading indicator/text appears.

### No data

Verify empty-state content is displayed.

### Insufficient data

Verify the insufficient-data message is shown.

### Prediction error

Verify a safe error message appears.

### Budget exceeded

Verify the appropriate over-budget warning appears.

### Within budget

Verify the safe/within-budget state appears.

# Part 17 — Mock Data During Parallel Development

The UI developer should not wait for TensorFlow integration to be finished.

Use mock `SpendingPrediction` objects during development.

Example:

```dart
SpendingPrediction(
  currentSpending: 2950,
  predictedMonthEndSpending: 7180,
  confidence: 0.78,
)
```

This allows the UI to be developed in parallel.

Once `AiAnalyticsService` is available, replace mock data with real service calls.

---

# Part 18 — Accessibility and Usability

Ensure:

* Important messages are readable without relying only on colour.
* Warning states include text/icons.
* Currency values are readable.
* Layout works on common phone screen sizes.
* Long monetary values do not overflow.
* Loading/error messages are understandable.
* Predictions are labelled clearly.

---

# Part 19 — Currency Formatting

Use the application's standard currency formatting.

For South African Rand:

```text
R1,250.00
```

or the existing project convention.

Do not manually concatenate inconsistent currency strings across multiple widgets.

Where possible, centralize formatting or reuse existing helpers.

---

# Part 20 — Prediction Language

Use wording that reflects uncertainty.

Preferred:

```text
Projected spending
```

```text
Estimated month-end spending
```

```text
Based on your current spending pattern
```

Avoid:

```text
You will spend...
```

```text
Your final spending will be...
```

The AI feature should communicate that results are estimates.
