# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**[API & Automation] Add a Pulumi provider for managing Lightdash resources**

*Project description:*
## Problem / underlying need

Teams that manage their infrastructure as code want to provision and manage Lightdash resources using Pulumi, the same way they can today with Terraform. Keeping Lightdash configuration in the same IaC workflow as the rest of their infrastructure gives them plan/diff review, state tracking, and version control for things like projects, spaces, and permissions.

## Desired behavior

Users should be able to define and manage core Lightdash resources (e.g. projects, spaces, groups, permissions) as Pulumi resources, in their preferred Pulumi language (TypeScript, Python, Go, etc.), with Pulumi tracking state and applying changes through the Lightdash API.

## Acceptance checklist

- [ ] A Pulumi provider package exists and is available (published to the Pulumi registry or otherwise documented as installable)
- [ ] The provider can create, read, update, and delete at least the core resources: projects, spaces, and group/user permissions
- [ ] The provider authenticates using a Lightdash personal access token or service account token
- [ ] Basic usage is documented with a working example

## Workaround

None available today beyond calling the Lightdash REST API directly, or using the Lightdash CLI / content-as-code YAML workflow for dbt-backed provisioning.

## Scope

- MVP (minimum acceptable): A Pulumi provider covering the most commonly automated resources - projects, spaces, and access/permissions.
- Full / GA: Resource coverage matching the REST API's provisioning surface, including users, groups, custom roles, and warehouse connection config where applicable.
- Out of scope: Managing dashboard/chart content itself, which is already covered by content-as-code and dbt-based workflows.

## GA compatibility

- [ ] REST API & Python SDK
- [ ] Permissions & user attributes

## Impact

Requested by a customer looking to standardize infrastructure provisioning across tools alongside their existing Terraform usage for other systems.
