*Project description:*
## Summary

On the BIM4LCA office, a handful of property values Revit's export writes have no rule in rvt-rs yet. They are smaller than the clusters tracked elsewhere (#1016 and #1046 for quantities, #1185 to #1187 for type objects, stairs and curtain members), so they are collected here to keep W7 of the [1.0 release criteria](https://github.com/DrunkOnJava/rvt-rs/blob/main/docs/release-1.0-criteria.md) complete.

## Where things stand

Office as built, from the property census (`tools/re/psets_vs_ifc.py`, Measure run 41129228138 on `main` at b09310a6):

| Property | Missing | Notes |
|---|---:|---|
| `Pset_ColumnCommon.Slope` | 73 | A measured negative (RE-277): six columns have identical native records in both office files, yet Revit gives them `Slope` at permit only. No rule over a column's own record can be exact, so this needs a decision or a new signal. |
| `Pset_EnvironmentalImpactIndicators.Reference` | 28 | On openings (`VP-1` on 27). |
| `Pset_MemberCommon.Span` | 18 | Curtain mullions whose span RE-226 does not read. |
| `Pset_SlabCommon.PitchAngle` | 8 | Sloped slabs; RE-238 writes 0 where a slab's top is level. |

## Done when

Each value is written where a rule from the model gives Revit's value on every element it covers, with nothing different and nothing Revit's export omits. Anything left out is reported with its evidence and, where needed, the maintainer's decision.

## Where to start

Run Measure with `-f psets_missing=<set>.<property>` to list every object missing a property, then compare with the readers named in each report.
