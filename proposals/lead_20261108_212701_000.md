# Project Proposal — Structural Drawings

## Project Understanding
You need assistance with: 
**SCAN-BIM-IFC-DELIVERY-001: qualify editable IFC outputs through independent openBIM validation**

*Project description:*
## Mission

Prove that an admitted Scan-to-BIM candidate is not merely a hash-identified IFC-shaped file, but a usable, exchangeable building model whose required geometry, topology, identities, units, placements and information survive independent validation and an explicit edit/round-trip path.

This is a child integration workstream of [SCAN-BIM-ADMISSION-001 #4086](https://github.com/Luminous-Dynamics/symtropy/issues/4086) and composes with the existing BUILT-INTEROP validation owners. It does not create another IFC parser, IDS engine, geometry kernel, or semantic-diff implementation.

## Why this is the next gap

The Scan-to-BIM replay receipt (#4188) binds exact IFC and element-graph output bytes, but byte integrity does not establish that an IFC file is parseable, schema-valid, information-complete, semantically preserved, or still editable after another tool imports and exports it.

The broader BUILT-INTEROP programme already owns the needed independent validation ladder and components:
- #2056 / #2057: fail-closed eight-gate report contract.
- #2010 / #2013: pinned Rust IFC4 + narrow IDS 1.0 ingestion adapter.
- #2020 / #2036: rights-aware official IDS corpus inventory.
- #2059 / #2060: IFC schema validation.
- #2079: offline IDS XML/XSD validity.
- #2073 / #2007: paired source-to-target semantic preservation.
- #2061: composition of independent gate outputs.
- #2117 and #2143: IFC structural diff and unit-aware value comparison.

The Scan-to-BIM work should consume these owners' outputs rather than reimplement their validators. Before using any component, inspect its current exact-head status and supported profile; open issues or historical CI passes are not evidence that an implementation is available on the selected branch.

## Paradigm shift

From: “The IFC file exists, its bytes match the replay receipt, and a viewer can display something.”

To: “The model has a declared exchange profile, its geometry and element graph have an explicit crosswalk, every required interchange gate has independently evidenced status, and a controlled round trip preserves the intended building information—or reports exactly what was lost.”

EditableInteropQualified is a profile-specific interchange claim, not proof of survey accuracy, physical truth, code compliance, structural safety, or authority to mutate an asset record.

## Input contract

Consume, without modifying their ownership:
- The exact Scan-to-BIM replay receipt and candidate-output digests from #4188 / #4116.
- The per-scene IFC artifact and corresponding element-graph artifact.
- The model's declared IFC schema / exchange profile, units, coordinate frame, axis order, handedness and placement conventions.
- An IDS 1.0 requirements artifact where applicable, with exact bytes and scope.
- The source model/revision and any source-to-target transformation receipt for round-trip tests.
- Independent validator gate reports from the BUILT-INTEROP owners, each bound to the same artifact and profile.

Do not require IFC4.3 for every dataset. The selected schema must be explicit and supported by the validator profile. Use the current official IFC release (buildingSMART IFC 4.3.2.0 / ISO 16739-1:2024) as a modern target profile where the source workflow can legitimately produce it; preserve legacy IFC profiles where benchmark compatibility requires them.

## P0 — synthetic delivery adapter

Create a versioned Rust-first adapter/report contract with:
- Exact binding from replay run + scene ID + IFC digest + element-graph digest to the independent interop report.
- Explicit IFC schema/exchange-view profile, unit/frame declarations and IDS requirement digest.
- A stable mapping between IFC GlobalIds and Scan-to-BIM element-graph IDs; GlobalId lexical validity or uniqueness alone must not be promoted to proof of physical identity.
- Separate gate states: artifact integrity, STEP parse, IFC schema validation, IDS XSD validity, IDS semantic support, IFC-vs-IDS conformance, source-to-target semantic preservation, geometry/topology equivalence, and edit/round-trip verification.
- Typed outcomes PASS, FAIL, UNRESOLVED and NOT_RUN; missing or unsupported gates never count as passes.
- A deterministic per-scene delivery receipt and explicit claim ceiling.

The adapter may compose producer reports but must not infer a gate result from log text, filenames, visual previews, or an overall Boolean.

## P0 adversarial corpus

At minimum:
1. Valid synthetic IFC + graph pair with all required mappings.
2. IFC bytes change after the replay receipt is created.
3. Duplicate or missing GlobalIds; graph node with no IFC counterpart; IFC element with no graph counterpart.
4. Two distinct elements collapsed because their geometry or names match.
5. Units, axis order, handedness, CRS/frame or placement origin changed without an approved transform.
6. Opening boundary / wall connection changes while the IFC remains parseable.
7. A hard IDS-required property is missing, changed, or changed from Unknown to a default value.
8. Unsupported IDS facet or IFC entity is incorrectly reported as preserved.
9. Validator report refers to a different IFC digest, scene, exchange profile or replay run.
10. Missing, duplicate, stale, truncated or contradictory gate reports.
11. Geometry changes beyond the predeclared exchange-profile tolerance while semantic properties remain identical.
12. Property ordering or STEP entity numbering changes without semantic change; canonical semantic comparison remains stable.
13. Round trip preserves a visible preview but loses an opening, relation, placement, property, or stable element identity.
14. A tool refuses or only partially supports an entity/representation; outcome is UNRESOLVED or FAIL, never qualified.
15. Input ordering changes only; output receipt remains deterministic after canonicalization.

## Benchmark tracks

Keep these dimensions separate; no weighted aggregate may hide a hard failure.

| Track | Measurement |
|---|---|
| IFC syntax/schema | Parse coverage, supported schema rules, errors, unsupported/evaluation errors |
| Information delivery | IDS hard-requirement preservation and explicit unsupported/missing counts |
| Identity | IFC ↔ element-graph correspondence, collision and orphan rates |
| Geometry | Independent bidirectional surface deviation, dimensions, opening boundaries and profile-specific tolerance |
| Topology | Wall/slab adjacency, containment, connectivity and opening relationships |
| Round-trip editability | Preserved elements/properties/placements/geometry after import, controlled edit and re-export |
| Evidence integrity | Same replay, scene, artifact, tool, configuration and validator digests |
| Operational interoperability | Manual repair effort, import/export failures, review time and cross-tool rework |

## Proposed acceptance targets (not results)

- 100% exact agreement with the frozen synthetic adapter oracle.
- Zero QUALIFIED or EditableInteropQualified outcomes while any required gate is FAIL, UNRESOLVED or NOT_RUN.
- Zero acceptance when an IFC digest, scene, model revision, IDS digest or validator report is mismatched or stale.
- 100% detection of seeded hard-property loss, unit/frame drift, identity collisions and required topology loss.
- 100% preservation of stable element correspondence and hard information requirements on the synthetic no-op round trip.
- Geometry passes only against an explicit, predeclared, profile-specific tolerance; no universal tolerance is invented.
- Unsupported or unimplemented checks remain visible in the denominator and block qualification where required.
- Report vendor/tool import, edit and export results separately; do not call an IFC parser pass a round-trip or editability result.

## P1 — independent implementations

After P0:
1. Run a bounded IFC profile through the existing pinned Rust parser/validator owners.
2. Compose IDS and semantic-loss results from existing BUILT-INTEROP producers.
3. Use a second independent implementation for differential parsing/round-trip comparison where licensing and exact version pinning allow it.
4. Add an editable non-load-bearing room fixture with walls, slabs, openings, doors/windows, spatial containment, placements, stable IDs and IDS-required properties.
5. Compare exact source → target → controlled edit → re-export → re-import semantics and geometry.

External vendor workflows (Revit/Autodesk, Leica, Trimble and other available toolchains) must be version/configuration pinned and measured on identical fixtures. Availability or a product feature list is not a benchmark result.

## Claim ceiling

A successful P0 proves only the adapter/report semantics on synthetic inputs. P1 can establish conformance for named software versions and declared IFC/IDS profiles. Neither proves that the reconstructed building is physically correct, structurally safe, code-compliant, professionally surveyed, or authorized for construction or asset-record mutation.
