*Project description:*
## In plain terms

`polygres-wizard` already automates one part of setting up Polygres: installing the CLI/SDK and logging you in, so you don't do that by hand. `analyze` is the next automation layer this roadmap builds — it's meant to do the *database and retrieval-config* work a developer would otherwise do manually through the Polygres CLI and docs: looking at your schema, figuring out which tables need graph search (relationships), semantic/vector search, or keyword search, and turning that into real Polygres configuration — plus, eventually, the application code that uses it.

If a later step is going to write code into your actual project repo (see I18 below), the wizard first needs to know *which* folder that is. This issue is that "where do I put this" logic — default to the folder you're standing in, look for a real project root, and ask if it's ambiguous.

---

## Summary

Stage 8's target-repo resolution — pure filesystem logic to establish, unambiguously, which repo/directory Stage 8's generated code and manifest edits should target. This part of Stage 8 is fully designed (the doc specifies the algorithm); only the manifest *editing* that follows it (#28/I17) is design-blocked.

## Scope

- Default to the current working directory.
- Walk up the directory tree looking for a `.git` root; warn (don't hard-fail) if none is found.
- Enumerate Python dependency manifests (`requirements.txt`, `pyproject.toml`, `Pipfile`) under the resolved root.
- On ambiguity (e.g. a monorepo with multiple Python subprojects/manifests), ask the user rather than guessing — consistent with this design's "ask when ambiguous, don't infer" posture used everywhere else.
- Record exactly one resolved repo path in session state for #28 (I17) and #29 (I18) to consume.

## Acceptance criteria

- [ ] Correctly resolves a single-manifest repo with zero prompts.
- [ ] Warns (not fails) when no `.git` root is found, and still proceeds with cwd.
- [ ] Prompts the user to disambiguate when more than one Python manifest is found under the root.
- [ ] Resolved path is stored once in session state and reused by downstream Stage 8 steps rather than re-resolved.
