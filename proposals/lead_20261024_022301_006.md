# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Autonomy 4/4: worker document — open a second local copy, worksets, checkout and relinquish, document-scoped tools**

*Project description:*
## Goal

Let the agent work in **its own copy of the model** while the user keeps working in theirs. Today every tool except the `documents` group acts on `uiapp.ActiveUIDocument.Document`, so the agent and the user fight over the same document, the same active view and the same selection. This issue adds the worksharing tools the agent needs to own its work, and makes the `document` argument work for every tool.

| Tool | Permission | Purpose |
|---|---|---|
| `revit_open_document` | RequiresApproval | Opens a central model as a new local (or a detached copy, or a plain file) **without activating it**; selectable worksets |
| `revit_close_document` | DestructiveRequiresManualApproval | Closes a non-active document, with or without saving |
| `revit_list_worksets` | ReadOnly | User worksets of a document: id, name, owner, open/closed, editable, default, element count (from the graph when present) |
| `revit_set_workset` | RequiresApproval | Sets the active workset, or moves elements to a workset (`ELEM_PARTITION_PARAM`) |
| `revit_get_ownership` | ReadOnly | Checkout status of elements and worksets: owned by me, owned by someone else (who), not owned, and whether a newer version exists in central |
| `revit_checkout_elements` | RequiresApproval | `WorksharingUtils.CheckoutElements`; reports what could not be checked out and by whom it is owned |
| `revit_relinquish` | RequiresApproval | `WorksharingUtils.RelinquishOwnership` for elements, worksets, families, views, standards, or all |
| `revit_reload_latest` | RequiresApproval | `Document.ReloadLatest` to pull central changes without syncing |

Plus one cross-cutting change: **every tool resolves its document through one helper**, so `document="<title>"` works for reads and writes outside the `documents` group.

Part of the autonomy series with #98, #99 and #100. Independent of them; the job runner (#100) can target the worker document once this lands.

## Why

The ExternalEvent lane is Revit's single UI thread, so the user's Revit is never fully independent of the agent's work. What *can* be separated is the **model**: with its own local copy the agent owns its elements through worksharing, its writes never hit "element owned by another user", the user's selection and active view are never disturbed, and sync becomes an explicit, reviewable step. For real independence the connector already supports a second Revit instance (`revit_list_instances`, pinning); this issue is the building block that makes a second instance or a second document a worker.

## Design

### Document resolution for all tools

- Add `RevitMCP.Addin/Documents/ToolDocument.cs`: `static DocumentTarget? Resolve(UIApplication uiapp, McpToolRequest request, out McpToolResult? failure)` — a thin wrapper over `RevitDocumentResolver.Resolve` (`DocumentToolSupport.ResolveTarget` already does this for the documents group; move it here and keep the old name as a forwarding call).
- Migrate tools in waves, each wave one PR: (1) `core` and `query` groups (reads), (2) `edit` and `electrical` writes that use no UI, (3) `views`, `tags`, `devices`. A tool that needs the UI (selection, active view, `uidoc`) checks `target.IsActive` and returns `validation_failed` with the message "This tool needs the document to be active; call revit_activate_document first" when it is not. Keep a checklist in the PR description; `grep -c "ActiveUIDocument?.Document" RevitMCP.Addin/Tools` must trend to zero.
- Approvals already bind to the target document (`RevitDocumentResolver.ResolveApprovalDocument` in `ExternalEventHandler`), so no approval change is needed.
- Bridge: add `[Description(DocumentArgDescription)] string? document = null` to every migrated `[McpServerTool]` method (the constant exists at `RevitMcpTools.cs` ~line 6428). Do it with a script and review the diff; the schema grows by one optional string per tool, so run the benchmark `--schema-only` before and after.

### `revit_open_document`

Arguments: `path` (central `.rvt`, a plain `.rvt`, or a Revit Server / ACC path accepted by `ModelPathUtils.ConvertUserVisiblePathToModelPath`), `mode` (`newLocal` default for a workshared central | `detach` (`DetachFromCentralOption.DetachAndPreserveWorksets`) | `plain`), `worksets` (`all` | `editable` | `lastViewed` | `closeAll` | explicit names → `WorksetConfiguration` with `WorksetConfigurationOption` and `Open(IList<WorksetId>)`), `localFolder` (default `%LOCALAPPDATA%\RevitMCP\Locals\`), `audit` (default false), `activate` (default **false**).

Behaviour: validate `path` with `FilePathPolicy.ValidateRead` (and `AllowNetworkPaths` for UNC — most centrals are on a share; the policy default is off, so the result must say which config key to flip). For `newLocal`: `WorksharingUtils.CreateNewLocal(centralPath, localPath)` into `localFolder` with the name `<central>_<username>_mcp.rvt`, then `app.OpenDocumentFile(localModelPath, openOptions)` (`UIApplication.Application`). `OpenDocumentFile` opens without a UI window, which is exactly what a worker needs; `activate=true` instead calls `uiapp.OpenAndActivateDocument(modelPath, openOptions, false)`. Refuse when a document with the same central is already open (report its title), when the active document has an open transaction, or when the file is already a local of another user. Long-running: add `revit_open_document`, `revit_close_document` and `revit_reload_latest` to `LongRunningTools.Names`.

Result: `title`, `path`, `isWorkshared`, `centralPath`, `worksets {open, closed}`, `activated`, and the `document` selector to pass to other tools. Approval summary: "Open '<file>' as a new local copy (worksets: …). Nothing in central changes until revit_sync_with_central."

### `revit_close_document`

Arguments: `document` (required; never the active document — the API cannot close it from an add-in without `OpenAndActivate` tricks), `save` (`false` default | `true` → `doc.Save()` first; for a workshared local `save=true` saves the local only). Destructive because unsaved changes are lost; summary names the document, whether it is modified (`doc.IsModified`) and what will be discarded. Relinquish on close is **not** automatic; say so.

### Worksets and ownership

- `revit_list_worksets`: `FilteredWorksetCollector(doc).OfKind(WorksetKind.UserWorkset)` → `{id, name, owner, isOpen, isEditable, isDefault, isVisibleByDefault}`; `elementCount` from the graph's `ElementsByWorkset` when `revit_graph_status` says fresh, else omitted (never counted live without `countElements=true`, capped by `QueryLimits.MaxScanElements`). Reuse `RevitGraphExtractor.WorksetName` caching pattern.
- `revit_set_workset`: `activeWorkset=<name|id>` → `doc.GetWorksetTable().SetActiveWorksetId`; `elementIds[] + workset` → set `ELEM_PARTITION_PARAM` per element (the code in `LinkReloadService.cs:286-294` shows the parameter write; extract `WorksetAssigner.TryAssign(element, worksetId, out reason)`). Elements owned by someone else are skipped with the owner's name. Preview tool `revit_preview_set_workset` lists what would move.
- `revit_get_ownership`: for `elementIds[]`: `WorksharingUtils.GetCheckoutStatus(doc, id, out owner)` and `WorksharingUtils.GetWorksharingTooltipInfo` (creator, owner, last changed by), `GetModelUpdatesStatus` (current | updated in central | deleted in central); for `worksets[]`: `WorksetTable` + `workset.Owner`, `IsEditable`. Non-workshared document → `validation_failed` "not workshared". The existing usages in `PanelSchematicsStorage.cs:264` and `SetTextNotesTools.cs:361` should switch to the new `OwnershipReader` helper.
- `revit_checkout_elements`: `WorksharingUtils.CheckoutElements(doc, ISet<ElementId>)` returns what was obtained; the result lists `checkedOut[]`, `alreadyMine[]`, `ownedByOthers[] {id, owner}`, `failed[]`. Cap 5 000 ids. Preview = `revit_get_ownership`.
- `revit_relinquish`: `RelinquishOptions` flags from `what[]` (`elements` with ids → `CheckedOutElements`, `userWorksets`, `standardWorksets`, `familyWorksets`, `viewWorksets`, `all`); `WorksharingUtils.RelinquishOwnership(doc, options, new TransactWithCentralOptions())`. This talks to central (long-running) and must run outside a transaction (`DocumentToolSupport.CheckNoOpenTransaction`). Result: counts per kind.
- `revit_reload_latest`: `doc.ReloadLatest(new ReloadLatestOptions())`; outside a transaction; long-running; result says whether the document was modified by the reload (`DocumentChangeTracker` stamp before/after) and advises a `revit_graph_build` when the graph exists.

### Worker-document workflow (documented, not a tool)

`docs/worker-document.md` describes the recommended setup: the user opens Revit normally; the agent runs `revit_open_document path=<central> mode=newLocal worksets=editable activate=false`, then every call passes `document=<title>` (or, with #100, the job runs with `document` set in every step); it checks out what it will edit (`revit_checkout_elements`), works, verifies with `revit_checkpoint_diff` (#98), then `revit_sync_with_central comment=…` (existing, destructive, manual approval) and `revit_relinquish what=all`. It also states the limit plainly: Revit's API thread is shared, so heavy agent work still competes with the user's commands for UI time; a second Revit instance (`revit_list_instances`) removes that too.

### Status codes

`document_already_open`, `not_workshared`, `owned_by_other` (data lists owners), `active_document_required`.

Manual test, Revit 2026 and 2024, with a workshared central on a share: user has their local open and active; agent opens its own local without activation; `revit_list_open_documents` shows both; agent sets a parameter on 10 elements with `document=<agent local>` while the user keeps drawing; `revit_get_ownership` shows the agent owns them; user tries to edit one in their local → Revit reports it as owned by the agent's user; agent syncs, relinquishes; user reloads latest and sees the change. Also: `AllowNetworkPaths=false` produces the config hint, not a bare failure.

## Acceptance criteria

- A read or write tool from the `core`, `query`, `edit` and `electrical` groups accepts `document=<title>` and acts on that document while another one is active; UI-bound tools return `active_document_required` instead of acting on the wrong document.
- `revit_open_document mode=newLocal activate=false` opens a local the user never sees as a window change; the local file is in the configured folder with the agent's username in its name.
- Ownership, checkout and relinquish results name the other owner when one exists and never throw Revit's modal worksharing dialogs (the `RollBackOnErrorPreprocessor` is attached where a transaction is involved; central calls run outside transactions).
- `revit_close_document` is refused for the active document and needs manual approval; unsaved changes are named in the summary.
- Long-running calls (open, close, reload, relinquish, sync) do not time out at 30 s.
- Unit tests green, both targets build, benchmark report committed, `docs/worker-document.md` written.
