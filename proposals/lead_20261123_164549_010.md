## What to build
Pin CI to explicit Flutter versions with a floor/latest matrix, example build jobs and an API 36 integration job, and gate all golden tests behind one switch so they run only on the pinned macOS job.

## Required context
- `.github/workflows/flutter.yaml` (currently `channel: stable`, emulator API 34), `validate.sh`
- `test/render_golden_test.dart` (skip via `_inCi`), `test/image_test.dart` (`matchesGoldenFile` with `skip: kIsWeb || isLinux`)

## Acceptance criteria
- [ ] `flutter.yaml` pins Flutter by version, not `channel: stable`.
- [ ] Floor job: Flutter 3.35.0 on `ubuntu-latest`, runs `validate.sh` (clean, pub get, format, analyze, tests); goldens skipped.
- [ ] Latest job: Flutter 3.50.x on the macOS runner, runs `validate.sh` with goldens enabled.
- [ ] Example build jobs on 3.50.x: `flutter build apk --debug`, `flutter build ios --simulator --debug` (Xcode 27.x), `flutter build web`.
- [ ] Android integration test job on 3.50.x with emulator API level 36 (add `target: google_apis` if needed).
- [ ] `validate.sh` forwards `--dart-define=GOLDENS=true` to `flutter test`.
- [ ] Every `matchesGoldenFile` test in `test/render_golden_test.dart` and `test/image_test.dart` runs only when `GOLDENS=true`; otherwise it is skipped with a printed reason. The `_inCi` / `kIsWeb || isLinux` golden skips are replaced by this switch.
- [ ] A manual `workflow_dispatch` job on the same pinned macOS runner regenerates golden references and opens a PR; goldens are never regenerated from a developer machine.
- [ ] Golden references are regenerated through that job and all jobs are green on main.
- [ ] Contributor PR runs awaiting maintainer approval are approved so CI evidence exists before merge.
- [ ] Workflows pass `actionlint`.
