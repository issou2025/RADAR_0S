*Project description:*
## Goal

Make the app build and run on macOS 13 or later, on Apple Silicon (arm64) only. Publish an unsigned `.dmg` in GitHub Releases. There is no notarization, no Apple Developer account, no Mac App Store and no signing secret in CI.

## Scope

- Add `app/macos` (`flutter create --platforms=macos`). Set the minimum deployment target to macOS 13.
- Build the Rust core (`wallet-ffi`) for `aarch64-apple-darwin`. Link it in the Xcode project (static library or `.dylib` in the bundle). Add a script like `scripts/build_android.sh`.
- Replace each Android platform channel with a Swift version, or turn the feature off on macOS. Share the code with the iOS app (#152) where it is possible:
  - secure storage (Keychain)
  - deep links `celaut:` and `ergopay:` (`CFBundleURLTypes`)
  - open a `.celaut.bee` file (`CFBundleDocumentTypes`)
  - cards sensors and motion cues: no equivalent, turn them off
  - in-app update: not supported (see Updates)
  - foreground service: not needed on desktop
- Turn off the App Sandbox (no developer signature). Add the camera and microphone usage descriptions to `Info.plist` and the matching entitlements.
- Check that `flutter_zxing` (camera and QR), `record`, `share_plus`, `file_picker` and `flutter_local_notifications` work on macOS. Check the `objective_c` hook problem in `docs/flutter-toolchain.md`.
- Check that arti (Tor) works on macOS.
- CI: a `macos` runner on Apple Silicon runs `flutter build macos --release` and packs the `.app` in a `.dmg` with `hdiutil`. The `release.yml` publish job adds it to the release with a SHA-256 checksum. Check the `.dmg` (version and build number, `arm64` architecture, and that the app starts).
- Document the install steps, with the Gatekeeper step (see Gatekeeper).

## Gatekeeper

The app is not notarized, so macOS blocks it the first time. Flutter signs the app ad hoc, which is the minimum for Apple Silicon. The user must open System Settings, Privacy & Security, and choose "Open Anyway", or run `xattr -dr com.apple.quarantine /Applications/<app>.app`. Since macOS 15, right-click and Open is not enough. The install instructions must show these steps.

## Background and warnings

macOS does not suspend the app in the background, so conversations and `AutoTopUp` keep running while the app is open. Two points need care:

- **App Nap** can slow the timers of a hidden app. Use `ProcessInfo.beginActivity` while a conversation is open or an instance has automatic top-up on, and test it.
- **Closing the app** (for example with ⌘Q) stops everything. Automatic top-up runs only while the app runs. When the balance of an instance runs out, the node stops the instance. Show a short warning where the user turns on automatic top-up.

## Updates

The app does not update itself on macOS. `UpdateChannel.supported` stays Android only. The user downloads the new `.dmg`.

## Out of scope

Intel (x86_64) and universal binary, macOS 12 and older, notarization, Mac App Store, Homebrew cask, `.zip` distribution.
