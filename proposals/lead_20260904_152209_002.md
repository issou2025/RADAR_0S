## Why this campaign exists

This is the public, self-contained control issue for the repository-wide campaign that transfers durable contract, authoring, validation, provenance, and delivery lessons from AutoNovel into AutoMovie. The campaign began by recovering the interrupted Claude Code session and its child-agent research, but recovery was only evidence collection: a single main reviewer then rechecked AutoMovie and the fixed AutoNovel delta rather than trusting inherited conclusions.

The goal is not to copy AutoNovel code or novel-specific features. The goal is to identify generalizable invariants proved by the fixed AutoNovel delta, test whether the same failure independently exists within AutoMovie's prototype boundary, and repair only the failures that survive that falsification. AutoNovel benchmark numbers, repository accidents, and novel-only behavior remain out of scope.

This issue replaces no historical record and does not revive #2233. That issue remains closed as NOT_PLANNED. This new issue, #2363, is the sole current campaign control and handoff.

Implementers are assumed to start without private working notes. Every issue-specific fact needed to reproduce, scope, implement, and verify a topic is embedded in that issue. The common mission, immutable bases, adjudication result, branch state, batching rules, and complete operational DAG are embedded here. Neither this issue nor any campaign issue requires an untracked knowledge directory.

## Operational semantics

The DAG nodes are batches, never individual issues. Do not launch 37 agents at once. B00 is resolved only on a base that contains its commits; among remaining work, the initial unresolved frontier is B01, B02, B03, B04, B06, B07, B11, B12, B14, B18, B20, and B21. A later batch becomes ready immediately when all of its direct predecessors are integrated and green; it need not wait for unrelated work in an earlier wave.

One owner owns one whole batch and its complete consequence surface. In a solo session, select one ready batch, implement it, Self-Review it, verify it, and commit it before selecting the next ready batch. If a future session explicitly uses parallel agents, isolate ready batches in separate worktrees and branches, and inspect shared files, generated fixtures, exports, evidence indexes, and integration owners before running same-wave batches concurrently. Semantic readiness does not guarantee freedom from file conflicts.
