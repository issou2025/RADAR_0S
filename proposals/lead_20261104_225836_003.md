# Project Proposal — Bim Modeling

## Project Understanding
You need assistance with: 
**Doors and windows: decode hand flip and facing flip**

*Project description:*
Thank you for 0.13.0 and 0.14.0. The 2026/2027 room outlines (#1260) and the parking spaces (#1262) are both fixed for us.

**Request:** decode a door or window instance's hand flip and facing flip (Revit's `FamilyInstance.HandFlipped` / `FacingFlipped`), or document how to derive them from fields already decoded.

**Why:** we turn doors into 2D plan swings, which need two things:
- **Hinge side:** comes from `m_opening_facing_x/y`. It agrees with Revit's own IFC export on 565 of 577 placed single doors across 12 model pairs, including 94 of 94 on Snowdon Towers 2024.
- **Opening side:** which room the leaf opens into. Nothing decoded gives this directly. Today we infer it from the lean of a saved door mesh, which works only where the body is a mesh, not a box. Across our corpus that gives an opening side on about 800 of roughly 2,665 doors that have a hinge side.

On `snowdon_towers_sample_architectural.rvt` (Revit 2024), the 0.14.0 `Door` records carry `m_opening_facing_x/y`, `m_instance_x_axis_x/y`, `m_filler_opening_axis_x/y` and `m_instance_origin_x/y`, but no flip fields. Two questions:
- If the instance transform is stored mirrored, can the flips be read from it?
- Does `m_opening_facing` already include the facing flip?

**What we can offer:** Revit's IFC export of the same models gives each door's `OperationType` and `ObjectPlacement`, so we can check flips against it on the same 12 pairs, and we're happy to run it against a branch.
