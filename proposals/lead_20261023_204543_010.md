## Project Understanding
You need assistance with: 
**[Ticket]: Run fespalier tasks from VS Code and from IntelliJ IDEA or Android Studio**

*Project description:*
### Type

Spike / Investigation

### Summary

Since 0.22.0 (#281) the two editor plugins run the `tasks:` of an app's `pubspec.yaml`:
- **VS Code** lists them under _Terminal | Run Task... | fespalier_.
- **IntelliJ IDEA and Android Studio** put a run icon beside each task key in `pubspec.yaml`, add a _fespalier task_ run configuration, and add _Tools | fespalier: Run Task..._.

The tests cover a lot without a window:
- The VS Code provider runs against a stand-in for the `vscode` module.
- IntelliJ runs in a headless IDE.
- `fsp run --json` runs for real.

No test has opened a real editor window, run a task in its terminal, or pressed Stop. This ticket is that check.

Expected result: a report on each case below, per editor and operating system.

### Intent

Make sure a developer can run `dev`, `build` and their own tasks from either editor, and stop them, on macOS, Linux and, if possible, Windows. These are the "UNCHECKED on a device" items of `docs/cli.md`, "Tasks in your editor".

### Source of truth (links)

- `docs/cli.md`, "Tasks in your editor" (https://github.com/fespalier/fespalier/blob/main/docs/cli.md#tasks-in-your-editor) and "Editor plugins" (https://github.com/fespalier/fespalier/blob/main/docs/cli.md#editor-plugins)
- `editors/vscode/README.md` and `editors/intellij/README.md`, which say how to build and install each plugin
- `docs/cli.md`, "Tasks: commands around `flutter run`", which describes the `tasks:` section

### Current Behavior

Checked by tests only:
- VS Code: `npm test`, 31 tests, against a stand-in for the `vscode` module.
- IntelliJ: `./gradlew build`, 50+ tests in a headless IDE.
- `fsp run --json`: unit and CLI tests.

Not checked:
- The Run Task list in a real VS Code.
- A task's terminal, and Terminate Task.
- The run icons in a real IDE.
- The run console.
- Stop.
- Windows.

### Expected Behavior

- **VS Code.** _Run Task... | fespalier_ lists `dev` and the app's own tasks. Each runs in a terminal of its own, and `fsp dev` shows its full-screen view there. Terminate Task stops flutter.
- **IntelliJ / Android Studio.** A run icon sits beside each task key under `fespalier: tasks:`. Clicking it runs the task in the run console and adds a configuration named `<task> (<folder>)`. _Tools | fespalier: Run Task..._ lists every task, `dev` and `build` included. On Linux and macOS, Stop stops flutter.
- **Messages.** These are the exact texts in `docs/cli.md`:
  - An `fsp` older than 0.22.0 makes both plugins say ``this fsp cannot list tasks: `fsp run --json` needs fespalier 0.22.0 or later``, once.
  - A `tasks.json` entry with wrong types, or a folder without a `pubspec.yaml`, gets a message, and nothing runs.

### Acceptance Criteria

- Tried in VS Code, and in IntelliJ IDEA or Android Studio (2025.2 or later), on at least one of macOS or Linux. Windows is a bonus, and the most useful one.
- Each case below is marked pass, fail, or not run, with what the editor showed.
- The report lists the OS, the editor and its version, `fsp --version` (or `dart run fespalier --version`), `flutter --version`, and the commit of `main`.

### Out of Scope

### Technical Context

**Setup.**

1. Install `fsp` 0.22.0 or later (`fsp upgrade`, or `install.sh` from the README), or build it from `main`: `cd cli && cargo build --release`, then put `target/release` on `PATH`.
2. Make an app with tasks:
   ```sh
   fsp create taskdemo && cd taskdemo
   ```
   Then add to its `pubspec.yaml`:
   ```yaml
   fespalier:
     tasks:
       hello:
         run: echo hello from a task
       slow:
         run: sleep 30
   ```
   `fsp run hello` in a terminal should print `hello from a task`.
3. **VS Code plugin:**
   ```sh
   cd editors/vscode && npm install && npm test && npx @vscode/vsce package
   ```
   Then _Extensions | ... | Install from VSIX..._ and pick the `.vsix`.
4. **IntelliJ plugin**, with JDK 21:
   ```sh
   cd editors/intellij && ./gradlew build buildPlugin
   ```
   Then _Settings | Plugins | gear icon | Install Plugin from Disk..._ and pick `build/distributions/fespalier-intellij-<version>.zip`. The first build downloads the IntelliJ Platform, about 6 GB. Or run `./gradlew runIde` for a sandbox IDE.

### The cases

**VS Code** (open the `taskdemo` folder):

1. **The list.** _Terminal | Run Task..._, then pick _fespalier_. Expect `dev`, `hello` and `slow`. `build` is not listed.
2. **A task.** Run `hello`. Expect a terminal of its own that prints `hello from a task`.
3. **Terminate.** Run `slow`, then _Terminal | Terminate Task_. Expect the terminal to say the task ended, with no `sleep` left running (`ps` or Task Manager).
4. **`dev`.** With a device or Chrome available, run `dev`. Expect `fsp dev`'s full-screen view: the device picker if there are several devices, then the app. Press `r`, then `R`, then `q`. Expect a hot reload, a hot restart, then flutter stopped. Run `dev` again and use Terminate Task instead. Report whether flutter and the app stopped.
5. **A new task.** Add `bye: {run: echo bye}` to `tasks:` and save. Run Task again: expect `bye` in the list without a reload.
6. **`build`.** Add the `.vscode/tasks.json` entry from `docs/cli.md` (`"task": "build"`, `"target": "web"`) and run it. Expect `fsp build web` to run. Then change `"args"` to the string `"--release"`. Expect a message, and nothing runs.
7. **Two projects in one folder.** Open a folder that holds two apps, e.g. `examples/shop` and `examples/tabs` of this repository. Expect the tasks named `name - <path>`.
8. **An old fsp.** With an `fsp` 0.21 on `PATH`, open Run Task. Expect one warning with the text above, and an empty list. Then `fsp upgrade` (or put 0.22 on `PATH`) and open Run Task again: expect the tasks, without reloading the window.
9. **Windows, if you can.** Repeat 1 to 4. Then set `fespalier.runner` to `dart` and repeat 2.

**IntelliJ IDEA or Android Studio** (open `taskdemo`):

10. **The run icons.** Open `pubspec.yaml`. Expect a run icon beside `hello` and `slow` under `fespalier: tasks:`. Click the one beside `hello`. Expect the run console with `hello from a task`, and a temporary configuration `hello (taskdemo)` in the run configurations list.
11. **Run Task.** _Tools | fespalier: Run Task..._. Expect `dev`, `build`, `hello` and `slow`. Pick `build` with no target. Expect a message that the build task needs a target.
12. **By hand.** _Run | Edit Configurations... | + | fespalier task_. Set the project folder, the task `build`, and the target `web`. Run it and expect `fsp build web` to run. Set a folder without a `pubspec.yaml` and expect a message that says so.
13. **`dev` in the run console.** Run `dev`, with `-d chrome` in the arguments when there are several devices. Expect plain lines with `[flutter]` and `[fsp]` in front. Type `r` then Enter, and expect a hot reload.
14. **Stop.** While `dev` runs, press Stop. On Linux and macOS, expect flutter and the app to stop. Report whether the first Stop was enough. Also try it with the runner set to `dart run fespalier` (Settings | Tools | fespalier): the first Stop may not reach `fsp` there, and a second Stop ends it. Report how many Stops it took.
15. **Two projects with one folder name.** Open a parent folder with `apps/shop` and `examples/shop` (copy an example twice). Run `hello` (or any task) in both. Expect two configurations, `<task> (apps/shop)` and `<task> (examples/shop)`, each running its own project.
16. **Windows, if you can.** Repeat 10, 13 and 14. On Windows Stop ends the process at once unless the IDE's registry key `kill.windows.processes.softly` is on. Report whether flutter's app stayed running after Stop.
