## What happened

On 2026-09-14 at 06:20 UTC, `alexissolanas` opened [PR #7162](https://github.com/quay/quay/pull/7162) to bump `qs` to 6.16.0 for CVE-2026-82417 (HIGH, CVSSv4 6.3), touching five dependency manifest files (`package.json`, `package-lock.json`, `web/package.json`, `web/package-lock.json`, `web/pnpm-lock.yaml`). `redhat-chai-bot` had opened [PR #7055](https://github.com/quay/quay/pull/7055) against the same five files on 2026-09-04 — 10 days earlier — but that PR had been failing CI continuously (conventional-commit lint failure due to a missing title prefix; a Playwright test failure), leaving it looking blocked rather than pending review. No automated system warned the contributor about the existing open PR. Full CI ran on the duplicate: 33m 43s Playwright E2E, CodeQL (Go + Python + JS), Konflux builds (~16 min combined), and several lighter checks. At 07:00 UTC the contributor self-identified the duplicate and closed PR #7162 without merge.

## What could go better

A contributor searching GitHub for the CVE or the package name before opening would likely have found PR #7055, but a PR with continuous CI failures does not surface clearly as "this fix is already in progress" — it looks stalled or abandoned. The absence of any automated cross-PR signal meant the contributor had no prompt to check until they had already waited 40 minutes for CI. The preconditions are structural and plausibly recurring: automated CVE bots (chai-bot, Renovate, Dependabot) open dependency-bump PRs that sometimes sit with lint or test failures, and community contributors independently rediscover the same vulnerability. Confidence is moderate — this is one observed instance — but the cost per recurrence (~34 min CI compute plus contributor time) is non-trivial, and the fix is low-effort.

## Proposed change

Add a fast, non-blocking GitHub Actions job to `.github/workflows/ci-lint.yaml` (or a new `.github/workflows/pr-duplicate-check.yaml`) that fires on `pull_request` events (types: `opened`, `reopened`) when the changed files include any dependency manifest path (glob: `package.json`, `**/package-lock.json`, `**/pnpm-lock.yaml`, `requirements*.txt`, `**/pyproject.toml`). The job should query the GitHub API for all other open PRs that touch at least one overlapping file:

```bash
gh api repos/quay/quay/pulls?state=open\&per_page=100 \
  | jq --argjson changed "$CHANGED_FILES" \
    '[.[] | select(.number != $ENV.PR_NUMBER) | select(.changed_files as $n | $changed | any(. as $f | $n | contains($f)))]'
```

If any matching open PRs are found, post a one-time PR comment (idempotent — skip if the bot already commented) listing them with title, author, and URL. The comment should be explicitly non-blocking and advisory. Target runtime: under 60 seconds. No new secrets required; use the existing `GITHUB_TOKEN`.

## Validation criteria

The next time an automated bot or contributor opens a PR that touches the same dependency manifest files as an already-open PR, the new PR receives a comment within 2 minutes of opening that links to the existing open PR(s). Validate over the next three such events. Additionally: the check job completes in under 60 seconds, produces no false positives for PRs that happen to touch manifests for unrelated reasons without file-level overlap, and does not comment more than once per PR.
