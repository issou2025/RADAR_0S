# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Compare the same interactions in Jolt, Reanimated and Flutter**

*Project description:*
We need to know where Jolt is better, where it is worse, and how much code an app needs to get the same result. A smooth GIF and an FPS average cannot answer that.

Build small equivalent apps in Jolt/NativeScript, React Native/Reanimated and Flutter. Begin with the features Jolt already has: an interruptible spring, a stagger over 50 and 200 items, and a repeating transform/opacity animation. Add a scrolling header and the sheet recipe as those land.

Match trajectories, visible content, interruption timing and list virtualization. Run production-equivalent builds on the same physical Android and iPhone, at the supported refresh rates. Use Flutter profile mode for its profiling tools and release builds for end-user runs; never compare a debug build with a release build. Record versions, flags, hardware, thermal state and raw traces.

Measure startup-to-first-frame, frame-time percentiles, missed deadlines, input-to-visible-response latency, memory and CPU. Separate normal app work, deliberate app-runtime blocking and native UI-thread blocking. NativeScript's JS shares the UI thread, so a 300ms JS block is not the same experiment across these stacks. Repeat runs and report variability.

Track the code and setup needed for each example too, with the same behavior and accessibility requirements. Keep those comparisons readable rather than reducing developer effort to a single line count.

Use Android [Macrobenchmark frame timing](https://developer.android.com/reference/androidx/benchmark/macro/FrameTimingMetric), iOS Instruments and [Flutter's profiling guidance](https://docs.flutter.dev/perf/rendering-performance). Reanimated now has experimental [platform-backed CSS transitions](https://docs.swmansion.com/react-native-reanimated/docs/guides/feature-flags/#ios_css_core_animation-and-android_css_platform_transitions); include the applicable path as a separate configuration instead of benchmarking only an older path.

Publish the runnable apps, procedure and results, including cases Jolt loses. Extend #9 and #11 into a repeatable comparison, then choose regression budgets from measured baselines. The first deliverable is one runnable comparison, not a claim of universal superiority.
