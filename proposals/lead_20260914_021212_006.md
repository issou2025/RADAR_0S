## Goal
Make the machine-readable AI PR coordination contract authoritative for the **current PR body**, not only for the body snapshot that happened to exist at the last code push.

The current required Flutter CI workflow declares:

```yaml
pull_request:
  branches:
    - main
```

GitHub therefore uses the default `pull_request` activity types (`opened`, `synchronize`, `reopened`). A normal PR-body `edited` event does not start the workflow. Because `tool/pr_coordination_guard.py` reads lane / Related Issue / dependencies / `Shared hotspots` / `Migration/data impact` from the live PR body, those fields can be changed after a green required run without changing the head SHA or invalidating the old green `merge-gate`.

Current concrete reproduction: PR #1427 changed its body to claim `Shared hotspots: lib/views/generic_database_page.dart` and to describe real-host integration while the exact current PR file diff still contains only the width adapter/widget and two focused tests. Its earlier `ci-scope` success remains attached to the unchanged head because the body edit itself did not trigger Flutter CI. The guard would reject the current hotspot declaration if rerun (`declared != actual`), but no rerun is currently guaranteed.

## Acceptance
- Editing any machine-readable PR coordination field cannot leave an older successful required contract audit authoritative without validating the new body.
- The validation is tied to the current PR head **and** current coordination metadata/body state before merge.
- A regression demonstrates: green contract at one body state -> edit `Shared hotspots` (or another deterministic field) to an invalid value without a code commit -> the PR no longer remains merge-eligible on the stale contract result.
- Ordinary code pushes/open/reopen behavior remains unchanged and fail closed.
- Do not create a PR-body self-approval token or weaken #1107/#1331 destructive-approval semantics.
- Avoid rerunning the entire expensive Flutter suite for harmless prose-only body edits if a smaller trustworthy event/check design can preserve the required-gate invariant; however, correctness of the required contract is more important than optimization.
- GitHub Actions triggered by repository `GITHUB_TOKEN` must continue respecting the completed #1208 self-mutation/approval boundary; do not add a PAT/App credential merely to force recursion.

## Non-goals
- no product/runtime change;
- no schema/migration;
- no redesign of lane ownership semantics;
- no weakening/removal of the existing exact hotspot/migration/duplicate-Issue checks;
- no requirement that arbitrary non-contract prose edits rerun unrelated expensive validation if they can be safely distinguished.
