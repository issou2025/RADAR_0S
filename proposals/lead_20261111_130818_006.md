# Project Proposal — Flutter App

## Project Understanding
You need assistance with: 
**Inspect sqflite databases**

*Project description:*
Many Flutter apps store their data with `sqflite`, the most used SQLite plugin. This issue adds `xray_sqflite_inspector`, a small package that shows an app's sqflite database in xRay's **Database** tab (see #56): its tables, its rows and a Query view for SQL. Setting it up is one line in the app.

## Background

xRay has two sides: the **SDK**, which you add to your Flutter or Dart app, and the **desktop app**, which shows what is happening inside that app. Each kind of data has an **inspector** you list in `XRayInspectorServerConfig(inspectors: [...])`. #56 adds the Database tab and the shared database support; each database engine then needs its own inspector package. `sqflite` and `sqflite_common_ffi` (used on desktop and in tests) both hand the app a `Database` object, which is what this inspector takes.

## User story

As a Flutter developer whose app uses sqflite, I want to pass my `Database` to an xRay inspector, so that I can browse, query and fix its data from the desktop app while the app runs.

## Current behaviour

There is no way to see a sqflite database in xRay. Developers copy the `.db` file off the device and open it in another SQLite tool.

## Expected behaviour

1. The app adds `xray_sqflite_inspector` and registers `XRaySqfliteInspector(database: db)` with the `Database` it already opened.
2. The database shows in the Database tab, titled with its file name, with its tables and views and their row counts.
3. Rows page, search and sort; the Query view runs SQL.
4. Read-only by default; `allowWrites: true` turns on adding, editing and deleting rows and queries that change data.
5. `title:` and `id:` name the database when an app has several.

## Acceptance criteria

- [ ] `XRaySqfliteInspector(database: db)` works with a `Database` from `sqflite` and from `sqflite_common_ffi`.
- [ ] Tables, views and row counts match the database; tables without a primary key are addressed by `rowid`.
- [ ] Read-only queries run with writes off; other statements are refused by the app.
- [ ] With `allowWrites: true`, a row edited in xRay is in the database the app reads next.
- [ ] An encrypted database opened with `sqflite_sqlcipher` works through the same `Database`, without passing the key to xRay.
- [ ] The package is published on pub.dev with a docs page and an example.

## Out of scope

- Telling the app's in-memory state about xRay's edits: sqflite has no change notifications, so the app sees an edit on its next read.
- Opening database files the app has not opened itself.

## Edge cases

- The app holds a transaction → xRay's statements wait for it.
- Two sqflite databases in one app → both show, each with its own title.
- `WITHOUT ROWID` tables without a primary key and views → shown, read-only.

## Workaround

Copy the database file off the device and open it in a SQLite tool.
